# 运营 SOP · 每日 20 分钟 / 每周 1 小时

> 配套手册第四章。这份 SOP 同时是**未来 agent 的脚本**——
> 每一条都写成「看什么 → 阈值 → 触发什么动作」，就是为了两周后能原样交给 agent。
> 手册第五章第 1 步：**先人工跑 2 周把阈值跑准，再自动化**。顺序反了，agent 只会自动化地犯错。

---

## 每日（20 分钟）

### 第 0 步 · 跑体检脚本（2 分钟，其余步骤都靠它的输出）

```bash
export POSTHOG_PERSONAL_API_KEY=phx_...          # 只读 key，绝不写进任何文件
python3 scripts/ops/daily-health-check.py --out ~/tailtopia-health/$(date +%F).md
```

脚本**只读、只诊断、不执行任何动作**——它不发推送、不改投放、不写库。
输出的是「诊断 + 候选动作清单」，勾选与执行是你的事。

> 没有 key 时先 `--dry-run` 看它要查什么（不联网）。

### 第 1–4 步 · 按体检表逐条处置

| # | 看什么 | 阈值 | 命中后做什么 |
|---|---|---|---|
| 1 | **D1 留存**（北极星） | < 10% 报警 | **先查推送有没有发出去，别先改文案**——两者长得一模一样。看后端日志 `lifecycle push daily scan: users=.. planned=.. dispatched=..`：`planned=0` → 开关/取数问题；`dispatched < planned` → 撞每日上限，正常；两者都 > 0 而 D1 没动 → 才轮到换文案 |
| 2 | **在线兽医数 vs 问诊请求** | 无人接单 ≥ 1 单 | 补兽医；补不上就**限流**，别让用户发起了再空等。⚠️ 在线兽医数在后端 Redis，体检脚本查不到，要去后台兽医管理页看 |
| 3 | **Feed 当日新内容** | < 5 条 | 去 `/admin/seed-post?tab=batch` 补种子。⚠️ 脚本只数得到 App 内发布的埋点，**运营种子不经埋点**——补之前先去后台确认今天实际发了多少 |
| 4 | **召回 push 漏斗** | 点击率/建档率下滑 | 换文案（备选臂见 `retention-push-copy-matrix.md` §2）。⚠️ 这块在后端库，体检报告末尾直接给了 SQL |

### 第 5 步 · 记一行日志（30 秒，两周后校准阈值全靠它）

在下面的《阈值校准记录》里补一行。**别跳过这步**——
两周后没有这张表，你只能再拍一次脑袋。

## 每周（1 小时）

| 动作 | 看什么 | 判据 |
|---|---|---|
| 分层复盘 | 五个分层的人数变化、D1/D7 趋势 | 「已建档未发布」这层在不在缩小？不缩小说明 D3/D7 推送没起作用 |
| 渠道复盘 | 分 `media_source` 的注册质量 | ⚠️ **归因修好之前这条做不了**——诊断报告：utm/media_source 全为空，`$virt_initial_channel_type` 对 1240 人全是 Unknown |
| 分享飞轮复盘 | 发布 → 里程碑 → 分享 → 新客 | 现状 106 发布 / 15 分享 = 14%，目标先翻倍到 30% |
| 供给复盘 | 兽医评分、接单率、资质到期 | 30 天内到期 / 已过期账号数（后台已有） |

**每周还要做一件手册没列但必须做的事**：把本周所有 `guess` 级阈值拿出来看一遍，
够两周数据了就改 `scripts/ops/thresholds.json` 里的 `value`，并把 `confidence` 从 `guess` 升上去。

## 阈值校准记录（人工跑的这两周，每天补一行）

| 日期 | D1 | cohort | DAU | 无人接单 | Feed 新内容 | 当天判定对不对？ | 备注 |
|---|---|---|---|---|---|---|---|
| 2026-08-__ | | | | | | | |

**「判定对不对」怎么填**——这一列才是这张表的全部价值：
- `准` = 报警了，去查确实有问题
- `虚警` = 报警了，但查下来没事 → **阈值太敏感，该放宽**
- `漏报` = 没报警，但事后发现出了问题 → **阈值太松，该收紧**

两周结束时，把 `虚警` 和 `漏报` 各自数一遍，就知道每个阈值该往哪边挪。

## 交给 agent 的顺序（手册第五章第 3 步）

| 状态 | 动作 | 为什么是这个顺序 |
|---|---|---|
| ✅ 可以先交 | 种子内容**生产**（选题/写稿/出 Excel） | 可逆、低风险，发错了能下架 |
| ✅ 可以先交 | push 文案 A/B 的**方案生成** | 只出方案，按不按下由人决定 |
| ⏸️ 后交 | 召回 push 的**发送** | 已有引擎 + 每日上限兜底，但放量节奏仍需人判断 |
| ⏸️ 后交 | 投放调整 | 涉及预算，必须你确认 |
| ❌ 暂不交 | 兽医供给调度 | 涉及人 |
| ❌ 暂不交 | 内容举报处置 | 涉及社区规则判断与用户申诉 |

> 手册原话：**你拍板，agent 干活**。
