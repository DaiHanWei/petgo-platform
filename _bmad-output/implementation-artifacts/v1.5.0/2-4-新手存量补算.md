## Story

As a 上线前就在用 App 的老用户,
I want 我以前做过的事自动算进新手任务、满了就直接拿到徽章,
so that 不会看到「徽章已拿、任务 3/7」或被要求重做。

## Acceptance Criteria

**AC1 — 标记回溯** `[L1]`
对未注销账号（`users.deleted_at IS NULL` 且无 `account_deletions` 行）写 `user_newbie_marks`（`source='BACKFILL'`，`occurred_at` = 来源最早时间，`ON CONFLICT DO NOTHING`）：
| 任务 | 来源（任一成立） |
|---|---|
| ① FIRST_DIARY | 账号任一宠物（含只读）已完成 `C-S2 / D-S2 / G-S2`；或本人作者的 `GROWTH_MOMENT` 帖（`status='PUBLISHED'`，含软删） |
| ② FIRST_LIKE_RECEIVED | 任一宠物已完成 `C-S15 / D-S15 / G-S8`；或 `content_likes` 中他人（`l.user_id <> p.author_id`）给本人帖子的赞（**不按 `is_automated` 过滤**——若该列已存在也不用它） |
| ③ FIRST_FOLLOW | 已有 `FIRST_FOLLOW_USER` flag；或 `user_follows.source='USER'`；或 `pet_follows` 有行 |
| ④ FIRST_LIKE_GIVEN | `content_likes` 本人给他人帖子 |
| ⑤ FIRST_COMMENT | `comments.parent_id IS NULL`、本人、帖子作者非本人（含软删评论） |
| ⑥ FIRST_REPLY | `comments.parent_id IS NOT NULL`、本人、被回复评论 `COALESCE(reply_to_comment_id, parent_id)` 的作者非本人（含软删） |
| ⑦ ONE_WEEK | `(created_at AT TIME ZONE 'Asia/Jakarta')::date + 7 <= (now() AT TIME ZONE 'Asia/Jakarta')::date` |

编码以 `MilestoneAutoCompleteMap`（`GROWTH_MOMENT_FIRST`、`FIRST_LIKE`）为准，SQL 里显式列举，不按后缀切分。

**AC2 — 已解锁的不收回、补到其他宠物（PRD AC28）** `[L1]`
有按宠物 Lulus 完成行（`C-S16 / D-S16 / G-S9`）的账号 → 写 `LULUS_PEMULA` flag（`occurred_at = celebrated_at = MIN(completed_at)`）；账号其他 ACTIVE 宠物补完成行 `completed_at = celebrated_at = GREATEST(flag.occurred_at, 宠物 created_at)`（roster 行缺失跳过）；**不发成长值**（双宠账号成长值不变）。

**AC3 — 回溯满 7 项直接解锁（PRD AC27）** `[L1]`
未解锁且 7 项标记齐全的账号 → 写 flag（`occurred_at` = 7 项标记里最晚的时间，`celebrated_at` 同值）+ 全部 ACTIVE 宠物完成且已庆祝 + 成长值 `LAUNCH_BACKFILL` +20（写死分值，不读 `growth_rules`），`ref_type='MILESTONE'`、`ref_id='LULUS_PEMULA'`、`idem_key = 'BACKFILL150:' || user_id || ':LULUS_PEMULA'`，排除已有运行时键 `MILESTONE_ACCT:{u}:LULUS_PEMULA` 的账号；eligible 与 `V20261018_1503` 逐字一致；`growth_accounts` 累加 `lifetime_total` 并重算 `level`，**不写** `celebrate_from_level / celebrate_to_level`、不改 `backfill_popup_pending`。不写通知、不弹庆祝、之后进里程碑页也不补弹。

**AC4 — 可重复执行（PRD AC29）** `[L1]`
用 `ScriptUtils` 在自动提交下再执行一次迁移：行数不变、流水不重复、`growth_accounts` 不再累加。

**AC5 — 常量对齐** `[L0]`
`GrowthIdemKeys` 加 `backfillNewbie(long userId)` → `"BACKFILL150:" + userId + ":LULUS_PEMULA"`；测试读迁移文件文本，断言其中拼键格式与该方法一致（同 1.4.2 `BACKFILL142` 的守卫写法，若有）。
