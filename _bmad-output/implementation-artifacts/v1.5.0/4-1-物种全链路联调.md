> 口径优先级：`decision-log.md` > PRD 全文各 AC > `architecture-v1.5.0-pet-species-delta.md` > UI 稿（App 26 屏、后台 6 屏）。
> 前置：1.1 ~ 3.5 全部 review。

## Story

As a 发版负责人,
I want 在本地把建档、改类型、冷却、里程碑切换、后台代改、迁移脚本、推送导出、旧版兼容整条链路跑一遍,
so that 合并进 dev 之前就把问题收干净。

## Acceptance Criteria

> 层级：`[L1]` Docker postgres + redis，scratch 库 + 独立 Redis DB（本地）· `[L2]` Android 模拟器 + 真后端（本地）。

### AC1 — 后端 L1 `[L1]`
1. 起 scratch 库前先 flush 对应 Redis DB（防陈旧幂等键 / busy 键造成假回归）；`./mvnw -B clean package` 后跑本线新增与受影响的测试包：`profile`、`admin.usermgmt`、`gift`、`social`、`content`、`passport`、`order`、`shared.ai`、`notify.ops`，以及 1.4 的 `PetSpeciesOpsScriptIntegrationTest`；全绿。
2. 启动 `mvn spring-boot:run`，`/actuator/health` = UP（`ddl-auto=validate` 通过四条迁移）。
3. `bash scripts/ci/check-flyway-versions.sh origin/main` 通过。

### AC2 — 迁移脚本与导出演练 `[L1]`
1. 用 `sample-mapping.csv` + 自造 30 只宠物（含 5 只「其他」里的猫、LOW 行、名字不符行、已有品种行）在 scratch 库跑 `run-migration.sh`：干跑统计正确 → `apply=1` → 抽查 20 只细分类型 / 品种 / 大类与映射一致（PRD 3.4 AC1）；猫的里程碑仍是 G 清单（PRD 3.4 AC2）；重跑 0 变更。
2. 跑 `export-push-groups.sql`：三份 ID 清单两两无交集、与无宠物用户无交集（PRD 3.5 AC1）。
3. **不连 stag / 生产执行**（stag 演练等操作者指令；生产执行须操作者确认，见 1.4 README）。

### AC3 — App × 后端联调 `[L2]`（连本地或 stag 后端；测试账号 + 真登录）
逐条走、截图留证（PRD AC 编号）：
1. 建档：类型 15 项顺序（3.1 AC1）；兔子品种清单；「其他」12 组 +「… lainnya」（3.1 AC2）；「Musang Pandan」保存后显示「Lainnya / Musang Pandan」且库内 CIVET（3.1 AC3）；新建兔子的里程碑 / 新手任务 / 卡号物种码 / 首页推荐与「其他」宠物一致（3.1 AC4）。
2. 搜索：「poo」三项（3.2 AC1）；清单外词只剩「Pakai」（3.2 AC2）；身份证建卡弹同一抽屉（3.2 AC3）。
3. 改类型：首次改不受限、改完锁定并显示日期（3.3 AC1）；curl 改被拒并返回日期（3.3 AC2）；未保存返回恢复原值（3.3 AC3）；迁移过的宠物可立即改（3.3 AC4）；猫 → 兔里程碑清单变、徽章完成记录在（3.3 AC5）。
4. 推送落地：2 只（猫 + 其他）→ 抽屉「其他」第一（3.5 AC2）；无宠物 → 建档页（3.5 AC3）。
5. 后台：G1 ~ G5 全流程（代改不改用户冷却日期、记录表来源「运营」）；H1 下拉含「宠物类型」。
6. AI 分诊：一只兔子发起分诊，后端日志（脱敏）里的提示上下文物种为「兔」（不记录宠物名与症状原文）。

### AC4 — 旧版兼容 `[L2]`（PRD §6、架构 §4.5）
用 1.4.2 正式包（或 `main` 当前版本的 debug 包）连本线后端：
1. 新建档案（只传 `petType`）成功，库内 `pet_species = petType`。
2. 编辑一只已迁移的兔子（改名字）→ `pet_species` 仍是 RABBIT。
3. 兔子在旧版里显示「Lainnya」，不报错。
4. 建身份证卡成功。
5. 点 `PET_SPECIES` 推送 → 只打开 App、不闪退（PRD 3.5 AC4）。

### AC5 — 还原度 `[L2]`
App 26 屏、后台 6 屏逐屏截图与拆页对照打分，**每屏 ≥ 95%**；不足的就地修（只改样式，不改交互口径），结论写进 Completion Notes（每屏分数表）。

### AC6 — 收尾
1. 所有 story 文件 Completion Notes 里「L1 / L2 待本地验收」逐条改为实际结果；sprint-status 对应 story 改 `done`（通过的）或保持 `review` 并写原因。
2. **不提交、不推送、不部署**，结果报告给操作者，等明确指令。
