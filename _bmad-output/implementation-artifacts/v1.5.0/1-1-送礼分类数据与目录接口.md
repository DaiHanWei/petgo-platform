## Story

As a 送礼人,
I want 选礼物目录按运营配置的分类分组，并看到每件礼物我能得的 EXP、谁送过,
so that 我能按类别挑礼物，不再被写死的价格档限制。

### AC3 — 目录接口 `GET /api/v1/gifts/catalog` `[L0]` `[L1]`（D-3、架构 §4.1）
1. **旧字段逐字不变**：`recipient`、`qrisMinAmount`、`tiers`（按价格分组，内容、排序与改动前完全一致）、`exclusiveGroups`、`lockBlock`。
2. 新增 `categories: List<Category>`，`Category(long categoryId, String nameEn, String nameId, List<GiftItem> gifts)`：只含在线分类里的在线普通礼物；没有在线礼物的分类不出现；分类按 `sort_order ASC, id ASC`；组内排序用**现有** `GiftCatalogService.orderFor(species)` 比较器（不改它的签名与实现）。普通礼物若 `category_id` 为空或所在分类已下线 → 不进 `categories`（仍在 `tiers` 里，旧版照旧可见），记一行 WARN（只记礼物 id）。
3. `GiftItem` 新增两个字段（record 末尾追加）：
   - `int senderExp`：送 1 个时送礼人可得 EXP = 送礼人参与成长体系 ? `GrowthLedgerService.pointsForAmount(RuleCode.GIFT_SENT, price)` : 0；参与判定同 `GiftSendService` 的专属礼物判断（`growth.getLevel(senderId).participating()`）。一次请求只查一次等级。
   - `ReceivedFrom receivedFrom`（可空）：`ReceivedFrom(List<Sender> senders, int more)`、`Sender(String nickname, boolean deleted)`：这只收礼宠物收到过这件礼物（`gift_orders` 中 `pet_id = :petId AND gift_id = g.id AND status = 'DELIVERED'`）的送礼人，按各送礼人最近一次 `delivered_at` 倒序取前 3，`more` = 其余不同送礼人数；没收到过 → `null`。一次请求一条聚合 SQL 查完所有礼物（不得 N+1）；昵称批量走 `AccountQueryService.findAuthorViewsWithoutTags`，已注销 → `nickname = null, deleted = true`。
4. 专属礼物不进 `categories`，照旧在 `exclusiveGroups`；专属礼物的 `GiftItem` 同样带 `senderExp` / `receivedFrom`。
5. L0：`GiftCatalogServiceTest` 扩充（Mockito）：分类分组与排序；空分类不出现；下线分类不出现；未归类普通礼物只在 `tiers`；`senderExp` 不参与成长体系为 0；旧 `tiers` 断言不变。
6. L1：`GiftCatalogIntegrationTest` 扩充：真库 `receivedFrom` 三人 + `more`、注销送礼人 `deleted = true`；JSON 里旧字段名不变。

## Dev Notes

- 现有目录：`B/gift/service/GiftCatalogService.java`（`catalog(senderId, petId, postId)`，`online.sort(orderFor(species))` 后按价格进 `tiers`）、`B/gift/dto/GiftCatalogResponse.java`。在同一份已排序列表上**再**分一次组即可。
- `receivedFrom` 的 SQL 建议：
  ```sql
  SELECT gift_id, sender_id, max(delivered_at) AS last_at
    FROM gift_orders WHERE pet_id = :petId AND status = 'DELIVERED' GROUP BY gift_id, sender_id
  ```
  Java 里按 gift 分组、按 `last_at DESC` 截 3。用 `ix_gift_orders_pet_status` 现有索引。
- 目录 DTO 不下发 `sort_order`、目录内部 id、物种布尔值（原 AC4 规矩）；`categoryId` 是参考数据例外（D-4）。
- 日志不记昵称。
