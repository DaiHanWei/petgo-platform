## Story

As a 有免费次数的用户,
I want 用次数直接解锁 KTP 高清、性格测试结果，或免费送 Rp1.000 礼物,
so that 礼包里的东西真的能用上。

## Acceptance Criteria

### AC1 — 迁移 `[L0]` `[L1]`
逐字照架构 §3.7。L0：`PackCreditChannelMigrationTextTest`：`ck_gift_orders_channel` 三值、`ck_gift_orders_total` 两分支（含 `unit_price = 1000` 与 `payment_intent_id IS NULL`）、`ck_id_card_hd_purchases_channel` 三值，均 DROP + ADD；`gift_orders.channel` 值集合 ⊆ `PayChannel` 名集合。

### AC2 — `PayChannel.PACK_CREDIT` 与护栏 `[L0]`（D-18）
1. `PayChannel` **末尾**加 `PACK_CREDIT`（javadoc：不是支付渠道，只用于送礼订单与 KTP 购买记录；永不进 `payment_intents`）。
2. `PaymentIntentService.createIntent`：`channel == PACK_CREDIT` → 422 `validation`（第一行校验）。
3. 所有现存 `switch (channel)`（`GiftSendService` ×2、`IdCardHdService` ×2、`KeepsakePurchaseService`、`ConsultPayService`）补 `case PACK_CREDIT ->`：送礼走 AC5，其余 `throw AppException.validation("该商品不支持免费次数")`。
4. 所有**非 switch**接 `PayChannel` 的请求入口（grep `PayChannel channel` 于 `*Request.java` 与 `*Service.java`：宠物名额租用 / 续租、AI 解锁、`PawCoinTopupService` 的字符串解析等）对 `PACK_CREDIT` 显式 422，不得落到「非 QRIS 即扣币」分支。
5. L0：`PayChannelPackCreditGuardTest`：逐个服务（Mockito）传 `PACK_CREDIT` 断言 422 且未调钱包 / 意图；`createIntent` 拒绝。Completion Notes 列出 grep 到的全部入口与处理方式。

### AC3 — KTP 用次数解锁 `POST /api/v1/pet-profiles/me/id-cards/{cardId}/hd-credit-unlock` `[L0]` `[L1]`（D-19）
`IdCardHdService.unlockCardWithCredit(userId, cardId)`，`@Transactional`：
1. 卡不存在 / 非本人 → 404；已解锁 → 返回 `granted` + `remaining`，**不扣**。
2. `type = CreditType.ktpHdOf(card.cardType, card.cardVariant)`；`credits.consume(new ConsumeCommand(userId, KTP_HD, type, 1, cardId, card.name 截 20))`（不足 → 409 `entitlement-insufficient`，整事务回滚）。
3. `card.markHdUnlocked()` + `purchases.save(IdCardHdPurchase.of(userId, null, cardId, PayChannel.PACK_CREDIT, null))`。
4. 不发 `IdHdPawcoinUnlockedEvent`（不报 `ktp_unlock_succeeded`、不产生消费 EXP）；AFTER_COMMIT 上报 `entitlement_used {credit_type: ktp_hd, source: <firstSource 小写>}`（`alreadyUsed` 时不报）。
5. 响应：`HdPurchaseResponse.granted()` 形状 + `remaining`（该款 + ANY 剩余合计，从 `summary` 取）。限流同 `/hd-download`（共用桶）。
6. L1：`IdCardHdCreditUnlockIntegrationTest`：KTP 款扣 KTP 批；该款用完扣 ANY；已解锁不扣；无次数 409 且卡仍未解锁；并发两次只扣一次。

### AC4 — 性格测试用次数解锁 `POST /api/v1/pet-profiles/me/tailsonality/results/{token}/credit-unlock` `[L0]` `[L1]`（D-19）
1. 结果不存在 / 非本人 → 404；已解锁 → 成功不扣。
2. `consume(userId, TAILSONALITY, CreditType.TAILSONALITY, 1, resultId, 宠物名)` → 执行与 `TailsonalityKeepsakeGranter.unlock` **同一段** SQL（把 `unlock` 改为包内可见的 `static`/实例方法供复用，或抽 `TailsonalityUnlockSql`；不复制 SQL 字符串）：`UPDATE tailsonality_results SET unlocked_at = now() WHERE id = :id AND unlocked_at IS NULL` + `AUTO_EQUIP`。
3. **不写 `keepsake_purchases`**（否则进「我的订单」）；不发 `KeepsakeUnlockedEvent`；上报 `entitlement_used {credit_type: tailsonality, ...}`。
4. 响应形状同现有 `KeepsakePurchaseResponse` 的「已解锁」分支 + `remaining`。
5. L1：`TailsonalityCreditUnlockIntegrationTest`：解锁后 `unlocked_at` 非空、首次自动佩戴、`keepsake_purchases` 无新行、订单中心无新行。

### AC5 — 免费送礼 `channel = PACK_CREDIT` `[L0]` `[L1]`（D-16、D-17）
`GiftSendService.send`：
1. 校验 ⑦ 渠道：`PACK_CREDIT` 允许；⑦′ 礼物单价 ≠ 1000 → 422 `gift-credit-not-applicable`；⑧ QRIS 门槛对它不适用；⑩ 祝福语照常。
2. `GiftOrder.pending(..., channel = PACK_CREDIT ...)`：`total = 0`（`pending` 工厂按渠道算：`PACK_CREDIT → 0`，其余 `price × quantity`）。
3. `payWithCredits(order)`：同一事务 `credits.consume(senderId, GIFT, GIFT_1K, quantity, orderId, order.petName)`（不足 409 `entitlement-insufficient`，整事务回滚、订单行不留）→ `delivery.deliver(order)`；非 DELIVERED → 抛 409（照 `payWithCoins`：次数与订单一起回滚）。
4. 幂等重放：已有 `PACK_CREDIT` 订单 → 按状态返回，不再扣（consume 的 `use_key = GIFT:{orderId}` 二次保险）。
5. 响应 `senderExp = 0`。上报 `entitlement_used {credit_type: gift, ...}`。
6. L1：`GiftCreditSendIntegrationTest`：扣 5 次送 5 个；次数 3 送 5 → 409 无订单；礼物 5000 → 422；主人收礼通知照常；`growth_ledger` 有主人 `GIFT_RECEIVED`（按 1000 × 数量算，每个 +4）、**没有**送礼人 `GIFT_SENT`；送礼人 PawCoin 余额不变。

### AC6 — `GiftSentEvent` 与成长值 `[L0]`（D-16）
1. `GiftSentEvent` 末尾加 `boolean paidByCredit`；javadoc 改为：`totalAmount` = **面值**（`unit_price × quantity`）。所有构造点同步改。
2. `GiftDeliveryService.deliver`：`new GiftSentEvent(id, sender, owner, pet, unitPrice × quantity, channel == PACK_CREDIT)`；`addToSupporters` 仍传 `order.getTotal()`（免费单 0）；`addToWall` 不变。
3. `GrowthGiftListener.onGiftSent`：`paidByCredit` 时跳过 `GIFT_SENT`，`GIFT_RECEIVED` 照常按 `totalAmount`。
4. L0：`GrowthGiftListenerTest` 补：`paidByCredit = true` 只入一条；`false` 两条（原行为）。`GiftDeliveryServiceTest` 补事件字段。

### AC7 — 旧行为不变 `[L0]`
PawCoin / QRIS 送礼、HD 付费解锁、性格测试付费解锁的全部既有测试保持原断言（`GiftSentEvent` 构造参数变化导致的编译修改除外）。
