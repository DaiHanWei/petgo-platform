# Story 1.3: 健康档案上线回填与怀孕自动清除（后端）

Status: ready-for-dev

> 版本 v1.5.0 · 会话 ① 健康记录提醒 · 分支 `feat/1.5.0-health-reminder`
> 口径优先级：CROSS-STORY-DECISIONS 地基段 > 架构增量 §4.7「部署时」、§1.2、§4.6、§6.1 旧版客户端 > PRD FR-162 Auto-clear、FR-168（全部）、AC50 ~ AC54 > UI 稿 A8。
> 前置：1.1、1.2。
> 范围层：**只后端**。回填只写记录 / 档案字段；**不建提醒行**（提醒表在 2.1，首跑重建在 2.2）。

## Story

As a 运营,
I want V1.5.0 部署时把存量健康记录补上预设、Next date 与绝育状态，旧版 App 的编辑不会弄乱新字段，怀孕标记 4 个月后自动关掉,
so that 开关打开那天，老用户的记录就能正确显示和提醒，且不会被一墙「过期」吓到。

## Acceptance Criteria

### AC1 — 上线回填 Runner `[L0]` `[L1]`（PRD FR-168 Backfill、AC50、AC51、AC53）
1. `healthreminder.backfill.HealthLaunchBackfillRunner implements ApplicationRunner`。`health_reminder_settings`（含 `backfill_done_at`）在 2.1 才建，本 story **不依赖它**：只处理「`record_origin='BACKFILL'` 且该字段还没被回填过」的行（预设为空的疫苗、next_date 为空的可预填记录、有 Neuter 记录但 neuter_status 不是 NEUTERED 的宠物），天然幂等——再跑一次没有可改的行。2.1 建表后在 Runner 末尾补写 `backfill_done_at`、开头见非空即跳过（2.1 AC 里有这一条）。
2. 处理范围 `record_origin='BACKFILL'`，按宠物分批（每批 200 只，一批一个事务），对每只宠物：
   - VACCINE：`vaccine_preset` 为空且物种为 CAT/DOG → `VaccineKeywordMatcher`；命中 → 写预设（`vaccine_name` 原文不动）；`OTHER` → 写 `OTHER`。物种 OTHER 不写。
   - 有预设（非 OTHER）的疫苗 → `VaccineSeriesRule`（剂次未知 → 空剂次分支：<16 周 +4 周，否则 +1 年）写 `next_date`。
   - DEWORM：`deworm_type` 保持 null（Legacy）；CAT/DOG 的 `next_date` = event + 3 个月（物种 OTHER 不写，FR-158 OTHER 永不预填）。
   - MENSTRUATION：仅母狗未绝育的**周期首条**写 `HeatRule` 结果。
   - VET_VISIT 不存在于存量；CUSTOM / NEUTER 不写。
   - 有任一 NEUTER 记录的宠物 → `neuter_status = NEUTERED`。
3. 不走用户 API、不限流、**不发任何事件**（不触发里程碑、不触发重建）；日志只记批次计数。
4. 用例（L1，scratch 库注入数据，`settings.launch_date` 由 2.2 决定，这里只验字段）：AC50「Vaksin tricat」2026-02-01 成年猫 → F3、next 2027-02-01；AC51「F4 + rabies」→ OTHER 无 next；「Vaksin DHPPi+L」「dhpp + lepto」狗 → COMBO；「Lepto」→ LEPTO；有 Neuter 记录的宠物 → NEUTERED；AC53 无类型驱虫 2026-10-15 → next 2027-01-15。
5. 显示上的「回填静默」（next_date < launch_date 不显示）已由 1.2 `RecordDisplayStatus` 负责，本 story 只确保 `record_origin` 正确。

### AC2 — 旧版客户端编辑兼容 `[L0]` `[L1]`（PRD FR-168「Old app versions」、AC54）
1. 实现 1.1 留下的 `HealthRecordDefaults.applyForLegacyClient(record, change)`：
   - 旧版**改了 `vaccineName`** → 重新关键词匹配写 `vaccine_preset`、`dose=null`，并按新预设重算 `next_date`（PRD 只要求重匹配与清剂次；Next date 按「新预设的默认值」重算，若原 next_date 是用户手填的也会被覆盖——这是改名后唯一合理的结果，Completion Notes 记一句）。
   - 旧版**改了 `eventDate`** 且 `next_date ≤ 新 eventDate` → 按当前字段重算默认 `next_date`。
   - 其余情况新字段一律不动（AC54：1.4.1 改 F4 备注 → Next date / 预设 / 剂次不变）。
2. 旧版新建（1.2 已接默认值）：再确认无类型驱虫存 Legacy + next_date（AC54 第一句）。

### AC3 — 怀孕自动清除 `[L0]` `[L1]`（PRD FR-162 Auto-clear、AC45 最后一条）
1. `profile.health.PregnancyFlag`：`autoOffDate(Instant setAt)` = `setAt` 的 WIB 日期 + 4 个日历月；`isActiveOn(pet, LocalDate day)` = `pregnant_nursing && day < autoOffDate`（sex=MALE 恒 false）。1.1 的 `pregnantAutoOffDate` 改为调用它。
2. `PregnancyAutoClearService.clearExpired(LocalDate day)`：把 `pregnant_nursing=true AND autoOffDate ≤ day` 的宠物置 false、清 `pregnant_set_at`，并为每只发布 `PetHealthProfileChangedEvent(pregnantCleared=true, changedAt = day 的 00:00 WIB)`。**本 story 只实现方法**；由 2.3 日跑在第一步调用（2.3 AC 已写）。
3. 用例：2027-01-01 设为是、从未改 → 2027-05-01 清除（AC45）；1-31 设为是 → 5-31；再次设为是重新起算 4 个月。

### AC4 — 回归 `[L0]`
1. `./mvnw -B clean package -DskipTests` 绿；Runner 在测试 profile 下默认**不运行**（`@ConditionalOnProperty(petgo.health-reminder.backfill-on-startup, matchIfMissing=true)`，测试配置里置 false；L1 测试显式调用 `run()`）。

- 批量写用 `NamedParameterJdbcTemplate` 或实体批量 `saveAll` 均可；**不要**经 `HealthRecordService`（会发事件、会限流）。
- 生产部署：Runner 随应用启动跑一次；大约 1,002 条记录 / 509 只宠物（PRD §2），秒级完成。
- 日志禁记健康字段明文。
