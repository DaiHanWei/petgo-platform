# Story 1.3: 运营活动参与即奖判定（后端）

Status: ready-for-dev

> 版本 v1.5.0 · 会话 ⑥ ops-activity · 分支 `feat/1.5.0-ops-activity`
> 口径优先级：`CROSS-STORY-DECISIONS.md`（含「五线规划后补充的跨线口径」自动点赞条）> `decision-log.md`（11-13 按行为发生时间判、评论同人同帖一次、点赞只发 EXP）> PRD §3.2、§3.4、§6「判定」> 架构 OA-5、OA-6、OA-7、§1 #2 ~ #4、#13。
> 前置：1-2。
> 范围层：**只后端**。不改 `GrowthActivityListener`。

## Story

As a 参加活动的用户,
I want 我发帖 / 点赞 / 评论只要符合进行中的活动就当场拿到奖励,
so that 我参加的当下就能看到回报。

## Acceptance Criteria

### AC1 — 独立监听 `[L0]`
新类 `B/opsactivity/listener/OpsActivityContentListener`：三个方法均 `@Async` + `@TransactionalEventListener`（默认 AFTER_COMMIT，回滚的业务不触发）；每个方法整体 `try/catch`，失败只记 ERROR（事件类型、postId / userId、异常类名），**不记正文、昵称**；**不改** `B/growth/listener/GrowthActivityListener`（⑤ likes 会改它，避免撞文件）。

### AC2 — 总开关 `[L0]`
每个方法第一步 `GrowthLedgerService.campaignEnabled()`：false → 直接返回，不写任何记录（Q-5：关闭期间的行为不补）。

### AC3 — 发帖 `[L0]` `[L1]`
`onPublished(ContentPublishedEvent e)`：
1. `e.visibility() != PUBLIC` → 返回（私密帖一律不算，PRD §3.2）。
2. 发生时刻 `occurredAt = e.createdAt()`（= 帖子创建时刻；过审路径 `approveReview` 同样传 `p.getCreatedAt()`，因此活动结束后才过审的帖子按发帖时间命中，PRD 11-13）。
3. 候选：`OpsActivityMatchQuery.instantActivities(POST, occurredAt)`（`status = PUBLISHED AND grant_mode = INSTANT AND action = 'POST' AND start_at <= :t AND end_at > :t`，一次查询带出各自话题集合与 `content_types`）。
4. 范围：活动话题 ∩ `e.topicIds()` 非空（发帖活动话题必有 1–3 个，Q-1）；`e.type().name() ∈ content_types`。
5. 命中的每个活动 → `reserveAndExecute(ReserveCommand(a, e.authorId(), POST, e.postId(), null, GrowthIdemKeys.activityPost(a, e.postId()), occurredAt))`，各活动互不影响（单个活动异常 catch 后继续下一个）。
6. 举报拉回再过审重复发事件 → 幂等键挡住（L1 断言只 1 条）。

### AC4 — 点赞 `[L0]` `[L1]`
`onLiked(ContentLikedEvent e)`：
1. `e.likerId() == e.authorId()` → 返回。
2. **自动点赞**：开工时检查 `ContentLikedEvent` 是否已有 `automated()` 分量（⑤ likes 线加）：有 → 第 2 步加 `if (e.automated()) return;`；没有 → 不加，靠资格判定（虚拟号 `account_type = VIRTUAL` 不参与）兜住，并在 Completion Notes 写「⑤ 合入 dev 后补 `if (e.automated()) return;`」。**无论哪种，自动点赞都不得给点赞人发活动奖励**（L1 用虚拟号点赞断言无记录）。
3. `occurredAt = e.createdAt()`；候选 `instantActivities(LIKE, occurredAt)`。
4. 范围：活动话题为空 = 不限；否则按 `e.postId()` 查 `content_topics`（一次查询，本事件所有候选活动共用）求交。
5. 命中 → `reserveAndExecute(…, LIKE, postId, null, GrowthIdemKeys.activityLike(a, likerId, postId), occurredAt)`。
6. 执行完后复查 `ContentLikeRepository.existsByPostIdAndUserId(postId, likerId)`：不在了 → 调 `OpsActivityReclaimer.onUnlike(postId, likerId)`（本 story 先建接口 + 空实现，1-4 换成真实现；复查抛错按「仍在」处理）。
7. 取消后再点同一帖：键已存在 → 不再发（PRD「取消后再点不重复算」）。

### AC5 — 评论 `[L0]` `[L1]`
`onCommented(ContentCommentedEvent e)`：
1. `e.commenterId() == e.contentAuthorId()` 或 `e.contentAuthorId() <= 0`（帖已消失）→ 返回。
2. `occurredAt` = `comments.created_at`（`CommentRepository.findById(e.commentId())`；查不到 → 返回）。**不用** `e.createdAt()`——那是评论变可见的时刻（架构 §1 #3，Q-11）。
3. 候选 `instantActivities(COMMENT, occurredAt)`；范围同点赞（按 `e.postId()` 查话题）。
4. 命中 → `reserveAndExecute(…, COMMENT, postId, commentId, GrowthIdemKeys.activityComment(a, commenterId, postId), occurredAt)`。同一人同一帖多条评论、删了再评 → 同键，只算一次。

### AC6 — 匹配查询与纯函数 `[L0]`
- `OpsActivityMatchQuery`（`NamedParameterJdbcTemplate`，走 1-1 的 `ix_ops_activities_match` 索引）返回 `MatchCandidate(long id, Set<Long> topicIds, Set<String> contentTypes)`。
- 纯函数 `OpsActivityScope.matches(candidate, ActivityAction, Set<Long> postTopicIds, String contentType)`：话题空 = 不限（仅 LIKE / COMMENT 会出现）、话题交集、内容类型。
- L0：`OpsActivityScopeTest`；`OpsActivityContentListenerTest`（Mockito）：开关关 → 不查活动；私密帖 / 自赞 / 自评 / 帖已消失跳过；评论用 `comments.created_at` 而非事件时间；一个活动抛错不影响第二个；点赞后复查不在 → 调 `OpsActivityReclaimer.onUnlike`。

### AC7 — 集成 `[L1]`
`OpsActivityInstantFlowIntegrationTest`（直接发布事件 + 等异步，或照现有 growth 监听集成测试的同步执行器写法）：
1. 发帖活动（#话题 A、Diary + Moment、20 EXP + 500 PawCoin、每人每天 1 / 活动内 2、总 3 份）：用户 1 一天发 2 帖带 #A → 只第 1 帖得奖；第二天再发 → 得奖；第三天 → 不得（活动内 2 次）；用户 2、3 各发 → 第 3 份给用户 2、用户 3 不得（总 3 份）且活动显示「已发完」。
2. Tips 类型、不带话题、私密帖 → 不得。
3. 活动结束前 1 秒创建、结束后过审的帖子 → 得奖；结束后创建的 → 不得。
4. 两个进行中的活动同话题 → 两个都发（各一条记录）。
5. 点赞活动（不限话题，5 EXP）：赞别人帖得 EXP、赞自己不得；取消再赞同帖不再发；虚拟号点赞无记录。
6. 评论活动：同一人同帖评论 3 条只 1 次；自评不得；评论审核中、活动结束后才可见 → 按创建时间仍得奖。
7. 停发用户（直接插 `ops_activity_user_stops`）→ 之后的行为不再有记录；总开关关 → 无记录。
