## Story

As a 自动点赞任务,
I want 每天 10:30 / 16:30 各排一轮：每个作者最多一帖、轮流、时间在 3 小时内随机，并且多台实例同时跑也只排一次,
so that 作者一天最多收到 2 次自动点赞提醒，提醒不会扎堆在同一分钟。

## Acceptance Criteria

**AC1 — 两张表** `[L0]` `[L1]`（L-7）
迁移 `V20261115_0520__init_auto_like_runs_and_logs.sql`：
- `auto_like_runs`：`id` identity PK；`run_date DATE NOT NULL`（WIB 日期）；`slot VARCHAR(8) NOT NULL CHECK (slot IN ('MORNING','EVENING'))`；`started_at`、`window_end TIMESTAMPTZ NOT NULL`；`status VARCHAR(8) NOT NULL CHECK (status IN ('ACTIVE','DONE','STOPPED'))`；`stop_reason VARCHAR(32)`；`launch BOOLEAN NOT NULL`；`checked_count`、`joined_count`、`planned_count`、`consecutive_failures INTEGER NOT NULL DEFAULT 0`；`created_at`、`updated_at`；`CONSTRAINT uq_auto_like_runs_slot UNIQUE (run_date, slot)`。
- `auto_like_logs`：`id` identity PK；`run_id BIGINT NOT NULL REFERENCES auto_like_runs(id)`；`post_id BIGINT NOT NULL REFERENCES content_posts(id) ON DELETE CASCADE`（**不设**指向 `content_likes` 的外键）；`run_date`、`slot`（同上 CHECK）；`planned_at`、`window_end TIMESTAMPTZ NOT NULL`；`status VARCHAR(16) NOT NULL CHECK (status IN ('PLANNED','MISSED','LIKED','REACHED_TARGET','SKIPPED_REVIEW','POST_GONE','NO_IDENTITY','FAILED'))`；`virtual_user_id BIGINT`；`like_count_before INTEGER`；`error_code VARCHAR(64)`；`attempted_at TIMESTAMPTZ`；`created_at`、`updated_at`；`CONSTRAINT uq_auto_like_logs_post_slot UNIQUE (post_id, run_date, slot)`；索引 `ix_auto_like_logs_due ON (planned_at) WHERE status = 'PLANNED'`、`ix_auto_like_logs_liked_at ON (attempted_at) WHERE status = 'LIKED'`、`ix_auto_like_logs_run ON (run_id)`。
- 表与列 `COMMENT ON`；顶部注释写清各状态含义（照 `V20260929_1317__init_auto_comment_logs.sql` 写法）与「只存 id 和计数，不存帖子内容」。
- 实体 `AutoLikeRun` / `AutoLikeLog`、枚举 `AutoLikeSlot`、`AutoLikeRunStatus`、`AutoLikeLogStatus`、仓库。

**AC2 — 定时入口 `AutoLikeJob`** `[L0]`（FR-212、A-AC40）
```java
@Scheduled(cron = "${petgo.auto-like.morning-cron:0 30 10 * * *}", zone = "Asia/Jakarta") public void morning() { plan(AutoLikeSlot.MORNING); }
@Scheduled(cron = "${petgo.auto-like.evening-cron:0 30 16 * * *}", zone = "Asia/Jakarta") public void evening() { plan(AutoLikeSlot.EVENING); }
```
- 🔴 `zone` 必须显式写（容器默认 UTC）。
- `plan`：开关关 → `log.info("auto like disabled, skip {} run", slot)` 返回；否则调 `AutoLikePlanner.plan(slot, clock.instant())`（仓库没有 `Clock` bean；照 `social/service/FollowSuggestionService.java:41-46` 写法：`@Autowired` 主构造器默认 `Clock.systemUTC()`，包内构造器可传入固定钟，便于 2.3 / 2.4 的 L1 拨钟）；整体 `try/catch RuntimeException` 只 `log.warn` 类名（不让调度线程崩）。
- 与 `AutoCommentJob` 无任何共享状态（A-AC3）。

**AC3 — 计划事务 `AutoLikePlanner.plan(slot, now)`** `[L0]` `[L1]`（L-6、L-8）
`TransactionTemplate`（`PROPAGATION_REQUIRES_NEW`）内按序：
1. `SELECT pg_try_advisory_xact_lock(hashtext('auto_like_plan'))` → false：`log.warn("auto like {} plan skipped: another instance is planning", slot)`，返回 `PlanResult.skipped(LOCKED)`。
2. 上一轮未结束：存在 `status = 'ACTIVE' AND window_end > now` 的 run → `log.warn("auto like {} run skipped: previous run still in progress", slot)`，返回 `skipped(OVERLAP)`，**不写 run 行**（A-AC1）。
3. `run_date = LocalDate.ofInstant(now, ScheduleWindow.WIB)`；`INSERT INTO auto_like_runs … ON CONFLICT ON CONSTRAINT uq_auto_like_runs_slot DO NOTHING RETURNING id` → 无返回：`skipped(ALREADY_PLANNED)`（另一实例已排，A-AC2）。`window_end = now + spreadWindow`，`status = ACTIVE`。
4. `checkStep.run(now)`（2.1）→ 回写 `launch`、`checked_count`、`joined_count`。
5. 号池（VIRTUAL + `isEnabled` + 未注销 + `status == UserStatus.ACTIVE`，抽成 `AutoLikeVirtualPool.load()` 供 2.3 复用）为空 → run `STOPPED / NO_POOL`，`log.warn("auto like {} run stopped: no usable virtual account", slot)`；**检查结果照常提交**、不排期、不关任何帖（A-AC26，Q-3）。
6. 排期：取全部 `joined AND left_at IS NULL` 的目标行，按 `author_id` 分组，组内按 `last_liked_at NULLS FIRST, post_created_at, post_id` 取前 `maxLikesPerAuthorPerRun` 条（A-AC43）；入选行按 `post_created_at, post_id` 升序（最老优先，A1）逐条写 `auto_like_logs`：`status = PLANNED`、`planned_at = now + random[0, spreadWindow)`（毫秒）、`window_end`、`run_id / run_date / slot`。**不设每轮上限**（A-AC14）。写入用 `ON CONFLICT ON CONSTRAINT uq_auto_like_logs_post_slot DO NOTHING`。
7. 回写 `planned_count`；提交；`log.info("auto like {} planned: launch={} checked={} joined={} planned={} tookMs={}", …)`（只有数字）。

- 随机源可注入（构造器重载 + `@Autowired` 标在主构造器上——🔴 双构造器不标 `@Autowired` 启动即崩，`VirtualIdentityPicker` 注释里记过这个坑）。
- 分组选帖可以在 Java 里做（集合约 600–800 行），也可以用 `ROW_NUMBER() OVER (PARTITION BY author_id ORDER BY …)` 一条 SQL；二选一，测试覆盖轮流规则即可。

**AC4 — 每作者每轮 1 帖、轮流** `[L1]`（FR-214、A-AC43、AC44）
- 作者有 3 帖在集合 → 每轮只排 1 帖；接下来 3 轮各排一帖，任何一帖第二次被排之前另外两帖都已各排一次（`last_liked_at` 由 2.3 写，本 story 的 L1 直接改库模拟）。没排到的帖留在集合。
- 任何作者在一个 WIB 自然日内最多被排 2 次（早晚各一）。

**AC5 — 时间随机** `[L0]` `[L1]`（A-AC15）
同一轮所有 `planned_at ∈ [now, now + 3h)`；不早于本轮开始；顺序与帖子顺序无关（L0：注入固定随机序列断言；L1：100 帖 → `planned_at` 按帖子 id 排序后不单调）。

**AC6 — 两实例并发** `[L1]`（A-AC2）
两个线程同时 `plan(MORNING, 同一 now)` → 只有一条 run 行、每帖一条 `PLANNED`；另一线程返回 `LOCKED` 或 `ALREADY_PLANNED`。

### 关键语义
- 「一轮」= 一个槽（日期 + 早 / 晚）。默认 cron 下早晚相隔 6h / 18h，大于 3h 窗口，第 2 步「上一轮未结束」只在 stag 把 cron 调密时才会命中。
- 计划阶段只写库、不点赞、不发事件，所以整轮放一个事务是安全的；上线首轮约 1,400 帖检查 + 约 820 条排期，单事务秒级。
- 本 story 结束时，`PLANNED` 行不会被消费（2.3 才有派发器）——这是预期，测试不要等派发。

- 实现说明：
  - 计划事务用 `NamedParameterJdbcTemplate` + `TransactionTemplate(REQUIRES_NEW)`（照 `TopicHeatJob`）；`AutoLikeCheckStep` 的 JPA 原生写入与之共用同一事务（`MANDATORY`）。
  - 分组轮流抽成纯函数 `AutoLikeTurnPicker.pick(open, perAuthor)`（Java 内分组）。随机源为可注入的 `LongUnaryOperator`（默认 `ThreadLocalRandom`）；`AutoLikePlanner` 与 `AutoLikeJob` 双构造器，主构造器标 `@Autowired`。
  - 在「上一轮未结束」判定**之前**加了一次「本槽已存在」预查（返回 `ALREADY_PLANNED`）：否则第二个实例在第一个提交之后拿到锁时会因第一轮 ACTIVE 而返回 `OVERLAP`，与 AC6「另一线程返回 LOCKED 或 ALREADY_PLANNED」不符。`INSERT … ON CONFLICT … RETURNING` 仍保留兜底。
  - 实体 `AutoLikeRun` / `AutoLikeLog`（以及 2.1 的 `AutoLikeTarget`）标 `@Immutable`：写入全走原生 SQL，防止后续误 `save` 覆盖。
- **待确认**（复审提出，按架构原文未改）：
  1. 拿不到 advisory 锁即跳过、不重试（L-6 原文）。若持锁实例的计划事务回滚，本槽当天不会再排；stag 若把早晚 cron 设成同一时刻，两个槽会抢同一把锁，输的那个被跳过。
  2. `planned_at ∈ [now, now + spread)`（AC5 原文）：落在窗口最后一个派发间隔（默认 60s）内的行，可能被下一 tick 收成 `MISSED`（约 0.5%，MISSED 不计失败，帖子下一轮再来）。若要避免可把随机上界收窄为 `spread − dispatchInterval`，需主会话拍板。
  3. 号池为空时，本轮检查步骤里的 `MAX_AGE` / `TOO_MANY_FAILURES` 关闭照常生效（L-8 顺序：关闭在号池判定之前）；「不关任何帖」理解为不因号池为空而关帖。
- 本 story 结束时 `PLANNED` 行不会被消费（派发器在 2.3）。
