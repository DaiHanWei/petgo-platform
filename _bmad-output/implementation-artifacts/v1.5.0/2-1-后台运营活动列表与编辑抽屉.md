## Story

As a 运营,
I want 在「成长体系」页的「运营活动」页签里建、改、发布、删除活动,
so that 办活动不再需要研发或手工补发。

## Acceptance Criteria

### AC1 — 页签与列表（C1 ~ C3）`[L0]` `[L1]`
1. `T/growth.html` `.tabs` 末尾加第 4 个 `<button data-gtab="activities">`（`admin.v150.activity.tab`「运营活动」），面板 `<section data-gtab-panel="activities">` 引 `T/fragments/growth-activities.html :: panel`；`tab=activities` 时默认选中（`AdminGrowthConfigController` 的 `tab` 参数放行该值）。页头「批量发放」**不动**。
2. 面板：工具栏（状态下拉「全部状态 / 草稿 / 未开始 / 进行中 / 已发完 / 待发放 / 已结束」、名称搜索框、右侧「新建活动」——仅 `growth.config_edit` 可见）；表格 10 列照 PRD §3.8 / C1：名称（ID / EN 两行）、行为、范围（话题 `#名` 逗号连接，空 =「不限」）、发放方式、每份奖励（摘要：`20 EXP · 500 PawCoin · 优惠券 · KTP 高清解锁 1 次`；排名 =「{n} 档」）、时间（WIB，`dd/MM HH:mm – dd/MM HH:mm`）、状态徽标、参与人数、已发出（`27,360 EXP · 684,000 PawCoin · 1,000 张券 · n 次`，无则「—」）、操作（查看 → 详情页；编辑 → 抽屉；草稿另有删除）。数字千分位 `formatInteger(…, 'COMMA')`。
3. 状态徽标配色照执行说明：进行中 `badge-ok`、未开始 info、已发完 warn、待发放 danger、草稿 / 已结束 muted。
4. 筛选 / 搜索走 htmx 刷新 `GET /admin/growth/activities/list?status=&q=&page=`；空态：无任何活动 → C2（`.empty` + 🎯 + 「新建活动」）；有筛选无结果 → C3（🔍 + 「清除筛选」）。分页 20。
5. 总开关 `OPS_CAMPAIGN` 关闭时，面板顶部黄条（Q-7 新文案 `admin.v150.activity.campaignDisabledBanner`）。
6. L1：`AdminOpsActivityPageIntegrationTest`：页签渲染、只读权限无「新建活动」、状态筛选、搜索、空态两种。

### AC2 — 新建 / 编辑抽屉（D1 ~ D8、D12 ~ D14）`[L0]` `[L1]`
1. `T/fragments/drawer-growth-activity.html`，`tpl-shared :: drawer('growthactivity', …)`，480 宽；分组小标题「基本信息 / 规则 / 奖励（每份）/ 上限」；字段顺序：名称（ID）*、名称（EN）*（说明行）→ 备注 → 开始 / 结束（WIB，`datetime-local`，照 `drawer-ops-popup.html`）→ 行为（发帖 / 点赞 / 评论）→ 范围 → 发放方式 → 奖励 → 上限；吸底「保存草稿 / 发布」。
2. 联动（前端 + 服务端都拦）：
   - 发帖（D1）：「指定话题」（官方 ACTIVE 话题选择器，`GET /admin/growth/activities/topics?q=`，最多 3 个，至少 1 个）+「内容类型」Diary / Moment / Tips（默认全选；Diary = `GROWTH_MOMENT`、Moment = `DAILY`、Tips = `KNOWLEDGE`）。
   - 点赞（D2）：范围只剩「被赞帖子的话题」（可不选 = 不限）；「排名奖励」置灰 + 「排名奖励只限发帖」；奖励只有 EXP、无「＋ 添加奖励」，下方说明「点赞活动只能发 EXP…」；无总份数必填。
   - 评论（D3）：「被评论帖子的话题」（可不选）；排名置灰；奖励 6 种全可加。
3. 奖励（D4 ~ D6）：「＋ 添加奖励」下拉 6 种（EXP、PawCoin、优惠券、KTP 高清解锁、性格测试解锁、免费 Rp1.000 礼物），已加过的置灰；每项一行「类型 + 数值」右对齐；KTP 多一个模板下拉（8 款 + 「任意款」，8 款显示名复用现有 KTP 卡种后台文案 key，若无则用 `admin.v150.activity.ktp.<TEMPLATE>`，Q-7）；优惠券下拉（D5）来自 `GET /admin/growth/activities/coupons?q=`（`ActivityCouponIssuer.selectable`），每项第二行灰字「剩 {n} · 每人 {m}」（不限 → 「剩 不限」），下拉宽度跟输入框。
4. 发放方式「排名奖励」（D7）：奖励区换成档位编辑——每档卡（圆角 10，内奖励框 6）= 名次起止 + 一个奖励组合；「＋ 添加档位」到第 5 档后消失；上限区隐藏。
5. 上限（D6）：每人每天（可空）、每人活动内（必填 *）、活动总份数（奖励含 PawCoin 或券时加 * 必填，说明「奖励含 PawCoin 或优惠券时必填；发满自动停止」）。
6. 422（D8）：服务端一次返回全部字段错误（`OpsActivityRules` 的 `FieldError` → 字段下红字 + 底部「{n} 处填写有误」），照 `drawer-growth-rule :: errors`；输入框最小高度 32（核对结论）。
7. 编辑：未开始（D12）全部可改，标题「编辑活动」+ 状态徽标，底部只有「保存」→ 确认弹层 `cm.diffs`（旧值 → 新值，只列改动项，`OpsActivityConfigService.update` 返回的改动项）；进行中 / 已发完（D13）只有结束时间可改（只能往后）、其余灰底只读，顶部提示条（进行中 / 已发完两种文案见 A.2），左下「提前结束」→ E6（2-2 实现确认弹层，本 story 放按钮）；已结束（D14）全部只读，标题「活动设置」，底部只有「关闭」。
8. 缺 `user.grant_pawcoin`（D11）：奖励含 PawCoin 时「发布」置灰 + 原因（`.why.wn` 写法），「保存草稿」照常可用；直接 POST 发布 → 403。
9. L0：`AdminOpsActivityFormTest`（表单 ↔ `OpsActivityDraft` 转换：WIB 时间转 UTC、券 token ↔ id、KTP 模板、档位解析；非法数字串 → 字段错误而不是 500）。
10. L1：渲染新建 / 编辑三种状态抽屉；点赞活动提交 PawCoin 奖励 → 422；进行中提交改话题 → 409 toast；无 PawCoin 权限发布含 PawCoin → 403。

### AC3 — 保存、发布确认、删除草稿（C5、D9、D10）`[L0]` `[L1]`
1. 「保存草稿」→ `POST /admin/growth/activities`（新建）/ `POST …/{token}`（草稿保存）：成功关抽屉 + toast + 列表刷新。
2. 「发布」→ `POST …/publish/confirm`：服务端确认弹层 `confirm-modal.html`，`cm.facts` 逐项复述名称、时间、行为与范围、发放方式、每份奖励（或各档）、上限，`cm.note`「发布后，进行中只能延长结束时间或提前结束。」；有重叠（`publishPreview` 返回）→ 顶部黄条 `cm.danger + warnBanner`「和进行中的「{name}」行为、话题重叠：同一条帖子两个活动都会发奖。」，按钮改「仍然发布」（D9，不另弹）。确认 → `POST …/{token}/publish`（未保存的新建活动先存草稿再发布，同一请求同一事务）→ toast「已发布」。
3. 删除（C5）：仅草稿行有「删除」→ 危险确认「删除草稿？「{name}」删除后不能恢复。」→ `POST …/{token}/delete`。
4. 审计（同一事务，`AdminAuditService.record`）：`OPS_ACTIVITY_CREATED`、`OPS_ACTIVITY_UPDATED`（摘要 = 改动字段名列表）、`OPS_ACTIVITY_PUBLISHED`、`OPS_ACTIVITY_DRAFT_DELETED`；`AuditActions` 常量 + `admin.audit.action.<CODE>` 四个 properties（`AuditActionLabelsTest` 守卫）。本 story 同时把 2-2 / 2-3 要用的另外 6 个审计码（`OPS_ACTIVITY_ENDED_EARLY`、`OPS_ACTIVITY_USER_STOPPED`、`OPS_ACTIVITY_GRANTS_RETRIED`、`OPS_ACTIVITY_RANK_EXCLUDED`、`OPS_ACTIVITY_RANK_RESTORED`、`OPS_ACTIVITY_RANK_GRANTED`）一并登记。
5. L0：`AdminOpsActivityServiceTest`（Mockito）：发布前权限判断按奖励内容（单份 / 任一档含 PawCoin）；审计码与摘要。
6. L1：发布确认弹层含重叠黄条与「仍然发布」；删除非草稿 409；审计行写入。
