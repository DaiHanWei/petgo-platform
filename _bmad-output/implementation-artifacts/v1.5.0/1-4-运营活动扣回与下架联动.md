# Story 1.4: 运营活动扣回与下架联动（后端）

Status: ready-for-dev

> 版本 v1.5.0 · 会话 ⑥ ops-activity · 分支 `feat/1.5.0-ops-activity`
> 口径优先级：`decision-log.md`（11-11 非 EXP 不扣回、11-12 排名奖不扣回）> PRD §3.4「扣回」、§3.5「发放时帖子已被下架…不发放」「排名奖发出后一律不扣回」、§6「下架扣回」> 架构 OA-15、OA-17 第 3 条、§1 #14。
> 前置：1-3（`OpsActivityReclaimer` 接口已在）。名单表在 1-1 已建，1-5 才写入；本 story 对名单表的更新在名单为空时是空操作。
> 范围层：**只后端**。

## Story

As a 运营,
I want 帖子被下架、点赞被取消时，系统自动扣回该行为在参与即奖活动里得到的 EXP,
so that 刷帖 / 刷赞拿不走活动 EXP，而 PawCoin / 券 / 次数不会扣成负数引发客诉。

## Acceptance Criteria

### AC1 — 取消点赞扣回 `[L0]` `[L1]`
`OpsActivityReclaimer` 的真实现 `OpsActivityReclaimService`（替换 1-3 的空实现）：
1. 新监听方法（放 `OpsActivityContentListener`）`onUnliked(ContentUnlikedEvent e)`（`@Async @TransactionalEventListener`）→ `reclaimer.onUnlike(e.postId(), e.likerId())`。
2. `onUnlike(postId, likerId)`：查 `ops_activity_grants WHERE trigger_kind = 'LIKE' AND post_id = :p AND user_id = :u AND status = 'SENT' AND exp_granted > exp_reclaimed`（可能多个活动各一条），逐条：
   - `GrowthLedgerService.reverseDetailed(new ReverseCommand(grant.idemKey, ReverseReason.UNLIKE, GrowthIdemKeys.SOURCE_UNLIKE, null))`；
   - `ReverseOutcome.done(amount, …)` → 条件更新 `exp_reclaimed = exp_reclaimed + :amount WHERE id = :id AND exp_reclaimed + :amount <= exp_granted`；`alreadyReversed / nothingToReverse` → 不改。
   - 每条独立事务（REQUIRES_NEW），一条失败不影响其他条；失败记 ERROR（grantId / 异常类名）。
3. 点赞活动只有 EXP（1-1 校验保证），所以这里只有 EXP 可扣；即使历史数据里有别的奖励也**不碰**。
4. 与 1-3 点赞复查共用同一入口：两条路径谁先到都只扣一次（成长值反向键 `REV:{原流水 id}:UNLIKE` 唯一）。

### AC2 — 运营下架扣回 `[L0]` `[L1]`
1. 监听 `onRemoved(ContentRemovedEvent e)`（只有运营下架发此事件；作者自删不发 → 不扣，PRD 1.4.0 口径）→ `reclaimer.onTakedown(e.postId())`。
2. `onTakedown(postId)`：
   - 参与即奖：`trigger_kind = 'POST' AND post_id = :p AND status = 'SENT' AND exp_granted > exp_reclaimed` 逐条 `reverseDetailed(new ReverseCommand(idemKey, ReverseReason.TAKEDOWN, GrowthIdemKeys.SOURCE_TAKEDOWN, null))` + 同 AC1 更新 `exp_reclaimed`。
   - 🔴 **`trigger_kind = 'RANK'`（`ACTRANK:` 键）一律跳过**（排名奖不扣，PRD §3.5）；查询条件里写死 `trigger_kind = 'POST'`，并加断言测试。
   - 该帖上别人点赞 / 评论得到的活动 EXP **不扣**（与日常规则同口径：下架只扣发帖分；`doSoftDelete` 删点赞行时也不发取消点赞事件，架构 §1 #14）。
   - 排名名单联动：`UPDATE ops_activity_rank_entries SET status = 'NOT_GRANTED', reason = 'POST_REMOVED', updated_at = now() WHERE post_id = :p AND status = 'PENDING'`（不递补，名次保留；名单已 `GRANTED` 的行不动）。
3. 只扣实际入账的部分、不扣成负数——由 `reverseDetailed` 保证（`min(原值剩余, 账户累计)`）；`exp_reclaimed` 记实扣额。
4. 下架后 `restore`：不补回（同日常规则 P-1）。

### AC3 — 不扣的东西 `[L0]`
- PawCoin、优惠券、权益次数：本 story **不提供**任何扣减代码路径（L0 守卫：`OpsActivityReclaimService` 源码里不出现 `PawCoinWalletService`、`CouponLedgerService`、`EntitlementCreditService`）。
- 评论被删：不扣（不监听评论删除）。

### AC4 — 测试 `[L0]` `[L1]`
- L0：`OpsActivityReclaimServiceTest`（Mockito）：只查 `trigger_kind = 'POST'` 的下架（断言 SQL 参数 / 方法名）；多条分别扣、一条失败其他继续；`alreadyReversed` 不改 `exp_reclaimed`；`OpsActivityReclaimGuardTest`（AC3 源码守卫）。
- L1：`OpsActivityReclaimIntegrationTest`：
  1. 发帖活动 20 EXP + 500 PawCoin → 运营下架 → 成长值反向流水 −20（`note` 与原行同、`activity_id` 有值）、`exp_reclaimed = 20`、PawCoin 余额不变；作者自删 → 不扣。
  2. 用户 EXP 累计只剩 5 时下架 → 只扣 5、`exp_reclaimed = 5`、累计为 0。
  3. 点赞活动 5 EXP → 取消点赞 → 扣 5；再赞同帖 → 不再发、不再扣。
  4. 排名记录（手工插 `trigger_kind = 'RANK'` 的 `SENT` 记录 + 对应成长值流水）→ 下架后不扣。
  5. 名单里该帖的 `PENDING` 行 → `NOT_GRANTED / POST_REMOVED`。
