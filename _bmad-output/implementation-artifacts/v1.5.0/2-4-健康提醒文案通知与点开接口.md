# Story 2.4: 健康提醒文案、通知与点开接口（后端）

Status: ready-for-dev

> 版本 v1.5.0 · 会话 ① 健康记录提醒 · 分支 `feat/1.5.0-health-reminder`
> 口径优先级：CROSS-STORY-DECISIONS 地基段 > 架构增量 §0 Z-4/Z-5/Z-6/Z-7/Z-13/Z-15、§5.3、§5.4、§6.4、§8 > PRD FR-167、FR-169、FR-170、§4、附录 A（文案原文）、附录 C（选行规则）、AC46 ~ AC49、AC55 ~ AC58、AC61 ~ AC63 > UI 稿 G1、G2、E5。

> 范围层：**只后端**。App 的点开页、通知中心样式归 3.4。

## Story

As a 宠物主人,
I want 健康推送和通知中心写着具体的话（宠物名、疫苗名、第几针、隔了多久），点开直接到对应宠物的健康页或预填好的表单,
so that 一看就懂、两下就能记好。

## Acceptance Criteria

### AC1 — 文案 i18n `[L0]`（PRD 附录 A、FR-169、架构 §5.3 ROW 表）
1. 在 `messages_id.properties`、`messages_en.properties`、`messages.properties`（= EN）写 `notify.health.<ROW>.title` / `.body`，ROW 共 28 个（架构 §5.3 表）。**文案逐字取 PRD 附录 A**（A.1 ~ A.4 的 ID / EN 列）；占位符按顺序编号：`{0}` 宠物名、其余按 ROW 需要（在 properties 注释里写清每个编号含义）。若仓库已有「四个 properties 键必须一致」的守卫测试，`messages_zh_CN.properties` 也补同键（内容用 EN）。
2. 带参数串走 `MessageFormat`：单引号写 `''`（EN 的 `{nama}'s` → `{0}''s`）。EN 计数用 choice：`{n,choice,1#1 day|1<{n} days}`、周 / 月同理（`{interval}` 传「数字 + 单位」两个参数，单位用 choice 选 `week/weeks`、`month/months`；ID 直接「{n} minggu / bulan」）。
3. A.5 中性模板**不写**（PRD：v1 不用）。

### AC2 — 文案渲染 `[L0]`（PRD FR-166 Same-type merge copy、FR-169 选行、附录 C Placeholders、AC56、AC57）
1. `HealthCopyRenderer.render(SendGroup, PetHealthSnapshot, Locale, LocalDate sendDate)` → `(title, body, notificationKind)`；locale：`accountQuery.localeOf(userId)` 为 `en` → EN，其余 → ID。
2. 选行规则逐字按架构 §5.3 表（Rabies D-7、Series D-Day 仅单条且有到期剂次、Internal Young = 到期日早于满 6 个月且物种 CAT/DOG、D+3 external dog 变体、合并时的选行与 `notification_kind`）。
3. 占位符：`{nama}` 缺 → `hewanmu` / `your pet`；`{vaksin}` = 到期疫苗名（预设标签，OTHER 用原文；合并「 & 」连接）；`{dosis}`；`{hari}` = 发送日 − Next date（合并取最大）；`{hari_lagi}` = Next date − 发送日（合并取最小）；`{interval}` = 来源记录 event date → 发送日：<56 天按整周（向下取整、最小 1），否则按整月四舍五入（合并取最大）；`{kucing/anjing}` / `{kittens/puppies}`；`{judul}`（合并「 & 」）。用户文本去换行 / 控制字符，`{vaksin}` ≤30、`{judul}` ≤20。缺值 → 用不带该占位符的变体（如 Young 缺物种词 → 用 generic Internal）。
4. 用例：AC56 四句；AC57（23 个 kind × 各推送点 × ID/EN 全部渲染且无残留 `{`；`{hari}`=1 EN「It's 1 day late, but not too late!」ID「Sudah lewat 1 hari…」；Internal D-Day 10 天后 EN「It's been 1 week since the last one.」）；AC37 合并文案（两疫苗 D-Day → generic）；AC63 合并 `notification_kind=DEWORM_FLEA_WORM_D_DAY`。

### AC3 — 通知落库与推送 `[L0]` `[L1]`（架构 §5.3、Z-5/Z-6/Z-7/Z-15）
1. `NotificationService.sendHealthReminder(long recipientUserId, NotificationType type, String title, String body, String targetRef)`（`REQUIRES_NEW`）→ `HealthPushOutcome(long notificationId, PushResult)`：落 `notifications`（`deepLinkType = type.name()`、`targetRef` = 健康通知 `public_token`、title / body = 已渲染文案）+ 角标；虚拟号 → `NO_TOKEN`；`!pushAllowed(recipient, type)` → `MUTED`（只留通知中心，PRD AC44）；`pusher.pushToUserNow(...)` 返回 false → `FAILED`；否则 `SENT`。
2. `PushExitStructureTest.PUSHER_CALLER_METHODS` 加 `"NotificationService#sendHealthReminder"`；`pushAllowed` 次数 = 推送调用次数（该测试会数）。
3. `HealthReminderDispatcher implements HealthDispatchPort`：生成 32 位 base62 `public_token`（`SecureRandom`）→ 插 `health_notifications`（kind、point、origin、merged_count、deferred_days = 组内最大、route：合并 → PAGE，否则按 kind）→ 渲染 → `sendHealthReminder` → 回写 `push_result`、`inbox_notification_id`；组内各行 `SENT`、`sent_at`、`health_notification_id`。排队出队的成功投递回写 `last_queue_sent_date`。
4. 日志不记宠物名 / 文案 / 健康字段。

### AC4 — 通知中心旧版过滤 `[L0]` `[L1]`（架构 §6.4，PRD FR-166 Per device）
1. 通知列表接口读 `X-App-Version`；<1.5.0 → 过滤 `type` 以 `HEALTH_` 开头的行（游标分页仍正确：在 SQL 层过滤，不要捞出来再筛）。未读角标口径不变。

### AC5 — 点开接口 `[L0]` `[L1]`（架构 §5.4，PRD FR-167、AC46 ~ AC49、AC12）
1. `GET /api/v1/me/health-notifications/{token}/open?source=push|inbox`：JWT；token 不存在或不属于本人 → 404（ProblemDetail，不区分）。成功时把对应通知中心条目标已读（复用现有已读逻辑与角标递减）。
2. 返回体逐字按架构 §5.4；判定顺序：`PET_UNAVAILABLE`（宠物已删 / READ_ONLY / 非本人）→ `PAGE_SATISFIED`（承载的提醒都已满足，`focusRecordId` = 满足它的最新记录）→ 驱虫安全情形 `PAGE + safetyBoxes`（**按点开时的当前档案判**，怀孕在前）→ 按 `health_notifications.route`。
3. `prefill` 规则：D-Day / D+3 / D+7 / 补发 → `eventDateEmpty=false`（App 填今天）、到期疫苗 / 剂次 / 驱虫类型 / custom 名；FIRST_VACCINE → VACCINE；FIRST_DEWORM → DEWORM 不带类型；SPAY_NEUTER → NEUTER；CHECKUP → VET_VISIT；这四类 `eventDateEmpty=true`；LEGACY → DEWORM 不带类型；PAGE 路由带 `focusRecordId`（合并不带）。
4. `analytics` 对象（App 直接用来报 `health_notification_opened`）：`notificationId`=token、`notificationKind`、`pushPoint`、`origin`、`mergedCount`；枚举值小写蛇形。
5. 用例：AC46（看着 A 点 B 的 F4 第 2 剂 D-Day → `petId=B`、FORM、prefill VACCINE/F4/2）；AC47（D-7 → PAGE + focus）；AC48（已记过 → PAGE_SATISFIED + 新记录 id）；AC49（宠物已删 / 别人的 token → PET_UNAVAILABLE / 404）；AC12 四句（家里有猫的狗 External D-Day → PAGE+PERMETHRIN；怀孕猫 Internal D-Day → PAGE+PREGNANT；怀孕且家里有猫的母狗首驱虫 → 两个框、怀孕在前；家里有猫的狗 Internal D-Day → FORM）。

### AC6 — 后端埋点 `[L0]`（PRD §4、AC58、AC61 ~ AC63；架构 §8）
1. `HealthReminderAnalytics` 真实实现（替换 2.1 空实现），经 `AnalyticsClient.capture(AnalyticsDistinctId.of(userId), event, props)`：
   - `health_notification_sent`：`notification_id`、`pet_id`、`notification_kind`、`push_point`、`origin`、`push_result`（sent/muted/no_token/failed）、`merged_count`、`deferred_days`。
   - `health_reminder_sent`：每行一条，`reminder_id`、`notification_id`、`pet_id`、`reminder_kind`、`push_point`、`origin`、`record_id`（记录类）、`deferred_days`。
   - `health_reminder_cancelled`：`reminder_id`、`pet_id`、`reminder_kind`、`push_point`、`origin`、`reason`、`displaced_by`（skipped_cap / skipped_scheduled_push / expired_defer）、`by_record_id`（satisfied）。`old_app` 不发。
   - 不传明文 `user_id`（distinctId 已是哈希；PRD 的 `user_id` 属性以 distinctId 代替）。
2. 三个事件名常量 + 全部新属性键登记 `AnalyticsEventGuard` 白名单（`ALLOWED_EVENTS`、`ALLOWED_PROPERTY_KEYS`），守卫测试同步。
3. 幂等：只在行状态由 PENDING 迁移成功（`UPDATE … WHERE status='PENDING'` 影响 1 行）后发。
4. 用例：AC63 合并 / 跳过 / 顺延 / 重跑四段（合并 → 1 条 notification_sent + 2 条 reminder_sent 同 notification_id；跳过 → 只有 cancelled；顺延 1 天 → 发出那天 `deferred_days=1`；重跑 → 无重复）。
