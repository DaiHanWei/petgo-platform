## Story

As a 还没记过健康记录的宠物主人,
I want 系统按宠物年龄给我首针、首次驱虫、绝育、年度体检的建议；存量用户在上线时也只会一条条、隔几天收到,
so that 我被提醒到该做的事，又不会在上线当天被刷屏。

### AC2 — 体检到期 `[L0]`（架构 §4.4，PRD AC24、AC25、AC26、AC30）
1. `CheckupDueRule.due(PetHealthSnapshot, lastVisitDate, lastSentCheckupDate)` → `(dueDate, senior)`，算法逐字按架构 §4.4（base → 无生日 +12 → base 时 senior +6 → 否则 max(base+6, min(base+12, senior 生日))；senior：CAT 10 岁、DOG 7 岁；文案按 due 当天是否 senior）。
2. `lastVisitDate` = max(VET_VISIT 记录 event_date, `health_vet_consult_visits.visit_date`)；AI 分诊、疫苗都不算。
3. 用例：AC26 六个子句（2017-01-01 生的猫四个到访日；2020-01-01 生的狗两个到访日）原样写成参数化用例；AC25（2 岁狗 2027-03-05 兽医问诊 → 2028-03-05，2027-06-01 AI 分诊不影响）；AC30（due 2027-06-10，2027-06-01 问诊结束 → 改为 2028-06-01，10 Jun 不发；同日 Vet visit 记录等效；删掉该记录 → 回到 2027-06-10）；AC24（无生日：仍有体检，按 +12 个月；**无** senior 体检文案、无首针、无绝育建议）。

### AC3 — 档案类建议 `[L0]`（架构 §4.5，PRD FR-164 表、AC23、AC27、AC29）
1. `ProfileReminderRules.desired(PetHealthSnapshot, records, history, userLaunchDate, fromDate)` → `List<DesiredReminder>`（origin=PROFILE、point=NONE），实现 2.1 的 `ProfileReminderSource`。只 CAT / DOG；READ_ONLY → 空；用户没有 `health_reminder_user_launch` 行 → 空。
2. normal date / 跳过条件逐字按架构 §4.5 表；normal date < `userLaunchDate` 的不生成（归排队）；已 SENT 过（一次性三类）不再生成；CHECKUP 由 AC2 算出 due，键含 due_date。
3. SPAY_NEUTER：sex=null 不生成；sex 已填且 `sex_set_at` 非空 → normal = max(原 normal, `nextRunDate(sex_set_at)`)；发送日已满 12 个月的不生成（按 normal date 判，2.3 发送日再判一次）。
4. 用例：AC23（2027-01-01 生、无疫苗 → 2027-02-12）；AC29 全部（8 个月母猫 3/1 建档 → 3/8 首驱虫、3/15 绝育、无首针；13 个月不发绝育；7 个月 sex 空 3/3 设 Female → 3/15；3/20 15:00 设 → 3/21）；UJ-3（3 个月母猫 → 下次日跑首针、第 7 天首驱虫、5 个月绝育）；AC17（狗不论体重品种 6 个月绝育建议、7 岁起 senior 间隔）。

### AC4 — 上线开关与首跑 `[L0]` `[L1]`（架构 §4.7，PRD §0 Launch、FR-164 Launch rules）
1. `HealthReminderSettingsService`：读 `health_reminder_settings`（每次日跑读一次，不缓存）。
2. `LaunchService.onRun(LocalDate D)`（由 2.3 日跑在开头调用）：
   - `enabled=true` 且 `launch_date` 为空 → 写 `launch_date = D`（**上线日 = 开关打开后第一次 10:00 日跑**）。
   - 对 `AppVersionGate.usersOnV150OrLater(有宠物的全部用户)`（分批 500）中还没有 `health_reminder_user_launch` 行的用户：建行 `launch_date = D`、`queue_start_date = D + (user_id mod 7)`；生成排队（AC5）；然后对其全部宠物 `rebuildPet`（档案类此时才生效）。首跑时这一步覆盖所有已在 1.5.0 的用户；之后每天只覆盖新升级的用户（个人上线，架构 §4.7 / 待拍板 Q-7）。
   - 首跑额外对**全部**宠物（含旧版用户的）`rebuildPet`，把回填记录的未来点排上（旧版用户的行到期时由 2.3 按门槛作废）。
3. `enabled=false` → 什么都不做。

### AC5 — 排队生成 `[L0]`（PRD FR-164 Launch queue、AC27、AC28）
1. `LaunchQueueRules.items(user 的全部 CAT/DOG 宠物快照与记录, userLaunchDate)` → 有序列表：资格（只有 normal date < userLaunchDate 的才进队）：FIRST_VACCINE（6 周–6 个月、无疫苗记录）、SPAY_NEUTER（<12 个月、已过触发日、sex 已填、未绝育且无 Neuter 记录）、FIRST_DEWORM（无驱虫记录）、CHECKUP（due < userLaunchDate）。排序：种类优先级 FIRST_VACCINE > SPAY_NEUTER > FIRST_DEWORM > CHECKUP，同类按宠物建档先后。
2. 落库：`origin=LAUNCH_QUEUE`、`queue_position` 递增、`due_date = userLaunchDate`、`send_date = queue_start_date`、`push_point=NONE`、tier/movable 按 kind。
3. 用例：AC27（3 岁 UNKNOWN 猫不进绝育队；8 个月未绝育母猫（sex 已填）进队）；AC28 的出队顺序（幼猫首针 → 狗首驱虫 → 幼猫首驱虫 → 狗体检）与「上线前 3 天建档的宠物不进队、按 add+7 正常发」。

### AC6 — 出队 `[L0]`（PRD FR-164「Real reminders come first」「Checked again」、AC28、AC43）
1. `LaunchQueueService.pickForUser(userId, D, boolean userHasAnyPushToday, queuePaused)` → 0 或 1 行：`queuePaused` → 无；D < queue_start_date → 无；`last_queue_sent_date` 非空且 > D−3 → 无；`userHasAnyPushToday` → 无（未出队的行 `send_date` 改为 D+1）；否则按 `queue_position` 取第一条做发送日再校验（跳过条件成立、FIRST_VACCINE 遇怀孕或已满 6 个月 → `CANCELLED queue_recheck` 并发埋点，继续下一条）。选中的由 2.3 投递，投递成功后写 `last_queue_sent_date = D`。
2. 排队行**永不** `expired_defer`、不受 3 天上限。
3. 排队发出的 CHECKUP：该 send_date 作为下一周期的 base（2.1 的 `ReminderHistory` 已含已发 CHECKUP 日期）。
4. 用例：AC28 时间线（start = launch+2：+2 首针、+5、+8、+11；+8 有狗生日 → 幼猫首驱虫挪到 +9、体检挪到 +12；上线当天无排队推送）；AC43（1.4.1 用户 3/10 升级 → 3/10 当天起个人队列，两条相隔 ≥3 天）。

### 上线 runbook

> 开关无后台页；以下 SQL 一律在**确认操作者同意后**手工执行。日跑 cron `0 0 3 * * *` UTC = 每天 10:00 WIB（Story 2.3）。

1. **部署 V1.5.0 后端**：Flyway 依次跑 `V20261115_0100`、`0110`、`0120`、`0130`（`out-of-order=true` 常开）。应用启动时 `HealthLaunchBackfillRunner` 自动跑一次上线回填（`petgo.health-reminder.backfill-on-startup` 缺省 true）：
   - 日志依次出现 `health backfill batch pets=… changed=…`、`health backfill done pets=… changed=…`；
   - 核对：`SELECT backfill_done_at FROM health_reminder_settings WHERE id = 1;` 非空；之后重启见 `health backfill skipped: already done`。
   - 抽查：`SELECT vaccine_preset, count(*) FROM health_records WHERE record_origin = 'BACKFILL' AND type = 'VACCINE' GROUP BY 1;`
2. **开关默认关**（`enabled = FALSE`），此时日跑只记日志返回，不生成上线行、不发推送。
3. **App 1.5.0 上架后，先跟操作者确认**，再在生产库执行：
   `UPDATE health_reminder_settings SET enabled = TRUE, switched_on_at = now(), updated_at = now() WHERE id = 1;`
4. **下一次 10:00 WIB 日跑即上线日**（`LaunchService.onRun`）。核对：
   - `SELECT launch_date FROM health_reminder_settings WHERE id = 1;` = 当天；
   - `SELECT count(*) FROM health_reminder_user_launch WHERE launch_date = <当天>;` ≈ 当天已在 1.5.0 的用户数；
   - `SELECT reminder_kind, count(*) FROM health_reminders WHERE origin = 'LAUNCH_QUEUE' AND status = 'PENDING' GROUP BY 1;`
   - 日志 `health launch run day=… firstRun=true newUsers=… queued=…`。
   - 上线当天只有起始日 = 上线日的用户（约 1/7）会收到排队建议。
5. **个人上线**：之后每天日跑对新升级到 1.5.0 的用户建上线行（上线日 = 当天）并排队，日志 `firstRun=false newUsers=…`。
6. **暂停排队**（退订率 SM-C1 异常时）：`UPDATE health_reminder_settings SET queue_paused = TRUE, updated_at = now() WHERE id = 1;`，下一次日跑生效（排队行保留、每天后移，不过期）；恢复置 `FALSE`。
7. **紧急关停**：`UPDATE health_reminder_settings SET enabled = FALSE, updated_at = now() WHERE id = 1;`（已生成的行保留；重新打开后，发送日已过的非排队行在日跑第 ③ 步按 `missed_run` 作废）。
8. **回滚注意**：`launch_date` 只在为空时写一次；若要重新演练上线日，需同时清 `launch_date` 与 `health_reminder_user_launch`（仅限 stag）。

**待确认（按最保守做法实现）**
- **问诊到访日按 WIB**：`ConsultClosedEvent.eventDate` 现状是按 **UTC** 取的日期；架构要求所有日期 WIB。监听里按会话结束时刻 `COALESCE(pending_close_started_at, updated_at)` 换算 WIB 日期（与 0130 回填同口径），读不到会话行才用事件日期兜底。未改 consult 模块。
- **体检周期未发出**：PRD 只说「已发的体检」算 base；一个周期若被日跑作废（名额 / 顺延到期 / 错过日跑 / 生日占用 / 旧版），base 不前进，到期日会永远停在过去、之后再无体检。实现为把这类作废行的原定日（排队行取发送日）也当作周期终点。
- **到期日已过（但不早于上线日）的体检**（如补录了很早的 Vet visit）：改在下一跑发，否则该周期永远排不上。
- 首针 / 绝育建议的边界：建档当天恰为满 6 周 / 触发日时，按「建档后的下一跑」/「建档 + 14 天」，避免当天日跑已过而丢失。
- 排队资格不排除怀孕（PRD：发送日再判，怀孕则 `queue_recheck` 作废）。只读宠物的排队行在出队时以 `read_only` 作废。
- 个人上线的日跑只扫还没有上线行的宠物主（已上线用户不再每天过版本门槛）；单个用户排队失败只 warn、次日重试，不中断首跑的全宠重建。

**复审结论**：CONFIRMED 并已修——过期体检永不排上、首跑单个用户异常中断全宠重建、6 周 / 触发日当天建档的边界、出队不取宠物锁、排队体检周期终点取错、每日全量扫宠物主、出队重复查宠物。未改：排队资格不排除怀孕（PRD 原文发送日再判）、到访行显式删除与 FK 级联重复（story AC 要求显式删）。
