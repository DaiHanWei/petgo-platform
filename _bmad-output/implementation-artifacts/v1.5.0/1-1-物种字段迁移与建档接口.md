## Story

As a 新建档案的用户,
I want 建档时就能选到兔子、仓鼠等具体类型,
so that 我的宠物资料从一开始就准确，而系统里按猫 / 狗 / 其他走的逻辑一点不变。

### AC1 — 枚举 `PetSpecies` `[L0]`（D-1）
1. 新建 `com.tailtopia.profile.domain.PetSpecies`，常量**严格按此顺序**（App 守卫测试会逐个比对）：
   `CAT, DOG, RABBIT, HAMSTER, BIRD, CHICKEN, FISH, LIZARD, TURTLE, SUGAR_GLIDER, SNAKE, DUCK, FROG, GUINEA_PIG, CIVET, HEDGEHOG, HERMIT_CRAB, OTTER, SHEEP, COW, SPIDER, SQUIRREL, GOAT, CRAB, INSECT, MOUSE, OTHER`（27 个）。类注释写「只往后加；加值须同步迁移 CHECK 全集重建 + App `pet_species.dart`」。
2. `PetType group()`：CAT → CAT、DOG → DOG、其余 → OTHER。**全仓库唯一的大类推导**。
3. `PetSpecies pickerType()`：`CAT … GUINEA_PIG` 返回自己；`CIVET … MOUSE` 与 `OTHER` 返回 `OTHER`。
4. `String zhName()`：猫 / 狗 / 兔 / 仓鼠 / 鸟 / 鸡 / 鱼 / 蜥蜴 / 龟 / 蜜袋鼯 / 蛇 / 鸭 / 青蛙 / 豚鼠 / 麝香猫 / 迷你刺猬 / 寄居蟹 / 水獭 / 绵羊 / 牛 / 蜘蛛 / 松鼠 / 山羊 / 螃蟹 / 昆虫 / 鼠类 / 其他。
5. `static Optional<PetSpecies> parse(String raw)`：null / 空 → empty；trim + `toUpperCase(Locale.ROOT)` 后 `valueOf`，失败 → empty。
6. `static final String WIRE_PATTERN`：27 值 `|` 拼接（供 DTO `@Pattern` 用），单测断言它与 `values()` 一致。
7. 单测 `PetSpeciesTest`：27 个值逐个断言 `group()` / `pickerType()` / `zhName()`；`parse("rabbit")` = RABBIT；`parse("CATS")` = empty。

### AC4 — 建档 `POST /api/v1/pet-profiles` 接 `species` `[L0][L1]`（D-7、D-11）
1. `PetProfileCreateRequest` **末尾**追加 `@Pattern(regexp = PetSpecies.WIRE_PATTERN, message = "细分类型不合法") String species`；`petType` 的 `@NotBlank` 去掉（改服务层判）。现有 6 参 / 9 参便捷构造器保留，新增 10 参规范构造器（record 本身）。
2. `ProfileService.create` 解析（替换 `parsePetType` 调用处）：

   - `species` 为空 → `petType` 为空 → 422「宠物类型必选」（与现状同文案）；否则 `species = PetSpecies.valueOf(parsePetType(petType).name())`。
3. `PetProfile.create(..., species, ...)`；`milestoneService.assignRoster(saved.getId(), saved.getMilestoneTrack())`（= 大类）。
4. 建档**不写** `pet_type_changed_at`、不写修改记录（创建不算修改，PRD 3.3.1）。

Given 旧版请求 `{petType:"OTHER"}`，Then `pet_species=OTHER`、`pet_type=OTHER`、`milestone_track=OTHER`；Given `{species:"RABBIT"}`，Then `pet_type=OTHER`、里程碑 roster 为 G 清单（与现在的「其他」完全一致，PRD 3.1 AC4）；Given `{species:"CIVET"}` → `pet_type=OTHER`；Given `{petType:"CAT", species:"RABBIT"}` → 422；Given `{species:"DRAGON"}` → 422（Bean 校验）。

### 设计要点
- **为什么要 `milestone_track`**：FR-208 迁移把 51 只误存成「其他」的猫改成 CAT（大类变），但 PRD 3.3.3 / 3.4 规定迁移不换里程碑清单。若里程碑 code 还按 `pet_type` 算，这些猫会去找 C- 开头的 roster 行，而它们只有 G- 行 → 自动完成全部失效。所以清单归属单独一列，本 story 建列回填，1.2 把读路径切过去。
- **为什么 CHECK 绑死 species 与 pet_type**：两列冗余，任何一处只改一列就会让「兔子大类是 CAT」这种脏数据进库；DB 层兜底，加上 `applySpecies` 单一入口。
- **健康提醒线 ① 会同时改 `PetProfile` / `PetProfileUpdateRequest` / `PetProfileResponse`**：本线最后合并，冲突由本线解决，所以这里一律末尾追加、别动别人的行。
