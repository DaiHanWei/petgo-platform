## Story

As a 用户,
I want 用 PawCoin 或 QRIS 买一档超值礼包，付完马上拿到次数和名额,
so that 我能低成本体验所有付费功能。

### AC3 — 查询 `GET /api/v1/starter-pack` `[L0]` `[L1]`
响应照架构 §4.2：
- `enabled = pricing.starterPackEnabled && !虚拟号`；`balance` = PawCoin 余额；`maxSaving` = 三档 saving 最大值。
- `slotState`（只档 2 / 3）：`quotaOf(userId).total() < 5` → `GRANT`；否则有 ACTIVE 租用名额 → `EXTEND`；否则 `FULL`。`defaultTier` = 3，档 3 为 `FULL` 时 1。
- `cooldown`：最近一笔 PAID 的 `paid_at + 7×24h > now` → `{until, daysLeft = ceil(剩余小时 / 24)}`。
- `pending`：有 PENDING 且 `pay_expires_at > now` → `{purchaseToken, tier, price, payExpiresAt}`；PENDING 已过窗 → 就地置 EXPIRED（同时对意图调 `paymentIntents.statusOf` 让意图走自己的过期），不返回。
- L0：`StarterPackViewAssemblerTest`（三种 slotState、冷却天数向上取整：6 天 23 小时 → 7、1 小时 → 1）。

### AC4 — 下单 `POST /api/v1/starter-pack/purchases` `[L0]` `[L1]`（D-22）
1. body `{tier, channel, requestId}`；`channel` 只接受 `PAWCOIN` / `QRIS`（其他 422）；`requestId` 非空 ≤ 64；幂等键 `STARTER_PACK:{userId}:{requestId}`：已有订单 → 不再校验、按当前状态返回（PENDING 带回同一意图与二维码）。
2. 事务内先 `pg_advisory_xact_lock(hashtext('starter_pack:' || :userId))`，再按 D-22 顺序校验：停售 409 `starter-pack-disabled` → 虚拟号 403 → 未过窗 PENDING 409 `starter-pack-pending`（ProblemDetail 扩展字段 `purchaseToken`）→ 冷却 409 `starter-pack-cooldown`（扩展字段 `until`）→ 档 2 / 3 `slotState = FULL` 409 `starter-pack-slots-full`。错误码登记 `ErrorTypes`。
3. 落库：`price` = 当前档价快照、`separate_total` 快照、`pay_channel`、`status = PENDING`。
4. **PawCoin**：同一事务 `wallet.debit(userId, price, SPEND, "STARTER_PACK", purchaseId, "STARTER_PACK_COIN:" + token)`（余额不足 409 `pawcoin-insufficient` 整笔回滚）→ 置 PAID（`paid_at`、`purchase_index`）→ 调 AC6 的 `fulfill`（同事务）→ 返回 `{status: PAID, purchaseToken}`。任何异常整笔回滚（不扣钱、不留单）。
5. **QRIS**：`paymentIntents.createIntent(userId, STARTER_PACK, QRIS, price, "IDR", "STARTER_PACK_QRIS:" + token, 60 分钟)` → 回填 `payment_intent_id`、`pay_expires_at` → 出码（`ensureCharge` 写法照 `GiftSendService` 的 gift 包私有副本：失败 → `failChargeAttempt` → 购买置 FAILED、返回 FAILED 状态不 500，`noRollbackFor = PayException`）→ 返回 `{status: PENDING, purchaseToken, intent, qrPayload}`。
6. 限流：`rl:starterpack:buy:{userId}` 10 次 / 分钟。
7. 并发同 `requestId` 撞 `uq_starter_pack_purchases_idem_key` → 控制器捕获后新事务重读（照 `GiftController` 的 `replayExisting`）。
8. L1：`StarterPackPurchaseIntegrationTest`：PawCoin 成功（余额、次数 9 / 10 / 15 批行、名额、EXP 由监听入账 40 / 55 / 65）；余额不足无单；冷却内 409；未付 QRIS 单 409；过窗 PENDING 不挡新单；同 requestId 重放；名额满无租用档 3 409。

### AC5 — QRIS 到账与失败 `[L0]` `[L1]`（D-24）
1. `StarterPackPaidHandler`：`@EventListener` + `@Transactional(MANDATORY)` 监听 `PaymentIntentPaidEvent`，`purpose != STARTER_PACK` 直接返回；按 `payment_intent_id` 找购买；`status ∈ {PENDING, EXPIRED, FAILED}` → 置 PAID、写 `paid_at` / `purchase_index`，发布 `StarterPackPaidEvent(purchaseId)`；已 PAID → 什么都不做。异常只记 ERROR、不向上抛（照 `GiftPaidHandler`）。
2. `StarterPackFulfillmentListener`：`@TransactionalEventListener(AFTER_COMMIT)` + `@Transactional(REQUIRES_NEW)`，调 `fulfill(purchaseId)`；失败只记 ERROR（重试任务兜底）。
3. `StarterPackFulfillmentRetryJob`：`@Scheduled(fixedDelay = 5 分钟)`，取 `status = PAID AND fulfilled_at IS NULL AND paid_at < now − 2 分钟`，每笔独立 `REQUIRES_NEW` 调 `fulfill`。
4. `StarterPackPaymentFailedHandler`：监听 `PaymentIntentFailedEvent`（照 `GiftPaymentFailedHandler`），PENDING → EXPIRED / FAILED（按意图状态）。
5. L1：`StarterPackQrisIntegrationTest`：stub 网关回调 → PAID → 发放完成；回调重放不重复发放；发放失败（注入异常）后重试任务补齐；过窗后才到账照样 PAID + 发放；失败事件 → EXPIRED。

### AC6 — 发放 `fulfill(purchaseId)` `[L0]` `[L1]`（D-23、D-24）
幂等：`fulfilled_at` 非空直接返回；锁购买行（`FOR UPDATE`）。
1. 次数：对 `CreditType.ktpTemplates()` 8 款各 `grant(PACK, qty 1)`、`TAILSONALITY` qty 1、档 3 另 `GIFT_1K` qty 5；`idemKey = "PACK:" + purchaseId`、`sourceRef = String.valueOf(purchaseId)`；`credits_expire_at` = 返回的 `expiresAt`（同一事务内同一时刻，取第一批的）。
2. 名额（档 2 / 3）：在 `PetSlotLock.lockUser` 锁内，`idem_key = "PACK_SLOT:" + purchaseId` 已有行 → 跳过（重放）；`quotaOf(userId).total() < 5` → 插 `PACK_GRANT` 购买行（金额 0、无渠道、`days = 30`、`starter_pack_purchase_id`）→ `PetSlotGranter.grant`（新建 1 个 `PACK_GRANT` 租用名额）→ `reconcile(RENTAL_ADDED)` → `slot_outcome = GRANTED`；否则有 ACTIVE 租用名额 → 取 `expires_at` 最早的一个，插 `PACK_EXTEND` 购买行（`rental_ids = [该 id]`）→ 走与续租相同的延长 SQL（`EXTEND_SQL`，+30 天，重置 `reminded_at`）→ `slot_outcome = EXTENDED`；否则 `SKIPPED` + WARN（待拍板 Q-10）。档 1 → `NONE`。写 `slot_rental_id`、`slot_expires_at`。
3. 不调钱包、不建意图、不发 `PawCoinSpentEvent`（名额发放不产生 EXP；EXP 只来自购买本身的扣币 / 到账信号）。
4. 写 `fulfilled_at = now`。
5. AFTER_COMMIT 上报 `starter_pack_purchased {tier, channel, purchase_index}`（`AnalyticsClient.capture`，`AnalyticsEventGuard.ALLOWED_EVENTS` 登记；照 `KtpUnlockAnalyticsListener`：不 `@Async`、不写库、属性只有枚举与数值）。
6. L0：`StarterPackFulfillmentTest`（Mockito）：档 1 / 2 / 3 发放的类型与数量；名额三分支；重放不重复。

### AC7 — 状态查询 `GET /api/v1/me/starter-pack-purchases/{token}` `[L1]`
非本人 → 404。字段照架构 §4.2；PENDING 未过窗带 `intent` + `qrPayload`（取已存载荷，没有就补出码）；过窗 → 就地 EXPIRED。`slot.petName` 按待拍板 Q-5 默认规则取（只在 `EXTENDED` 时）。
