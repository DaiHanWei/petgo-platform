# Story 5.2: 礼包后台用户免费次数与记录展示（后台 AB-41 · J / K / L / M）

Status: ready-for-dev

> 版本 v1.5.0 · 会话 ② gift-pack · 分支 `feat/1.5.0-gift-pack`
> 口径优先级：`decision-log.md`（11-13 补发 1–3 次、新权限默认超管 + 运营主管）> PRD B §3.7 / §8 > 后台整合稿页头「研发执行说明」J / K / L / M、「新权限」段 > 架构 D-30、D-31。拆页 `超值礼包/拆页-后台/` 逐屏对照。

> 范围层：后台 service + Controller + 模板 + 三语文案。

## Story

As a 运营 / 客服,
I want 在用户抽屉里看到他买过的礼包、剩余免费次数与记录，必要时补发,
so that 客诉能查能补。

## Acceptance Criteria

### AC1 — 新权限 `[L0]`（D-30）
1. `AdminPermissions.USER_ENTITLEMENT_GRANT = "user.entitlement_grant"`；加进 `AdminRole.OPS_MANAGER` 预授列表（注释同 `USER_PET_SLOT_ADJUST`：「按 PRD 预授，偏离『新码不预授』惯例」）与 `AdminPageCatalog` 用户页写权限列表；角色表内岗位不预授（「角色配置」页可勾选）。
2. `perm.user.entitlement_grant` 三语：中「补发免费次数」/ EN「Grant free credits」/ ID「Beri jatah gratis」。
3. L0：权限目录相关现有测试（`AdminPageCatalog` / `RolePermissionResolver` 测试）补断言。

### AC2 — 补发服务 `[L0]` `[L1]`
`B/admin/entitlement/service/AdminEntitlementGrantService.grant(userId, CreditType type, int quantity, String reason, String grantToken, long adminId)`：
1. `quantity` 1 ~ 3（否则 422）；原因 trim 后非空且 ≤ 200；`grantToken` 校验同 `PetSlotPurchaseService.ADMIN_GRANT_TOKEN`；`type` 不得为 `KTP_HD_ANY`（D-31，422）；用户不存在 404 / 已注销 422。
2. 调 `EntitlementCreditService.grant(new GrantCommand(userId, type, quantity, ADMIN, grantToken, "ADMIN:" + grantToken, null, null, adminId, reason))`；`replayed = true` → 视为重放，不再写审计，返回同一结果。
3. 同一事务写审计 `ENTITLEMENT_ADMIN_GRANT`，摘要「{类型} × {次数} · {原因}」（原因写入审计是 PRD 要求；UI 说明已提醒勿填隐私）。审计常量四语。
4. 控制器：用户抽屉「已购解锁」页签下的行内表单 `POST`（照 `AdminPetSlotController` 的补发路由与 `@PreAuthorize("hasRole('SUPER_ADMIN') or hasAuthority('user.entitlement_grant')")`）；`data-confirm` 原生确认（补发确认文案）；成功 toast「已补发 {0} 次 {1}（有效期 3 个月）」。
5. L0：`AdminEntitlementGrantServiceTest`：0 与 4 被拒、原因空被拒、ANY 被拒、重放只发一次且只一条审计。
6. L1：`AdminEntitlementGrantIntegrationTest`：无权限 403、成功后 `entitlement_credits` 一行 + 审计一条。

### AC3 — 「已购解锁」页签 J `[L1]`
`T/drawer-users.html` 的 `ud-purchases` 段：
1. 最上面加两张卡：「超值礼包」（该用户全部 PAID 礼包：档位、时间（WIB）、支付方式、金额）与「免费次数（剩余）」（每类型一行：类型名、剩余 / 最早到期（WIB），7 天内到期标红，0 次不显示；说明「7 天内到期的标红；0 次的类型不显示。」）。
2. 原 4 张卡下面加「免费次数记录」（最近 20 条，变动 / 来源 / 用途，来源文案：礼包「超值礼包 · 档 {0}」、活动「活动：{0}」、补发「运营补发：{0}」；用途「用于 {0} 的卡 / 用于 {0} 的结果 / 送给 {0}」）与「补发次数」卡（类型下拉只列 8 款 + Tailsonality + Rp1.000 礼物、次数 1–3、原因必填；说明文案；无权限渲染置灰卡 + `admin.v130.err.forbidden`）。
3. KTP 卡高清表里 `pay_channel = PACK_CREDIT` 的行加 badge「免费次数」。
4. 空态说明改 PRD B §8 J 泳道新句。

### AC4 — 名额记录 K / 支付记录 L / 送礼记录 M `[L1]`
1. K：`drawer-users-petslots.html` 购买记录类型加 `PACK_GRANT`「超值礼包赠送 · 档 {0} · 30 天」、`PACK_EXTEND`「超值礼包延长 · 档 {0} · 名额 {1} · +30 天」（档位经 `pet_slot_purchases.starter_pack_purchase_id` 取；名额序号 = 该租用名额在用户 ACTIVE 租用名额里按 `starts_at` 的序号），金额 / 方式 / 支付单显示「—」。
2. L：`admin.payments.purpose.STARTER_PACK`「超值礼包」三语（用途多选自动出现）；支付详情「用途」后拼「 · 档 {n}」（按意图反查礼包购买）。
3. M：送礼记录渠道 `PACK_CREDIT` →「免费次数」三语，筛选下拉加此项；总价 Rp0、支付意图「—」；页头说明改 PRD B §8 M 新句。现有汇总数字（金额合计）不受影响（免费单金额 0）。
