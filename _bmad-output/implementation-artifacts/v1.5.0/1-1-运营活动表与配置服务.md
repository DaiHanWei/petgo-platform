### AC4 — 配置校验 `[L0]`
`OpsActivityRules.validate(OpsActivityDraft draft, ValidationMode mode, Instant now)` 一次收齐所有错误，返回 `List<FieldError(field, code, args)>`；`mode = DRAFT | PUBLISH`。规则逐条照架构 OA-4 第 1 ~ 7 条：
1. 名称 ID / EN 必填、trim 后**按码点** 1–40；备注 ≤ 200；`start < end`。
2. `RANKING` 只配 `POST`。
3. 话题：`POST` 1–3 个、`LIKE / COMMENT` 0–3 个（待拍板 Q-1 默认）；全部须是 `OFFICIAL` 且 `ACTIVE`（由调用方传入话题快照，规则类不查库）；`content_types` 仅 `POST` 且非空子集（三值 `DAILY / GROWTH_MOMENT / KNOWLEDGE`），其他行为必须为空。
4. 奖励：至少一项；`exp` 1–1000；`pawcoin` 1–100000；三类次数各 1–100（4-1 契约上限）；`couponId` 须在调用方传入的「可选券 id 集合」里；`LIKE` 只能有 `exp`。
5. `INSTANT`：`perUserTotal` 必填 1–10000；`perUserDaily` 可空、1 ≤ 值 ≤ `perUserTotal`；含 PawCoin 或券时 `totalLimit` 必填 1–1000000；`rankTiers` 必须为空。
6. `RANKING`：1–5 档，首档 `from = 1`、`from ≤ to`、相邻连续、末档 `to ≤ 100`（Q-3）；每档奖励同第 4 条；三个上限与 `reward` 为空。
7. `PUBLISH` 另加：`end > now`。
- 错误码前缀 `admin.v150.activity.err.*`（文案由 2-1 写进 properties；本 story 只定 code 常量 `OpsActivityErrors`）。
- L0：`OpsActivityRulesTest` 每条规则正反例；一次提交多处错误能全部返回；名称 40 个 emoji（码点）通过、41 个被拒。

### AC5 — 配置服务 `[L0]` `[L1]`
`B/opsactivity/service/OpsActivityConfigService`（`@Transactional`），对外方法（后台 2-1 调用；返回领域视图，不返回实体）：
1. `createDraft(draft, adminId)`：校验 `DRAFT` 模式 → 生成 `public_token`（复用 `ShopTokenGenerator` 或同写法）→ 插活动 + 话题子表；返回 token。
2. `update(token, draft, adminId)`：按 OA-4 第 8 条判可改范围——`DRAFT` 全改（DRAFT 校验）；`SCHEDULED` 全改（PUBLISH 校验）；`LIVE / FULLY_GRANTED` 只接受 `end_at` 变晚，其余字段与库里不同 → 409 `activity-locked-while-live`；`end_at` 不晚于原值 → 422；`ENDED / PENDING_GRANT` → 409 `activity-ended`。返回「改动项列表」（字段, 旧值, 新值）供后台 diffs 弹层。
3. `publishPreview(token | draft, now)`：返回发布确认需要的事实（名称、时间、行为与范围、发放方式、每份奖励 / 档位、上限）+ 重叠活动（OA-4 第 9 条，取第一条名称，Q-8 默认）。
4. `publish(token, adminId, boolean canGrantPawcoin)`：PUBLISH 校验；奖励或任一档含 PawCoin 且 `!canGrantPawcoin` → 403 `activity-pawcoin-permission`；`status = PUBLISHED`、`published_at = now`。重复发布已发布的 → 幂等返回。
5. `deleteDraft(token)`：非 `DRAFT` → 409；物理删除（子表 CASCADE）。
6. `endEarly(token, adminId)`：仅 `LIVE / FULLY_GRANTED / SCHEDULED`（未开始提前结束 = 直接结束）；`end_at = now`、`ended_early_at = now`；条件更新 `WHERE end_at > now`，重复提交幂等。
7. `get(token)`、`list(filter: displayStatus?, q?, page)`：列表按 `created_at DESC, id DESC`、每页 20，`displayStatus` 用 `CASE_EXPR` 过滤，`q` 对 `name_id / name_en` 不分大小写包含匹配；行内带「参与人数」（`count(DISTINCT user_id)` over 发放记录 `status <> 'VOID'`，排名活动 = 名单人数）与「已发出」合计（`sum(exp_granted - exp_reclaimed)`、`sum(pawcoin_granted)`、`count(coupon_outcome = 'ISSUED')`、三类次数和，只算 `SENT`），**一条聚合查询**，不 N+1。
8. 话题快照、可选券集合由调用方（后台服务）传入，或由本服务通过 `TopicQuery` / `ActivityCouponIssuer.selectableIds()` 取——`ActivityCouponIssuer` 在 1-2 才建，本 story 先定义接口 `SelectableCouponSource { Set<Long> selectableIds(Instant now); }`，1-2 实现。
- 审计不在本服务写（后台服务在同一事务写，2-1）。
- L0：`OpsActivityConfigServiceTest`（Mockito）：进行中改话题被拒、进行中延长结束通过、缩短被拒、已结束改被拒、非草稿删除被拒、无 PawCoin 权限发布含 PawCoin 活动被拒（草稿保存不受影响）。
- L1：`OpsActivityConfigServiceIntegrationTest`：创建 → 发布 → 列表状态 SCHEDULED / LIVE（可注入 Clock）；提前结束后显示 ENDED（排名 → PENDING_GRANT）；列表按状态筛选与名称搜索；聚合列在无发放记录时为 0。
