## Story

As a 运营,
I want 每天早上在飞书日报里看到「自动点赞成功数」,
so that 一眼知道任务是否在跑，异常时去查开关和日志。

## Acceptance Criteria

**AC1 — 日报行** `[L0]` `[L1]`（FR-220、L-13、A-AC39）
- `admin/dailyreport/DailyReportQuery.java`：在 `SQL_AUTO_COMMENTS` 下加
  ```java
  /** 当日自动点赞成功数（V1.5.0 自动点赞 FR-220）：只看成功数、不做环比，同自动评论。 */
  static final String SQL_AUTO_LIKES =
          "SELECT count(*) FROM auto_like_logs l WHERE l.status = 'LIKED' AND " + day("l.attempted_at") + " = ?";
  ```
  并在组装处（`:87` 附近 `count(SQL_AUTO_COMMENTS, d)` 之后）取数。
- `DailyReport.Metrics`（`autoComments` 所在的嵌套记录）在 `autoComments` 后加 `long autoLikes`，javadoc 同 `autoComments` 写法（「虚拟账号自动点的赞，**不**计入点赞数与活跃率；只展示、不做环比」）。所有构造点同步补参（含测试里的造数工厂）。
- `DailyReportCard.java`：`:45` 「自动评论成功数」下一行 `fieldNoChange("自动点赞成功数", count(c.autoLikes()))`；`:25` 脚注在自动评论那句后接「；自动点赞 = 虚拟账号自动点的赞，不计入点赞数与活跃率，不做环比」。
- 当天 120 条 `LIKED` → 日报「自动点赞成功数」= 120，「点赞数」不含这 120（后半由 1.2 AC4 保证，本 story L1 再串一次）。

**AC2 — 全链路场景（UJ-1）** `[L1]`（FR-212 ~ FR-219）
`content/autolike/AutoLikeJourneyIntegrationTest extends ApiIntegrationTest`，拨钟复现 PRD UJ-1：周一 20:00 WIB 发帖（2 个真人赞）→ 周三 10:30 轮检查入集合、该轮排 1 条并派发 → 16:30 轮再 1 条（通知合并为「… dan 1 lainnya …」）→ 周四 10:30 轮第 3 条到 5 → 离开集合；之后再跑两轮不再排它。断言：`auto_like_targets` 一行 `REACHED_TARGET`、`auto_like_logs` 3 行 `LIKED`、`content_likes` 3 行 `is_automated = true`、作者无 `LIKE_RECEIVED` 流水、日报对应日期计数正确。

**AC3 — 环境开关核对** `[L0]` `[L1]`（FR-221、A-AC40）
- L0：`AutoLikePropertiesProfileTest`（`@SpringBootTest(classes = …)` 不可用于 L0 的话改用 `YamlPropertiesFactoryBean` 直接读两份 yml）：base 为 `true`、`application-dev.yml` 覆盖为 `false`。
- L1：以 dev profile 启动（不设 `AUTO_LIKE_ENABLED`）→ 手动调 `AutoLikeJob.morning()` 不写任何 run / log 行，日志含 `auto like disabled`。

**AC4 — 上线核对清单（写进 Completion Notes，不写新文档）** `[L2]`（PRD §2.3、SM-2、Q-7）
stag 验收时逐项勾（stag 跑 prod profile → 默认开）：
1. 部署前确认 stag env 没有误设 `AUTO_LIKE_ENABLED=false`；想立刻验证就临时设 `AUTO_LIKE_MORNING_CRON=0 */10 * * * *`，验完删掉并重建容器（`docker restart` 不重读 env）。
2. 首轮后查 `auto_like_runs`：`launch = true`，`checked_count / joined_count / planned_count` 与 stag 数据量相称。
3. 3 小时窗口内 `auto_like_logs` 逐步从 `PLANNED` 变 `LIKED`；通知中心出现虚拟号的点赞通知；真机收到推送。
4. 次日日报「自动点赞成功数」非零，「点赞数」未被抬高。
5. 「点赞数」「Feed 推荐」「话题热度」「推荐关注」「宠物推荐」不因自动赞变化（抽 1–2 帖对比）。
6. 生产上线前：确认 PRD A 先行合并的提交点（Epic 2 最后一个提交 sha，见 Completion Notes），主会话决定是否把分支截到该点单独合 `dev_1.5.0`（Q-7）。
