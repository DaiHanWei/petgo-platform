## Story

As a 做完 7 项新手任务的用户,
I want 一次就拿到 Lulus Pemula 徽章（多只宠物一起亮）和 +20 成长值,
so that 不会再出现「6/6 却没有徽章」。

## Acceptance Criteria

**AC1 — 迁移 ②** `[L0]` `[L1]`
DDL 照架构 §3.2 ②：`ck_user_milestone_flags_key` DROP + ADD 为 `('FIRST_FOLLOW_USER', 'FIRST_COLLECT_CONTENT', 'LULUS_PEMULA')`（值取 `V20261104_2030` 原文 + 1，不凭记忆）；`user_milestone_flags.celebrated_at TIMESTAMPTZ` 可空；已有两种 flag 的行 `celebrated_at = occurred_at`。可重放。`UserMilestoneFlag` 实体加 `celebratedAt` 字段（`ddl-auto=validate`）。

**AC2 — 迁移 ③** `[L0]` `[L1]`
`growth_rules` 插 `('NEWBIE_GRADUATED', 20, NULL, NULL, NULL, true) ON CONFLICT (code) DO NOTHING`；`RuleCode` 末尾（`ADMIN_ADJUST` 之后）加 `NEWBIE_GRADUATED`；后台 `AdminGrowthConfigService.RULE_ORDER`、App 等级页 `GrowthPageQuery.RULE_ORDER` 在 `MILESTONE_L` 后加它；四个 `messages*.properties` 加 `admin.v140.growth.rule.NEWBIE_GRADUATED`（中「新手毕业」/ EN「Beginner graduate」/ ID「Lulus Pemula」）与 `.source`（中「7 项新手任务全部完成时」/ EN「When all 7 Beginner Tasks are done」/ ID「Saat 7 Tugas Pemula selesai」）。

**AC3 — 账号级 flag（PRD AC21）** `[L0]` `[L1]`
`AccountMilestoneFlag` 加 `LULUS_PEMULA(MilestoneAutoEvent.LULUS_PEMULA)`；`MilestoneAutoEvent` 加 `LULUS_PEMULA`；`MilestoneAutoCompleteMap` 加 `LULUS_PEMULA → C-S16 / D-S16 / G-S9`。猫、狗两只 ACTIVE 宠物的账号毕业后，两只宠物的里程碑页都显示 Lulus Pemula 已完成（各自本物种编码）；只读宠物不写。

**AC4 — 毕业判定** `[L0]` `[L1]`
`NewbieGraduationService.checkAndGraduate(userId)`：①–⑥ 标记齐全 **且** ⑦（WIB 注册日 + 7 ≤ 今天）**且** 账号是 REAL USER ACTIVE 未注销 → `AccountMilestoneService.onFlagTriggered(userId, LULUS_PEMULA)`（已有 flag 时它本身 no-op）。替换 2-1 的空 `NewbieMarkHooks`：任何新标记写入后、`NewbieWeekJob` 写 ⑦ 后都调用。无宠物账号凑不齐 ①，自然不会毕业。

**AC5 — 删除按宠物判定** `[L0]` `[L1]`
`MilestoneCompletionService` 删除 `checkAndUnlockLulusPemula` 及 `complete()` 里 `isNewbiePrereq` 分支；`maybeUnlockLulusPemulaForOwner(ownerId)` / `maybeUnlockLulusPemulaForPet(petId)` 改为委托 `checkAndGraduate(ownerId)`（保留方法名；`MilestoneAutoCompleteListener.onHealthRecordCreated:145` 那行调用保留不动——PRD「录健康记录时的徽章检查保留，只把判定换成新 7 项」）。不再要求健康记录。`MilestoneCatalog.newbiePrereqCodes / isNewbiePrereq` 无调用方则删除并同步测试。

**AC6 — 一次通知、一次成长值（PRD AC22）** `[L1]`
毕业时：通知中心只 1 条 `MILESTONE_SM_NODE`（`sendWithoutPush`，不推送，落库中性文案不写宠物名，`targetRef` 规则见 AC7）；成长值流水只 1 笔 `NEWBIE_GRADUATED` +20（`GrowthActivityListener.onAccountMilestone`：`flagKey == LULUS_PEMULA` → `NEWBIE_GRADUATED`，否则仍 `MILESTONE_S`；幂等键 `MILESTONE_ACCT:{u}:LULUS_PEMULA` 不变）；不弹庆祝（完成行 `celebrated_at = NULL`、flag `celebrated_at = NULL`，等补弹）。`MilestoneAnalyticsListener` 照常报 `milestone_achieved`。

**AC7 — 无 ACTIVE 宠物也通知（FR-177）** `[L1]`
毕业时账号无 ACTIVE 宠物（做过 ① 后宠物全删或全只读）：照常写 flag、成长值 +20、**发通知**（`MilestoneNotifyListener.onAccountMilestone` 对 `LULUS_PEMULA` 不因 `petIds` 空而 return）。`targetRef` = 事件 `targetCode`；为空时取账号最早一只宠物（含只读）的 Lulus 编码，再没有用 `C-S16`。另两个 flag 的「petIds 空不通知」规则不变。

**AC8 — 之后的新宠物（PRD AC23）** `[L1]`
毕业后新建第三只宠物 / 只读恢复 → 该宠物 Lulus 直接「已完成且已庆祝」，不弹、不加成长值、不发通知（`applyExistingFlagsToPet` 自动覆盖，测试钉住）。

**AC9 — 庆祝回报同时置 flag** `[L1]`
`POST /api/v1/pet-profiles/me/milestones/celebrations` 的 codes 含任一 Lulus 编码 → 除账号下全部宠物同 flag 行外，同时置 `user_milestone_flags.celebrated_at`（只置 NULL 的）。

**AC10 — 回归** `[L0]` `[L1]`
1.4.2 两个账号级里程碑行为不变（通知 petIds 空不发、`MILESTONE_S` +5）；`MilestoneCompletionServiceTest`、`AccountMilestoneServiceTest`、`GrowthActivityListenerTest`、`MilestoneCelebrationServiceTest`、`MilestoneAutoCompleteMapTest` 更新断言表达新规则后全绿（不删测试、不 skip）。
