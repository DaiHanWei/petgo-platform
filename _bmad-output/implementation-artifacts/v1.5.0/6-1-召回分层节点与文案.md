## Story

As a 注册不到一周的新用户,
I want 第 1 / 3 / 7 天收到的提醒和我自己的状态有关（没宠物不催建档、还没互动的去看同品种）,
so that 每条推送都给我一个具体的回来理由。

## Acceptance Criteria

**AC1 — WIB 日期（PRD AC21）** `[L0]`
`LifecyclePushJob` 用 `LocalDate.now(ScheduleWindow.WIB)`；`UserLifecycleSnapshot.registeredDate` 改为按 WIB 折算（`AccountQueryService.lifecycleSnapshots` 改 `toWibDate`）。WIB 11/12 03:00 注册（UTC 11/11 20:00）→ D1 在 WIB 11/13 19:00 发。

**AC2 — 快照与上下文（OR-21）** `[L0]` `[L1]`
- `UserLifecycleSnapshot` 加 `petStatus`（`users.pet_status`，可空）。
- 新只读端口 `notify/port/LifecycleContextPort` + 实现（profile / social 侧），对一批 userIds **一次批量**给出：默认宠物 `(name, breed, petType)`（`DefaultPetPolicy`，含只读；有任一宠物行即「有宠物」）、新手标记集合、`activeToday`（`user_active_days.active_date = 今天 WIB`）、`graduated`（有 `LULUS_PEMULA` flag）。
- 候选收窄：只取 WIB 注册日落在 D1 / D3 / D7 两天窗口内的 REAL USER ACTIVE 账号（SQL 条件，不再全量扫；召回节点打开时才额外取全量，见 6-2）。

**AC3 — 五层分层（OR-22）** `[L0]`
自上而下取第一个：A 没宠物（无宠物且 `petStatus != HAS_PET`，含为空）/ B 待建档（无宠物且 `HAS_PET`）/ C 待发帖（有宠物、`publishedCount == 0`）/ D 待互动（发过帖、`FIRST_FOLLOW / FIRST_LIKE_GIVEN / FIRST_COMMENT` 都没有）/ E 已互动（至少一个）。

**AC4 — 节点 × 分层（OR-23 表）** `[L0]`
| 节点 | A | B | C | D | E |
|---|---|---|---|---|---|
| D1 | `DISCOVER` · `D1.NO_PET`；A 且 ③④⑤ 任一完成 → `FEED` · `D1.NO_PET` | `CREATE_PROFILE` · 现有 `D1.CREATE_PROFILE` | `RECORD` · 现有 `D1.RECORD` | `DISCOVER` · `D1.SQUAD` | `RECORD` · `D1.ACTIVE` |
| D3 | 同 D1（`D3.NO_PET`） | `CREATE_PROFILE` · 现有 `D3.CREATE_PROFILE` | `DISCOVER` · `D3.SQUAD` | `DISCOVER` · `D3.BESTIE` | 不推（不写 mark） |
| D7 | 毕业 `GRADUATED` · `D7.GRADUATED`；否则 `NEWBIE_TASKS` · `D7.TASKS_LEFT` | `CREATE_PROFILE` · 现有 `D7.CREATE_PROFILE` | 同 A | 同 A | 同 A |
- 毕业 = `graduated` 包含该用户，**或** ①–⑥ 标记齐全（⑦ 在 D7 窗口必然满足）。N = 7 − 已完成项数（⑦ 计为完成）。
- 一人一天最多 1 条、窗口 2 天、`(用户, 类型, 节点)` 去重、按 D1 → D3 → D7 排序，不变。
- 现有 D3 `FEED`（已建档未发帖）与 D7 `REVIEW` 分支取消。

**AC5 — 当天已来过（PRD AC17）** `[L0]` `[L1]`
D1 / D3 发送时该用户在 `activeToday` → 本节点作废：**写** `lifecycle_push_marks`（variant `SKIPPED_ACTIVE`），不推送、不写通知；第二天窗口内不再补。D7 不受影响照发。

**AC6 — D3 E 层不推（PRD AC18）** `[L0]`
发过帖并追更过一只宠物的用户（E）在 D3 不推、不写 mark。

**AC7 — 变体与 mark** `[L0]`
`LifecycleVariant` 保留旧值（`CREATE_PROFILE / RECORD / FEED / REVIEW`），新增 `DISCOVER / NEWBIE_TASKS / GRADUATED / SKIPPED_ACTIVE`；通知 `targetRef` = 变体名（`SKIPPED_ACTIVE` 从不下发）；`lifecycle_push_marks.variant` 存 `<层>_<变体>`（如 `D_DISCOVER`、`A_GRADUATED`，≤ 32 字符）。`LifecyclePlannedPush` 加 `layer`、`copy`（文案键后缀）、`breedWord`、`remaining`；`copyKey()` = `type.name() + "." + copy`。

**AC8 — 文案（附录 A，逐字）** `[L0]`
`messages_id.properties` / `messages_en.properties`（`messages.properties` 同 EN；`messages_zh_CN.properties` 写中文意思）新增 `notify.LIFECYCLE_D1.NO_PET / D1.SQUAD / D1.ACTIVE / D3.NO_PET / D3.SQUAD / D3.BESTIE / D7.GRADUATED / D7.TASKS_LEFT` 的 `.title / .body`（附录 A 每格「标题 / 正文」以「 / 」分隔）。参数固定：`{0}` 宠物名、`{1}` 品种词、`{2}` N。品种词 = 默认宠物 `breed`（trim 非空）否则 `notify.species.<PetType>`（ID CAT `Kucing` / DOG `Anjing` / OTHER `Anabul`；EN `cat` / `dog` / `pet`）。现有 `D1/D3/D7.CREATE_PROFILE`、`D1.RECORD` 文案不改。含参串的撇号写 `''`。

**AC9 — `LifecyclePushCopyTest`（OQ-5）** `[L0]`
- 带宠物名规则：C / D / E 层句子必须含 `{0}`；A、B 层不含宠物名。
- 例外：`D7.GRADUATED`、`D7.TASKS_LEFT` 豁免宠物名规则，测试里注释「账号级内容」。
- 「禁止回来看看类空话」规则不变（新句子过守卫）。

**AC10 — 通知中心存渲染文案（FR-183 通知中心）** `[L0]` `[L1]`
`LifecyclePushDispatcher` 改用 `NotificationService.sendRendered(…, push=true)`，落库与推送同一句。

**AC11 — 落点（PRD AC15 / AC16 / AC19 / AC20 后端部分）** `[L1]`
- 选「计划养」没建档 → D1 `DISCOVER`，文案不提建档、不带宠物名；
- 「Mochi · Persia」发过 1 条 Diary、无互动 → D1 `D1.SQUAD` 文案含「Persia」，`targetRef=DISCOVER`；
- 满 7 天当天刚好全部完成 → `D7.GRADUATED`、`targetRef=GRADUATED`，这是 Lulus 唯一一次推送；
