## Story

As a 活动引擎,
I want 一个「先记待发、再一次性发完整份奖励、失败可重发」的执行器,
so that 活动奖励不会静默丢失、不会重复到账、总份数在并发下准确。

### AC5 — 执行（事务 2 / 3）`[L0]` `[L1]`（架构 OA-8、§5）
`OpsActivityGrantService.execute(long grantId)` → `GrantExecution {SENT, FAILED, VOID, SKIPPED_ALREADY_DONE}`：
1. 事务 2（`REQUIRES_NEW`，通过独立 bean `OpsActivityGrantExecutor` 调用，避免自调用失效）：`SELECT … FOR UPDATE` 记录；状态不是 `PENDING / FAILED` → `SKIPPED_ALREADY_DONE`。总开关关 → 抛 `ActivityGrantStepException(CAMPAIGN_DISABLED)`。资格再判：不合格 → `VOID` + `USER_INACTIVE | USER_STOPPED`，提交，返回 `VOID`。
2. 按顺序发（每步失败抛 `ActivityGrantStepException(对应原因)` 包住原异常）：
   - EXP：`accrueActivity`（`refType = "CONTENT_POST"`、`refId = postId`，排名同）；`NOT_PARTICIPATING` → 同第 1 条 `VOID`；`CAMPAIGN_DISABLED` → 抛；`GRANTED / REPLAYED` → `exp_granted = exp`。
   - PawCoin：`PawCoinWalletService.credit(userId, n, BONUS, "ACTIVITY", activityId, idemKey)` → `pawcoin_granted = n`。
   - 权益次数：按 KTP → 性格测试 → 礼物顺序各一次 `EntitlementCreditService.grant(GrantCommand.activity(userId, type, n, activityId, idemKey, nameId, nameEn))`；记三列。KTP 类型 = `KtpTemplate.toCreditType()`。
   - 券：`ActivityCouponIssuer.tryIssue(…)` → `coupon_outcome`、`user_coupon_id`。
   - `status = SENT`、`sent_at = now`、`fail_reason = NULL`、`attempts += 1`。
3. 事务 2 抛任何异常 → 回滚 → 事务 3（`REQUIRES_NEW`）：`status = FAILED`、`fail_reason` = 步骤原因（非 `ActivityGrantStepException` → `UNKNOWN`）、`attempts += 1`、`updated_at`。ERROR 日志只记 grantId / activityId / userId / 原因 / 异常类名。
4. 返回前（事务外）调 `OpsActivityNotifier.afterExecuted(grantId, result)`（AC6）；通知抛错只记 WARN。
5. L0：`OpsActivityGrantExecutorTest`（Mockito）：发奖顺序（`InOrder`）；PawCoin 抛错 → 结果 `FAILED / PAWCOIN_FAILED` 且券未发；券跳过不算失败；`SENT` 记录再执行 → `SKIPPED_ALREADY_DONE`；不合格 → `VOID`；只有 EXP 的奖励不调 PawCoin / 权益 / 券。
6. L1：`OpsActivityGrantExecutionIntegrationTest`：
   - 一份奖励（20 EXP + 500 PawCoin + KTP ANY ×1 + 礼物 ×3 + 券）→ 成长值流水 1 行（`activity_id`、`note`）、PawCoin 流水 `BONUS / ACTIVITY / refId = 活动 id`、`entitlement_credits` 两行（同 `idem_key`，`source_type = 'ACTIVITY'`、`source_ref = 活动 id`、`label_id / label_en`）、`user_coupons` 1 行。
   - 注入故障（让权益服务抛错）→ 整份回滚：成长值 / PawCoin / 券都没有、记录 `FAILED / CREDIT_FAILED`；去掉故障后 `execute` 同一记录 → 全部到账且只一份（PawCoin Redis 幂等映射在回滚后未残留）。
   - 两个线程同时 `execute` 同一 `FAILED` 记录 → 只到账一次。
