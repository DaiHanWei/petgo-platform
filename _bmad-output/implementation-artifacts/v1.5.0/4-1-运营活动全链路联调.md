# Story 4.1: 运营活动全链路联调（本地 L1 / L2）

Status: ready-for-dev

> 版本 v1.5.0 · 会话 ⑥ ops-activity · 分支 `feat/1.5.0-ops-activity`
> 🔴 **云端不跑**：本 story 只在本地执行。云端做到 3-2 为止。
> 前置：1-1 ~ 3-2 全部 review；gift-pack 4-1 已在 dev（6-3 若也已合入，B2 / 合并页一起验）。

## Story

As a 操作者,
I want 在本地把运营活动从后台配置到用户得奖、扣回、排名发放、通知整条走通,
so that 合进 dev 前确认份数、上限、幂等、扣回、权益次数都对。

## Acceptance Criteria

### AC1 — L1 全绿 `[L1]`（本地 Docker postgres + redis）
- scratch 库（先 flush Redis 对应 DB，再重建）Flyway 跑到 `V20261115_0610`：`opsactivity`、`growth`、`pay`、`shop.coupon`、`entitlement`、`notify`、`content`、`admin.growth`、`admin.shared` 包全部集成测试绿（含 1-1 ~ 2-3 里所有 `*IntegrationTest`）。
- `bash scripts/ci/check-flyway-versions.sh origin/main` 通过；`./mvnw -B clean package` + `spring-boot:run` → `/actuator/health = UP`（无路由撞车）。
- 共享约束复核：`ck_user_coupons_source` 6 值 = `UserCouponSource`；**`ck_notifications_type` 未被本线修改**（`git diff dev_1.5.0 -- '*ck_notifications_type*'` 为空）；`entitlement_*` 约束未改。

### AC2 — 参与即奖端到端 `[L2]`（Android 模拟器 + 真 Google 登录 + 本地后端）
1. 后台建发帖活动（官方话题 #A、Diary + Moment、20 EXP + 500 PawCoin + KTP 任意款 ×1 + 免费礼物 ×3 + 一张领取券、每人每天 1 / 活动内 2、总 3 份）→ 发布确认弹层事实正确 → App 发带 #A 的 Moment：EXP 明细「Event · {名}」（切 EN 界面显示英文名）、PawCoin 记录「Event · {名}」、「Koin & Jatah Saya」免费次数区 +1 KTP（Desain apa saja）+3 礼物、记录「Event · {名}」、我的优惠券 +1、通知中心一条「Hadiah dari {名} 🎁」（无推送），点开进 `/me/pawcoin`。
2. 当天再发一帖 → 无奖励、无第二条通知；第二天（改库时间或等）→ 得奖；第三帖 → 不得。三个账号抢最后份数 → 后台「已发完」黄条与状态。
3. 券库存设 1：第二个得奖用户券未发出、其余照发，后台明细灰字「券未发出：库存不足」。
4. 点赞活动（5 EXP、不限话题）：点赞得 EXP、取消扣回（后台「EXP 已扣回 · 取消点赞」）、再赞不再发。
5. 评论活动：同帖多条评论只 1 次。
6. 运营下架得奖帖 → 发帖活动 EXP 扣回、PawCoin / 次数 / 券不动。
7. 停发某用户（原因必填）→ 之后不再发、明细「已停发」行；关 `OPS_CAMPAIGN` 总开关 → 不再发、后台黄条。
8. 故障注入（如临时停 Redis 或让权益服务抛错）→ 明细「发放失败」→ 恢复后批量重新发放 → 到账且只一次。
9. ⑤ 自动点赞（若已合入 dev）：虚拟号自动赞不产生任何活动记录。

### AC3 — 排名端到端 `[L2]`
1. 排名活动（三档 1 / 2–3 / 4–10），多账号发帖互动（含同一人多条评论、作者自赞、虚拟号赞），提前结束 → F1 → 5 分钟内 F2；热度分解与手算一致、每人只取最好一帖、同分先发在前。
2. 剔除第 1 名（原因必填）→ 递补；撤销 → 复原；下架某获奖帖 → 该行「不发放 · 帖子已下架」、不递补。
3. 确认发放（合计与弹层一致）→ F5 批次号与成功数；获奖用户收到通知 + 推送「Selamat! Postinganmu juara #1 di {名} 🏆」，点推送直达帖子；从通知中心点、帖子已删 → toast 不跳转。
4. 连点 / 两个后台账号同时点确认发放 → 只发一批。
5. 名单 8 天未确认（改 `rank_built_at`）→ 侧栏待办中心「运营待办 · 排名待发放」角标 1，点进页签筛待发放；无 `growth.config_edit` 的账号看不到该项。
6. 无参赛帖的排名活动 → F7、不进待办。

### AC4 — 权限与审计 `[L2]`
- 只读账号（`growth.config_view`）：能看列表 / 详情，看不到新建 / 编辑 / 停发 / 重发 / 剔除 / 确认发放。
- 无 `user.grant_pawcoin`：含 PawCoin 的活动「发布」「确认发放」「重新发放」置灰 + 原因，直接 POST 403；草稿照存。
- 操作审计页能查到全部 10 种 `OPS_ACTIVITY_*` 动作，三语标签正常。

### AC5 — 旧版 App 兼容 `[L2]`
1.4.x 旧包：活动 EXP 明细「Event · {名}」、PawCoin 记录显示「Bonus」、通知中心两类显示兜底且点开不崩、获奖推送点开进通知中心。

### AC6 — 还原度 `[L2]`
后台 33 屏（C1 ~ F9）、App 6 屏（A1 ~ A4、B1、B2）逐屏打分 ≥ 95%；不足的回对应 story 修；三种后台语言切换无漏翻。Completion Notes 记 Q-7 那批「待产品复核」文案的清单，交产品确认。
