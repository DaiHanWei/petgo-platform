## Story

As a 运营,
I want 排名活动结束后在详情页核对名单、剔除刷量用户、一键发放，并在待办中心看到超期没发的活动,
so that 获奖名单经人工把关、不会漏发也不会重复发。

## Acceptance Criteria

### AC1 — 排名详情布局（F1、F2、F5、F7）`[L1]`
`T/fragments/growth-activity-ranking.html`（2-2 详情页 `grant_mode = RANKING` 分支引用）：
1. F1 生成中（`rank_state = NONE` 且已结束）：提示条「活动已于 {time} 结束，系统正在按热度生成待发放名单，1 小时内完成。」+ 表格骨架 `.skl`；不自动刷新。
2. F2 待发放（`READY`）：汇总卡（照 F2 截图：人数、EXP、PawCoin、优惠券、各类次数，只算「待发」行，用 `grantPreview` 同口径）；名单表：名次（圆形徽标，前三浅紫底）、用户（`昵称 · id`）、帖子（前 30 字，新标签进内容管理详情）、热度「总分 (赞 / 评 / 藏)」（等宽数字）、应发奖励（档位摘要）、状态（待发 / 不发放 + 原因 / 剔除 + 原因）、操作（待发 / 不发放 →「剔除」；剔除 →「撤销剔除」）。只列 `rank ≤ 末档 to` 的行 + 底部 `EXCLUDED` 行；`NOT_GRANTED` 行整行变淡。每页 20。右下「确认发放」+ 灰字「名单生成于 {time} · 7 天内没确认会进「待办中心」」。
3. F5 已发放（`GRANTED`）：顶部绿条「已发放：批次 {no}，{a} 位用户成功，{b} 位失败。」（`banner ok`）；状态列改为发放记录状态（已发 / 发放失败 + 原因 / 不发放）；「剔除」消失；失败行有「重新发放」（复用 2-2 的重发路由与确认弹层）。
4. F7 空名单（`EMPTY`）：「活动期间没有符合条件的帖子，不需要发放」，无「确认发放」；状态徽标「已结束」。

### AC2 — 剔除 / 撤销（F3）`[L0]` `[L1]`
1. 「剔除」→ `POST …/{token}/ranking/{entryId}/exclude/confirm` → 确认弹层（`withReason`）「剔除 {user}？剔的是这个人：他的其他帖子也不再上榜，后面的人自动递补名次。」→ `POST …/exclude`（`growth.config_edit`）→ `OpsActivityRankService.exclude`；审计 `OPS_ACTIVITY_RANK_EXCLUDED`（摘要：entryId、原名次）。
2. 「撤销剔除」→ `POST …/{token}/ranking/{entryId}/restore`（无原因，普通确认）→ `restore`；审计 `OPS_ACTIVITY_RANK_RESTORED`。
3. 「剔除」只要 `growth.config_edit`（不要 PawCoin 权限，F8 说明）。
4. 成功后名单片段 htmx 刷新（名次递补可见）。
5. L1：剔除第 1 名 → 原第 2 名变第 1、档位奖励随之变；撤销复原；已发放后剔除 409。

### AC3 — 确认发放（F4、F8）`[L0]` `[L1]`
1. 「确认发放」→ `POST …/{token}/ranking/grant/confirm` → 服务端确认弹层：`cm.facts` 人数、EXP 合计、PawCoin 合计、优惠券张数、KTP / 性格测试 / 免费礼物次数合计（`grantPreview` **现算**，页面可能过期）；正文「确认发放排名奖励？同一活动只能发一次；发出后一律不扣回。获奖用户会收到通知和推送。」。
2. 任一档含 PawCoin 且无 `user.grant_pawcoin`（F8）：按钮置灰 + 原因「奖励含 PawCoin，需要「赠送 PawCoin」权限才能确认发放」；名单照常可看；直接 POST → 403。
3. `POST …/{token}/ranking/grant`（`growth.config_edit`）→ `OpsActivityRankService.confirmGrant` → 页面切到 F5；重复点（包括两个运营同时点）不重复发（服务端 `rank_state` + `ACTRANK:` 键）。审计 `OPS_ACTIVITY_RANK_GRANTED`（摘要：批次号、人数、成功 / 失败数）。
4. 总开关关 → 弹层内 422「「运营活动」规则已停用」。
5. L1：`AdminOpsActivityRankingIntegrationTest`：合计与服务端一致；无 PawCoin 权限 403；重复提交只一批；F5 结果条数字正确。

### AC4 — 待办中心「排名待发放」（F9）`[L0]` `[L1]`
1. `AdminPageCatalog` 新增页面 key `ops-activity-ranking`（`G_CONFIG`，路由 `/admin/growth?tab=activities&status=PENDING_GRANT`，查看与编辑权限都为 `growth.config_edit`，**不出现在配置组导航**，只作待办队列）——写法照 `shop-order-exceptions` 的 `shared(...)` 条目。
2. `NavBadgeService.QUEUES` **末尾追加** `"ops-activity-ranking"`；`supplierFor` 加分支 → `OpsActivityAdminQuery.overdueRankingCount()`（`grant_mode = 'RANKING' AND rank_state = 'READY' AND rank_built_at < now − 7 天`）；`RELATED_GROUPS` 加 `Set.of("ops-activity-ranking")`。
3. `T/fragments/nav.html`：「商城待办」两项之后，照同样写法加 `nav-subhead`「运营待办」（`admin.v150.activity.nav.opsTasks`）+ 跳转项「排名待发放 ↗」（`admin.v150.activity.nav.rankingPending`，角标 oob 填入）；只对有 `growth.config_edit` 的人显示。
4. 点进 → 运营活动页签并筛「待发放」（列表筛选显示全部待发放，角标只数超 7 天的）。
5. L0：`NavBadgeServiceTest`（若有则补）：新队列对无 `growth.config_edit` 的人不可见、计数函数被调用。
6. L1：造一个 8 天前生成名单未确认的活动 → 角标 1；6 天前的 → 0；确认发放后 → 0。
