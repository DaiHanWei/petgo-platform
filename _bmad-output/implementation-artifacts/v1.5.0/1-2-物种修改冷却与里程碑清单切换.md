### AC6 — 清单切换器 `MilestoneTrackSwitcher` `[L0][L1]`（D-4）
`profile.service.MilestoneTrackSwitcher.switchTo(PetProfile pet, PetType newTrack)`，`@Transactional(propagation = MANDATORY)`，`newTrack == pet.getMilestoneTrack()` 直接返回：
1. 取该宠物全部 roster 行（含退役）。当前活跃行全部 `retire(now)`。
2. 对 `MilestoneCatalog.forType(newTrack)` 每条定义：已有同 code 行 → `revive()`；没有 → `PetMilestone.of(...)` 新建。
3. **按事实补记**（不发任何事件 → 不发成长值、不发通知、不进补庆祝）：
   - 遍历 `MilestoneAutoEvent.values()`：`oldCode = MilestoneAutoCompleteMap.codeOf(oldTrack, e)`、`newCode = codeOf(newTrack, e)`，二者非空、旧行有完成记录、新行无完成记录 → `completions.save(MilestoneCompletion.ofCelebrated(newRowId, SYSTEM_AUTO, 旧完成时间))`。
   - Lulus Pemula：`MilestoneCatalog.lulusPemulaCode(oldTrack)` 已完成 → 新的同样补记。
   - 打卡类 / 无对应项不补。
4. `accountMilestones.applyExistingFlagsToPet(petId)`（已有，幂等）。
5. `pet.setMilestoneTrack(newTrack)`。
6. 退役行的完成记录**不删**；来回改（CAT → OTHER → CAT）时 C 行复活、原完成记录自然回来。
7. 用例（L1，逐条有测试）：

   - 兔 → 仓鼠（大类同为 OTHER）→ 不调切换器，清单不变。
   - 迁移过来的猫（`pet_type = CAT`、`milestone_track = OTHER`）改狗 → 切到 DOG；改兔 → `groupChanged`（CAT → OTHER）但 track 已是 OTHER → 切换器直接返回。

### 设计要点
- **为什么退役而不删**：PRD 3.3.3「已完成的里程碑、徽章、已发的奖励保留不收回」。`milestone_completions` 引用 `pet_milestones`，删 roster 行就得删完成记录；退役保留一切，还天然支持来回改。
- **为什么补记不发事件**：成长值（`GrowthActivityListener`）与里程碑通知（`MilestoneNotifyListener`）都由 `MilestoneCompletedEvent` 驱动；补记的是「同一件事在另一套清单里的对应项」，再发一次就是重复发奖励（PRD「不重复发奖励」）。
- **为什么要悲观锁**：冷却判定是读后写；两台设备同时提交会都通过。锁宠物行即可（单实例部署，行锁足够）。
- **健康提醒（①）不受影响**：其规则读 `pet_type`；PRD 3.3.3「健康记录与已生成的提醒全部保留，不取消，之后新生成的按新大类」——本 story 不碰健康表。
