Status: ready-for-dev

> 版本 v1.5.0 · 会话 ⑥ ops-activity · 分支 `feat/1.5.0-ops-activity`
> 口径优先级：`decision-log.md`（11-13：详情做独立子页、停发 / 剔除原因在确认弹层里填、停发不可恢复、发放失败可重发）> PRD §3.6、§3.8、附录 A.2 > 后台整合稿执行说明「详情子页」「确认弹层」> 架构 OA-8、OA-20、§4.2。拆页 `拆页-后台/` E1 ~ E7。

## Story

As a 运营,
I want 在活动详情页看到发了多少、发给了谁、哪些失败，并能停发异常用户、重发失败记录、提前结束活动,
so that 用户说「参加了没拿到」时我能查到并补上。

## Acceptance Criteria

### AC1 — 确认弹层「必填原因」（通用）`[L0]` `[L1]`
1. `AdminConfirmModal` 加可选 `ReasonField(String name, String label, int maxLength)` 与 `withReason(...)`；`T/fragments/confirm-modal.html` 在有 `reason` 时渲染 `<textarea required maxlength>`（标签「原因（必填）」）；提交空值 → 服务端 422，错误渲染在弹层内（不关弹层）。
2. 现有调用方不受影响（未设置时不渲染）；`AdminConfirmModalTest`（若无则新建）覆盖 `withReason` 不破坏其他字段。
3. 本 story 的停发（E5）与 2-3 的剔除（F3）共用。

### AC2 — 详情子页框架（E1、E2、E7）`[L0]` `[L1]`
1. 路由 `GET /admin/growth/activities/{token}`（`growth.config_view`），模板 `T/growth-activity-detail.html`（布局 `admin/layout :: page`），面包屑「‹ 成长体系 · 运营活动」→ `/admin/growth?tab=activities`；标题 + 状态徽标；右侧「查看设置」（只读抽屉，2-1 的 D14）/「编辑」（可改时）/「提前结束」（进行中 / 已发完 / 未开始，`growth.config_edit`）。
2. 设置摘要一行（照 E1：`参与即奖 · 发帖 · #话题 · Diary / Moment / Tips  每份 … 每人每天 n 次 · 活动内 n 次 · 总份数 n（已发 n）  时间 WIB`）。
3. `grant_mode = RANKING` 时本页渲染 F 布局（2-3 实现片段，本 story 留 `th:if` 分支与占位片段）。
4. 汇总卡（照批量发放预览 `.sum`，按活动实际有的奖励出卡）：参与人数（`count(DISTINCT user_id)`，`status ≠ VOID`）、发放次数（`SENT` 条数）、EXP（`Σ exp_granted`）、PawCoin（`Σ pawcoin_granted`）、优惠券（`ISSUED` 张数）、KTP 高清解锁 / 性格测试解锁 / 免费礼物（各 `Σ … 次`）、EXP 被扣回（`−Σ exp_reclaimed`，灰色）、券未发出（`SKIPPED_*` 条数，有券时才出）、发放失败（`FAILED` 条数，> 0 标红）。**一条聚合查询**。
5. 异常提示条（E7，黄色 `.banner`，可同时出现，顺序：已发完 → 话题已禁用 → 优惠券已失效）：已发完「已发完：{a} / {b} 份，之后不再发放。可以延长结束时间（份数不能加）或提前结束。」；活动话题任一 `DISABLED` →「话题 {topic} 已被禁用：…」；奖励券满足 OA-11 第 4 条 →「优惠券「{name}」已失效：…」（A.2 原文）。
6. 无记录（E2）：汇总全 0、明细换空态「还没有人参与」。
7. L1：渲染进行中 / 已发完 / 未开始三种；提示条条件；只读权限不显示「编辑」「提前结束」「停发」「重新发放」。

### AC3 — 明细列表、筛选、CSV（E1、E3）`[L0]` `[L1]`
1. `GET …/{token}/grants?status=&q=&page=`（htmx 片段）：筛选「全部状态 / 已发 / 发放失败 / EXP 已扣回 / 已停发」+ 搜索「用户 ID / 昵称」；每页 20，`created_at DESC, id DESC`。
2. 列：时间（WIB `dd/MM HH:mm`）、用户（`昵称 · id`，已注销显示现有「已注销用户」文案）、关联帖子（帖子文本前 30 字，点开新标签进内容管理详情；无 →「—」）、发了什么（实际发出：`20 EXP · 500 PawCoin · KTP 1 次`；扣回后 EXP 显示「20 EXP 已扣回」；券未发出灰字「券未发出：库存不足 / 已达每人限领 / 券已失效」）、状态（已发 / 发放失败 + 原因 / EXP 已扣回 + 「帖子被下架」或「取消点赞」/ 不再发放 + 原因）、操作（已发 → 「停发」；发放失败 → 「重新发放」；已停发 →「—」）。
3. 「已停发」行来自 `ops_activity_user_stops`：每个停发用户一行（时间 = 停发时刻、关联帖子「—」、发了什么「不再发放」、状态「已停发」+ 原因）；「全部」时与发放记录按时间倒序 UNION ALL 分页（查询放 `OpsActivityAdminQuery`）。
4. 「EXP 已扣回」= `exp_reclaimed > 0`；原因：`trigger_kind = POST` →「帖子被下架」、`LIKE` →「取消点赞」（Q-7 新文案）。
5. CSV：`GET …/{token}/grants.csv?status=`（`growth.config_view`），UTF-8 BOM，列头（三语按后台当前语言）：时间（WIB）、用户 ID、昵称、关联帖子 ID、发了什么、状态、原因；最多 50,000 行（Q-13），超出截断并在文件末行写「已截断」。
6. L0：`OpsActivityGrantRowFormatterTest`（「发了什么」/ 状态 / 原因拼装：扣回、券跳过三种、VOID 两种、FAILED 七种原因码）。
7. L1：筛选五种状态条数正确；UNION 分页不重不漏；CSV 行数与 BOM。

### AC4 — 重新发放（E3、E4）`[L0]` `[L1]`
1. 筛「发放失败」后出勾选列；勾选后表头上方批量条「已选 {n} 条 · 重新发放」（照 `.selbar` 写法）；行内单条「重新发放」。
2. `POST …/{token}/grants/retry/confirm`（ids ≤ 100）→ 确认弹层 `cm.facts`：条数、涉及的奖励合计；文案「重新发放 {n} 条？已经到账的部分不会重复发。」。含 PawCoin 的记录且无 `user.grant_pawcoin` → 按钮置灰 + 原因（同 D11），直接 POST → 403。
3. `POST …/{token}/grants/retry`（`growth.config_edit`）：只处理本活动、`FAILED` 的 id（其他状态忽略）；逐条 `OpsActivityGrantService.execute(id)`；toast「已重新发放 {n} 条」（n = 本次变 `SENT` 的条数）；仍失败的留在「发放失败」并更新原因；停发用户的记录 → `VOID / USER_STOPPED`（Q-9）。审计 `OPS_ACTIVITY_GRANTS_RETRIED`（摘要：请求条数 / 成功条数）。
4. L1：故障注入后重发成功且只到账一次；权限 403；非本活动 id 被忽略。

### AC5 — 停发用户（E5）`[L0]` `[L1]`
1. 行内「停发」→ `POST …/{token}/stops/confirm?userId=` → 确认弹层（`withReason`，标题 / 正文「停发 {user}？之后这个活动不再给他发奖励，已发的不收回。」）。
2. `POST …/{token}/stops`（`growth.config_edit`，`userId`、`reason` trim 后 1–200）→ `OpsActivityStopService.stop(activityId, userId, reason, adminId)`（opsactivity 包内写 `ops_activity_user_stops`，`ON CONFLICT DO NOTHING` 幂等）；审计 `OPS_ACTIVITY_USER_STOPPED`；**不能恢复**（无撤销路由）。
3. 已结束活动也可停发（无副作用，仅留痕）——为简单起见允许。
4. L1：停发后该用户新行为无记录、明细出现「已停发」行；空原因 422 在弹层内。

### AC6 — 提前结束（E6）`[L1]`
`POST …/{token}/end-early/confirm` → 危险确认（`cm.danger` 红条 + `cm.diffs` 结束时间 旧 → 新 + 危险按钮），文案「提前结束这个活动？结束后不能再开始；已发的奖励不收回。」→ `POST …/{token}/end-early` → `OpsActivityConfigService.endEarly`；审计 `OPS_ACTIVITY_ENDED_EARLY`。排名活动提前结束后详情页立刻显示 F1（名单生成中）。
