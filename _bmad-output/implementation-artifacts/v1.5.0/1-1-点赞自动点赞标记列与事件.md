## Story

As a 后端,
I want 每一条点赞都能分清「是不是自动任务点的」，并让这个标记随点赞事件传给各个监听,
so that 后续的自动点赞任务只需要一个开关就能让自动赞「对作者像真赞、对排序像没发生」。

public record ContentLikedEvent(long postId, long likerId, long authorId, Instant createdAt, boolean automated) {
    /** 真人点赞（既有调用点与测试沿用，automated = false）。 */

**AC3 — `LikeService.likeAutomated`** `[L0]` `[L1]`（L-3、A-AC21）
1. `ContentLikeRepository` 新增：
   ```java
   /** 自动点赞写入（V1.5.0）：已赞则不插，返回插入行数（0 / 1）。不靠异常判重——外层事务里吞唯一约束异常会把事务标成 rollback-only。 */
   @Modifying
   @Query(value = "INSERT INTO content_likes (post_id, user_id, created_at, is_automated) VALUES (:postId, :userId, now(), true) "
           + "ON CONFLICT ON CONSTRAINT uq_content_likes_post_user DO NOTHING", nativeQuery = true)
   int insertAutomatedIfAbsent(@Param("postId") long postId, @Param("userId") long userId);
   ```
2. `LikeService` 新增：
   ```java
   public record AutomatedLikeResult(boolean created, long likeCount) {}

   /** 自动点赞专用（V1.5.0 FR-215/217）。不做可见性校验（调用方已复查）；只有真新建一行才发事件（automated = true）。 */
   @Transactional
   public AutomatedLikeResult likeAutomated(long postId, long virtualUserId, long authorId)
   ```
   `insertAutomatedIfAbsent == 1` 且 `virtualUserId != authorId` → `events.publishEvent(new ContentLikedEvent(postId, virtualUserId, authorId, Instant.now(), true))`；返回 `new AutomatedLikeResult(inserted == 1, likes.countByPostId(postId))`。
3. 既有 `like(postId, userId)` / `unlike(...)` **一行不改**（App 接口行为不变）；App 点赞写入的行 `is_automated = false`（A-AC46）。

### 实现提示
- 原生 INSERT 不经过 `@PrePersist`，所以显式写 `created_at = now()`（与 V10 默认值一致，UTC）。
- `likeAutomated` 不调 `requireVisible`：派发方（Story 2.3）在同一事务里已复查 PUBLIC / PUBLISHED / 未删 / 作者状态，比 `requireVisible` 更严。
- 事件仍由 `ApplicationEventPublisher` 发布；所有监听 `AFTER_COMMIT`，外层事务回滚 = 无通知、无里程碑（Story 2.3 依赖这一点，A-AC35）。
