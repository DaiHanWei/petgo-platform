# Story 1.2: 健康下次日期规则与预填接口（后端）

Status: ready-for-dev

> 版本 v1.5.0 · 会话 ① 健康记录提醒 · 分支 `feat/1.5.0-health-reminder`
> 口径优先级：CROSS-STORY-DECISIONS 地基段 > 架构增量 §2、§3（3.1 ~ 3.5）、§6.1 > PRD FR-158、FR-159、FR-160、FR-163「Pet age」、FR-168「Free-text vaccines」、FR-171、附录 B.1 > UI 稿 B2–B8、C1–C7、D1–D4。
> 前置：Story 1.1（字段、枚举、DTO）。

## Story

As a 宠物主人,
I want 填健康记录时系统按宠物年龄、物种和历史帮我预填 Next date，列表里每条记录显示「Berikutnya / Melewati jadwal / 已完成」,
so that 我不用自己算下次时间，一眼看到哪条需要处理。

## Acceptance Criteria

### AC1 — 日期工具 `[L0]`
1. `profile.health.HealthDates`：`today()` = `LocalDate.now(ScheduleWindow.WIB)`（可注入 `Clock`）；`ageInDays / ageInWeeks / ageInMonths(birthday, at)`；`plusMonths` 用 `LocalDate.plusMonths`（月末钳制，31 Jan + 1 = 28 Feb）；年龄组：`young` = event date 时未满 6 个月；`adult` = ≥6 个月**或无生日**。
2. `nextRunDate(Instant now)` = WIB 时刻 < 10:00 → 当天，否则次日（架构 §4.2）。放这里供 2.x 复用。

### AC2 — 疫苗系列规则 `[L0]`（PRD FR-159 两张表，AC1、AC7、AC9、AC56）
1. `VaccineSeriesRule.next(preset, dose, eventDate, birthday, petHasPuppyDpRecord)` → `NextDateSuggestion(nextDate, dueVaccinePreset, dueDose)`，按架构 §3.2 自上而下第一条命中；DP 剂次 >2 当 2。系列长度表见架构 §3.1；Combo 在宠物有任一 Puppy DP 记录时 young 长度为 2。`OTHER` / 无预设 → 无预填（null）。
2. 参数化用例至少覆盖 PRD：AC1（2026-10-01 出生小猫，F4 第 1 剂 2026-12-03 → 2026-12-31）；AC7 全部子句（小猫空剂次 8/12/16 周恰好 2 次系列提示后转加强；成年猫 / 无生日猫一致；成年狗 Combo；FeLV / Lepto 第 1 剂 +4 周；12 周 Rabies → +1 年；有 / 无 DP 的 Combo）；AC9（DP 第 2 剂 3 月 1 日 → 3 月 22 日，到期 Combo 第 1 剂；空剂次同第 2 剂；DP 第 1 剂 → +4 周）；AC56（成年猫 F4 第 1 剂 → 到期剂次 2；第 2 剂 / 空 → 加强、到期剂次空）。
3. 6 个月跨越：每剂按自己的 event date 判年龄组（5 个月第 1 剂、6.5 个月第 2 剂 → 第 2 剂已是 adult，系列完成 → +1 年）。

### AC3 — 驱虫规则 `[L0]`（PRD FR-160、FR-163 表、AC11、AC19）
1. `DewormRule.next(type, durationMonths, eventDate, birthday)`：INTERNAL <8 周 +14 天 / 8 周–<6 个月 +1 个月 / ≥6 个月或无生日 +3 个月；EXTERNAL +duration（null → 1）；FLEA_WORM +1 个月；HEARTWORM +1 个月；`null`（Legacy）+3 个月。
2. 用例：AC11（EXTERNAL 3 个月）；AC19（6 个月以上 +3 个月；3–6 个月 +1 个月；5 周与 7 周 6 天都是 +14 天）。

### AC4 — 发情周期与平均间隔 `[L0]`（PRD FR-171、词表 Heat episode、AC31、AC32、AC35）
1. `HeatEpisodes.of(heatRecords, petType)`：按 event date（同日按 created_at、id）升序分周期；与周期首条相差 < 10 天（CAT）/ < 21 天（DOG 及其他）归入；不链式。输出每条记录所属周期与是否首条。
2. `HeatRule.nextForFemaleDog(episodeFirstDays)`：最近 3 次首日的间隔（1 或 2 个），丢弃 <120 天，有剩余取均值（四舍五入到天）加到最近一次首日，否则 +6 个月；钳在 [+4 个月, +12 个月]。只对 DOG + FEMALE + 未绝育（`NEUTERED` 以外，null 与 UNKNOWN 都算未绝育）的周期首条给值。
3. 用例：AC31（1 Jan 2027 → 1 Jul 2027；第二次 1 Jul（间隔 181）→ 29 Dec 2027）；AC32（第三次 29 Dec → 27 Jun 2028；20 天间隔被忽略）；AC35 周期分组（猫 1/2/4 Mar 一个周期；1–7 Mar 一个、15 Mar 新周期；狗 1/3/6 Jan 一个周期且 Next date 只看 1 Jan）。

### AC5 — 覆盖组与显示状态 `[L0]`（架构 §3.3、§3.4，PRD 词表、FR-158、FR-161、AC4、AC14、AC21、AC51、AC53）
1. `RecordKinds.kindOf(record, petType)`：疫苗预设 / 规范化名字（trim + 小写 + 空白折叠；「其他」名字规范化后等于某预设标签 → 该预设）；驱虫类型（null → `LEGACY`）；Custom 规范化名；其余 = 类型；Vet visit 每条独立。
2. `CoverageGroups`：`{F3,F4}` 合组；Combo 覆盖 Puppy DP；FLEA_WORM 覆盖 INTERNAL、EXTERNAL；INTERNAL + EXTERNAL 相差 ≤3 天成对覆盖 FLEA_WORM（对的日期取较晚者）；任何已分型驱虫覆盖 LEGACY；「被覆盖」⇔ 覆盖记录 event date ≥ 组内最新记录 event date。只单向。
3. `RecordDisplayStatus.compute(records, pet, today, effectiveLaunchDate)` → 每条 `(displayNextDate, recordStatus, nextDateLocked)`，规则逐条按架构 §3.4（含回填静默、发情永不 OVERDUE、发情后续记录显示首条 Next date 且 `nextDateLocked=true`、Vet visit 各自显示直到出现 event date ≥ NextDate−1 的另一条 Vet visit）。
4. 用例：AC4（F4 Next 1 Dec：1 Dec 前 UPCOMING/DUE_SOON，2 Dec OVERDUE；记 F3 5 Dec 后 F4 变 DONE）；AC14 显示部分（Vet visit Next 14 Nov，记 5 Nov 的另一条不影响；记 13 Nov 的 → 满足）；AC21（Flea+worm 覆盖 Internal 后 Internal DONE；删 Flea+worm 恢复 `displayNextDate=1 Apr`；15 Feb 新 Internal 开新周期）；AC51 / AC53 回填静默；DUE_SOON 边界（今天与今天+7 都算）。

### AC6 — 疫苗关键词匹配 `[L0]`（架构 §3.5，PRD AC50、AC51）
1. `VaccineKeywordMatcher.match(text, petType)` → `VaccinePreset`（含 `OTHER`）。用例：「Vaksin tricat」(CAT) → F3；「F4 + rabies」→ OTHER；「Vaksin DHPPi+L」「dhpp + lepto」(DOG) → COMBO；「Lepto」「Vaksin Leptospirosis」→ LEPTO；猫的「dhpp」→ OTHER（物种过滤）；大小写 / 标点不敏感；「f3」只认整词（「f35」不算）。

### AC7 — 预填接口 `[L0]` `[L1]`（架构 §6.1）
1. `POST /api/v1/pet-profiles/me/health-records/preview?petId=`，JWT、宠物归属同现有端点（404 防枚举）；限流 `rl:health-record:preview:<owner>` 60 次 / 分钟。
2. 入参 `HealthRecordPreviewRequest {Long recordId, String type, String vaccinePreset, String vaccineName, Integer dose, String dewormType, Integer productDurationMonths, LocalDate eventDate}`；出参 `HealthRecordPreviewResponse {LocalDate suggestedNextDate, boolean nextDateAllowed, boolean nextDateLocked, LocalDate lockedNextDate, LocalDate nextDateMin, LocalDate nextDateMax, String dueVaccinePreset, Integer dueDose, List<String> hints}`。
3. `nextDateAllowed`：NEUTER、CAT 发情、MALE 发情、sex=null 发情、非母狗发情 → false；其余 true（OTHER 物种也 true，但 `suggestedNextDate` 恒 null）。发情周期后续记录（按传入 eventDate 与该宠物现有发情记录算，编辑时排除 recordId 自己）→ `nextDateLocked=true` + `lockedNextDate` = 首条的 Next date。
4. `nextDateMin = eventDate + 1 天`、`nextDateMax = eventDate + 3 年`；eventDate 为空 → 全部 null、hints 只出与日期无关的。
5. `hints`（顺序固定）：`VACCINE_PREGNANT`（疫苗 + 怀孕）、`RABIES_YEARLY`（疫苗 + RABIES）、`DEWORM_UNDER_8_WEEKS`（驱虫 EXTERNAL/FLEA_WORM/HEARTWORM + eventDate 时 <8 周）、`DEWORM_PREGNANT`（驱虫 + 怀孕）、`PERMETHRIN`（DOG + `catInHome=true` + EXTERNAL/FLEA_WORM）、`HEARTWORM_TEST`（DOG + HEARTWORM + >6 个月 + 无 HEARTWORM 记录（编辑排除自己））、`HEAT_NEUTERED`（发情 + NEUTERED）。
6. 「宠物有 Puppy DP 记录」「最近发情」等历史从库里现查（编辑时排除 recordId）。

### AC8 — 列表显示字段 `[L0]` `[L1]`
1. `HealthListItemResponse` 追加 `displayNextDate`、`recordStatus`（OVERDUE / DUE_SOON / UPCOMING / DONE）、`nextDateLocked`；问诊只读行 `recordStatus=DONE`。`effectiveLaunchDate` 读 `health_reminder_settings.launch_date`——该表在 2.1 才建：本 story 先定义接口 `LaunchDateProvider`（默认实现返回今天 WIB），2.1 换成读表实现。
2. 默认 Next date 接入：1.1 留的 `HealthRecordDefaults` 在旧版客户端**新建**时调用 `NextDateRules`（含关键词匹配）写默认 next_date；编辑分支留给 1.3。
