## Story

As a 宠物主人 / 访客,
I want 按笔看到这只宠物收到的每一份礼物、主人能一份份或一次全部拆开,
so that 收礼像拆礼物，而不是看一个累计数字。

## Acceptance Criteria

### AC1 — 逐笔列表 `GET /api/v1/pets/{petId}/gift-orders` `[L0]` `[L1]`（D-12、架构 §4.1）
1. 参数 `filter=ALL|UNOPENED`（缺省 ALL）、`categoryId`（可空）、`cursor`；每页 30。
2. 可见性 = `GiftShowcaseAccess.requireVisible(viewerId, petId)`（与旧礼物页同一判定，宠物不可见 → 同旧接口的状态码）。
3. 只列 `status = 'DELIVERED' AND pet_id = :petId`。`categoryId` 过滤按礼物**当前**所在分类（`JOIN gift_catalog g ON g.id = o.gift_id WHERE g.category_id = :cid`；专属礼物只在 ALL 里出现）。
4. 主人视角：排序 `(opened_at IS NULL) DESC, delivered_at DESC, id DESC`，`UNOPENED` 只列 `opened_at IS NULL`；响应带 `unopenedCount`。访客视角：排序 `delivered_at DESC, id DESC`，`UNOPENED` 当 `ALL`，`items[].opened` 与 `unopenedCount` 均为 `null`（JSON 省略或 null，App 两种都要能读）。
5. 游标：`GiftOrderCursor`（base64url，含 unopened 标志、`delivered_at` 微秒、id），解析失败 → 400 `validation`「游标无效」（照 `SupporterCursor`）。
6. 首页（无 cursor）另带 `categories`：全部在线分类（`sort_order, id`），供筛选胶囊；另带 `pet`（**复用** `PetGiftShowcaseResponse.PetView` 类型，组装照 `PetGiftShowcaseController.showcase`）与 `viewerIsOwner`。不要新建一个同义的宠物视图类型——④ 物种线会给 `PetView` 末尾加字段，复用才能自动带上。
7. 卡片字段照架构 §4.1 `GiftOrderCard`；送礼人批量取 `AccountQueryService.findAuthorViewsWithoutTags`，注销 → `nickname/avatarUrl = null, deleted = true`；头像走 `AliyunOssClient.exifStrippedDeliveryUrl`（照 `PetGiftShowcaseController`）。
8. 不下发 `sender_id`（卡片上）/ `owner_id` / 目录 token / 订单自增 id；本接口不打日志。
9. L1：`PetGiftOrderListIntegrationTest`：主人未拆在前、访客无 opened 字段、分类过滤、翻页无重复无遗漏（同一 `delivered_at` 多笔）、宠物被删 404。

### AC2 — Diary 礼物行 `GET /api/v1/pets/{petId}/gift-orders/preview` `[L1]`
`{giftCount, unopenedCount(仅主人), recent: [≤10 GiftOrderCard]}`；`giftCount = Σ quantity`（已送达，读 `gift_pet_wall` 汇总 `Σ count` 即可）；`recent` 排序同 AC1 对应视角。

### AC3 — 详情 `GET /api/v1/gift-orders/{orderToken}` `[L0]` `[L1]`
1. 订单不存在 / 非 DELIVERED / 宠物已删（`pet_id IS NULL`）→ 404；查看者对该宠物不可见 → 同 AC1。
2. 字段照架构 §4.1 `GiftOrderDetail`：`message` 在 `message_hidden_at` 非空时为 `null` 且 `messageHidden = true`；`sender.userId` 仅送礼人未注销时给（App「Lihat profil」走现有 `/users/{id}`）；`sender.petNames` = 送礼人名下未删除宠物名，最多 3 个，按建档时间；`ownerExp` 仅主人视角 = 主人参与成长体系 ? `pointsForAmount(GIFT_RECEIVED, unitPrice × quantity)` : 0（D-7；免费礼物按面值，故 4-3 后同样成立）；`canReport` 照架构定义。
3. 访客也能看主人未拆的礼物（含祝福语）——不因 `opened_at` 为空而拒绝。
4. L0：`GiftOrderDetailAssemblerTest`（隐藏祝福语、注销送礼人、访客无 opened / ownerExp、canReport 三条件）。

### AC4 — 拆礼物 `POST /api/v1/pets/{petId}/gift-orders/open` `[L0]` `[L1]`（D-7）
1. 仅主人（`viewerIsOwner`），否则 403。
2. body 二选一：`{orderTokens: [1..50]}` 或 `{all: true}`；都没有 / 都有 / 超 50 → 422。
3. 写库：`UPDATE gift_orders SET opened_at = now() WHERE pet_id = :petId AND status = 'DELIVERED' AND opened_at IS NULL AND public_token IN (:tokens)`；`all` 时取最早 200 笔未拆（`delivered_at ASC`）。不属于这只宠物的 token 忽略（不报错、不返回）。
4. 响应 `{items: [GiftOrderDetail], totalOwnerExp}`：`items` = 本次请求涉及的全部订单（含本来就已拆的，`alreadyOpened = true`），按 `delivered_at DESC`；`totalOwnerExp = Σ items.ownerExp`。
5. **不调用任何成长值 / 钱包 / 通知**（守卫：`GiftOpenService` 不注入 `GrowthLedgerService`、`PawCoinWalletService`、`NotificationService`，用 L0 反射测试断言构造参数类型）。
6. 并发两次拆同一笔：两次都 200，第二次 `alreadyOpened = true`。
7. L1：`GiftOpenIntegrationTest`：单笔、批量 all、非主人 403、他宠 token 被忽略、拆后 growth_ledger 行数不变。

### AC5 — 统计与 H5 名片 `[L1]`（D-11、FR-192）
1. `ArchiveStatsResponse`、`VisitorStats` 末尾新增 `long giftCount`（Σ quantity，已送达，按宠物）；旧字段 `giftTotalValue` 保留、值不变（旧版 App 用）。
2. `B/profile/web/CardPageController`：票根「Hadiah」列改显示 `giftCount`（整数千分位，按页面语言），模板里不再出现「Rp」与 `IdrCompact` 单位；布局不变。对应模板与 `CardPageControllerTest`（或现有 H5 测试）断言更新。

### AC6 — 旧接口保留 `[L0]`
`GET /api/v1/pets/{petId}/gifts`、`/gifts/supporters` 与 `gift_pet_wall` / `gift_pet_supporters` 写入不改；现有测试全部保持原断言。
