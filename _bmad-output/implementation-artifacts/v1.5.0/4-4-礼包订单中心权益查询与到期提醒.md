## Story

As a 用户,
I want 在我的订单里看到礼包单（含待支付）、随时查我还有多少免费次数、快过期时被提醒,
so that 买了什么、还剩什么一目了然。

## Acceptance Criteria

### AC1 — 订单中心第 6 源 `[L0]` `[L1]`（D-26）
1. `OrderType` **末尾**加 `STARTER_PACK`；`OrderDisplayNo` 加前缀常量 `PAKET`。
2. `OrderCenterService.listOrders` 加重载参数 `includeStarterPack`（旧重载默认 false，老 App 结果逐字不变）；`RANK_STARTER_PACK = 5`（只追加）；分支追加在 if 链**末尾**：`(filter == null && includeStarterPack) || filter == STARTER_PACK` 时查 `starter_pack_purchases`：`status = PAID` 全部 + `status = PENDING AND pay_expires_at > now`，同一游标规则（`created_at` 倒序 + rank + id），各取 `limit + 1`。
3. 映射：PAID → `statusCode = PAID`、`SUCCESS` 色；PENDING → `statusCode = PENDING`、`WARN` 色（照 `mapTopupPending`）；`amount = price`、`payChannel`、`displayNo = OrderDisplayNo.of(PAKET, id, createdAt)`；卡片新增可选字段 `starterPackTier`（int，仅本类型）。
4. 详情 `orderDetail(token)`：支持礼包 token，额外字段 `starterPack: {tier, contents, creditsExpireAt, slot: {outcome, expiresAt, petName}}`；PENDING 时另带 `purchaseToken`（App「继续支付」调 4-2 的状态接口取二维码）。
5. 控制器 `GET /api/v1/me/orders` 接 `includeStarterPack` 参数（缺省 false）。
6. L1：`OrderCenterStarterPackIntegrationTest`：闸门 false 时无礼包行；true 时 PAID + 未过期 PENDING 入列、过期 PENDING / FAILED 不入；与充值、keepsake 同毫秒混排翻页无漏无重；详情字段。

### AC2 — 权益汇总 `GET /api/v1/me/entitlements` `[L0]` `[L1]`
调 `EntitlementCreditService.summary`，响应照架构 §4.2：family 顺序固定 `KTP_HD, TAILSONALITY, GIFT_1K`；KTP 的 `templates` 按 `CreditType` 声明序（8 款在前、`ANY` 最后），剩余 0 的不列；`expiringSoon = earliestExpiry ≤ now + 7 天`；只列 `remaining > 0` 的 family；`totalRemaining`。游客 401。

### AC3 — 权益记录 `GET /api/v1/me/entitlements/history?cursor=` `[L0]` `[L1]`
1. 两源归并：发放行（`entitlement_credits`，`kind = GRANT`，`at = created_at`，`quantity`，`source`，PACK 时 `packTier` = 关联 `starter_pack_purchases.tier`（按 `source_ref` 查），ACTIVITY 时 `labelId/labelEn`）与使用行（`entitlement_credit_uses`，`kind = USE`，`useKind`，`petName`，`quantity`）。
2. 每页 20；排序 `at DESC, kindRank ASC (GRANT 0, USE 1), id DESC`；游标 base64url `(at 微秒, kindRank, id)`，写法照 `OrderCenterCursor`（同刻组靠 `idBound` 编进 SQL）。
3. 一次使用跨多批时（如一次送礼扣了两批），流水表里是每批一行；接口**在服务端按 `use_key` 聚合成一行**返回（`quantity` 求和、`creditType` 取第一批），游标用该组最小 id。App 不做合并。
4. L1：`EntitlementHistoryIntegrationTest`：礼包发放 + KTP 使用 + 送礼跨两批使用的顺序与合并；翻页。

### AC4 — 到期提醒任务 `[L0]` `[L1]`（D-27）
1. `EntitlementExpiryReminderJob`：`@Scheduled(cron = "0 0 3 * * *", zone = "UTC")`（= 10:00 WIB）；带分布式互斥（照现有定时任务的 advisory lock / ShedLock 写法，grep 现有 `@Scheduled` 任务取同一种）。
2. 取批：`used < quantity AND expires_at > now AND expires_at <= now + interval '7 days' AND expiry_notified_at IS NULL`；按（用户, family）分组；每组取最早到期的 WIB 日期 `D`，`n` = 该组 `expires_at` 落在 WIB 日 `D` 的批剩余之和。
3. 每组发一条 `NotificationType.PACK_CREDIT_EXPIRING`：`notifications.sendWithoutPush(userId, PACK_CREDIT_EXPIRING, title, body, "PACK_CREDIT_EXPIRING", null)`；标题 / 正文按收件人语言（`accounts.localeOf`）从 `messages*.properties` 取：
   - `notify.PACK_CREDIT_EXPIRING.title`：ID「Jatah gratis kamu segera berakhir」/ EN「Your free credits expire soon」
   - `notify.PACK_CREDIT_EXPIRING.body`：ID「{0} jatah {1} berakhir {2}. Pakai sebelum hangus, ya!」/ EN「{0} {1} credits expire on {2}. Use them before they're gone!」（PRD B §7 原文，`{n}/{type}/{date}` → `{0}/{1}/{2}`）
   - `{1}` 类型名（待拍板 Q-8）：`notify.packCredit.type.KTP_HD` ID「HD KTP」/ EN「KTP HD」；`.TAILSONALITY` 两语「Tailsonality」；`.GIFT_1K` ID「hadiah Rp1.000」/ EN「Rp1.000 gift」
   - `{2}` 日期：WIB 日期 `d MMM yyyy`（按 locale 月份缩写，如「20 Nov 2026」）
   四个语言文件（含默认 `messages.properties`、`messages_zh_CN`）key 集合一致。
4. 本组被扫到的批（所有 `expires_at` 在窗口内的）`UPDATE … SET expiry_notified_at = now()`，与发通知在同一用户粒度的事务里；发通知失败 → 不写 `expiry_notified_at`（下次重试），记 WARN（只记 userId / family）。
5. 注销 / 注销受理中 / 虚拟号跳过（同时把其批标 notified，免得每天重扫）。
6. **不推送**、不改 `kPushDirectTypes`、不改 `ck_notifications_type`。
7. L0：`EntitlementExpiryGroupingTest`（纯函数：分组、取最早日期、n 计算、WIB 跨日边界）。
8. L1：`EntitlementExpiryReminderIntegrationTest`：7 天内到期发一条、8 天不发、已提醒不再发、两个 family 两条、通知 `push = false`（推送桩未被调用）。
