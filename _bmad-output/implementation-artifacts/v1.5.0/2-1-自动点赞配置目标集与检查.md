## Story

As a 自动点赞任务,
I want 每帖只在发帖 36–60 小时时看一次赞数，不足 5 的记进目标集，并留下「检查过」的痕迹,
so that 冷清的帖子会被持续补赞，而每帖只进一次、离开就不再回来。

## Acceptance Criteria

**AC1 — 配置类** `[L0]`（FR-222、L-12、Q-1、Q-10）
新建 `content/autolike/AutoLikeProperties.java`，`@ConfigurationProperties(prefix = "petgo.auto-like")`，字段与默认值：

| 字段 | 类型 | 默认 |
|---|---|---|
| `enabled` | boolean | `true` |
| `morningCron` / `eveningCron` | String | `"0 30 10 * * *"` / `"0 30 16 * * *"` |
| `checkWindowMin` / `checkWindowMax` | Duration | `36h` / `60h` |
| `maxPostAge` | Duration | `7d` |
| `likeTarget` | int | `5` |
| `likesPerRun` | int | `1` |
| `maxLikesPerAuthorPerRun` | int | `1` |
| `spreadWindow` | Duration | `3h` |
| `holdoutPercent` | int | `10` |
| `holdoutSalt` | String | `"tt-auto-like-holdout-v1"` |
| `maxFailures` | int | `3` |
| `stopAfterConsecutiveFailures` | int | `10` |
| `dispatchIntervalMs` | long | `60000` |
| `dispatchBatch` | int | `200` |

- 启动校验（`@PostConstruct` 或 `@Validated` + 自定义）：`likesPerRun != 1` → 抛 `IllegalStateException("petgo.auto-like.likes-per-run 目前只支持 1（每槽每帖一赞，见 FR-212）")`（Q-1）；`checkWindowMin < checkWindowMax <= maxPostAge`、`0 <= holdoutPercent <= 100`、`likeTarget >= 1`、`spreadWindow > 0` 不满足同样启动失败。
- 类注释照 `AutoCommentProperties` 写法说明：`enabled` 是**部署层**开关，没有后台开关（决策 2026-11-09）。

**AC2 — yml** `[L0]`（FR-221、L-12）
- `application.yml` 在 `auto-comment:` 段之后加 `auto-like:` 段，每项 `${AUTO_LIKE_…:默认}`（env 名见架构 L-12 表；`likes-per-run` / `holdout-salt` / `dispatch-batch` 不进 env，直接写默认值）。注释写明：「🔴 enabled 默认 true（stag / 生产部署即生效，同自动评论）；`application-dev.yml` 覆盖为 false，本机连真库也不会点赞、推送。stag 想立刻验证：把 `AUTO_LIKE_MORNING_CRON` 临时设成 `0 */10 * * * *`（每 10 分钟）。」
- `application-dev.yml` 加：
  ```yaml

  petgo:
  ```

**AC3 — 对照组** `[L0]`（FR-223、L-11、A-AC48）
`content/autolike/AutoLikeHoldout.java`：`boolean isHoldout(long userId)` = `SHA-256((salt + ":" + userId) UTF-8)` 前 8 字节按无符号 long `Long.remainderUnsigned(v, 100) < holdoutPercent`。纯函数，无状态、不落库。

**AC4 — 目标集表** `[L0]` `[L1]`（L-7）
迁移 `V20261115_0510__init_auto_like_targets.sql` 建 `auto_like_targets`，列 / 约束 / 索引照架构 L-7 表逐字实现（`post_id` 唯一 + `REFERENCES content_posts(id) ON DELETE CASCADE`；`author_id` 不设外键；`leave_reason` CHECK 七值 `AT_TARGET_ON_CHECK, HOLDOUT, REACHED_TARGET, MAX_AGE, POST_GONE, NO_IDENTITY, TOO_MANY_FAILURES`；`(left_at IS NULL) = (leave_reason IS NULL)`；`joined OR left_at IS NOT NULL`；部分索引 `ix_auto_like_targets_open ON (author_id, post_created_at, post_id) WHERE joined AND left_at IS NULL`）。表与每列 `COMMENT ON`。实体 `AutoLikeTarget`（`leave_reason` 用 `@Enumerated(STRING)` + 枚举 `AutoLikeLeaveReason`，`length = 24`）+ `AutoLikeTargetRepository`。

**AC5 — 检查步骤 `AutoLikeCheckStep`** `[L0]` `[L1]`（FR-213、L-8 第 3–5 步）
`content/autolike/AutoLikeCheckStep.java`，方法 `CheckResult run(Instant runStart)`，**要求调用方已开启事务**（`@Transactional(propagation = MANDATORY)`），按序：
1. `boolean launch = !targets.existsAny()`（表里一行都没有，含已离开的）。**先判，再做第 2、3 步。**
2. 关闭：未关闭 `joined` 行中 `post_created_at <= runStart − maxPostAge` → `left_at = runStart, leave_reason = MAX_AGE`（A-AC50）；`failed_attempts >= maxFailures` → `TOO_MANY_FAILURES`（A-AC37，Q-4）。各一条集合 UPDATE。
3. 候选（原生，见架构 L-8 第 5 步 SQL）：真人帖 `PUBLISHED + PUBLIC + 未删`、作者 `REAL + USER + 未注销 + ACTIVE`（Q-8）、`created_at <= runStart − checkWindowMin` 且 `created_at > runStart − (launch ? maxPostAge : checkWindowMax)`、尚无目标集行；`ORDER BY created_at, id`；取 `(id, author_id, created_at, like_count)`，其中 `like_count` = 该帖**全部**赞（真人 + 虚拟 + 自动，即 App 显示的数）。
4. 逐条决定并批量写入（`INSERT … ON CONFLICT (post_id) DO NOTHING`）：
   - 作者 `holdout.isHoldout(authorId)` → `joined=false, left_at=runStart, leave_reason=HOLDOUT`（无论赞数，A-AC47）；
   - 否则 `like_count >= likeTarget` → `joined=false, AT_TARGET_ON_CHECK`（A-AC6）；
   - 否则 `joined=true`，`left_at / leave_reason` 为空。
   - 都写 `checked_at = runStart, like_count_at_check = like_count, post_created_at = created_at`。
5. 返回 `record CheckResult(boolean launch, int checked, int joined, int closedMaxAge, int closedFailures)`。

边界（A-AC5）：发帖恰好 36h → 检查；35h → 不查；恰好 60h → 不查（`>` 开区间）。审核中（`UNDER_REVIEW`）的帖本轮不满足条件、不写行；若下一轮还在窗口内且已恢复 `PUBLISHED` → 被检查（A-AC12）；过了窗口就永远不查（A-AC11）。

**AC6 — 首轮** `[L1]`（FR-221、A-AC9、AC10）
目标集表为空时那一轮用上限 7 天：50h / 1 赞、6 天 / 1 赞都进；8 天不查；发帖 30h 的不查，等它满 36h 后的普通轮再查。首轮识别**只看表是否为空**，开关关了又开不会产生新的首轮。

### 参照
- 配置类写法、`@EnableConfigurationProperties` 挂法：`content/autocomment/AutoCommentProperties.java`、`AutoCommentService.java:44-45`。
- 候选 SQL 形状：`content/autocomment/AutoCommentLogRepository.findCandidatePostIds`（作者 REAL/USER/未注销、`ORDER BY p.created_at, p.id`）——本 story 去掉「有图」「零评论」两条、加 `u.status='ACTIVE'` 与年龄上下界。

### 为什么 `like_count` 用全部赞
PRD §3「Like count: real and virtual together. This is the number the app shows.」——判定「冷清」用的是作者看得到的数；排序排除自动赞是另一件事（Story 1.2）。
