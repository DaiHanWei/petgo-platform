# Story 3.1: 送礼优化全链路联调（本地 L1 / L2）

Status: ready-for-dev

> 版本 v1.5.0 · 会话 ② gift-pack · 分支 `feat/1.5.0-gift-pack`
> 🔴 **云端不跑**：本 story 只在本地执行（Docker postgres + redis、Android 模拟器、真后端）。云端做到 2-6 后直接跳到 4-2。
> 前置：1-1 ~ 2-6 全部 review。

## Story

As a 操作者,
I want 在本地把送礼优化从后台配分类到送礼、拆礼物、举报整条走通,
so that 合进 dev 前确认前后端对得上、动画与还原度达标。

## Acceptance Criteria

### AC1 — L1 全绿 `[L1]`
- scratch 库（flush Redis DB 后重建）跑 Flyway 到 `V20261115_0210`：`gift`、`admin.gift`、`admin.moderation`、`profile`（统计 / H5）、`growth`（送礼成长值）包全部集成测试绿；记录条数。
- `bash scripts/ci/check-flyway-versions.sh origin/main` 通过。
- `mvn -B clean package` 后 `mvn spring-boot:run` 起得来、`/actuator/health = UP`（路由无撞车）。

### AC2 — 后台 `[L2]`
- 新建分类、改名重名被拒、有在线礼物下线被拦、礼物改分类、专属礼物无分类、分类下线后礼物不能重新上线（K1 ~ L6 逐屏）。
- 三条线上文案改写在中 / EN / ID 三语生效。

### AC3 — App 全链路 `[L2]`（Android 模拟器 + 真 Google 登录 + 本地后端）
1. 选礼物按分类、B3「dari 谁」、专属组与锁区块。
2. 包装页：祝福语 500 上限、命中敏感词不扣款（先在 `moderation_keyword_rules` 插一条 L1 词）、余额不足自动展开 / 默认直接付款 / 门槛置灰、充值往返内容保留。
3. PawCoin 送出 → Rive 送出动画 → 送达页 EXP 正确；QRIS（stub 网关）付款成功同样进动画。
4. 主人：Diary 礼物行 Baru、礼物页未拆在前、单个拆、批量拆（1 / 9 / >9 份）、逐条祝福语；拆后成长值流水**无新增**。
5. 收礼通知点开直接拆最新一笔；已拆过 → 详情。
6. 访客：看得到主人未拆礼物含祝福语、无「未拆」；举报祝福语 → 后台工单出现 → 隐藏 → App 显示隐藏文案。
7. 旧版 App（1.4.x 包）：送礼、礼物页汇总 / 粉丝榜照旧可用。
8. H5 宠物名片「Hadiah」列显示个数。

### AC4 — 还原度 `[L2]`
送礼 App 38 屏、后台 14 屏逐屏对照拆页打分，每屏 ≥ 95%；不足的列清单回到对应 story 修。

### AC5 — 上线前清单 `[L2]`
- 查生产非五档价格的普通礼物（只读、经用户同意后执行）交运营，按待拍板 Q-1 处理。
- 查线上礼物图标实际像素，列出非 1000×1000 的交运营重传（PRD A §6）。
- 设计师素材（`sendDone` / `revealDone` / `GiftVM.giftImage` / 礼盒 PNG）到位情况记录；到位则同名覆盖文件并复测 G1 ~ G6。
