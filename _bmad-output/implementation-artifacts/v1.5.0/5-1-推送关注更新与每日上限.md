## Story

As a 关注了别人的用户,
I want 我关注的人发新帖时收到一条推送（但不会被刷屏）,
so that 关注关系能把我带回来。

## Acceptance Criteria

**AC1 — 迁移 ⑤** `[L0]` `[L1]`
三表 DDL 照架构 §3.2 ⑤（`user_post_notify_log` PK `(follower_id, post_id)` + `wib_date` 索引、`user_post_push_daily` PK `(follower_id, author_id, wib_date)`、`follow_update_push_quota` PK `(user_id, wib_date)` + `used INT`）；无 FK、无实体；可重放。**不改** `ck_notifications_type`（地基已含 `USER_POST_PUBLISHED`）。

**AC2 — 公开帖触发、三类都算（PRD AC1 / AC2）** `[L1]`
A 关注 B，B 发公开 Moment / Tips / Diary → A 收到 `USER_POST_PUBLISHED` 通知 + 推送（A ≥ 1.5.0）；B 发私密帖 → 什么都不发。人工审核帖在审核通过时触发（`ContentPublishedEvent` 补发路径）。

**AC3 — 不触发的作者（PRD AC3）** `[L1]`
作者是官方号（`isOfficialAccount`）、虚拟号（`isVirtual`）或 `AutoFollowTargets.contains(author)`（env `AUTO_FOLLOW_USER_IDS`，不写死 id）→ 粉丝不推、通知中心也不写。作者非 `isActive` → 不发。

**AC4 — 收件人排除（PRD AC5）** `[L1]`
排除：作者本人、非 `isActive`、隐藏了作者（`hideRelations.holdersHiding`，拉黑与举报隐藏都算）、被作者拉黑（`hideRelations.blockedByHolder`）——与 `PetDiaryNotifyListener` 同口径。

**AC5 — 同帖命中追更只走追更（FR-181，PRD AC7）** `[L1]`
A 关注 B、也追更了 B 的宠物 Mochi；B 发公开 Diary 关联 Mochi → A 只收到 `PET_DIARY_POSTED`「Mochi …」一条，不收 `USER_POST_PUBLISHED`（`petFollows.followersOfAny(e.petIds())` 的收件人整体跳过）；即使 `PET_DIARY_POSTED` 因「今天已提醒过 Mochi」没发，也不改发本类。

**AC6 — 同作者每天推 1 条、通知每次写（PRD AC4）** `[L1]`
B 当天（WIB）发 3 条公开帖 → A 推送 1 条、通知中心 3 条（`user_post_push_daily` 抢位）；`user_post_notify_log` 3 行，outcome 依次 `PUSHED / AUTHOR_DUP / AUTHOR_DUP`。

**AC7 — 两类合计每人每天 3 条（PRD AC8 / AC9）** `[L1]`
A 当天已收 3 条关注 / 追更更新推送（两类任意组合），第 4 条起：通知照写、不推送（本类 outcome `CAP_REACHED`；`PET_DIARY_POSTED` 只留通知中心）。名额 = `petgo.follow-update-push.daily-cap`（默认 3，env `FOLLOW_UPDATE_PUSH_DAILY_CAP`）；WIB 00:00 后重置。关了分类 / 虚拟号 / 官方号 / 旧版不推的不占名额。

**AC8 — 分类关闭（PRD AC6）** `[L1]`
A 关闭 `PET_DIARY` 分类（App 显示「Yang kamu ikuti」）→ 不推送，通知照写（outcome `MUTED`）。

**AC9 — 旧版门槛（FR-185）** `[L1]`
`AppVersionGate.reportedV150OrLater(A) == false` → 通知照写、不推送（outcome `OLD_APP`）。`PET_DIARY_POSTED` 不加门槛。

**AC10 — 通知内容** `[L0]` `[L1]`
`NotificationService.sendUserPostPublished(recipient, postId, authorId, authorNickname, petName, isDiary)`：按收件人 `localeOf` 渲染标题并落库——Diary 且有宠物名：`notify.tpl.userPostPublished.diary`（ID `{0} baru update Diary {1}, kepoin yuk 👀` / EN `{0} just updated {1}''s Diary, take a peek 👀`）；否则 `notify.tpl.userPostPublished.post`（ID `{0} baru posting nih, intip yuk 👀` / EN `{0} just posted something new, take a peek 👀`）；`{0}` 作者昵称、`{1}` 帖子第一只关联宠物名；`body=""`；`deepLinkType=USER_POST_PUBLISHED`、`targetRef=postId`；角标 +1。推送标题同一句、正文空。四个 `messages*.properties` 都加（zh_CN 用中文意思）。

**AC11 — 回滚开关（FR-185）** `[L0]`
`petgo.follow-update-push.enabled`（默认 true，env `FOLLOW_UPDATE_PUSH_ENABLED`）为 false → 监听 no-op。

**AC12 — 清理** `[L0]`
`PetDiaryNotifyLogCleanupJob` 同时删三张新表 `wib_date < 今天(WIB) − 30 天` 的行。

**AC13 — 回归** `[L0]` `[L1]`
`PetDiaryNotifyListenerTest`、`NotificationServiceTest`、`PushCategoryTest` 全绿；`PET_DIARY_POSTED` 除「多一道名额闸」外行为不变。
