# Story 7.1: 超值礼包全链路联调（本地 L1 / L2）

Status: ready-for-dev

> 版本 v1.5.0 · 会话 ② gift-pack · 分支 `feat/1.5.0-gift-pack`
> 🔴 **云端不跑**：本 story 只在本地执行。云端做到 6-5 为止。
> 前置：4-1 ~ 6-5 全部 review；3-1 已完成。

## Story

As a 操作者,
I want 在本地把超值礼包从后台配置到购买、使用、到期提醒整条走通,
so that 合进 dev 前确认资金、次数、名额都对。

## Acceptance Criteria

### AC1 — L1 全绿 `[L1]`
- scratch 库（先 flush Redis DB，再重建）Flyway 跑到 `V20261115_0235`：`entitlement`、`starterpack`、`gift`、`profile`（KTP 次数解锁、名额）、`tailsonality`、`order`、`notify`、`growth`、`admin.config`、`admin.entitlement`、`admin.petslot`、`admin.gift`、`pay` 包全部集成测试绿。
- `bash scripts/ci/check-flyway-versions.sh origin/main` 通过；`mvn -B clean package` + `spring-boot:run` 健康 UP（无路由撞车）。
- 共享 CHECK 复核：`ck_payment_intents_purpose` 13 值 = `PaymentPurpose`；`gift_orders` / `id_card_hd_purchases` / `pet_slot_*` 约束与枚举一致；**`ck_notifications_type` 未被本线修改**。

### AC2 — 资金与次数 `[L2]`（Android 模拟器 + 真 Google 登录 + 本地后端，QRIS 用 stub 或沙箱）
1. 三档 PawCoin 购买：余额扣对、次数 9 / 10 / 15、名额 +1、EXP 40 / 55 / 65、成功页到期日 = 3 个月后 / 名额 30 天后。
2. QRIS 购买：待支付单在礼包页（C4）与我的订单（F1 / F3）可继续支付；付款后到账发放；过期后可重新下单。
3. 冷却：买完 7 天内三处入口状态正确（我的页「Beli lagi n hari」、礼包页置灰、推荐行隐藏）；服务端直接调接口也被拒。
4. 名额已满：5 个名额含租用 → 档 3 延长最早到期的租用名额（C10）；全是等级名额 → 档 2 / 3 置灰（C5）。
5. 使用：KTP 某款解锁扣该款、用完后扣 ANY（ANY 需先用 ⑥ 契约或 SQL 造一批 ACTIVITY 来源）；性格测试解锁不进我的订单；免费送 Rp1.000 礼物 ×5 → 主人得 EXP、送礼人不得、送礼人余额不变、主人拆礼物照常。
6. 合并页 D1 ~ D7 各状态；商城胶囊次数；到期提醒：把一批 `expires_at` 改到 6 天后、手动触发任务 → 通知中心出现 D8、无推送、点开进合并页。
7. 停售：后台关总开关 → App 礼包格 / 推荐行消失、合并页入口仍在、系统通知点开 toast 不跳转、开屏弹窗点按钮只关闭。
8. 后台：配置卡改价 / 停售 / 恢复 + 审计；补发三种类型（1–3 次、无权限 403、重放只一次）；支付记录 / 送礼记录 / 名额记录展示。
9. 旧版 App（1.4.x 包）：订单中心无礼包行；KTP / 性格测试付费解锁照旧；送礼照旧。

### AC3 — 付费抽屉 9 处回归 `[L2]`
KTP 高清、性格测试结果 / 配型、名额租用 / 续租、护照快照、登机牌、keepsake、礼包付款逐个点一遍：默认选中、余额不足、充值回来自动选回、QRIS 流程。

### AC4 — 还原度 `[L2]`
礼包 App 34 屏、后台 21 屏逐屏打分 ≥ 95%；不足的回对应 story 修。

### AC5 — ⑥ 契约复核 `[L1]`
用一段测试代码按架构 §5 的 `GrantCommand.activity(...)` 发一批 `KTP_HD_ANY`，确认：同键重放不重复、App 合并页记录显示「Event · {name}」。Completion Notes 写明 4-1 合 dev 的时间与提交号（若已单独合过）。
