## Story

As a 维护者,
I want 在三条线合入 dev 之后，把它们新增的类型显示、物种匹配和里程碑计算都接到细分类型 / 清单归属上,
so that 最后合并的本线不会留下「新代码还在按三值显示」的死角。

1. 从最新 `dev_1.5.0` 切 `feat/1.5.0-pet-species-align`；`git merge feat/1.5.0-pet-species`。**不把 dev 反向合并进 `feat/1.5.0-pet-species`**。
2. 冲突解决原则（架构 G-1）：两边新增字段都保留（实体 / DTO / 请求体末尾追加的顺序：先别的线、后本线，便捷构造器都保留）；App `OpsAppPage` 两值都留、`starterPack` 在前；同一行一边换函数一边改布局 → 保留布局改动、再把类型显示换成 `petSpeciesView`。

### AC2 — 后端扫描 `[L0][L1]`
1. `grep -rn "getPetType()\|\.petType()" petgo-backend/src/main/java`，对**三条线新增**的每一处判定并在 Completion Notes 列表：
   - 用于显示的返回体字段 → 追加 `species`（照 1.3 写法）；
   - 用于里程碑 / 新手任务 code 计算的（如首日线改动的 `NewbieTaskService`、健康线新增的健康类里程碑）→ 改读 `getMilestoneTrack()`，并让 `MilestoneTrackUsageGuardTest` 覆盖到新文件；
   - 业务按大类的（健康提醒规则、送礼物种排序等）→ 保持 `pet_type`，不动（G-3）。
2. **首日线 FR-174 同物种匹配**（首日 PRD §6：「只读 `pet_profiles` 的物种字段做同物种匹配，不写死物种枚举」）：首日线 Story 1-1（`1-1-首日推荐宠物接口排序与游客访问.md` 任务 3.2）已约定「物种扩展线以后只改 `speciesKeyOf(PetProfile)` + SQL 过滤列」：把 `speciesKeyOf` 改为返回 `pet.getPetSpecies().name()`，`ContentPostRepository.findRecommendablePets` 里按物种过滤的 `pp.pet_type` 谓词改为 `pp.pet_species`（同品种 → 同细分物种其他品种 → 其他物种 → 全站；「其他」组物种各自成池，`OTHER` 仍与 `OTHER` 匹配）；埋点 `match` 取值不变。补该线 `PetRecommendationIntegrationTest` 一条兔子用例（兔子主人先看到兔子，不再先看到全部「其他」）。
3. 健康线若在 `PetProfileUpdateRequest` / `ProfileService.update` 里加了字段处理：确认本线 `applySpeciesChange` 仍在 `requireWritable` 之后、其他字段之前，且冷却 409 时健康字段同样不落库（整次回滚）。
4. L1：`profile`、`admin.usermgmt`、`gift`、`social`、`content` 以及三条线各自的集成测试包全绿。

### AC3 — App 扫描 `[L0][L2]`
