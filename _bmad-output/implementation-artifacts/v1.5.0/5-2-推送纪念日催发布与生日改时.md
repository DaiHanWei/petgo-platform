## Story

As a 养宠用户,
I want 陪伴纪念日在晚上提醒我「拍一张记下来」并直接打开这只宠物的发布页、生日提醒在上午到,
so that 推送能变成一条真实的记录。

## Acceptance Criteria

**AC1 — 两个日扫（FR-186 / FR-182）** `[L0]`
`ScheduledPushJob` 拆为 `runBirthdayScan`（`@Scheduled(cron = "${petgo.scheduled-push.birthday-cron:0 0 4 * * *}", zone = "UTC")` = 11:00 WIB，只产出 `PET_BIRTHDAY` 与第一个生日 `MILESTONE_NODE`）与 `runAnniversaryScan`（`${petgo.scheduled-push.anniversary-cron:0 0 12 * * *}` UTC = 19:00 WIB，只产出 `COMPANION_ANNIVERSARY`）；旧键 `petgo.scheduled-push.cron` 从 `application.yml` 删除。`ScheduledPushPlanner` 新增 `planBirthdays(...)` 与 `planAnniversaries(...)` 两个方法；🔴 **现有 `plan(LocalDate, List<PetProfileSnapshot>, Set<String>)` 签名保留**（健康提醒线 ① 调它判生日 / 第一个生日占用，见 `cloud-rules-health-reminder.md`），实现改为两者并集，生日部分语义不变。`PetProfileSnapshot` 加字段时**保留原 5 参构造器**（健康线测试会直接 new 它）。

**AC2 — 生日只改时间（PRD AC27 / AC28）** `[L0]` `[L1]`
宠物 11/20 生日 → 11/19 11:00 WIB 推；明天满 1 岁 → 生日 + 第一个生日两条都在 11:00 这一批；触发日、文案、去重（`scheduled_push_marks`）、分类（宠物提醒）、`targetRef`、点开去向全部不变（仍走 `sendWithCopy`）。`today` 改为 `LocalDate.now(ScheduleWindow.WIB)`。

**AC3 — 纪念日按 WIB、只推 ACTIVE（PRD AC10 / AC12）** `[L0]` `[L1]`
- 天数 = WIB 今天 − 建档时间按 WIB 折算的日期（`PetProfileSnapshot` 加 `createdDateWib`、`status`、`ownerActive`）；节点 30 / 100 / 365 不变。
- 只读宠物、owner 非 `isActive` → 不推、不写通知、**不写** `scheduled_push_marks`（恢复 ACTIVE 后当天仍满节点的话下一轮还能发——实际一天只扫一次，等价于不发）。
- 受 `petgo.scheduled-push.anniversary-enabled`（默认 true，env `ANNIVERSARY_PUSH_ENABLED`）控制；false 时纪念日日扫 no-op。

**AC4 — 同主人同天合并（PRD AC13）** `[L0]` `[L1]`
纯函数 `AnniversaryPlan.compute(snapshots, wibDate)`：同 owner 当天多只满节点 → 建档最早（`created_at, id` 升序）`push=true`，其余 `push=false`；输出 `AnniversaryPush(petId, ownerId, petName, days, push)`。Mochi 与 Kopi 同天满 30 天 → 推送 1 条（建档早的那只）、通知中心 2 条，两只都写 `scheduled_push_marks`。

**AC5 — 文案与通知中心存渲染结果（FR-182）** `[L0]` `[L1]`
- `NotificationService.sendRendered(recipient, type, copyKey, args, fallbackTitle, fallbackBody, targetRef, boolean push)`（新，`REQUIRES_NEW`）：按收件人 `localeOf` 渲染 `notify.<copyKey>.title/body`，**落库存渲染结果**（title ≤ 120、body ≤ 255，按码点截断不劈 emoji），`push=true` 且非虚拟号、`pushAllowed` 时推送同一句；`push=false` 只写通知 + 角标。`sendWithCopy` 签名与行为不动。
- 纪念日改用 `sendRendered`：`notify.COMPANION_ANNIVERSARY.title` ID `🎉 Hari ke-{1} bareng {0}!` / EN `🎉 Day {1} with {0}!`；`.body` ID `Cheers buat {1} hari kalian! Abadikan gaya {0} hari ini, satu foto aja cukup 📸` / EN `Cheers to {1} days together! Snap {0}''s look today, one photo is all it takes 📸`（`{0}` 宠物名、`{1}` 天数；EN 撇号写 `''`）；`messages.properties` 同 EN、`messages_zh_CN.properties` 写中文意思（附录 A 中文列）。`targetRef = petProfileId`（不变）；不带 `milestoneCode`。

**AC6 — `RetentionPushCalendar.anniversaryPushPets`（地基占位替换，OR-20）** `[L0]` `[L1]`
替换方法体（签名、包名不动）：取入参宠物所属 owner 的**全部**宠物快照（一次查询），跑与 19:00 日扫同一个 `AnniversaryPlan.compute(…, wibDate)`，返回 `push=true` 且在入参里的 petId 集合；入参空 → 空集。与当天 19:00 实际推送的宠物集合一致（测试用同一组数据同时跑两边断言相等）。`recallNodeUsers` **不改**。

**AC7 — 健康提醒对齐（PRD §6）** `[L0]`
`RetentionPushCalendarTest` 补用例：只读宠物不算占用、同主人非最早的那只不算占用、WIB 00:00–07:00 建档的宠物按 WIB 日算。类注释更新「纪念日占位已由会话 ③ 实现」。

**AC8 — 回归** `[L0]` `[L1]`
`ScheduledPushPlannerTest`（拆分后断言改写，不删用例）、`ScheduledPushDispatcherTest`、`RetentionPushCalendarTest`、`V150FoundationIntegrationTest` 全绿。
