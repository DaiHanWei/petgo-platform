## Story

As a 交付负责人,
I want 用注入日期在本地把 PRD 的关键场景从记录保存一路跑到推送点开，并用旧版包回归,
so that 打开上线开关前确认引擎、文案、落点和兼容都对。

## Acceptance Criteria

### AC1 — L0 收口 `[L0]`（云端可做）
1. `./mvnw -B clean package -DskipTests` 绿；本线所有 L0 测试类一起跑绿；`bash scripts/ci/check-flyway-versions.sh origin/main` 通过。
2. `flutter analyze` 零警告、`flutter test` 全绿。
3. 在本 story 的 Dev Notes「验收矩阵」里逐条列出 PRD AC1 ~ AC70 → 覆盖它的测试类 / 手测步骤（缺的补 L0 测试或标 L1 / L2 手测）。

### AC2 — L1 全链路 `[L1]`（本地 Docker：postgres + redis，scratch 库）
1. 先 flush Redis DB0、重建 scratch 库，`mvn spring-boot:run` + `/actuator/health=UP`；Flyway 跑通 `V20261115_0100` ~ `0130`，validate 通过；回填 Runner 跑一次、再启动一次不再改数据。
2. 本线全部 `*IntegrationTest` 绿；`notify` / `profile` / `consult` 包现有集成测试不红。
3. 用 stag QA 端点（本地 stag profile）或直接调 `HealthReminderJob.runFor(date)` 跑以下时间线并核对 `health_reminders` / `health_notifications` / `notifications` 行与埋点调用：UJ-1（Mochi 首针 → F4 系列 → D-7 / D-Day / 提前记录撤 D-Day）、UJ-2（两只狗各自 D-Day、同日两条推送）、UJ-3（从未记录：首针 → 首驱虫 → 绝育 → 记 Neuter → 拆线）、AC28 上线排队时间线、AC37 ~ AC42 冲突、AC45 怀孕恢复全部、AC43 旧版用户升级。

### AC3 — L2 真机 `[L2]`（本地，Android + iOS，连 stag 后端）
1. 推送到达（锁屏两行折行，UI G1「真机确认」项）；冷启动 / 后台 / 前台三态点开：FORM（E1 预填）、建议（E2 日期空）、体检（E3 Kontrol dokter）、D-7（A3 定位）、已满足（A4）、安全（A5 ~ A7）、宠物不可用（E5 toast）、未保存表单（E4 toast）；每次点开 `health_notification_opened` 上报（PRD AC63「Open firing」）。
2. 推送设置关闭「Pengingat hewan」→ 只进通知中心不推送（AC44）。
3. 旧版回归：装 1.4.2 正式包连同一后端：健康记录列表不出现 Kontrol dokter、能新建无类型驱虫（存为 Legacy）、编辑 F4 备注不丢新字段（AC54）、通知中心看不到 `HEALTH_*`、Kesehatan 页历史不出现 VET_VISIT、Diary 时间线对 VET_VISIT 显示兜底图标不崩（待拍板 Q-6）。
4. UI 还原度：A1 ~ H2 共 53 屏逐屏打分，≥95%；不足的回到对应 story 修。印尼语日期选择器按钮文字记录实际值。

### AC4 — 上线清单 `[L0]`
1. Dev Notes 补「上线清单」：部署顺序（后端先上、开关保持关 → App 1.5.0 上架 → 产品补 PRD §5 基线（AC59，待拍板 Q-5）→ 跟操作者确认 → 执行 2.2 runbook 开关 SQL → 次日 10:00 核对首跑计数）；回滚（开关置 FALSE）。
