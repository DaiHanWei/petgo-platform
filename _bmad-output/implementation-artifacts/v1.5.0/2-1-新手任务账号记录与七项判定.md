## Story

As a 新用户,
I want 新手任务按我整个账号做过的事来算、做过一次就不会倒退,
so that 我能清楚看到还差什么、并且没宠物也能推进进度。

## Acceptance Criteria

**AC1 — 迁移 ①** `[L0]` `[L1]`
建表 `user_newbie_marks`（DDL 照架构 §3.2 ①：PK `(user_id, task_key)`、FK users CASCADE、`ck_user_newbie_marks_key` 7 值、`ck_user_newbie_marks_source` RUNTIME / BACKFILL）；`IF NOT EXISTS` 可重放；文件头注释写明「`ck_user_newbie_marks_key` 是本表自有约束，加值须新迁移 DROP + ADD 重列全集」。`bash scripts/ci/check-flyway-versions.sh origin/main` 通过。

**AC2 — 7 项定义** `[L0]`
`NewbieTask` 改为 7 值（固定顺序）：`FIRST_DIARY, FIRST_LIKE_RECEIVED, FIRST_FOLLOW, FIRST_LIKE_GIVEN, FIRST_COMMENT, FIRST_REPLY, ONE_WEEK`；`name()` 即落库 `task_key` 与对外 `key`；每项带对外序号 1–7（埋点 `task`）。

**AC3 — 点赞（PRD AC14）** `[L1]`
A 给 B 的帖子点赞 → A 记 `FIRST_LIKE_GIVEN`、B 记 `FIRST_LIKE_RECEIVED`；A 给自己的帖子点赞 → 两项都不记。点赞者是虚拟号 / 自动点赞照记 B 的 ②（**不排除**）。

**AC4 — 评论与回复（PRD AC15 / AC16）** `[L1]`
- A 在 B 的帖子下发一级评论 → A 记 `FIRST_COMMENT`；A 在自己帖子下发一级评论 → 不记。
- A 回复 B 的评论（含在自己帖子下回复 B、回复运营虚拟号的自动评论）→ A 记 `FIRST_REPLY`，不记 `FIRST_COMMENT`；A 回复自己的评论 → 不记。被回复人 = `replyToAuthorId != null ? replyToAuthorId : parentAuthorId`。

**AC5 — 关注 / 追更（PRD AC17）** `[L1]`
A 只追更了一只宠物（`PetFollowedEvent`）→ A 记 `FIRST_FOLLOW`，S19「第一次关注一个人」里程碑**不**完成；A 手动关注一个人（`UserFollowedEvent`）→ 记 `FIRST_FOLLOW`（S19 照 1.4.2 逻辑完成）；系统自动关注 TailUs 不发事件 → 不记。

**AC6 — 发 Diary** `[L1]`
`ContentPublishedEvent.type == GROWTH_MOMENT`（公开 / 私密都算，审核通过补发的也算）→ 作者记 `FIRST_DIARY`；Moment / Tips 不记。

**AC7 — 不撤（PRD AC18）** `[L1]`
完成后取消点赞 / 删评论 / 取关 / 取消追更 / 删帖 / 删宠物 → 标记不删，进度不倒退。

**AC8 — 无宠物也有进度（PRD AC19）** `[L0]` `[L1]`
≥ 1.5.0 客户端 `GET /api/v1/me/newbie-tasks`：无宠物账号 200，返回 7 项、`hasPet=false`；字段：`items[{key, done}]`（7 项固定顺序）、`completedCount`、`total=7`、`lulusPemulaUnlocked`、`hasPet`（账号下有 ACTIVE 或只读宠物）、`oneWeekDaysLeft`（⑦ 未完成时 `7 − 注册天数`，≥1；完成为 0）、`replyGoPostId`（⑥ 未完成且我作为作者、未删 `PUBLISHED` 的帖子下有别人发的未删评论时，最近一条这样评论所在帖子 id；否则 null）。`lulusPemulaUnlocked` 本 story 先按「任一宠物已完成 Lulus 编码」计算，2-2 改为读账号 flag。

**AC9 — ⑦ 不打开 App 也当天完成（PRD AC20）** `[L0]` `[L1]`
- 读进度时 ⑦ 按 WIB 注册日判定：`(created_at AT TIME ZONE 'Asia/Jakarta')::date + 7 <= 今天(WIB)` 即完成（不依赖标记）。
- `NewbieWeekJob`：`@Scheduled(cron = "${petgo.newbie.week-cron:0 5 0 * * *}", zone = "Asia/Jakarta")`，扫 WIB 注册日 ∈ [今天−8, 今天−7]、`role=USER`、`account_type=REAL`、`status=ACTIVE`、未注销、无 `ONE_WEEK` 标记的账号 → 写 `ONE_WEEK` 并调 `NewbieMarkHooks.afterMarked(userId, ONE_WEEK)`（2-2 在此接毕业判定）。分批 500，单人失败只 warn。

**AC10 — 旧版兼容（OR-9）** `[L0]` `[L1]`
`X-App-Version` < 1.5.0（缺头 / 解析不了也算旧版）→ 返回**现有 6 项旧逻辑**（`LegacyNewbieTaskCompat`：照搬当前 `NewbieTaskService.progress` 的实现，含无宠物 404、6 个旧 key）；只有 `lulusPemulaUnlocked` 与新版同口径。

**AC11 — 后端埋点** `[L0]`
每次**新写入**运行时标记（`INSERT … ON CONFLICT DO NOTHING` 返回 1）后同步 `AnalyticsClient.capture("newbie_task_completed", {task: 1–7, days_since_signup})`（`days_since_signup` = WIB 注册日到今天的天数）；补算（2-4）不报。

**AC12 — 并发与幂等** `[L1]`
同一用户两条点赞事件并发 → `FIRST_LIKE_GIVEN` 只一行、埋点只一次。

**AC13 — 注销清理** `[L1]`
`AccountDeletionService.execute` 显式删除该用户全部 `user_newbie_marks` 行（与 `AccountMilestoneService.deleteByUserId` 同处调用）。
