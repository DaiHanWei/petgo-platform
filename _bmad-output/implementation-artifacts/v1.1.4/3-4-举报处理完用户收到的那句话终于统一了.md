## Story

As a **举报过内容或账号的用户**,
I want **在举报被处理后收到一句一致、得体的回告**,
so that **我知道我的举报被认真对待了，而不是收到一句机械的「已完成审核」**。

---

### ⚠️ 两条文案路径，都要确认

`NotificationService.send` 内部：

```java
Notification saved = repo.save(Notification.of(
        recipientUserId, type, title, body, deepLinkType, token, targetRef));   // ← ① 落库的 title/body
...
java.util.Locale locale = accountQuery.localeOf(recipientUserId);
pusher.pushToUser(recipientUserId,
        pushText(type, "title", locale, title),                                 // ← ② 推送的本地化文案
        pushText(type, "body", locale, body),
        deepLinkType, token, targetRef);
```

代码注释写明：「push 文案按收件人语言渲染（bug 20260625-105）；**站内通知中心不用这里的文本**（App 端按 type 自行本地化），故落库 title/body 保持不变。」

**➜ 意味着：**
- **落库的 title/body** 是给谁看的？按注释说 App 端按 type 自行本地化，所以站内展示可能不读它 —— **但仍要改对**，因为它是数据记录。
- **推送文案**走 `pushText(type, ...)` 的本地化查表 —— **新文案要落到那套本地化资源里**，否则推送出去的还是旧的。

⚠️ **实现时先确认这两条路径各自的文案来源**，改一处漏一处会出现「站内看到新文案、推送收到旧文案」。

---

### 为什么这条要单独立 story（AC3 的理由）

PRD §6 第 2 条的原文以**「描述既有机制」的口吻**写：

> 通知文案统一为「你的举报已处理，感谢你帮助维护社区环境」

但代码实证发现**线上实际发出的是另一句**：「举报已处理 / 感谢你的举报，我们已完成审核。」

**两句并不相同，而 PRD 既不是在描述现状、也没声明自己是在提变更。**

**➜ 产品 2026-08-15 决定：采用 PRD 这句，本版本把线上文案改过来。**
**➜ 但必须显式列为交付项**，否则：
- 上线后没人知道这是有意改的
- 日后有人对着线上文案与 PRD 比对，会以为是 bug 又改回去
- **内容举报的用户会突然收到不一样的回告**，而没有任何记录说明为什么

#### ⚠️ story 说有两条路径，实际是**三条**

story 的 Dev Notes 列了①落库文案 与 ②推送本地化，并把站内通知中心一句带过（「App 端按 type 自行本地化」）。**但那第三条才是用户真正看到的那句** —— App 的通知中心根本不渲染后端下发的 title/body，它按 type 查自己的 ARB。

实测确认：App 的 `notifyBodyReportReviewed` 里躺的正是**旧文案原文**（"Thanks for your report. We've completed our review."）。**只改后端两处的话，用户在通知中心看到的还是旧话**，而推送弹出来的是新话 —— 用户会觉得平台在自说自话。

三处都改了，且都有测试守着：

| # | 位置 | 守它的测试 |

| ① 落库 title/body | `ModerationNotifyListener` | `ReportReviewedCopyTest`（含「旧话不得复活」断言） |
| ② 离线推送 | `messages_{zh_CN,en,id}.properties` | 同上，三份 properties 逐一读校 |
| ③ **站内通知中心** | App 的 `app_{en,id}.arb` | 前端 `notification_center_test.dart` |
