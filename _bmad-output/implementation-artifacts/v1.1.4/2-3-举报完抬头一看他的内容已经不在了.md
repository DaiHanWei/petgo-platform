# Story 2.3: 举报完抬头一看，他的内容已经不在了

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

> **所属**：V1.1.4 Epic 2 第三个 Story（**纯前端 Flutter**）。
> **交付**：举报成功收尾时，**当前列表立即移除该作者的全部可见卡片**（两个入口都覆盖）。
> ⚠️ **本 story 的存在理由**：UI 稿 B5 收尾只说「两层收起、回到点开迷你卡之前的页面」——**那个页面通常就是 Feed，上面还挂着那个人的帖子**。不处理的话，用户举报完抬头就看见「我举报了，他的内容还在」，**这正是方案甲要消灭的体验，只是推迟了几秒**。
> ⚠️ **这是行为不是视觉，静态 UI 稿画不出来** —— UI 稿自己标注了「必须写进 AC」。

## Story

As a **刚刚举报完某个账号的用户**,
I want **收起举报流程的那一瞬间就看不到他的内容了**,
so that **我不会「举报完抬头就看见他的帖子还挂在那儿」，怀疑自己是不是没提交成功**。

## Acceptance Criteria

> **验证层**：**L0**（`flutter analyze` / `flutter test`）· **L1**（与服务端过滤的一致性）· **L2**（模拟器视觉）。

### AC1 — 从首页进入的路径（L2）

**Given** 用户从首页 Feed 点开某作者的迷你卡并完成举报
**When** 用户点击成功态的「关闭」、两层收起
**Then** 当前 Feed 列表**立即移除该作者的全部可见卡片**——**不是只移除点开的那一条**
**And** 沿用既有帖子级举报成功后乐观移除该卡片的做法

> ⚠️ **实证：既有只有单帖粒度的移除** —— `feedProvider.notifier.removeItem(int postId)`。本 story 需**新增按作者的批量移除**（如 `removeByAuthor(int authorId)`）。
> ✅ `FeedItem` 已带 `authorId`（`home_page.dart:190` 的 `onAuthorTap: (item) => showMiniProfile(context, ref, item.authorId)` 可证），**前端有足够信息做作者维度过滤，无需后端补字段**。

### AC2 — 从内容详情页进入的路径（L2）

**Given** 用户在某内容详情页点作者头像、弹卡并完成举报
**When** 用户点击「关闭」
**Then** **先退回上一级列表**（停留在被举报者的帖子详情页上是明显穿帮）
**And** 在该列表里**同样移除该作者的全部卡片**

### AC3 — 移除必须静默（L2）

**Given** 卡片被移除
**When** 界面更新
**Then** **不弹任何提示**——不出现「已不再向你展示 TA 的内容」之类的话

> ⚠️ 任何这类提示都会**泄露「举报会隐藏内容」**，与成功态刻意不提的取舍直接冲突（A-A27）。
> ⚠️ **注意与既有内容举报的差异**：既有帖子级举报**会**弹 `reportHiddenToast`「Kamu tidak akan melihat konten ini lagi」。**账号举报刻意不弹。** 两处行为不同是有意为之，实现时别顺手复用那段。

### AC4 — 已知代价（L2）

**Given** 被举报者在当前列表有多条内容
**When** 一并移除后
**Then** **列表会突然变短**，这是产品已接受的代价，不做补位、不做占位

### AC5 — 下次刷新的一致性（L1）

**Given** 乐观移除只是前端行为
**When** 用户下拉刷新或重新进入
**Then** 服务端过滤（Story 2.1 AC6）保证该作者内容**依然不出现**，前后端结论一致

### AC6 — 护栏（L0）

**Given** 本 story 的实现
**Then** 未新增第三方依赖、未新增 l10n 键
**And** ⚠️ **两处回调都要改**（Feed 侧与详情页侧各自独立写了一遍乐观移除，见 Dev Notes）
**And** `flutter analyze` / `flutter test` 全绿

## Dev Notes

> ⚠️ 本节代码事实来自 CS 阶段实证扫描。

### 实证：既有乐观移除只有单帖粒度，且两处各写了一遍

**Feed 侧** `features/content/presentation/home_page.dart:181-189`：

```dart
onLongPressItem: (item) => openReport(context, ref, item.id, onReported: () {
  // cm-6 §6.1：举报成功 → 乐观移除卡片 +「不再向你展示」提示（后端 §5.4 已过滤，刷新亦不复现）。
  ref.read(feedProvider.notifier).removeItem(item.id);
  if (context.mounted) {
    ScaffoldMessenger.of(context)
      ..hideCurrentSnackBar()
      ..showSnackBar(SnackBar(content: Text(l10n.reportHiddenToast)));
  }
}),
```

**详情页侧** `features/content/presentation/content_detail_page.dart:279-287`：

```dart
openReport(context, ref, detail.id, onReported: () {
  // cm-6 §6.1：详情页举报成功 → pop 回列表（该帖对本人已不存在，后端详情 404）+ 提示。
  ref.read(feedProvider.notifier).removeItem(detail.id);
  if (context.mounted) {
    showAppToast(context, l10n.reportHiddenToast);
    Navigator.of(context).maybePop();
  }
});
```

**三点要注意：**

1. **`removeItem(int postId)` 是单帖粒度** —— 本 story 要新增 `removeByAuthor(int authorId)`。
2. **两处各自独立写了一遍** —— 账号举报的回调也要写两处，**改一处漏一处的风险是真实的**。建议抽共享工厂（T4）。
3. ⚠️ **两处的提示方式还不一致**：Feed 用 `ScaffoldMessenger` SnackBar（遗留写法），详情页用 `showAppToast`。**但账号举报两处都不弹提示**（AC3），所以这个不一致对本 story 不构成问题 —— **只是别顺手复制那段 toast 代码**。

#### T4 的公共回调抽出来了 —— 而且比 story 建议的多收了两处

story 建议把**账号举报的两处**抽成共享回调。实际抽的时候发现**拉黑的两处形状完全一样**（Story 1.2 我也是各写了一遍），于是一并收进 `author_moderation_callbacks.dart` 的 `onAuthorHidden(ref, authorId, {popContext})`：

| 入口 | 拉黑 | 举报 |
|---|---|---|
| Feed（home_page） | `onAuthorHidden(ref, id)` | 同左 |
| 详情页（content_detail_page） | `onAuthorHidden(ref, id, popContext: context)` | 同左 |

四处收敛成一个函数，「改一处漏一处」的风险从 4 降到 1。`popContext` 非空 = 调用方是详情页 → 先 pop 再移除。

⚠️ **既有内容举报（帖子级）的那两处回调一行未动** —— 它们要弹 `reportHiddenToast`、粒度是单帖，与账号维度是两回事，story 也明确划在范围外。

#### 顺带确认：`removeByAuthor` 早在 Story 1.2 就建好了

story 的 AC1 写「需新增按作者的批量移除」，实际它在 **Story 1.2**（拉黑成功后移除该作者卡片）时就已经加进 `FeedController` 了，本 story 直接复用。既有的 `removeItem(int postId)` 保留未动（内容举报仍在用）。

#### `showMiniProfile` 新增 `onReported` 回调

与既有的 `onBlocked` 并列。两者**仅成功路径触发**，取消与失败都不触发（有用例：中途取消 → 列表一条不动、迷你卡还开着）。
