## Story

As a 宠物主人或追更者,
I want 被追更、或追更的宠物发新 Diary 时收到提醒,
so that 知道谁在关注我的宠物、不错过它的新动态。

### AC6 — `PET_DIARY_POSTED`（追更宠物有新 Diary）`[L0]` `[L1]`（D-10、D-5、PRD「追更了能看到什么」、AC5 / AC7 / AC9）
1. 新增 `notify/service/PetDiaryNotifyListener`，消费 `ContentPublishedEvent`：`@Async` + `@TransactionalEventListener`（AFTER_COMMIT）。发帖与**人工审核通过补发**（`ContentService.approveReview`:357-373 同样发该事件）都会触发；运营后台种子帖（`publishTrusted`，`petIds` 恒空）自然不触发。
2. 只处理 `type == GROWTH_MOMENT && visibility == PUBLIC && !petIds.isEmpty()`；私密 Diary、Moment、Tips 一律不发。
3. 收件人 = 追更了 `petIds` 中任一只的人（经 1.1 的 `PetFollowReader` 批量方法一次查出 `(followerId, petProfileId)` 对），再排除：
   - 作者本人（追更了自己…理论上不可能，双保险）；
   - **追更者隐藏了作者**（`hideRelations.hiddenByHolder` 反向批量或 `hiddenEitherWay` 取交集；拉黑与举报隐藏都算 —— 与关注流「作者不在我的隐藏名单」同口径，NFR1）；
   - **作者 BLOCK 了追更者**（只认 BLOCK，PRD AC9「B 收不到 A 宠物的 PET_DIARY_POSTED」，与 1.3 关注流追更一路同口径）；
   - 追更者非 `isActive`（注销 / `DEACTIVATED`，`accounts.activeIdsAmong` 批量）；作者非 `isActive` 时整帖不发（理论上封号不能发帖，双保险）。
   - **已关注作者本人的追更者照常收**（这是与关注人的主要区别）。
4. 每个追更者**只收 1 条**：按 `petIds` 顺序（宠物创建顺序）遍历他命中的宠物，对每只尝试 `INSERT INTO pet_diary_notify_log (follower_id, pet_profile_id, wib_date) … ON CONFLICT DO NOTHING`（`wib_date = LocalDate.now(ScheduleWindow.WIB)`，P-6），**第一只插入成功的宠物**即用于本条文案并停止；全部冲突（这些宠物今天都已提醒过）→ 不发。
5. 写入：新增 `NotificationService.sendPetDiaryPosted(long recipientUserId, long postId, long petId, String petName)`（`REQUIRES_NEW`）：
   - 标题在**写入时**按收件人语言渲染并落库（`notify.tpl.petDiaryPosted`，`{0}` 宠物名；无参取不到时兜底「{宠物} punya cerita baru」）—— 列表兜底与推送用同一句；`body` 落空串；
   - `deepLinkType = "PET_DIARY_POSTED"`、`targetRef = String.valueOf(postId)`；
   - 命中的宠物 id 存入 `variant` 列（`String.valueOf(petId)`，`VARCHAR(16)` 足够；该列无 CHECK，取值由 Java 常量收口 —— 见 `V20261012_1259` 注释），供列表现查宠物名；
   - 角标 +1；推送：虚拟号 / 官方号不推 → `if (!pushAllowed(recipient, PET_DIARY_POSTED)) return;`（分类 `PET_DIARY`）→ `pusher.pushToUser(recipient, title, "", "PET_DIARY_POSTED", token, targetRef)`；失败不重推（`NotificationPusher` 本就不重试），全局限速由 `TencentImClient` 内的 `PushRateLimiter`（25/s，bug 604）自动生效、**不要另加限速、不要调高**。
6. 文案：id `notify.tpl.petDiaryPosted={0} punya cerita baru`；en `{0} has a new story`；zh_CN `{0} 有新动态了`；`messages.properties` 同 en。
7. 列表现拼：`PET_DIARY_POSTED` 行在 `renderPage` 里与 `PET_FOLLOWED` 同批取宠物名（宠物 id 取自 `variant`）→ 输出 `actorName = petName = 宠物现名`、`title` 用现名按当前语言重渲染、`actorUserId / actorToken` 为 null；宠物已删 / 取不到名 → 原样返回库值（`plain`），App 按 `_storedTitle` 兜底（1.5）。不改未读角标口径（它不是 `INTERACTION_TYPES`）。
8. 分批扇出：收件人按 500 一批处理（每批一次 `activeIdsAmong`、一次隐藏关系查询、逐人插日志 + 发通知）；每条通知各自 `REQUIRES_NEW`，单条失败只 warn 并继续下一位（不让一个人的异常吞掉整批）。
9. 🔴 `@Async` 线程里没有事务；所有写库操作必须调用**另一个 bean** 上带 `@Transactional(propagation = REQUIRES_NEW)` 的方法（`NotificationService.sendPetDiaryPosted`、日志写入 DAO）——**禁止在监听器内部用 `this.xxx()` 调自己的 `@Transactional` 方法**（自调用不过代理，事务不生效）。
10. Given 我追更 Mochi（未关注主人），When 主人发公开 Diary，Then 我收到 1 条「Mochi punya cerita baru」，点击进该帖；Given 当天再发 2 条 → 不再收；Given 一帖关联我追更的 Mochi 与 Kopi → 只收 1 条、文案 Mochi；Given 私密 Diary / Moment / Tips / 作者是我 / 我拉黑主人 / 主人拉黑我 / 我 DEACTIVATED / 主人 DEACTIVATED → 都不收；Given 挂起帖人工审核通过 → 此刻才收。

### 拍板点（按建议实现，Completion Notes 复述）

- **① `PET_DIARY_POSTED` 的宠物 id 放 `variant`**：`targetRef` 必须是帖子 id（App 深链 / 推送直跳 `/content/{id}`），列表又要现查宠物名加粗（A12），而 `notifications` 没有第二个引用列、架构未规定存放位置。`variant` 无 CHECK、`VARCHAR(16)`、对外不下发（`NotificationItem` 注释「不暴露 variant」）。不新增列、不加迁移。
- **② 一帖多宠时按 `petIds` 顺序取「第一只今天还没提醒过的」**：PRD「同一宠物每天最多 1 条」+「一帖只发 1 条、文案取第一只」两条同时成立的唯一解；若第一只今天已提醒、第二只没有，则用第二只发 1 条。
- **③ 追更者举报隐藏了作者也不发**：与关注流过滤「作者在我的隐藏名单」同口径（NFR1）；PRD「REPORT 隐藏不影响追更」指关系不删，不指内容照推。
- **④ `PET_FOLLOWED` 不聚合、`targetRef` = 追更者 user id、宠物 id 存 `variant`**：2026-11-04 主会话拍板（原「待确认」1 已关闭），推送点击与列表点击都进追更者主页。

### 实现提示

- `PetDiaryNotifyListener` 骨架：
  ```java
  @Async
  @TransactionalEventListener
  public void onContentPublished(ContentPublishedEvent e) {
      if (e.type() != ContentType.GROWTH_MOMENT || e.visibility() != ContentVisibility.PUBLIC || e.petIds().isEmpty()) return;
      if (!accounts.isActive(e.authorId())) return;
      Map<Long, List<Long>> petsByFollower = petFollows.followersOf(e.petIds()); // follower -> 命中的宠物（按 petIds 顺序）
      petsByFollower.remove(e.authorId());
      for (List<Long> batch : partition(petsByFollower.keySet(), 500)) {
          Set<Long> active = accounts.activeIdsAmong(batch);
          Set<Long> hidesAuthor = /* batch 中 isHidden(follower, author) 的人，一次查询 */;
          Set<Long> blockedByAuthor = /* author BLOCK 了的人（只认 BLOCK），一次查询 */;
          LocalDate today = LocalDate.now(ScheduleWindow.WIB);
          for (Long f : batch) {
              if (!active.contains(f) || hidesAuthor.contains(f) || blockedByAuthor.contains(f)) continue;
              try {
                  for (Long pet : petsByFollower.get(f)) {
                      if (logDao.tryInsert(f, pet, today)) {            // REQUIRES_NEW，另一个 bean
                          notifications.sendPetDiaryPosted(f, e.postId(), pet, names.get(pet));
                          break;
                      }
                  }
              } catch (RuntimeException ex) {
                  log.warn("追更日提醒失败 follower={} post={} cause={}", f, e.postId(), ex.getClass().getSimpleName());
              }
          }
      }
  }
  ```

- 「作者 BLOCK 了谁」批量：`UserHideRelationReader.hiddenByHolder(authorId, batch)` 是不分来源的；只认 BLOCK 需要新增读端口方法 `blockedByHolder(holderId, targetIds)`（照 `FollowListQueryService` 里 `hideRepo.findTargetIdsByHolderAndSourceIn(viewerId, HideSource.BLOCK, ids)` 的仓库方法封一层），放在 `social.read`（notify 只依赖端口，不引 `social.repository`）。
