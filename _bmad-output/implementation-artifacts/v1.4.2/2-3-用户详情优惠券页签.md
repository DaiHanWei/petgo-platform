## Story

As a 客服,
I want 按用户查券,
So that 能回答「券为什么没退回」.

## Acceptance Criteria

1. 用户抽屉 **Then** 9 个页签保留，末尾加「优惠券」，只读，列按 A11〔L1〕
2. 点一行展开状态变化记录；占用或已使用显示订单号，可点进订单〔L1〕
3. 空态 A12〔L1〕
4. 用户被兑换锁定时顶部显示剩余分钟，无解锁按钮（A13）〔L1〕
5. 不提供修改券或补发入口〔L0〕

- L0 已跑绿：`AdminUserCouponsTabRenderTest`（新：行 / 状态记录 / 订单链接 / 锁定横幅 / 空态 / 三语无缺 key / 无任何写入口）、`AdminUserAccessControlTest`（构造器按设计加一参）、`AdminMessagesParityTest`。
- 实现：`AdminUserCouponsService.tab(userId)`（只读 JDBC，不开事务；最多列最近 200 张，流水只取这 200 张的）；行以 `user_coupons.public_token` 定位，不外露自增 id；当前占用 / 已使用显示订单展示号并可点进 `/admin/shop/orders?open=<token>`；已退回券的订单只在状态记录里（取自 2.1 `user_coupon_events.order_id`）。`AVAILABLE` 但过有效期现算显示「已过期」。
- 兑换锁定：`CouponRedeemService.redeemLockRemainingSeconds`（公开只读，读 `getExpire`，读失败 / 无 TTL 返回空）；后台不另写 key 字面量、常量仍包内可见；剩余分钟向上取整。

- 文案取自三语表 A11~A13；表外自拟（**待设计确认**）：获得方式 `REISSUE`（重新下单补回）、状态 `EXPIRED`、流水 ISSUED 各来源文案（表里只有「兑换获得」）、`RELEASED` 通用为「订单 {no} 取消，退回为可用」（表里写的是超时取消的特例）、`VOIDED`「已作废」、`name.discountNoMin`、`openOrder`、`truncated`。状态记录标题的券名按后台语言取印尼语 / 英语名。
