# Story 1.1：挂起退款标记与扣回服务

Status: review

> V1.4.2 · 主题 exp-reverse · 分支 `feat/1.4.2-exp-reverse`（从 `dev_1.4.2` 切出）。
> 口径优先级：`决策日志-exp-reverse.md` > PRD `电商/1-4-2退款扣回成长值修复prd.md` > `architecture-v1.4.2-exp-reverse-delta.md`。

## Story

As a 系统,
I want 准确认出「问诊挂起 + QRIS + 退款中」的订单并安全扣回成长值,
So that 不误扣常规退款和存量订单.

## Acceptance Criteria

1. 挂起到期或用户逃生走 QRIS 分支 **Then** 订单写入 `suspension_refund_at`，状态仍为 REFUNDING〔L1〕
2. PawCoin 挂起退款、常规退款批准后的 REFUNDING、迁移前存量订单 **Then** 该列为 NULL，不可扣回〔L1〕
3. `state` 正确区分：可扣回、无入账（`accrued = null`）、已扣回、存量、常规退款中〔L0〕
4. 定位入账流水按幂等键且校验同一用户，不按 ref 反查〔L0〕
5. 执行扣回 **Then** 写反向流水（原因 REFUND、来源 `REFUND:consult-refund-{orderId}`），等级重算，用户收不到通知〔L1〕
6. 审计记操作人、时间、订单号、入账、此前已扣回、本次扣回、前后等级，不含 PII，与扣回同事务〔L1〕
7. 重复或并发执行 **Then** 第二次 422「这单的成长值已经扣回过了」，流水只有一条〔L1〕
8. 用户累计不足致实扣小于入账 **Then** 返回实扣额，之后视为已扣回（E-5）；累计为 0 **Then** 不可扣回（E-9）〔L0〕
9. `reverse` 现有调用方行为不变，`GrowthRefundListener` 既有测试不改断言〔L0〕
