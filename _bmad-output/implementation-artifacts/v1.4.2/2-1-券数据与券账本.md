## Story

As a 平台,
I want 券的模板、用户券、兑换码有清晰的数据与唯一的状态入口,
so that 券不会被重复使用、取消时按规则退回。

### AC1 — 迁移 ⑦ 四张表 `[L0]` `[L1]`（D-1 ~ D-4、I8、P-8 ⑦）
文件 `V20261105_1615__create_shop_coupons_user_coupons_codes_notify_log.sql`，按下列顺序建表（`user_coupons` 引用 `shop_orders`，`shop_coupon_codes` 引用 `shop_coupons`）：
```sql
-- ① 券模板
CREATE TABLE shop_coupons (
    id              BIGINT       GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    public_token    VARCHAR(32)  NOT NULL,
    kind            VARCHAR(16)  NOT NULL,                 -- DISCOUNT | FREE_SHIPPING
    name_id         VARCHAR(60)  NOT NULL,                 -- 券名（印尼语），运营录入
    name_en         VARCHAR(60)  NOT NULL,
    amount          BIGINT       NOT NULL,                 -- 满减额；免运券 = 每张减免封顶
    min_spend       BIGINT       NOT NULL DEFAULT 0,       -- 0 = 无门槛
    scope_type      VARCHAR(16)  NOT NULL DEFAULT 'ALL',   -- ALL | CATEGORY | PRODUCT
    scope_values    JSONB        NOT NULL DEFAULT '[]'::jsonb, -- 品类码或商品 public_token 数组
    acquire_type    VARCHAR(16)  NOT NULL,                 -- NEWBIE | CLAIM | CODE
    issue_start_at  TIMESTAMPTZ  NOT NULL,                 -- 发放期（能领 / 能兑 / 新人能发 / banner 能展示）
    issue_end_at    TIMESTAMPTZ  NOT NULL,
    valid_mode      VARCHAR(16)  NOT NULL,                 -- FIXED | RELATIVE
    valid_start_at  TIMESTAMPTZ,                           -- FIXED 用
    valid_end_at    TIMESTAMPTZ,
    valid_days      INTEGER,                               -- RELATIVE 用：领取后 N 天
    total_quantity  INTEGER,                               -- NULL = 不限
    issued_count    INTEGER      NOT NULL DEFAULT 0,
    per_user_limit  INTEGER      NOT NULL DEFAULT 1,
    status          VARCHAR(16)  NOT NULL DEFAULT 'ACTIVE',-- ACTIVE | STOPPED
    void_on_stop    BOOLEAN      NOT NULL DEFAULT FALSE,   -- 停用时是否选了「作废已领未用」（D-3 需要，D-1 未列，本 story 补）
    stopped_at      TIMESTAMPTZ,
    created_at      TIMESTAMPTZ  NOT NULL DEFAULT now(),
    updated_at      TIMESTAMPTZ  NOT NULL DEFAULT now(),
    CONSTRAINT uq_shop_coupons_public_token UNIQUE (public_token),
    CONSTRAINT ck_shop_coupons_kind CHECK (kind IN ('DISCOUNT', 'FREE_SHIPPING')),
    CONSTRAINT ck_shop_coupons_scope_type CHECK (scope_type IN ('ALL', 'CATEGORY', 'PRODUCT')),
    CONSTRAINT ck_shop_coupons_acquire_type CHECK (acquire_type IN ('NEWBIE', 'CLAIM', 'CODE')),
    CONSTRAINT ck_shop_coupons_valid_mode CHECK (valid_mode IN ('FIXED', 'RELATIVE')),
    CONSTRAINT ck_shop_coupons_status CHECK (status IN ('ACTIVE', 'STOPPED')),
    CONSTRAINT ck_shop_coupons_amount CHECK (amount > 0),
    CONSTRAINT ck_shop_coupons_min_spend CHECK (min_spend >= 0),
    CONSTRAINT ck_shop_coupons_discount_below_min CHECK (NOT (kind = 'DISCOUNT' AND min_spend > 0 AND amount >= min_spend)),
    CONSTRAINT ck_shop_coupons_issue_period CHECK (issue_end_at > issue_start_at),
    CONSTRAINT ck_shop_coupons_validity CHECK (
        (valid_mode = 'FIXED' AND valid_start_at IS NOT NULL AND valid_end_at IS NOT NULL
             AND valid_end_at > valid_start_at AND valid_days IS NULL)
        OR (valid_mode = 'RELATIVE' AND valid_days IS NOT NULL AND valid_days >= 1
             AND valid_start_at IS NULL AND valid_end_at IS NULL)),
    CONSTRAINT ck_shop_coupons_quantity CHECK (
        (total_quantity IS NULL OR total_quantity >= 1) AND issued_count >= 0
        AND (total_quantity IS NULL OR issued_count <= total_quantity)),
    CONSTRAINT ck_shop_coupons_per_user CHECK (per_user_limit >= 1),
    CONSTRAINT ck_shop_coupons_stopped CHECK ((status = 'STOPPED') = (stopped_at IS NOT NULL))
);
CREATE INDEX idx_shop_coupons_issuing ON shop_coupons (acquire_type, status, issue_start_at, issue_end_at);

-- ② 兑换码
CREATE TABLE shop_coupon_codes (
    id                   BIGINT      GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    coupon_id            BIGINT      NOT NULL REFERENCES shop_coupons (id),
    code                 VARCHAR(32) NOT NULL,          -- 大写规范化
    single_use           BOOLEAN     NOT NULL,
    redeemed_by_user_id  BIGINT      REFERENCES users (id) ON DELETE SET NULL,
    redeemed_at          TIMESTAMPTZ,
    created_at           TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT uq_shop_coupon_codes_code UNIQUE (code),
    CONSTRAINT ck_shop_coupon_codes_format CHECK (code ~ '^[A-Z0-9]{4,32}$'),
    CONSTRAINT ck_shop_coupon_codes_universal_never_redeemed CHECK (single_use OR redeemed_at IS NULL)
);
CREATE INDEX idx_shop_coupon_codes_coupon ON shop_coupon_codes (coupon_id);

-- ③ 用户券（状态只经 CouponLedgerService，P-2）
CREATE TABLE user_coupons (
    id                  BIGINT      GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    public_token        VARCHAR(32) NOT NULL,
    user_id             BIGINT      NOT NULL REFERENCES users (id) ON DELETE CASCADE,
    coupon_id           BIGINT      NOT NULL REFERENCES shop_coupons (id),
    source              VARCHAR(16) NOT NULL,           -- NEWBIE | CLAIM | CODE | BANNER | REISSUE
    status              VARCHAR(16) NOT NULL DEFAULT 'AVAILABLE', -- AVAILABLE | LOCKED | USED | VOIDED
    locked_order_id     BIGINT      REFERENCES shop_orders (id) ON DELETE SET NULL,
    used_order_id       BIGINT      REFERENCES shop_orders (id) ON DELETE SET NULL,
    valid_from          TIMESTAMPTZ NOT NULL,           -- 领取时按模板物化
    valid_until         TIMESTAMPTZ NOT NULL,
    claimed_at          TIMESTAMPTZ NOT NULL,
    expiry_notified_at  TIMESTAMPTZ,                    -- 2.3：每张券只提醒一次（I8）
    created_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT uq_user_coupons_public_token UNIQUE (public_token),
    CONSTRAINT ck_user_coupons_source CHECK (source IN ('NEWBIE', 'CLAIM', 'CODE', 'BANNER', 'REISSUE')),
    CONSTRAINT ck_user_coupons_status CHECK (status IN ('AVAILABLE', 'LOCKED', 'USED', 'VOIDED')),
    CONSTRAINT ck_user_coupons_validity CHECK (valid_until > valid_from)
);
CREATE INDEX idx_user_coupons_user_status_valid ON user_coupons (user_id, status, valid_until);
CREATE INDEX idx_user_coupons_coupon_user ON user_coupons (coupon_id, user_id);
CREATE INDEX idx_user_coupons_locked_order ON user_coupons (locked_order_id) WHERE locked_order_id IS NOT NULL;
CREATE INDEX idx_user_coupons_expiry_scan ON user_coupons (valid_until)
    WHERE status = 'AVAILABLE' AND expiry_notified_at IS NULL;

-- ④ 快过期提醒去重（2.3 使用）
CREATE TABLE coupon_expiry_notify_log (
    user_id       BIGINT      NOT NULL REFERENCES users (id) ON DELETE CASCADE,
    wib_date      DATE        NOT NULL,
    coupon_count  INTEGER     NOT NULL,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT pk_coupon_expiry_notify_log PRIMARY KEY (user_id, wib_date),
    CONSTRAINT ck_coupon_expiry_notify_log_count CHECK (coupon_count >= 1)
);
CREATE INDEX idx_coupon_expiry_notify_log_date ON coupon_expiry_notify_log (wib_date);
```
- 整数列 `INTEGER`、金额 `BIGINT`、**禁止 SMALLINT**；对外标识 `public_token`（券模板、用户券）；兑换码本身是对外输入，不是标识。
- **不在 `user_coupons` 上加「LOCKED ⇔ locked_order_id 非空」CHECK**：订单被删（测试 `deleteAll`）时 `ON DELETE SET NULL` 会违反它、反过来挡住删除（记忆库「新表 FK 阻断 deleteAll」的老坑）；一致性由 service 保证。
- 文件头注释：「已过期不落库，由 `valid_until` 现算（D-2）」；「注销只匿名化 users 行，`ON DELETE CASCADE` 在注销路径不触发，注销联动见 AC7」。

### AC2 — 领域与仓库 `[L0]` `[L1]`（D-1 ~ D-4、P-2、P-4）
包 `B/shop/coupon/{domain, repository, service, web, dto}`（`B/` = `petgo-backend/src/main/java/com/tailtopia/`）。
1. 枚举：`CouponKind { DISCOUNT, FREE_SHIPPING }`、`CouponScopeType { ALL, CATEGORY, PRODUCT }`、`CouponAcquireType { NEWBIE, CLAIM, CODE }`、`CouponValidMode { FIXED, RELATIVE }`、`CouponStatus { ACTIVE, STOPPED }`、`UserCouponSource { NEWBIE, CLAIM, CODE, BANNER, REISSUE }`、`UserCouponStatus { AVAILABLE, LOCKED, USED, VOIDED }`、`CouponReleaseMode { RETURN, KEEP }`。
2. 实体 `ShopCoupon`（可写，`scopeValues` 用 `@JdbcTypeCode(SqlTypes.JSON) List<String>`，照 `ShopProduct.feedingGuide`）、`ShopCouponCode`、`UserCoupon`。**`UserCoupon` 是只读映射**：类上 `@org.hibernate.annotations.Immutable`，**没有任何 public setter / 状态修改方法**，只有 getter 与 `boolean isUsableAt(Instant now)`（`status == AVAILABLE && !now.isBefore(validFrom) && now.isBefore(validUntil)`）、`boolean isExpiredAt(Instant now)`。
3. 读仓库 `UserCouponRepository extends org.springframework.data.repository.Repository<UserCoupon, Long>`（**不继承 `CrudRepository` / `JpaRepository`**，天然没有 `save` / `delete`），只放 `find*` / `count*` / `exists*`。
4. 写 DAO `UserCouponLedgerDao`（`@Repository`，`NamedParameterJdbcTemplate` 或 `JpaRepository` 之外的 native `@Modifying` 均可）：**全仓库唯一出现 `INSERT INTO user_coupons` / `UPDATE user_coupons` / `DELETE FROM user_coupons` 的文件**；只被 `CouponLedgerService` 注入（AC6 守卫）。
5. `ShopCouponRepository extends JpaRepository<ShopCoupon, Long>`：`findByPublicToken`、`@Lock(PESSIMISTIC_WRITE) findLockedById`、条件扣总量 `@Modifying @Query(nativeQuery = true) "UPDATE shop_coupons SET issued_count = issued_count + 1, updated_at = now() WHERE id = :id AND status = 'ACTIVE' AND (total_quantity IS NULL OR issued_count < total_quantity)"` → `int`（D-1，影响 0 行 = 领完）。
6. `ShopCouponCodeRepository extends JpaRepository<ShopCouponCode, Long>`：`findByCode`、条件核销 `UPDATE shop_coupon_codes SET redeemed_by_user_id = :uid, redeemed_at = :now WHERE id = :id AND single_use AND redeemed_at IS NULL` → `int`。

### AC3 — 建券 / 停券 / 兑换码（后台线调用的 service） `[L0]` `[L1]`（D-1、D-3、D-4、S-2、PRD AB-24 口径）
`B/shop/coupon/service/CouponAdminService`：
1. `ShopCoupon create(CouponDraft draft, Long actorAdminId)`：校验后保存，`public_token` 用 `ShopTokenGenerator`。校验（失败抛 `AppException.validation`，detail 中文给后台看）：
   - `amount > 0`、`min_spend ≥ 0`；`DISCOUNT` 且 `min_spend > 0` 时 `amount < min_spend`（epics：「`amount < min_spend` 或 `min_spend = 0` 允许」）；`FREE_SHIPPING` 的 `amount` 即封顶。
   - `scope_type = ALL` 时 `scope_values` 必须为空；`CATEGORY` 时非空且每个值是 `ProductCategory` 名；`PRODUCT` 时非空且每个值是存在的商品 `public_token`（`ShopProductRepository` 校验，下架商品允许）；去重、最多 200 个。
   - `issue_end_at > issue_start_at`；`FIXED`：`valid_end_at > valid_start_at`、**`valid_start_at ≤ issue_start_at`**（领到即可用，不存在「已领但未生效」，见「待确认」②）、`issue_end_at ≤ valid_end_at`；`RELATIVE`：`valid_days ≥ 1`。
   - `per_user_limit ≥ 1`；`NEWBIE` 强制 `per_user_limit = 1`；`total_quantity` 为 null 或 ≥ 1。
   - `name_id` / `name_en` 非空、≤ 60 字。
   - **新人券唯一**（AB-24 / FR-130.5）：`acquire_type = NEWBIE` 时，同一事务先 `SELECT pg_advisory_xact_lock(hashtext('shop_coupon_newbie'))`，再查「`acquire_type='NEWBIE' AND status='ACTIVE' AND issue_start_at < :newEnd AND issue_end_at > :newStart`」，存在 → 409 `AppException.conflict("已有发放期重叠的新人券")`。
2. `void stop(String couponToken, boolean voidUnused, Long actorAdminId)`：`ACTIVE → STOPPED`，写 `stopped_at`、`void_on_stop = voidUnused`；`voidUnused=true` 时调 `CouponLedgerService.voidUnused(couponId)`（AVAILABLE → VOIDED，LOCKED / USED 不动）。已 STOPPED 再停 → 幂等返回（不改 `void_on_stop`）。
3. 兑换码：`String createUniversalCode(String couponToken, String code, Long actor)`（`single_use=false`，一张码多人兑换，受每人限领与总量约束）与 `List<String> generateSingleUseCodes(String couponToken, int count, Long actor)`（`1 ≤ count ≤ 1000`，10 位，字符集 `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`（去掉易混的 0/O/1/I），`SecureRandom`，撞码重试）；只允许 `acquire_type = CODE` 的模板；码规范化 = `trim().toUpperCase(Locale.ROOT)`，格式 `^[A-Z0-9]{4,32}$`，重复 → 409。
4. 审计：`actorAdminId != null` 时 `audit.record(actor, AuditActions.SHOP_COUPON_CREATED | SHOP_COUPON_STOPPED | SHOP_COUPON_CODES_CREATED, "SHOP_COUPON", couponToken, summary)`；**新增这三个常量必须同时在 `R/i18n/messages.properties`、`messages_en`、`messages_id`、`messages_zh_CN` 加 `admin.audit.action.<CODE>` 文案**（`AuditActionLabelsTest` 守卫，`R/` = `petgo-backend/src/main/resources/`）。`actorAdminId == null`（只有 D-24 stag 入口会这样）→ 不写审计、INFO 日志一行。summary 不含兑换码明文。

### AC4 — `CouponLedgerService`：用户券唯一状态入口 `[L0]` `[L1]`（D-2、D-3、P-2）
`B/shop/coupon/service/CouponLedgerService`，所有写都经 `UserCouponLedgerDao` 的**条件语句**完成（并发安全靠 `WHERE status = …`，不靠读后写）：
1. `UserCoupon issue(long userId, ShopCoupon coupon, UserCouponSource source, Instant now)`（`@Transactional(propagation = MANDATORY)`：调用方 2.2 必须已在事务里锁住模板行并扣过总量）：物化有效期——`FIXED`：`valid_from = valid_start_at`、`valid_until = valid_end_at`；`RELATIVE`：`valid_from = now`、`valid_until = (now 的 WIB 日期 + valid_days 天) 的 23:59:59 WIB`（`ScheduleWindow.WIB`；与 UI 稿 G1「Berakhir 6 Nov 2026, 23:59」一致，见「待确认」③）；`INSERT … RETURNING` 后按 id 读回。
2. `void lock(long userId, long orderId, Collection<String> userCouponTokens, Instant now)`（`MANDATORY`，在 3.2 的提交事务内）：对每个 token 执行
   `UPDATE user_coupons SET status='LOCKED', locked_order_id=:orderId, updated_at=:now WHERE public_token=:t AND user_id=:uid AND status='AVAILABLE' AND valid_from <= :now AND valid_until > :now`；任一影响 0 行 → 抛 `CouponInvalidException(token)`（整个提交事务回滚）。**有效性按下单时刻判断**（之后过期不影响本单）。**模板 STOPPED 但未选作废的券照常可锁**（D-3）。
3. `int markUsed(long orderId, Instant now)`（`MANDATORY`）：`UPDATE … SET status='USED', used_order_id=:orderId WHERE locked_order_id=:orderId AND status='LOCKED'`；幂等（重复调用影响 0 行不报错）；**不校验有效期**。
4. `int releaseOnCancel(long orderId, CouponReleaseMode mode, Instant now)`（`MANDATORY`）：
   - `KEEP` → 不动，返回 0（部分取消、用户原因被退回，FR-130.7）；
   - `RETURN` → 对 `locked_order_id = :orderId AND status IN ('LOCKED','USED')` 的行：模板 `status='STOPPED' AND void_on_stop` → `VOIDED`；否则 → `AVAILABLE`，两种都清空 `locked_order_id` / `used_order_id`。已过有效期的回到 `AVAILABLE` 后由 `valid_until` 现算为过期（不另改状态）。
   - 「哪些取消原因退券」的映射在 4.1 的 `CancelReason.refundCoupon` 里决定，本 story **不引入 `CancelReason`**（避免前向依赖），只提供两种模式。
5. `int voidUnused(long couponId, Instant now)`：`AVAILABLE → VOIDED`（只给 AC3.2 调）。
6. `int voidAllAvailableForUser(long userId, Instant now)`：注销联动（AC7）。
7. 2.3 将在本类追加 `markExpiryNotified(...)`；4.2 将追加「迟到款重下单把原券重新锁到新单（已过期也允许）」——都必须写在本类里（P-2）。

### AC5 — 状态现算与有效期口径 `[L0]` `[L1]`（D-2、FR-130.6）
1. 「已过期」**不落库**：`AVAILABLE && valid_until ≤ now` 即过期；`VOIDED` 用户端不展示、不通知。
2. 有效期判断一律用服务端 `now`（P-6），区间左闭右开 `[valid_from, valid_until)`（与 1.2 计价器 P27 一致）。
3. 发放期（`issue_*`）只决定能不能领 / 兑 / 发；使用有效期（`valid_*`）只决定能不能用（PRD「发放期与使用有效期分开」）。

### AC9 — stag 测试入口 `[L0]` `[L1]`（D-24、S-2）
