## Story

As a 买家,
I want 在详情、购物车、结算页都能看到能否送达、运费和优惠后的应付,
so that 下单前就知道要付多少。

## Acceptance Criteria

> 层级：`[L0]` 纯单元 / 静态（云端可跑）· `[L1]` 需 Docker postgres + redis（本地）· `[L2]` 真机 / 视觉 / 真 Biteship（本 story 无界面，L2 只在 10.1 / 10.2 联调）。
> 金额一律 `long`（IDR 无小数）；**所有金额只来自 `ShopPricingCalculator`（P-1）**，本 story 的 service / controller 只装配入参、搬运出参，不做任何加减乘除。

### AC1 — `POST /api/v1/me/checkout/preview` 结算试算（只读）`[L0]` `[L1]`（D-8、FR-128.1 ~ .4、FR-130.3、FR-131）

1. 新端点放在 `MeCheckoutController`（`@RequestMapping("/api/v1/me")`），方法 POST（参数多才用 POST，**语义仍是只读**：不占券、不扣币、不锁库存、不写订单、不改购物车）。
2. 请求体 `CheckoutPreviewRequest`（`shop/order/dto/`）：
   ```json
   {
     "source": "CART | BUY_NOW",              // 必填；缺省或非法 → 422 validation
     "buyNow": { "skuToken": "…", "qty": 1, "entrySource": "…" },   // source=BUY_NOW 时必填；qty 1..99
     "addressToken": "…",                     // 可空 = 用默认地址；默认地址也没有 → notPlaceableReason=NO_ADDRESS
     "courierKey": "jne:reg",                 // 可空 = 最便宜
     "insurance": false,                      // 缺省 false
     "couponMode": "AUTO | MANUAL",           // 缺省 AUTO
     "discountCouponToken": "…",              // MANUAL 时生效；null = 不用满减券
     "freeShippingCouponToken": "…",          // MANUAL 时生效；null = 不用免运券
     "useCoin": true                          // 缺省 true（PRD「有余额默认勾选」）
   }
   ```
   - `courierKey` 格式 = `<courierCode>:<courierServiceCode>`（小写，取 1.1 报价行的两个码拼接）。**若 1.1 已定义了别的快递唯一键，以 1.1 为准并回改本条。**
   - 券 token 是**用户券**的 `public_token`（`user_coupons.public_token`，D-2），不是券模板 token。
3. 行的来源：
   - `CART`：只取购物车 `selected=true` **且有效**的行（`CartView.selectedLines()`，见 AC5 对失效行的改动）；失效行与未勾选行不进入计价。
   - `BUY_NOW`：只用 `buyNow.skuToken` × `buyNow.qty`，**不读、不写购物车**；SKU 不存在 → 404；商品下架 / 售罄 / 不可售（1.1 的 `ShopSku.isSellable()` 为 false）→ 该行进 `lines[]` 且带 `unavailableReason`，`placeable=false`（不抛错，页面要能渲染「不可买」）。
4. 地址：`addressToken` 非空 → `ShippingAddressService.require(userId, token)`（不是本人 → 404，沿用）；为空 → 默认地址（`ShippingAddressRepository.findByUserIdAndIsDefaultTrue`）；都没有 → `address=null`、**不询价**、`notPlaceableReason=NO_ADDRESS`。
5. 询价（调用 1.1 的 `ShippingQuoteService`，**网关调用不在任何数据库事务内**，P-7）：
   - 可配送判定（D-9）= 地址 Kecamatan 在 `shipping_zones.active=true` **且** 报价 ≥ 1 家；区域未开通 → 不询价，`NOT_SERVICEABLE`；报价 0 家 → `NOT_SERVICEABLE`；Biteship 超时 / 5xx / 网络错误（1.1 的 `QuoteFailedException`）→ `QUOTE_FAILED`、`quoteToken=null`、快递列表空，**不抛 503、不回退固定运费**（页面要渲染「运费暂时无法获取 · 重试」）。
   - 报价复用（同收货邮编 + `items_hash` + 发货邮编 30 分钟内）由 1.1 负责，本 story 不另做缓存。
   - 快递列表按价格升序（同价按 `courierCode`、`serviceCode` 字典序，保证稳定）；已选快递 = `courierKey` 指定且仍在列表中则保留，否则最便宜一家（FR-128.3「原快递仍可选则保留否则改最便宜」）。
6. 券：
   - 候选 = 当前用户 `AVAILABLE` 且 `valid_until > now` 的用户券（**`LOCKED` / `USED` / `VOIDED` / 已过期一律不列**，PRD「被占用的券在其他订单结算页不可选」）。读取经 2.2 的券查询服务（计划名 `CouponQueryService`），**不得**在本 story 直接查 `user_coupons` 写 SQL 以外的状态更新（P-2）。
   - 候选映射为 1.2 计价器的值对象 `PricingCoupon`，交计价器给出每张券的可用性与原因（`BELOW_MIN_SPEND | OUT_OF_SCOPE | EXPIRED | RULE_BETTER`）与默认最优组合。
   - `couponMode=AUTO` → 用计价器的最优组合；`MANUAL` → 用请求里的两个 token（null = 不用该类券）；MANUAL 指定的券不在候选里或计价器判为不可用 → 本次**不采用**该券（对应类目 `selectedToken=null`），并把它放进 `unavailable` 组带原因（候选里查不到的券原因 = `UNAVAILABLE`，表示被占用 / 已失效 / 不是你的）；**试算永不因券报错**。
7. PawCoin：`useCoin` 有效值 = `request.useCoin && shop_pawcoin_rules.enabled`；上限 `coinCap = shop_pawcoin_rules.max_coin_per_order`；余额 `PawCoinWalletService.balanceOf(userId)`；币额由计价器给（`min(应付, 余额, 上限)`，D-7）。
8. 保价：`insurance` 有效值 = `request.insurance && 已选快递支持保价`；已选快递不支持时 `insuranceAvailable=false`、`insurance=false`、`insuranceFee=0`。
9. 响应 `CheckoutQuoteView`（新 record，`shop/order/dto/`；**不复用、不改** 旧 `CheckoutPreviewView`，后者留给旧版 App，见 AC4）：
   ```json
   {
     "source": "CART",
     "address": { …ShippingAddressView… } | null,
     "quoteToken": "…" | null,
     "couriers": [ { "courierKey": "jne:reg", "courierCode": "jne", "serviceCode": "reg",
                     "courierName": "JNE", "serviceName": "Reguler", "etaText": "2-4",
                     "price": 18000, "insuranceSupported": true, "cheapest": true } ],
     "selectedCourierKey": "jne:reg" | null,
     "insuranceAvailable": true, "insurance": false,
     "lines": [ { "skuToken", "productToken", "productName", "specName", "price", "qty",
                  "mainImageUrl", "returnPolicy", "unavailableReason": null | "DELISTED" | "OUT_OF_STOCK" | "INSUFFICIENT_STOCK" | "NOT_SELLABLE",
                  "availableStock" } ],
     "pricing": { "goodsAmount", "discountCouponAmount", "shippingFee", "shippingDiscount",
                  "shippingDiscountSource": "NONE | FREE_SHIPPING_RULE | COUPON",
                  "insuranceFee", "payable", "coinAmount", "cashAmount", "savedAmount",
                  "shippingIncluded": true,
                  "freeShippingProgress": { "threshold", "remaining" } | null },
     "coupons": {
       "discount":     { "selectedToken": "…" | null, "available": [CouponOption], "unavailable": [CouponOption] },
       "freeShipping": { "selectedToken": "…" | null, "available": [CouponOption], "unavailable": [CouponOption] }
     },
     "coin": { "balance": 5000, "cap": 1000000, "enabled": true, "useCoin": true, "capReached": false },
     "strictestReturnPolicy": "NO_RETURN_AFTER_OPEN",
     "returnPolicyCopyKey": "NO_RETURN_AFTER_OPEN",
     "placeable": true,
     "notPlaceableReason": null | "NO_ADDRESS" | "NOT_SERVICEABLE" | "QUOTE_FAILED" | "NO_LINES" | "UNAVAILABLE_LINES"
   }
   ```
   - `CouponOption = { userCouponToken, couponToken, kind: DISCOUNT|FREE_SHIPPING, nameId, nameEn, amount, minSpend, validUntil, expiringSoon, deduction, unavailableReason }`；`deduction` = 计价器算出的「若选它能减多少」（不可用时 0）；`expiringSoon` = `valid_until − now ≤ 48h`。
   - `shippingDiscount` 在本视图里是**正数**（减了多少，计价器原值）；订单落库时再取负（见 3.2 AC3，存量列 `shipping_discount ≤ 0`）。两处不要混用。
   - 无报价（`NO_ADDRESS` / `NOT_SERVICEABLE` / `QUOTE_FAILED`）时：仍调计价器（运费、本单最低报价按 0 传入），`pricing.shippingIncluded=false`、`pricing.shippingFee=null`、`pricing.shippingDiscount=null`、`shippingDiscountSource=NONE`；`payable / coinAmount / cashAmount` 是不含运费的值（App 7.1 只展示商品与券，提交按钮禁用）。
   - `returnPolicyCopyKey` = 生效退货规则最严一档的枚举名（与 `strictestReturnPolicy` 同值，App 用它取「开封不退」文案；沿用 `CheckoutPreviewView.strictest` 的判定，抽成静态工具复用，不复制一份）。
   - `notPlaceableReason` 判序：`NO_LINES`（CART 无选中有效行且无选中失效行）→ `UNAVAILABLE_LINES`（存在带 `unavailableReason` 的行）→ `NO_ADDRESS` → `NOT_SERVICEABLE` → `QUOTE_FAILED`；`placeable = (notPlaceableReason == null)`。
   - `coin.capReached` = 计价器判定「若无上限本可用得更多」（沿用 `CheckoutService.coinCapped` 的语义：不是 `coinAmount == cap`），供 D13 提示。
10. 端点不出现可枚举 id：`regionKecamatanId` 之外（区域参考数据例外，架构 m10）一律 token。

### AC2 — `GET /api/v1/shop/products/{token}/shipping-estimate` 运费估算 `[L0]` `[L1]`（D-9、FR-127.1 / .2 / .3、FR-172.1）

1. 参数：`skuToken`（必填）、`qty`（缺省 1，1..99）、`addressToken`（可空，仅登录 `role=USER` 时生效）、`regionKecamatanId`（可空，游客 / 无地址时用）。二者都没有 → 返回 `{serviceable: null, lowestFee: null, quoteFailed: false, freeShippingProgress: null, reason: "NO_DESTINATION"}`。
2. 收货地：`addressToken` → 本人地址（非本人 → 404）；`regionKecamatanId` → `shipping_zones.id`：区域不存在或 `active=false` → `serviceable=false`；区域 `postal_code` 为空（运营未补齐）→ `serviceable=false`（D-9「未配置的区按不支持配送处理」），**都不询价**。
3. 询价包裹 = 该 SKU × qty（走 1.1 的 `items_hash` 与 30 分钟复用）；SKU 不可售（1.1）→ 422 `sku-not-sellable`；商品下架 → 404（410 区分归 6.1，本 story 不改详情接口）。
4. 响应 `ShippingEstimateView { serviceable: Boolean, lowestFee: Long, quoteFailed: boolean, freeShippingProgress: {threshold, remaining} | null, reason: null | "NO_DESTINATION" | "NOT_SERVICEABLE" | "QUOTE_FAILED" }`：
   - `lowestFee` = 本单所有快递最低运费（「运费 Rp X 起」）；
   - `freeShippingProgress` 由计价器给（基数 = 商品实付；此处无券 → 商品实付 = 单价 × qty）；门槛 0 → null；
   - Biteship 失败 → `quoteFailed=true`、`serviceable=null`、`reason=QUOTE_FAILED`，HTTP 200（App 显示「运费暂时无法获取 · 重试」）。
5. 安全：路径在既有 `GET /api/v1/shop/products/**` permitAll 下（`SecurityConfig.java:267-268`），**不新增规则**；controller 内取可选 viewer 时**只认 `role=USER`**（照 `InAppVisitorPetController` 的 viewerId 写法：兽医 token 的 `sub` 与 `users.id` 撞号，不能当用户读其地址），非 USER 带 `addressToken` → 忽略该参数按游客处理。
6. 限流：`rateLimiter.check("rl:shop:ship-estimate:" + (viewerId 或 客户端 IP), 30, 1 分钟)`，超限 429（防刷 Biteship 计费询价）。IP 取法照现有限流先例；若无现成取 IP 工具，游客按 `regionKecamatanId + skuToken` 维度限流并在 Completion Notes 说明。

### AC3 — `GET /api/v1/me/cart` 带 `estimate` `[L0]` `[L1]`（D-9、FR-133.8）

1. `CartView` 末尾追加 `CartEstimate estimate`（可空，全局 NON_NULL 不下发 null）：
   `{ lowestFee: Long|null, goodsAmount, discountCouponAmount, shippingDiscount, payable, saved, freeShippingProgress|null, reason: null | "NO_DESTINATION" | "NOT_SERVICEABLE" | "QUOTE_FAILED" | "NO_SELECTION" }`
2. 口径（PRD 11-04 最终拍板）：预估应付 = 所选商品金额 + 本单最低运费 − 默认最优券（满减 + 免运券，AUTO）− 满额免运减免；**不用币、不保价**；`saved` = 计价器 `savedAmount`。全部由计价器以「最便宜快递 + AUTO 券 + useCoin=false + insurance=false」入参算出。
3. 收货地：默认地址 → 否则查询参数 `regionKecamatanId`（App 传详情页选过的地区）→ 都没有：`lowestFee=null`、`reason=NO_DESTINATION`，`payable` 为不含运费的值（计价器以运费 0 计算）。询价失败同理 `reason=QUOTE_FAILED`。一件没选 → `reason=NO_SELECTION`、金额全 0、不询价。
4. **只在 controller 出口装配**：新建 `shop/cart/service/CartEstimateService.estimate(userId, CartView, regionKecamatanId)`，由 `MeCartController` 的 GET 以及会改变选中集 / 数量的端点（`PUT /items/{skuToken}`、`DELETE /items/{skuToken}`、`PUT /items/{skuToken}/selected`、`PUT /selection`、`DELETE /invalid-items`、`POST /items`）在返回前调用，这些端点都接受可选查询参数 `regionKecamatanId`。**不得**放进 `CartService.view()`：`view()` 被 `CheckoutService` 等内部调用，放进去会让每次结算 / 下单都多打一次 Biteship。
5. Biteship 调用不在 `CartService` 的写事务内：controller 先拿到 `CartView`（写事务已提交），再调 `CartEstimateService`（自身无事务或只读事务，询价由 1.1 服务管理其落库短事务）。

### AC4 — 旧 `GET /api/v1/me/checkout` 保留旧结构（旧版 App，S-4）`[L0]` `[L1]`

1. 路径、参数（`addressToken` 可空）、响应类型 `CheckoutPreviewView` **字段集合一个不增不减**（旧版 App `checkout_preview.dart` 按这些键解析）。
2. 取值改为走与新端点同一条装配链路的「旧结算模式」（3.2 的 `LegacyCheckoutAdapter` 负责组装入参；本 story 先落 `LegacyCheckoutAdapter.previewCommand(...)`，3.2 再补下单那一半）：`source=CART`、最便宜快递、不用券、`useCoin=true`、不保价。
3. 字段映射：`shippingFee` = 最便宜快递运费；`shippingDiscount` = −计价器 `shippingDiscount`（**负数**，旧口径「免运抵扣 ≤ 0」）；`payableTotal / coinAmount / cashAmount` = 计价器 `payable / coinAmount / cashAmount`；`coinBalance`、`maxCoinPerOrder`、`coinCapped` 同 AC1；`serviceable=false` 当且仅当 `NOT_SERVICEABLE`；`shippingMethod` 仍为常量 `REGULER`；`lines` / `unavailableLines` 构造方式不变（`unavailableLines` 只含选中的失效行）。
4. 无地址：**不再**用 `ShippingQuoteService.estimateWithoutAddress`（按最大区域固定运费估算，`shipping_zones.fee` 停读，D-9）→ `shippingFee / shippingDiscount / payableTotal / coinAmount / cashAmount` 全部 `null`、`serviceable=true`（与旧代码「quote == null」分支同形，旧版 App 已能渲染）。询价失败同此处理。
5. `GET /me/checkout` 本身不加任何券字段（旧版 App 不认识）。

### AC5 — 购物车失效行不再默认勾选 `[L0]` `[L1]`（FR-133.8、epics 3.1）

1. `CartService.view()`：失效行（`invalidReason != null`，含 1.1 新增的不可售原因）下发的 `selected` **一律 false**（只改出参，不回写库）。现 `CartService.java:274` 注释「失效行的 selected 照实下发」作废，改为说明新规则。
2. `PUT /api/v1/me/cart/items/{skuToken}/selected`（epics 写的「PATCH」，实际端点是 PUT，见 `MeCartController.java:78`）`selected=true` 且该行当前失效 → **422**（`AppException.validation`，detail「该商品当前不可购买」）；`selected=false` 照常成功（允许取消）。
3. `PUT /api/v1/me/cart/selection`（全选）`selected=true` 时**只把有效行置 true**，失效行不动；`selected=false` 仍作用于全部行。实现：先 `view()` 拿有效行的 skuId 集合，再按集合批量更新（`ShopCartItemRepository` 新增 `updateSelectedForSkuIds(cartId, skuIds, selected)`，`@Modifying` JPQL）。
4. 商品补货后该行重新变为有效时，按库内 `selected` 原值显示（不额外处理）。

### AC6 — 地址簿 `serviceable` `[L0]` `[L1]`（D-9 第 4 点「地址簿标注」、FR-133.11、就绪度 I10）

1. `ShippingAddressView` 末尾追加 `Boolean serviceable`（装箱，可空；NON_NULL 时 null 不下发）。只有 `GET /api/v1/me/shipping-addresses` 列表填它；其他出口（create / update / setDefault 响应、结算视图里的 `address`）传 null，**行为不变**。
2. 判定：
   - Kecamatan 不在 `shipping_zones.active=true` → `false`（不询价）；
   - 已开通 → 用**标准探测包裹**（1,000 g、20×15×10 cm，1.1 定义）按该地址 `kode_pos` 询价，报价 ≥ 1 家 → `true`，0 家 → `false`；
   - 询价失败 → `null`（App 不标注）。

### 拍板点（按建议实现，Completion Notes 复述）

- **① 试算永不因券报错**：MANUAL 指定的券不可用 → 不采用 + 放进 `unavailable` 组；只有提交（3.2）才 409 `coupon-invalid`。理由：试算是渲染页面用的，报错会让整页变错误态（同 `CheckoutService.preview` 头注释「超范围不抛异常」的既有姿态）。
- **② 无报价时 `pricing` 仍下发（不含运费）**：App 需要显示商品金额与券；`shippingIncluded=false` 让 App 知道运费未计。
- **③ 购物车 `estimate` 在 controller 出口装配**：避免 `CartService.view()` 被内部调用时触发计费询价。
- **④ 失效行 `selected` 只改出参不回写**：回写会让补货后「用户曾经勾过」的信息丢失；而不回写不影响下单（下单只认有效行）。
- **⑤ `/me/checkout/**` 加进 USER 精确表**：安全修正，非功能变化。

### 实现提示

- 新编排 `CheckoutQuoteService.preview(userId, CheckoutPreviewRequest)` **不加 `@Transactional`**（要在中间调 Biteship）：
  ```java
  public CheckoutQuoteView preview(long userId, CheckoutPreviewRequest req) {
      CheckoutInputs in = self.loadInputs(userId, req);          // @Transactional(readOnly) ：行、地址、券候选、规则、余额、退货规则
      QuoteOutcome quote = in.address() == null ? QuoteOutcome.noAddress()
              : !zones.isActive(in.address().kecamatan()) ? QuoteOutcome.notServiceable()
              : quotes.quote(in.address().kodePos(), in.packageItems());   // 1.1，事务外；失败 → QuoteOutcome.failed()
      PricingResult pr = ShopPricingCalculator.price(PricingInputs.of(in, quote, req)); // 1.2 纯函数；pr.shippingKnown() → 视图 shippingIncluded，pr.coinCapped() → coin.capReached
      return CheckoutQuoteView.assemble(in, quote, pr, req);
  }
  ```
  `self` 用 `ObjectProvider<CheckoutQuoteService>` 自引用（照 `ShopOrderPaymentService.selfProvider`，`:70`），否则 `@Transactional` 自调用不生效。
- `PricingInputs` 的「本单最低报价」= 报价列表里最低价（不是已选快递价），免运减免封顶要用它（D-7）。

## 待确认 / 发现的规划冲突

1. **安全缺口**：`/api/v1/me/checkout` 在 `SecurityConfig` 是精确路径，架构 D-8 新增的 `/me/checkout/preview` 不在 USER 表内（会落 `anyRequest().authenticated()`，兽医 token 可冒用同号用户）。本 story 追加 `/api/v1/me/checkout/**`（AC7），规划未提，属必须的修正。
2. **epics「勾选失效行的 PATCH 返回 422」**：实际端点是 `PUT /me/cart/items/{skuToken}/selected`，本 story 按 PUT 实现；全选端点 `PUT /me/cart/selection` 同时改为不勾失效行（epics 未写，按「后端不再默认勾选失效行」推出）。旧版 App 若对失效行点勾选会收到 422（旧版统一 toast），可接受。
3. **购物车 `estimate` 的收货地参数**：架构写「详情页选过的地区由 App 传 `regionKecamatanId`」但未说挂在哪些购物车端点上。本 story 让所有会返回 `CartView` 的购物车端点都接受该可选参数（AC3.4）。
4. **无报价时的 `pricing`**：架构未定义无地址 / 询价失败时 `PricingResult` 怎么给。本 story 定为「运费按 0 入计价器 + `shippingIncluded=false` + 运费两字段 null」（AC1.9）。7.1 若需不同口径以本文件为准回改 App。
5. **旧 `GET /me/checkout` 无地址时金额由「最大区域运费估算」变为全 null**（`shipping_zones.fee` 停读的必然结果）。旧版 App 已有该分支的渲染（与「无开通区域」同形），但界面会从「显示一个估算应付」变为「不显示」，10.1 用 1.4.1 包回归时留意。
6. **`courierKey` 格式**：架构只给了字段名。本 story 定为 `<courierCode>:<serviceCode>`，若 1.1 已有快递唯一键，以 1.1 为准。
