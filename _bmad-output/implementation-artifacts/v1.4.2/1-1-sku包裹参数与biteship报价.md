## Story

As a 平台,
I want 按真实包裹向 Biteship 询价并复用报价,
so that 运费准确、询价成本可控。

3. **报价接口细节（2026-11-05 对照官方文档核实）**：
   - `POST https://api.biteship.com/v1/rates/couriers`；测试与正式**同一 base URL**，由 key 区分。
   - 认证头 `Authorization: <API_KEY>`（文档示例原样写 key；`Bearer <key>` 也被接受，本项目统一用**原样 key**）；`Content-Type: application/json`。

   - 起止点三选一：邮编（`origin_postal_code` / `destination_postal_code`，**JSON 数字**，文档示例 `12440`）、`origin_area_id` / `destination_area_id`（字符串）、经纬度（`*_latitude` / `*_longitude`）。**本项目只用邮编**（5 位、首位非 0，按 `Integer.parseInt` 传数字）。
   - `couriers`：**逗号分隔字符串**（如 `"jne,sicepat,anteraja"`），取配置 `BITESHIP_COURIERS`，装配时小写、去空格、去重；**`jntcargo` 必须剔除并 WARN**（其 `price` 强制含保价费，会与本平台自算保价重复）。
   - `items[]` 每项：`name`（商品名 + 规格名，截 100 字）、`value`（单价，整数 IDR）、`quantity`、`weight`（**克**）、`length` / `width` / `height`（**厘米**）；`description` / `category` / `sku` 不传。
   - **不传 `courier_insurance`**：传了 `price` 会把 Biteship 的 `insurance_fee` 加进去，与本平台自算保价（D-7，`insurance_rate_bp`）重复计费。保价金额只在 5.1 下运单时传。也不传任何 COD 参数。
   - 响应顶层 `success / object / message / code / origin / destination / pricing[]`；`pricing[]` 取用字段：`courier_code`、`courier_name`、`courier_service_code`、`courier_service_name`、`duration`（如 `"2 - 3 days"`）、`shipment_duration_range`（如 `"2 - 3"`）、`shipment_duration_unit`（`days` / `hours`）、`price`（IDR，**最终价**）、`available_for_insurance`（布尔）。其余字段（`shipping_fee`、`insurance_fee`、`available_collection_method` 等）忽略。`price` 为非整数时按 `CEILING` 取整为 `long`。
   - **错误格式** `{"success": false, "error": "…", "code": 40001010}`；HTTP 状态 400 / 401 / 402 / 403 / 404 / 422 / 429 / 500。
4. 结果分三类（`BiteshipRatesResult`）：
   - **有报价**：`success=true` 且 `pricing` 非空 → `rates` 列表；

   - **询价失败**：其余一切（401 / 402 / 403 / 422 配额 / 429 / 5xx / 其它 400 码 / 连接超时 / 读超时 / 响应解析失败）→ 抛 `BiteshipException(kind, httpStatus, biteshipCode)`，`kind ∈ AUTH | QUOTA | RATE_LIMITED | BAD_REQUEST | SERVER | NETWORK | PARSE`。

7. **装配护栏**（照 `B/shared/pay/PayConfig.java` 的 fail-closed 先例）：

   - `env.matchesProfiles("prod & !stag")` 且 `mode != live` → 拒启动（stag 容器是 prod + stag 双 profile，允许 stub / sandbox）；
   - 其余（dev、测试、云端）默认 `stub`。

### AC6 — 报价服务与复用 `ShippingQuoteService` `[L0]` `[L1]`（D-9、NFR2）
1. 新建 `B/shop/logistics/ShippingQuoteService`（架构 §5.1 的「替换现 shipping/service 同名类」——**本 story 只新增、不删旧类**，见 AC8）、实体 `B/shop/logistics/ShippingQuoteRecord`（`@Table(name = "shipping_quotes")`，`response` 用 `@JdbcTypeCode(SqlTypes.JSON)`，照 `ShopProduct.feedingGuide` 写法）、`ShippingQuoteRecordRepository`。
2. 值对象（`B/shop/logistics/`）：
   ```java
   public record PackageItem(String name, long value, int quantity, int weightG, int lengthCm, int widthCm, int heightCm) {}
   public record CourierRate(String courierKey,          // = courierCode + ":" + courierServiceCode，如 "jne:reg"
                             String courierCode, String courierServiceCode,
                             String courierName, String courierServiceName,
                             String durationText, String durationRange, String durationUnit,
                             long price, boolean insuranceSupported) {}
   public record QuoteResult(String quoteToken, boolean serviceable, List<CourierRate> rates,   // price 升序
                             Long lowestPrice, String destPostalCode, String itemsHash, Instant expiresAt) {}
   ```
   `PackageItems.of(ShopSku sku, String productName, int qty)`：`!sku.isSellable()` → 抛 `SkuNotSellableException`（即 AC4.2 的 422）。
3. `itemsHash(List<PackageItem>)`（静态、纯函数）：每项规范化为 `weightG,lengthCm,widthCm,heightCm,quantity`，按字典序排序后以 `;` 连接、前缀 `v1|`，取 SHA-256 小写十六进制（64 字符）。**只含包裹参数与数量**（D-9 原文），不含名称、单价 —— 不传 `courier_insurance` 时 Biteship 价格与 `value` 无关。
4. `QuoteResult quote(String destPostalCode, List<PackageItem> items, Long userId)`（默认复用 30 分钟）与重载 `quote(..., Duration reuseFor)`（3.1 地址簿探测包裹传 24 小时）：
   1. 目的邮编不匹配 `^[1-9][0-9]{4}$` → 直接返回不可配送（不调 Biteship、不落库）；
   2. 读发货地邮编（`shipping_settings.origin_postal_code`）：live / sandbox 下为空 → ERROR 日志 + 抛 `QuoteFailedException`；stub 下为空用占位 `"00000"`；
   3. 按 `(dest, itemsHash, origin, providerMode)` 查 `expires_at > now()` 的最新一行 → 命中直接返回（**不调 Biteship**）；
   4. 未命中 → **在事务之外**调 `BiteshipClient.rates` → 成功（含「不可配送」）则在**短事务**里插一行（`expires_at = now + reuseFor`，`lowest_price` = 最低价或 null）并返回；
   5. `BiteshipException` → 抛 `QuoteFailedException`（映射 **503**，`type = https://petgo/errors/quote-failed`，`ErrorTypes.QUOTE_FAILED`），**不落库、不回退固定运费**。
5. `response` JSONB 存**规范化后**的 `{"rates":[CourierRate…],"noCourierCode":40001010|null}`，不存 Biteship 原始响应（原始响应含起止点行政区划，没有存的必要）。`rates` 按 `price` 升序，价格相同按 `courierName`、`courierServiceCode` 升序（结果确定）。
6. `QuoteResult probe(String destPostalCode, Long userId)`：用**标准探测包裹**（1 件、1,000 g、20 × 15 × 10 cm，名称 `probe`、`value` 100,000；配置项 `petgo.shop.shipping-probe.{weight-g,length-cm,width-cm,height-cm}`）调 `quote(..., Duration.ofHours(24))`；3.1 地址簿 `serviceable` 用（3.1 文件里的计划名即 `probe`）。
7. `Optional<QuoteResult> findValid(String quoteToken, Instant now)`：按 token 取、`expires_at > now` 才返回（3.2 提交用；过期由 3.2 映射 409 `quote-expired`）。
8. **可配送判定**（FR-172.1 / D-9）：
   - `Serviceability checkAddress(String kecamatan, String kodePos, List<PackageItem> items, Long userId)`：`shipping_zones` 中该 Kecamatan 不存在或 `active=false` → `ZONE_NOT_OPEN`（**不调 Biteship**）；否则按 `kodePos` 询价 → 报价 ≥ 1 家 `SERVICEABLE`（带 `QuoteResult`）/ 0 家 `NO_COURIER`；询价失败抛 `QuoteFailedException`。
   - `Serviceability checkZone(long zoneId, List<PackageItem> items, Long userId)`（游客按地区，3.1 用）：区不存在 / 未开通 → `ZONE_NOT_OPEN`；`postal_code` 为空 → `NO_COURIER`（不调 Biteship）；否则同上。

### 实现提示

- `LiveBiteshipClient.rates` 骨架：
  ```java
  public BiteshipRatesResult rates(BiteshipRatesRequest req) {
      Map<String, Object> body = Map.of(
              "origin_postal_code", Integer.parseInt(req.originPostalCode()),
              "destination_postal_code", Integer.parseInt(req.destPostalCode()),
              "couriers", props.couriersCsv(),
              "items", req.items().stream().map(i -> Map.of(
                      "name", truncate(i.name(), 100), "value", i.value(), "quantity", i.quantity(),
                      "weight", i.weightG(), "length", i.lengthCm(), "width", i.widthCm(), "height", i.heightCm()))
                      .toList());
      try {
          return rest.post().uri("/v1/rates/couriers")
                  .header("Authorization", props.getApiKey())
                  .contentType(MediaType.APPLICATION_JSON).body(body)
                  .exchange((request, response) -> parse(response.getStatusCode(), readBody(response)));
      } catch (ResourceAccessException e) {
          throw new BiteshipException(Kind.NETWORK, null, null);   // 连接 / 读超时
      }
  }
  ```
  `parse`：2xx → 读 `pricing`；400 且 `code ∈ {40001010, 40001001}` → `BiteshipRatesResult.noCourier(code)`；401/403 → AUTH；402/422 → QUOTA；429 → RATE_LIMITED；5xx → SERVER；其他 400 → BAD_REQUEST；JSON 解析异常 → PARSE。
- `ShippingQuoteService.quote` 的「先查 → 事务外调用 → 短事务落库」用 `TransactionTemplate`（或仓库方法自带的事务），**不要**给 `quote` 方法加 `@Transactional`。
- `Serviceability` 判定时对 `ZONE_NOT_OPEN` / 无邮编**不调 Biteship**（省钱）；日志只记 Kecamatan 所在区 id、不记地址。
- 迁移文本测试照 `B/../test/java/com/tailtopia/notify/PetNotifyMigrationTest.java` 的「读文件去注释再断言」写法。
