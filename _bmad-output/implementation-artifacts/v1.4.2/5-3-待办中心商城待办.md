## Story

As a 运营,
I want 待办中心看到商城待处理数,
So that 不漏.

## Acceptance Criteria

1. 有权限账号 **Then** 待办中心末尾显示「商城待办」两项，点击跳商城页（D0）〔L1〕
2. 计数口径按 PRD，并入 `/admin/nav/badges` 与组角标，注销用户线下处理不计入〔L1〕
3. 无页面权限不渲染、不计入〔L1〕

- **L1/L2 待本地验收**：AC1 ~ AC3 均为 〔L1〕，云端未起容器未验。`AdminPagesRenderSmokeTest.everySidebarLinkMatchesItsPageGate` 与 `AdminNavPermissionMatrixTest`（侧栏 × 权限矩阵）L1 待本地验收：只有商城权限、没有待办页面权限的账号，现在也会渲染待办中心组（只含「商城待办」两项），如果矩阵断言了「整组不渲染」需按设计更新。侧栏样式 L2 待本地验收。
- 无迁移。`NavBadgeService.QUEUES` 加 `shop-order-exceptions`、`shop-refund-payouts`，计数并入 `/admin/nav/badges` 与待办中心组角标；只汇总可见页面（页面 navCodes 判权，无权限不计入）。计数源构造注入（复审修：不用可缺省 setter，免得静默显示 0）：
  - 异常订单 = `AdminShopOrderExceptionService.queueCount()`，与队列列表同一 JPQL 条件（`ShopOrderRepository.EXCEPTION_QUEUE_WHERE`，含 O-26 排除注销用户）；页内「待处理」页签计数也改用它（复审修：原用 100 条上限的列表长度）。
  - 退款打款 = 待打款 + 打款失败 + 待用户选择中超 7 天未选（`AdminShopRefundPayoutService.badgeCount()`，与页签同一 where，排除注销用户）。
- 侧栏（D0）：`AdminNavModel.NavGroup` 增 `shopTodos`（保留两参构造器）；待办中心组末尾「商城待办」小标题 + 「异常订单 ↗」「退款打款 ↗」两项（指向商城组既有页面，不新增 Catalog 页），各挂角标，无页面权限不渲染；只有商城权限的账号也渲染待办中心组。
