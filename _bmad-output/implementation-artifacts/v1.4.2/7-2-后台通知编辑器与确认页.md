正文框同构，去掉 `data-single-line`、`aria-multiline="true"`，CSS `white-space: pre-wrap`。

**序列化（编辑区 → 隐藏字段，每次 `input` 后执行）**
- 递归遍历子节点：文本节点 → `nodeValue` 去掉 `​`、` ` 换普通空格；`span[data-var]` → `{{nickname}}` / `{{petName}}`；`<br>` → 正文 `\n`、标题忽略；块元素（`div` / `p`，浏览器回车可能产生）→ 正文前置 `\n` 再递归、标题直接递归；其它元素（粘贴漏网的）→ 只取其文本。
- 结果只 `trim()` 首尾（与服务端 `trim` 一致），写回 `hidden.value`。
- **手打检测只看文本节点**：拼接全部文本节点（不含标签）后检查 `{{` 与 `data-var-names` 里的显示名（正则 `[{｛]\s*(名1|名2|…)\s*[}｝]`，`i` 标志，名字先做正则转义）。

**反序列化（页面加载 / bfcache 返回时，隐藏字段有值）**：按 `/\{\{(nickname|petName)\}\}/g` 切分，文本段建文本节点（正文里 `\n` 建 `<br>`），令牌建标签。

**光标记录与插入**
- 每个编辑区维护 `savedRange`：`document.addEventListener('selectionchange')` 时，若 `getSelection().anchorNode` 在某编辑区内则 `cloneRange()` 存下。
- 变量按钮在 `mousedown` 时 `preventDefault()`（不让编辑区失焦、不丢选区）；`click` 时：编辑区 `focus()` → 恢复 `savedRange`（没有则折叠到末尾）→ `range.deleteContents()` → 插入标签 → 在标签后插入一个 `​` 文本节点（Chrome / Safari 在 `contenteditable=false` 节点后放不住光标的老问题）→ 光标折叠到该文本节点末尾 → 派发 `new Event('input', {bubbles: true})`（让计数 / 示例 / 序列化 / 清错误统一走 `input`）。
- 插入点若落在另一个标签内部（理论上不会，`contenteditable=false`）→ 改插到该标签之后。

**整体删除**
- `keydown`：`Backspace` 且选区折叠——取光标前一个「有效」节点（跳过只含 `​` 的文本）若是 `span[data-var]` → 删掉它（连同其后的 `​`），`preventDefault`，派发 `input`；`Delete` 对称处理光标后的节点。
- 选区跨标签时浏览器默认会整块删，不额外处理；标签内文字不可编辑由 `contenteditable="false"` 保证。

**粘贴 / 拖放 / 格式化净化**
- `paste`：`preventDefault()`，取 `clipboardData.getData('text/plain')`；标题把 `\r?\n` 换空格；用 `document.execCommand('insertText', false, text)` 插入（保留撤销栈；后台只用 Chrome / Safari，可接受）。**粘贴进来的 `{用户昵称}` 永远是纯文本**，被手打检测拦住——这是预期。
- `drop`：同理只接受 `text/plain`；`dragstart` 在标签上 `preventDefault`（防把标签拖成 HTML 片段）。
- `beforeinput`：`inputType` 以 `format` 开头（Ctrl+B / I / U）→ `preventDefault`；标题的 `insertParagraph` / `insertLineBreak` → `preventDefault`（单行）；正文的 `insertParagraph` → `preventDefault` 后 `execCommand('insertLineBreak')`（统一产出 `<br>`，序列化简单）。

**计数与示例**
- `counted = 文本节点总长度（去 ​） + 20 × 标签数`；写 `[data-count-of]`，`counted > max` 时给 `<em>` 加 `.is-over`、编辑区加 `.is-invalid`。
- 示例效果：遍历同一结构，标签换 `data-sample-nickname` / `data-sample-pet`（hex / tuotuo），文本原样（手打的 `{宠物昵称}` 原样出现，I2）；用 `textContent` 写入，**禁止 `innerHTML`**（防 XSS）。标签与相邻文字之间的空格要保留（I3 稿「temanhex」缺空格视为稿面瑕疵，以真实拼接为准）。

**与现有脚本的衔接**
- `val(name)` 读隐藏字段即可（隐藏字段不 `disabled`）。`validate(1)` 的「空」判断改看序列化结果；标红元素改为对应编辑区（`[data-ed="…"]`）。
- `count(el)` 改为接受编辑区；表单 `input` 监听里把 `t.hasAttribute('data-max')` 分支换成「`t.closest('[data-ed]')` → 序列化 + 计数 + 示例」。
- `clearErrs()` 已按 `.is-invalid` 清，编辑区同样生效。
- 「是否用了宠物变量」= 四个隐藏字段任一含 `{{petName}}`；值变化（true ↔ false）时 `refreshEstimate()`（AC4.3）。

- 架构 §2：原生 `contenteditable` + 不可编辑 `<span>` + 少量 JS；**不引编辑器库、不引前端构建链、不加 npm 依赖**。

### 踩坑与禁止事项

1. `hx-include="#opsn-form"` 只收表单控件——**contenteditable 的内容不会提交**，必须同步到隐藏字段；隐藏字段不能 `disabled`（`val()` 与 htmx 都会跳过 disabled）。
2. 表单上 `hx-disinherit` 不能删（:11-12 注释的坑）；「换一个」按钮自己声明 `hx-target` / `hx-sync="this:drop"`，不要依赖继承。
3. `admin-core.js` 的 422 标红选择器排除 `type="hidden"`：标红靠编辑区的 `data-error-name`，不要给隐藏字段加类。
4. Thymeleaf 片段参数**具名**（3.1.5）：`~{admin/fragments/ops-notification-steps :: previewPane(sample=${sample})}`；`th:attr` 里写 JSON 用 `th:attr="data-var-names=${varNamesJson}"`（Controller 用 Jackson 序列化好，Thymeleaf 自动转义引号）。
5. properties：含 `{0}` 的 `excludedNoPet` / `reach.skippedNoPet` 等撇号写 `''`；`var.hint` EN 含 `won't`、无占位符 → 单撇号；三份文件都写。
6. 千分位：`excludedNoPet` 的 `{0}` 传数字（显示 `3,000`）；预览条的用户 id 由 7.1 传字符串（显示 `#10234`）。
7. **不要整文件格式化** `admin.css` / JS / 模板（存量未格式化），只改相关行，避免几百行无关 diff。
8. 「原有模块照线上」：步骤条、键值表、气泡、吸底条、列表其余列的样式不按稿改。
9. `​` 只是光标锚点：计数、序列化、手打检测、示例都要去掉它。
