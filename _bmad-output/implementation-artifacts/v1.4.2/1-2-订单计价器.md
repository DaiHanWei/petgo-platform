## Story

As a 平台,
I want 所有应付、减免、保价、PawCoin 拆分由一个纯函数算出,
so that 结算、下单、订单详情、退款口径永远一致。

### AC1 — 包与类型 `[L0]`（D-7、P-1、P-4、m6）
1. 位置 `B/shop/order/pricing/`（`B/` = `petgo-backend/src/main/java/com/tailtopia/`）。`ShopPricingCalculator` 为**无状态纯函数**（`public static PricingResult price(PricingInput in)`，或无字段的 `@Component` 包一层静态方法，二选一）。**禁止**任何 IO：不注入仓库、不读时钟（`now` 由入参给）、不读配置。
2. 输入用计价器**自有值对象**（不 import `shop.coupon.*`、`shop.logistics.*`、任何 JPA 实体）：

       public enum Mode { AUTO, MANUAL }

### AC2 — 计算顺序与公式 `[L0]`（PRD FR-130「计算顺序」、FR-172、D-7）
按以下顺序，全部 `long` 整数运算，乘法用 `Math.multiplyExact` / `Math.addExact`（溢出抛 `ArithmeticException`）：
1. `goodsAmount = Σ unitPrice × qty`。
2. **满减券**（DISCOUNT）：`eligible` = 适用范围内行金额之和（`ALL` = 全部；`CATEGORY` = 品类在 `scopeValues` 的行；`PRODUCT` = `productToken` 在 `scopeValues` 的行）。可用条件依次：`validFrom ≤ now < validUntil`（否则 `EXPIRED`）→ `eligible > 0`（否则 `OUT_OF_SCOPE`）→ `eligible ≥ minSpend`（否则 `BELOW_MIN_SPEND`；**门槛按券前、范围内金额**）。`benefit = min(amount, eligible)`（**抵扣不超过适用商品金额**）。
3. `discountCouponAmount` = 选中满减券的 `benefit`（无则 0）；`goodsNetAmount = goodsAmount − discountCouponAmount`（**商品实付**）。
4. `shipping == null`（运费未知）→ `shippingKnown=false`，`shippingFee = 0`、`shippingDiscount = 0`、`source = NONE`；免运券只判 `EXPIRED / OUT_OF_SCOPE / BELOW_MIN_SPEND`，通过者 `usable=true, benefit=0, applied=false`；跳到第 7 步。
5. **满额免运**：`rule.threshold > 0 且 goodsNetAmount ≥ threshold` 时生效；`ruleCap = (cap == null || cap == 0) ? lowestFee : min(lowestFee, cap)`；`ruleDiscount = min(selectedFee, ruleCap)`。否则 `ruleDiscount = 0`。
6. **免运券**（FREE_SHIPPING）：可用条件依次：有效期（`EXPIRED`）→ 有范围时**每一行**都在范围内（任一行不在 → `OUT_OF_SCOPE`）→ `goodsNetAmount ≥ minSpend`（**按商品实付**，否则 `BELOW_MIN_SPEND`）。`benefit = min(selectedFee, lowestFee, amount)`。选中券的 `benefit > ruleDiscount` → 用券（`source = COUPON`）；否则若 `ruleDiscount > 0` → 用满额免运（`source = FREE_SHIPPING_RULE`），该券**不扣**、`applied=false`、`usable=false`、`reason = RULE_BETTER`；两者都为 0 → `NONE`。**相等用满额免运**。所有 `benefit ≤ ruleDiscount` 且 `ruleDiscount > 0` 的可用免运券在评估结果里都标 `RULE_BETTER`。
7. `insuranceFee = insuranceApplicable ? ceil(goodsNetAmount × insuranceRateBp / 10000) : 0`，整数实现 `(goodsNetAmount × rateBp + 9999) / 10000`；**不受运费减免影响**。
8. `payable = goodsNetAmount + shippingFee − shippingDiscount + insuranceFee`。
9. **PawCoin**：复用 `PaymentSplit.compute`（AC5 加 `useCoin` 参数），`shippingPortion = (shippingFee − shippingDiscount) + insuranceFee`：`coinAmount = (useCoin && coinEnabled) ? max(0, min(deductible, balance, maxPerOrder)) : 0`，`deductible = allowShippingDeduction ? payable : max(payable − shippingPortion, 0)`；`cashAmount = payable − coinAmount`；`coinCapped = useCoin && coinEnabled && min(deductible, balance) > maxPerOrder`。
10. `savedAmount = discountCouponAmount + shippingDiscount`（**不含 PawCoin**——PawCoin 是支付方式不是折扣，FR-131）。
11. `freeShippingProgress = rule.threshold > 0 ? (threshold, max(0, threshold − goodsNetAmount)) : null`（**基数 = 商品实付**，FR-127.3；与运费是否已知无关）。

### AC3 — 默认最优组合与手选 `[L0]`（D-7、PRD「券的使用规则细节」、FR-130.3）
1. `AUTO`：满减券取 `benefit` 最大的可用券；并列取 `validUntil` 早的；再并列取 `userCouponToken` 字典序小的（结果确定）。**先定满减券，再按定下后的商品实付评估免运券**；免运券取 `benefit` 最大且 `> ruleDiscount` 的可用券（并列同上）。无可用券 → 对应 `applied*` 为 null。
2. `MANUAL`：只用入参指定的 token（null = 不用该类券）。指定的 token 不在 `coupons` 里，或该券不可用（`EXPIRED / OUT_OF_SCOPE / BELOW_MIN_SPEND`）→ 不应用、`manualSelectionInvalid = true`。指定的免运券只是**输给满额免运**（`RULE_BETTER`）**不算无效**：不扣券、用满额免运、`manualSelectionInvalid = false`。
3. 所有入参券都出现在 `evaluations`（顺序同入参），`applied=true` 的最多一张满减 + 一张免运（每单最多 1 + 1，FR-130.1）。
4. ⚠️ AUTO 是 PRD 原文的**贪心口径**（「抵扣额最大的满减券 + 优于满额免运的免运券」），不做全局最优搜索；表中 P49 钉住这一行为（见「待确认」①）。

## 待确认 / 发现的规划冲突

1. **默认最优组合是贪心口径**（P49）：满减券取抵扣最大后，可能让商品实付跌破满额免运门槛，整体反而比不用券贵（例：302,000 用 5,000 券应付 317,000，不用券 302,000）。PRD 与 D-7 原文就是贪心，本 story 照做并用 P49 钉住；是否改为「两类券联合取应付最小」需产品拍板（涉及钱，不擅改）。用户仍可手动不用券。
2. **`allow_shipping_deduction=false` 时保价费是否算「运费部分」**：现规则 3 只说运费；本 story 按保守侧把保价也排除在币抵扣外。该开关默认 true、后台无页面，线上实际不触发。
3. **`payable = 0` 的订单**（P45：满减把商品抵到 0 + 免运券抵掉全部运费）：计价器照算；提交与支付路径如何处理（不出码、直接已付款）归 3.2，需 3.2 明确。
