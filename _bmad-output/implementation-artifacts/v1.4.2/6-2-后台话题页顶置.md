## Story

As a 运营,
I want 给话题页顶置示范帖或活动推广卡,
so that 话题页有官方引导。

## Acceptance Criteria

> 层级：L0 = `mvn -B clean package` 内单元 / 守卫；L1 = Docker 集成（MockMvc + 真库）；L2 = 本地浏览器看后台 + Android 模拟器看 App 话题页。

**AC1 — 顶置管理页签（G1）**〔L1 / L2〕（epics 6.2 AC1、AB-10A.1、UI G1）
1. 顶置管理页顶部加两个页签「首页 Feed」｜「话题页」（`admin.pins.tab.feed` / `admin.pins.tab.topics`），写法照评论管理 `fragments/comments-tabs.html`（`.tabs` + `a.tab.tab--on`，13px 加粗、选中品牌紫字 + 2px 紫下划线），**整页链接** `/admin/content-pins` 与 `/admin/content-pins/topics`；两个页签门控都 = `AdminContentPinController.VIEW`（`sec:authorize` 逐字一致）。
2. 「首页 Feed」页签 = 线上现有列表**原样**（标题行、筛选栏坑位 / 状态、摘要条、表格 4 列、分页、新建 / 改时间 / 提前结束全部照旧）；只把说明句 `admin.pins.subtitle` 改为 PRD §7 新值（「配置首页 Feed 与话题页坑位：…」，四个 properties 文件同步改）。坑位下拉保持原样（不在本 story 删）。

**AC2 — 话题页页签 · 话题列表（G1a）**〔L1 / L2〕（epics 6.2 AC1、AB-10A.1、UI G1a）
1. `GET /admin/content-pins/topics?q=&page=`：说明句 `admin.pins.topics.hint`；带话题名搜索（`admin.topics.searchPlaceholder`，忽略前导 `#`、不区分大小写、转义 `%` `_`）；本页签右上**不放**「＋ 新建顶置」。
2. **只列正常（ACTIVE）与隐藏（HIDDEN）话题，不列禁用**；列：话题名（官方带方角「官方」标签 `admin.topics.type.OFFICIAL`）/ 状态（圆点 + 徽章，同 6.1）/ 当前生效的顶置（类型灰字 + 标题摘要一行截断，无则「—」）/ 排期中（条数）/ 近 7 天热度（默认倒序、表头 ▼）/ 操作（文字链 `admin.pins.topics.manage`「管理顶置 →」，`.opsp-lnk`）。每页 20，`.pager` 分页。
3. **整行可点**：悬停整行浅紫底 + 手形光标（`.lst-table tr[data-drawer-url]` 同款视觉），点击进 G1b（整页跳转，不是开抽屉——用 `data-href` 或行内链接覆盖，见 Dev Notes）。
4. 无话题 / 搜索无结果 → `.empty` 空态（文案复用 `admin.topics.emptyFiltered`）。

**AC3 — 话题排期页（G1b）**〔L1 / L2〕（epics 6.2 AC2、UI G1b）
1. `GET /admin/content-pins/topics/{topicId}?status=&page=`：顶部面包屑「顶置管理 / 话题页 / #话题」（前两段可点：`/admin/content-pins`、`/admin/content-pins/topics`；13px 灰字 + 品牌紫链接；**新写法**，后台无既有面包屑组件）；h1 = `#` + 话题显示写法 + 官方标签；右侧「返回列表」（`btn btn-neutral btn-sm`，`admin.common.backToList`，回 G1a）+「＋ 新建顶置」（`MANAGE` 门控）。说明句 `admin.pins.topic.subtitle`。
2. 下方结构 = 现有顶置列表**原样复用**：筛选栏只剩「状态」（坑位由页面决定）、摘要条（生效中 / 排期中 / 已结束，`pins-list :: sumbar`）、表格 4 列（`pins-list :: rows`）、分页、点行开「顶置详情」抽屉（改时间 / 提前结束，同 Feed）。分页与刷新链接必须留在本话题页（不得跳回 Feed 列表，见 Dev Notes「pins-list 参数化」）。
3. 话题 HIDDEN → 照样能进、能新建；话题 DISABLED 或不存在 → **404**（G1a 不列它，也就进不来；直接敲 URL 同样 404）。
4. 空排期 → 复用 `admin.pins.empty`「该坑位还没有任何顶置排期。」。

**AC4 — 新建话题页顶置（G2）**〔L1〕（epics 6.2 AC2 / AC3、AB-10A.1、D-6、UI G2）
1. 从 G1b「＋ 新建顶置」打开 `GET /admin/content-pins/new/drawer?slot=TOPIC_PAGE&topicId={id}`：抽屉同现有新建表单（`drawer-content-pin :: createForm`，6 项原有模块全保留：头「顶置详情 ✕」、h3「新建顶置」、类型下拉、「选择内容」、生效时间（WIB，必填 *）、「保存」），**新增**：h3 下一行只读文字「坑位 话题页 · #KucingLucu」（`admin.pins.slot` + `admin.pins.slot.topicPage`，不用灰底框）；Feed 坑位打开时不显示这一行。
2. 选择内容：候选**只列该话题下已发布、公开、未删除的帖子**（`content_topics` 关联 ∩ `PinnableContentPicker.pinnable`）；说明句换成 `admin.pins.pickHintTopic`；候选为空 → `admin.pins.pickEmptyTopic`「该话题下还没有可顶置的公开内容。」；搜索框与「加载更多」都带上 `topicId`；按数字 id 直达（`PinnableContentPicker.page` 的 `\d{1,18}` 分支）同样只认该话题下的帖子。推广卡片字段与 Feed 坑位完全一样、不受话题限制。
3. 服务端权威：`POST /admin/content-pins` 收 `slot=TOPIC_PAGE` + `topicId`，**服务端自己拼** `ContentPin.topicSlot(topicId)`；话题不存在或 DISABLED → 422；内容顶置所选帖子不属于该话题 / 非公开 / 未发布 / 已删 → 422（文案见「待确认 #1」）；`slot` 只接受 `HOME_FEED` 与 `TOPIC_PAGE`，其他任意字符串 → 422（关掉现有「slot 是任意字符串」的口子）。
4. **同坑位重叠校验沿用**（`ContentPinService.requireNoOverlap`，首尾相接不算重叠，报错带冲突项 `admin.err.pins.overlap`）；不同话题之间、话题与首页 Feed 之间互不影响。
5. 成功：toast `admin.flash.pins.saved`「已保存顶置排期」，回 G1b 并刷新列表（与现有 Feed 新建一致）。
6. 写操作审计沿用 `CONTENT_PIN_CREATE` / `CONTENT_PIN_EDIT` / `CONTENT_PIN_TERMINATE`（summary 里的 `slot=TOPIC:{id}` 足以区分）。

**AC5 — 话题下拉 / 可配置范围**〔L1〕（epics 6.2 AC3、AB-10A.1）
1. 任何「选话题」的入口（G1a 列表、`newDrawer` 的 `topicId` 校验、`POST` 的 `topicId` 校验）只认 ACTIVE 与 HIDDEN，**不列 / 不收 DISABLED**。

**AC6 — 禁用联动**〔L1〕（epics 6.2 AC4、D-6）
1. 话题被禁用（6.1 的 `disable`）→ 其话题页坑位全部未结束排期写 `terminated_at`，后台显示「已结束」（`PinRow.ended()`）；App 端不再展示（4.2）。
2. 恢复为正常后**不自动恢复**：G1b 里这些排期仍是「已结束」，需运营重新新建。

**AC7 — 下架联动回归**〔L1〕（epics 6.2 AC5、PRD §3.4「不会出现点进去是空的置顶」）
1. Given 话题页内容顶置引用的帖子被作者删除 / 审核下架 / 作者封号（`ContentUnavailableEvent`），Then `ContentPinTakedownListener` 在同一事务内结束该排期（`terminateByContent`），同首页 Feed。
2. Given 作者注销（`ContentService.deactivateAuthorContent` → `terminateForAuthor`），Then 话题页排期同样结束。

**AC8 — 话题编辑抽屉「话题页顶置」区块（F4 / F5）**〔L1 / L2〕（epics 6.2 AC6、AB-10B.5、UI F4 / F5 / F7）
1. 官方 / 用户 / 隐藏话题的抽屉（6.1 的 `drawer-topic :: drawer`）在说明字段之后、底部操作条之前显示区块：小标题 `admin.topics.pins.title`「话题页顶置」（`.pin-card` / `.tag-card` 写法：白卡 + 13px 灰色半粗小标题）→「生效中」= 当前生效的一条（类型灰字 + 标题摘要一行截断；无 →「—」）→「排期中」= 接下来最多 3 条（类型 + 标题 + 起止时间 WIB；无 →「—」）→「＋ 新建顶置」（`btn-neutral btn-sm`）→「查看全部排期 →」`admin.topics.pins.viewAll`（普通链接跳 G1b）。
2. **禁用话题（F7）无此区块**；没有 `CONTENT_PIN_VIEW`（且非超管）的账号也不显示此区块；「＋ 新建顶置」只对有 `CONTENT_PIN_MANAGE`（或超管）显示（`sec:authorize` 与 `AdminContentPinController.MANAGE` 逐字一致）。
3. 「＋ 新建顶置」= `<button data-drawer-open="/admin/content-pins/new/drawer?slot=TOPIC_PAGE&topicId={id}&from=topic" data-drawer-res="topic">`：`admin-drawer.js` 把 G2 新建表单载入**同一个 480px 话题抽屉**（替换抽屉体，不叠第二层），坑位与话题只读预选；表单顶部加文字链「← 返回话题详情」`admin.pins.backToTopic`（`data-drawer-open` 回 `/admin/topics/{id}/drawer`、`data-drawer-res="topic"`）。
4. 在话题抽屉里保存成功 → toast「已保存顶置排期」+ 服务端 `HX-Trigger: admin:drawer-open` 带回本话题抽屉 URL（`{"url":"/admin/topics/{id}/drawer","res":"topic"}`），回到话题详情、区块刷新（同「内容标签」新建后用 `admin:drawer-open` 切换抽屉内容的机制）；失败（重叠 / 缺必填 / 不属于该话题）错误留在表单内的 `#pin-drawer-err`。
5. 抽屉里**只看和新建**；改时间 / 提前结束在 G1b 做。区块与 G1b 是同一份数据。

**AC9 — 端到端**〔L1 / L2〕（epics 6.2 AC7、PRD FR-69 AC7）
1. L1：后台给话题配一条时间窗包含当前时刻的推广卡 → `GET /api/v1/content-posts/pinned?topic={标准名}` 返回它；时间窗在未来 → 空；提前结束 → 空；配内容顶置 → 返回该帖且该帖不在 `GET /api/v1/topics/{name}/posts?sort=latest` 列表里重复出现（4.2 让位规则回归）；话题 HIDDEN → 仍返回；话题 DISABLED → 不返回。
2. L2：App 话题页在时间段内显示顶置、到点自动下线（模拟器 + 真后端，配一条 2–3 分钟的短窗口观察）。

**AC10 — 权限、三语、还原度**〔L0 / L1 / L2〕（epics 6.2 AC8）
1. 新增页面 / 端点门控：G1a、G1b、`pick` = `AdminContentPinController.VIEW`；`newDrawer`、`POST` = `MANAGE`（复用顶置两码，**不新增权限码**）；`active` = `"content-pins"`（侧栏仍高亮「顶置管理」）。
2. 新文案按 PRD §7「AB-10A 话题页顶置（G 屏）」表 + F 屏表里的 `admin.topics.pins.title` / `admin.topics.pins.viewAll` / `admin.pins.backToTopic` 写入四个 properties；复用词条直接引用原 key；含 `{0}` 的词条撇号写 `''`。
3. EN / ID 下 G1 / G1a / G1b / G2 无中文残留（`AdminPagesRenderSmokeTest` 双语扫描）。
4. L2：G1 / G1a / G1b / G2 / F4 区块 / F5 区块逐屏对照 UI 稿打分，**还原度 ≥ 95%**。
