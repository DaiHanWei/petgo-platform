## Story

As a 运营,
I want 在后台管理话题、建官方话题、决定首页话题行放哪些,
so that 能策划话题活动、冷处理或封禁违规话题。

## Acceptance Criteria

> 层级：L0 = `mvn -B clean package` 内的纯单元 / 源码守卫；L1 = Docker postgres + redis 集成测试（MockMvc + 真库）；L2 = 本地浏览器打开后台页面目视 + 还原度打分。

**AC1 — 权限与侧栏**〔L0 / L1〕（epics 6.1 AC1、D-18）
1. 新增权限码 `AdminPermissions.TOPIC_VIEW = "content.topic_view"`、`TOPIC_MANAGE = "content.topic_manage"`（命名沿用同组 `content.tag_view` / `content.pin_view`），分别进 `GROUPS` 的「查看」「编辑」两组（从而进 `ALL`）；**不预授**任何预置角色、不做回填迁移（同 1.4.0 新码做法：超管隐式拥有，需要时在角色页勾选）。
2. `AdminPageCatalog.PAGES` 在 `content-tags`（`AdminPageCatalog.java`:162-163）**之后**插入 `page("topics", G_CONTENT, "/admin/topics", List.of(TOPIC_VIEW), List.of(TOPIC_MANAGE), List.of()).nav("admin.nav.topics", "topics", TOPIC_VIEW)`。
3. Given 有 `TOPIC_VIEW`，Then 侧栏「✍️ 内容」组「内容标签」后出现「话题」；无该码（且非超管）→ 侧栏无此项、直接访问 `/admin/topics` 403。
4. `@PreAuthorize` 入口门与侧栏 `navCodes` **逐字同集**；页面内所有写操作按钮的 `sec:authorize` 与对应 Controller 的 `MANAGE` 表达式逐字一致（`hasRole('SUPER_ADMIN') or hasAuthority('content.topic_manage')`）。只有 `TOPIC_VIEW` 的账号：能看列表 / 抽屉，看不到「＋ 新建话题」、开关不可点、序号框只读、抽屉无「保存 / 隐藏 / 禁用 / 恢复」；直接 POST → 403。

**AC2 — 列表（F1 / F9）**〔L1 / L2〕（epics 6.1 AC2、AB-10B.1、UI F1 / F9）
1. 页面骨架同「内容标签」「顶置管理」：标题行（h1「话题」+ 右上「＋ 新建话题」）→ 灰色说明（`admin.topics.subtitle`）→ 筛选栏 → 摘要条 → 表格 → 分页（每页 20）→ 行内报错槽（`#admin-inline-error`）。
2. 筛选：类型（全部 / 官方 / 用户）、状态（全部 / 正常 / 隐藏 / 禁用）、按话题名搜索（占位 `admin.topics.searchPlaceholder`；忽略用户输入的前导 `#`；不区分大小写、包含匹配、转义 `%` `_`）。
3. 摘要条 5 格：话题总数 / 官方话题 / 首页话题行（显示「N / 5」）/ 已隐藏 / 已禁用；**全量口径，不随筛选变**（同内容管理摘要条）。
4. 表格 8 列：话题名（`#` + `name_display`，不加粗）/ 类型（方角 `.tag`：官方 = 品牌紫描边，用户 = 中性灰）/ 状态（圆点 + 徽章：正常 `dot--ok` + `badge-ok`、隐藏 `dot--wait` + `badge-warn`、禁用 `dot--hot` + `badge-danger`）/ 帖子数（`topics.post_count`，每小时刷新，右对齐等宽数字）/ 近 7 天热度（`heat_score` 一位小数，右对齐等宽，DISABLED 显示「—」，表头 ▼ 品牌色表示当前排序列）/ 首页话题行（开关 + 序号）/ 创建时间（WIB，`yyyy-MM-dd HH:mm`）/ 操作（「编辑」）。
5. 默认按近 7 天热度倒序（`heat_score DESC NULLS LAST, created_at DESC, id DESC`）；行高 48px；禁用行置灰（`row-muted`）；点行或「编辑」开右侧 480px 抽屉；行内开关 / 序号框 / 编辑链接的点击**不触发**开抽屉（`admin-drawer.js` 已排除 a / button / input / label / select）。
6. F9：筛选或搜索无结果 → 表格换成线上 `.empty`（🔍 28px + `admin.topics.emptyFiltered`「没有符合条件的话题。」，无白卡、上下 40px），筛选栏与摘要条保留。

**AC3 — 新建官方话题与升级（F2 / F3）**〔L1〕（epics 6.1 AC3、AB-10B.2、D-2、**R-5**）
1. F2 抽屉：头部标题 `admin.topics.drawer.title`，体内 h3 `admin.topics.drawer.new` → 名称（`.price-inp` 写法的框内灰色固定 `#` 前缀，输入不含 `#`，必填红 *，灰字 `admin.topics.nameHint`）→ 说明 ID / 说明 EN（textarea，圆角 6、最小高 96，选填，占位 `admin.topics.descPlaceholder`，灰字 `admin.topics.descHint`）→ 错误槽 → 「保存」（最小宽 88）。官方话题**不做封面**。
2. 名称按 `TopicNameRules` 校验（2–30 字符、字母（任何语言）/ 数字 / 下划线、非纯数字；与 App 正文解析同一实现，P-1）；不合规 → 422 抽屉错误槽。
3. 不存在同名（按 `name_norm`）→ 新建 `type = OFFICIAL`、`status = ACTIVE`、`name_display` = 填写写法；成功后关闭抽屉、列表刷新并**定位到新行**（翻到新行所在页、行高亮约 2 秒），toast `admin.flash.topics.created`「已创建话题 #{0}」。
4. F3：输入时（300ms 防抖）若与已有**用户话题**同名（不区分大小写）→ 名称下方黄条 `admin.topics.upgradeWarn`「已有用户话题 #{0}（{1} 条帖子）……」（`.banner.warn`；`{1}` = **实时**查的帖子数，见 AC7.2）；点「保存」弹浏览器原生 confirm `admin.topics.upgradeConfirm`（3 行）→ 确认后升级：`type → OFFICIAL`、`name_display` → 后台填写写法、写入说明、**帖子关联不动**、首页话题行位置不动；toast `admin.flash.topics.upgraded`。
5. **R-5**：重名用户话题为 HIDDEN → 照常升级、**保持 HIDDEN**；为 DISABLED → **拒绝升级**（422，提示先恢复，文案见「待确认 #1」），不改任何字段。
6. 与**官方话题**重名 → 422「不可保存」（文案见「待确认 #1」），黄条不出现。
7. 升级后**不可降回**用户话题：系统中不存在任何「取消官方 / 降级」入口与端点。
8. 服务端权威：保存时若发现同名用户话题而请求未带「已确认升级」标记（输入时没看到黄条，例如期间刚被 App 用户建出来）→ 422 并回显黄条同句，运营再点一次保存走 confirm；并发新建同名（App 发帖建 USER 与后台新建同时）不 500、不出两条（`INSERT … ON CONFLICT (name_norm) DO NOTHING` 后重查判定，D-2 同口径）。

**AC4 — 编辑（F4 / F5）**〔L1〕（epics 6.1 AC4、AB-10B.2）
1. 抽屉结构照「内容标签」详情抽屉：头部卡（`.card` + 13px 半粗：名称 + 类型方角标签 + 状态圆点徽章；数据行：帖子数（**实时**）/ 近 7 天热度 / 首页话题行「第 N 位」或「否」/ 创建时间 WIB，禁用话题把创建时间换成「禁用时间」`admin.topics.meta.disabledAt`）→ 编辑区（字段 + 「保存」，未改动时为线上禁用态：品牌紫 50% 透明）→ 吸底操作条（`.pl-actions.sticky-footer`，按钮靠右）。
2. F4 官方话题：「显示写法」+ 灰字 `admin.topics.displayNameHint`；说明 ID / EN **随时可改**；toast `admin.flash.topics.updated`。
3. 显示写法**只能改大小写**：`TopicNameRules.normalize(新写法) == name_norm` 且新写法本身合规，否则 422，抽屉错误槽（`p.err` 13px 红字，位于「保存」上方）显示 `admin.err.topics.caseOnly`；前端 `admin-topics.js` 同步做同一判断（输入即提示、保存置灰），服务端为准。
4. F5 用户话题：只有「显示写法」一个可编辑字段；说明区显示灰字 `admin.topics.userDescHint`，**无说明输入框**；服务端对用户话题忽略任何说明参数（不写库）。
5. 改显示写法后：话题页标题 / 首页话题行 / `#` 联想用新写法（App 侧由 4.2 读 `name_display`），帖子正文不变、帖子关联不变（PRD FR-69 AC11 后台一侧）。

**AC5 — 首页话题行（F1 / F8）**〔L1〕（epics 6.1 AC5、AB-10B.3）
1. 行内「首页话题行」格 = 新开关组件（32×18，整格 28px 可点）+ 序号框（只在已放入时显示；只读文本给无 `MANAGE` 的账号）。
2. 打开开关 → 排到最后（已有 N 个 → 第 N+1 位），toast `admin.flash.topics.featured`「已放入首页话题行（第 {0} 位）」。
3. 改序号 → 与原占该位的话题**互换**，toast `admin.flash.topics.featureReordered`；序号只接受 1 到当前已放入个数（最多 5），超出 → 该行下方报错 `admin.err.topics.featureOrderRange`「序号只能填 1–{0}」（前端即时校验 + 服务端 422 兜底）。
4. 关闭开关 → 移出，后面的依次前移，toast `admin.flash.topics.unfeatured`。
5. 最多 5 个：已有 5 个时打开第 6 个 → 开关弹回关闭、表格（含分页）下方 `#admin-inline-error` 红字 `admin.err.topics.featureLimit`（F8，页面下滚可见）；不挤掉任何一个。
6. 隐藏 / 禁用的话题：开关半透明不可点（同 `.btn[disabled]`）；服务端对其放入请求 422（文案见「待确认 #1」）。
7. 并发一致：两个运营同时打开开关 / 同时改序号 → 结果序号连续（1..N 无空洞、无重复）、总数 ≤ 5、不 500（AC8 并发测试）。
8. 列表排序不受序号影响（仍按热度）；序号只决定 App 首页话题行从左到右的顺序，不足 5 个由 4.2 的 `home-row` 按热度补齐。

**AC6 — 隐藏 / 禁用 / 恢复（F4–F7）**〔L1〕（epics 6.1 AC6、AB-10B.4、D-2、D-6）
1. **隐藏**（底部 `btn-neutral`「隐藏」）：直接生效、不弹确认；`status → HIDDEN`；若在首页话题行 → 自动移出、后面前移；toast `admin.flash.topics.hidden`，原在首页话题行时追加 `admin.flash.topics.hiddenUnfeaturedSuffix`。话题页仍可访问（App 侧 4.2 行为）。
2. **禁用**（底部 `btn-danger`「禁用」）：浏览器原生 confirm `admin.topics.disableConfirm`（3 行，`admin-core.js` 的 `data-confirm` 机制）→ 同一事务内：`status → DISABLED`、记 `disabled_at = now`、移出首页话题行并前移、**立即结束该话题页坑位所有未结束排期**（`content_pins.slot = 'TOPIC:{topicId}'` 中 `terminated_at IS NULL AND ends_at > now` 的行写 `terminated_at = now`，含生效中与排期中，见「待确认 #2」）；抽屉头部徽章变「禁用」、列表该行置灰、toast `admin.flash.topics.disabled`。
3. 禁用后（App 侧由 4.1 / 4.2 保证，本 story L1 回归断言）：`GET /api/v1/topics/{name}` 404；帖子出参 `topicNames` 不含它；新发帖同名话题不建关联；首页话题行 / `#` 联想不出现。
4. **恢复**：隐藏中的话题底部为「恢复为正常」+「禁用」，「恢复为正常」直接生效（无确认）；禁用中的话题底部只剩「恢复为正常」（主按钮小号），点后原生 confirm `admin.topics.restoreConfirm`（3 行，`{1}` = 实时帖子数）→ `status → ACTIVE`、`disabled_at → NULL`；两种恢复 toast 都是 `admin.flash.topics.restored`。
5. 恢复后：禁用前的帖子关联回到话题下（关联一直保留，D-2）；禁用期间同名帖子不补；**首页话题行位置不恢复**、**禁用时结束的话题页顶置不恢复**。

**AC7 — 帖子数口径**〔L1〕（R-5、D-2、D-14）
1. 列表「帖子数」读 `topics.post_count`（热度任务每小时重算，最多滞后 1 小时，R-5 接受）。
2. 抽屉头部、升级黄条 / 升级确认句、恢复确认句里的帖子数**实时查**：`content_topics ⋈ content_posts`，口径与 `TopicHeatJob` 的 `post_count` 一致（`visibility = 'PUBLIC' AND status = 'PUBLISHED' AND deleted_at IS NULL`）。

**AC8 — 审计、三语、并发、还原度**〔L0 / L1 / L2〕（epics 6.1 AC7、NFR4、NFR5、D-18）
1. 每个写操作调 `AdminAuditService.record(adminId, AuditActions.TOPIC_*, "topic", String.valueOf(id), summary)`（新建 / 升级 / 编辑 / 隐藏 / 禁用 / 恢复 / 放入 / 移出 / 改序号）；summary 只记话题标准名、状态变化、序号，不记说明全文。
2. 新增文案一律按 PRD §7「AB-10B 话题管理（F 屏）」表的**建议 key** 写入 `messages_zh_CN.properties` / `messages_en.properties` / `messages_id.properties`，并同步默认文件 `messages.properties`（英文，见 Dev Notes「i18n」）；表中标「复用」与「直接复用的线上词条」的**直接引用原 key**，不新建重复 key。
3. 含 `{0}` / `{1}` 的词条里撇号写成 `''`（EN `can''t`、`isn''t`）；确认框多行写 `\n`。
4. 后台切到 EN / ID 时本页无中文残留（`AdminPagesRenderSmokeTest` 双语扫描通过）。
5. 并发：AC5.7 的并发测试通过（`pg_advisory_xact_lock` 串行化首页话题行改动）。
6. L2：本地打开 F1–F9 逐屏对照 UI 稿打分，**还原度 ≥ 95%**（记入 Completion Notes）。

### 首页话题行算法（AC5，必须照此实现）

- 每个改动 `featured_order` 的方法（feature / unfeature / reorder / hide / disable）开头执行 `SELECT pg_advisory_xact_lock(hashtext('topics_featured_order'))`（先例 `AdminConfigService.java`:474-477），随事务释放。
- 🔴 **部分唯一索引是立即检查**：Postgres 的唯一**索引**不能 deferrable，单条 `UPDATE … SET featured_order = featured_order - 1 WHERE featured_order > :pos` 在行处理顺序不利时会撞索引。前移 / 互换必须分步：
  - 移出 `pos`：先把它置 `NULL`，再对 `featured_order > pos` 的行**按升序逐行** `-1`（≤ 4 行），或用「先取负再还原」两条 UPDATE（`SET featured_order = -featured_order` → `SET featured_order = -featured_order - 1 WHERE featured_order < 0`）。
  - 互换 `A(pos a) ↔ B(pos b)`：`A → NULL`，`B → a`，`A → b`。
- 放入：校验 `status = ACTIVE`（否则 422）、已在行中则幂等返回当前位、`count >= 5` → 422 `admin.err.topics.featureLimit`，否则 `count + 1`。
- 改序号：`1 <= order <= count`，否则 422 `admin.err.topics.featureOrderRange`（`{0}` = count）。

### 待确认 / 发现的规划冲突（不改规划文档）

1. **PRD §7 文案表缺以下 key（本 story 需要，按推荐写入并请产品确认措辞）**：
   - `admin.page.topics`（角色权限矩阵页的页面名）：话题 / Topics / Topik；
   - `admin.err.topics.nameInvalid`：名称不符合规则：2–30 个字符，只能用字母、数字、下划线，不能是纯数字。/ Invalid name: 2–30 characters, letters, numbers and underscores only, and not numbers only. / Nama tidak valid: 2–30 karakter, hanya huruf, angka, dan garis bawah, tidak boleh angka saja.
   - `admin.err.topics.officialExists`：已有同名官方话题 #{0}，不能重复创建。/ An official topic #{0} already exists. / Topik resmi #{0} sudah ada.
   - `admin.err.topics.upgradeDisabled`（R-5）：同名用户话题 #{0} 已被禁用，请先在列表中把它恢复为正常，再新建。/ User topic #{0} is disabled. Restore it in the list first, then create it again. / Topik pengguna #{0} sedang nonaktif. Pulihkan dulu di daftar, lalu buat lagi.
   - `admin.err.topics.featureNotAllowed`：隐藏或禁用的话题不能放入首页话题行。/ Hidden or disabled topics can't be added to the home topic row.（无占位符，写单个撇号）/ Topik yang disembunyikan atau nonaktif tidak bisa ditambahkan ke baris topik Sosial.
   - `admin.err.topics.notFound`：话题不存在。/ Topic not found. / Topik tidak ditemukan.
   - `admin.audit.action.TOPIC_CREATED / UPGRADED / UPDATED / HIDDEN / DISABLED / RESTORED / FEATURED / UNFEATURED / FEATURE_REORDERED`：新建话题 / 升级为官方话题 / 编辑话题 / 隐藏话题 / 禁用话题 / 恢复话题 / 放入首页话题行 / 移出首页话题行 / 调整首页话题行顺序（EN / ID 照同类审计显示名句式）。
2. **禁用时结束「生效排期」还是「全部未结束排期」**：架构 D-6 / epics 写「立即结束其生效排期」，PRD 写「已有的顶置随禁用一并失效」「恢复后不自动恢复」。若只结束生效中的那条，排期中的未来排期在恢复后会按时自动上线，违反「恢复不自动恢复」。本 story 按推荐**结束全部未结束排期**（生效中 + 排期中），与 `terminateByContent` 同一守卫；请确认。

4. **「隐藏 → 恢复」是否回到首页话题行**：PRD 只说隐藏 / 禁用自动移出；本 story 按推荐**不自动回到**首页话题行（与禁用恢复一致，需运营重新放入）。
