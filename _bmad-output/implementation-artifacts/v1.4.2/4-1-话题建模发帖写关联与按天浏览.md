**AC3 — 话题名规则唯一实现 `topic.domain.TopicNameRules` + 共用样例** `[L0]`（P-1、PRD §3.3「话题名规则」、epics 4.1 AC1）
1. 纯 Java、无 Spring 依赖。对外方法：
   - `List<TopicToken> parse(String text)`：返回正文中**所有**合法话题出现位置（`start` 含 `#`、`end`、`display` 原文写法、`norm` 标准名、`effective` 是否属于前 5 个不同话题），按出现顺序；
   - `List<TopicToken> effectiveDistinct(String text)`：前 5 个不同标准名（首次出现的那一处，`display` 取首次写法）；
   - `String normalize(String raw)`：`Normalizer.normalize(raw, NFC).toLowerCase(Locale.ROOT)`；
   - `boolean isValidName(String raw)`：供 6.1 后台新建 / 4.2 联想入参校验复用（不含 `#`）。
2. 规则（PRD 话题名规则 + 本 story 补全的边界，全部写进样例）：
   - 起点：ASCII `#`（U+0023）；**全角 `＃` 不算**；`#` 必须在行首或前一个字符**不是**话题字符（同 `MentionToken` 的「词首」口径：`abc#def` 不是话题、`(#kucing)` 是）。
   - 话题字符集 `[\p{L}\p{M}\p{Nd}_]`（Java `Pattern.UNICODE_CHARACTER_CLASS` 不需要，直接用 `\p{L}\p{M}\p{Nd}`）：字母（任何语言，含组合附标 `\p{M}`，否则天城文 / 泰文等会被附标截断）、十进制数字、下划线；**遇其他任何字符（空格、标点、emoji、`#`、`@`）即结束**。
   - 取 `#` 之后的**最长**话题字符串；其长度（**按 NFC 后的码点数**）不在 2–30 → 整段不是话题（**不截断**，31 字的串整段按普通文字）；全部为 `\p{Nd}` → 不是话题。
   - 同帖重复（标准名相同）只算 1 个、只占 1 个名额；所有出现处都是同一话题（`parse` 全部返回、`effective=true`）。
   - 前 5 个**不同**标准名有效；第 6 个起 `effective=false`（普通文字、不建话题）。**名额与话题在库里的状态无关**（命中 DISABLED 也占名额）——App 输入高亮无从得知状态，规则必须纯文本可判，前后端才能一致。
3. 共用样例 `petgo-backend/src/test/resources/fixtures/topic-parse-cases.json`（**本 story 新建，4.4 的 Dart 测试按相对路径读同一份**）：格式与初稿清单见 Dev Notes「共用样例初稿」，≥ 20 条，覆盖上面每一条边界。Java 测试 `TopicNameRulesFixtureTest` 逐条断言 `effectiveDistinct` 的 `display` / `norm` 列表与 `ranges`（UTF-16 下标，Java 与 Dart 字符串下标同为 UTF-16，可直接共用）。带 `"dartSkip": true` 的条目 Java 照跑。
4. **禁止在别处另写话题正则**（P-1）：`TopicService`、4.2 联想入参、6.1 后台校验一律调本类。

**AC4 — 发帖写关联 `topic.service.TopicService`** `[L1]`（D-2、epics 4.1 AC2 ~ AC4、PRD FR-69 AC1 / AC2 / AC5）
1. `List<AttachedTopic> attach(long postId, String text, ContentVisibility visibility)`，`AttachedTopic(long topicId, String name /*name_norm*/, boolean official, boolean created)`：
   - `visibility != PUBLIC` 或正文为空 → 直接返回空表：**不写关联、不新建话题**（私密 Diary 带话题，AC「私密不写」）。

   - 显示写法：新建时取本帖**首次出现**的写法；已存在的话题**一律不改** `name_display`（再发 `#kucinglucu` 进同一话题、显示写法不变）。

3. 话题写入失败**不吞**：与帖子同事务，失败整帖失败（不同于浏览统计的「丢了无所谓」——丢关联会让帖子永远不进话题页）。

### 实现提示

- **包结构（P-4）**：`com.tailtopia.topic.{domain, repository, service, web}`。本 story 建 `domain` / `repository` / `service`（`TopicService` 写、`TopicQueryService` 读——本 story 只实现 `topicNamesFor`，其余查询 4.2 补）。
- **Bean 依赖方向（防循环）**：`ContentService → TopicService`、`FeedService / ContentDetailService / ContentService(时间线) → TopicQueryService`；`TopicService` / `TopicQueryService` **不得**注入任何 content service（只用自己的 repository / `JdbcTemplate`，可读 `content_posts` 表）——§5.3「话题模块不反向依赖内容 service」。
- **`attach` 建议用 `JdbcTemplate`**：`INSERT … ON CONFLICT (name_norm) DO NOTHING` 的影响行数就是 `created`；随后 `SELECT id, type, status FROM topics WHERE name_norm = ?`。READ COMMITTED 下第二个并发事务会在唯一索引上等第一个提交，之后 `DO NOTHING` + 新语句能读到已提交行——这正是 D-2 要的并发安全。**不要**先 `findByNameNorm` 再 `save`（并发时第二个抛唯一约束异常、整帖失败）。
- **`topicNamesFor` SQL**：`SELECT ct.post_id, t.name_norm FROM content_topics ct JOIN topics t ON t.id = ct.topic_id WHERE ct.post_id IN (:ids) AND t.status IN ('ACTIVE','HIDDEN')`；空集合直接返回空 Map 不发查询。
- **`effective` 与 DISABLED**：规则层先取前 5 个不同标准名，**再**在 `attach` 里跳过 DISABLED。不要「跳过 DISABLED 后再补第 6 个」——App 高亮已按纯文本规则显示前 5 个，补位会让第 6 个在服务端生效、App 却显示普通色。
- **`ContentPostResponse.topics` 元素** `TopicRef(String name, boolean official, boolean created)`，放 `content/dto`（JSON：`{"name":"kucinglucu","official":false,"created":true}`）。
- **事件构造器**：record 规范构造器里 `topicIds = topicIds == null ? List.of() : List.copyOf(topicIds)`（同 `petIds` 写法）。
- **清理任务**放 `content/service`（与 `ContentViewStatsService` 同包），用 `JdbcTemplate` 或仓储 `@Modifying` 方法 + `@Transactional`；不需要 advisory lock（DELETE 幂等）。

### 架构约束（违反即返工）

- 迁移时间戳版本号、文件名用预分配的两个；已应用迁移冻结不改；`ddl-auto=validate`，schema 只归 Flyway；整数列 `INTEGER`，**不用 `SMALLINT`**。
- 对外不暴露 `topics.id`（只出标准名）；日志不记正文、话题名可记（非 PII，但不必记）、不记 viewerKey。
- 写库在发帖事务内同步完成，不引 MQ / 缓存 / 新中间件；浏览按天写入沿用 `@Async` + 吞异常。
- 时间：库内 `timestamptz` UTC；「按天」= WIB 日期（P-6）。
