## Story

As a 刚开始在社区互动的用户,
I want 第一次关注一个人、第一次收藏一条帖子被记为宠物的里程碑,
so that 社交行为也能带来成长激励。

### 触发与完成

**AC2 — 第一次手动关注一个人（多宠 + 只读）** `[L1]`（D-12、PRD AC1 / AC7）
Given 账号有 2 只 ACTIVE 宠物 + 1 只 READ_ONLY，When 第一次手动关注一个人（`FollowService.follow` 新建关注行 → `UserFollowedEvent`），Then：
- `user_milestone_flags` 写入 `(userId, FIRST_FOLLOW_USER)`；
- 两只 ACTIVE 宠物各写一条对应物种编码的 `milestone_completions`（`source = SYSTEM_AUTO`、`celebrated_at = NULL`）；READ_ONLY 宠物**不写**；
- 通知中心只 1 条 `MILESTONE_SM_NODE`（`sendWithoutPush`，不推送；`targetRef` 见 AC7；落库 title / body 用中性留痕文案，不含宠物名）；
- 成长值流水只 1 条 `MILESTONE_S` +5，幂等键 `MILESTONE_ACCT:{userId}:FIRST_FOLLOW_USER`；
- **不**发布按宠物的 `MilestoneCompletedEvent`（否则按宠物数重复通知、重复给分）。

**AC3 — 不触发的来源 / 自收藏触发** `[L1]`（PRD AC2 / AC3、G-7）
1. 系统自动关注官方号（`OfficialAutoFollowService` 写 `source=SYSTEM`，不发 `UserFollowedEvent`）→ 不触发。
2. 追更宠物（Epic 1 的 `PetFollowedEvent`）→ 不触发（本 story 不监听它）。
3. 收藏场所（`PlaceCollectService`，不发 `ContentCollectedEvent`）→ 不触发。
4. 收藏**自己的**帖子 → 触发「第一次收藏」（里程碑监听**不**跳过 `collectorId == authorId`；`GrowthActivityListener.onCollected` 的自收藏跳过逻辑不动）。

**AC4 — 只触发一次、不撤销** `[L1]`（PRD AC4）
Given 已完成，When 再关注别人 / 再收藏 / 取关后再关注 / 取消收藏后再收藏，Then 不再写完成、不再通知、不再给成长值（flag 主键冲突即整条路径 no-op）；取关、取消收藏不删 flag、不删完成行。

**AC5 — 触发时没有 ACTIVE 宠物；之后建宠 / 只读恢复** `[L1]`（G-3、PRD AC5 / AC9、FR-154.3）
1. Given 触发时账号 0 只宠物（或全部 READ_ONLY），Then 写 flag、成长值照发 +5（同 AC2 幂等键），**不写完成、不发通知**。
2. When 之后新建宠物（`ProfileService.create` → `assignRoster`），Then 该宠物这两个编码（账号已有 flag 的那几个）直接写完成且 `celebrated_at = completed_at`，**不发任何事件**（无通知、无成长值、无庆祝）。
3. When READ_ONLY 宠物被 `PetSlotStateService` 恢复为 ACTIVE（任何触发：租名额、升级、改选），Then 同上直接写「已完成且已庆祝」，不发事件。
4. 已完成两项的账号新建第 3 只宠物 → 新宠物两项直接已完成，无庆祝、无成长值（PRD AC5）。

**AC6 — 庆祝回报按账号** `[L1]`（D-12 末条、PRD AC10）
Given 某宠物经 `POST /api/v1/pet-profiles/me/milestones/celebrations?petId=` 回报的 codes 含这 6 个账号级编码之一，Then 账号下**所有宠物**（含 READ_ONLY，只要有完成行）对应同一 flag 的完成行一并置 `celebrated_at`（只置 NULL 的，不覆盖已有值）；其余 code 仍只置本宠物（原 AD-A2.3b 规则不变）。

**AC7 — 物种映射 / 混养通知载荷** `[L1]`（R-4、D-12）
1. OTHER 物种宠物完成的是 `G-S12` / `G-S13`。
2. 混养账号（如 1 猫 1 狗）：两只各完成本物种编码；通知只 1 条，`targetRef` = **账号下第一只 ACTIVE 宠物**（`findAllByOwnerIdOrderByCreatedAtAscIdAsc` 中首个 ACTIVE）物种对应的编码（猫在前 → `C-S19`）。

**AC8 — 并发** `[L1]`
并发两次关注不同的人（两个 `UserFollowedEvent` 同时被异步消费）→ 只触发一次（flag `INSERT … ON CONFLICT DO NOTHING` 返回 1 的那条才继续）：完成行每宠 1 条、通知 1 条、成长值 1 条。

**AC9 — 回归** `[L1]`
原有按宠物里程碑（自动 / 打卡 / 计数 / 组合 / Lulus Pemula）行为不变；`GrowthActivityListener.onMilestone` 的「同账号同 code 最多 5 次」规则对其他编码不变；`MilestoneAnalyticsListener` 对按宠物事件不变。

**AC10 — 注销清理** `[L1]`（根 CLAUDE.md 护栏「注销级联删除 / 匿名化」）
账号注销 `AccountDeletionService.execute` 显式删除该用户全部 `user_milestone_flags` 行（users 行是匿名化不删，FK CASCADE 在注销路径上永不触发）。

### 拍板点（按推荐实现，Completion Notes 复述）

1. **成长值 refId = flagKey**（`FIRST_FOLLOW_USER`），refType 仍 `MILESTONE`：账号级与物种无关，用 flagKey 比挑某个物种的 code 更准确；5 次上限按 refId 计数，不会与其他编码互相影响。后台流水 `KNOWN_REF_TYPES` 已含 `MILESTONE`，refId 原样显示。
2. **埋点 `milestone_achieved`**：账号级按「去重后的物种编码」各报一次（1 猫 1 狗 → `C-S19`、`D-S19` 两条；2 猫 → 1 条）。理由：保留「新编码自动覆盖」，又不按宠物数放大。若产品要「每账号只 1 条」，改成只报 `targetCode` 即可。
3. **注销删 flag**：flag 不含 PII，但属用户行为数据，按 D1/D2「级联删除 / 匿名化」一并删。
4. **触发路径加 `PetSlotLock`**：与建档 / reconcile 串行，避免「触发时新宠物刚建、两边都没写」的窗口。锁要求在事务内（`PetSlotStateService.lockAccount` 是 MANDATORY，`PetSlotLock.lockUser` 同理），所以放在 `REQUIRES_NEW` 方法体内第一步。

  ```java
  lock.lockUser(userId);
  if (flags.insertIfAbsent(userId, flag.name()) == 0) return;          // AC4 / AC8
  List<PetProfile> active = profiles.findAllByOwnerIdOrderByCreatedAtAscIdAsc(userId).stream()
          .filter(p -> p.getStatus() != PetStatus.READ_ONLY).toList();
  List<Long> petIds = new ArrayList<>(); List<String> codes = new ArrayList<>();
  for (PetProfile p : active) {
      String code = MilestoneAutoCompleteMap.codeOf(p.getPetType(), flag.event());
      milestones.findByPetProfileIdAndCode(p.getId(), code).ifPresent(m -> {

              petIds.add(p.getId()); codes.add(code);
          }
      });

  String target = active.isEmpty() ? null : MilestoneAutoCompleteMap.codeOf(active.get(0).getPetType(), flag.event());

  ```
