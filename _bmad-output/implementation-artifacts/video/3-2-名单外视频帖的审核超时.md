# Story 3.2：名单外视频帖的审核超时

Status: review

> 专题线 video · Epic 3 · 只改后端。分支 `feat/video`。依赖 1.3（`review_reason=VIDEO_FORCED` 与无条件入队）、3.1（审核通过 / 拒绝的 Controller 即时对账）。
> 权威顺序：决策日志-video.md > PRD-video.md > architecture-video-delta.md > epics-video.md。

## Story

As a 平台，
I want 没人处理的名单外视频帖在 3 天后自动丢弃，
so that 它们不会一直挂在「审核中」。

**范围**：FR-10（超时部分）；架构 AD-5（超时扫描条件）；决策 V-37（沿用 3 天时限）。

## Acceptance Criteria

1. **总开关关闭也超时【L0 + L1】** 人工审核总开关**关闭**时，`review_reason=VIDEO_FORCED` 的视频帖在队列里超过 3 天 → `scanTimeouts` 照常丢弃（`discardReview`），作者收到现有的超时通知，审计照写，desired=PRIVATE。
2. **其他帖子不受影响【L0 + L1】** 总开关关闭时，其他（非 VIDEO_FORCED）帖子仍按现有逻辑**不**被超时丢弃；总开关打开时行为与现在一致。
3. **审核通过 / 拒绝【L1】** 运营通过一条 VIDEO_FORCED 视频帖 → desired=PUBLIC 并在 Controller 层立即对账（3.1 已接入）；拒绝 → desired=PRIVATE。

## Tasks / Subtasks

- [x] **T1** `ContentService.isVideoForcedReview(long postId)`（只读：帖子存在且 `review_reason=VIDEO_FORCED`）。
- [x] **T2** `ManualReviewService.scanTimeouts`：帖子分支条件改为 `postGateEnabled || contentService.isVideoForcedReview(postId)`（AD-5 原文 `postGateEnabled || review_reason=VIDEO_FORCED`）。
- [x] **T3 测试**：L0 `ManualReviewServiceTest`（或新建）：开关关 + VIDEO_FORCED 超时 → 丢弃 + 通知 + 审计；开关关 + 普通帖 → 不动；开关开 → 都处理。L1 `VideoForcedReviewTimeoutIntegrationTest`：开关关、提交时间拨到 4 天前 → `scanTimeouts` 丢弃视频帖、desired=PRIVATE、通知存在；同库普通挂起帖不动；审核通过 → desired=PUBLIC。
- [x] **T4 收尾**：`mvn -B clean package`（云端 `-DskipTests` + 纯单元测试）。本 Story 无迁移。
