# Story 1.4：视频文件公开对账（发布路径）

Status: review

> 专题线 video · Epic 1 · 只改后端。分支 `feat/video`。依赖 1.3（`content_posts` 的 `media_acl_*` 列、`ContentPost.desiredOf`、`mediaAclApplied` 不可由实体更新）。
> 权威顺序：决策日志-video.md > PRD-video.md > architecture-video-delta.md > epics-video.md。

## Story

As a 官方号，
I want 视频帖发布后，视频和封面马上就能被别人看到，
so that 发布成功后去推荐流里能看到正常的封面和视频。

**范围**：FR-10、FR-17（发布部分）；架构 AD-6 对账器、AD-8 `VideoUrlResolver` 基础、AD-11 Noop 刷新器与开关；一致性规则 1。
**不在范围**：下架 / 恢复 / 审核通过等入口的即时对账与 L1 全覆盖 → 3.1；DTO 用 `VideoUrlResolver` 下发地址 → 2.1；后台预览 → 3.3；CDN 真实接入与 L2 → 3.4（本 Story 只写 `AliyunCdnCacheRefresher` 的实现与装配，不做 L2）。

## Acceptance Criteria

1. **定时对账【L0 + L1】** `MediaAclReconciler` 按 `media.video.acl-reconcile-cron`（默认每分钟）运行：
   - 每批最多 100 条 `media_type='VIDEO' AND media_acl_desired <> media_acl_applied`（按 id 升序，命中 1.3 的部分索引）；
   - 每条依次：设置**视频对象** ACL → 设置**封面对象** ACL → `CdnCacheRefresher.refresh(视频公开地址)` → **条件单列 UPDATE** 回写 applied：`UPDATE content_posts SET media_acl_applied = :v WHERE id = :id AND media_acl_desired = :v`；
   - 影响 0 行（回写前 desired 已被并发改掉）→ 本条留到下一轮，不报错；
   - 单条失败（OSS / CDN 异常）只记 WARN，不影响同批其他帖子，下一轮重试；
   - 视频或封面对象 404（或封面 URL 反解不出 key）→ 打 ERROR `video_acl_object_missing postId=…`，并把 applied **强制写成 desired**（同样走条件 UPDATE），不再无限重试；
   - PUBLIC 和 PRIVATE 两个方向都刷 CDN（避免 CDN 缓存了 403 或旧内容）。

2. **卡住告警【L0】** 处理完一条后若仍不一致，且 `now - media_acl_desired_at > 5 分钟` → 打 ERROR，消息以 `video_acl_reconcile_stuck` 开头，带 `postId`、`desired`、卡住秒数。日志里**不出现签名 URL、AK、对象完整 URL**（只记 postId）。

3. **发布后即时对账【L1】** 名单内账号发布视频帖成功后，`ContentApiController` 在 `contentService.publish(…)` **返回之后（事务已提交、事务外）** 调 `reconcileOne(postId)`：
   - 成功 → 视频和封面 ACL 为 public-read，`media_acl_applied=PUBLIC`；
   - 失败（任何异常）→ 只记 WARN，**发布接口照常返回 201**，由定时任务兜底；
   - 名单外（UNDER_REVIEW、desired=PRIVATE=applied）→ `reconcileOne` 无事可做，不调 OSS。

4. **CDN 开关【L0】** `media.video.cdn-base-url`：
   - 空字符串（yml `${MEDIA_VIDEO_CDN_BASE_URL:}`）或空白 → 装配 `NoopCdnCacheRefresher`；有值 → 装配 `AliyunCdnCacheRefresher`；
   - 判断写在 `MediaConfig` 的 `@Bean` 方法里，用 `StringUtils.hasText`，**不用 `@ConditionalOnProperty`**（空串也会被它当成「有」）；
   - 有一条测试专门覆盖「空串 → Noop」。

5. **`VideoUrlResolver`【L0】**（Epic 2 / 3 都会用，这里先建好）：
   - `publicUrl(post)`：有 CDN 用 `media.video.cdn-base-url` + `/` + 对象 key，否则用 OSS 源站（`AliyunOssClient.publicUrl(key)`，即 `media.oss.cdn-base-url`）；
   - `signedUrl(post, ttl)`：签名 GET，桶 = `media.oss.public-bucket`；
   - `signedTtl(post)` = max(15 分钟, 时长 × 3)；`forAdmin(post)` = `signedUrl(post, signedTtl(post))`；
   - `SignedUrlService` 新增 `sign(String bucket, String key, Duration ttl)` 重载（无凭证时走现有打桩逻辑）；
   - 日志里不打印签名 URL。
   - 非视频帖调用 → `IllegalArgumentException`（调用方必须先判 `mediaType`，一致性规则 5）。

6. **测试环境不自动跑【L1】** `ApiIntegrationTest` 基类属性加 `media.video.acl-reconcile-cron=-`（`Scheduled.CRON_DISABLED`），对账逻辑由测试直接调用验证 —— 否则定时任务会在套件中途去改共享库里其他测试造的视频帖。

7. **真实 OSS【L2：stag，留给验收】** RAM 用户追加 `oss:PutObjectAcl` / `oss:GetObjectAcl` 后，在 stag 发布一条名单内视频帖：1 分钟内（通常立刻）可以匿名访问视频和封面的源站地址。

### 设计取舍（照做）

- **为什么回写用条件单列 UPDATE**：对账是「读 desired → 改 OSS → 写 applied」，中间几百毫秒里 desired 可能被下架改掉。`WHERE desired = :v` 保证只有「我刚应用的就是当前期望」时才算完成，否则下一轮重做。整行 `save()` 会把别人刚写的 desired 也写回旧值，所以禁止。
- **为什么对象 404 要强制收敛**：F21 下文件不会被删，404 只可能是上传没完成或数据异常；无限重试只会每分钟刷 ERROR。收敛后由 ERROR 日志通知人工处理。
- **为什么即时对账在 Controller**：发布事务已提交，查得到新行；放在事务里会让 OSS 网络调用占着数据库连接（一致性规则 7）；用 `AFTER_COMMIT` 监听器写库是项目明令禁止的（曾出过事务吞写事故）。
- **为什么 Noop 刷新器不需要做任何事**：没有 CDN 时客户端直连 OSS 源站，ACL 一改立即生效（NFR-6）。

### 日志规范

- 一律只记 `postId`、`desired`、异常类名；**不记**对象 URL、签名 URL、AK。告警走日志（项目约定，不发 App 通知）。
- 事件名前缀：`video_acl_reconcile_stuck`（ERROR）、`video_acl_object_missing`（ERROR）、`video_acl_reconcile_failed`（WARN，单条失败）、`video_acl_reconcile_inline_failed`（WARN，Controller 即时对账失败）。
