# Story 1.1：后台设置会员等级与视频免审名单

Status: done

## Story

As a 有权限的运营，
I want 在后台把官方号设为会员等级 10 并加入视频免审名单，
so that 官方号获得发视频的权限，发出的视频直接公开。

**范围**：只改后端和后台。本 Story **不改 App**：App 端读取 `vipLevel` 放在 Story 1.5。
**需求来源**：FR-1、FR-2、FR-3（接口部分）、FR-22；架构 AD-2（vip_level 与名单表）、AD-12（等级与名单）。

## Acceptance Criteria

1. **迁移【L1】**
   - 迁移执行后，存量用户和新注册用户的 `users.vip_level` 都是 1。
   - 列类型为 `INTEGER NOT NULL DEFAULT 1`，约束为 `CHECK (vip_level BETWEEN 1 AND 99)`，约束名 `ck_users_vip_level`。
   - 新表 `video_trusted_publishers` 已存在：`user_id BIGINT PRIMARY KEY REFERENCES users(id) ON DELETE CASCADE`、`created_by_admin_id BIGINT NOT NULL`、`created_at TIMESTAMPTZ NOT NULL DEFAULT now()`。

2. **设置等级【L1】**
   - 持有 `user.vip_level.edit` 的后台账号在用户抽屉把等级改为 10，保存成功。
   - 审计日志记录：操作人、targetType=`USER`、targetId=用户 id，摘要为 `vip_level 1→10`。
   - 提交 0、100 或非数字时，返回校验错误，等级不变。
   - 已注销的账号拒绝修改，沿用 `AdminUserService` 现有的拦截方式。

3. **等级权限【L1】**
   - 没有 `user.vip_level.edit` 的账号，在抽屉里只能看到禁用按钮和权限提示，没有可提交的表单。
   - 这类账号直接 POST 该接口，返回 403。

4. **加入 / 移出名单【L1】**
   - 持有 `video.trusted.manage` 的后台账号，可以在用户抽屉把用户加入或移出视频免审名单。
   - 名单表同步变化；每次操作都写审计日志（加入、移出各有一个动作码）。
   - 重复加入、移出不在名单中的用户：都是幂等操作，返回明确提示，不报 500。

5. **名单列表页【L1】**
   - `/admin/video-trusted` 列出名单中的账号，每行显示：昵称、用户 id、会员等级、加入人、加入时间。
   - 按加入时间倒序，分页每页 20 条。
   - 没有 `video.trusted.manage` 时返回 403；侧栏只对有权限的账号显示这一项。

6. **默认不授予【L0】**
   - 两个新权限码已加入 `AdminPermissions`，并登记到 `AdminPageCatalog`。
   - 默认**不分配给任何角色**：不写权限迁移，也不加入 `AdminRole.OPS_MANAGER`。
   - 现有的权限一致性测试全部通过（总数从 78 改为 80）。

7. **`/me` 返回等级【L1】**
   - 登录用户请求 `GET /api/v1/me`，响应包含 `vipLevel`（整数）。
   - 登录响应里的用户资料同样包含 `vipLevel`，因为两处走同一个工厂。

8. **不丢失更新【L1】**
   - 后台改完等级后，用户自己调用会整行保存 User 的接口（例如 `PATCH /me` 改昵称），`vip_level` 不会被写回旧值。

## Dev Notes

### 关键约束（违反就要返工）

- **不能丢失更新**：User 没有 `@DynamicUpdate`，`vipLevel` 必须是只读映射，改等级用定向 UPDATE（T2）。这是本 Story 最容易出错的地方。
- **两个点的权限码**：门控要拼接常量，否则接线测试会把它判成死码（T4）。
- **默认不授予**：不写权限迁移，不改 OPS_MANAGER（T4）。
- **模块边界**：admin 不直接读写 users，要经过 auth 的 service；content 通过只读端口 `VideoTrustedPublisherService` 读名单（架构「边界」一节）。
- **免审只看名单**：以后判断免审只查 `video_trusted_publishers`，**不要**用 `isOfficialAccount` 或 `role`。1.3.4 的「官方号」是 `role=ADMIN` 的后台作者账号，不登录 App，和这里的官方号不是一回事（决策 V-25、V-35）。
- **会员等级只能由运营在后台设置**，用户没有任何途径自己获得。等级 ≥ 10 但不在名单里的账号，发视频要走人工审核，由 Story 1.3 实现。
