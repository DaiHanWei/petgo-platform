# Story 2.1：帖子接口下发视频信息与签名地址

Status: review

> 专题线 video · Epic 2 · 只改后端。分支 `feat/video`。依赖 1.3（`content_posts` 视频列、`MediaType`）、1.4（`VideoUrlResolver`、`SignedUrlService.sign(bucket,key,ttl)`）。
> 权威顺序：决策日志-video.md > PRD-video.md > architecture-video-delta.md > epics-video.md。

## Story

As a 新版 App，
I want 帖子接口告诉我哪条是视频帖、视频地址是什么，
so that 我能区分视频帖并播放。

**范围**：FR-14、FR-15（数据部分）；架构 AD-8、AD-11（地址拼接）；一致性规则 4、5。
**不在范围**：能力声明与旧版过滤（2.2 —— 本 Story 不判断 `X-App-Capabilities`，旧版过滤由 2.2 在查询里做）；App 解析（2.3）；后台预览（3.3）；CDN 真实接入（3.4）。

## Acceptance Criteria

1. **DTO 新增字段【L0 + L1】** 以下出口增加 `mediaType`（恒下发，`IMAGE` / `VIDEO`）与 `video{url,durationMs,width,height}`（只在视频帖出现，NON_NULL）：
   - `FeedItemResponse.of()`（推荐流、分类 Tab、关注流、他人主页、我的发布、顶置坑位共用）；
   - `ContentDetailResponse` 的 2 个 `of()`；
   - `SharedPostResponse`：**新增 `of()` 工厂**，`ContentShareService.project` 改为调用它（不再直接 `new`）；
   - `ContentPostResponse.from()`：只加 `mediaType`（发布接口回显用；架构「结构」节只要求 `+ mediaType`，发布回显不需要可播放地址）。
2. **图文帖不变【L0】** 图文帖 `mediaType=IMAGE`，不下发 `video`；其余字段（`imageUrls`、`firstImageUrl`、`imageSizes`…）与改动前**逐字节一致**（契约测试覆盖）。
3. **公开视频帖的地址【L0 + L1】** 视频帖对外：`video.url = VideoUrlResolver.publicUrl(post)`（配了 `media.video.cdn-base-url` 用 CDN，否则 OSS 源站 + 对象 key）；`imageUrls[0]` / `firstImageUrl` 就是库里的封面地址；`video.width/height` 为显示宽高，`durationMs` 为毫秒。
4. **作者看 PRIVATE 状态的视频帖用签名地址【L0 + L1】** 当 **查看者是作者本人** 且帖子文件尚未公开（`media_acl_desired=PRIVATE` 或 `media_acl_applied=PRIVATE`：审核中、预处置中、ACL 还没生效）：`video.url`、`imageUrls[0]`、`firstImageUrl` 都换成签名 URL（桶 = `media.oss.public-bucket`），有效期 `VideoUrlResolver.signedTtl(post)` = max(15 分钟, 时长 × 3)。封面 key 反解不出时封面保持原地址（不抛错）。
   - 其他人请求这条帖子：按现有可见性规则（审核中他人本来就看不到；ACL 尚未生效的已发布帖给公开地址，对账器 1 分钟内兜底）。
5. **单一组装点【L0 评审项】** `mediaType` / `video` / 签名替换只在 DTO 工厂里组装：服务层先算出一个 `PostMedia`（媒体投影）再传给 `of()`；不在各服务里各自拼。签名 URL 不进任何日志。

## Dev Notes

### 必须保留

- **图文帖字段零变化**：`firstImageUrl` 老客户端在读，`imageUrls` / `imageSizes` / `imageCropOffsets` 不动；只新增 `mediaType`、`video`。
- **App 用 `mediaType` 判断视频帖**，`video` 只在视频帖出现（NON_NULL）。
- **签名只给作者本人**；分享页（匿名）、他人一律公开地址。签名 URL 不进日志（NFR-4）。
- **一致性规则 4**：`mediaType` / `video` 只在 DTO 工厂组装（经 `PostMedia`）。
- 本 Story **不做**能力过滤（2.2），服务方法签名不加 `includeVideo`。

### 现状（已读过）

- `FeedItemResponse.of` 被 `FeedService` 4 处调用（`assemble`、`loadPinnedSlot`、`userPublicPosts`、`myPosts`）；关注流也走 `assemble`。
- `ContentDetailResponse.of` 被 `ContentDetailService.getDetail` 调用（12 参版本）。
- `SharedPostResponse` 在 `ContentShareService.project` 里直接 `new`；投影刻意无 postId / authorId（AD-15 Rule 5），本 Story 不加 id。
- `ContentPostResponse.from` 被 `ContentService` 发布路径 6 处调用。
- `VideoUrlResolver`（1.4）：`publicUrl`、`signedUrl(post, ttl)`、`signedTtl`、`forAdmin`、`coverObjectKey`；非视频帖抛 IAE。
- 契约测试 `FeedResponseContractTest` / `ContentDetailAndCommentContractTest` 用 `new` 构造 record，并要求同步 App `feed_item.dart` / `content_detail.dart` 与 `core/mock/mock_backend.dart`（若存在）—— App 侧解析由 2.3 做，本 Story 只更新后端契约测试并在注释里指向 2.3。
