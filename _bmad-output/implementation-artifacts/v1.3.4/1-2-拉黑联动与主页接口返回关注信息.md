# Story 1.2: 拉黑联动与主页接口返回关注信息

Status: ready-for-dev

> 版本 v1.3.4 · 主题 follow · 分支 `feat/1.3.4-follow-notify`
> 口径优先级：`决策日志-follow.md` > `PRD-v1.3.4-follow.md` > `architecture-v1.3.4-follow-delta.md` > `ui-v1.3.4-follow.html`（均在 `_bmad-output/planning-artifacts/v1.3.4/`）
> 依赖：Story 1.1（`user_follows`、`users.public_token` / 两计数列、`FollowService`、`FollowReader`、`FollowCounterService`）。

## Story

As a 用户,
I want 主页显示关注 / 粉丝数与我们的关注关系，拉黑某人时我对他的关注自动取消,
so that 我能看到彼此关系，拉黑后也不会继续关注对方。

## Acceptance Criteria

**AC1 — 拉黑联动取关** `[L1]`（AD-5，FR-140.13）
1. `UserHideRelationService.block(holderId, targetId)` 在插入 `BLOCK` 行的**同一事务**里调用 `FollowService.removeOnBlock(holderId, targetId)`：删除 `holder → target` 关注行，**仅当删除行数 = 1** 时 `holder.following_count − 1`、`target.follower_count − 1`（走 Story 1.1 的 `FollowCounterService.applyUnfollow`）。
2. `target → holder` 的关注**保留不动**、计数不变。
3. **不发任何通知、推送、事件**（PRD AC6 / AC9）。不得复用会发事件的方法。
4. 重复拉黑（`BLOCK` 行已存在）照常执行一次删除——删 0 行即无副作用，幂等。
5. `unblock` **不恢复**关注；`hideByReport`（`REPORT` 来源）**不触碰**关注。
6. 任一步失败整体回滚（拉黑和取关要么都成要么都不成）。

**AC2 — 他人主页 `GET /api/v1/users/{userId}/profile` 新字段** `[L0]` `[L1]`（AD-6）
1. `PublicProfileResponse` 在现有字段**之后**追加：`String userToken`、`long followingCount`、`long followerCount`、`boolean iFollow`、`boolean followsMe`。
   - `userToken` = 目标 `users.public_token`；
   - 两计数 = 目标 `users.following_count` / `follower_count`（冗余列直读，不实时 count）；
   - `iFollow` / `followsMe` = `FollowReader.followState(viewerId, userId)`；**游客、兽医 token（按游客处理）、本人视角**一律 `false`，且**不调用** `FollowReader`。
2. `PublicProfileResponse.of(...)` 增参；`deactivated()` 里 `userToken = null`（NON_NULL 省略该键）、两计数 0、两布尔 false。
3. JSON 键名必须是 `userToken` / `followingCount` / `followerCount` / `iFollow` / `followsMe`（record 组件名即键名；端点测试断言一次，防序列化命名漂移）。
4. 目标 User 只加载一次：现有 `accounts.findUserById(userId)`（`PublicProfileController.java:95`，取 `joinedAt`）的同一个对象里取 token 与两计数，不新增查询。

**AC3 — 被拉黑方视角：计数真实** `[L1]`（PRD「拉黑与关注」，UI 稿 A7）
1. B 被 A 拉黑、B 看 A 的主页：`postCount` / `likeCount` 仍为 0（现有伪装，`PublicProfileController.java:103-112` 不动）；**`followingCount` / `followerCount` 为真实值**；B 仍关注 A 时 `iFollow = true`；`followsMe` 按真实关系（A 拉黑 B 时 A→B 已被 AC1 删除，故为 `false`）。
2. 不新增任何「被拉黑」标识字段（FR-118.5 原则：服务端不下发拉黑态）。

**AC4 — 封号按已注销处理** `[L1]`（PRD AC11，FR-140.15）
1. 目标 `status = DEACTIVATED`（封号）时返回 `PublicProfileResponse.deactivated()`，与已注销 / 不存在同一出口（现有 `author.deleted()` 分支，`PublicProfileController.java:89-92`）。判据用 `AccountQueryService.isActive(userId)`（未注销 + ACTIVE），并更新 `isActive` 的 javadoc：它「只服务 H5 分享页」「唯二调用方」的说法已不成立，补上本调用方与理由。
2. 拉黑守卫顺序不变：我拉黑了对方 → 仍先 403 `blocked-user`（`:77-79`），再判注销 / 封号。
3. 重新激活后主页恢复（封号可逆，与 `isActive` 现有语义一致）。

**AC5 — `/api/v1/me` 新字段** `[L0]` `[L1]`（AD-6，D-5）
1. `UserProfileResponse` 追加：`String userToken`、`Long postCount`、`Long likeCount`、`int followingCount`、`int followerCount`；`email` 字段**保留**（App 不再展示，接口不删）。
2. `postCount` / `likeCount` **按我的全部帖子**（D-5），口径与「我的发布」网格**同一谓词**（`ContentPostRepository.findMyPosts`，`:427-444`）：`author_id = me AND deleted_at IS NULL AND status IN (PUBLISHED, UNDER_REVIEW)`，**不过滤 visibility**（含私密 / 仅自己可见）。即：
   - 计入：已发布的公开帖、已发布的私密帖、本人待审帖（`UNDER_REVIEW`）；
   - 不计：已删除 / 审核拒绝（软删 `deleted_at`）、`AUTHOR_DEACTIVATED`。
   - `likeCount` = 上述帖子集合收到的 `content_likes` 行数之和。
3. 新增 `ContentService.countOwnPostsByAuthor(long)` 与 `ContentService.sumLikesOnOwnPostsByAuthor(long)`，各一条 SQL（照 `countPublicPublishedByAuthor` / `sumLikesOnPublicPostsByAuthor` 的写法，仓储方法分别放 `ContentPostRepository` / `ContentLikeRepository`），javadoc 写明「作者自视口径，与 `findMyPosts` 同源；他人视角一律用 `*Public*` 那两个」。**不改**现有两个 Public 方法。
4. 计算位置：`MeService.getMe` 与 `MeService.updateMe`（PATCH 响应）都带全部五个字段——PATCH 的响应若缺计数，App 用它覆盖本地状态时四格会被清空。登录响应（`AuthService.java:128` / `:160` 内嵌的 `UserProfileResponse.from`）**不查帖子统计**：`postCount` / `likeCount` 传 `null`（NON_NULL 省略），`userToken` 与两关注计数照常带（实体直读，零额外查询）。
5. `UserProfileResponse.from(User, boolean)` 保留给登录用（统计为 null），新增 `from(User, boolean, long postCount, long likeCount)` 给 `/me` 用。

**AC6 — 注释与测试** `[L0]` `[L1]`（AD-15）
1. `FeedService.java:35` 类注释「无算法、无关注、无缓存」改为说明「关注关系不影响 Feed 排序与候选（V1.3.4 FR-140.20，不做关注 Feed）」，其余描述不动。
2. `PublicProfileControllerTest`（单测，`auth/web/PublicProfileControllerTest.java`，构造器在 `:53`）：构造器加 `FollowReader` mock；新增用例：
   - 登录看他人：五个新字段正确；
   - 游客 / 兽医：两布尔 false，`verify(followReader, never())`；本人视角两布尔 false、不查；
   - 被拉黑方视角：帖子 / 获赞 0、关注 / 粉丝真实、`iFollow` 真实；
   - 封号用户 → `isDeactivated = true`、无 `userToken`、无任何身份字段；
   - 既有用例全部保持通过（尤其 `anUnknownIdIsIndistinguishableFromADeactivatedUser`、`blockedTargetThrows403AndTouchesNoProfileData`、`guestNeverConsultsHideRelationsAndGetsNoReportedKey`）。
3. `social/UserHideRelationIntegrationTest` 新增：A 关注 B、B 关注 A → A 拉黑 B → A→B 消失、B→A 仍在、A.following −1、B.follower −1、B.following 与 A.follower 不变；B 的 `notifications` 行数不变；解除拉黑后 A→B 不恢复；A 举报 B（`hideByReport`）后 A→B 仍在；重复拉黑计数不再变。
4. 端点级断言 JSON 键（任选新建 `auth/web/PublicProfileFollowFieldsIntegrationTest extends ApiIntegrationTest` 或并入上面集成测试）：`$.userToken`（32 位）、`$.followerCount`、`$.iFollow`、`$.followsMe`；游客请求时 `$.iFollow == false`。
5. `auth/web/MeControllerEndpointTest`：`$.userToken`、`$.followingCount`、`$.followerCount` 存在；`postCount` 计入公开 + 私密 + 待审、不计删除帖；`likeCount` 含私密帖上的赞；PATCH `/me` 响应同样带这五个字段。
6. `auth/service/MeServiceTest`（mock 构造，`:44` 起）按新依赖（`ContentService`）更新。
7. `mvn -B clean package` 绿（L0）。

## Dev Notes

### 现状（改动前必读）

- **拉黑写入**：`UserHideRelationService.block`（`social/service/UserHideRelationService.java:39-46`）：`requireNotSelf` → `requireUserExists`（注销用户行仍在，照常可拉黑）→ `insertIfAbsent(BLOCK)`（native `ON CONFLICT DO NOTHING`）。`unblock`（`:52-55`）只删 BLOCK 行；`hideByReport`（`:68-72`）由 moderation 在举报事务内调用。入口 `MeBlockedUsersController`（`POST /api/v1/me/blocked-users`，body `targetUserId` 数字 id，`social/web/MeBlockedUsersController.java:53-57`）。本 story 不改接口形状。
- **他人主页**：`PublicProfileController.profile`（`auth/web/PublicProfileController.java:71-115`）：
  - `:77` 我拉黑对方 → 403 `blocked-user`（只认 BLOCK）；
  - `:87-92` `findAuthorViews` 补齐匿名投影，`deleted()` → `deactivated()`（注销与不存在刻意合流）；**只看注销，不看封号**（AD §0：封号目前显示正常主页）；
  - `:95` `findUserById` 取 `joinedAt`；
  - `:103` `hiddenByOwner = isBlocked(userId, viewerId)` → `:110-112` 两计数归零（伪装，必须保持）；
  - `viewerId()`（`:159-169`）只认 `role=USER`，兽医 / 游客为 null。
- **`PublicProfileResponse`**（`auth/dto/PublicProfileResponse.java:41-77`）：record，全局 Jackson NON_NULL；`reported` 刻意用装箱 `Boolean` 让游客键集合不变。本 story 两个关注布尔按 epics 用 primitive `false`（游客也出现该键），与 `reported` 不同，属有意差异（App 需要两布尔恒有值以决定按钮三态）。
- **`MiniProfileController`**（`/mini-profile`）也算帖子数，但 App 已零引用；本 story 不动。
- **`AccountQueryService.isActive`**（`auth/service/AccountQueryService.java:58-63`）= 未注销 + `status = ACTIVE`，javadoc（`:41-57`）声明只服务 H5 分享页。
- **`/me`**：`MeController`（`GET`/`PATCH /api/v1/me`）→ `MeService.getMe`（`auth/service/MeService.java:42-44`）/ `updateMe`（`:137`）→ `UserProfileResponse.from(User, boolean)`（`auth/dto/UserProfileResponse.java:46-62`）。同一工厂还被登录响应用（`AuthService.java:128`、`:160`）。当前无帖子数 / 获赞数 / token。
- **帖子统计现有两个方法都是他人视角**：`ContentService.countPublicPostsByAuthor`（`content/service/ContentService.java:185`，`PUBLISHED + PUBLIC + 未软删`）、`sumLikesOnPublicPostsByAuthor`（`:197`，`ContentLikeRepository.java:35-45`）。其 javadoc 明确「作者自视走 `findMyPosts`，刻意不过滤 visibility」。
- **「我的发布」网格谓词**：`ContentPostRepository.findMyPosts`（`content/repository/ContentPostRepository.java:427-444`）= `deletedAt IS NULL AND status IN (PUBLISHED, UNDER_REVIEW)`，无 visibility 过滤；`FeedService.myPosts`（`content/service/FeedService.java:485`）调用。`PostStatus`（`content/domain/PostStatus.java`）三值：`PUBLISHED` / `UNDER_REVIEW` / `AUTHOR_DEACTIVATED`；审核拒绝 = 软删。
- **`FeedService.java:35`** 类注释写「无算法、无关注、无缓存」。

### 架构约束

- AD-5：拉黑同事务删 holder→target、扣计数；target→holder 保留；不发通知；解除不恢复；REPORT 不影响。
- AD-6：主页 / `/me` 字段名按约定（`userToken` / `followingCount` / `followerCount` / `iFollow` / `followsMe`；`/me` 另加 `postCount` / `likeCount`）；被拉黑方看拉黑者计数真实；封号按已注销。
- D-5：我的页四格按全部帖子；他人主页（含别人看我）仍只数 PUBLIC —— 两套方法不得互相替代。
- 模块边界：`auth` 只依赖 `social.read.FollowReader`（与 `UserHideRelationReader` 同模式），不引 `social.repository`；`MeService` 经 `ContentService` 取统计，不直读 content 仓储。
- 不暴露拉黑：不新增任何能让被拉黑方推断出被拉黑的字段或差异（NFR2）。

### 本 story 不做

- 不改 Feed / 详情接口（`authorToken` / `authorFollowState` 属 Story 2.1）。
- 不做关注列表 / 推荐接口（Story 2.2 / 2.3）；不做 App 页面（Story 1.3 / 1.4）。
- 不改 `/users/{userId}/posts`、`/users/{userId}/pet` 对封号用户的行为（见待确认）。
- 不删 `/me` 的 `email` 字段。
