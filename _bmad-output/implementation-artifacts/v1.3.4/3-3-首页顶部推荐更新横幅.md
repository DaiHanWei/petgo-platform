# Story 3.3: 首页顶部推荐更新横幅

Status: review

## Story

As a 使用旧版本的用户,
I want 有新版本时首页顶部出现一行不打扰的提醒，可以关掉,
so that 我知道有新版本、又不被弹窗打断看内容。

> 范围：**纯 App**。依赖 3.2 交付的 `appUpdateControllerProvider`（`AppUpdateState.bannerVisible`、`recordSkip()`、`markBannerShownReported()`、`storeUrlForPlatform`）与 `app_update_presenter.dart` 的 `storeLauncherProvider`、`app_update_icons.dart` 的 `kUpdatePhoneSvgBanner`。无后端改动、无新增文案。

## Acceptance Criteria

**AC1 — 出现条件与位置** `[L0]` `[L2]`
1. 横幅显示 ⇔ `ref.watch(appUpdateControllerProvider).bannerVisible == true`（3.2 AC5.3 公式：本平台判定为推荐 `minSupported ≤ 当前 < 本平台最新`、本平台商店链接非空、不在 72 小时冷却期内）。不满足 → 渲染 `SizedBox.shrink()`，首页与现状逐像素一致（不留占位）。
2. 位置：首页（Social，`HomePage`）滚动头部 `_BerandaTop` 最上方、`PlaceEntryRow` **之前**（`home_page.dart` L312 `const SizedBox(height: 8)` 与 L314 `const PlaceEntryRow()` 之间）；随页面滚动、不悬浮；loading / error / empty / data 四态头部都含它（`_BerandaTop` 本就四态恒渲染，`home_page.dart` L125-145）。
3. 只在首页出现：全仓只有 `_BerandaTop` 一处引用 `AppUpdateBanner`（L0 源码扫描测试钉住：`lib/` 中 `AppUpdateBanner(` 恰出现 1 次，且在 `home_page.dart`；扫描排除构造函数声明 `AppUpdateBanner({super.key})`）。
4. 冷启动判定为推荐时**不弹窗**（PRD AC3b）——由 3.2 的冷启动回调保证，本 story 不加任何弹窗。
5. 本次运行内用户多次离开又回到首页：只要 `bannerVisible` 仍为 true 就每次都在（状态在进程内单例 provider 中，不随页面销毁）。

**AC3 — 点「Perbarui sekarang」** `[L0]` `[L2]`
1. 顺序：报埋点 `Analytics.capture('app_update_go_store_tapped', {'decision': 'recommend', 'surface': 'banner'})` → `await recordSkip()`（横幅当下收起 + 写 72h 冷却）→ `ref.read(storeLauncherProvider)(storeUrlForPlatform!)` 跳本平台商店（iOS → App Store，Android → Google Play）。
2. L0：点后横幅消失；launcher 收到的 URL = 本平台链接；`AppPrefs.updateSkippedVersion` = 本平台最新版本号。
3. `[L2]` 真机 / 模拟器点按钮打开商店 TailTopia 页（PRD AC8）。

**AC4 — 点 ✕** `[L0]`
报 `Analytics.capture('app_update_later_tapped', {'decision': 'recommend', 'surface': 'banner'})` → `await recordSkip()`；横幅收起；**不**跳商店。

**AC5 — 冷却生效与恢复** `[L0]`
1. 冷却记录存在且同一最新版本、72 小时内 → 再次检查（冷启动 / 回前台）判定为推荐也**不出横幅**。
2. 服务端本平台最新版本号上升到比记录更新（如记录 1.3.4、接口返回 1.3.5）→ 下一次检查后横幅立即恢复（PRD AC3）。
3. 以上由 3.2 `cooldownActive` 计算；本 story 加 widget 级用例：预置 prefs `petgo.update_skipped_version=1.3.4`、`petgo.update_skipped_at=now-1h`，fake 接口返回 1.3.4 → 无横幅；返回 1.3.5 → 有横幅。

**AC6 — 曝光埋点每次运行只报一次** `[L0]`
1. 横幅首次真正构建且可见时，在 `addPostFrameCallback` 中：`if (ref.read(appUpdateControllerProvider.notifier).markBannerShownReported()) Analytics.capture('app_update_prompt_shown', {'decision': 'recommend', 'surface': 'banner'});`。
2. 本次运行内离开再回首页、横幅重建 → **不再上报**（PRD AC10）。L0：同一 `ProviderContainer` 内先后 pump 两次首页，`debugCaptureSink` 只收到 1 条 `app_update_prompt_shown`。
3. 事件名以字面量直接写在 `Analytics.capture(` 第一个参数（守卫测试按正则提取）。`app_`、`_shown`、`_tapped` 均已在 `v112_events_test.dart` 白名单内，**守卫测试不改**。

**AC7 — 不出现的情形** `[L0]`
本平台商店链接为空、接口异常（`check` 返回 null）、冷却期内、判定为 `none` 或 `forced` → 无横幅，首页与现状一致（PRD AC6 / AC5 / FR-124.11）。每种至少一个 widget 用例（经 override `appUpdateControllerProvider` 或 fake repository + env 驱动）。

### 关键设计点

- **为什么是「白底小方块」而 UI 稿 C1 渲染里没有方块**：UI 稿 C1 的 `.upd2 .ic` 只有紫色图标，`.upd .ic`（36×36 白底圆角 10）属于旧两行版横幅；epics UX-DR5 明写「白底小方块内紫色小图标」，按权威顺序（epics 承接决策日志 / PRD，高于 UI 稿）采用白底方块，尺寸取 `.upd .ic` 的 36×36 / 圆角 10。8 + 36 + 8 = 52，与横幅高 52 吻合。
- **标题不截断**：PRD / epics 要求「Versi baru tersedia」完整显示。360dp 屏上「图标 + 标题 + 胶囊 + ✕」一行放不下时，宁可折行增高，也不 ellipsis。
- **点「前往更新」= 进冷却**（PRD §3.3 规则 h）：App 无法得知用户在商店里是否真的更新；若已更新，新版本自然不再提示；若没更新就回来，72 小时内不打扰。
- **先 `recordSkip` 再跳商店**：跳商店会让 App 进后台，先落盘冷却避免进程被系统回收后丢失记录。
- **曝光去重放在控制器**（`bannerShownReported`），不放组件 State：组件会随离开首页销毁重建，State 里的标记会丢。
- **游客也显示**：版本提醒与登录无关（接口游客可读）。
