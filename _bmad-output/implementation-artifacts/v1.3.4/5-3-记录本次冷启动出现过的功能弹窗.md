# Story 5.3: 记录本次冷启动出现过的功能弹窗

Status: ready-for-dev

## Story

As a 用户,
I want 打开 App 时不会同时被功能弹窗和活动弹窗轮番打扰,
so that 系统授权、新功能引导这些更重要的弹窗不被挤掉。

> 本 story **只做 App、只加登记**：新建进程内的「本次冷启动功能弹窗记录」（ledger，AD-12），在每个功能弹窗**真正出现**的那一刻登记；并在启动链末尾打一个「启动链已结束」的标记，供 Story 5.4 的运营弹窗判定等待。**不改变任何既有弹窗的触发条件、时机与顺序**（AD-12「只登记、不排队」）。
> 按 Epic 1→6 串行，Story 3.2（强制更新弹窗）与 Story 4.3（达成当场庆祝）此时已提交，本 story 负责回头给这两处补登记。

## Acceptance Criteria

**AC1 — ledger 本体** `[L0]`
新建 `petgo_app/lib/core/startup/startup_popup_ledger.dart`（纯 Dart 进程内单例，**不依赖 Riverpod**——ATT 与推送权限在 `main.dart` 的 `ProviderScope` 之外执行，读不到 provider）：
```dart
enum StartupPopupKind { att, pushPermission, forceUpdate, coachmark, milestoneCelebration }

class StartupPopupLedger {
  StartupPopupLedger._();
  static final StartupPopupLedger instance = StartupPopupLedger._();

  void record(StartupPopupKind kind);            // 登记；同一种重复登记无副作用；debugPrint('[StartupPopupLedger] $kind')
  bool get hasAny;                                // 本次冷启动是否出现过任一功能弹窗
  Set<StartupPopupKind> get recorded;             // 只读视图

  void markStartupChainDone();                    // 幂等
  bool get isStartupChainDone;
  Future<void> get startupChainDone;              // 启动链结束时完成；永不 error

  @visibleForTesting
  void resetForTest();                            // 清空记录 + 换一个新的未完成 Completer
}
```
- 不持久化（进程结束即清空 = 「本次冷启动」口径）。
- 不提供「删除某条记录」的接口（弹窗关闭后记录仍在：本次冷启动出现过就算，PRD AC2）。

### 关键设计点

- **为什么是纯 Dart 单例而不是 Riverpod provider**：ATT 与首启通知权限在 `runApp` 之后的首帧回调里执行，那里没有 `ref`；`AttGate`、`PushPermissionBootstrap` 本身就是静态类。用 provider 就得把 container 透传进去，改动面远超「只加登记」。
- **为什么在弹窗「入口」而不是「页面」登记**：入口只有一个，调用方会增加（4.3 新增了两处当场庆祝）；登在入口就不会漏，也不用改各调用方。蒙层登在组件 `initState` 同理——它被插进 Overlay 才会 build，与「插入时」（AD-12）等价。
- **ATT 只在「确实夺焦」时登记**：被系统吞掉的请求（iOS 26 首启、iPad 兼容模式）用户什么都没看到，不应挡掉运营弹窗；之后前台补弹真正弹出时再登记。
- **推送权限「会弹才登记」**：Android 12 及以下没有运行时通知权限、存量用户已问过，这两类冷启动没有任何系统弹窗，不该因此失去运营弹窗。
- **启动链结束标记放 `finally`**：Story 5.4 的判定先 `await startupChainDone`；任何一步抛错导致标记缺失，运营弹窗本次就永远不出——这是「安全侧失败」，但不该因为 AppsFlyer 之类无关步骤的异常而丢。
- **与 D-22 的关系**：Diary 蒙层要等 `onboardingMarksProvider` 网络返回后才插入，可能晚于运营弹窗判定的起点；Story 5.4 在真正 show 之前**再查一次** ledger（D-22），本 story 只需保证蒙层一出现就登记。
