# Story 4.2: 打卡成功、解锁完整解读时自动达成

Status: ready-for-dev

## Story

As a 宠物主人,
I want 打卡成功或解锁完整性格解读后，对应成就自动完成,
so that 我不用手动打卡这两项。

> 依赖 Story 4.1（清单已含 `C/D-S17`、`C/D-S18`、`G-S10`、`G-S11`，存量名册已补行）。本 story 只做**后端**事件接线；App 当场庆祝在 Story 4.3。

## Acceptance Criteria

**AC1 — 新自动事件与映射** `[L0]`
1. `MilestoneAutoEvent` 末尾新增两个常量：`PLACE_CHECKED_IN`（场所打卡成功）、`TAILSONALITY_UNLOCKED`（Tailsonality 完整解读解锁成功）。枚举由 17 种变 19 种。
2. `MilestoneAutoCompleteMap` 登记：`PLACE_CHECKED_IN` → `C-S17` / `D-S17` / `G-S10`；`TAILSONALITY_UNLOCKED` → `C-S18` / `D-S18` / `G-S11`（三物种都有节点，无 `null`）。

**AC2 — `PlaceCheckedInEvent` 携带 `petIds`** `[L0]`
1. record 末尾加字段 `List<Long> petIds`：`PlaceCheckedInEvent(long userId, String placeToken, PlaceType placeType, boolean isNewStamp, int stampCount, List<Long> petIds)`。
2. `PlaceCheckinService.checkIn` 发事件时传入本次已校验、去重后的 `petIds`（即 `ownedPetIds(...)` 的返回值，`List.copyOf`，不可变）。
3. `petIds` **不进埋点**：`PassportAnalyticsListener.onCheckedIn` 不改（属性仍只有 `place_id` / `place_type` / `is_new_stamp` / `stamp_count`），并加测试钉住（AD-19：埋点不带宠物标识）。

**AC3 — 打卡逐宠达成** `[L0]`（单测）`[L1]`（端到端）
打卡事务提交后（`@TransactionalEventListener` AFTER_COMMIT + `@Async`），对 `petIds` 中**每只宠物**按其物种完成打卡项（`PLACE_CHECKED_IN` 经映射表），`source = SYSTEM_AUTO`。
- 已完成的再次打卡 → 幂等跳过（不新增完成行、不再发 `MilestoneCompletedEvent`）。
- 宠物在事件消费时已被删除 → 静默跳过，不抛。
- 打卡被拒（404 / 422 / 403 / 409）→ 不发事件 → 不达成（既有行为，`PlaceCheckinServiceTest.rejectedCheckinDoesNotIssuePassport` 已钉「不发事件」）。

**AC4 — 完整解读解锁达成；配型单买不算** `[L0]`（单测）`[L1]`（端到端）
监听 `KeepsakeUnlockedEvent`（AFTER_COMMIT + `@Async`）：
1. **只认 `sku == KeepsakeSku.TAILSONALITY`**（QRIS 到账 `KeepsakePaidHandler`、PawCoin 当场成交 `KeepsakePurchaseService.startPawcoin`、配型后补差价升级都走这一 SKU）；`TS_MATCH`、`PASSPORT_SNAP`、`BOARDING_PASS` 一律直接 return。
2. 宠物 = `tailsonality_results.pet_profile_id`，按 `refId`（= `tailsonality_results.id`）查得；查不到（结果已随删档物理删除）→ 静默跳过。
3. 完成该宠物物种的性格测试项（`TAILSONALITY_UNLOCKED`），`source = SYSTEM_AUTO`。
4. 重测后再次解锁新结果 → 该项已完成 → 幂等跳过，不重复达成、不再发通知。
5. 只答题未解锁（`POST /results` 建行，无解锁）→ 不发 `KeepsakeUnlockedEvent` → 不达成（既有行为，无需新代码，补测试钉住）。
6. `KeepsakeUnlockedEvent` 只在 `GrantOutcome.GRANTED` 时发出（`KeepsakePaidHandler` L87-90、`KeepsakePurchaseService` L136-138），`ALREADY_UNLOCKED` / `REF_MISSING` 不发——本 story **不改**这两处发事件逻辑。

**AC5 — 与既有自动里程碑一致的下游** `[L0]`（单测）`[L1]`
新完成的两项走 `MilestoneCompletionService.complete(...)`：写 `milestone_completions`（`celebrated_at = NULL`，供 4.3 当场庆祝与既有补庆祝判定）、发 `MilestoneCompletedEvent` → `MilestoneNotifyListener`（S 级：`MILESTONE_SM_NODE` 只写通知中心、不推送）+ `MilestoneAnalyticsListener`（`milestone_achieved`，属性含 `code` 自动区分，PRD §4「不新增事件」）。**不新增**通知类型、埋点事件。

**AC6 — 端到端** `[L1]`
新增 `MilestoneCheckinTailsonalityIntegrationTest`（见 Dev Notes）：真接口打卡 / PawCoin 解锁完整解读后，≤5 秒内 `GET /api/v1/pet-profiles/me/milestones` 对应条目 `completed=true`、`celebratedAt=null`；配型单买、只答题不解锁 → 不完成；同宠物重测再解锁 → 完成行仍为 1 条。

### 关键设计点

1. **新监听器 `MilestoneCheckinTailsonalityListener`**（`com.tailtopia.profile.service`，`@Component`）：
   ```java
   @Component
   public class MilestoneCheckinTailsonalityListener {
       private final MilestoneCompletionService completion;
       private final TailsonalityResultPetQuery tailsonalityPets;
       // 构造器注入两者

       /** 打卡成功 → 本次选中的每只宠物完成其物种的打卡项（PRD「逐宠达成」；本版一人一宠，结构按列表处理）。 */
       @Async
       @TransactionalEventListener
       public void onPlaceCheckedIn(PlaceCheckedInEvent e) {
           if (e.petIds() == null) return;
           for (Long petId : e.petIds()) {
               if (petId != null) {
                   completion.completeForPet(petId, MilestoneAutoEvent.PLACE_CHECKED_IN,
                           MilestoneCompletionSource.SYSTEM_AUTO);
               }
           }
       }

       /**
        * 完整解读解锁 → 该结果所属宠物完成性格测试项。🔴 只认 TAILSONALITY（含补差价升级）；
        * TS_MATCH（配型单买）不算（PRD 2026-10-12）；其它 SKU 与本里程碑无关。
        */
       @Async
       @TransactionalEventListener
       public void onKeepsakeUnlocked(KeepsakeUnlockedEvent e) {
           if (e.sku() != KeepsakeSku.TAILSONALITY) return;
           tailsonalityPets.petProfileIdOf(e.refId()).ifPresent(petId ->
                   completion.completeForPet(petId, MilestoneAutoEvent.TAILSONALITY_UNLOCKED,
                           MilestoneCompletionSource.SYSTEM_AUTO));
       }
   }
   ```
   - 单独成类而非塞进 `MilestoneAutoCompleteListener`：后者构造器只有一个参数，三个既有单测直接 `new` 它；加参数会打破它们，且这两路需要额外依赖。
   - `@Async` 线程里无事务，`completeForPet` 自带 `@Transactional`；监听器内**不 try/catch 吞异常**（与既有监听器一致，异步异常由 Spring 记日志，不影响打卡 / 支付主流程）。
   - **不得**订阅 `PaymentIntentPaidEvent`（`KeepsakeSingleConsumerSourceGuardTest` 钉着）。
2. **`TailsonalityResultPetQuery`**（`com.tailtopia.tailsonality.service`，`@Service`）：
   ```java
   /** 结果 → 所属宠物 id 的只读口（V1.3.4 Story 4.2）。只依赖自己的仓库（profile 注入它，避免构造器循环；同 TailsonalityBadgeQuery）。 */
   @Transactional(readOnly = true)
   public Optional<Long> petProfileIdOf(long resultId) {
       return results.findById(resultId).map(TailsonalityResult::getPetProfileId);
   }
   ```
   （`TailsonalityResult.getPetProfileId()` 在 L98，返回 `Long`。）
3. **`MilestoneCompletionService.completeForPet`**（放在 `completeCodeForOwner` 之后）：
   ```java
   /** 按宠物 id + 自动事件幂等完成（V1.3.4：打卡 / 性格测试按宠物达成，不经 owner 反查）。宠物不存在 → false。 */
   @Transactional
   public boolean completeForPet(long petProfileId, MilestoneAutoEvent event, MilestoneCompletionSource source) {
       return profiles.findById(petProfileId)
               .map(p -> complete(p.getId(), p.getPetType(), event, source, null))
               .orElse(false);
   }
   ```
   不做归属校验：两条来源都已在上游校验（打卡 `ownedPetIds`；解锁结果行本身就挂在宠物上）。
4. **为什么只认 `TAILSONALITY`**：配型单买（`TS_MATCH`）只置 `match_unlocked_at`，不代表完整解读已解锁；补差价升级走的仍是 `TAILSONALITY` SKU（`tailsonality_match_page.dart` 的 `full: true` 调 `repo.unlock`），`unlocked_at` 只由 `TailsonalityKeepsakeGranter.unlock` 置位（L67-78），GRANTED 才发事件。
5. **幂等的来源**：`complete(...)` 先 `completions.existsByPetMilestoneId` 短路，再由 `uq_milestone_completions_milestone` 唯一约束兜住并发（L116-124）。不需要也**不要**另加「是否首次打卡」判断。
6. **`celebrated_at` 留空**：运行时完成不写 `celebrated_at`（`MilestoneCompletion.of` 不设），由 4.3 当场庆祝或既有补庆祝回报置位。
