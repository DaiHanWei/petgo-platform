# Story 4.3: 达成当场弹出庆祝页

Status: ready-for-dev

## Story

As a 宠物主人,
I want 打卡成功、解锁完整解读的那一刻就看到庆祝页,
so that 成就感在当下就出现，而不是下次进里程碑页才补弹。

> 依赖 Story 4.1（App 文案 / 徽章映射）与 Story 4.2（后端异步达成）。本 story **只改 App**，后端零改动。庆祝页本身（`showMilestoneCelebration`）**结构一行不改**。

## Acceptance Criteria

**AC1 — 打卡成功页当场庆祝** `[L0]`（widget 测试）`[L2]`（真机视觉）
1. 进入打卡成功页（`PlaceCheckinSuccessPage`）首帧后，按短轮询范式查当前宠物的打卡项（`C-S17` / `D-S17` / `G-S10` 中出现在列表里的那一条）。
2. 该项 `completed == true && celebratedAt == null`，且不在本机「已庆祝」集合（`locallyCelebratedMilestonesProvider`）里 → 调 `showMilestoneCelebration(path: MilestoneCelebrationPath.instant)` 盖在成功页之上；徽章为 `place_checkin` 插画（`MilestoneBadge` 按 code 自动取），标题 / 正文为 4.1 写入的 D-12 文案（`localizedMilestoneCelebration` 自动取）。
3. 关闭庆祝页 → 回到打卡成功页，「Lihat Paspor」「Rekam Momen Ini」照常可点。
4. 弹出前 `markMilestonesCelebrating(ref, [code])`，关闭后 `reportMilestoneCelebrated(ref, [code])`（上报 `POST /api/v1/pet-profiles/me/milestones/celebrations`），之后进里程碑列表页**不再补弹**。
5. 每个成功页实例**只检测一次**（重建 / 返回本页不重复检测）。

**AC2 — 完整解读解锁成功当场庆祝** `[L0]` `[L2]`
1. 结果页 `TailsonalityResultPage._startUnlock`：`outcome == KeepsakeFlowOutcome.unlocked` 时（现有成功 SnackBar 之后），对性格测试项（`C-S18` / `D-S18` / `G-S11`）执行同一检测与庆祝；关闭回到结果页。挽留弹层里点「解锁」最终也走 `_startUnlock`，同样覆盖。
2. 配型页 `TailsonalityMatchPage._startUnlock`：**仅 `full == true`**（「买完整解读」）且 `outcome == unlocked` 时同上；关闭回到配型页。
3. 庆祝检测**不阻塞**解锁流程收尾：用 `unawaited(...)` 发起，`_buying` 照常在 `finally` 复位。

**AC3 — 短轮询与兜底** `[L0]`
1. 轮询间隔 500 / 800 / 1200 ms（健康页既有范式），每次 `ref.invalidate(milestoneListProvider)` 后重读，单次读取超时 2 秒。
2. **轮询前先读一次当前列表**（超时 2 秒）：目标项不在列表里 → 结束；目标项已完成且已庆祝（`celebratedAt != null`）或在本机已庆祝集合 → 结束，**不轮询**（回填过 / 重测再解锁 / 再次打卡的常见情形，省掉 2.5 秒请求）；目标项已是「已完成未庆祝」→ 直接庆祝，不再等。
3. 三次都没等到「已完成未庆祝」/ 任一次读取失败 / 页面已销毁（`!context.mounted`）→ **不弹、不报错、不提示**，交既有补庆祝（进里程碑列表页时 `resolveCatchup`）兜底。
4. 轮询间隔取自新 provider `milestoneInstantPollDelaysProvider`（默认上述三值），测试可覆盖为 `const []`（= 不检测）或 `[Duration.zero]`。

**AC4 — 不该弹的情形** `[L0]`
1. 只单独买配型（`full == false`）成功 → 不检测、不弹。
2. `outcome == KeepsakeFlowOutcome.alreadyUnlocked` / `notCompleted` → 不检测、不弹。
3. 该宠物此前已达成（回填过、重测再解锁、再次打卡）→ 预读即发现「已完成且已庆祝」→ 不弹。
4. 游客 / 无宠物：打卡与解锁本身需登录有宠，正常到不了；若列表读取抛错 → 按 AC3.3 静默结束。

**AC5 — 冷启动功能弹窗登记（预留）** `[L0]`
本 story **不写**冷启动功能弹窗记录（`startupPopupLedger`）相关代码。两处调用点一律经 `showMilestoneCelebration` 入口；Story 5.3 会在该入口（`milestone_celebration.dart` L37 函数体首行）统一登记「里程碑庆祝」，自动覆盖本 story 的调用。在新 helper 调用 `showMilestoneCelebration` 的那一行上方加注释：`// 冷启动功能弹窗登记（AD-12）由 Story 5.3 在 showMilestoneCelebration 入口统一完成，此处不另登记。`

**AC6 — 埋点** `[L0]`
不新增事件；`milestone_celebration_shown`（`code` / `level` / `path=instant`）由 `showMilestoneCelebration` 既有逻辑上报（PRD §4「FR-126 不新增事件」）。

### 关键设计点

1. **`milestone_instant_codes.dart`（纯 Dart，L0 可测）**：
   ```dart
   import 'milestone.dart';

   /// V1.3.4 FR-126：两项「当场庆祝」里程碑的完整 code（三物种各一条；与后端 MilestoneAutoCompleteMap 一致）。
   const Set<String> kPlaceCheckinMilestoneCodes = {'C-S17', 'D-S17', 'G-S10'};
   const Set<String> kTailsonalityMilestoneCodes = {'C-S18', 'D-S18', 'G-S11'};

   /// 列表里属于 [codes] 的那一条（单宠清单只会命中一条）；没有 → null。
   MilestoneItem? findMilestoneByCodes(MilestoneList list, Set<String> codes) { … 遍历 groups/items … }

   /// 当场庆祝候选：命中 [codes]、`isUncelebrated`、且不在 [locallyCelebrated] 中 → 该条；否则 null。
   MilestoneItem? pickInstantCelebration(MilestoneList list, Set<String> codes, Set<String> locallyCelebrated) { … }

   /// 预读判定：true = 不必轮询（不在列表 / 已完成且已庆祝 / 本机已庆祝）。
   bool instantCelebrationSettled(MilestoneList list, Set<String> codes, Set<String> locallyCelebrated) { … }
   ```
   **不得**用后缀 / 正则拼 code（与 `milestone_badge_assets.dart` 同一纪律），一律显式集合。
2. **`milestone_instant_celebration.dart`**：
   ```dart
   /// 当场庆祝短轮询间隔（健康页范式）。测试覆盖为 const [] 即完全不检测。
   final milestoneInstantPollDelaysProvider = Provider<List<Duration>>((ref) => const [
         Duration(milliseconds: 500), Duration(milliseconds: 800), Duration(milliseconds: 1200),
       ]);

   /// 打卡 / 完整解读解锁成功后：等后端异步达成 [codes] 中的那一条，已完成未庆祝 → 当场庆祝。
   /// 没等到 / 读失败 / 页面已销毁 → 静默结束，交补庆祝兜底（AD-19）。
   Future<void> celebrateAutoMilestoneIfAny(BuildContext context, WidgetRef ref, Set<String> codes) async
   ```
   流程：
   - `delays = ref.read(milestoneInstantPollDelaysProvider)`；为空 → return。
   - 预读：`await ref.read(milestoneListProvider.future).timeout(const Duration(seconds: 2))`（catch 任意异常 → return）；`if (!context.mounted) return;`；`local = ref.read(locallyCelebratedMilestonesProvider)`；`pickInstantCelebration` 命中 → 直接 `_celebrate`；`instantCelebrationSettled` 为真 → return。
   - 循环 `for (final d in delays)`：`await Future<void>.delayed(d)`；`if (!context.mounted) return;`；`ref.invalidate(milestoneListProvider)`；重读（2s 超时，异常 → return）；`if (!context.mounted) return;`；命中 → `_celebrate` 并 return。
   - `_celebrate(context, ref, list, item)`：照 `health_list_page.dart` `_celebrate` L709-741——`collection = [for (g in list.groups) ...g.items]`、`petName = list.petName`、`shareText`；`markMilestonesCelebrating(ref, [item.code])`；（AC5 注释）`await showMilestoneCelebration(context, item, petName:, path: MilestoneCelebrationPath.instant, collection:, onShare: () => shareMilestoneWithLink(...), onSeeAll: () => context.push(DeepLinkRoutes.milestoneList, extra: <String>{item.code}))`；之后 `reportMilestoneCelebrated(ref, [item.code])`（**在 show 返回后调用、不 await**；若此时 `!context.mounted`，仍要报——`reportMilestoneCelebrated` 内部走 provider 自己的 Ref，调用前用一个在 show 之前取好的 `notifier = ref.read(locallyCelebratedMilestonesProvider.notifier)` 直接 `notifier.report([code])`，避免在已销毁的 `WidgetRef` 上 read）。
   - `onSeeAll` 用 `push` 而非 `go`：返回键回到成功页 / 结果页。
3. **打卡成功页**：
   ```dart
   bool _milestoneChecked = false;
   // initState 首帧回调内，现有 invalidate 之后：
   if (mounted && !_milestoneChecked) {
     _milestoneChecked = true;
     unawaited(celebrateAutoMilestoneIfAny(context, ref, kPlaceCheckinMilestoneCodes));
   }
   ```
   不按 `isNewStamp` 过滤：`isNewStamp` 指「这个场所的新章」，与「这只宠物第一次打卡」不是一回事（例如 4.2 上线前已打过卡、又未被回填覆盖的边缘情形），统一交给「已完成未庆祝」判据；已庆祝过的由预读直接结束、不轮询。
4. **Tailsonality 两页**：
   - 结果页：`if (outcome == KeepsakeFlowOutcome.unlocked) { …SnackBar…; unawaited(celebrateAutoMilestoneIfAny(context, ref, kTailsonalityMilestoneCodes)); }`
   - 配型页：同一分支内 `if (full) unawaited(celebrateAutoMilestoneIfAny(context, ref, kTailsonalityMilestoneCodes));`
   - `unawaited` 需要 `import 'dart:async';`：`tailsonality_result_page.dart` 已有；`tailsonality_match_page.dart` 与 `place_checkin_success_page.dart` **没有，需补**。
5. **为什么用「已完成未庆祝」而不是健康页的「前后 diff」**：健康页一次保存可能点亮多条、要挑最高级；这里目标 code 已知且唯一，直接看该条状态更简单，也天然排除「此前已达成」（回填时 `celebrated_at` 已置）。
6. **与补庆祝的互斥**：弹之前 `markMilestonesCelebrating` 记本地，回报前若用户进里程碑列表，`resolveCatchup` 会先扣本地集合，不会连弹；`onSeeAll` 另带 `justCelebrated`。
7. **护栏**：不加依赖、不改 `showMilestoneCelebration`、不新增 ARB key、不新增埋点。

  4. 重测后再次解锁 → 不弹；

  6. 弱网下轮询超时 → 不弹，之后进列表页补弹一次。
