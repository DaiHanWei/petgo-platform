# Story 2.4: 发布链路改为原图上传并带上露出位置

Status: ready-for-dev

> 版本 V1.3.4 · 主题 app · Epic 2「发图不丢画面」· FR-125.1 / 125.2 / 125.4 / 125.5 / 125.6 / 125.7 / 125.11 · AD-8 · NFR1 / NFR12
> 本 story **只动 App**：把 2.3 的露出区域页接进发帖页、取消物理裁剪、把每张图的 offset 随发布请求带给 2.1 的后端字段，并删除旧三档裁剪代码。

## Story

As a 发帖用户,
I want 我的图片完整上传、不再被裁掉,
so that 别人点开大图能看到我拍的全部画面。

## Acceptance Criteria

**AC1 — 选图后：超界图自动进露出区域页，区间内的不进** `[L0]`
1. 选图处理 `ImageProcessor`（剥 EXIF 含 GPS、≤10MB）**保留不变**：仍由 `MediaUploadUseCase.pickAndProcess` / `pickMultiAndProcess` 完成（NFR1，PRD「原图」= 处理后产物）。
2. 处理后的字节交给新编排函数 `prepareBatchExposure`（见 T1）：读文件头得尺寸，`needsCrop(w, h)` 为真（`ratio < 0.75` 或 `> 1.78`）的图**一次性**打开露出区域页（2.3 `PublishExposurePage`，整批超界图同页）；全部在 `[0.75, 1.78]` 内（含端点）或量不出尺寸 → **不打开页面**、不上报任何 crop 事件。

**AC2 — 「Lanjut」后带 offset 加入发帖页** `[L0]`
超界图带页面返回的 offset 加入（不调整直接 Lanjut = **0.5**）；区间内 / 量不出尺寸的图 offset 为 `null`；加入顺序 = 选图顺序。

**AC3 — ✕ / 返回 = 本次一张不加** `[L0]`
页面返回 `null` → `prepareBatchExposure` 返回 `null` → 发帖页本次选的图**全部不加**（区间内的也不加），已在发帖页的旧图不受影响。

**AC4 — offset 跟着图走** `[L0]`
`ImageUploadItem` 新增 `final double? cropOffset`；长按拖拽重排、点 ✕ 删除后，每张图的 offset 仍属于原图；发布时按 `items` 最终顺序组装 `imageCropOffsets`（与 `imageUrls`、`imageSizes` 同序等长）。

**AC5 — 上传原字节，不再裁切 / 重编码** `[L0]` 代理断言 · `[L2]` 真 OSS
1. `[L0]` `prepareBatchExposure` 返回的每个 `bytes` 与传入的是**同一个对象**（`identical`）；`PublishController` 交给 `uploadOne` 的也是 `addImage` 收到的那个对象——处理之后零裁切、零重编码。
2. `[L0]` 既有 `test/media/image_processor_test.dart`（GPS EXIF 被剥离）保持绿（防止误删选图处理）。
3. `[L2]` 本地 / stag：发布一张 3:1 超界图后，下载 OSS 原图（URL 不带 `x-oss-process`）与发帖时 `ImageProcessor` 产物比对 SHA-256 一致；`exiftool` 查无任何 EXIF / GPS（PRD AC1 / AC1b）。

**AC6 — 发帖页缩略图不变** `[L0]`
缩略图仍 `Image.memory(item.bytes, fit: BoxFit.cover, cacheWidth: 400)`、方形取正中，不读 `cropOffset`（PRD 2026-10-09）。

**AC7 — 发布请求带 `imageCropOffsets`** `[L0]` · `[L1]` 联调
1. `ContentRepository.publish` 新增命名参数 `List<double?> imageCropOffsets`（默认 `const []`）；
2. `DioContentRepository`：**仅当**其中至少一个非 null 时写 `data['imageCropOffsets']`，元素 `null` 原样、非 null 先 `clamp(0.0, 1.0)` 再保留 3 位小数（`(v * 1000).round() / 1000`）；全为 null（无超界图）→ **整键不出现**（与老请求体逐字节一致，后端列为 NULL）；
3. `[L1]` 本地后端联调：发一条含一张 3:1（offset 0）+ 一张 4:3 的帖，库里 `image_crop_offsets = [0.0, null]`。

**AC8 — 旧裁剪代码删除** `[L0]`
1. 删除：`CropPreset`、`CropRect`、`computeCropRect`、`cropToAspect`、`CropChoice`、`CropAsk`、`applyBatchCrop`（`image_crop.dart`）；整文件删除 `lib/features/content/presentation/publish_crop_page.dart`；
2. **保留不改**：`needsCrop()`、`imageSizeOf()`（仍在 `image_crop.dart`）；`kFeedRatioMin` / `kFeedRatioMax`（`feed_image_layout.dart`，shop 与 brag 模块也在用）；
3. 删除 l10n key `publishCropHint`、`publishCropApply`、`publishCropLocked`（en + id 两文件，重新 `flutter gen-l10n`）；`publishCropTitle` **保留**（2.3 页面在用）；
4. `grep -rn "CropPreset\|cropToAspect\|computeCropRect\|applyBatchCrop\|PublishCropPage\|is_batch_lock_source" petgo_app/lib petgo_app/test` 结果为空。

**AC9 — 埋点口径变更** `[L0]`
1. `publish_image_crop_shown`：每张超界图一条，属性**不变** `{original_ratio: <w/h 保留 3 位小数 double>, batch_size: <本次选图总张数，含区间内>}`，在打开露出区域页**之前**上报；
2. `publish_image_crop_completed`：用户点「Lanjut」后**每张超界图一条**，属性改为 `{target_ratio: '1x78' | '0x75', adjusted: <bool>}`（`target_ratio` 由越界方向唯一决定：过宽 `1x78`、过竖 `0x75`；`adjusted` 取 2.3 页面返回值）；**不再有** `is_batch_lock_source`；取消（✕ / 返回）时不报；
3. `publish_image_crop_exit_tapped` 保留（2.3 页面内上报，属性 `original_ratio`）；
4. 三个事件都以**字符串字面量**调用 `Analytics.capture('publish_image_crop_…', …)`（`test/analytics/v116_events_test.dart` 靠扫描字面量判「事件在源码里存在」）；
5. Completion Notes **必须**写一句：「埋点口径变更：`publish_image_crop_completed` 的 `target_ratio` 取值由 `1x1/4x5/3x4` 改为 `0x75/1x78`，新增 `adjusted`、删除 `is_batch_lock_source`；数据侧须按发版日切分」（NFR12）。

### 关键设计点

- **取消物理裁切 = 删掉一次解码 + 重编码**：旧链路 `cropToAspect` 对超界图整张解码再 `encodeJpg(quality: 90)`；新链路上传的就是 `ImageProcessor` 的产物本身，因此 L0 用 `identical` 断言即可代理「哈希一致」，真文件比对留 L2。
- **一次页面处理整批**：旧 `applyBatchCrop` 逐张 push 页面；新编排只 push 一次，把所有超界图交给 2.3 页面（PRD「多张同一页左右切换」）。
- **offset 随 item 对象走**：重排 / 删除操作的都是 `ImageUploadItem` 对象本身，offset 作为对象字段天然跟随，不另建「下标 → offset」映射（那就是第二份顺序，违反 AD-A27.1）。
- **全 null 不发**：没有超界图的帖子请求体与 V1.3.3 逐字节一致；后端也因此对这类帖子保持 `NULL`（2.1 AC4）。
- **预填图不走露出区域页**：预填入口传进来的是 App 自己生成的卡片图，现状也不经裁剪页；本版保持不进，offset 为 null（居中）。
- **`kFeedRatioMin` / `kFeedRatioMax` 不能删**：`lib/features/shop/domain/shop_product.dart` 与 `lib/features/content/domain/brag_post_image.dart` 也引用；本 story 只删 `image_crop.dart` 里的裁剪 API。

### 本 story 不做

- 不改 `ImageProcessor`、`MediaUploadUseCase`、上传串行策略（AD §13 第 3 条）；
- 不改发帖页缩略图（仍取正中）；不加发帖页「再次调整露出位置」入口（PRD 未要求）；
- 存量帖不回溯、不补偿（FR-125.10）；
- 发帖页上传失败的 ⚠ 与 ✕ 叠角不处理（决策日志 D-14）。
