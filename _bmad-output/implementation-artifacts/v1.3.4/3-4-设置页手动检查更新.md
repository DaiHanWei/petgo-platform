# Story 3.4: 设置页手动检查更新

Status: ready-for-dev

## Story

As a 用户,
I want 在设置页手动检查是否有新版本,
so that 我想更新时能主动确认。

> 范围：**纯 App**。依赖 3.2 的 `appUpdateControllerProvider.checkManually()` / `recordSkip()`、`AppUpdateDialog`（推荐态外观已在 3.2 做完）、`showForcedUpdateDialog`、`storeLauncherProvider`。本 story 新增 4 条文案（第 5 条 `updateVersionLabel` 已由 3.2 加）。

**AC2 — 检查中** `[L0]`
点击后 `_checkingUpdate = true`：右侧（版本号 + 箭头的位置）换成 18×18 紫色转圈（`CircularProgressIndicator(strokeWidth: 2.5, color: AppColors.mint, backgroundColor: AppColors.violet100)`，key `settingsCheckUpdateSpinner`）；行 `onTap: null`（不可再点，连点只发一次请求）。结束（任何结果）后恢复。`await` 之后先判 `mounted`。

**AC3 — 有新版本（推荐态）** `[L0]` `[L2]`
1. `checkManually()` 返回 `recommended`（**冷却期内也算**，手动检查无视冷却）→ 调新函数 `showRecommendedUpdateDialog(context, ref)`（加在 3.2 的 `app_update_presenter.dart`）：
   - 弹出前报 `Analytics.capture('app_update_prompt_shown', {'decision': 'recommend', 'surface': 'dialog'})`；
   - `AppUpdateDialog.show(context, decision: UpdateDecision.recommended, version: <本平台最新版本号>, onGoStore: <本平台链接为空则 null>, onLater: …)`；外观见 3.2「弹窗规格」：标题 `updateRecommendTitle`、正文 `updateRecommendBody`、「Versi {version}」、主按钮「Perbarui sekarang」、其下文字按钮「Nanti」（UX-DR6 / UI 稿 C5）。
2. 点「Nanti」→ 报 `Analytics.capture('app_update_later_tapped', {'decision': 'recommend', 'surface': 'dialog'})` → `recordSkip()` 进入 72 小时冷却（首页横幅随之不出，PRD AC3 / AC9）。
3. 点「Perbarui sekarang」→ 报 `Analytics.capture('app_update_go_store_tapped', {'decision': 'recommend', 'surface': 'dialog'})` → 关弹窗 → `recordSkip()` → `storeLauncherProvider` 跳本平台商店。
4. 点遮罩 / 返回键关闭推荐态弹窗：不记冷却、不报埋点（与 3.2 AC7.5 一致）。

**AC4 — 判定为强制** `[L0]`

### 关键设计点

- **为什么手动检查无视冷却**（PRD §3.3 规则 h）：用户主动查就如实告知；冷却只抑制「自动」打扰。
- **转圈期间行不可点**：防连点；3.2 控制器另有在途去重，双保险。
- **toast 用 `context` 前判 `mounted`**：检查最长约 10 秒（3.2 的超时），用户可能已离开设置页；离开了就不弹。
- **推荐弹窗在设置页弹，横幅只在首页**：设置页没有横幅位置，主动查询时弹窗不算打断（PRD §3.3 规则 f）。
- 右值带 `v` 前缀（UI 稿 C3 / C5：`<em>v1.3.4</em>`）。
