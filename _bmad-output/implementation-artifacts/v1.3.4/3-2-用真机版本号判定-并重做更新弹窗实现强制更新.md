# Story 3.2: 用真机版本号判定，并重做更新弹窗实现强制更新

Status: review

## Story

As a 使用旧版本的用户,
I want App 正确识别我装的版本，在必须更新时给我一个清楚、可直达商店的弹窗,
so that 我不会被误判，也不会被卡在没有出路的弹窗里。

> 范围：**纯 App**（后端接口已由 3.1 改为 5 字段）。本 story 交付：版本号来源、接口模型、统一控制器 `appUpdateControllerProvider`、冷启动 / 回前台触发、重做后的 `AppUpdateDialog`（强制态 + 推荐态两种外观都在本 story 做完，推荐态的**调用**在 3.4）、强制态弹出与埋点。横幅在 3.3，设置页在 3.4。

## Acceptance Criteria

**AC1 — 版本号取真机包** `[L0]` `[L2]`
1. 删除 `app_version_check.dart` L6-8 的 `kAppVersion`（`String.fromEnvironment('APP_VERSION', …)`）及其注释；当前版本一律经 `AppUpdateEnv.loadCurrentVersion` 取，默认实现 = `(await PackageInfo.fromPlatform()).version`。
2. L0 源码扫描测试：`lib/` 下任何 `.dart` 文件都不得出现 `fromEnvironment('APP_VERSION'`。
3. `[L2]` 真机安装 1.2.0（或任一旧版本）的包，判定所用版本 = 包版本（PRD AC2 / NFR6）；**只接受真机包结论**，模拟器或 dart-define 环境下的通过不算。stag 包 versionName 带 `-stag` 后缀（如 `1.3.3-stag`），`compareSemver` 既有逻辑会忽略 `-` 后缀，判定按 `1.3.3`。

**AC2 — 接口模型换字段、失败放行** `[L0]`
1. `AppVersionInfo` 字段改为 `iosLatestVersion`、`androidLatestVersion`、`minSupportedVersion`（均 `String`，必填）与 `iosStoreUrl`、`androidStoreUrl`（`String?`）；删除 `latestVersion`。
2. 新增 `String latestFor({required bool isIos})`、`String? storeUrlFor({required bool isIos})`（后者空串 / null → null，复用 `AppVersionCheck.storeUrl`）。
3. `AppVersionRepository.fetch()`：整体 `.timeout(const Duration(seconds: 10))`；**任何异常**（`DioException`、`TimeoutException`、类型错误、缺字段）一律返回 `null`；三个版本字段任一缺失或不是非空 `String` → 视为异常返回 `null`（不再用 `'1.0.0'` 兜底——兜底会把坏响应误判成「强制更新」或「无更新」）。
4. 单测覆盖：正常 5 字段解析；缺 `androidLatestVersion` → null；`iosStoreUrl: ""` → `storeUrlFor(isIos: true)` 为 null；Dio 抛错 → null（用自定义 `HttpClientAdapter` 造响应，照 `test/shop/shop_product_paging_test.dart` 写法）。

**AC3 — 按本平台判定（三态）** `[L0]`
1. iOS（`defaultTargetPlatform == TargetPlatform.iOS`）只用 `iosLatestVersion`，其余平台一律用 `androidLatestVersion`；`minSupportedVersion` 双端共用。判定仍用既有 `AppVersionCheck.decide(current, latest, minSupported)`（`app_version_check.dart` L48-56，**不改**）。
2. 单测：iOS 设备、`ios=1.3.3 / android=1.3.5 / current=1.3.3` → `none`；Android 同数据 → `recommended`（PRD AC7「只调高一端时另一端无提示」）；`current=0.9.0, min=1.0.0` → `forced`。

**AC4 — 统一控制器 `appUpdateControllerProvider`** `[L0]`
新建 `lib/features/notify/domain/app_update_controller.dart`，结构写死如下（3.3 / 3.4 直接调用这些名字）：
```dart
enum AppUpdateTrigger { coldStart, resume, manual }
enum ManualCheckOutcome { forced, recommended, upToDate, failed }

class AppUpdateEnv {                       // 测试经 appUpdateEnvProvider.overrideWithValue 注入
  const AppUpdateEnv({required this.now, required this.isIos,
      required this.loadCurrentVersion, required this.loadPrefs});
  final DateTime Function() now;
  final bool isIos;
  final Future<String> Function() loadCurrentVersion;
  final Future<AppPrefs> Function() loadPrefs;
}
final appUpdateEnvProvider = Provider<AppUpdateEnv>((ref) => AppUpdateEnv(
      now: DateTime.now,
      isIos: defaultTargetPlatform == TargetPlatform.iOS,
      loadCurrentVersion: () async => (await PackageInfo.fromPlatform()).version,
      loadPrefs: AppPrefs.create,
    ));

@immutable
class AppUpdateState {
  const AppUpdateState({this.info, this.currentVersion, this.decision = UpdateDecision.none,
      this.lastCheckedAt, this.skippedVersion, this.skippedAt,
      this.bannerVisible = false, this.bannerShownReported = false});
  final AppVersionInfo? info;          // 最近一次成功拉到的接口数据
  final String? currentVersion;        // 真机包版本
  final UpdateDecision decision;       // 最近一次成功判定；失败时保持 none
  final DateTime? lastCheckedAt;       // 最近一次「发出请求」的时刻（成功或失败都记）
  final String? skippedVersion;        // 冷却记录（来自 AppPrefs）
  final DateTime? skippedAt;
  final bool bannerVisible;            // 3.3 横幅是否该显示（见 AC5.3 公式）
  final bool bannerShownReported;      // 本次运行是否已报过横幅曝光（3.3 用）
  // copyWith(...) 按需实现
}

final appUpdateControllerProvider =
    NotifierProvider<AppUpdateController, AppUpdateState>(AppUpdateController.new);

class AppUpdateController extends Notifier<AppUpdateState> {
  @override AppUpdateState build() => const AppUpdateState();   // 纯构造，不发请求
  /// 发一次检查。成功返回本平台判定；失败返回 null（状态保持上一次成功值不变，只更新 lastCheckedAt）。
  Future<UpdateDecision?> check(AppUpdateTrigger trigger);
  /// 回前台：lastCheckedAt 为 null（冷启动检查尚未发出）或距今 < 6h → 直接返回 null、不发请求；否则 check(resume)。
  Future<UpdateDecision?> onResumed();
  /// 设置页手动检查（3.4 调用）：无视冷却。
  Future<ManualCheckOutcome> checkManually();
  /// 记 72h 冷却：skippedVersion = 本平台最新版本号，skippedAt = env.now()；写 AppPrefs；bannerVisible 立刻置 false。
  Future<void> recordSkip();
  /// 横幅曝光去重（3.3 用）：本次运行首次调用返回 true 并置位，之后恒 false。
  bool markBannerShownReported();
  /// 本平台最新版本号 / 商店链接（info 为 null 时返回 null）。
  String? get latestForPlatform;
  String? get storeUrlForPlatform;
}
```
1. **并发去重**：已有检查在途时再调 `check` / `onResumed` / `checkManually`，复用同一个在途 `Future`，不发第二个请求。
2. **常量**写在 `app_version_check.dart`：`const Duration kUpdateCooldown = Duration(hours: 72);`、`const Duration kUpdateResumeCheckInterval = Duration(hours: 6);`。
3. `check` 流程：记 `lastCheckedAt = env.now()` → 取当前版本（失败 → 返回 null）→ `fetch()`（null → 返回 null）→ 读 AppPrefs 冷却两键 → 算 `decision` 与 `bannerVisible` → 一次性 `state = …`。
4. `checkManually`：调 `check(manual)`；null → `failed`；`forced` → `forced`；`recommended` → `recommended`（**冷却期内也返回 recommended**）；`none` → `upToDate`。

**AC5 — 冷却（存 `AppPrefs`）** `[L0]`
1. `AppPrefs`（`lib/core/storage/prefs.dart`）新增两键（AD-11 定名）：`petgo.update_skipped_version`（String）、`petgo.update_skipped_at`（int，UTC 毫秒时间戳）；新增 `String? get updateSkippedVersion`、`DateTime? get updateSkippedAt`（`DateTime.fromMillisecondsSinceEpoch(ms, isUtc: true)`）、`Future<void> setUpdateSkipped(String version, DateTime at)`。
2. 纯函数 `AppVersionCheck.cooldownActive({required String latest, String? skippedVersion, DateTime? skippedAt, required DateTime now})`：`skippedVersion`/`skippedAt` 任一为 null → false；`compareSemver(latest, skippedVersion) > 0`（服务端最新版本已上升）→ false；`skippedAt` 晚于 `now`（时钟被往回拨）→ false；`now.difference(skippedAt) < kUpdateCooldown` → true；否则 false。
3. `bannerVisible = decision == recommended && storeUrlForPlatform != null && !cooldownActive(...)`。强制态 `bannerVisible` 恒 false，且**强制态不受冷却影响**。
4. 单测：71h59m → 冷却中；72h → 不冷却；冷却中服务端从 1.3.4 升到 1.3.5 → 不冷却；`recordSkip()` 后 `bannerVisible` 立即 false 且 prefs 两键写入。

**AC6 — 触发时机** `[L0]` `[L2]`
1. 冷启动：`main.dart` 首帧回调链**末尾**（L141 `await TikTokClient.instance.start();` 之后）追加 `await AppUpdateBootstrap.runColdStartCheck();`。该回调由 `app.dart` `_TailTopiaAppState.initState`（L133 起，与 `PhoneSoftPrompt.register` 同段）注册：
   ```dart
   AppUpdateBootstrap.register(() async {
     final d = await ref.read(appUpdateControllerProvider.notifier).check(AppUpdateTrigger.coldStart);
     if (d == UpdateDecision.forced) await showForcedUpdateDialog(ref);
   });
   ```
   `AppUpdateBootstrap`（新建 `lib/features/notify/domain/app_update_bootstrap.dart`）：静态 `register(Future<void> Function())` + `runColdStartCheck()`（未注册 → 空转；内部 `try/catch` 吞掉一切异常，绝不影响启动）。理由同 `app.dart` L141-146 注释：main 的启动回调在 ProviderScope 之外，拿不到 ref。
2. 回前台：`app.dart` `didChangeAppLifecycleState`（L164-177）`resumed` 分支追加 `unawaited(_onResumeUpdateCheck())`，其中 `final d = await …onResumed(); if (d == UpdateDecision.forced) await showForcedUpdateDialog(ref);`，整体 try/catch 静默。**距上次检查 < 6 小时不产生任何网络调用**（PRD AC1）；冷启动检查尚未发出时（`lastCheckedAt == null`，例如 ATT / 推送系统框关闭触发的 resumed）也不发。
3. 不做登录后触发、不做关键流程前触发（PRD §3.3 b）。
4. 单测（fake repository 计数）：`onResumed` 在 `lastCheckedAt == null` → 0 次请求；5h59m → 0 次；6h → 1 次。

**AC7 — 强制更新弹窗（重做 + 不可跳过）** `[L0]` `[L2]`
1. `AppUpdateDialog` 重做为品牌卡片（UX-DR6，UI 稿 C2；样式数值见 Dev Notes「弹窗规格」，全部写死）：白卡圆角 24、顶部 64 紫色渐变图标块（手机 + 下载箭头 SVG）、标题 / 正文居中、版本标签 `updateVersionLabel`（「Versi {version}」，取**本平台最新版本号**）、整行主按钮 `updateGoStore`（「Perbarui sekarang」）。
2. 强制态：标题 `updateForceTitle`、正文 `updateForceBody`；**没有**「Nanti」；`barrierDismissible: false` + `PopScope(canPop: false)`（系统返回键、点遮罩都关不掉，PRD AC4）；点「Perbarui sekarang」跳商店后**弹窗不关闭**。
3. 推荐态外观（本 story 做完，3.4 调用）：标题 `updateRecommendTitle`、正文 `updateRecommendBody`，主按钮下方文字按钮 `updateLater`（「Nanti」）。
4. 本平台商店链接为空 → **不渲染**主按钮（PRD AC6）；强制态此时卡片无任何按钮（这是 3.1 校验要防止的配置，App 照实渲染）。
5. 新 API（取代旧 `show(context, decision, onGoStore)`）：
   ```dart
   static Future<void> show(BuildContext context, {required UpdateDecision decision,
       required String version, VoidCallback? onGoStore, VoidCallback? onLater});
   ```
   `onGoStore == null` → 不渲染主按钮。推荐态点「Nanti」→ 先 `Navigator.pop` 再调 `onLater`；推荐态 `barrierDismissible: true`、可返回键关闭（遮罩 / 返回关闭**不**记冷却、不报埋点）。
6. Key 保留：卡片 `appUpdateForced` / `appUpdateRecommended`、主按钮 `appUpdateGoStore`、文字按钮 `appUpdateLater`；新增版本标签 `appUpdateVersionLabel`、图标块 `appUpdateIcon`。
7. 强制态弹出由新文件 `lib/features/notify/presentation/app_update_presenter.dart` 的 `Future<void> showForcedUpdateDialog(WidgetRef ref)` 负责：
   - 若当前路由仍是 `/splash`（`ref.read(routerProvider).routerDelegate.currentConfiguration.uri.path == '/splash'`），先等它离开 `/splash`（`routerDelegate.addListener` 一次性监听，最多等 10 秒，超时照常继续）——**原因**：splash 交棒时 `go(...)` 会替换页面栈，挂在 splash 页上的弹窗会被一起移除。
   - 进程内静态标记 `_forcedShowing`：已在显示 → 直接返回（回前台再判定强制不会叠第二个）。
   - 取 `rootNavigatorKey.currentContext`（`core/router/app_router.dart`）；null 或未 mounted → 返回。
   - 弹出前报埋点（AC9）；在弹出调用**正上方**留一行注释 `// LEDGER-HOOK(5.3): 强制更新弹窗真正出现时登记 startupPopupLedger`，**本 story 不实现登记**。
8. L0 widget 测试（改写 `test/notify/app_update_dialog_test.dart`）：强制态无 `appUpdateLater`、点遮罩后卡片仍在、`tester.binding.handlePopRoute()` 后卡片仍在、点主按钮回调被调用且卡片仍在；推荐态有「Nanti」，点后卡片消失且 `onLater` 被调用；`onGoStore: null` → 找不到 `appUpdateGoStore`；版本标签文案 = `Version 1.3.4`（en）/ `Versi 1.3.4`（id）。结构断言：卡片 `BorderRadius.circular(24)`、图标块尺寸 64×64；**不写 golden**。

**AC10 — 失败放行** `[L0]`

### 关键设计点

- **为什么版本号修复必须先于强制更新**（PRD §3.3 🔴）：`kAppVersion` 恒为 1.0.0，若先启用强制更新，全量用户会被锁进不可跳过的弹窗。本 story 同时做两件事，但 AC1 的 L2 真机验证是**上线前置条件**（`minSupportedVersion` 默认 1.0.0 永不上调，本版本上线本身不会触发强制态）。
- **`lastCheckedAt` 记「发出请求」时刻、失败也记**：避免弱网下每次回前台都打一次接口；代价是冷启动失败后 6 小时内不再自动重试（手动检查不受限）。
- **resumed 的坑**：iOS 上 ATT / 通知权限系统框关闭会触发 `resumed`，此时冷启动检查还没发（排在启动链末尾）。所以 `onResumed` 在 `lastCheckedAt == null` 时必须空转，否则冷启动会出现两次请求、甚至两次判定。
- **强制弹窗为什么等离开 `/splash`**：splash 交棒用 `ctx.go(...)`（`app_router.dart` L486-530），go_router 替换页面栈时挂在旧页上的无页路由（dialog）会被一起移除，强制弹窗就「闪一下没了」。
- **推荐态冷启动不弹窗**（PRD AC3b）：`check(coldStart)` 返回 `recommended` 时 app.dart 回调**什么都不做**，横幅由 3.3 读 `bannerVisible` 自己出现。
- **控制器不持有 BuildContext**：弹窗与跳商店在 `app_update_presenter.dart`，控制器只管数据与冷却，便于纯单测。
- **功能弹窗登记（Epic 5 依赖）**：强制更新弹窗属于「功能弹窗」，要登记进 Epic 5 新建的「本次冷启动功能弹窗记录」（AD-12）。**本 story 只预留调用点注释 `// LEDGER-HOOK(5.3)`（见 AC7.7），登记由 5.3 负责**；5.3 会 grep 这个标记接入。供参考：D-6 定 iOS ATT 也算功能弹窗（与本 story 无直接关系）。
- **AppPrefs 没有 provider**：项目惯例是 `AppPrefs.create()` ad-hoc 创建（`push_permission_providers.dart` L11-13 注释），本 story 经 `AppUpdateEnv.loadPrefs` 注入，测试用 `SharedPreferences.setMockInitialValues`。
- **不新增 Flutter 依赖**（NFR10）：`package_info_plus`、`url_launcher`、`flutter_svg`、`shared_preferences` 均已在 `pubspec.yaml`。
