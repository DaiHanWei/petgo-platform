## Story

As a 发帖用户,
I want 点赞和评论通知告诉我是谁、同一帖子的多个赞合成一条,
so that 通知不再是一串看不出内容的「有人赞了你」。

**AC3 — `NotificationService.sendInteraction`：写入、聚合、角标** `[L0]` `[L1]`（AD-9）
1. 新增方法（`NotificationService.java`，`@Transactional(propagation = Propagation.REQUIRES_NEW)`，理由同 `send` 的 javadoc :63-69）：
   ```java
   public Notification sendInteraction(long recipientUserId, NotificationType type, long actorUserId,
           String aggregateKey, String targetRef, Long commentId, String variant, String pushBodyText)
   ```
   `pushBodyText` 只用于推送正文（评论 / 回复原文），**不落库**；其余类型传 `null`。
2. `aggregateKey == null`（评论、回复、新粉丝）：新建一行（`deepLinkType = type.name()`、不可枚举 `deepLinkToken` 用既有 `generateToken()`、`targetRef`、`commentId`、`variant`），插一行 `notification_actors(actor, now())`，`bumpUnreadBadge` +1。
3. `aggregateKey != null`（点赞，Story 3.2 起含场所评论）：**同一条 SQL 原子完成「有未读同键行则合并，否则新建」**——推荐 `INSERT … ON CONFLICT (recipient_user_id, aggregate_key) WHERE is_read = false AND aggregate_key IS NOT NULL DO UPDATE SET created_at = now(), updated_at = now() RETURNING id, (xmax = 0) AS inserted`（`JdbcTemplate`，与 JPA 同事务）；然后 `INSERT INTO notification_actors … ON CONFLICT (notification_id, actor_user_id) DO NOTHING`：
   - 新建（`inserted = true`）→ 角标 +1；
   - 合并（`inserted = false`）→ **角标不动**、时间刷新（`created_at` 也刷新，列表按 `created_at DESC, id DESC` 排序才会移到最上）、同一人不重复加 actor；
   - 已读后再来 → 部分唯一索引不再命中 → 新建一条。
   - 若不用 upsert 而用「先查后插」，必须捕获唯一冲突后**在新事务里重试一次**（Postgres 冲突后当前事务已中止，不能原地继续）。任一实现都必须满足 AC6.3 的并发用例。
   - ⚠️ `Notification.createdAt` 是 `updatable = false`（`Notification.java:53`），刷新时间只能走原生 SQL，不要改实体映射。
4. 落库 `title` / `body`：沿用现有兜底串（如点赞「有人赞了你的内容」/「点击查看」），**不含昵称、不含评论原文**（AD-3：昵称读取时现查；评论原文由 Story 3.3 按 `comment_id` 现查，评论删掉后不在通知表里残留）。
5. 既有 `send` / `sendWithoutPush` / `sendWithCopy` 行为不变；抑制（拉黑 / 隐藏）**不写进** `sendInteraction`，仍在各监听器里（`ContentNotifyListener` 类注释 :30-36 的约束同样适用于新方法）。

**AC4 — 点赞 / 评论 / 回复改走 `sendInteraction`** `[L0]` `[L1]`（FR-141.5 / 141.7 / 141.9）
