> 2026-10-15。后台三页最初在无后台 PRD / UI 稿时自设计实现（spec-ab-22/30/31）。文档到位后用户拍板：**与文档冲突处一律以文档为准**。

## 0. 已定的歧义（按推荐执行，2026-10-15）

1. **弹窗状态模型**：表仍存 `ACTIVE` / `DISABLED`，展示合一：`DISABLED` → 已停用；否则按时间阶段 未开始 / 进行中 / 已结束。新建直接 `ACTIVE`。App 候选口径不变。
2. **只有「未开始」可删**：条件 = `ACTIVE` 且 `now < starts_at` 且 `ops_popup_impressions` 无记录（挡住上线后又把开始时间后移）。已停用且未到开始时间 → 只能启用不能删。
3. **新 / 老用户的 N 天**：选新用户或老用户时都可编辑 N，共用一个值；列表显示「新用户（N 天内）」/「老用户（N 天以上）」。
4. **EN 按钮文案、结束时间必填**：只在后台强制，表结构与 App 回落逻辑不动（不加迁移）。
5. **按条件筛选的注册 / 活跃时间**：改为相对预设 不限 / 近 7 天 / 近 30 天 / 近 90 天，在 `AudienceSpec` 与 `OpsAudienceSql` 增加相对键（如 `registeredWithinDays` / `activeWithinDays`），保证定时发送「按实际发送时刻圈人群」。旧的绝对日期键保留兼容解析。
6. **宠物物种**：单选下拉 不限 / 猫 / 狗 / 其他。
7. **跳过原因**：4 类照稿（不存在 / 已注销 / 已封号 / 虚拟号）；兽医、管理员、停用账号并入「不存在」。
8. **G4 输入确认**：最低支持版本任何改动（上调或下调）都走 G4，标题按方向显示「确认上调…」/「确认修改…」，按钮同理。
9. **最低版本权限**：端点仍要求 `config.edit`，改「最低支持版本」额外要求新码；无新码时该行只读，其余字段可改。
10. **AB-22 卡片位置**：照稿放在「一次性解锁定价」卡之后。
11. **立即发送 toast**（稿缺）：「已提交，正在发送（操作留审计）」。
12. **三语**：中文照稿；EN / ID 出初稿待复核。跳转类型、App 页面等共享文案键 AB-30 / AB-31 共用。
