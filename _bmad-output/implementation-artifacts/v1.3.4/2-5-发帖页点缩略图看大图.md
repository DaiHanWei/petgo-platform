# Story 2.5: 发帖页点缩略图看大图

Status: ready-for-dev

> 版本 V1.3.4 · 主题 app · Epic 2「发图不丢画面」· FR-139.1 ~ 139.8 · AD-9 · UX-DR4 · UI 稿 B1–B5
> 纯 App，只改发帖页缩略图格子的点击入口；**灯箱组件零改动**，无后端、无数据模型变更。

## Story

As a 发帖用户,
I want 发布前点已选图片的缩略图，全屏查看完整图片,
so that 我能确认图片细节再发。

## Acceptance Criteria

**AC1 — 点第 N 张打开灯箱定位第 N 张，顺序 = 格子顺序** `[L0]`
1. 发帖页已选 4 张图，点第 2 张缩略图 → 调 `ImageLightbox.openMemory(context, images: <controller.items 按当前顺序的 bytes>, initialIndex: 1, heroTagPrefix: 'publish_compose', source: 'publish_compose')`；
2. 灯箱内左右滑依次查看全部 4 张，顺序与格子一致；
3. 拖拽重排后（`controller.reorderImage` 落定）再点开，`images` 顺序为新顺序（PRD AC1，AD-9）。

**AC2 — 完整原图，不套 Feed 窗口** `[L0]`
传给灯箱的是 `ImageUploadItem.bytes` 本身（`ImageProcessor` 处理后的完整图，2.4 起不再物理裁剪），**不读** `cropOffset`；超宽 / 超长图在灯箱里完整显示（灯箱 `BoxFit.contain`，PRD AC2）。`[L2]` 模拟器看 3:1 全景完整显示（UI 稿 B3）。

**AC3 — 关闭回发帖页，内容全保留** `[L0]` · `[L2]`
单击图片或黑边、下滑、点 ✕、系统返回键都关闭灯箱回到发帖页；`controller.items`（数量、顺序、每张 `cropOffset` / 上传状态）、正文、类型、同步开关**全部不变**（PRD AC3 / AC7）。双击为缩放、不关闭；灯箱内无删除 / 重排 / 设封面按钮——以上均为灯箱既有能力，本 story 只做回归断言。

**AC4 — 点 ✕ 只删除；长按仍拖拽** `[L0]`
1. 点格子右上 ✕ → 只 `controller.removeImage(index)`，**不**打开灯箱；
2. 长按仍触发 `LongPressDraggable` 拖拽重排，松手后不打开灯箱；
3. 上传在途（`canReorder == false`，拖拽入口不挂）时，点缩略图**仍能**打开灯箱（PRD AC4）。

**AC5 — 上传中 / 上传失败的图同样可点开** `[L0]` · `[L2]`
`status` 为 `pending` / `uploading`（黑 38% 遮罩 + 转圈）或 `failed`（右上红色 ⚠）的格子，点击同样打开灯箱看本地字节，不依赖上传结果（PRD AC5，UI 稿 B5）。

**AC6 — 键盘弹起时第一次点只收键盘** `[L0]`
正文输入中、键盘弹起（`View.viewInsets.bottom > 0`）时点缩略图：本次只收键盘、不打开灯箱；再点一次才打开（由 `ImageLightbox.openMemory` 内置的 `_keyboardSwallowsTap` 完成，bug 507 规则，本 story 不另写逻辑）。

**AC7 — 埋点** `[L0]`
打开时上报 `lightbox_opened {source: 'publish_compose'}`，关闭时 `lightbox_dismissed` 的 `source` 同为 `publish_compose`（灯箱既有上报，本 story 只传 `source`；PRD §4，不新增事件）。

**AC8 — 视觉** `[L2]`
被点的格子**不加任何标记**（UI 稿 B1「框内零解释」）；灯箱外观同帖子详情灯箱（纯黑、左上 ✕、顶部「2 / 4」页码胶囊，UI 稿 B2）。

### 关键设计点

- **只加入口，不改灯箱**（PRD 边界、AD-9）：手势（单击关 / 双击缩放 / 下滑关 / ✕ / 返回键）、键盘规则、埋点都是灯箱既有能力。
- **下标用 controller 真实下标**：`_thumb` 收到的 `index` 本就是 `controller.items` 的下标（预览让位只影响摆放位置），灯箱 `images` 也按 `controller.items` 现取，二者天然对齐；拖拽进行中不会有点击（长按已被拖拽占用）。
- **✕ 与格子点击互斥**：靠 Flutter 点击竞技场「更深的识别器先胜出」，不需要 `AbsorbPointer` 或手动 stopPropagation。
- **内存**：`openMemory` 用 `PageView` 懒加载，不一次解码全部（PRD 影响面）；本 story 不改。

### 本 story 不做

- **发帖页上传失败的图：⚠ 与 ✕ 叠在同一角（UI 稿 B5 画为失败时无 ✕）——本版不处理，保持现状，两个图标都在（决策日志 D-14，已记入待办 / AD §13 第 4 条）**；B5 只示意「失败的图也能点开看大图」；
- 灯箱内不加删除 / 重排 / 设封面 / 调整露出位置；
- 只覆盖发帖页：评论、场所评论、客服工单等其它带图输入框不在范围（PRD 边界）；
- 不改缩略图解码尺寸（`cacheWidth: 400`）。

### 必须新增的测试（`test/content/publish_preview_lightbox_test.dart`，全部 L0）

照 `publish_reorder_test.dart` 的 `pumpGrid` 搭（`publishControllerProvider.overrideWithValue(c)`、`uploadOne` 用永不完成的 `Completer` 或立即成功，按用例需要），`Analytics.debugCaptureSink` 抓事件。

1. 4 张图，点 `publishThumb_1` → `pumpAndSettle` 后 `find.byType(ImageLightbox)` 恰一个，其 `initialIndex == 1`、`images` 长度 4 且逐个 `identical(controller.items[i].bytes)`、`source == 'publish_compose'`；事件含 `('lightbox_opened', {'source': 'publish_compose'})`。
2. 关闭（`await tester.binding.handlePopRoute()` + `pumpAndSettle`）→ 无 `ImageLightbox`；`controller.items` 长度与顺序不变、正文（先 `enterText` 一段）不变；事件含 `lightbox_dismissed` 且 `source == 'publish_compose'`。
3. `controller.reorderImage(3, 0)` 后点 `publishThumb_0` → 灯箱 `images[0]` 与 `controller.items[0].bytes` `identical`（即原第 4 张）。
4. 点 `publishRemoveImage_2` → `controller.items.length == 3` 且 `find.byType(ImageLightbox)` 为 0。
5. 上传在途（`uploadOne` 挂起 + `unawaited(c.uploadAll())` 使 `canReorder == false`，照本仓 `publish_reorder_test.dart` L422 用例造法）→ 无 `LongPressDraggable`，点缩略图仍打开灯箱。
6. 失败态：`uploadOne` 抛异常、`await c.uploadAll()` 后某格为 `failed`（`find.byIcon(Icons.error)` 可见）→ 点该格打开灯箱，`initialIndex` 正确。
7. 键盘：`tester.view.viewInsets = const FakeViewPadding(bottom: 300)` 且正文框聚焦 → 点缩略图无灯箱；`viewInsets` 归零后再点 → 打开。
8. 长按 `publishThumb_0` 并原地松手（`tester.longPress`）→ 不打开灯箱。
