# Story 6.3: 通知中心显示运营通知并按配置跳转

Status: review

## Story

As a 用户,
I want 在通知中心看到运营发来的消息原文，点开去到对应页面,
so that 我能看懂并参与活动。

> 范围：纯 App（`petgo_app/`）。后端在 Story 6.1（`OPS_ANNOUNCEMENT` 类型、列表项 `opsTarget`）与 6.2（发送）已交付；跳转复用 Story 5.2 的统一跳转目标：模型 `OpsTarget`（`petgo_app/lib/features/ops/domain/ops_target.dart`，含 `OpsTarget.fromJson` / `OpsTarget.none`）与执行入口 `openOpsTarget`（`petgo_app/lib/features/ops/presentation/open_ops_target.dart`）（AD-16）。**本 story 不另建任何目标模型、解析或跳转逻辑。**

### 关键设计点

- **本地化规则的唯一例外**：项目铁律是「App 绝不渲染后端显示串、按 code / type 本地化」——因为其它类型的后端串是服务端语言、会泄漏到印尼语界面。运营通知不同：①内容由运营每次填写，App 无从本地化；②后端写入时已按收件人 `users.locale` 选好 EN / ID（6.1 AC5），推送与通知中心同一语言。所以**只对 `OPS_ANNOUNCEMENT` 例外**读 `item.title / item.body`，并在代码注释里写明理由，防止后来者把例外扩散到其它类型。
- **按账号语言，不按 App 当前语言**：PRD §3.7「显示语言按账号语言」。账号语言每次冷启动由 `MeService.captureLocale` 从 App 请求语言同步，通常与 App 当前语言一致；已知差异（系统语言为第三语言）本版不处理。
- **推送不直达**：沿用 2026-08-07 规则（先落通知中心、标已读，再点才跳），`pushPayloadToLocation` 对本类型返回通知中心，不加分支。
- **旧版 App**：未升级的客户端遇到 `OPS_ANNOUNCEMENT` 走既有 `_` 兜底（「Notifikasi sistem」+ 中性正文、点击落通知中心不动），不崩——可接受。
- **campaign_id 通过 scrub**：键名 `campaign_id` 不在 `_piiKeys` / `_freeTextKeys`，值为 32 位 token（< 64 字符上限），不会被剥离。
