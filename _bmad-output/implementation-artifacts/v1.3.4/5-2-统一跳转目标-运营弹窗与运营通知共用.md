# Story 5.2: 统一跳转目标（运营弹窗与运营通知共用）

Status: ready-for-dev

## Story

As a 用户,
I want 点运营弹窗或运营通知后，准确跳到运营配置的页面,
so that 我能直接看到活动内容。

> 本 story **只做 App**：跳转目标的数据模型 `OpsTarget`、纯函数解析 `resolveOpsTarget`、执行入口 `openOpsTarget`。后端的目标类型枚举与校验 `OpsTargetPolicy` 已在 Story 5.1 交付；本 story 的取值集合必须与之**逐字一致**。Story 5.4（运营弹窗）与 Story 6.3（通知中心运营通知）直接调用本 story 的 `openOpsTarget`，**不得各写一份跳转**。

## Acceptance Criteria

**AC1 — 数据模型 `OpsTarget`** `[L0]`
1. 新建 `petgo_app/lib/features/ops/domain/ops_target.dart`：
   - `enum OpsTargetType { none, product, category, appPage, external }`，`wire` 分别为 `NONE` / `PRODUCT` / `CATEGORY` / `APP_PAGE` / `EXTERNAL`；
   - `enum OpsAppPage { home, publish, toko, knowYourPet, health }`，`wire` 分别为 `HOME` / `PUBLISH` / `TOKO` / `KNOW_YOUR_PET` / `HEALTH`（**只这 5 个**，PRD 补充细则）；
   - `class OpsTarget { final OpsTargetType type; final String? value; }`，`static const none = OpsTarget(OpsTargetType.none, null)`；
   - `factory OpsTarget.fromJson(Map<String, dynamic>? json)`：解析后端 `{"type": "...", "value": "..."}`（Story 5.1 AC3.5 / Story 6.1 `opsTarget`）。`json == null`、`type` 缺失或不是五值之一（区分大小写）→ `OpsTarget.none`；`value` 非字符串 → 当作 null。
2. 解析**不做**可用性判断（是否有效交给 AC2），`fromJson` 绝不抛异常。

**AC2 — 纯函数 `resolveOpsTarget(OpsTarget) → OpsTargetAction`** `[L0]`
新建 `petgo_app/lib/features/ops/domain/ops_target_action.dart`，`sealed class OpsTargetAction`，按下表映射（与架构 AD-16 一致；值校验与后端 `OpsTargetPolicy.isWellFormed` 同口径）：

| 目标 | 值校验（不通过 → `OpsNoAction`） | 动作 | 需登录 |
|---|---|---|---|
| `NONE` | — | `OpsNoAction` | — |
| `PRODUCT` | 匹配 `^[0-9A-Za-z_-]{1,32}$` | `OpsPushAction('/shop/products/{value}')` | 否 |
| `CATEGORY` | ∈ `ShopCategory.values.map((c) => c.api)`（`MAKANAN` / `OBAT_VITAMIN` / `CAMILAN` / `PERAWATAN`，区分大小写） | `OpsGoAction('/shop?category={value}')` | 否 |
| `APP_PAGE` = `HOME` | 值严格等于五个 wire 之一 | `OpsGoAction('/home')` | 否 |
| `APP_PAGE` = `PUBLISH` | 同上 | `OpsOpenPublishAction()` | **是** |
| `APP_PAGE` = `TOKO` | 同上 | `OpsGoAction('/shop')` | 否 |
| `APP_PAGE` = `KNOW_YOUR_PET` | 同上 | `OpsPushAction(PetInsightsRoutes.hub)`（= `/profile/pet-insights`） | **是** |
| `APP_PAGE` = `HEALTH` | 同上 | `OpsPushAction('/profile/health')` | **是** |
| `EXTERNAL` | 长度 ≤ 512；`Uri.tryParse` 非空；`scheme.toLowerCase()` ∈ {`http`, `https`}；`host` 非空 | `OpsExternalAction(uri)` | 否 |

- `OpsPushAction` / `OpsOpenPublishAction` 带 `bool requiresLogin`；其余动作恒不需要登录。
- 不认识的 `APP_PAGE` 值（如 `SETTINGS`、小写 `home`）、`javascript:` / `ftp:` / 无 host 的外链 → `OpsNoAction`（PRD「只接受这 5 个值，其他值视为无效、不跳转」）。

**AC3 — 执行入口 `openOpsTarget(BuildContext context, WidgetRef ref, OpsTarget target, {OpsUrlLauncher? launcher})`** `[L0]` `[L2]`
新建 `petgo_app/lib/features/ops/presentation/open_ops_target.dart`，返回 `Future<void>`，**任何情况都不抛异常、不弹错误提示**（PRD「目标为 NONE 或目标值无效 → 不跳转、不报错」）。
1. 导航统一用根 Navigator 的 context：`final nav = rootNavigatorKey.currentContext;`（`core/router/app_router.dart` L119），为 null 或 `!nav.mounted` → 直接返回。调用方（弹窗）可能在调用前已把自己关掉，所以**不得**用调用方传入的 `context` 做导航；传入的 `context` 只用于 `requireLogin` 弹登录框前的 `mounted` 判断。
2. `OpsNoAction` → 直接返回。
3. `OpsGoAction(loc)` → `nav.go(loc)`（Tab 根必须 `go`，`push` 会二次构建 StatefulShellRoute → GlobalKey 撞车白屏，见 `DeepLinkRoutes.shellTabRoots` 注释）。
4. `OpsPushAction(loc)` → `nav.push(loc)`。
5. `OpsOpenPublishAction` → `PublishComposePage.open(nav)`（不传 preset，由发布页按有无档案决定，同 `app_shell.dart` L252 `addButtonPreset` 的职责边界）。
6. 需登录且当前是游客（`!ref.read(authControllerProvider).isLoggedIn`）→ `requireLogin(ref, nav, entrySource: 'ops_target', pendingAction: RouteIntent(onResume: …))`，`onResume` 内**重新取** `rootNavigatorKey.currentContext` 再执行第 4 / 5 条的动作（登录成功后继续进入目标页；新用户先走 onboarding，由既有 `resumePendingAfterOnboarding` 续上）；被拦下时补报既有事件 `Analytics.capture('login_guide_entry_blocked', {'entry': 'ops_target'})`（与 `app_shell.dart` L154-156 同一规则）。**不得**直接 `push` 受控路由——路由守卫会把游客改写回 `/home`（`redirectWouldRewrite`）。
7. 已登录且角色为 VET（`isVet`）→ 一律 `OpsNoAction` 处理（兽医端不承接用户侧页面）。
8. `OpsExternalAction(uri)` → 先 `launcher(uri, LaunchMode.inAppBrowserView)`（iOS SFSafariViewController / Android Chrome Custom Tabs，**系统默认配色、不传任何颜色参数**，D-9）；返回 `false` 或抛异常 → 再 `launcher(uri, LaunchMode.externalApplication)`（设备不支持时退回系统浏览器，FR-137.3）；再失败 → 静默返回。默认 `launcher = (u, m) => launchUrl(u, mode: m)`；`typedef OpsUrlLauncher = Future<bool> Function(Uri uri, LaunchMode mode);`。
9. **不新增任何 Flutter 依赖**（`url_launcher` 已在 `pubspec.yaml` L57，锁定 6.3.2 / android 6.3.32 / ios 6.4.1，已支持 `inAppBrowserView`）；**不扩展** `tailtopia://` 外部深链（`app.dart` 的 `deepLinkToLocation` 与 AndroidManifest `<intent-filter>` 不动，NFR10）。

**AC5 — 单测覆盖全部类型** `[L0]`
1. `test/ops/ops_target_test.dart`：`fromJson` 五类型、未知类型、`null`、`value` 非字符串；`resolveOpsTarget` 按 AC2 表逐行断言（含全部非法值用例：`APP_PAGE` 的 `home` / `SETTINGS`、`CATEGORY` 的 `makanan` / `FOOD`、`PRODUCT` 的空串 / 33 位 / 含 `/`、`EXTERNAL` 的 `javascript:alert(1)` / `ftp://a.b` / `https://` / `HTTPS://promo.tailtopia.id`（合法）/ 513 字符）。
2. `test/ops/open_ops_target_test.dart`（widget 测试，`MaterialApp.router` + 以 `rootNavigatorKey` 为 `navigatorKey` 的测试 GoRouter，含 `/home`、`/shop`、`/shop/products/:token`、`/profile/pet-insights`、`/profile/health` 占位页）：
   - `go` 类：落点 `uri.toString()` 分别为 `/home`、`/shop`、`/shop?category=MAKANAN`；
   - `push` 类：已登录时栈顶为对应占位页且可 `pop` 回原页；
   - 游客点 `KNOW_YOUR_PET` / `HEALTH` / `PUBLISH`：出现 `LoginHardDialog`、路由不变、`login_guide_entry_blocked{entry: ops_target}` 经 `Analytics.debugCaptureSink` 捕获到一次；
   - 游客点 `PRODUCT` / `CATEGORY` / `HOME` / `TOKO`：直接跳转、不弹登录；
   - `EXTERNAL`：fake launcher 记录调用序列——第一次 `inAppBrowserView`；fake 返回 false → 第二次 `externalApplication`；fake 抛异常 → 同样退回且 `openOpsTarget` 不抛；
   - `NONE` / 非法值：路由不变、launcher 零调用、不抛。

### 关键设计点

- **为什么拆「纯函数解析 + 执行」两层**：映射表（哪种目标去哪儿、要不要登录、值合不合法）是本 story 的全部业务规则，必须能在 L0 逐行断言；执行层只剩「拿根 context 去 go / push / launch」。Story 6.3 的通知中心点击直接复用同一张表，口径天然一致。
- **为什么用根 Navigator 的 context**：弹窗场景下调用方先 `pop` 自己再跳，原 context 已失效；通知中心场景下页面 context 有效但用根 context 也等价。统一用根 context 消除两处差异。
- **需登录页面用 `onResume` 而不是 `location`**：`RouteIntent.run` 遇 `location` 走 `context.go`，会替换整个栈——`/profile/pet-insights`、`/profile/health` 是 shell 外的顶层路由，`go` 过去之后没有返回栈，按返回键直接退出 App（`app_router.dart` `goDeepLinkFromLiveApp` 注释记录过同一事故）。
- **外链只认 http/https**：防运营误填 `javascript:` / `intent:` / 自定义 scheme 被系统接管；与后端 `OpsTargetPolicy` 同口径，双端各拦一次。
- **App 内浏览器不着色**（D-9）：`url_launcher` 的 `inAppBrowserView` 不支持改色；作废 UI 稿 D3 / D3b 的品牌紫。不得为着色引入 `flutter_custom_tabs` 等依赖。
- **VET 不跳**：兽医账号走 `/vet/*` 工作台，用户侧页面会被角色守卫改写；正常情况下兽医看不到运营弹窗 / 运营通知，这里是兜底。
