# Story 1.8: 付费落点与详情页按钮统一为「Buka HD」

Status: ready-for-dev

> 版本 v1.3.4 · 主题 ktp · 分支 `feat/1.3.4-ktp-revamp`
> 口径优先级：`决策日志-ktp.md` > `PRD-v1.3.4-ktp.md` > `architecture-v1.3.4-ktp-delta.md` > `ui-v1.3.4-ktp.html`（均在 `_bmad-output/planning-artifacts/v1.3.4/`）
> 前置：Story 1.1（`card_variant` 列 / 字段）、Story 1.2（`IdCardStyle` 注册表）、Story 1.6（共享函数 `openIdCardHdPaywall` + `id_card_buka_hd_tapped` / `id_card_paywall_dismissed` 埋点）。本 story **复用** 1.6 的共享函数，把建卡页与详情页两个入口切过去。

## Story

As a 用户,
I want 建完卡无论付不付费都能直接看到这张新卡,
so that 我不会回到建卡页重复建卡。

## Acceptance Criteria

**AC1 — 建卡后付费落点（`entry = create`）** `[L0]` `[L2]`（FR-142F.4，AD-10，UI 稿 C2 → E1 → G1 / G2）
1. `IdCardCreatePage._create` 建卡成功后调用 `openIdCardHdPaywall(context, ref, card, entry: IdCardPaywallEntry.create)`，删除页内私有的 `_openPayment`（`id_card_create_page.dart:358-418`）。
2. 共享函数返回后（`mounted` 时）**一律** `context.pushReplacement('/profile/id-cards/${card.id}')`，替换掉现在的 `context.pop()`（`:354`）：
   - 关闭抽屉（未选渠道 / 系统返回）→ 新卡详情，未解锁态（水印预览 +「Bagikan」+「Buka HD」，G1）；
   - PawCoin 当场成功 / QRIS 到账 → 新卡详情，已解锁态（「✓ HD」行 +「Bagikan」+「Unduh HD」，G2）+ SnackBar `idCardHdUnlockedToast`（落到详情页后可见）；
   - 其余结局（PawCoin 余额不足 409、网络失败、QRIS 二维码页未到账即关闭、QRIS pending）→ 同样替换到新卡详情（未解锁态），原有错误 SnackBar 照常（见「待确认」）。
3. 建卡页出栈：在详情页按返回 → 回到列表页（`PetInsightsRoutes.idCard`），**不会**回到建卡页；列表页仍停在用户进入建卡页前所在的「Pilih Kartu」Tab；列表含这张新卡（`idCardListProvider` 已失效重拉）。
4. 落到详情时详情数据为最新：成功路径下 `idCardDetailProvider(card.id)` / `idCardListProvider` 已失效（由共享函数负责；PawCoin 成功同时失效 `pawCoinProvider`），详情页不出现「已付费却仍显示 Buka HD」。

**AC2 — 详情页入口（`entry = detail`）** `[L0]` `[L2]`（FR-142F.5，UI 稿 G1 → E1 → G1 / G2）
1. `IdCardDetailPage._onDownloadHd`：未解锁时调用 `openIdCardHdPaywall(context, ref, card, entry: IdCardPaywallEntry.detail)`，删除页内私有的 `_openHdPaywall`（`id_card_detail_page.dart:297-330`）与 `_purchaseHd`（`:332-378`）；已解锁时仍直接 `_exportHd()`（不变）。
2. 关闭抽屉 → 留在详情页，无跳转、无提示。
3. 付费成功（PawCoin 当场 / QRIS 到账）→ 留在详情页，详情重拉后右侧按钮由「Buka HD」变「Unduh HD」，出现「✓ HD」行，SnackBar `idCardHdUnlockedToast`。成功后是否仍自动弹出导出选单（现状 `_purchaseHd` 成功即 `_exportHd()`）**本 story 默认保留现状**，见「待确认」。
4. 共享函数执行期间右侧按钮显示转圈且不可点（保持现状 `_hdBusy` 行为），结束后恢复。

**AC3 — 按钮文案「Buka HD」** `[L0]`（FR-142F.1 / F.2，UX-DR9，UI 稿 G1）

**AC4 — 三入口共用一个付费抽屉** `[L0]` `[L2]`（FR-142F.3 / F.6 / F.7，UI 稿 E1 ~ E4）
1. `id_card_create_page.dart` 与 `id_card_detail_page.dart` 中不再出现 `showModalBottomSheet<HdPayChannel>`、`HdPaywallSheet(`、`purchaseHdForCard(`、`showQrPaymentSheet(`、`KtpUnlockAnalytics.` 的直接调用——全部经 `openIdCardHdPaywall`（`lib/features/profile/presentation/id_card/id_card_hd_flow.dart`）。

**AC5 — 付费埋点（App）** `[L0]`（AD-12，PRD §4）
1. 详情页点「Buka HD」（仅未解锁时）→ `id_card_buka_hd_tapped{card_type, entry: 'detail'}`；点「Unduh HD」不报。
2. 抽屉未付款关闭 → `id_card_paywall_dismissed{card_type, entry}`，`entry` 取 `create` / `detail`。
3. 既有 `ktp_unlock_paywall_shown` / `ktp_unlock_started` / `ktp_unlock_failed` 在 `create` / `detail` 两个入口也带 `entry` + `card_type` + `card_variant`（与 1.6 的 `list_badge` 同口径；`card_variant` 非学生卡无值时不带键）。

**AC6 — 服务端 `ktp_unlock_succeeded` 补卡种** `[L0]`（AD-12）

3. `AnalyticsEventGuard.ALLOWED_PROPERTY_KEYS` 增加 `"card_type"`、`"card_variant"`（注释写明 V1.3.4 Story 1.8、值为枚举名、不带卡号 / 宠物名）。

### 架构约束

- AD-10：付费抽屉打开与成功处理只有一份（`openIdCardHdPaywall`），落点按 `entry` 区分：`create` → 关闭或成功都 `pushReplacement` 新卡详情；`detail` → 留详情；`list_badge` → 留列表（1.6）。
- AD-6：卡种 / 配色 / `card_style` 一律从 `IdCardStyle` 注册表取，页面里不写 switch。
- AD-12：成功只由服务端报；服务端补 `card_type` / `card_variant`（PawCoin 事件带卡 id，QRIS 由意图反查）；`AnalyticsEventGuard` 白名单同步。
