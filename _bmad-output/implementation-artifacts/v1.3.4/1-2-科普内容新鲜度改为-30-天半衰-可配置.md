## Story

### 打分器改法（写死）

```java
/** 新鲜度：半衰期 h 小时 ⇒ h 小时衰减到 0.5、2h 到 1/3。⚠️ 未来时间按 0 小时算；halfLifeHours 须 > 0（调用方保证）。 */
static double freshness(Instant createdAt, Instant now, double halfLifeHours) {
    if (createdAt == null) {
        return 0d;
    }
    double hours = Duration.between(createdAt, now).toMillis() / 3_600_000d;
    if (hours < 0) {
        hours = 0;
    }
    return 1d / (1d + hours / halfLifeHours);
}

/** 半衰期按内容属性（= 内容类型）取，不按所在槽位：科普用配置值，其余固定 24 小时（V1.3.4 FR-122.3）。 */
static double halfLifeHours(RankCandidate c, RankParams p) {
    return c.attribute() == FeedAttribute.EDU
            ? p.eduFreshnessHalfLifeHours()
            : RankParams.DEFAULT_FRESHNESS_HALF_LIFE_HOURS;
}

static double contentScore(RankCandidate c, Instant now, RankParams p) {
    return p.freshnessWeight() * freshness(c.createdAt(), now, halfLifeHours(c, p))
            + p.interactionWeight() * interaction(c.likes(), c.comments(), p);
}
```

服务层兜底：
```java
private static double eduHalfLife(FeedRankConfig cfg) {
    double v = cfg.getEduFreshnessHalfLifeHours();
    // 🛡 库里有 CHECK > 0；这里只为 mock / 脏数据兜底 —— 0 会除零、负数会让越老的科普分越高。
    return v > 0 ? v : RankParams.DEFAULT_EDU_FRESHNESS_HALF_LIFE_HOURS;   // NaN > 0 为 false，同样回落
}
```

### 关键设计点

- **为什么放进 `RankParams` 而不是另传参数**：引擎与打分器是纯函数（`FeedRankEngine` 类注释 L18-26），参数一律经 `RankParams` 进来、可在纯单测穷举；末尾追加分量只影响 3 处构造调用（`RankParams.defaults`、`FeedRecommendationService.params`、`FeedRankEngineTest` 两处）。
- **既有引擎测试不受影响**：`FeedRankEngineTest` 的候选 `createdAt` 全是 `NOW`（L26-28），新鲜度恒 1，与半衰期无关；`FeedRankScorerTest` 的 `at()` 造的是 FUN 候选，`contentScoreIsWeightedSum`（L87-92）仍按 24 算 0.5。
- **改值生效路径**：`PlatformConfigService.feedRank()`（`config/service/PlatformConfigService.java` L64-68）每次生成序列直读单行、无缓存；已缓存的序列快照不重算，30 分钟 TTL 过期或下拉刷新（换种子）后新序列按新值。
- **不在后台露出**：后台 PRD 与本主题都不加输入框（OQ-1 / D-2）；admin 主题若日后要露出，须同时加表单字段、diff 审计与校验，那是另一个 story。
- **对 Story 1.1 的协同**：720h 让教育池里的老科普能靠互动度竞争槽位，否则 1.1 扩池无效（PRD §3.1 对比表）。
