# V1.3.4 增补：帖子点赞人列表

## 0. 背景与目的

现在帖子上的点赞区（爱心 + 数字）是一个整体，点哪里都是点赞 / 取消赞。用户想知道「谁赞了我」只能靠通知中心，看不全也翻不回去。本增补仿 Instagram：**点爱心照旧点赞，点数字看点赞人列表**。

- **随 V1.3.4 一起上线**（2026-10-14 拍板），在 Following 关注流之后实现。
- 无设计图，视觉沿用现有底部抽屉、关注列表行样式与品牌紫。

## 1. 目标 / 不做 / 反目标

**目标**
1. 帖子作者与其他用户能看到「谁赞了这条帖子」。
2. 点赞人列表里可以直接关注对方，给关注体系多一个入口。

**不做**
- 不改点赞本身（点爱心的行为、乐观更新、动画、计数逻辑一律不变）。
- 不做评论点赞的点赞人列表（只做帖子）。
- 不做列表内搜索。
- 不在列表里显示「点赞时间」。

**反目标**
- 点爱心误触打开列表，或点数字误触点赞 / 取消赞。
- 列表里出现我拉黑的人、已注销 / 封号的人。
- 通过点赞人列表看到本来看不到的帖子的信息（私密帖、已删帖、我拉黑的作者的帖）。

## 2. 产品规则（已拍板，2026-10-14）

### 2.1 入口
- 两处：**首页 Feed 卡片**、**帖子详情页**底部的点赞区。（两处共用组件 `LikeButton`。）
- 点赞区拆为两个点击区：**爱心** = 点赞 / 取消赞（现状）；**数字** = 打开点赞人列表。
- Feed 双列卡片上的数字很小：数字的可点击区域放大（视觉不变），爱心与数字的热区**互不重叠**。
- 点赞数为 0 时，点数字**无反应**。
- **游客点数字 → 弹登录**（与游客点关注按钮同一个登录引导），不显示列表。
- 是否「0 赞」以组件本地计数（乐观更新后的值）判断：刚从 0 点成 1 时点数字可直接打开（我的决定）。
- 自己点过赞：自己按点赞时间正常排位，**不做置顶**（刚点的自然在最上；我的决定）。

### 2.2 抽屉交互（仿 Instagram）
- 点数字 → 抽屉从底部弹出，**默认盖住半屏**。
- 在抽屉上**上滑** → 展开到**全屏**；全屏时**下拉** → 回到半屏；半屏时**再下拉** → 关闭。
- 半屏时**点抽屉外的阴影区** → 关闭。系统返回键也关闭。
- 列表在抽屉内滚动；全屏状态下列表滚到顶后继续下拉 → 回到半屏（与 Instagram 手感一致）。
- 抽屉顶部：拖拽把手 + 标题「Suka」/「Likes」。

### 2.3 列表内容
- 每行：头像 + 昵称 + 关注按钮；点行（头像 / 昵称）→ 对方个人主页。
- 关注按钮沿用 1.3.4 三态规则（`+ Ikuti` / `Ikuti Balik` / `Mengikuti`，在此处点关注后按钮变 Mengikuti 可立即取关，同一用户其他位置按钮立即隐藏，刷新后已关注的不显示按钮）；**自己那一行不显示按钮**。
- 排序：**按点赞时间倒序**（最新点赞的在最上）；上拉加载更多（每页 20）。
- 过滤：排除**我拉黑的人**（单向，只看 BLOCK holder=我；对方拉黑我不影响，沿用 D-4 / D-10「不暴露被拉黑」口径）、已注销、封号（`status ≠ ACTIVE`）的用户。
- **列表人数可能少于点赞数**（被过滤的人不显示），接受；抽屉标题不显示数量，接口不返回过滤后总数（我的决定）。
- 空列表（例如点赞的人全被过滤掉）：显示简单空状态文案。
- 加载失败：显示失败文案 + 重试按钮。

### 2.4 可见性
- 只有**当前用户能看到这条帖子**时才能看点赞人列表：私密帖仅作者本人可看；已删帖、我拉黑的作者的帖、我举报过的帖 → 接口返回 404，App 提示「内容已不存在」并关闭抽屉。

## 3. 技术约束

- 后端：Spring Boot 4 / Java 21 / Flyway 时间戳迁移；`ddl-auto=validate`；不引入新中间件。对外用户标识随行返回 `userToken`（D-2），沿用 `FollowListItem` 结构（含关注状态三态所需的 `iFollow` / `followsMe` / `self` 等字段）。
- 点赞表 `content_likes(id, post_id, user_id, created_at)`，现只有 `idx_content_likes_post(post_id)` → 新增索引 `(post_id, created_at DESC, id DESC)` 支撑游标分页（新迁移，不改 V10）。
- 帖子可见性判定复用帖子详情接口已有的判定（不另写一套）。关注状态批量查（禁止逐条）。
- App：`LikeButton`（`features/content/presentation/like_button.dart`）是 Feed 卡片（`shared/widgets/masonry_card.dart`）与详情页底栏（`comment_composer.dart`）共用的组件；本次拆分点击区只改这一个组件。行组件与关注按钮复用 `FollowButton` / 关注列表行样式。新增文案 en / id 两份 ARB；不整文件格式化。
- 游客门控用 `requireLogin`（`features/auth/domain/auth_guard.dart`）。

## 5. 留给 builder

- 范围：只对普通帖子的 `LikeButton` 生效；评论点赞不受影响（我的决定）。
- 关注状态同步复用 1.3.4 已有的全局 `followStateProvider` + `FollowButton`（已落地，见 `features/social/domain/follow_state.dart`）。

- 接口路径与分页游标格式（建议 `GET /api/v1/content-posts/{id}/likers?cursor=`，复用关注列表的游标风格）。
- 抽屉的具体实现方式（`DraggableScrollableSheet` 或等价方案），半屏比例取 0.5 左右。
- 埋点：建议 `post_likers_opened {source: feed_card|content_detail}`，关注按钮沿用 `user_followed` 并新增 `source = likers`。

## 6. 验收要点

1. Feed 卡片与详情页：点爱心 = 点赞（行为不变）；点数字 = 打开抽屉；两者不误触。
2. 抽屉半屏 → 上滑全屏 → 下拉回半屏 → 再下拉关闭；半屏点阴影关闭；返回键关闭。
3. 列表按点赞时间倒序、分页无重复；自己那行无按钮；三态按钮正确；点行进主页。
4. 我拉黑的、注销、封号的用户不出现；0 赞时点数字无反应；游客点数字弹登录。
5. 私密帖（非作者）/ 已删帖 / 我拉黑作者的帖：接口 404，App 提示内容不存在。
