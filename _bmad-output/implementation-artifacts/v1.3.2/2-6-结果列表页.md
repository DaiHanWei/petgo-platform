# Story 2.6: 结果列表页

Status: review

## Story

As a 测过好几次的用户,
I want 看到这只宠物所有的测试结果,
so that 可以回看以前的结果、也能从这里重测。

## Acceptance Criteria

**AC1 — 页面与路由** `[L2]` `[L0]`
1. 新路由 `TailsonalityRoutes.results` = `/profile/pet-insights/tailsonality/results`（落在 `/profile/` 前缀下自动受控；与 `/results/:token` 段数不同，不会被吞）；页面标题「Riwayat Tailsonality」。
2. 数据：Story 2.1 的 `GET …/tailsonality/results`（经 2.3 的 `tailsonalityResultsProvider`），按接口顺序（`created_at` 倒序，最新在上）渲染。
3. 三态：加载中；失败 → 通用失败 +「Coba lagi」；空列表（正常不会出现，如删档重建后从深链进）→ `EmptyState`（标题「Belum ada hasil tes」、按钮「Mulai Tes」→ 说明抽屉）。

**AC2 — 行内容** `[L2]` `[L0]`
每行（UX-DR11；UI 稿 A17 单条 / A18 多条）：
1. 代号：完整代号字母间距展开（`E N T J - H`，连字符保留，等宽数字 / 字母，NFR-8）；
2. 角色名：`kTsRoles[letters].name`（Jaksel 原文，不翻译）；
3. 测试日期：`formatDayMonthYear(context, createdAt.toLocal())`（「22 Sep 2026」形态）；
4. 解锁状态：未解锁 → 标签「Belum dibuka」**置灰**（`AppColors.muted`）；已解锁 → 不显示该标签（本 epic 内全部未解锁）。
5. 整行可点（热区 ≥44 高、按压 scale(0.96)）→ `context.push(TailsonalityRoutes.result(token), extra: result)`；未解锁行**照样可点进结果页**（置灰的是状态标签，不是整行）。
6. 行尾留 `trailing` 插槽（本 story 传 null），Story 3.3 在此加「Dipakai / Pakai ini」佩戴切换。

**AC3 — 底部重测** `[L2]` `[L0]`
吸底主按钮「Tes Ulang」→ 与 Story 2.4 **同一个**重测流程（`kTsRetakeDialog` 确认 → 发 `tailsonality_retake_confirmed` → 说明抽屉 → 答题）。把 2.4 里的流程抽成 `Future<void> startTailsonalityRetake(BuildContext, WidgetRef)`（`presentation/tailsonality_retake.dart`），结果页 ⋯ 菜单与本页按钮都调它，**不许复制两份**。答题完成后回到本页时列表已刷新（2.3 提交成功会 invalidate 列表 provider）。

**AC4 — 聚合页去向切换** `[L2]` `[L0]`
聚合页 Tailsonality 卡：该宠物**有结果** → `context.push(TailsonalityRoutes.results)`（替换 Story 2.3 的「进最近一次结果页」临时去向）；无结果 / 读取失败 → 说明抽屉（不变）。更新 2.3 对应的 widget 测试断言。

**AC5 — 本 story 不含佩戴** `[L0]`
页面与行组件内不出现佩戴相关控件与文案：L0 断言无 `Dipakai` / `Pakai ini` 文本、无 `ValueKey('tsEquip…')` 前缀的 key（Epic 3 Story 3.3 加）。

### 关键设计点

- **已解锁结果是购买当时的快照**（FR-117.19）：本版本文案随发版固定，列表与结果页按 `content_version` 取同一套内容表即可，无需额外处理；Epic 3 解锁后也不回写文案。
- **列表不分页**：一只宠物的测试次数有限（重测虽不限次，但每次 3 分钟），本版本一次取全；若将来需要分页，接口已按 `created_at DESC, id DESC` 稳定排序，可平滑加游标。
- **佩戴切换在行内**（C-6：只在列表页行内切换，结果页内不做），本 story 只留插槽，别提前做半截。
