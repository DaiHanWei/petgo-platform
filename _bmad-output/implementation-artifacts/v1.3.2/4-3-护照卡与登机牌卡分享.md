# Story 4.3: 护照卡与登机牌卡分享

Status: review

## Story

As a 集了章的用户,
I want 把护照或某张登机牌晒出去,
so that 朋友看到我们去过哪些地方。

## Acceptance Criteria

**AC1 — 护照卡预览（B8）** `[L2]`（卡面数据 `[L0]`）
1. 护照单章页 B2 吸底「Bagikan」（Story 1.2 当时刻意不显示，本 story 接上）→ 护照卡预览页（`ShareCardPreviewPage.custom`，Story 4.1）。**纵览页 B2b 的吸底仍是快照解锁 CTA**（3.4），不加分享；空态 B1 不出「Bagikan」（没有章可晒）。
2. 卡面走 4.1 `ShareCardSkeleton`：
   - **主体段**：护照内页——页眉宠物名 + 护照号（12 位连写、等宽数字、单独一行不截断）+ 章格。章格复用 1.2 纵览页（B2b）的章 cell 组件（章面：`stampImageUrl` 非空用专属章，否则按 `placeType` 用包内默认章；**原色、不着色、不圆形裁切**，AD-5 / D-10）。主体段内以 `BoxFit.contain` 居中放置（**不 cover**：cover 会裁掉护照号或章），留白处用护照页底色。
   - 章多到一张卡放不下时：网格按列数自适应缩小，cell 不小于画布宽的 1/6；仍放不下时末格折叠为「+N」（N = 未显示的章数；做法同庆祝页 KOLEKSI 的 `+N`）。**不显示任何总数分母**（不出现「x / 12」，FR-120.4）。
   - **信息段**：「Paspor {pet} · {N} cap · {护照号}」（N = 本次卡面代表的章数）。
   - **品牌段**：同 4.1（字标 + `shareCardScanHint` + `petDownloadUrl()` 二维码）。
3. 只出 9:16、无比例切换。

**AC2 — 护照卡水印按「当前版本是否已买」** `[L1]`（客户端分支 `[L0]`）
1. 当前版本（按 AD-7 的 `place_set_hash` 现算）**未买** → `watermarked: true`；**已买** → `false`。判定**以服务端下发字段为准**：Story 3.4 在 1-2 护照读接口 DTO 上追加的 `currentVersionUnlocked`（= 存在已付快照且其现算 hash == 当前章集合现算 hash），客户端不自己算 hash。
2. L1：买下快照后预览无水印；再盖一枚新章 → 预览重新带水印；只是到访次数变化 → 仍无水印（与 3.4 同口径，本 story 只验证分享入口读的是同一个字段）。

**AC3 — 已购版本重新导出** `[L2]`（入口与数据源 `[L0]`）
1. 「已购版本」回看页（Story 3.4）每个版本加「Bagikan」→ 同一个护照卡预览，卡面**按该快照 JSON 渲染**（章列表、`stamp_count` 均取快照，不读实时数据），**恒无水印**。
2. 章面取法与 3.4 回看页一致（复用 3.4 回看页的渲染组件，不另写一套快照→章 cell 的转换）。
3. widget 测试：用一份与实时章列表不同的快照打开 → 卡面章数 / 场所名来自快照；`find.byType(CardWatermark)` 为 nothing。

**AC4 — 登机牌卡预览（B9）** `[L2]`（卡面数据 `[L0]`）
1. 登机牌详情（Story 3.5，B3b 未解锁 / B3c 已解锁）顶栏右上加分享图标按钮（`Icons.ios_share_rounded`，44×44 热区，两态都有）→ 登机牌卡预览页。
   - 放顶栏的理由：B3b 底部是解锁 CTA、B3c 底部是「Pamer di postingan」（4.4），UI 稿两屏都没画分享入口，而 PRD 要求未解锁也可生成分享卡（带水印）。见 Dev Notes。
2. 卡面：
   - **主体段**：3.5 的整张登机牌卡组件（顶部场所图带 + BOARDING PASS 字段 PASSENGER / BREED / TO / **PASSPORT 单独一行** / DATE / VISITS / SEAT），`BoxFit.contain` 居中（不 cover，避免裁掉字段）。
   - **信息段**：第一行「{pet} · {场所名}」，第二行「{日期} · {次数}×」（日期与卡上 DATE 字段同一取值、同一格式；次数等宽数字）。
   - **品牌段**：同 4.1。
3. 水印按**该张**登机牌解锁态（3.5 详情 DTO 的 `unlocked`：解锁行存在、`unlocked_at` 非空且未 `superseded`）：false 带、true 无；不影响其他场所的卡。卡面字段直接用 3.5 详情 DTO（`passenger` / `breed` / `placeName` / `passportNo` / `lastVisitDate` / `visitCount` / `seat` / `placeImageUrl` …），信息段日期取 `lastVisitDate`。
4. 场所已下架：卡照常可分享，场所名照常显示（下架只影响详情页的地址与跳转，AD-5）。
5. 只出 9:16。

**AC5 — 埋点** `[L0]`
1. `passport_card_shared`：系统分享面板**回调成功后**上报，属性 `stamp_count`（护照卡 = 卡面代表的章数；登机牌卡 = 该宠物当前总章数，见 Dev Notes 待确认项）。不带护照号、场所名、token、宠物名。
2. `test/analytics/v112_events_test.dart` 的 `allowedPrefixes` 补 `passport_`（1.2 的 `passport_issued` / `passport_stamped` 是服务端事件，不经过这张表，所以 App 侧此前没有这个前缀），附一行理由注释。

### 关键设计点

- **护照与登机牌是两套付费规则，水印也各看各的**：护照 = 快照（整本当前版本，按 hash 判）；登机牌 = 单张（宠物 × 场所）。勿把登机牌水印并进护照判定（PRD §3.3「不得把登机牌并进样式解锁逻辑」）。
- **水印判定只读服务端字段**：AD-14「水印由客户端按服务端下发的解锁态决定」；hash 定义在 AD-7 只有一个实现（服务端），客户端再算一遍就是第二个真相源。
- **contain 而不是 cover**：结果卡 / 配型卡主体是插画，cover 裁边无伤；护照内页与登机牌是**带字段的版面**，cover 会裁掉护照号 / SEAT。12 位护照号「须单独占一行」（PRD §3.3 ⚠️、C-13），在卡上同样适用。
- **已购版本「按快照 JSON 渲染」**：AD-7「回看渲染读快照 JSON」。3.4 回看页已经把快照转成可渲染的章列表，4.3 复用那一步，不另写。
- **UI 稿缺口（已按 PRD 补）**：B3b / B3c 没画分享入口，但 PRD §3.3 付费点②写明「未解锁：可看、可生成分享卡，但产物带水印」「已解锁则为分享 CTA」——而 B3c 底部 CTA 已被 09-23 改成「Pamer di postingan」。本 story 把分享放顶栏，两态一致；若产品要把 B3c 底部改成两个按钮，只挪入口不改卡面。
- **B8 / B9 稿里的吸底文字是「Bagikan」**，本 story 统一用 4.1 的 `shareCardShareCta`「Bagikan ke Story」（四类卡同一套预览页、同一个 CTA），差异来自 UI 稿最低优先级。
- **埋点待确认**：PRD E-16 只给 `passport_card_shared` + `stamp_count`，epics 把登机牌分享也挂在这个事件下。不加 `card_type` 属性就分不出是护照卡还是登机牌卡；按项目惯例「清单外的属性先改清单再改代码」，本 story **不擅自加**，在 Completion Notes 提醒产品确认是否补 `card_type: page|boarding`。
- **B7 / B8 稿注「两款样式各自独立解锁，互不包含」是过期残留**（C-12），忽略。
