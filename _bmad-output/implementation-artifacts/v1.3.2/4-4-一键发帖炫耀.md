# Story 4.4: 一键发帖炫耀

Status: review

## Story

As a 想把结果发到社区的用户,
I want 点一下就带着卡图和一句话进发帖页,
so that 不用自己截图、也不用想文案。

## Acceptance Criteria

**AC1 — `PublishComposePage.open` 预填参数** `[L0]`
1. `PublishComposePage` 构造与 `open()` 各新增两个**可选**参数：`String? initialText`、`List<Uint8List>? initialImages`；原有参数（`preset` / `presetEventDate` / `milestoneCode`，以及 Story 1.5 加的 `placeCheckinToken` / `placeCheckinPlace`）语义不变；本 story 的四个入口都**不传**打卡参数。
2. 预填在 `initState` 既有的 post-frame 回调里、**在 `c.setType(initial)` 之后**执行：
   - `initialText` 非空 → 截到 `kMaxPostTextLength`（1000）后同时写 `_textController.text` 与 `controller.setText`（两处必须一致，否则字数计与发布内容会分叉）；
   - `initialImages` 非空 → 逐张 `controller.addImage(bytes)`（最多 `kMaxImages`=9，超出丢弃）→ `controller.uploadAll()`（不 await，走既有上传进度 UI）。
   - **不经相册、不调 `pickMultiAndProcess`、不申请任何权限**（有测试：fake `MediaUploadUseCase` 断言 `pickMultiAndProcess` 调用 0 次、`uploadBytes` 调用次数 = 图片数）。
3. 两个参数都不传时行为逐项不变：`test/content/publish_compose_test.dart`、`publish_reorder_test.dart`、`test/mention/mention_entry_test.dart`、`test/analytics/v112_events_test.dart` 全绿。
4. 关闭发帖页即清空：provider 仍为 `Provider.autoDispose`、无草稿（NFR-10）。widget 测试：带预填打开 → 关闭 → 不带参数再打开 → 文字框为空、图片区为空。

**AC2 — 统一入口：先出卡图、转成可上传的图，再开发帖页** `[L0]`（图像处理）`[L2]`（整体体感）
1. NEW `BragPostEntry.open(context, {required Uint8List cardPng, required String text})`（放 `lib/features/content/presentation/brag_post_entry.dart`）：
   - 在后台 isolate（`compute`）把 PNG **转为 JPEG** 并保证比例落在信息流免裁区间 `[kFeedRatioMin, kFeedRatioMax]`（0.75~1.78）内：比例已在区间内原样转码；过高（< 0.75）或过宽（> 1.78）→ 以卡面同色底**补边**到最近的边界比例（不裁卡面）；转码复用 `ImageProcessor().process`（剥 EXIF、≤10MB）。
   - 然后 `PublishComposePage.open(context, preset: ContentType.daily, initialText: text, initialImages: [jpeg])`。
   - 转换失败（`ImageProcessingException`）→ 轻提示 `shareCardExportError`，**不**打开发帖页。
2. 单测（纯 Dart）：输入 1080×1440 PNG → 输出 JPEG 且尺寸不变；输入 1080×1920 PNG → 输出比例 = 0.75（补边）；输入 2000×800 → 比例 = 1.78；输出不含 EXIF。
3. 进行中防重复点击（入口按钮 loading / disabled）。

**AC3 — 四处「Pamer di postingan」** `[L2]`（入口存在性 `[L0]`）
每处都是：**先用 `CardRenderPipeline.capture` 截对应卡图** → `BragPostEntry.open`。
1. **结果页右上 ⋯**（4.1 留好的第二项）：截结果页 3:4 卡 `TsResultCard`（`kTsCardCanvas` 1080×1440；未解锁截**含水印**外层 boundary，已解锁截内层——与分享图同一水印规则）；文案 `tailsonalityBragResultText`。
2. **配型页底部主按钮**（UI A13 底部；2.5 当时不含）：截配型页页首 3:4 配型卡（永不带水印）；文案 `tailsonalityBragMatchText`。
3. **配型卡预览页底部主按钮**（4.2 预留的主操作位，接入后「Bagikan ke Story」自动降为次按钮）：预览页上是 9:16 卡，**发帖用的仍是 3:4 配型卡**——由配型页在 push 预览页之前先截好 3:4 字节并传给预览页的主操作回调；文案同 2。
4. **已解锁登机牌 B3c 底部「Pamer di postingan」**（3.5 留的底部位）：截详情页上的登机牌卡（已解锁 = 无水印）；文案 `boardingPassBragText`（带宠物名与场所名）。未解锁 B3b 不出本按钮（底部是解锁 CTA）。
5. 发帖页打开后：图片区已有卡图、文字框已预填，类型预选 **Momen**（`ContentType.daily`，UI A16b 标注），用户可改可删后照常发布；发布成功后既有刷新（`feedProvider` / `myPostsProvider` 等）照常。

### 关键设计点

- **必须转 JPEG**：上传票据的 content-type 写死 `image/jpeg`（`media_upload_use_case.dart` L107）；直接把 `CardRenderPipeline` 出的 PNG 喂进 `addImage` 会以 JPEG 名义存一张 PNG。正常选图路径经 `pickMultiAndProcess` → `ImageProcessor` 重编码为 JPEG，预填路径要补上这一步（且在 `compute` 里做：1080×1440 的纯 Dart 解码 / 编码放主 isolate 会掉帧）。
- **发帖用 3:4，不用 9:16 分享卡**：9:16 = 0.5625 < `kFeedRatioMin` 0.75，进信息流会被二次裁切（`feed_image_layout.dart`；裁剪页预设最高只到 3:4，`image_crop.dart` L28-34）；且 9:16 卡底部的下载二维码在站内没有意义。页内卡本来就是 3:4（C-11），直接截它。登机牌卡的比例由 3.5 定，落在区间外时补边而不是裁，保证 PASSPORT / SEAT 字段完整。
- **截图对象必须在屏幕上**：`toImage` 截不到 offstage 的东西（`share_card_preview_page.dart` L20-22 注释）。所以配型卡预览页（上面画的是 9:16 卡）里的「Pamer」不能现场去截 3:4——由配型页在 push 之前截好传进去。
- **水印规则跟分享图一致**：未解锁结果卡发帖也带水印（否则发个帖就拿到干净卡，绕过 Rp5.000）；配型卡永不带；登机牌只有已解锁才有这个按钮。
- **四处共用一个入口、不自建发布流程**（AD-11）：三处 Tailsonality 入口 + 登机牌 B3c 都走 `BragPostEntry.open` → `PublishComposePage.open`；打卡「Rekam Momen Ini」（1.5）走同一个 `open()` 的 `placeCheckinToken` 参数。
- **类型预选 Momen**：UI A16b 框内标注「Momen 预选」，公开提示为 `publishPublicNotice`。登机牌发帖同样预选 Momen（PRD 未单独规定；如产品要 Diary，改 `preset` 一处）。
