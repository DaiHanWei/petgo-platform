# Story 2.3: 入口、说明抽屉与答题

Status: review

## Story

As a 想了解自家毛孩子性格的用户,
I want 从档案里点进去就能开始测,
so that 三分钟左右就能知道结果。

## Acceptance Criteria

**AC2 — 测试说明抽屉** `[L2]`
1. 贴底 `showModalBottomSheet`（`isScrollControlled: true`、顶部圆角 24、半透明遮罩、拖拽条 36×4——视觉规格同 `shared/widgets/confirm_sheet.dart`），**不是整页**（UX-DR3）。
2. 自上而下：顶部海报 `assets/tailsonality/intro_poster.webp`（16:9，`BoxFit.cover`）→ 标题「Tailsonality」→「Tes kepribadian {pet} · {breed}」→「18 pertanyaan · ± 3 menit」→ 主按钮「Mulai Tes」。
3. `{breed}` 取 `PetProfile.breed`（自由文本原样显示）；为空时 CAT / DOG 回落物种名（`petTypeCat` / `petTypeDog`），OTHER 且无品种时整段 `· {breed}` 省略（用 `tailsonalityIntroSubjectNoBreed`）。这是用户确认「测的是谁、物种对不对」的唯一机会（PRD §3.2），宠物名与品种都必须出现。

**AC3 — 答题页结构** `[L2]` `[L0]`
1. 3 页，每页 6 题：第 1 页 Q1–Q5 + P1，第 2 页 Q6–Q10 + P2，第 3 页 Q11–Q15 + P3（图片题固定在每页末尾，AD-2）；题目显示序号连续 1–18（第 1 页 1–6，第 2 页 7–12，第 3 页 13–18）。
2. 题套在 App 侧按 `PetProfile.petType` 选：`CAT→CAT`、`DOG→DOG`、其余→`GENERAL`（与后端映射一致，仅用于**显示**；计分与落库以服务端为准）。文案全部取 Story 2.2 的 `kTsQuestions['<SET>.<QID>']`，`{pet}` 替换为宠物名。
3. 顶栏进度「X / 3」（等宽数字 `FontFeature.tabularFigures()`，NFR-8）；左上返回键。
4. 每题 4 选 1，**选项按内容表原序显示、不打乱**（下标即提交值 0..3）；选中态：主色 1.5px 描边 + `AppColors.mintTint` 底 + 字重加粗；每个选项热区 ≥44×44、按压 scale(0.96)。
5. 图片题 2×2 网格，**每格 = 图（4:3）+ 下方文字标签**，成对出现、同一可点区域（PRD §3.2 硬要求）；图路径 `assets/tailsonality/quiz_<p1|p2|p3>_<0..3>.webp`，**素材未到**：`Image.asset(errorBuilder:)` 回落占位格（浅紫底 + 该组图标：p1 `Icons.place_outlined` / p2 `Icons.bolt_outlined` / p3 `Icons.schedule_outlined`），文字标签照常显示——素材到货放进同名文件即生效，不改代码（NFR-9）。
6. 吸底主按钮：第 1、2 页「Lanjut」，第 3 页「Lihat Hasil」；**本页 6 题全部作答前禁用**。滚动到底时最后一个选项下沿与按钮上沿留 **≥12px**（列表底部 padding = 按钮区高度 + 12 + 底部安全区，UX-DR4）。
7. 翻到下一页时列表回到顶部；**可返回上一页改答**，已答保留。

**AC4 — 中途退出 = 放弃** `[L2]` `[L0]`
1. 第 2、3 页点返回（顶栏返回键与系统返回 / 侧滑都算，用 `PopScope(canPop: false)` 拦截）→ 回上一页，不弹窗。
2. 第 1 页点返回：已答 ≥1 题 → 弹确认「Keluar dari tes? / Jawaban yang udah kamu isi nggak akan disimpan.」+「Batal」「Keluar」（`showConfirmSheet`）；确认即退出；一题未答 → 直接退出不弹。
3. **不保存任何进度**（C-5）：答案只存在页面 State 内存里，不写 prefs、不写服务端、不进 provider 缓存；有一条源码扫描测试断言答题页及其 controller 不引用 `SharedPreferences` / `prefs` / 任何「draft」字样。下次进入从第 1 题开始。

**AC5 — 提交与生成中过渡** `[L2]` `[L0]`
1. 第 3 页点「Lihat Hasil」→ 同一路由内切到「生成中」视图（**不另开路由**，答案因此留在内存里可重试）：中心动效 + 五条维度进度条**逐条点亮**，标签依次为 `E / I · Orientasi sosial`、`N / S · Cara menjelajah`、`T / F · Reaksi emosi`、`J / P · Gaya hidup`、`Tingkat energi`（PRD §3.2 定死的四字母体系译名）+ 标题「Lagi nyusun hasil…」+「Menghitung 5 dimensi kepribadian {pet}」（UX-DR5）。
2. 请求：`POST /api/v1/pet-profiles/me/tailsonality/results`，body 为 18 键 `{ "Q1": i, …, "P3": i }`（值 = 选项原始下标）。过渡视图最短展示 2.5s（`Future.wait([submit, Future.delayed(2500ms)])`，五条各约 450ms 点亮），避免闪一下就跳走；系统「减少动态效果」开启时静态显示五条已点亮。
3. 成功 → `invalidate` 结果列表 provider → `context.pushReplacement(TailsonalityRoutes.result(token))`（返回键回到进入答题前的页面）。
4. 失败 → 回到第 3 页、**答案原样保留**，顶部 / 吸底区给「Hasilnya belum kebentuk. Jawabanmu masih aman, coba lagi ya.」+「Coba lagi」（再次提交同一份答案）。
5. 过渡视图期间拦截返回（请求在飞，时长有上限，不给半途退出）。

### 关键设计点

- **答案不离开页面 State**：这是 C-5「不保存、重来」的实现方式，也是生成中视图不另开路由的原因——另开路由要么把答案塞进 `extra`（深链时丢）、要么进 provider（会被误当成「进度保存」）。失败重试直接复用 State 里那份。
- **题套 App 侧只用于显示**：服务端按 `PetType` 再选一次并计分。两边映射必须一致（`OTHER→GENERAL`），`tsQuestionSetFor` 配单测。
- **图片题永远图文成对**：选项的可点区域同时包住图与标签；图加载失败也不影响答题（标签仍在）。
- **不在本 story 做**：结果页完整内容（2.4）、结果列表（2.6）、引导蒙层（2.7）。
