# Story 5.2: H5 分享页徽章

Status: review

## Story

As a 收到里程碑分享链接的人,
I want 在网页上看到同样的专属徽章,
so that App 内外看到的是同一枚徽章。

## Acceptance Criteria

**AC1 — 后端素材目录与公开放行** `[L0]`
1. NEW `petgo-backend/src/main/resources/static/milestone/`（先只放 `.gitkeep`），对外路径 `/milestone/<语义键>.webp`。
2. `SecurityConfig` 在 `/brand/**` 那条之后加一条**同形**放行：`.requestMatchers(HttpMethod.GET, "/milestone/**").permitAll()`（只 GET；**不**并进 `/m/**` 那组——那是三种分享页各自的前缀，L154-156 注释禁止合并通配）。
3. 跨库测试（NEW 后端 `MilestoneBadgeAssetSyncTest`，写法照 `MilestoneCatalogI18nTest` 读 `../petgo_app/assets/milestone/`，找不到目录即失败）：
   - 两边 `*.webp` **文件名集合完全一致**（App `assets/milestone/` ↔ 后端 `static/milestone/`），并逐个比对 SHA-256（同名不同图也算不一致）；
   - 忽略非 `.webp` 文件（`.gitkeep` / `README.txt`）。
4. 集成测试：放行后 `GET /milestone/does-not-exist.webp` → 404（不是 401 / 302）；放入测试资源后 200 且 `Content-Type: image/webp`。

**AC2 — 后端 code → 语义键映射（与 App 同源）** `[L0]`
1. NEW `com.tailtopia.profile.domain.MilestoneBadgeKeys`：`static final Map<String, String>`，78 条，与 App `kMilestoneBadgeKeys`（Story 5.1）逐条相同；`static Optional<String> keyOf(String code)` **只精确查表**（不按后缀 / 前缀）。
2. 5.1 的 `MilestoneBadgeMappingTest` 扩一条：Java 表 == Dart 表（逐条 code → 键一致，条数一致）。
3. NEW `MilestoneBadgeResolver`（profile 包，`@Component`）：启动时用 `PathMatchingResourcePatternResolver` 扫一次 `classpath:static/milestone/*.webp` 得到可用键集合；`Optional<String> urlFor(String code)` → 键存在且文件存在 → `"/milestone/" + key + ".webp"`，否则 empty。单测覆盖：已有素材、缺素材、非法 code。

**AC3 — `milestone_shares.collection_codes`** `[L1]`（迁移与 DTO `[L0]`）
1. 新迁移（时间戳号，如 `V20260929_HHmm__milestone_shares_add_collection_codes.sql`）：`ALTER TABLE milestone_shares ADD COLUMN collection_codes VARCHAR(400) NULL;` + `COMMENT`（「新分享才写：分享当时已解锁合集的完整 code 列表，逗号分隔、按合集顺序；为空 = 旧分享，H5 按 collection_levels 旧样式渲染（C-10）」）。**不回填**。
2. `MilestoneShare` 实体加 `collectionCodes`（`@Column(name = "collection_codes", length = 400)`，可空）；`create(...)` / `refresh(...)` 各加一个参数。
3. `MilestoneShareRequest` 加可选 `List<@Pattern(regexp = "[CDG]-[SML]\\d{1,2}") String> collectionCodes`，`@Size(max = 31)`（单物种最多 31 条）。服务层再校验每个 code 都在 `MilestoneCatalog.byCode` 里，否则 422；落库为逗号拼接。
4. 老 App 不传该字段 → 存 `NULL`（新建或刷新都一样）；新 App 传空列表 → 存 `NULL`（无合集）。
5. `MilestoneShareServiceTest` 补：带 codes 新建 / 刷新写入；非法 code 422；不传 → NULL；刷新时老客户端不传会把旧值清成 NULL（与 `collectionLevels` 同为「本次分享的快照」语义）。

**AC4 — App 分享时写入 code 列表** `[L0]`
1. `shareMilestoneWithLink`（`milestone_share.dart`）在现有 `collectionLevels` 之外，按**同一顺序、同一过滤**（`collection.where((m) => m.completed)`）得出 `collectionCodes` 一并提交；`collectionLevels` 照旧提交（服务端旧样式回落与老链接依赖它）。
2. `MilestoneRepository.createShare` 签名加 `required List<String> collectionCodes`，`DioMilestoneRepository` 请求体加 `collectionCodes`。实现了该接口的测试替身同步更新：`test/profile/milestone_checkin_test.dart`、`test/profile/milestone_share_test.dart`（后者补断言：codes 与 levels 同序同长）。
3. 分享失败退化为纯文案分享的行为不变。

**AC5 — H5 `/m` 页按 code 出图，缺素材回落，旧分享不变** `[L1]`
1. `MilestoneSharePageController.share`：
   - 大徽章：`badgeUrl` = `resolver.urlFor(share.getCode())`，有 → 模板在 `.badge` 里渲染 `<img>`（`alt=""`、宽高撑满 120 圆内的正方形、`object-fit: contain`），无 → 现有 CSS 紫渐变圆 + 🏆（**一个字不改**）。
   - KOLEKSI：`collection_codes` **非空** → 下发条目列表（每项 `{level, url|null}`，level 取 `MilestoneCatalog.byCode(code).level()`），标头计数 = code 数；**为空** → 完全沿用现有 `collectionLevels` 串与 JS 渲染（C-10：旧链接保持原样）。
2. 模板 JS 的 `circle(color)` 扩为 `circle(color, url)`：有 url → 圆内放 `<img>`（不再写 🏆），无 → 现状。两排容量与「+N」折叠逻辑不变。
3. 数据以 `th:attr="data-items=${…}"` 下发 JSON（Thymeleaf 自动转义；JSON 在控制器里用 Jackson 序列化），**不**用 `th:utext`；页面仍无 OG 图（隐私边界不变）。
4. 集成测试（MockMvc）：① 旧分享（codes NULL）HTML 仍含 `data-levels` 且不含 `/milestone/`；② 新分享 + 素材缺失 → 含 🏆 回落、不含 `<img` 指向 `/milestone/`；③ 新分享 + 测试资源存在（测试 classpath 放一张 `static/milestone/first_treat.webp`，**只在 test resources**）→ 大徽章与 KOLEKSI 引用 `/milestone/first_treat.webp`；④ 失效分享仍落 `card_gone` + 404。

**AC6 — 补上缺失的字标** `[L1]`
1. `templates/content_share.html` L61 引用的 `/brand/wordmark_brand.svg` 在 `static/brand/` 下不存在（现只有 `logo.svg`），当前线上 404。新增 `static/brand/wordmark_brand.svg`：以 App `assets/brand/wordmark_brand.svg` 为源，但**把根节点 `fill="#FFFFFF"` 改为品牌主色 `#845EC9`**——原件是纯白字标（给紫底启动页用的），`content_share.html` 是浅色底（`--tint: #F8F2FF`），原样拷过去会白字画在浅底上隐形（与 App 分享卡 `share_card_template.dart` L402-406 注释里踩过的是同一个坑）。
2. 集成测试：`GET /brand/wordmark_brand.svg` → 200；`ContentShareIntegrationTest` 既有断言不变。

### 关键设计点

- **单一素材源**（AD-15）：素材以 App `assets/milestone/` 为源，同批拷入 `static/milestone/`，同步测试按文件名 + 哈希钉死——「App 里换了新图、网页上还是旧图」会直接红。放素材的操作说明写进 Completion Notes：两边同放、同名。
- **旧链接保持原样（C-10）**：旧分享只存了级别串，没有 code，**不回填**。判定口径只有一个：`collection_codes IS NULL` → 走旧路径。大徽章则不同——`share.code` 旧分享本来就有，所以**旧链接的大徽章在素材到货后也会变成专属图**；这符合「H5 与 App 同一枚徽章」，C-10 约束的是 KOLEKSI 圆点。**2026-09-29 决策 D-20：接受**——旧链接大徽章随素材到货变成专属图，不做冻结。
- **`UNIQUE(pet_profile_id, code)` 意味着「重新分享 = 刷新同一条」**：用新 App 再分享一次旧里程碑，会把那条的 `collection_codes` 写上，旧链接随之变新样式——这是既有「同 token 刷新快照」的语义，不是 bug。
- **映射两端各一份，用测试绑死**：H5 是服务端渲染，拿不到 App 的 Dart 表；照「三处文案同步」先例（`MilestoneCatalog` Javadoc L20-33），Java 表以 Dart 表为准，跨库测试逐条比对。**禁止按后缀寻址**两端同样适用（`G-S6` 与 `C-S8` 同图、`G-S8` 不是零食）。
- **素材可用性启动时扫一次**：jar 内资源运行期不会变，扫描结果缓存即可；不要每次请求 `ClassPathResource.exists()`。
- **字标颜色**：App 原件 `wordmark_brand.svg` 根节点 `fill="#FFFFFF"`（纯白）。直接拷贝等于修一个 404 换一个「看不见的 logo」。
