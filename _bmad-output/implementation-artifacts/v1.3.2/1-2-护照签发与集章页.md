# Story 1.2: 护照签发与集章页

Status: review

## Story

As a 打过卡的用户,
I want 打开宠物护照看到集到的每一枚章,
so that 去过的地方变成一本会长大的收藏。

## Acceptance Criteria

**AC1 — 迁移与护照签发** `[L0]` `[L1]`
1. 新迁移（时间戳号，取创建时刻，如 `V20260929_HHmm__init_pet_passports.sql`）：新表 `pet_passports(id BIGINT GENERATED BY DEFAULT AS IDENTITY PK, pet_profile_id BIGINT NOT NULL REFERENCES pet_profiles(id), passport_no VARCHAR(12) NOT NULL, source VARCHAR(8) NOT NULL CHECK (source IN ('KTP','ISSUED')), issued_at TIMESTAMPTZ NOT NULL)`，`UNIQUE(pet_profile_id)`、`UNIQUE(passport_no)`；表与列加 `COMMENT`（写明：号源规则见架构 delta AD-6；只读 `id_cards`、不回写）。
2. 签发时机：**首次打开护照页**（`GET` 护照接口）或**首次打卡**（Story 1.1 的打卡事务内）——两处调用同一个 `PetPassportService.ensureIssued(petId, ownerId)`，已签发则原样返回。
3. 号源（AD-6 / D-6）：取 `id_cards WHERE user_id = 本人 AND profile_deleted_at IS NULL AND created_at >= 当前宠物 created_at AND passport_no IS NOT NULL AND substring(passport_no, 3, 2) = 当前宠物物种码 AND passport_no 未被任何 pet_passports 行占用` 的 **created_at 最早一张**，存在则沿用（`source=KTP`）；否则经 `CardNumberService.allocatePassportNo(petType)` 新发（`source=ISSUED`，与 KTP 共用 `passport_no_counters`，保证不重号）。
4. 并发只产生一行：`INSERT … ON CONFLICT (pet_profile_id) DO NOTHING` 后回读；**只写 `pet_passports`，绝不 UPDATE `id_cards`**（有测试断言签发前后 `id_cards` 行逐字段不变）。输掉竞争时已分配的计数器序号作废成空洞——可接受（`CardNumberService` 类注释已声明顺序号仅展示语义）。
5. 护照号格式 12 位连写（例 `TT02P2600128`）：单测覆盖猫 `02` / 狗 `01` / 其他 `00` 三种物种码与 KTP 沿用、新发两种来源。

**AC2 — 打卡响应补字段** `[L1]` `[L0]`
Story 1.1 的 `POST /api/v1/places/{token}/checkins` 响应追加 `passportNo`（String）与 `stampCount`（int，写入后该宠物的章数 = 不同当前 `place_id` 数）；护照签发在**同一事务**内完成。打卡契约测试（1.1 建的）同步加这两个键。

**AC3 — 护照接口** `[L1]` `[L0]`
`GET /api/v1/pet-profiles/me/passport`（需 `USER` 角色；无宠物档案 → 既有 404 `not-found`，与时间线 `requireProfile` 同口径）：
1. 该请求内先 `ensureIssued`（GET 带幂等写，故该方法**不是** `readOnly` 事务，注释写明）。
2. 响应 `{ petName, passportNo, stampCount, stamps: [...] }`；每枚章 `{ placeToken, placeName, placeType, placeStatus, stampImageUrl, firstVisitDate, visitCount }`：
   - 章 = 该宠物全部打卡按**当前 `place_id`** 聚合（`firstVisitDate` = min(`visit_date`)，`visitCount` = count），**不建章表**（AD-5）；排序 `firstVisitDate ASC, 首条打卡 id ASC`（新章永远在最后，护照页「停在新章」据此定位）。
   - `placeStatus` ∈ `ACTIVE | UNAVAILABLE`：场所 `status=ACTIVE 且 deleted_at IS NULL` → `ACTIVE`，其余（DELISTED / 已软删 / 异常 MERGED）一律 `UNAVAILABLE`（沿用 V1.3.0「下架与不存在刻意不可区分」）。
   - `stampImageUrl` **本 story 恒为 null**（Story 1.4 接入专属章）；字段始终存在于 DTO 定义中，null 时按全局 `non_null` 省略。
3. **不下发任何总数分母**：DTO 中不得出现 `total` / `max` / `capacity` / `remaining` 一类键（契约测试钉住）。
4. 场所合并后（打卡已由 admin 合并事务改挂保留方）两枚章自动合为一枚、次数相加；场所下架后章仍在、`placeStatus=UNAVAILABLE`（集成测试两例）。
5. `SecurityConfig` 加精确 matcher：`/api/v1/pet-profiles/me/passport` → `hasRole("USER")`（防兽医 token 落到 `anyRequest().authenticated()`，同 L276-279 注释的教训）。

**AC4 — 聚合页新增护照卡** `[L2]` `[L0]`
1. `pet_insights_page.dart` 由「单行两卡」改为**一行两张的多行排布**：卡片按顺序每两张一行（`IntrinsicHeight > Row(stretch) > 2×Expanded`），最后落单的一张**整宽**独占一行（C-8 / UX-DR1 的 2+2+1 规则的通用实现）；**不改 `InsightEntryCard`**。本 story 后顺序为 KTP / 年龄卡 / 护照（第 2 行护照整宽）；Tailsonality（Story 2.3）、登机牌（Story 3.5）以后按同一规则追加。
2. 新卡：`inkKey: ValueKey('insightPassport')`、图标 `Icons.menu_book_outlined`（线性，跟随既有 Material 线性图标语义）、标题「Paspor Hewan」、副文案「Kumpulin cap dari tempatmu」；全物种可点 → `context.push(PetInsightsRoutes.passport)`。
3. 年龄卡置灰规则不变（非猫狗 `onTap:null` + 副文案换 `ageCardUnavailableForSpecies`）。
4. `test/profile/pet_insights_test.dart`（L91-126）按新规则**更新断言、不删**：禁词列表移除 `passport` / `Passport`，**保留** `tailsonality` / `Tailsonality` / `comingSoon` / `coming_soon`；`find.byType(InkWell)` 由 `findsNWidgets(2)` 改为 `3`；group 名「只有两张卡」改为描述当前三卡；新增一例「护照卡整宽独占第二行、全物种可点」。
5. 路由：`PetInsightsRoutes.passport = '$hub/passport'`（落 `/profile/` 前缀下，自动继承游客门控；**不得**进 `_controlledExactExceptions`，AC5 那组安全测试加一条 `redirectWouldRewrite(guest, PetInsightsRoutes.passport)` 为 true）；可选 query `?focus=<placeToken>`。

**AC5 — 护照页三态** `[L2]` `[L0]`
新页 `PetPassportPage`（AppBar 标题「Paspor Hewan」，**AppBar 无 ⋯**）：
1. **页眉**：宠物名 + 护照号完整 12 位，护照号用等宽数字（`FontFeature.tabularFigures()`），单独占一行不截断。
2. **B1 空态**（`stamps` 为空）：护照内页块与 B2 **同尺寸同版心**，内页里写「Belum ada cap」+「Datangi tempat pet-friendly buat dapat cap pertama」；页脚「0 cap」；**无 ⊞ 纵览入口、无翻页箭头**；吸底「Cari Tempat」→ `context.push(PlaceListPage.routePath)`（`/places`）。
3. **B2 单章页（有章时默认）**：`PageView` 一页一枚章，左右翻页；每页章面 + 场所名 + 「{首次日期} · {n} kunjungan」；重复到访章面带角标「×N」（N≥2 才显示，等宽数字）；页脚「Cap {i} / {总章数}」（分母 = 用户自己已集章数，不是上限）；右上 ⊞（tooltip「Lihat semua cap」）切 B2b。带 `?focus=<placeToken>` 进入时初始页停在该章，找不到则停第 1 页。
4. **B2b 纵览页**：3 列网格，每页 12 格（3×4），页数随章数增长（横向 `PageView` 分页），页脚「{n} cap · Halaman {p}」；**空格不画未到访占位、不写总数上限**；右上 ◎（tooltip「Lihat per cap」）切回 B2；点任一枚章 → 回 B2 并停在那一页（**不**直接进章详情）。
5. 章面：`PlaceStampView(placeType, imageUrl)`（Story 1.1 组件）；`imageUrl` 为 null 时先查包内默认章映射 `defaultStampAssetFor(PlaceType)`——**素材未到，映射返回 null → 回落 1.1 的占位章**（不造占位图文件，到一款换一款，AD-5 / D-12）。**原色展示、不着色、不圆形裁切**。
6. 本 story **不显示**：付费按钮（Story 3.4）、吸底「Bagikan」（Story 4.3）、章详情跳转（Story 1.3，B2 点章本体本 story 无反应）。
7. 加载失败：整页错误 + 重试；loading 骨架与 B1 同版心，避免跳动。

**AC6 — 打卡成功页「Lihat Paspor」** `[L2]` `[L0]`
Story 1.1 的 `PlaceCheckinSuccessPage`：**仅 `isNewStamp == true`（C2）** 时在底部出次级按钮「Lihat Paspor」→ `context.push(PetInsightsRoutes.passportFor(focus: placeToken))`，护照页停在新章；C2b（重复到访）**不出**该按钮（widget 测试钉住）。按钮放在 `Scaffold.bottomNavigationBar` 的一行 `Row` 里（成功页没有评论输入条，可吸底；1.1 对详情页「禁止 bottomNavigationBar」的约束不适用于成功页）——本 story 行内只有这一个次级按钮，Story 1.5 在同一行追加主 CTA 并排（D-14）。

**AC7 — 删档与埋点** `[L1]` `[L0]`
1. 删档 / 注销：`ProfileDeletionService.deleteByUserId` 中、`petProfiles.delete(pet)` **之前**调用 `PetPassportDeletionService.deleteForPet(petId)` 物理删除 `pet_passports`（与 1.1 的打卡删档同段）；集成测试：删档后无残留，重建宠物后首次打开护照**重新签发**（新宠物无 KTP → `source=ISSUED`；KTP 旧卡已被 `markProfileDeleted` 打标，不会被沿用）。
2. 服务端埋点（AD-19，`AnalyticsClient.capture`，`@TransactionalEventListener(AFTER_COMMIT)`，照 `KtpUnlockAnalyticsListener`）：
   - `place_checkin`：`place_id`（**值为场所 token**，沿用 App 端 `place_detail_viewed` 的既有键名约定）、`place_type`、`is_new_stamp`；
   - `passport_issued`：`passport_source`（`KTP`/`ISSUED`）；
   - `passport_stamped`（仅新章）：`place_type`、`stamp_count`。
   事件名与属性键**同时**登记 `AnalyticsEventGuard.ALLOWED_EVENTS` / `ALLOWED_PROPERTY_KEYS`（有常量引常量）；`AnalyticsEventGuardTest` 补断言。属性**不得**带宠物名、护照号、坐标。

### 关键设计点

- **号源的每个条件都在防一个真实事故**：`user_id` 维度（`id_cards` 无 pet 外键）+ `profile_deleted_at IS NULL`（删档重建后旧卡属于上一只宠物，`TimelineService` L264-289 注释记录过同类 bug 20260828）+ `created_at >= 宠物建档时间`（双保险）+ 物种段一致（KTP 多卡时建卡可选物种快照，可能与当前宠物不同）+ `passport_no IS NOT NULL`（V95 前的旧卡）+ 未被占用（`pet_passports.passport_no` UNIQUE，撞了在 PG 里会中止整个打卡事务）。
- **为什么 GET 里签发**：D-6 明确「首次进护照页」签发；`ensureIssued` 幂等（insert-on-conflict），重复 GET 无副作用。别为此另开一个 POST 让 App 先调——那会多一种「页面开了但没签发」的中间态。
- **章聚合放 place 包**：`place_checkins` / `place_checkin_pets` / `places` 三表都归 place（架构 delta §1 表），passport 只消费聚合结果；这样 Story 1.3（地址）/ 1.4（专属章 URL）加字段都只动 place 侧一个查询。
- **排序 = 首次日期升序**：新章恒在末尾，`focus` 定位与 B4「回 B2 停在新章」（Story 1.3）都靠 token 找页，而不是靠「最后一页」这种隐式约定——合并后次序可能变化，按 token 找更稳。
- **`placeStatus` 只有两值**：App 只需要知道「能不能点进去」；把 DELISTED / 软删 / MERGED 细分下发等于泄漏「下架 vs 不存在」的区分（V1.3.0 1.5 决定刻意不可区分）。
- **聚合页排布写成通用规则**：本 story 只有 3 张卡，但 Story 2.3 / 3.5 会各加一张；把「每两张一行、落单整宽」写成对 `List<Widget>` 的分组函数，后续 story 只往列表里加一项，不必再动布局代码。
- **护照页不做分享 / 付费占位**：Epic 1 另注明确「不显示该按钮，不是占位」。不要留 `enabled:false` 的按钮。
