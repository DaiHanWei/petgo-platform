# Story 2.1: 题库常量、计分与结果落库

Status: review

## Story

As a 做完测试的用户,
I want 我的答案被准确地算成一个性格代号,
so that 结果可信、每次同样的答案得到同样的结果。

## Acceptance Criteria

**AC1 — 题库常量 `TailsonalityCatalog`** `[L0]`
1. 新建 `com.tailtopia.tailsonality.domain.TailsonalityCatalog`（`final class` + 私有构造，**编译期常量**，照 `profile/domain/MilestoneCatalog.java` 的写法；不建表、不开运营编辑）。
2. 内容：题套枚举 `TailsonalityQuestionSet { CAT, DOG, GENERAL }` × 题号 `Q1..Q15, P1..P3`（共 18，**有序**常量 `QUESTION_IDS`）× 每题 4 个权重（按原始选项序号 0..3）。权重**逐字取自**内容设计 §6.2（猫）/ §6.3（狗）/ §6.4（通用）/ §6.5（图片题三套共用）——三套 54 题的现行权重**全部是 `[+2, +1, -1, -2]`**，但仍按「题套 × 题号」逐条列出（不得写成一个共享常量让三套偷懒共用：以后某题改权重时必须能只改一套）。
3. 题号归轴固定：`EI = {Q1,Q2,Q3,P1}`、`NS = {Q4,Q5,Q6,Q7}`、`TF = {Q8,Q9,Q10,P2}`、`JP = {Q11,Q12,Q13}`、`ENERGY = {Q14,Q15,P3}`；锚题固定 `EI→Q1 / NS→Q4 / TF→Q8 / JP→Q11 / ENERGY→Q14`。
4. 16 个四字母代号常量 `TYPE_CODES`（E/I × N/S × T/F × J/P 全组合，按「社交-探索-情绪-驱动」顺序拼写）。
5. 单测钉：每套恰好 18 题、题号集合 = `QUESTION_IDS`、每题恰好 4 个权重且逐条等于内容设计值、归轴 5 组互不相交且并集 = 18 题、锚题各属其轴、`TYPE_CODES` 恰 16 个且互不重复。

**AC2 — 计分** `[L0]`
1. 新建 `TailsonalityScorer.score(TailsonalityQuestionSet set, Map<String,Integer> answers) → TailsonalityCode(letters, energy)`（纯函数，无 Spring 依赖）。
2. 逐轴求和：轴得分 = 该轴全部题目所选权重之和。
3. 方向：**E / N / J / H 为先写字母正分**（>0 取 E/N/J/H，<0 取 I/S/P/L）；**情绪轴例外：>0 取 F，<0 取 T**（内容设计 §6.7 红框）。
4. 平局（得分 = 0）：取该轴**锚题所选选项权重的正负**决定方向（锚题权重不会为 0）——情绪轴平局且锚题为正 → **F**。
5. 拼接顺序固定「社交-探索-情绪-驱动」+ `-` + 能量：`ENTJ-H` 形态；`TailsonalityCode.full()` 返回 `ENTJ-H`，`letters()` 返回 `ENTJ`，`energy()` 返回 `H`/`L`。
6. 验收用例（内容设计 §6.7）**V-1 ~ V-5 全部以单测钉死，且 CAT / DOG / GENERAL 三套各跑一遍**（`@ParameterizedTest` + `@EnumSource`）：
   - V-1：18 题全选序号 0（全 +2）→ `ENFJ-H`
   - V-2：18 题全选序号 3（全 −2）→ `ISTP-L`
   - V-3：情绪轴 4 题（Q8/Q9/Q10/P2）全选 0，其余全选 3 → `ISFP-L`
   - V-4：情绪轴 4 题全选 3，其余全选 0 → `ENTJ-H`
   - V-5：Q11=0（+2）、Q12=2（−1）、Q13=2（−1），驱动轴和为 0 → 第 4 位 `J`
7. 另补五轴各一条平局用例（见 Dev Notes「平局测试向量」），其中**情绪轴平局 + 锚题为正必须得 F**（专抓把 T 当正极的实现）。

**AC3 — 迁移与实体** `[L0]` `[L1]`
1. 新迁移（时间戳号，取创建时刻，如 `V20260929_HHmm__init_tailsonality_results.sql`）建表 `tailsonality_results`：
   - `id BIGSERIAL PK`、`public_token VARCHAR(32) NOT NULL UNIQUE`、`pet_profile_id BIGINT NOT NULL REFERENCES pet_profiles(id)`、`user_id BIGINT NOT NULL REFERENCES users(id)`、`question_set VARCHAR(16) NOT NULL CHECK (question_set IN ('CAT','DOG','GENERAL'))`、`answers JSONB NOT NULL`、`type_code CHAR(4) NOT NULL CHECK (type_code ~ '^[EI][NS][TF][JP]$')`、`energy CHAR(1) NOT NULL CHECK (energy IN ('H','L'))`、`content_version INT NOT NULL CHECK (content_version >= 1)`、`unlocked_at TIMESTAMPTZ NULL`、`created_at TIMESTAMPTZ NOT NULL DEFAULT now()`。
   - 索引 `(pet_profile_id, created_at DESC)`；表与列 `COMMENT`（写明：结果行在提交答案时即建，是 Story 3.1 购买的「业务行」；`unlocked_at` 由 3.2 的 `grant` 置位；删档物理删除）。
   - **无**配额 / 计次 / 付费重测相关列（PRD §3.2「不留状态位」）。
2. 实体 `com.tailtopia.tailsonality.domain.TailsonalityResult`（`answers` 用 `@JdbcTypeCode(SqlTypes.JSON)` 映射 `Map<String,Integer>`，照 `admin/places/domain/Place.java:54`），`ddl-auto=validate` 下启动通过。

**AC4 — 提交接口** `[L1]`
`POST /api/v1/pet-profiles/me/tailsonality/results`，body `{ "Q1": 0, …, "Q15": 3, "P1": 1, "P2": 0, "P3": 2 }`，需登录（`USER`）。
1. 取当前用户唯一宠物（经 `profile` 模块读口，见 T2）；无宠物档案 → 404 `not-found`。
2. 题套由服务端按宠物 `PetType` 选：`CAT→CAT`、`DOG→DOG`、`OTHER→GENERAL`；**请求体不得带题套**（带了也忽略——body 只收 18 个题号键）。
3. 校验：键集合**恰好**等于 `QUESTION_IDS`（多一个、少一个、未知键都算错），每个值为 0..3 的整数，否则 422 `validation`（detail 固定文案，不回显原值）。值类型错（如字符串 / 小数）由既有 `HttpMessageNotReadableException` 处理为 400，不另写。
4. 计分（AC2）→ 同一事务落库一行：`public_token` 新生成、`answers` 原样存规范化后的 18 键、`content_version = 1`、`unlocked_at = null`。
5. 响应 `201` + 结果 DTO（AC6）。
6. 限流 `rl:tailsonality:submit:{userId}`，10 次 / 分钟（常量放控制器顶部）。
7. **中途不落任何进度**（C-5）：本接口是唯一写入口，没有「保存草稿 / 部分答案」接口。

**AC5 — 读取接口** `[L1]`
1. `GET /api/v1/pet-profiles/me/tailsonality/results`：当前宠物全部结果，按 `created_at DESC, id DESC`；无宠物 → 404；有宠物无结果 → `200 { "items": [] }`。
2. `GET /api/v1/pet-profiles/me/tailsonality/results/{token}`：token 不存在 **或** 不属于当前用户当前宠物 → 404 `not-found`（与不存在刻意不可区分，防枚举）。
3. `SecurityConfig` 加**显式** matcher：`/api/v1/pet-profiles/me/tailsonality`、`/api/v1/pet-profiles/me/tailsonality/**` → `hasRole("USER")`（理由同该文件 L274-277 注释：兽医 token 的 sub 与 users.id 撞号，不能落 `anyRequest().authenticated()`）。

**AC6 — 结果 DTO 与契约** `[L0]`
1. `TailsonalityResultResponse` record 字段（camelCase）：`token`、`typeCode`（完整代号 `ENTJ-H`）、`letters`（`ENTJ`）、`energy`（`H`/`L`）、`questionSet`、`resultIndex`（同宠物按 `created_at` 升序的 1 起序号，**现算不落库**）、`unlocked`（boolean，本 epic 恒 false）、`unlockedAt`（null 时按全局 `non_null` 省略）、`contentVersion`、`createdAt`。列表响应 `TailsonalityResultListResponse { items }`。
2. **DTO 与字段名不得含 answers / 权重 / 各轴原始分**（计分细节不外露）。
3. 后端契约金标 `TailsonalityResultResponseContractTest`（照 `place/dto/PlaceDetailResponseContractTest.java` 的 `JsonMapper` + `FULL_FIELDS` 写法）：钉字段全集；`unlockedAt` 为 null 时键被省略；无 `answers` 键。
4. App 侧 `TailsonalityResult.fromJson` + `test/tailsonality/tailsonality_result_wire_contract_test.dart`：fixture 与后端 `FULL_FIELDS` 同集；缺 `unlockedAt` 键解析为 null；`unlocked` 缺键**不得**默认 true。

**AC7 — 重测与删档** `[L0]` `[L1]`
1. 重测 = 再 POST 一次：新行、新 token、新 `resultIndex`，旧行不动；实现与 DTO 中**无**任何配额 / 计次字段（有一条源码扫描测试：`tailsonality` 包内不出现 `quota` / `remaining` / `retakeCount` 标识符）`[L0]`。
2. 删档：新建 `tailsonality.service.TailsonalityDeletionService.deleteForPet(long petId)` 物理删除该宠物全部 `tailsonality_results`；在 `ProfileDeletionService.deleteByUserId` 中、`petProfiles.delete(pet)` **之前**调用（与 Story 1.1 的 `PlaceCheckinDeletionService` 同段）。集成测试（照 `profile/service/ProfileDeletionIntegrationTest.java`）：删档后该宠物无结果行；同账号重建宠物后可正常提交 `[L1]`。
3. 注销路径天然覆盖（`AccountDeletionService.execute` 先调 `profileDeletion.deleteByUserId`，在 auth 删 user 行之前）——测试断言注销后 `tailsonality_results` 无该用户行 `[L1]`。

**AC8 — 合规** `[L0]`
接口路径、DTO 字段、类名、表名、迁移文件名一律不出现 `mbti`（不区分大小写）——由 Story 2.2 的静态扫描统一钉住；本 story 写代码时就守住，注释里也别写这个词（用「四字母商标词」代称）。

### 关键设计点

- **情绪轴是唯一反向轴**：`TailsonalityAxis.TF` 的 `positiveLetter = 'F'`、`negativeLetter = 'T'`。代码里**禁止**出现「按轴名第一个字母当正极」的推导（`name().charAt(0)`）——那正是内容设计 §6.7 警告的系统性错配：测试跑得通、16 个角色有 8 个整片对调。V-3 / V-4 与「情绪轴平局 + 锚题正 → F」三条用例是专门抓它的。
- **权重是按原始选项序号存的**：提交值 0 = 内容设计里的第 1 个选项（+2）。App 若将来打乱显示顺序，必须在提交前映射回原始序号（AD-2）；本版本 App 按原序显示（Story 2.3）。
- **题套不信客户端**：`PetType` 建档后不可改，服务端据此选套；body 里多出来的 `questionSet` 之类键直接让键集合校验失败（422）。
- **`resultIndex` 不落库**：删档重建后从 1 重新数，符合「按宠物」口径；埋点 `result_index` 用它。
- **结果行是付费的业务行**（AD-1）：Story 3.1 的 `keepsake_purchases.ref_id` 会指向本表 `id`，幂等键用本表 `public_token`。所以 `public_token` 必须**提交时即生成**、永不改。
- **不存文案**：只存 `type_code` + `energy` + `content_version`；文案在 App（AD-2）。已解锁结果的「购买当时快照」由 `content_version` 承载（本版本恒 1，FR-117.19）。

### 平局测试向量（AC2.7，序号 → 权重：0=+2, 1=+1, 2=−1, 3=−2）

| 轴 | 输入（其余题随意） | 和 | 期望 |
|---|---|---|---|
| EI | Q1=1(+1) Q2=2(−1) Q3=0(+2) P1=3(−2) | 0 | 锚 Q1 正 → **E** |
| EI | Q1=3(−2) Q2=0(+2) Q3=2(−1) P1=1(+1) | 0 | 锚 Q1 负 → **I** |
| NS | Q4=2(−1) Q5=1(+1) Q6=0(+2) Q7=3(−2) | 0 | **S** |
| TF | Q8=1(+1) Q9=3(−2) Q10=0(+2) P2=2(−1) | 0 | 锚 Q8 正 → **F**（不是 T） |
| JP | Q11=0 Q12=2 Q13=2（= V-5） | 0 | **J** |
| ENERGY | Q14=2(−1) Q15=0(+2) P3=2(−1) | 0 | **L** |
