# Story 4.1: 通用分享卡骨架与结果卡分享

Status: ready-for-dev

## Story

As a 测出有趣结果的用户,
I want 把结果卡存成图片或分享到 Story,
so that 朋友也能看到我家毛孩子是什么性格（顺便知道去哪下载）。

### 关键设计点

- **水印导出（本 story 最容易做错的一条）**：`CardFrame` 把水印放在截图 boundary **外面**（`card_frame.dart` L14、L46-57；`card_watermark.dart` L10-15 明说「走管线的高清导出 → 不带水印」）。所以「未解锁分享出去的图带水印」**不能**靠给 `CardFrame` 传 `watermark` 实现——那只影响预览。做法照 KTP：`RepaintBoundary(key: _watermarkedKey, child: CardFrame(..., watermark: CardWatermark(canvas: c)))`，`watermarked` 时 `CardRenderPipeline.capture(boundaryKey: _watermarkedKey, canvas)`。外层与 `CardFrame` 的 `AspectRatio` 同尺寸，管线的倍率反算照样成立；**不改**管线、`CardFrame`、`CardWatermark` 一行。
- **水印强度风险**：`CardWatermark` 是 0.25，而 KTP 的 `IdCardWatermark` 已因「免费分享图看着和高清没区别」调到 0.45（`id_card_watermark.dart` L21-30）。AD-14 要求水印零改动，本 story 沿用 0.25；L2 验收时若判断「未解锁图与解锁图区分不出」，在 Completion Notes 记录并提给产品（改 `CardWatermark` 的 opacity 参数只需调用方传 `opacity:`，无需改组件）。
- **骨架抽取的约束**：帖子卡的「图片 `Expanded` 吃余量、内容段 `ConstrainedBox` 被量」这一顺序（L170-172 注释）是正确性要求。骨架的主体区就是那个 `Expanded`、信息区就是那个 `ConstrainedBox`（上下界 0.18~0.45 of rest 作为骨架默认，业务卡可覆写）。纯文字模板（SH3）结构不同（整块 85% 文字 + 类型 chip + 作者行在底），骨架提供「非品牌区整块」的第二种入口或让 `_textLayout` 只复用品牌段——**不要**为了统一把 SH3 硬塞进「主体 + 信息」两段而改变它的布局。
- **二维码指向 `/get`**：`/get` 是 `LegalPageController` L71 的静态页（`SecurityConfig` L166-167 已 permitAll），公网经 CF 映射到 `s.tailtopia.id/get`。它没有埋点消费方，码内**不加** `?src=qr`。
- **主体段内容**：C-1 定「复用三段式」，内容设计 §2.5 与 PRD 要求「同一套卡面内容、3:4 页内 / 9:16 分享两种版式适配」——所以主体段直接复用 2.4 的 3:4 卡面 widget（cover 铺满），不另画一套。素材当前是带字的设计图（D-12 状态表），纯插画版到货后如需叠字，只改 2.4 那个卡面 widget，分享卡自动跟随。插画在 9:16 主体段会被裁左右或上下，关键元素须在安全区（PRD 已对设计提出）。
- **结果卡是「付费保护卡」**：未解锁带水印、解锁无水印（PRD §3.2 两卡对照表）；配型卡规则相反（4.2），**勿统一**。
- **灯箱为什么是内存图**：结果卡是本地渲染的 widget，没有 URL；`ImageLightbox` 注释 L19-21 要求接口不感知业务实体，所以扩展的是「图片来源形状」（`Uint8List`），不是加 `resultToken` 之类参数。heroTagPrefix 仍由调用方给且须唯一（同页可能有多个 Hero）。
