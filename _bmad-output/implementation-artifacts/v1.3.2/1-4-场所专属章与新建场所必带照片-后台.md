# Story 1.4: 场所专属章与新建场所必带照片（后台）

Status: ready-for-dev

## Story

As a 运营,
I want 给重点场所上传一枚专属章,
so that 用户在这些地方盖到的是独一无二的章。

## Acceptance Criteria

**AC1 — 迁移** `[L0]` `[L1]`
新迁移（时间戳号，如 `V20260929_HHmm__add_places_stamp_object_key.sql`）：`ALTER TABLE places ADD COLUMN stamp_object_key VARCHAR(255)`（可空，与 `place_photos.object_key` 同宽）+ `COMMENT`：「场所专属章 OSS objectKey（公开桶、对象级 public-read）；NULL = 用按 place_type 的默认章。合并 / 下架不清空，只有后台『移除』清空（AD-18）」。
- 后台实体 `admin.places.domain.Place`（`@Entity(name = "AdminPlace")`）映射可写列 `stampObjectKey`，新增 `setStamp(String objectKey)` / `clearStamp()`；`markMerged` / `delist` / `restore` / `softDelete` **不得**触碰该字段（单测钉住）。
- App 侧 `place.domain.Place` 映射为只读（`insertable = false, updatable = false`），与该实体现有 `status` / `merged_into_id` 的只读写法一致。

**AC2 — 抽屉「专属章」区** `[L2]` `[L1]`
场所详情抽屉（`drawer-places.html`，UI 上即「场所编辑页」）在 ① 基本信息之后、② 照片墙之前新增一张卡「专属章」：
1. 未上传：显示「使用默认章（{类型名}）」+ 规范说明 + 「上传专属章」文件选择（`accept="image/png"`）。**不是警告样式、不阻断任何保存**（不用 `banner warn` / 红字）。
2. 已上传：显示预览（公开 URL，棋盘格底以便看透明区域，`object-fit: contain`，**不做圆形裁切、不加滤色**）+「替换」「移除」。「移除」走既有 `data-confirm` 二次确认。
3. 规范说明常驻（一行）：「透明底 PNG · 512×512 · ≤300KB；颜色不限，按原图展示；换章对已盖出的章立即生效」——最后半句是后台 PRD 要求写进运营说明的。
4. `MERGED` 场所：只读展示当前章（若有），不出上传 / 替换 / 移除（与「已合并的场所不可编辑」同口径）；`DELISTED` 场所照常可操作。

**AC3 — 上传 / 替换 / 移除端点** `[L1]`
1. `POST /admin/places/{id}/stamp`（multipart `file`）与 `POST /admin/places/{id}/stamp/remove`，均 `@PreAuthorize(AdminPlaceController.VIEW_AUTH)`（`place.manage`，与场所其它写端点同权限码，不新增权限）、非 htmx 访问回 `redirect:/admin/places?open={id}`、成功走既有 `afterAction(id, toastKey, …)`（抽屉 fragment + oob 行 + toast + `HX-Trigger: admin:places-refresh`）。
2. 校验**只做四项**（D-10 / AD-18），任一不过 → 422 行内错误，文案给出**具体原因与实测值**：
   - PNG：按**文件头魔数** `89 50 4E 47 0D 0A 1A 0A` 判定（不只信 content-type）→「只支持 PNG」；
   - 尺寸：`ImageBytesMeasurer.measure(bytes)` 宽高都 = 512 →「须为 512×512，当前 {w}×{h}」；测不出 →「无法读取图片尺寸」；
   - 大小：≤ 300 × 1024 字节 →「单个文件须 ≤300KB，当前 {n}KB」；
   - 透明通道：IHDR color type ∈ {4, 6}，或 color type ∈ {0, 2, 3} 且存在 `tRNS` 块 →「须为透明底 PNG（未检测到透明通道）」。
   - **不校验颜色、不校验形状 / 圆形安全区**（D-10 作废 PRD §3.3 与后台 AB-18B 的单色 + 圆形安全区要求）。
3. 通过后复用 `AdminSeedImageService.upload(file, "place-stamps/" + id)`（带对象级 public-read ACL），把返回的 `objectKey()` 写入 `places.stamp_object_key`。**先校验再上传**，不合规的文件不产生 OSS 对象。
4. 替换 = 直接覆盖字段；移除 = 字段置 NULL。旧 OSS 对象**不删**（App 可能仍缓存旧 URL；与既有「移除照片不删 OSS」同策略，孤儿对象可接受）。
5. 审计：经统一入口 `AdminAuditService.record`，新动作常量 `AuditActions.PLACE_STAMP_UPLOADED` / `PLACE_STAMP_REMOVED`，target `PLACE`，summary 记 `name=<场所名>, replaced=<true|false>`（不记 URL / key）；四个语言文件补 `admin.audit.action.*` 显示名。
6. 合并（`PlaceMergeService.merge`）与下架（`AdminPlaceService.delist`）**不删 OSS、不清空** `stamp_object_key`：集成测试各一例（B 有章 → 合并后 B 行仍有 key；A 的章照旧；下架后 key 仍在）。

### 关键设计点

- **D-10 覆盖了两份 PRD**：PRD §3.3 与后台 AB-18B 都写「单色、客户端统一着色、圆形安全区」，决策日志 D-10 作废了这三条，改为「透明底 PNG / 512×512 / ≤300KB，颜色不限、原图原色，不做圆形检查（章不一定是圆的）」。UI 稿多屏说明里也残留「单色 + 客户端着色」，一律以 D-10 为准。测试里专门放一张彩色非圆形 RGBA 图证明它能过。
- **透明通道怎么判**：PNG 第 26 字节（IHDR 数据第 10 字节）是 color type：6 = RGBA、4 = 灰度 + alpha 直接合格；3（调色板）/ 2（RGB）/ 0（灰度）需要在 IDAT 之前出现 `tRNS` 块才算有透明。不需要解码像素，扫块头即可（块结构 = 4 字节长度 + 4 字节类型 + 数据 + 4 字节 CRC）。
- **为什么不拼 `x-oss-process`**：场所照片 URL 服务端统一带 `image/resize,w_1080/format,jpg`（App `place_detail_page.dart` 的注释写明是去 EXIF 重编码），那会把透明 PNG 变成黑 / 白底 JPG。专属章是运营素材、不含用户 EXIF，直接给原图。
- **「未上传不是错误态」**：绝大多数场所会一直用默认章，抽屉里这张卡必须是中性信息样式；也不要在列表页加「无专属章」筛选或标记。
- **与后台 PRD「同一次保存」的差异**：后台 PRD 写「与场所基础信息同页同一次保存」，Epic AC 与 AD-18 要求「替换 / 移除即时生效」且上传需要 multipart。本 story 采用**独立即时端点**（与照片删除同一交互范式），编辑表单保持纯文本字段不变。
- **权限**：专属章是既有「场所管理」页内的一个字段区，不是新功能页，沿用 `place.manage`（该码本就是「查看即管理」，D-9 / D-17），不新增权限码、不动侧栏。
