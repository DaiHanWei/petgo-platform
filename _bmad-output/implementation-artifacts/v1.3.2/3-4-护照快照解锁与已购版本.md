# Story 3.4: 护照快照解锁与已购版本

Status: review

## Story

As a 集了一些章的用户,
I want 买下「现在这一版」的无水印护照,
so that 我有一份干净的纪念，以后集了新章还能再买新版。

## Acceptance Criteria

**AC1 — 快照表** `[L0]` `[L1]`
新迁移（时间戳号；实际 `V20260930_2347__init_passport_snapshots.sql`）：
`passport_snapshots(id BIGINT IDENTITY PK, public_token VARCHAR(32) NOT NULL UNIQUE, pet_profile_id BIGINT NOT NULL REFERENCES pet_profiles(id) ON DELETE CASCADE, stamps JSONB NOT NULL, stamp_count INT NOT NULL CHECK (stamp_count >= 1), place_set_hash CHAR(64) NOT NULL, paid_at TIMESTAMPTZ NULL, created_at TIMESTAMPTZ NOT NULL DEFAULT now())`；索引 `(pet_profile_id, paid_at DESC)`；表 / 列 COMMENT（`stamps` 为发起购买时冻结的章列表；`place_set_hash` 仅作记录，判定一律现算）。实体 `com.tailtopia.passport.domain.PassportSnapshot`（NEW，放 1-2 建立的 passport 包）。

**AC2 — 章集合 hash（唯一定义）** `[L0]`
passport 包新建 `PlaceSetHash.of(Collection<Long> placeIds) → String`：
1. 每个 `place_id` 沿 `places.merged_into_id` 解析到最终场所（`PlaceMergeService` 经 `repointMergedInto` 保证单跳；实现仍按「循环到 `merged_into_id IS NULL` 且最多 N 跳」防御）；**DELISTED 照常计入**、软删（`deleted_at` 非空）同样计入原 id；
2. 去重 → 升序 → 以 `,` 连接十进制 id → SHA-256 → 小写 hex（64 位）；
3. **购买判定与读取判定调用同一个函数现算**，落库的 `place_set_hash` 不参与比较。
4. 单测：顺序无关；重复 id 去重；A 并入 B 后 `{A, C}` 与 `{B, C}` 同 hash；DELISTED 不被剔除；空集合抛 `IllegalArgumentException`。

**AC3 — 发起快照购买** `[L1]`
`POST /api/v1/pet-profiles/me/passport/snapshots`（与 1-2 的 `GET /api/v1/pet-profiles/me/passport` 同前缀，放 `PetPassportController`），body `{ "channel": "PAWCOIN" | "QRIS" }`，需 `USER`：
1. 取当前宠物的当前章（复用 1-2 的 `PlaceStampQueryService.stampsOf(petId)`：按当前 `place_id` 聚合，首次日期 = min(`visit_date`)，次数 = count；需要内部 `placeId` 时在该服务加一个只读投影，不要在 passport 包另写聚合 SQL）；无章 → 422 `validation`（B1 空态本就不出购买入口，这是兜底）。
2. 现算当前 hash；若该宠物**已有任一 `paid_at` 非空的快照**其 `stamps` 里场所集合现算 hash 等于当前 → 409 `keepsake-already-unlocked`。
3. 否则找该宠物 **`paid_at IS NULL` 且现算 hash 等于当前**的最新快照 → 复用（其上可能挂着 PENDING 购买，3-1 会复用同一笔）；没有 → 新建快照行：**此刻冻结** `stamps`（每枚：`placeId`（内部）、`placeToken`、`placeName`（与实时护照章同键名）、`placeType`、`firstVisitDate`、`visitCount`）+ `stamp_count` + `place_set_hash`。
4. 加锁读 / 建快照行后构造 `KeepsakeRef(PASSPORT_SNAP, snapshot.id, snapshot.publicToken, petId, snapshot.paidAt != null)` → `KeepsakePurchaseService.start`。响应 = `KeepsakePurchaseResponse` + `snapshotToken`。
5. 并发：同宠物同时两次发起 → 只产生一个未付快照行（对「宠物 + 未付」加 `pet_profiles` 行级锁或 `SELECT … FOR UPDATE` 该宠物的护照行 `pet_passports`，二选一，注释写明）。
6. 限流 `rl:passport:snapshot:{userId}` 10 次 / 分钟；`SecurityConfig` 精确 matcher → `hasRole("USER")`。

**AC4 — 发放** `[L1]`
`PassportSnapshotGranter implements KeepsakeGranter`（`sku() = PASSPORT_SNAP`）：`UPDATE passport_snapshots SET paid_at = now() WHERE id = :refId AND paid_at IS NULL` → 1 行 `GRANTED`；行存在已付 `ALREADY_UNLOCKED`；行不存在（删档）`REF_MISSING`；不抛异常。
- 付款期间用户又盖了新章：**按冻结内容发放**（买到的就是发起那一刻的版本），此时当前护照仍带水印——符合 D-4「买的是那一刻的快照」。

**AC5 — 护照页的版本状态** `[L1]` `[L0]`
1. 1-2 的 `PetPassportResponse`（`GET …/me/passport`）追加：`currentVersionUnlocked: boolean`（= 存在已付快照且其现算 hash == 当前章集合现算 hash）、`purchasedVersionCount: int`（已付快照数）。无章时二者为 false / 已付数。
2. **次数变化不算新版本**：同一组场所再到访、次数增加 → `currentVersionUnlocked` 仍为 true（测试）。
3. **新盖一枚章 → false**（整本重新带水印，D-4）（测试）。
4. **场所合并后已买版本仍判为当前**：买 `{A, B}` → 后台把 B 并入 A → 当前章集合 `{A}` → 现算两边都是 `{A}` → true（集成测试，走真实 `PlaceMergeService.merge`）。
5. 场所下架：章仍在（1-2 口径），hash 不变 → 已买仍判当前（测试）。

**AC6 — 纵览页购买入口与 B7 抽屉** `[L2]` `[L0]`
1. 1-2 的纵览页 B2b：`currentVersionUnlocked == false` 且有章 → 吸底主按钮「Buka versi ini · Rp{价格}」（价格读 `keepsakePricingProvider.passportSnapshot`，3-2 交付；**不硬编码** 2000）；`true` → 吸底改为已购态文案「Versi ini sudah kebuka」（禁用态，不可点）。
2. **单章页 B2 不出任何付费按钮**（源码 / widget 断言）；B2 吸底「Bagikan」属 Epic 4（4-3），本 story 不加。
3. 点按钮 → B7 抽屉（贴底、顶部圆角）：标题「Buka paspor versi ini」· 副行「{N} cap sekarang · Rp{价格}」· 说明「Nanti dapat cap baru? Versi barunya dibuka terpisah.」· 按钮「Nanti」（关闭）/「Buka」→ 进 3-2 的 `runKeepsakePurchase`（选渠道抽屉 header = 护照缩略 + 护照号；title / body 用下表文案）→ PawCoin 立即 / QRIS 面板轮询（`pollPaid` = 刷新护照读接口看 `currentVersionUnlocked`）。

5. 1-2「本 story 不显示付费按钮」的断言按新规则更新。

**AC7 — 已购版本列表与回看** `[L1]` `[L2]`
1. `GET /api/v1/pet-profiles/me/passport/snapshots` → 本宠物 **`paid_at IS NOT NULL`** 的快照，按 `paid_at` 倒序：`{ snapshotToken, paidAt, stampCount }`；未付快照**不出现**（测试）。
2. `GET /api/v1/pet-profiles/me/passport/snapshots/{token}` → 非本人 / 未付 / 不存在 → 404；返回冻结的 `stamps`（**不下发内部 placeId**，只 `placeToken` / `placeName` / `placeType` / `firstVisitDate` / `visitCount`）+ `stampCount` + `paidAt` + 当前护照号与宠物名（取实时 `pet_passports` / 宠物档案，快照不冻结这两项）。章面图 `stampImageUrl` 按**当前** `places.stamp_object_key` 现算（换章对历史生效，AD-5 / AB-18B 口径一致）。
3. 护照页 AppBar 右上加入口「已购版本」（图标按钮 + tooltip，`purchasedVersionCount > 0` 才显示；与 ⊞ / ◎ 并列，**appbar 不出 ⋯**，UX-DR14）→ 列表页「Versi yang dibeli」：每行「{日期} · {N} cap」→ 点进回看页：同护照内页版式、**无水印**、只读（不可翻到实时数据、不出购买按钮）。「重新导出」按钮属 Epic 4（4-3「已购版本里每个版本可重新导出」），本 story 不加。
4. 订单中心跳转（3-6）使用本接口的 `{token}`。

**AC8 — 服务端埋点** `[L0]`
AFTER_COMMIT 订阅 `KeepsakeUnlockedEvent`（`sku == PASSPORT_SNAP`）发 `passport_snapshot_unlocked`，属性 `stamp_count`、`price`；两者登记 `AnalyticsEventGuard` 双白名单（`price` 若 3-2 已登记则复用）。**事件名 PRD 未给**，本 story 暂定此名，Completion Notes 提请产品确认。

**AC9 — 删档** `[L1]`
`passport_snapshots` 在 `ProfileDeletionService` 内（`petProfiles.delete` 之前，经 1-2 建立的 passport 删档方法）物理删除（在 1-2 的 `PetPassportDeletionService.deleteForPet` 内追加）；FK `ON DELETE CASCADE` 作兜底。级联测试：删档后无快照残留；对应 `keepsake_purchases` 仍在、`pet_profile_id` 为空；删档后再到账 → `ORPHAN_PAID`（3-1 口径，此处端到端再测一次）。

### 关键设计点

- **版本 = 场所集合**：只看「有哪些场所的章」，不看次数、不看章面图；这正是「次数变化不算新版本」「换专属章不算新版本」的来源。
- **冻结在发起时**（AD-7）：付款窗 60 分钟内盖了新章，用户付款得到的仍是发起时的那一版——抽屉文案「{N} cap sekarang」就是这一版的章数；UI 不需要在付款后提示「你买的不含新章」，护照重新带水印已经说明。
- **hash 现算**的理由：合并场所会改变 `place_id`，落库值会过期；两处同调一个函数就不会出现「购买时一种算法、展示时另一种」。
- **快照 JSON 里的 `placeId` 只给现算 hash 用**，对外 DTO 不下发（对外标识一律 token）。
- **回看读快照 JSON，不读实时打卡**；但护照号 / 宠物名 / 章面图取当前值（它们不是「版本」的一部分，护照号本就不变）。
- 「已购版本」入口两处（D-4）：护照页右上 + 我的订单（3-6）；两处只列已付。
