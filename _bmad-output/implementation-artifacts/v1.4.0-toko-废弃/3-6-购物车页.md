## Dev Notes

### 🔒 游客的门控放在页面里，不放进 `_controlledLocations`
`/shop/cart` **有意不加入受控路由白名单**：redirect 会把游客直接甩回 `/home`，等于告诉他
「这里没有购物车」——而真相是「登录后就有」。这一句之差正是 FR-0B 软性引导存在的理由。
页面游客态**不发任何 `/me` 请求**，零数据暴露。

### 🔴 数据层自己短路游客，不能只靠页面不 watch
`CartController.build` 里 `if (!auth.isLoggedIn) return CartView.empty;` 是**安全语义**而非优化：
游客打 `/me/cart` 拿 401 → `AuthInterceptor` 续期失败 → 弹**强登录引导**。也就是说只要有一处
（如 Toko 的角标）watch 了这个 provider，游客一进商店就会被强弹窗糊脸 —— 那正是 FR-93A
明令不要的登录墙，只不过换了个触发点。
⚠️ 变异验证 M5 暴露过一次假绿：cart_page 的游客 widget 用例守不住这条（游客态页面根本没
watch），已补 `ProviderContainer` 直读 `cartProvider.future` 的用例把断言压在 build 上。

### 🔴 `showSoftSheet` 新增 `allowRepeat`（默认 false，既有调用点零行为变化）
软浮层原本「每 session 最多一次」。那条去重守的是**被动弹出**的引导（用户没做什么、系统主动
劝登录，弹第二次是骚扰）。但**用户自己点了加购**是明确意图，此时 no-op 会让按钮看起来是坏的，
而这恰是转化漏斗上最贵的一次点击。两类触发语义不同，不该共用一个开关。

### 🔴 客户端不重算合计
金额与件数**全部取后端 `CartView`**（`subtotal` / `itemCount` 已排除失效行）。
本页不自己 fold 一遍 —— 两处各算必漂移，而这是钱。

### 数量上限的两条保守选择
- `availableStock == null` 时 `+` **置灰**：库存不明宁可挡一次购买，不可放过一次超卖（硬纪律 5）
- 未知 `invalidReason` 归 `unavailable` 而不是当成有效行：认不出就当失效，是「宁可挡」的那一侧

### 减到 1 再减就是删除
后端 `qty<=0` 即删（不需要第二个端点），所以 qty=1 时减号图标同步换成垃圾桶 ——
否则用户点「−」整行却消失，会以为点错了。

### 角标暂挂 AppBar，不动 Tab
Tab 位序归 DEP-1、图标归 DEP-2，均未闭合，本版本不碰 `bottom_tab_bar.dart`（并行契约 §三.5）。
`CartIconButton` 挂在 Toko / 商品详情的 AppBar 上；DEP-1 闭合后 Tab 角标直接 watch 同一个
`cartItemCountProvider` 即可，与本次改动不冲突。

### ✏️ 改写了 Story 1.6 的一条断言
`toko_page_test.dart` 原有「购物车图标不可点」当时的意思是「不得跳到不存在的页面/登录页」。
页面存在之后继续禁用它就是死链，故翻面为「可点 + 游客态不显示角标」，
「游客点进去不被踢到登录页」由 `cart_page_test.dart` 的游客用例接手看守。

### 埋点（命名护栏：`toko_` 前缀 + 动作词尾）
`toko_cart_page_viewed` · `toko_cart_checkout_tapped` · `toko_cart_clear_invalid_tapped` ·
