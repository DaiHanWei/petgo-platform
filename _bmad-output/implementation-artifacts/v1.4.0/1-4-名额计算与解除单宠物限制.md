## Story

As a Lv5 及以上的用户,
I want 用等级解锁的名额建第二、第三只宠物,
so that 我的每只宠物都有地方记录。

## Acceptance Criteria

**AC1 — `PetSlotService.quotaOf(userId)`** `[L0]`（AD-5、FR-146.1、PRD §6.2「虚拟号返回不参与」）
1. 新包 `com.tailtopia.profile.slot`：`PetSlotService`（`@Service`）+ `PetSlotQuota` record：
   `PetSlotQuota(int total, int defaultSlots, int levelSlots, int rentalSlots, int petCount, int rentable, boolean canRent, Integer nextLevelSlot, boolean hasActiveRental)`。
2. 计算（实时、不落库）：`defaultSlots = 1`；`levelSlots = level.participating() ? [Lv≥5] + [Lv≥10] : 0`（读 `GrowthQueryService.getLevel(userId)`，**不得自写等级判断**）；`rentalSlots = 0`、`hasActiveRental = false`（Story 2.2 接入 `pet_slot_rentals`）；`total = min(MAX_PETS, default + level + rental)`，`MAX_PETS = 5`；`petCount = countByOwnerId(userId)`；`rentable = MAX_PETS − total`（架构 AD-5「可租数 = 5 − 名额」，与已建只数无关）；`canRent = rentable > 0`；`nextLevelSlot` = 参与且 `level < 5` → 5，`5 ≤ level < 10` → 10，其余（含不参与）→ `null`。
3. 等级门槛写成常量 `LEVEL_SLOT_THRESHOLDS = {5, 10}`（PRD 拍板值，`PetSlotService` 内唯一一处）。
4. 类 Javadoc 写：「名额**只经本方法**（架构 §5）；月租部分由 Story 2.2 接入；`GrowthQueryService` 由 ① 替换方法体后本方法自动读到真实等级」。
5. Given 虚拟号 / 查无此人（`NOT_PARTICIPATING`），Then `levelSlots = 0`、`total = 1`；Given 地基占位下的真实用户（Lv1），Then `total = 1`、`nextLevelSlot = 5`。

**AC2 — 建档改为名额校验** `[L0]` `[L1]`（PRD AC1 / AC8 / AC9、FR-145.1、AD-3）
1. `ProfileService.create`（:60）去掉「已有档案 → 409 `profile-exists`」（:61-63），改为（同一 `@Transactional` 内、在任何写入之前）：
   ① `PetSlotLock.lockUser(userId)`（见 AC4）；
   ② `count = countByOwnerId(userId)`；`count ≥ 5` → **409 `pet-limit-reached`**；
   ③ `quota = petSlotService.quotaOf(userId)`；`count ≥ quota.total()` → **409 `pet-slot-full`**；
   ④ 其余照旧建档（里程碑 roster、`ProfileCreatedEvent`、送审事件不变）。
2. 两个新错误：`ErrorTypes.PET_SLOT_FULL = BASE + "pet-slot-full"`、`PET_LIMIT_REACHED = BASE + "pet-limit-reached"`。`pet-slot-full` 用新异常 `profile.slot.PetSlotFullException extends AppException implements ProblemExtensions`（照 `shop/order/dto/CheckoutUnavailableException.java`），扩展成员（camelCase）：`canRent`（boolean）、`nextLevelSlot`（Integer，可 null）、`petCount`、`slotTotal`、`unitPrice`（long，IDR；**本 story 取常量 `PetSlotService.DEFAULT_UNIT_PRICE = 5000`**，Story 2.2 改读 `pricing_config.pet_slot_monthly_price`，键名与 2.2 `PetSlotOverview.unitPrice` 一致）——App 名额已满抽屉 A4 的正文「Kamu sudah punya {n} hewan dari {n} slot … sewa slot {price} / 30 hari」直接用这些值，不再请求别的接口。`pet-limit-reached` 用 `new AppException(CONFLICT, PET_LIMIT_REACHED, …)`，无扩展。
3. 场景（`GrowthQueryService` 用 mock 设定等级）：
   - Lv1 无月租、已有 1 只 → 建第二只 409 `pet-slot-full`（`slotTotal = 1`、`canRent = true`、`nextLevelSlot = 5`）。
   - Lv5（名额 2）→ 第二只成功；第三只 409 `pet-slot-full`（`nextLevelSlot = 10`）。Lv10 名额 3。
   - Lv10 有 3 只、降到 Lv9 → 3 只照常查询 / 使用；建第 4 只 409（PRD AC9：降级不影响已建，**不转只读**——只读状态在 2.1）。
   - 已有 5 只 → 建第 6 只 409 `pet-limit-reached`（优先于 `pet-slot-full` 判定）。
4. `catch (DataIntegrityViolationException)`（:106-109）保留，但注释改为「唯一约束只剩 `card_token`（理论撞号）」；仍归一为 409 `profile-exists`（旧版 App 只认这个 slug，`pet_profile_create_page.dart`:137）。
5. 旧版 App 兼容：旧版建档页有「已有档案直达」守卫，不会发第二次 POST；万一发了，收到 409（`status == 409` 分支）照旧提示，不崩。

**AC4 — 并发建档按账号串行化** `[L0]` `[L1]`（epics 1.4 AC5）
1. 新类 `profile.slot.PetSlotLock`（`@Component`），`@Transactional(propagation = MANDATORY)` 方法 `lockUser(long userId)`：`SELECT pg_advisory_xact_lock(:ns, :uid)`，`ns = PET_SLOT_LOCK_NS = 0x5045_5453`（"PETS"），`uid = (int) (userId % Integer.MAX_VALUE)`——写法照 `profile/service/CardNumberService.lockOwnerForCardCreation`（:97-103）的两参形式；命名空间不得与现有 `0x4943_4352`（CardNumberService）、`0x5453_5352` / `0x5050_5352` / `0x4147_4543`（三个分享奖励渠道）相撞，类 Javadoc 列出这些已占用值。

### 架构约束

- AD-1 / V-2：约束最后删；删前守卫绿。
- AD-3：建档满 → 409 `pet-slot-full`（带 `canRent` / `nextLevelSlot`）；已达 5 → 409 `pet-limit-reached`；他人主页 `GET /users/{userId}/pets` 列表，旧 `/pet` 保留默认宠物。
- AD-5：名额 = min(5, 1 + [Lv≥5] + [Lv≥10] + 生效月租数)，实时计算、不落库；虚拟号 / 官方号按「不参与」= 默认 + 月租。**官方号**是否参与以 `GrowthQueryService` 返回为准（地基占位把官方号当真实用户 Lv1，① 拍板 P-7「官方号不参与成长值」后由 ① 改方法体），本线不自行判断 `role`。
- §5：名额只经 `PetSlotService.quotaOf`；不得在别处拼「1 + 等级」。
- CROSS-STORY 地基节：`GrowthQueryService` 只调用，禁止替身或自写等级判断；`participating = false` 一律不给权益。
- 护栏：不引 MQ / 缓存；迁移时间戳号已预分配；`ddl-auto=validate`（本迁移只删约束 + 加普通索引，实体无需改动）。

### 本 story 不做

- 不做月租（`pet_slot_rentals` / `pet_slot_purchases`、价格配置、购买接口）→ **2.2**；`quotaOf` 的 `rentalSlots` / `hasActiveRental` 本 story 恒 0 / false。
- 不做只读状态、`reconcile`、监听 `GrowthLevelChangedEvent` → **2.1**（本 story 降级只影响「能否新建」）。
- `GET /pet-slots/me` 本 story 只做最小版（AC6）；月租名额列表、到期日、配置价格 → **2.2** 追加。
- 不改 App → **1.5**。
