## Acceptance Criteria

**AC1 — 迁移 `V20261018_1501__feed_rank_author_level_boost.sql`** `[L0]` `[L1]`（AD-15、6.4）
1. 内容：
   ```sql
   ALTER TABLE feed_rank_config
       ADD COLUMN author_level_boost DOUBLE PRECISION NOT NULL DEFAULT 1.05;
   ALTER TABLE feed_rank_config
       ADD CONSTRAINT ck_feed_rank_author_level_boost
           CHECK (author_level_boost >= 1.00 AND author_level_boost <= 2.00);
   COMMENT ON COLUMN feed_rank_config.author_level_boost IS '作者等级加权：Lv15 及以上真实作者在首页推荐流的乘法系数，默认 1.05，1 = 不加权；Lv15 门槛写死在代码';
   ```

3. 文件头注释照 `V20261012_1102__feed_rank_edu_half_life.sql` 的写法：出处（V1.4.0 ① AD-15 / FR-144.5）、默认值、CHECK 理由（< 1 就是降权，与「权益」相反；上限 2 防误填 10）。
4. 不改任何共享约束；`config_change_logs.ck_config_change_type` 已含 `FEED_RANK`（最新重建在 `V20261014_2304__config_change_log_app_version.sql:22-23`），**不动**。

### `config_change_logs` 真实写法

- 表 `config_change_logs(id, config_type VARCHAR(24), field VARCHAR(48), old_value VARCHAR(64), new_value VARCHAR(64), changed_by, changed_at)`（`V78__init_platform_config.sql:58-66`）；`config_type` CHECK 最新全集 `PRICING / PAWCOIN / TOPUP_TIER / FEED_RANK / SUPPORT_CONTACT / APP_VERSION`（`V20261014_2304`）。
- 写入只经 `AdminConfigService.diff` → `ConfigChangeLog.of(type, field, old, new, adminId)` → `commit` 的 `changeLogs.saveAll` + `audit.record(adminId, "CONFIG_UPDATE_FEED_RANK", "config", "feed_rank_config", "N field(s) changed")`。`field` 用**列名** `author_level_boost`（≤ 48 字符，变更抽屉按它筛选、按 `FIELDS.labelKey` 显示中文标签）。

### 架构约束

- AD-15：系数挂在 `FeedRankScorer` 乘法链末尾；Lv15 门槛写死；只作用首页推荐流；虚拟号不吃（AC12）。
- 5.5：权益判断只用 `getLevel(s)`，不得用展示用的 `getBadges`。
- 列表批量：一次生成只调**一次** `getLevels`（候选池几百条、作者数十到上百），禁止逐条查（NFR3）。
- 不加缓存：等级每次生成序列时直读（序列本身已由 `FeedSequenceStore` 缓存，续页不重算）。
- 生效时机：保存后**下一次生成序列**生效（下拉刷新 / 新会话）；已缓存的序列不回溯——与页面既有提示 `admin.v130.algo.scope`（zh_CN `:2814`）一致，不另加文案。
- 对用户只说「Postingan lebih sering tampil」，不出现 ×1.05（OQ-7）——那是 Story 1.5 / 2.3 的权益文案，本 story 不碰 App。

### 本 story 不做

- 不给分类 Tab / 关注流 / 置顶位加权；不做「可发布视频」等其它 Lv 权益。
- 不把 Lv15 门槛做成参数；不新增权限码。
- 不改 App；不改 `RankThrottleService`、`RankParams`。
