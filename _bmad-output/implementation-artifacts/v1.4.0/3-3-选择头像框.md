## Story

As a Lv5 及以上的用户,
I want 在等级页挑选头像框或不戴，升级时一键戴上新框,
so that 我能决定自己怎么被看见。

## Acceptance Criteria

### 后端

**AC1 — `PUT /api/v1/me/growth/frame`** `[L0]` `[L1]`（AD-16、FR-144.4、AC19）
1. 在 Story 1.4 的 `MeGrowthController` 加 `PUT /api/v1/me/growth/frame`，请求体 `{"frame": "NONE" | "BASIC" | "UPGRADED" | "ANIMATED"}`。
2. 新建 `growth.service.GrowthFrameService.choose(long userId, FrameChoice requested)`，同一事务内：
   ① 参与判定（与 Story 1.4 的口径一致：虚拟号 / 非真实用户按 1.4 对 `GET /me/growth` 的处理返回，T0 核对）→
   ② 懒建账户行（复用 Story 1.1 的 `INSERT … ON CONFLICT DO NOTHING`）并 `SELECT … FOR UPDATE` 锁住 →
   ③ 用 Story 1.2 的推导方法算**当前等级**下的可用档 →
   ④ `requested = NONE` 恒允许；`requested` 不在可用档内 → 抛 **409 `frame-locked`**，`frame_choice` **不变** →
   ⑤ 写 `frame_choice = requested`（与现值相同则不写，幂等 200）。
3. 成功返回 200，响应体 = 与 `GET /api/v1/me/growth` 中「头像框四档」**同一个 DTO**（可用 / 生效 / 是否手动），App 拿它直接刷新一排卡片，不必再拉整页。
4. 选择任何框（含当前自动生效的那一档、含 `NONE`）后 `frame_choice` 非空 → 此后升级**不再自动更换**（AD-10 / PRD 佩戴规则 ③）。
5. 非法取值（不在四值内 / 缺字段）→ 422 `validation`（RFC 9457，走既有 `AppException.validation`）；游客 401。
6. 新增 `shared/error/ErrorTypes.FRAME_LOCKED = BASE + "frame-locked"` 与 `AppException.frameLocked(String detail)`（照 `ErrorTypes.FOLLOW_BLOCKED` `:69` / `AppException.followBlocked` `:179` 的写法）；`detail` 只写英文技术说明，不含用户数据。
7. 本接口**不写成长值流水**、不触发等级变化、不发事件（5.4 的写入纪律只管 EXP；`frame_choice` 只经 `GrowthFrameService` 写）。

**AC2 — 生效即时可见** `[L1]`
1. `PUT` 成功后，`GET /api/v1/me` 的 `growth.frame`、`GET /api/v1/me/growth` 的生效框、以及 Story 3.1 下发给他人的 `authorFrame` **立刻**是新值（读时推导，无缓存）。
2. 选了 `NONE` → 上述三处都无框；`GET /me/growth` 的「是否手动」为 true。
3. 选 UPGRADED 后因退款降到 Lv9 → 生效框自动退回 BASIC，`frame_choice` 仍为 UPGRADED（Story 1.2 已实现，本 story 用 L1 回归一次，AC19）。

### App

**AC3 — 等级页头像框一排（C1 ~ C5）** `[L0]` `[L2]`（UX-DR6、FR-144.3 / 144.4）

### 架构约束

- AD-16：`PUT /api/v1/me/growth/frame`，不可用 → 409 `frame-locked`，RFC 9457 ProblemDetail，不外泄堆栈。
- AD-10：头像框读时推导，不存「当前框」；`frame_choice` 只表示用户意愿；`NONE` = 主动不戴。
- 5.4：写成长值只走 `GrowthLedgerService`；`frame_choice` 不是成长值，只经 `GrowthFrameService` 写，**其它地方不得直接 UPDATE 该列**（Story 1.2 的降级回退是读时推导，不写列）。
- 并发：`SELECT … FOR UPDATE` 锁账户行后再判可用，防止「判可用 → 同时降级 → 写入不可用档」；即便写入后降级，读时推导也会退回最高可用档。
- 对外标识：接口只认当前登录用户（JWT），无任何 id 入参。
- 日志只记 userId 与选择值，不记昵称。
- App：段位色 / 状态色只取 `colors.dart`；不渲染后端显示串；动效尊重 `disableAnimations`（由 3.2 组件保证）。

### 前后 story 边界

- **Story 1.5 → 本 story**：1.5 的等级页不放（或只占位）头像框一排，本 story 补上 C1 ~ C5，并把等级卡头部头像换成 3.2 的装饰组件。
- **Story 2.3 → 本 story**：2.3 的「Pakai Bingkai Baru」先跳等级页，本 story 改为一键戴上（D5 / D6）；2.3 的弹出时机、ack、`StartupPopupLedger` 登记、D2「已自动戴上」文案都不动。
- **Story 3.2 → 本 story**：3.2 提供组件与「我的」页读 `growth.frame`；本 story 只负责切换后把新值同步过去。
- **本 story 不做**：后台改用户头像框（无此需求）；虚拟号选框（虚拟号无等级页，后台只设展示等级，Story 4.4）；升级后自动换框逻辑（Story 1.2 读时推导已覆盖）；任何迁移。
