## Story

As a 多宠物用户,
I want 里程碑、护照、问诊、身份证、分享、推送、后台等所有模块都能正确处理多只宠物,
so that 账号有第二只宠物时不会出现报错、白屏或数据串错。

## Acceptance Criteria

**AC1 — 多宠下全部读口不抛异常、取对的宠物** `[L0]` `[L1]`（epics 1.2 AC1、§0.3 第 1 / 2 条）
- Given 测试夹具为同一账号造 A（先建）、B 两只宠物（做法同 Story 1.1 Dev Notes「造双宠物的测试夹具」：L0 mock 仓储；L1 用 `MultiPetDbFixture` 临时删约束），When 调用兽医工作台待接单 / 待付款 / 会话 / 历史列表、问诊发起、Tailsonality（提交 / 列表 / 详情 / 解锁 / 佩戴）、护照页 / 快照、登机牌、身份证（旧单卡 / 生成号 / 高清购买）、复购卡片与档案推荐、后台用户详情 / 种子帖宠物下拉 / 发布身份物种列，Then 均不抛异常，按「调用点改造清单」的规则取对的宠物：
  - `/me/*` 带 `petId` → 该宠物；不带 → 默认宠物（`DefaultPetPolicy`）。
  - token 寻址的资源（Tailsonality 结果、护照快照）→ 由 token 行的 `pet_profile_id` 反查宠物并校验属于本人，否则 404。
  - **问诊按单上的宠物**：`consult_requests.pet_profile_id` / `consult_orders.pet_profile_id`；没有订单的历史会话（V1.0 免费会话）回落默认宠物。
  - 后台：用户详情「宠物档案」列全部宠物；种子帖宠物下拉列全部宠物。
- 1.1 留下的 `TODO(v1.4.0-multi-pet-1.2)` 全部清零：控制器把 `pet.getId()`（或 `resolveOptional` 的结果）传入服务层。

**AC2 — 分享奖励：每只宠物各一次、年龄卡按账号** `[L0]` `[L1]`（PRD AC7、FR-145.6、P-3）

- 无宠物（`resolveOptional` 为 empty）→ 返回 coins 0（与现状 AC4「无档案不发」一致），不是 404；他人 petId → 404。

## Dev Notes

### 统一改法（先读这一段再看清单）

- **按宠物操作**：服务方法加 `long petId`（由控制器经 `PetResolver` 解析后传入）或 `Long petId`（服务内 `petResolver.resolve`）；跨模块服务不得注入 `PetProfileRepository`，走 `PetProfileQueryService` 的新读口。
- **只判有无**：`existsByOwnerId` 保留不改。
- **问诊按单号宠物**：用单据上的 `pet_profile_id`，不再按 `userId` 反查宠物。`consult_requests` / `consult_orders` 的 `pet_profile_id` **没有外键**（`V66__init_consult_billing.sql`:11 / :32），宠物删除后查不到 → 走现有「身份缺失」兜底（`EMPTY_PET` / null），不得抛异常。
- **后台列表**：取全部宠物（按创建时间）。
- **账号级过渡（最终语义在后续 story）**：库里仍单宠物，本 story 只保证多宠时确定性、不抛异常；注明「→ 1.3 / 3.2」的行，后续 story 会再改语义，本 story 不提前实现。

### 架构约束

- AD-1：删除 `Optional findByOwnerId` 前全仓清零 + 守卫测试；**唯一约束本 story 仍不删**（1.4）。
- AD-2：问诊按单上的宠物；后台按列表；默认宠物只经 `DefaultPetPolicy`。
- V-1：`ContentSpeciesResolver` / `viewerMainSpecies` / 兽医身份读口多宠下确定性、不抛异常。
- P-3：年龄卡分享奖励按账号，表结构不动；其余分享奖励每只宠物一次，受 `share_reward_monthly_cap`。
- 模块边界：跨模块只经 `PetProfileQueryService` / `PetResolver`（profile 包内）；consult / passport / tailsonality / place / share / shop / notify 不得新注入 `PetProfileRepository`（share 与 shop 现状已注入的保持，不扩散）。
- 护栏：不引 MQ / 缓存；本 story 无迁移；日志不记宠物名 / 体重。
