# Story 1.7: 商品详情页与规格选择器（App）

Status: review

## Story

As a 用户, I want 在详情页看清商品信息、选择规格、知道有没有货, so that 我能判断要不要买、买哪个规格。

## Acceptance Criteria

### AC1 — 页面内容与退货规则标识
主图 + 图集（≤8）· 品牌 · 名称 · 价格 · 详情富文本 · 保质期说明 · **退货规则标识**。
🔴 **UX-DR10 二义三值**：`可退` / `开封不退` / `不可退`（C-13 砍换货后，「可退可换」措辞作废 —— 换货零实现，标出来就是无法兑现的承诺）。
价格 `Rp 285.000`（千分位点号、无小数）。
🔴 **「开封不退」须在此页明示**（FR-104 三处明示的**第 1 处**；第 2 处结算页 Epic 3、第 3 处退货申请页 Epic 5，UX-DR11 要求三处一致）。
`[L0]` widget 测试 · `[L2]` 视觉比对 `页面/pages/02-商品详情-可购买.html`

### AC2 — 🔴 FR-94A 规格选择器：不默认选中
多规格时加购按钮**禁用**，且**不默认选中第一个** —— 1.5kg 与 7.5kg 差价近 4 倍，默认选中会让用户在没意识到时买错，而自营模式下误购的退货成本由平台承担。
单一规格不展示选择器、直接可加购。切换规格时价格 / 库存 / **退货规则标识**同步刷新（同商品不同 SKU 可不同）。
`[L0]` 未选禁用 / 选后启用 / 单规格直通 / 切换刷新

### AC3 — 🔴 FR-95 库存三态，不虚构数字
售罄 → `Stok habis` + 加购禁用；低库存 → `Sisa {n}`，**n 取真实剩余数**。
`[L0]` 三态 · `[L2]` 视觉比对 `页面/pages/02-商品详情-售罄.html`

## Dev Notes

### 🔴 三条会造成真实损失的规则
1. **不默认选中规格**（FR-94A）—— 防误购，自营模式下退货成本平台承担
2. **`Sisa {n}` 取真实数**（FR-95）—— 虚构紧迫感被戳穿，赔的是平台可信度
3. **「开封不退」购买前明示**（FR-104）—— 不说清就是把纠纷推给客服

### 未知枚举值的降级方向（有意选最保守）
- 未知 `returnPolicy` → `NO_RETURN`（宁可少承诺，不可多承诺）
- 未知 `stockStatus` → `OUT_OF_STOCK`（宁可挡一次可能成立的购买，不可放过一次超卖）

### 边界
❌ 加购动作本身属 Epic 3（按钮启用逻辑是本 Story 的，动作只给提示，不跳登录不跳死链）
❌ 评价列表属 Story 7.3 ❌ 富文本渲染库不引（NFR-1 不加依赖，剥标签按纯文本呈现）
