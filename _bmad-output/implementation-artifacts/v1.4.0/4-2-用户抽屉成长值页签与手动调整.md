## Story

As a 运营,
I want 在用户抽屉里查看某个用户的成长值，并手动调整或发放单个运营活动 EXP,
so that 能处理客诉、补发漏账、给单个用户发活动奖励。

**AC5 — 入账（`GrowthLedgerService.adjust`）** `[L0]` `[L1]`（AD-1 / AD-2 / AD-5 adjust / AD-10 / §5.2 / §5.4）
1. 在 Story 1.1 的 `GrowthLedgerService` 上**新增** `adjust(AdminAdjustCommand)`（不改 `accrue / reverse`）。`AdminAdjustCommand(long userId, AdjustType type, int delta, String note, long operatorAdminId, String grantToken)`，`AdjustType ∈ {ADMIN_ADJUST, OPS_CAMPAIGN}`。
2. 流程（同一事务）：①参与判定——与 Story 1.1 `accrue` 同一口径（`AccountQueryService.isActiveRegularUser` :72-80：`role = USER`、`account_type = REAL`、未注销、`status = ACTIVE`），否则 422（官方号 `role = ADMIN` 按 1.1 暂不参与）；②`OPS_CAMPAIGN` 时读 `growth_rules.OPS_CAMPAIGN.enabled`，停用 → 422；③锁账户行（`SELECT … FOR UPDATE`，无行则懒建，同 `accrue`）；④`lifetime_total + delta < 0` → 422 **拒绝**（AD-1：运营负向调整超出累计值时拒绝，不截断）；⑤插流水：`rule_code = type`、`delta`、`reason = 'ADMIN_ADJUST'`（运营活动可空，按 T0 核对的 Story 1.1 口径）、`note`、`operator_admin_id`、`wib_date = 今天(WIB)`、`idem_key = GrowthIdemKeys.admin(grantToken)`（= `ADMIN:{grantToken}`，**禁止手拼**，§5.2）；幂等键冲突 = 已处理过 → 直接返回「重复提交」结果、不再改累计；⑥更新 `lifetime_total`（`level` 由下一步 handler 统一算，不在这里写）；⑦调用 Story 1.2 的 **`GrowthLevelChangeHandler.onLifetimeChanged(lockedAccount, source)`**（`source = RuleCode.ADMIN_ADJUST` / `RuleCode.OPS_CAMPAIGN`；由 handler 统一定级与连锁：升级 → 待弹庆祝 + `GROWTH_LEVEL_UP` 通知；降级不通知；升降都发 `GrowthLevelChangedEvent`），本 story 不自写这些连锁。
3. 运营调整**不受每日上限约束、不占 `growth_daily_counters`**。
4. 返回值带 `{oldTotal, newTotal, oldLevel, newLevel, replayed}`，供 controller 出 toast 与重渲染。
