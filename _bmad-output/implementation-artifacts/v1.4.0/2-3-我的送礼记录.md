Status: ready-for-dev

> 前置：**Story 1.1**（`gift_orders` 表与状态机、`debit(SPEND, refType = "GIFT")`）、**Story 1.2**（退回 `credit(TOPUP, refType = "GIFT_REFUND")`、`UNDELIVERED_REFUND_PENDING` / `UNDELIVERED_REFUNDED` / `REFUND_MANUAL`）、**Story 2.2**（`DeepLinkRoutes` 已把 `GIFT_UNDELIVERED_REFUND` 映射到 `/me/gift-orders`）。

## Story

As a 送礼人,
I want 在钱包页看到我送出的每一笔礼物和状态,
so that 我知道礼物是否送达、退回是否到账。

## Acceptance Criteria

### 后端

**AC1 — `GET /api/v1/me/gift-orders?cursor=`** `[L0]` `[L1]`（AD-10、FR-148.6、PRD AC10b）
1. `GET /api/v1/me/gift-orders` 加在 1.1 的 `gift.web.GiftController` 里（它已有单笔状态 `GET /api/v1/me/gift-orders/{orderToken}`，见 1.1 story AC9「Web 层与安全」），两者路径不冲突；只作用于 JWT `sub` 本人，沿用该控制器的 `currentUserId`。`SecurityConfig`：1.1 加的是 `/api/v1/me/gift-orders/*`，**匹配不到不带段的列表路径** → 本 story 补精确 `"/api/v1/me/gift-orders"` → `hasRole("USER")`（放在 `anyRequest()` 之前；不加会落 `anyRequest().authenticated()`（:349），兽医 token 能以同号用户名义读）。
2. 只列 `sender_id = 本人` 的订单（**只送出**，收到的不在这里，PRD「收到的礼物不在这里重复展示」）；`ORDER BY created_at DESC, id DESC`，每页 20；游标用 `shared.paging.KeysetCursor`（`KeysetCursor.java`:37 `encode()` / :53 `decodeOrNull()`），非法游标 → 400 ProblemDetail；响应 `{ items: [...], nextCursor: string | null }`。走 1.1 建的索引 `(sender_id, created_at DESC)`。
3. **列入的状态**：`PENDING`、`DELIVERED`、`UNDELIVERED_REFUND_PENDING`、`UNDELIVERED_REFUNDED`、`REFUND_MANUAL`。**不列** `EXPIRED`、`FAILED`（未付款、没扣钱，不算一笔送礼；PRD 记录页只有三种状态）。
4. 行结构 `GiftOrderRow`：
   ```
   { orderToken, createdAt, status, channel, quantity, total,
     gift: { nameEn, nameId, iconUrl, unitPrice },      // 订单快照列，不 join gift_catalog
     pet:  { petId, name, avatarUrl } | null,            // 宠物已删 → null
     petGone: boolean }
   ```
   - `status` 原样下发订单状态代码，`channel` ∈ `PAWCOIN` / `QRIS`，App 按代码本地化（不下发显示串）。
   - `pet`：`gift_orders.pet_id` 为 null（宠物已删，AD-2 `ON DELETE SET NULL`）或 `GiftPetDirectory.pet(petId)` 为空 → `pet = null`、`petGone = true`（1.1 的 `pet_name` 快照不下发——UI 稿 F2 宠物已删行只显示「Hewan ini sudah tidak ada」）。否则取 `GiftPet` 的 name / avatarUrl（`avatarUrl` 经 `AliyunOssClient.exifStrippedDeliveryUrl`，与 `VisitorProfileResponse.java`:44 同口径）。一页内**按去重后的 petId 逐个**调 `GiftPetDirectory.pet`（每页至多 20 只；端口没有批量方法，不为此改端口签名——4.1 对齐时如需批量再加）。
   - **不下发** `payment_intent_id`、`owner_id`、`sender_id`、`gift_id`、`idem_key`、`undelivered_reason`、`refund_error`、自增 `id`。
5. Given 送礼人有 QRIS 等待付款、已送达、已退回各一笔，When 请求，Then 三行按时间倒序、`status` 分别 `PENDING` / `DELIVERED` / `UNDELIVERED_REFUNDED`，每行含时间、宠物、礼物快照 × 数量、总价、渠道；该 QRIS 付款成功后再请求，Then 同一行变 `DELIVERED`（AC10b）。
6. Given 收礼宠物已被删除，When 请求，Then 该行 `pet = null`、`petGone = true`，其余字段照常（快照仍在）。
7. Given 有 45 笔（含 2 笔 `EXPIRED`），When 翻页，Then 只出 43 笔、20 / 20 / 3、无重复无遗漏、末页 `nextCursor = null`。
8. 不接受 userId / token 参数；带 `?userId=` 也只返回本人。日志不记礼物名与金额明细。

### 拍板点（按建议实现，Completion Notes 复述）

- **① 退回中 / 需人工两态**：PRD 与 UI 稿只画了三种状态，但 `UNDELIVERED_REFUND_PENDING` / `REFUND_MANUAL` 是「钱已付、还没退回」的真实中间态（1.2 重试最多 5 次），不能显示成「已退回」也不能藏起来 → 复用现有「Pengembalian diproses」。
- **② 过期 / 失败不列**：未付款不扣钱，列出来会让记录页出现 UI 稿没有的「已过期」状态。

### 实现提示

- 后端查询：`gift_orders WHERE sender_id = :me AND status IN (…) AND (created_at, id) < (:c, :i) ORDER BY created_at DESC, id DESC LIMIT 21`（多取一条判 `nextCursor`）。
- App 宠物名、头像以接口当下值为准（宠物改名后记录页显示新名）；礼物名 / 图标 / 单价以订单快照为准（NFR2）。
- 渠道显示用品牌原名，不进 arb（`PawCoin` / `QRIS` 两语一致）。
- 列表空与首屏失败分开：首屏失败整页 F4；加载更多失败只在底部重试。

### 架构约束

- AD-10：`/me/gift-orders` 只送出、时间倒序、含状态与宠物是否已删除。
- AD-12：宠物删除 → 订单 `pet_id` 置空保留，记录页显示「该宠物已不存在」。
- AD-13 / S8：钱包流水按 `refType` 显示，钱包服务命名不动。
- §5：对外标识用 `public_token`（`orderToken`）；宠物沿用 petId 路由。
- 钱的纪律（cloud-rules-gift.md）：本 story 只读，不触碰钱包服务、订单状态、汇总表。

### 与前后 story 的边界（本 story 不做）

- 不做续付、取消、申请退款（decision-log ③ Q4；送达后不退款）。
- 不改退回逻辑与退回通知内容（1.2）；通知中心图标 / 文案 / 深链映射已在 2.2。
- 不做「收到的礼物」列表（看自己宠物的礼物墙，2.1 / 2.2）；后台抽屉「收送礼记录」在 3.2。
- 不在「我的」页或订单列表加入口（decision-log ③ S7 选 A：只放钱包页）。
