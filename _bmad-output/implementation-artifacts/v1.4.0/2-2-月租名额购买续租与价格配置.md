## Story

As a 想多养宠物的用户,
I want 按月租用名额、勾选多个名额一次续租,
so that 不升级也能多养几只。

**AC3 — `quotaOf` 接入月租** `[L0]` `[L1]`（AD-5、FR-146.1）
1. `PetSlotService.quotaOf(userId)` 的月租部分 = `pet_slot_rentals` 中 `status = 'ACTIVE' AND expires_at > now()` 的行数（`RENT` 与 `ADMIN_GRANT` 都算）。
2. `total = min(5, 1 + [Lv≥5] + [Lv≥10] + rentals)`；构成里 `rentalSlots` 给**有效**值 `total − 1 − levelSlots`（多出的本期不退、不显示为闲置），另给 `hasActiveRental`（供 4.4 `petSlotHint`）。虚拟号 / 官方号（`GrowthLevel.participating = false`）等级部分 = 0。返回类型以 1.4 实际为准，只扩字段不改签名。
3. 只经 `quotaOf` 取名额（§5）；本 story 不缓存。

**AC4 — `PetSlotPurchaseService`：新租** `[L0]` `[L1]`（AD-6、FR-146.2）
1. `rent(userId, quantity, channel, clientIdemKey)`：
   - 进入即 `PetSlotLock.lockUser(userId)`（与 2.1 / 1.4 同一把锁）。
   - `rentable = 5 − quotaOf(userId).total`；`quantity < 1 || quantity > rentable` → 409 `pet-slot-rent-unavailable`（扩展成员 `rentable`）。名额 5 时 rentable = 0，一律拒（AC8「租满后不能再租」）。
   - `unitPrice = platformConfig.pricing().getPetSlotMonthlyPrice()`（下单实时读），`total = unitPrice × quantity`，**快照进购买行**。
   - `MIXED` → 422「该商品不支持混合支付」（照 `KeepsakePurchaseService.start`:117）。
2. **PawCoin（同步成交）**：`wallet.debit(userId, total, PawCoinTxnType.SPEND, "PET_SLOT_RENT", purchaseId, idemKey)`（`refType` 必须是 `"PET_SLOT_RENT"`、`refId` = 购买行 id——① 1.3 口径表约定）→ 建购买行 `PAID`（`paid_at = now`）→ 建 N 行 rentals（`starts_at = now`、`expires_at = now + 30 天`、`source = RENT`）→ 回填 `rental_ids` → `reconcile(userId, RENTAL_ADDED)`。余额不足 `debit` 抛 `pawcoin-insufficient`（409）整事务回滚。为了拿到 `purchaseId` 先 `saveAndFlush` 一行 `PENDING` 再 debit，最后改 `PAID`（同一事务，回滚一起撤）。
3. **QRIS**：`paymentIntents.createIntent(userId, PaymentPurpose.PET_SLOT_RENT, QRIS, total, "IDR", idemKey, Duration.ofMinutes(60))` → 若返回意图已 `PAID` → 按 `payment_intent_id` 找购买行返回已完成；否则建 / 复用 `PENDING` 购买行（`payment_intent_id` = 意图 id）→ `ensureCharge` 取二维码载荷（照 `KeepsakePurchaseService.ensureCharge`:178-200 私有副本，失败 `failChargeAttempt` 留档后抛，方法 `@Transactional(noRollbackFor = PayException.class)`）。**不设 QRIS 最低额**（PRD 2026-10-13）。
4. 幂等键：资金下单端点强制 `Idempotency-Key` 头（缺失 → 422，照 `PawCoinTopupController.topup`:40-46）；服务端键 = `"PET_SLOT_RENT:" + userId + ":" + kind + ":" + clientKey + ":" + channel`（**按渠道加后缀**，原因见 `KeepsakePurchaseService` 类注释:38-41「先开 QRIS 再改 PawCoin 会被 debit 判成重放、免费拿到」）；同键重放返回同一结果，`idem_key` 唯一兜底。

**AC5 — 续租** `[L0]` `[L1]`（AD-6、AC11）
1. `renew(userId, List<String> rentalTokens, channel, clientIdemKey)`：加同一把锁；逐个按 `public_token` + `user_id` 查（非本人 / 不存在 → 404）；必须 `status = ACTIVE AND expires_at > now`，否则 409 `pet-slot-renew-invalid`（已过期名额不能续，走新租，AD-6）。
2. 续租数上限：`rentalTokens.size() ≤ max(0, 5 − 1 − levelSlots)`，否则 409 `pet-slot-rent-unavailable`（PRD：租用期间升级超 5，到期后只能续到「5 − 等级名额」个）。
3. `total = unitPrice × n`，一次付款；购买行 `kind = RENEW`、`rental_ids` = 所选名额 id、`quantity = n`。
4. 发放（PawCoin 当场 / QRIS 到账）：所选名额 `expires_at = expires_at + 30 天`、**`reminded_at = NULL`**（让 2.3 对新到期日再提醒一次）→ `reconcile(userId, RENEWED)`。例：10/31 到期、10/28 续 → 11/30（AC11）。
5. 🔴 QRIS 到账时若某个所选名额已在付款窗内过期（2.3 已置 EXPIRED）：**到账不回滚**——对该名额改为新建一行 `RENT` 名额（`starts_at = paid_at`、+30 天），`rental_ids` 记实际发放的 id；Completion Notes 记一句。

**AC6 — `PetSlotPaidHandler`（QRIS 到账）** `[L0]` `[L1]`（AD-6、AC12，照 `KeepsakePaidHandler`）
1. `@EventListener` + `@Transactional(propagation = MANDATORY)` 加入 `PaymentIntentService.applyCallback` 的事务；`event.purpose() != PET_SLOT_RENT` 直接 return。
2. 按 `payment_intent_id` 找购买行：无 → WARN 返回；已 `PAID` → 返回（重放幂等）；否则加用户锁 → 置 `PAID`、`paid_at` → 按 kind 发放（AC4 / AC5）→ reconcile。
3. **任何路径不向上抛**（兜底 catch 记 ERROR，只记 intentId / purchaseToken），否则 `markPaid` 随之回滚。
4. 回调与对账轮询（`PaymentReconciliationService.reconcile` 同走 `applyCallback`）同时到达只生效一次：`applyCallback` 的 Redis 前置 + 终态守卫 + `gateway_ref` 唯一，再加购买行 `PAID` 守卫与 `payment_intent_id` 唯一（AC12）。
5. 单一消费者守卫：新增 `PetSlotSingleConsumerSourceGuardTest`（照 `KeepsakeSingleConsumerSourceGuardTest`）——除 ① 的成长值监听外，`PET_SLOT_RENT` 的 `PaymentIntentPaidEvent` 发放只有 `PetSlotPaidHandler` 一处。

**AC7 — 付款失败 / 过期** `[L0]` `[L1]`（AC12）
1. `PetSlotPaymentFailedHandler`：`@EventListener` + `@Transactional` 监听 `PaymentIntentFailedEvent`，`purpose = PET_SLOT_RENT` 且购买行 `PENDING` → `EXPIRED`（类别 EXPIRED）或 `FAILED`（其余），照 `KeepsakePaymentFailedHandler`:30-44。**不增加名额**。
2. ⚠️ `PaymentIntentService.statusOf` 的懒过期**不发**失败事件（其 `publishFailed` 注释:276-280）→ 购买状态查询接口（AC8.4）读意图状态时自愈：意图已 `EXPIRED` / `FAILED` 而购买行仍 `PENDING` → 同步置终态。`createIntent` 复用分支懒过期同理（照 `KeepsakePurchaseService.startQris`:157-164 把旧 PENDING 行置 EXPIRED 再建新行）。

### 名额与价格口径

- 名额实时计算不落库；`rentalSlots` 只算 `status = ACTIVE AND expires_at > now`。2.3 每小时扫描置 `EXPIRED`，期间最多 1 小时内 `quotaOf` 已不算、宠物状态尚未降级——属预期（只读只由 `reconcile(RENTAL_EXPIRED)` 降级）。
- 同一次租的 N 个名额到期日相同、各自一行，之后分别续、分别提醒（PRD）。
- 不做自动续费、年 / 季租、退款、赠送（PRD 边界）——**无退款路径，故不发 `RefundSucceededEvent`**（① 1.3 口径表）。
- 允许同一用户同时有一笔新租 PENDING 与一笔续租 PENDING（幂等键不同）；同键重放复用。不加「每人一笔 PENDING」库级约束：用户换数量重开是合法的，旧 PENDING 意图会被付款窗过期收掉。

### 与前后 story 的边界（本 story 不做）

- reconcile 规则、只读拦截 → **2.1**（本 story 只在发放后调用 `reconcile(RENTAL_ADDED / RENEWED)`）。
- 到期提醒 / 到期置 EXPIRED / 通知 → **2.3**（本 story 只保证续租时 `reminded_at = NULL`）。
- App 名额管理页、租用 / 续租抽屉、SnackBar → **2.4**。
- 运营补发（`ADMIN_GRANT` 购买行 + 名额、权限 `user.pet_slot_adjust`、审计）、后台「宠物与名额」页签 → **4.3**（表结构本 story 已留好 `ADMIN_GRANT` / `operator_admin_id` / `reason`）。
- 升级庆祝页 `petSlotHint` → **4.4**（读本 story 的 `hasActiveRental`）。
- 成长值 → **①**，本线不写。
