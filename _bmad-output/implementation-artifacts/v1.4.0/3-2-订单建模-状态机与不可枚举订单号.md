## Dev Notes

### 🔒 为什么日期序列号同样不可接受
`TT + YYYYMMDD + 序列` 看着像"业务友好"，但**任何用户从自己的订单号即可推断平台当日单量与累计单量**。
对一个还在验证 A-15（能不能卖得动）的产品，这是**直接泄露最敏感的经营数据**。
已加断言：200 个订单号里不得出现今天的日期串；且首字符分布须 > 30 种（防前缀规律）。

### 🔴 地址快照不是外键 —— 履约凭证 vs 当前偏好
用户改地址簿**不得**改写历史订单的履约地址：快递已按旧地址发出。
两者混为一谈时，纠纷里没人说得清货该寄到哪。已有 L1 断言：改完地址簿后历史订单一个字不变。

### 🔴 订单行也快照（含退货规则）
**下单时承诺的是什么，退货时就按什么算**（FR-104）。若读当前 SKU 的规则，
运营事后把「可退」改成「开封不退」就会**溯及既往地毁约**。

### ⚠️ 状态机只开 Epic 3 自己的边
本 Epic 只有「待支付 → 待发货 / 已取消」两条。已发货段属 Epic 4、退款段属 Epic 5。
🔴 **提前开边 = 造出没有任何代码能推进的悬空态**。已有断言锁住这一点。
⚠️ SPEC-6 指出还缺四条边（拒收 / 退款驳回回边 / 退款执行失败 / 用户撤销退货），**须在 Epic 5 前闭合**。

### 同态迁移幂等
重复投递的支付回调不该报错 —— 支付网关重试是常态。
