## Dev Notes

### 🔴 `OrderSummaryView` 加字段但既有映射器一行不改
电商卡片需要主图/商品名/件数，而 record 加组件会让**所有**构造点编译失败 ——
那正是三线共享文件里最容易撞车的一种改动。
做法：**保留一个 8 参构造器**委托给 11 参 canonical 构造器，新字段对既有 4 类恒 null。
（这不是「暂时为空」：那些类型本就没有商品。）

### 🔴 取首图的三表串查封装到 `ShopOrderCardService`，不漏进订单中心
主图要串 line → sku → product。若直接在 `OrderCenterService` 注入三个仓储，
那个 275 行文件每多一个依赖就多一次撞车机会。现在它只多两个依赖（订单仓储 + 卡片服务）。

### 主图取「商品当前主图」而非下单快照
订单行刻意不存图（V109 无该列）。后果是运营换主图会连带改变历史订单卡的配图 ——
**有意接受**：卡片图只是让用户认出「是哪一单」，不是交付凭证；
为它加一列快照会把 URL 冻进订单表，图挪了位置反而变成死链。
CDN 未配置时 `publicUrl` 返回 null（Story 1.6 既定降级），前端回落到类型图标，**绝不留白块**。

### ⚠️ 偏离原型：类型 chips 与状态 chips **两行并存**
原型 06 只画了类型 chips（Semua / Belanja / Konsultasi / PawCoin / Lainnya），
但既有实现已有一行**状态** chips（V1.1 能力：Semua / Berlangsung / Selesai）。
**替换等于删掉既有功能**，超出本 story 范围，故并存：
类型走**后端筛选**（`setFilter` 重拉），状态走**前端过滤**，两者正交。
⚠️ 「Konsultasi」当前映射到兽医一类，AI 归「Lainnya」—— 后端筛选一次只接受一个类型，
而用户心智里两者都是「问诊」。**待 UX 拍板分组口径**（已登记，Story 3.10 收口时确认）。

### 🔴 「等 N 件」的 N 不含首件
「Royal Canin 等 3 件」在总共只有 3 件时读起来像**还有另外 3 件**。

### 电商卡片点击去专用详情页
`/shop/orders/{token}`（Story 3.8，有倒计时与支付入口），不是通用详情页。
待支付卡片直接给「Bayar sekarang」，少一次跳转。
🔴 **卡片上不放倒计时** —— 那会有两处时间源，而它们必然在某一秒对不上。

### 订单号前缀 `TOKO-` 与虚拟商品隔离
财务要能一眼区分自营实物与虚拟商品收入（AB-13D 对账）。
🔴 原型写的「TT + YYYYMMDD + 8 位自增」**作废**：那与 FR-102「订单号必须不可枚举」冲突
（Story 3.2 已定）。`displayNo` 只作展示，查询键仍是不可枚举 token —— 与既有三类同范式。
