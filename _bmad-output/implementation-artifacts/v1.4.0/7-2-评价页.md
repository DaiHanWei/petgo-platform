# Story 7.2: 评价页（App）

Status: **blocked-on-design**（后端与数据层已就绪；**前端页面按 AC 要求不实现**）

## 🔴 为什么没有前端页面
AC 原文：**「🎨 🔴 UX-DR4：视觉待补，实现前不得自行发挥 —— 须先与设计确认星级控件、
图片上传布局与三态呈现」**。本 story 的前端部分因此**刻意不做**，而不是遗漏。
（与 Story 5.9 同一处置；HANDOFF 的既定做法也是「先做后端，前端留稿子到位」。）

## 已就绪的部分（补稿后前端只差一页）
| 能力 | 落点 |
|---|---|
| 提交评价（星级必填 / 文字 ≤500 / 图 ≤6） | `POST /api/v1/me/shop-reviews` |
| **三态**：已发布 / 被拦截 / 审核中 | 返回体的 `reviewStatus`（同步过滤当场出结论） |
| 被拦截后**保留输入、改后重提** | `POST /api/v1/me/shop-reviews/{id}`（覆盖原记录，不 409） |
| 我的评价列表 | `GET /api/v1/me/shop-reviews` |
| Flutter 数据层 | `shop_review_repository.dart` 的 `submit` / `resubmit` 已写好 |

## 补稿后要做的
1. 建评价页 + 路由（入口在订单详情的已完成态）；
2. 星级控件、图片上传（沿用既有 media 能力）、三态呈现按稿实现；
3. 🔴 被拦截时**保留用户输入**（F13 输入类失败统一口径）—— 这一条要在对稿时确认呈现方式。
