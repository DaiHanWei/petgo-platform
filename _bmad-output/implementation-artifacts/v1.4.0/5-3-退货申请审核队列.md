# Story 5.3: 退货申请审核队列（后台 AB-12A）

Status: **review**（后台）

## 交付物
`AdminReturnService`（审核段）· `AdminReturnController` · `admin/shop-returns.html` · `admin/shop-return-detail.html` ·
`AuditActions.SHOP_RETURN_REVIEWED` · i18n 三份。

## AC 与验证
| AC | 层级 | 验证 |
|---|---|---|
| 列表字段含申请编号/订单号/退货行/类型/是否整单退/凭证/时间/状态 | L1 | `AdminReturnEndpointIntegrationTest` 列表用例 |
| 🔴 **不新建审核通道**，复用既有退款审批流程 | **L1** | `noRefundPermissionForbidden` · `viewOnlyCannotApprove` · `approverCannotPayout` |
| 🔴 「是否批准」与「运费由谁承担」分开记录 | L1 | `approveMovesToAwaitShipbackAndAudits`（审计摘要含两处运费） |
| 驳回必填理由并回告用户 | L1 | `rejectRequiresReasonAndRestoresOrder` |
| 「发货前取消」与「拒收」跳过寄回质检 | L1 | `refusedOnDeliverySkipsShipbackAndInspection` |
| 🔴 去程运费由 `is_full_return` 自动得出，不给手工开关 | L0 | `ReturnRequest.open` 里 `outboundFeeRefundable = fullReturn`，**审核接口无该参数** |
| 后台手工建单也校验「同订单仅一张」 | L1 | `requireNoActiveRequest` + 库级索引（Epic5 链路用例覆盖） |

## 一处刻意的设计选择
**审核方法签名里根本没有运费归属参数。** AC 说「不给客服手工开关」——
最可靠的实现不是加校验，是让那个参数不存在：客服在后台看到的运费归属是两个只读字段，
它们由退货类型与勾选范围推出。手工可调等于打开凑单-退货套利的口子（C-12）。

## 权限映射（复用，不新增码）
