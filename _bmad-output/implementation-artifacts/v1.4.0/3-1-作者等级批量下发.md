Status: ready-for-dev

> 版本 v1.4.0 · 主题 tailrent-level · 分支 `feat/1.4.0-tailrent-level`
> 口径优先级：`decision-log.md` ① 节 > `Tailrent等级/1-4-0Tailrent等级prd.md` > `architecture-v1.4.0-tailrent-level-delta.md` > UI 稿 `Tailrent等级/ui-1-4-0-tailrent-level-integrated-v1.html`（均在 `_bmad-output/planning-artifacts/v1.4.0/`）；跨分支契约以 `CROSS-STORY-DECISIONS.md`「2026-10-18 V1.4.0 四条线共用地基」为准。
> 前置：

> - **Story 1.2**：头像框读时推导方法（AD-10：段位 → 可用档，`frame_choice` NULL = 自动最高档、已选但不可用 = 退回最高可用档、`NONE` = 不戴）与 `growth.domain.FrameChoice` 枚举。

## Story

As a 浏览内容的用户,
I want 看到每个作者的等级与头像框,
so that 我能认出活跃、资深的宠物家长。

## Acceptance Criteria

**AC1 — `GrowthQueryService.getBadges` 批量展示查询** `[L0]` `[L1]`（AD-14、5.5）
1. 在既有 `growth.service.GrowthQueryService`（地基类，**只新增方法，不动 `getLevel` / `getLevels` 签名**）新增：
   `public Map<Long, GrowthBadge> getBadges(Collection<Long> userIds)`。
2. 新建 `growth.domain.GrowthBadge(int level, GrowthTier tier, FrameChoice frame)`（record；`frame` 为**生效**框，取 `BASIC` / `UPGRADED` / `ANIMATED`，无框为 `null`，不放 `NONE`）。若 Story 1.2 已建同名类型，复用、不重复定义。
3. **一次查询**（`users` LEFT JOIN `growth_accounts`，段位按 `growth_levels` 取；可同一条 SQL 或「一条取用户 + 账户、一条取等级表」两条，**不得随 id 个数增长**），规则：
   - 真实用户（`role = USER`、`account_type = REAL`、`deleted_at IS NULL`、`status = 'ACTIVE'`）：读 `growth_accounts.level`；**无账户行 = Lv1 / NEWBIE / 无框**；框 = Story 1.2 的推导方法（`frame_choice` + 当前段位）。
   - **官方内容账号（`role = ADMIN`，如「TailUs by Tailtopia」）按「不参与成长值」处理**（协调方 2026-10-18 约定，与 `AccountQueryService.isActiveRegularUser`（`:75`）口径一致：只有 `role = USER` 且 `account_type = REAL` 才算真实用户）→ **不出现在返回 Map 中**，不显示角标与框。
   - 虚拟号（`account_type = VIRTUAL`，未注销、未停用）：等级 = `display_level`（为 NULL 时按 Lv1 兜底并打 WARN 日志，只记 userId）；段位 = 该等级在 `growth_levels` 的段位；框 = 该段位**自动最高可用档**（不看 `frame_choice`）。
   - 已注销（`deleted_at` 非空）、已停用（`status = 'DEACTIVATED'`）、查无此人 → **不出现在返回 Map 中**。
   - 空入参 → `Map.of()`，不发查询。
4. 段位与可用档**一律由 `growth_levels` 的 `tier` 列决定**，不按数字硬编码 5 / 10 / 15（`GrowthTier` 类注释明令）。
5. `getBadges` 只用于展示；权益判定仍只走 `getLevel(s)`（5.5「两者不混用」）：虚拟号 `getLevels` 仍为 `NOT_PARTICIPATING`。

**AC2 — `AuthorView` 加 `growth`，在 `basicViews` 层批量填充** `[L0]`（AD-14）
1. `auth/dto/AuthorView`（`:18`）末尾追加组件 `GrowthBadge growth`（可空）。**保留一个与现状完全相同的 5 参构造器**（`growth = null`），让 37 处既有 `new AuthorView(...)`（2 处 main + 35 处测试，清单见 Dev Notes）不改也能编译；`anonymized(userId)`（`:21`）的 `growth = null`；`withTags`（`:26`）必须把 `growth` 原样带过去（漏带 = 有标签的作者角标消失、且不报错）。
2. `AccountQueryService` 构造器（`:36`）注入 `GrowthQueryService`；`basicViews`（`:230`）在 `findAllById` 之后对**未注销**的 id 调**一次** `getBadges`，把结果贴进投影（`toAuthorView` `:382` 不改口径）。`findAuthorViews`（`:191`）与 `findAuthorViewsWithoutTags`（`:208`）因此**同时**带上等级，**不另加第三个重载**。
3. 已停用（DEACTIVATED）作者：`AuthorView` 现状**不匿名化**（`toAuthorView` 只看 `deleted_at`），本 story 不改这一点，仅因 `getBadges` 不返回而 `growth = null`（A7「停用账号不显示角标与框」）。
4. `GrowthQueryService` **不得反向注入 `AccountQueryService`**（会形成 bean 循环依赖）。

**AC3 — 拍平 DTO 加三个可空字段** `[L0]`（AD-14、FR-144.1、A7）
1. 作者字段以 `author*` 拍平的响应加 `authorLevel`（Integer）、`authorTier`（String，`GrowthTier` 名）、`authorFrame`（String，`BASIC` / `UPGRADED` / `ANIMATED`）；以裸 `nickname` / `avatarUrl` 拍平的响应加 `level` / `tier` / `frame`（同类型、同取值）。命名跟随所在 DTO 的既有前缀（Dev Notes「字段命名」）。
2. 三个字段**全部装箱、可空**，`growth == null` 时全部为 null → 全局 `default-property-inclusion: non_null`（`application.yml:294`）下键整体消失，老 App 不受影响。
3. 必须覆盖的 DTO 与组装点**逐一**见 Dev Notes「必须覆盖的使用点」表 A（共 9 个响应 / 13 个组装点）；表 B 中的使用点**明确不加**。
4. 已注销作者：各 DTO 既有的 `authorDeleted = true` 分支下三个字段一律为 null（`growth` 本就为 null，再加一道防御：`deleted ? null : ...`）。

**AC4 — 各接口的端到端表现** `[L1]`（AC12、AC16、A7）
0. 官方号（`role = ADMIN`）作者 → 三字段缺失。
1. Feed 一页 20 条来自 15 个作者（`GET /api/v1/content-posts`，ALL 推荐流与分类 Tab 都测）→ 每条带 `authorLevel` / `authorTier`，戴框作者带 `authorFrame`；成长值相关查询次数为**常数**（与 1 个作者时相同；见「测试」的计数法）。
2. 作者为虚拟号、`display_level = 15` → `authorLevel = 15`、`authorTier = STAR`、`authorFrame = ANIMATED`；同时 `GrowthQueryService.getLevel(该号)` 仍为 `NOT_PARTICIPATING`。
3. 作者已注销 → 三字段缺失；作者已停用 → 三字段缺失（其余字段照现状）。
4. 作者是新用户（无 `growth_accounts` 行）→ `authorLevel = 1`、`authorTier = NEWBIE`、无 `authorFrame`。
5. 真实用户 `frame_choice = NONE`（主动不戴）→ 有等级、无 `authorFrame`。
6. 详情（`GET /api/v1/content-posts/{id}`）、评论与二级回复（`/comments`、`/comments/{parentId}/replies`）、发评论回显（`POST` 评论 / 回复的返回体）、他人主页（`GET /api/v1/users/{userId}/profile`）、他人帖子列表（`/users/{userId}/posts`）、关注 / 粉丝列表（`/users/{token}/following|followers`）、点赞人列表（`/content-posts/{id}/likers`）、推荐关注（`/me/follow-suggestions`）、关注头像条（`/me/following-strip`）、关注流（`/me/following-feed`）、@ 候选（`/me/mention-candidates`）、场所评论（`/places/{token}/comments` 与发评论回显）、置顶位（`/content-posts/pinned`）、我的发布（`/me/posts`）、公开分享（`/public/shared-posts/{shareToken}`）均带上述字段。
7. 运营标签：`authorTags` / `tags` 的取值与下发口径与改动前**逐字一致**（AC16）；`findAuthorViewsWithoutTags` 的调用方照旧不带标签。

**AC5 — 向后兼容与构建** `[L0]`
1. 契约测试（`FeedResponseContractTest`、`ContentDetailAndCommentContractTest`、`PlaceCommentResponseContractTest`、`PlaceDetailResponseContractTest`、`FollowListContractTest`）补新键，并各加一例「`growth == null` 时新键全部缺失」。
2. `mvn -B clean package` 绿；`bash scripts/ci/check-flyway-versions.sh origin/main` 通过（本 story 无迁移）。
