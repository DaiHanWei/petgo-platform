## Story

As a 运营,
I want 在用户抽屉看到用户全部宠物与名额情况，并能补发名额,
so that 能处理名额相关客诉。

**AC5 — 补发写入（`PetSlotPurchaseService.grantByAdmin`）** `[L0]` `[L1]`（AD-5 · AD-4 · AC13b）
1. 在 2.2 的 `PetSlotPurchaseService` 上**新增** `grantByAdmin(AdminSlotGrantCommand cmd)`（2.2 若已建同义方法则复用，T0 核对；不改 2.2 的租用 / 续租方法）。`AdminSlotGrantCommand(long userId, int days, String reason, String grantToken, long operatorAdminId)`。
2. 同一事务、按序：
   ① 校验：`1 ≤ days ≤ 365`、`reason` 非空且 ≤ 200、`grantToken` 非空，否则 422；目标用户不存在 → 404，已注销 → 422；
   ② 与建档 / 租用 / `reconcile` 同一把用户锁 `PetSlotLock.lockUser(userId)`（2.1 计划，`pg_advisory_xact_lock`），锁内读 `quotaOf(userId)`，总数已 = 5 → 422 `admin.err.petSlot.limitReached`（补发也受 5 封顶，AD-5）；
   ③ 插 `pet_slot_purchases`：`kind = ADMIN_GRANT`、`quantity = 1`、`unit_price = 0`、`total = 0`、`channel = NULL`、`payment_intent_id = NULL`、`idem_key = "ADMIN_GRANT:" + grantToken`（**唯一键冲突 = 已处理过 → 直接返回「重复提交」结果，不再建名额、不写审计**）、`status = PAID`、`days = N`、`operator_admin_id`、`reason`、`paid_at = now`；
   ④ 插 `pet_slot_rentals`：`public_token`（同 2.2 的生成方式）、`source = ADMIN_GRANT`、`starts_at = now`、`expires_at = now + N 天`、`status = ACTIVE`、`reminded_at = NULL`、`purchase_id` = ③ 的 id；回填 ③ 的 `rental_ids`；
   ⑤ `PetSlotStateService.reconcile(userId, PetSlotTrigger.RENTAL_ADDED)`（只恢复不降级：有只读宠物时按顺序恢复，AD-4）；
   ⑥ 审计（AC7）。
3. **不收费**：不调 `PawCoinWalletService`、不建支付意图、不发 `PawCoinSpentEvent`（因此 ① 的消费返成长值不会触发，符合「运营补发不产生成长值」的自然结果）。
4. 补发名额与月租**同表同状态**，由 2.3 的 `PetSlotExpiryScanner` 照常到期提醒（到期前 3 天）、到期处理；本 story 不改扫描器。用户名额即时 +1（`quotaOf` 实时计算）。
5. 返回 `{rentalExpiresAt, replayed}` 供 controller 出 toast 与重渲染。

## 需拍板 / 与文档不符（默认按建议执行）

1. **补发天数上限**：PRD / UI 稿只写「正整数」。建议 1–365（防手误填成 3650）；需要更长再放宽。
2. **补发也受 5 个封顶**：PRD 未写补发与上限的关系。按 AD-5「名额 = min(5, …)」，已满 5 再补发不会增加可用名额，建议直接拒绝（422 + 置灰提示），避免买到「无效名额」。
3. **补发 ≤ 3 天会当场收到「即将到期」通知**：扫描器条件是「到期前 3 天内且未提醒」，补 1–3 天的名额会在下一次扫描（≤ 1 小时）就提醒。符合「与月租一样提醒」，但对用户可能显得突兀；不改扫描器，记为已知行为。
4. **成功后只刷新本页签**：UI 稿 L4 批注写「抽屉重渲染」，但整体重渲染会切回「基本信息」页签（页签头不许改），按 ① Story 4.2 的做法只换本页签，视觉结果与 L4 一致。
5. **购买记录只列已付款**：UI 稿表格无状态列，建议只列 `PAID`（含运营补发），待支付 / 失败 / 过期的 QRIS 单不在此显示（支付详情可在「支付单」页查）。
