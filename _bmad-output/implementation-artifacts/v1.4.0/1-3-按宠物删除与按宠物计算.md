## Story

As a 多宠物用户,
I want 删除一只宠物不影响其他宠物，且访客统计、里程碑、打卡都按宠物算,
so that 每只宠物的记录准确独立。

## Acceptance Criteria

**AC1 — 按只删除 `DELETE /api/v1/pet-profiles/me?petId=`** `[L0]` `[L1]`（PRD AC3、FR-145.2、AD-9）
1. `ProfileDeletionService.deleteByPetId(long ownerId, long petId)`（取代 `deleteByUserId`）只删这一只：先删该宠物在 **7 张无级联表**中的行（`health_events`、`pet_milestones`（含其 `milestone_completions`）、`milestone_shares`、`place_checkin_pets`（再删该用户已无关联宠物的孤儿打卡行）、`pet_passports`、`tailsonality_results`；`content_posts` **不删、只解除**：`detachPet(petId)`），再删宠物；`health_records` / `tailsonality_badges` / `passport_snapshots` / `boarding_pass_unlocks` / `repurchase_triggers` 靠 FK `ON DELETE CASCADE`，`keepsake_purchases` / 两张分享奖励表 / `id_card_hd_purchases` 靠 `ON DELETE SET NULL`（不改）；流水号 `serial_id` 回池；返回该宠物的 `PersonalMedia`（OSS 照 F21 只记账不删）。
2. **不再调用 `idCards.markProfileDeleted`**（`id_cards` 不挂宠物，删一只不能给账号全部卡打标）。
3. `ProfileService.deleteMyProfile(long ownerId, Long petId)`：`petResolver.resolve(ownerId, petId)`（不带 petId = 默认宠物，兼容旧版 App；他人 / 不存在 petId → 404）→ `deleteByPetId` → 媒体记账（同现状 :129-130）。控制器 `DELETE /me` 加可选 `petId`，成功 204。
4. Given 账号有 A、B 两只宠物和两张身份证，When 删除 A，Then A 的健康事件 / 健康记录 / 里程碑与完成记录 / 里程碑分享 / 打卡关联 / 护照（与快照、登机牌）/ Tailsonality 结果（与佩戴）被删；A 的 Diary 帖子保留、`pet_id` 置空；B 的上述数据、两张身份证均不变，`id_cards.profile_deleted_at` 仍为 null。
5. 删最后一只沿用现状：`users.pet_status` **不改**（FR-145.2）；之后 `GET /me` → 404、`GET /me/list` → `[]`。

**AC2 — 多宠账号注销** `[L0]` `[L1]`（AD-9 末句）

### 架构约束

- AD-9：按只删除不打身份证标；注销遍历删除全部宠物后按账号打标。
- AD-12：带 petId 的事件按宠物；与具体宠物无关的账号级触发（平台帖、被评论、被点赞）→ 账号下全部宠物逐只。**问诊结束**有单上的宠物，按宠物；无单旧会话 → 默认宠物（见「待确认」）。
