## Story

As a 老用户,
I want 新版本上线时，我过去完成的里程碑和活跃天数被折算成 EXP,
so that 我不是从零开始，而是从「过去的陪伴」起步。

**AC1 — 迁移 `V20261018_1503__growth_launch_backfill.sql`：真实用户补算** `[L0]` `[L1]`（AD-13 · P-6 · FR-143.7 · PRD AC11）

3. 每人 EXP：
   - **活跃天数** = 该用户在 `user_active_days` 的行数（表自 2026-09-25 起才有数据，P-6 接受此限制，不找代理口径）；EXP = 天数 × 3。
   - **里程碑** = `milestone_completions` ⋈ `pet_milestones`（`pet_milestone_id`）⋈ `pet_profiles`（`pet_profile_id`，主人列 **`owner_id`**），按 `(owner_id, pet_milestones.code)` 计完成次数，**每个 code 最多计 5 次**（`LEAST(count, 5)`，FR-143.4）；分值按 `pet_milestones.level`：S = 5、M = 15、L = 25（AD-13 / PRD 原值，迁移内写死并加注释，不读 `growth_rules`——迁移只跑一次，与上线 seed 一致即可）。
   - 合计 `total = 天数 × 3 + 里程碑 EXP`；**不补算**发帖与互动（PRD）。
   - 例（AC11）：60 天、10 个 S、3 个 M → 180 + 50 + 45 = **275** → Lv4。
4. `total > 0` 的用户：
   - 写**一条** `growth_ledger`：`rule_code = 'LAUNCH_BACKFILL'`、`delta = total`、`idem_key = 'BACKFILL:' || user_id`（与 `GrowthIdemKeys` 的格式逐字一致，T0 核对）、`wib_date = (now() AT TIME ZONE 'Asia/Jakarta')::date`、`created_at = now()`，其余列按 1.1 的 NOT NULL 约束补齐；`ON CONFLICT (idem_key) DO NOTHING`。
   - 建 / 更新 `growth_accounts`：**只对上一步真正插入了流水的用户**（`RETURNING`）——新行 `lifetime_total = total`；已有行（stag 上 1500 先于 1503 部署、运行期已懒建）则 `lifetime_total = lifetime_total + total`；`level` = `growth_levels` 中 `threshold <= 新累计` 的最大 `level`；`backfill_popup_pending = true`；写入 AC2 的三个快照列。
   - **单条语句完成**（数据修改 CTE：`WITH calc AS (…), ins AS (INSERT INTO growth_ledger … ON CONFLICT DO NOTHING RETURNING user_id, delta) INSERT INTO growth_accounts … SELECT … FROM ins JOIN calc … ON CONFLICT (user_id) DO UPDATE …`），`level` 在 INSERT 与 `DO UPDATE` 两处分别用子查询按新累计算出。⚠️ **不要用 `CREATE TEMP TABLE … ON COMMIT DROP`**：L1 测试用 `ScriptUtils` 在自动提交下重放脚本，临时表会在建表语句提交时立即消失。
5. `total = 0` 的用户：**不建账户行、不写流水**（无行 = Lv1、累计 0，AD-1），也就不会有汇总弹窗。
6. 幂等：脚本**重复执行**（L1 测试连跑两次）不重复入账、不重复累加、不改已有快照——靠 `BACKFILL:{u}` 唯一键 + 只对 `RETURNING` 的行更新账户。空库从头迁移（全部迁移）通过。

### 迁移 SQL 骨架（列名以 1.1 实际为准）

```sql
-- 0) 快照列（AC2）
ALTER TABLE growth_accounts ADD COLUMN IF NOT EXISTS backfill_active_days INT NULL, …;

-- 1) 真实用户补算（AC1）：一条语句
WITH eligible AS (
    SELECT u.id AS user_id FROM users u
    WHERE u.role = 'USER' AND u.account_type = 'REAL' AND u.deleted_at IS NULL AND u.status = 'ACTIVE'
), days AS (
    SELECT d.user_id, COUNT(*)::int AS active_days
    FROM user_active_days d JOIN eligible e ON e.user_id = d.user_id GROUP BY d.user_id
), per_code AS (
    SELECT p.owner_id AS user_id, pm.code, pm.level, LEAST(COUNT(*), 5)::int AS n
    FROM milestone_completions mc
    JOIN pet_milestones pm ON pm.id = mc.pet_milestone_id
    JOIN pet_profiles p    ON p.id  = pm.pet_profile_id
    JOIN eligible e        ON e.user_id = p.owner_id
    GROUP BY p.owner_id, pm.code, pm.level
), ms AS (
    SELECT user_id, SUM(n)::int AS milestone_count,
           SUM(n * CASE level WHEN 'S' THEN 5 WHEN 'M' THEN 15 WHEN 'L' THEN 25 END)::int AS milestone_exp
    FROM per_code GROUP BY user_id
), calc AS (
    SELECT e.user_id, COALESCE(d.active_days, 0) AS active_days,
           COALESCE(m.milestone_count, 0) AS milestone_count, COALESCE(m.milestone_exp, 0) AS milestone_exp,
           COALESCE(d.active_days, 0) * 3 + COALESCE(m.milestone_exp, 0) AS total
    FROM eligible e LEFT JOIN days d ON d.user_id = e.user_id LEFT JOIN ms m ON m.user_id = e.user_id
), ins AS (
    INSERT INTO growth_ledger (user_id, rule_code, delta, idem_key, wib_date, created_at /* + 1.1 其余 NOT NULL 列 */)
    SELECT user_id, 'LAUNCH_BACKFILL', total, 'BACKFILL:' || user_id, (now() AT TIME ZONE 'Asia/Jakarta')::date, now()
    FROM calc WHERE total > 0
    ON CONFLICT (idem_key) DO NOTHING
    RETURNING user_id, delta
)
INSERT INTO growth_accounts (user_id, lifetime_total, level, backfill_popup_pending,
        backfill_active_days, backfill_milestone_count, backfill_milestone_exp, created_at, updated_at)
SELECT i.user_id, i.delta,
       (SELECT MAX(l.level) FROM growth_levels l WHERE l.threshold <= i.delta),
       true, c.active_days, c.milestone_count, c.milestone_exp, now(), now()
FROM ins i JOIN calc c ON c.user_id = i.user_id
ON CONFLICT (user_id) DO UPDATE SET
    lifetime_total = growth_accounts.lifetime_total + EXCLUDED.lifetime_total,
    level = (SELECT MAX(l.level) FROM growth_levels l
             WHERE l.threshold <= growth_accounts.lifetime_total + EXCLUDED.lifetime_total),
    backfill_popup_pending = true,
    backfill_active_days = EXCLUDED.backfill_active_days,
    backfill_milestone_count = EXCLUDED.backfill_milestone_count,
    backfill_milestone_exp = EXCLUDED.backfill_milestone_exp,
    updated_at = now();

-- 2) 虚拟号展示等级（AC3）
INSERT INTO growth_accounts (user_id, lifetime_total, level, display_level, created_at, updated_at)
SELECT u.id, 0, 1, 6 + floor(random() * 3)::int, now(), now()
FROM users u WHERE u.account_type = 'VIRTUAL' AND u.deleted_at IS NULL
ON CONFLICT (user_id) DO UPDATE SET display_level = EXCLUDED.display_level
WHERE growth_accounts.display_level IS NULL;
```
- 已有账户行走 `DO UPDATE` 改了 `level` 但**不发事件**：② 名额按 `getLevel` 实时读，不受影响（AD-13）。
- `wib_date` 只用 `Asia/Jakarta`，与 `ScheduleWindow.WIB` 同一时区。
