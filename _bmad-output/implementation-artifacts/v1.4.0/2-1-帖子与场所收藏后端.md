## Story

As a 用户,
I want 收藏公开的帖子和场所，详情页显示我是否已收藏,
so that 以后能再找到它们。

**AC2 — 收藏帖子 `POST /api/v1/content-posts/{id}/collect`** `[L0]` `[L1]`（AD-8、P-2、PRD AC7 / AC11 / AC11a）
1. 端点放在**新的** `collect.web.CollectController`（不放 `LikeController`），返回 `CollectResponse(boolean collected)` → `{"collected": true}`；只取 JWT `sub` 作本人，照 `LikeController.currentUserId`（`LikeController.java`:49-58）。
2. 可见性：先调 `ContentDetailService.requireVisiblePost(postId, me)`（`ContentDetailService.java`:76，`public`，`PostLikersService` 已在跨类调用）——不存在 / 软删 / 非 PUBLISHED（本人看自己 `UNDER_REVIEW` 例外）/ 我举报过 / 我隐藏了作者 → **404**，文案沿用统一 404（`GONE_DETAIL`「这条内容已不存在」）。通过后 `post.getVisibility() == PRIVATE` → **422** `collect-not-public`（P-2；新增 `ErrorTypes.COLLECT_NOT_PUBLIC` + `AppException.collectNotPublic(detail)`）。顺序固定为「先 404 后 422」，不可见的私密帖不泄漏「它是私密的」。
3. 写入：`ContentCollectionRepository.insertIfAbsent(userId, postId)`——原生 `INSERT … ON CONFLICT (user_id, post_id) DO NOTHING`，返回影响行数；**返回 1 = 真正新增**。不照抄 `LikeService` 的「`exists` → `save` → 吞 `DataIntegrityViolationException`」（见 Dev Notes「实现提示」①）。
4. 事件：**仅当真正新增（影响 1 行）且 `CollectVisibility.isVisibleTo(me, post)` 为真**时，在服务事务内 `publishEvent(new ContentCollectedEvent(postId, me, post.getAuthorId()))`；**收藏人 = 作者也发**（`(postId, B, B)`，① 自行不入账、1.4.2 里程碑要用）。重复收藏（影响 0 行）不发。可见性门槛的理由见「拍板点」②。
5. **不发任何通知**（不调 `NotificationService`；PRD「被收藏不通知作者」）。
6. Given A 收藏 B 的公开帖子，When POST，Then `collected = true`，发布一次 `ContentCollectedEvent(postId, A, B)`；再 POST 一次，Then 仍 `collected = true`、**不再发**事件。
7. Given B 收藏自己的公开帖子（含自己 `UNDER_REVIEW` 的帖），When POST，Then 200 并发 `ContentCollectedEvent(postId, B, B)`。
8. Given 私密帖（含自己的）/ 已删除帖 / 不存在的 id，When POST，Then 422 `collect-not-public` / 404 / 404，且库里无新行、无事件。

**AC3 — 取消收藏帖子 `DELETE /api/v1/content-posts/{id}/collect`** `[L0]` `[L1]`（AD-8、P-5、P-7、PRD AC11b / AC11c）
1. **不要求可见**（用户要能从 Disimpan 移除不可见条目）：帖子不存在 / 已软删也 200 `{"collected": false}`，幂等。
2. `int n = ContentCollectionRepository.deleteByUserIdAndPostId(me, postId)`（`@Modifying` JPQL / 原生 DELETE，返回行数）；`posts.findById(postId)` 取帖子（**含软删**，不过滤）。
3. 事件（P-7）：`n == 1` **且**帖子存在 **且** `CollectVisibility.isVisibleTo(me, post)` → 发 `ContentUncollectedEvent(postId, me, post.getAuthorId())`；否则不发。作者自取消同样按此判断（① 自行不扣）。
4. Given A 取消一条对 A 可见的已收藏帖子，Then 发一次 `ContentUncollectedEvent`；Given 该帖已被作者删除 / 运营下架 / `AUTHOR_DEACTIVATED` / 举报预处置（`UNDER_REVIEW` 且 A 非作者）/ A 举报过该帖 / A 拉黑或举报了作者 / 作者拉黑了 A，When 取消，Then 删除成功、**不发**事件（AC11c）；Given 本就没收藏，Then 200、不发。

**AC4 — 「对某用户是否可见」判断 `CollectVisibility`** `[L0]`（P-5、P-7、AD-11 不可见口径，供 2.2 复用）
1. 新建 `collect.service.CollectVisibility`（`@Component`），签名：
   ```java
   /** 批量：posts 中对 viewer 可见的 postId 集合。固定 2 次查询（举报 1 次 + 双向隐藏 1 次），与条数无关。 */
   public Set<Long> visiblePostIds(long viewerId, Collection<ContentPost> posts);
   /** 单条：等价于 visiblePostIds(viewerId, List.of(post)).contains(post.getId())。 */
   public boolean isVisibleTo(long viewerId, ContentPost post);
   ```
2. 规则（逐条全满足才可见）：`deletedAt == null`；`status == PUBLISHED`，或 `status == UNDER_REVIEW && authorId == viewerId`（`AUTHOR_DEACTIVATED` 一律不可见）；viewer **没有**举报过该帖；作者 ≠ viewer 时，作者**不在** `UserHideRelationReader.hiddenEitherWay(viewerId, 作者集合)`（`UserHideRelationReader.java`:75，双向、不分来源）。**不看 `visibility`**（PRIVATE 由收藏入口的 422 挡住，取消时不再区分）。
3. 举报批量查：`ReportService` 新增 `Set<Long> reportedPostIds(long reporterId, Collection<Long> postIds)`（空集直接返回、不发查询），底层 `ContentReportRepository` 新增 `@Query("select r.postId from ContentReport r where r.reporterId = :reporterId and r.postId in :postIds") List<Long> findReportedPostIds(...)`；不让 collect 直读 moderation repository（与 `ReportService.hasReported` :90 的模块边界注释同理）。
4. 空集合入参 → 返回空集、**零查询**；作者全是 viewer 本人 → 不调 `hiddenEitherWay`。

**AC5 — 场所收藏 `POST | DELETE /api/v1/places/{token}/collect`** `[L0]` `[L1]`（AD-9、P-6、PRD AC8 / AC11b）
1. 两个端点同在 `collect.web.CollectController`；🔴 **绝不放进 `PlaceController`**——`PlaceControllerNoEditEndpointTest` 用反射断言 `PlaceController` 不得有任何 `@DeleteMapping`（见「现状」表）。返回 `{"collected": true|false}`。
2. 收藏：`PlaceRepository.resolveForView(token)`（:140；ACTIVE 原样、MERGED 跳保留场所一层、其余 empty）→ empty 则 **404**「场所不存在」（与 `PlaceQueryService.detail` :100 同文案）；解析结果 `X`。若 `PlaceCollectionRepository.existsCovering(me, X.id)` 已为真（见 AC5.4）→ 直接返回 `true`；否则 `insertIfAbsent(me, X.id)`（`ON CONFLICT DO NOTHING`）。**收藏一律落在解析后的保留场所 `X` 上**（P-6）。
3. 取消：按 token 找**原场所行，含下架与软删**——`PlaceRepository` 新增 `@Query("select p from Place p where p.publicToken = :publicToken") Optional<Place> findAnyByPublicToken(...)`（现有 `findUndeletedByPublicToken` :127 排除软删，不能用）。找不到 → 200 `false`（幂等，不 404）。找到 `raw` 后：`target = (raw.status == MERGED && raw.mergedIntoId != null) ? raw.mergedIntoId : raw.id`，删除本人在**同一显示条目**上的全部行：
   ```sql
   DELETE FROM place_collections
    WHERE user_id = :userId
      AND (place_id = :rawId OR place_id = :targetId
           OR place_id IN (SELECT id FROM places WHERE merged_into_id = :targetId))
   ```
   即：原 token 那一行 + 保留场所那一行 + 其他已并入保留场所、且属于本人的行（MERGED 时删哪些见「拍板点」③）。只删 `user_id = 本人`。
4. 「是否已收藏」的覆盖口径（详情与收藏入口共用，`PlaceCollectionRepository.existsCovering(userId, placeId)`）：本人在 `placeId` 本身**或**任一 `merged_into_id = placeId` 的场所上有行即为 `true`。合并只跳一层，与 `resolveForView` 一致。
5. **无任何事件、无成长值、不展示计数**（PRD「场所被收藏不发成长值」「场所收藏数本版本不展示」）。
6. Given 场所 P，When 收藏 / 取消，Then `PlaceDetailResponse.collected` 随之 `true` / `false`；Given P 已下架或软删，When POST，Then 404，When DELETE，Then 200 并删掉本人那一行；Given Y 已 MERGED 进 X，When 用 Y 的 token POST，Then 行落在 X 上、X 详情 `collected = true`；Given 合并前收藏过 Y，When 打开 X 详情，Then `collected = true`，When 用 X 或 Y 的 token DELETE，Then 两行都被删、X 详情 `collected = false`。

### 迁移 SQL 草案（`V20261018_1801__create_content_and_place_collections.sql`）

```sql
-- V1.4.0 ④ push-collect · Story 2.1 · AD-7：帖子收藏 / 场所收藏（FR-151）。
-- · 收藏是「仅本人可见」的私人数据；注销由 CollectDeletionService 显式删除（users 行只匿名化，CASCADE 不触发）。
-- · 外键一律 ON DELETE CASCADE：生产无硬删路径，CASCADE 只为存量测试 deleteAll 不被阻断。
-- · 帖子软删 / 下架 / 场所下架 / 合并时**不删**收藏行（列表读时判不可见，PRD「保留这一条」）。
-- · 不加冗余计数列（与点赞一致，实时 COUNT）。自增 id 不外露（帖子沿用 /content-posts/{id}，场所用 public_token）。

CREATE TABLE content_collections (
    id         BIGSERIAL    PRIMARY KEY,
    user_id    BIGINT       NOT NULL,
    post_id    BIGINT       NOT NULL,
    created_at TIMESTAMPTZ  NOT NULL DEFAULT now(),   -- UTC
    CONSTRAINT uq_content_collections_user_post UNIQUE (user_id, post_id),
    CONSTRAINT fk_content_collections_user FOREIGN KEY (user_id) REFERENCES users (id) ON DELETE CASCADE,
    CONSTRAINT fk_content_collections_post FOREIGN KEY (post_id) REFERENCES content_posts (id) ON DELETE CASCADE
);
-- 我的收藏列表（2.2）：按收藏时间倒序 keyset。
CREATE INDEX idx_content_collections_user_created ON content_collections (user_id, created_at DESC, id DESC);
-- 作者视角收藏数（详情 collectCount）。
CREATE INDEX idx_content_collections_post ON content_collections (post_id);

CREATE TABLE place_collections (
    id         BIGSERIAL    PRIMARY KEY,
    user_id    BIGINT       NOT NULL,
    place_id   BIGINT       NOT NULL,
    created_at TIMESTAMPTZ  NOT NULL DEFAULT now(),   -- UTC
    CONSTRAINT uq_place_collections_user_place UNIQUE (user_id, place_id),
    CONSTRAINT fk_place_collections_user FOREIGN KEY (user_id) REFERENCES users (id) ON DELETE CASCADE,
    CONSTRAINT fk_place_collections_place FOREIGN KEY (place_id) REFERENCES places (id) ON DELETE CASCADE
);
CREATE INDEX idx_place_collections_user_created ON place_collections (user_id, created_at DESC, id DESC);
-- 场所收藏数本版不展示，索引留给以后「最多人收藏的场所」与合并覆盖查询。
CREATE INDEX idx_place_collections_place ON place_collections (place_id);
```

### 拍板点（按建议实现，Completion Notes 复述）

- **① 写入用 `INSERT … ON CONFLICT DO NOTHING`，不照抄 `LikeService`**：`LikeService.like` 在 `@Transactional` 里 `save` 撞唯一键后吞异常——Hibernate 抛约束异常时会把事务标成 rollback-only，并发时提交阶段可能变 `UnexpectedRollbackException`（500）。原生插入返回影响行数，「是否真正新增」直接拿来决定发不发事件，也不需要先 `exists`。与 AD-3（推送设置「关 = `INSERT … ON CONFLICT DO NOTHING`」）同一手法。
- **② `ContentCollectedEvent` 也加「对收藏人可见」门槛**：收藏入口用 `requireVisiblePost`（与详情一致：详情打得开就能收藏，**不因对方拉黑我而 404**——否则等于告诉用户「你被拉黑了」，违背 `ErrorTypes.FOLLOW_BLOCKED` 注释里「对方拉黑了我不出现」的既有口径）。但 `requireVisiblePost` 只判单向，作者拉黑我时详情仍可见；此时若照发 `Collected`，之后取消按 P-7 判不可见、不发 `Uncollected`，作者白得 +2。因此两个事件**共用同一个 `CollectVisibility` 门槛**：只有「此刻对收藏人可见」时才发，① 永远不会收到无法配对扣回的 `Collected`。正常路径（无拉黑）下行为与 epics 完全一致；作者自收藏恒可见、照常发。
- **③ 场所取消收藏的删除范围**：P-6 让「我的收藏」里同一保留场所只显示一条（读时去重），因此取消时要把**这一条显示条目背后本人的所有行**一并删掉，否则删完 X 后，合并前收藏的 Y 行又会顶上来显示成「还在收藏」。范围 = 原 token 行 + 其保留场所行 + 其他已并入该保留场所的本人行（AC5.3 SQL）；只删本人、只跳一层（与 `resolveForView` 一致）。下架 / 软删场所：`target = raw.id`，只删它本身（以及并入它的，正常为空）。
- **④ 详情查看者按 role 收紧**：收藏状态是「仅自己可见」的私人数据，`ContentDetailController.viewerId` 只看 sub 会让兽医 token 看到同号用户的 `collected`（作者视角时还有 `collectCount`）。改成与 `PlaceController.optionalUserId` 同口径（非 USER 按游客）。副作用：兽医 token 打开帖子详情时 `liked` / `isAuthor` / 评论视角都按游客——兽医端本无帖子详情入口，可接受。
- **⑤ 取消接口永不 404**：帖子 / 场所不存在或已软删时 DELETE 仍 200 `false`；对任何 token / id 结果一致，不泄漏存在性。

### 架构约束

- AD-7：两表结构、CASCADE、索引；不加计数列。
- AD-8 / P-2 / P-7：私密帖 422 `collect-not-public`；`Collected` 只在真正新增时发、自收藏也发；`Uncollected` 只在「删到 1 行且此刻可见」时发；事件只由 `CollectService` 发布。
