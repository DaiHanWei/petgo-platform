## Story

As a 多宠物用户,
I want 首页推荐按我所有宠物的物种比例来,
so that 养猫又养狗的我两类内容都能看到。

## Acceptance Criteria

**AC1 — 内容物种（`ContentSpeciesResolver`）** `[L0]` `[L1]`（AD-11、PRD §3.3 分支 ①、AC16）
1. 优先级链改为（前两级**不变**）：
   ```
   ① 行级覆写 species_override（运营）
   ② 账号物种定位 account_species（仅虚拟账号；NULL 读作 GENERAL）
   ③ 内容关联：Diary（GROWTH_MOMENT）按 content_pets 关联宠物的物种集合
   ④ 作者全部宠物：Moment / Tips（以及无关联宠物的 Diary，见 4）按作者名下全部宠物的物种集合
   ⑤ 无 → NONE（推不出来，引擎消费时映射 GENERAL，SpeciesBucket 现规则不变）
   ```
2. 物种集合 → 结果：去重后 **1 种 → 该物种**；**≥ 2 种 → `GENERAL`**（通用池）；0 种 → 走下一级。
3. 来源 `SpeciesSource`：③④ 均记 `PET_PROFILE`（多物种落 GENERAL 也记 `PET_PROFILE`），**不新增枚举值**（后台自查列 / 筛选与 i18n 不动）。
4. Diary 的关联宠物全被删（`content_pets` 无行）→ 回落 ④ 作者全部宠物（默认做法，见「待确认」2）。
5. 只读宠物计入、已删宠物自然不在（物理删除 + 级联）。
6. **输入扩展**：`ContentSpeciesResolver.Input` 改为 `Input(long contentId, String rowOverride, Long authorId, ContentType type)`（`contentId` 即 postId）；保留旧 3 参构造（`type = null` → 按 ④ 作者规则，等价于今天的行为语义）。新增 `resolve(ContentPost post)` 便捷方法；旧 `resolve(String, Long)` 保留（作者规则）。
7. **批量不 N+1**：`resolveAll` 一次取作者（既有）、一次 `pets.findAllByOwnerIdInOrderByCreatedAtAscIdAsc(authorIds)`（T0 核对：1.2 X27 已把 `findByOwnerIdIn` 换成此名）聚合成 `ownerId → Set<物种>`（替换 1.2 V-1 过渡的 `DefaultPetPolicy.pickPerOwner` 取默认宠物）、一次 `ContentPetQuery.petsOfAll(Diary 的 contentId)` + 一次按 id 取这些宠物的类型。
8. 四个调用方改为传 `type`（或改用 `resolve(post)`）：`FeedRecommendationService`:340-342、`AdminContentManageService`:155-156 / :262-263（`AdminContentRow` 已有 `type`）、`AutoCommentService`:263、`VirtualCommentService`:102。
9. 验收：Given 关联一猫一狗的 Diary → `GENERAL`；只养猫作者的 Moment → `CAT`；猫狗都养作者的 Moment → `GENERAL`；同一猫狗作者的「只关联猫」Diary → `CAT`；行级覆写 / 虚拟号定位仍最高（AC16）。

**AC2 — 用户物种权重** `[L0]` `[L1]`（AD-11、PRD §3.3 分支 ②、FR-147.3）
1. `FeedRecommendationService.viewerMainSpecies`（:450-456）替换为 `viewerSpeciesCounts(Long viewerId) → Map<String, Integer>`（物种 → 宠物数）：取 `findAllByOwnerIdOrderByCreatedAtAscIdAsc(viewerId)`，**含只读、不含已删**；游客 / 无宠物 → 空 Map（物种维度不生效，与今天 `null` 等价）。
2. 用整数宠物数作权重（架构写 `Map<Species, Double>`，整数等价且避免浮点舍入；Completion Notes 记一句）。
3. **首页不跟随 Diary Tab 切换**：只读账号全部宠物，不读 `currentPetId` / 任何 `petId` 参数。
4. 1.2 的 V-1 过渡实现在此**被替换**（不是叠加）；删除过渡代码，保留其测试意图（多宠不抛异常）。

**AC3 — 槽位分配（确定性算法）** `[L0]`（AD-11、PRD AC17）
1. 新增纯函数类 `content.rank.SpeciesSlotAllocator`：`static Map<String, Integer> allocate(int quota, Map<String, Integer> counts)`，算法：
   ```
   total = Σ counts                       （counts 为空或 total=0 → 返回空 Map）
   base[s] = floor(quota × counts[s] / total)
   left    = quota − Σ base               （必有 0 ≤ left < 物种数）
   把 left 个余数槽各 +1，依次给：
     宠物数多的物种优先（PRD「余数向宠物数多的物种取整」）
     → 同数时小数部分大的优先
     → 仍同时按固定顺序 CAT, DOG, OTHER
   ```
   只用 `int` / `long` 运算（`quota × count` 先乘后除，小数部分比较用 `(quota × count) mod total`），不用 `double`。
2. **AC17 算例**（必须写成单测）：`allocate(10, {CAT:2, DOG:1})`：base = ⌊20/3⌋=6、⌊10/3⌋=3，left = 1 → 给宠物数多的 CAT → **CAT 7、DOG 3**。
3. 其余必测算例：`allocate(6, {CAT:2, DOG:1})` = 4 / 2（无余数）；`allocate(6, {CAT:1})` = 6（单宠物 = 现状）；`allocate(4, {CAT:3, DOG:2})` = base 2 / 1、left 1 → 给 CAT（宠物数多，**不是**小数部分更大的 DOG）= 3 / 1；`allocate(6, {CAT:1, DOG:1, OTHER:1})` = 2 / 2 / 2；`allocate(10, {CAT:1, DOG:1, OTHER:1})` = base 3/3/3、left 1、同数同小数 → CAT = 4 / 3 / 3；`allocate(6, {})` = 空；总和恒等于 `quota`。
4. 结果与输入 Map 的迭代顺序无关（用 `HashMap` / `TreeMap` 输入各跑一遍断言相同）。

**AC4 — `FeedRankEngine` 权重化** `[L0]`（AD-11）

7. Given 2 猫 1 狗、默认参数 `6 / 2 / 2`、四类内容都充足 → 首窗 **猫 4、狗 2、其他物种 2、通用 2**。

### 为什么只拆「主物种配额」（重要，请先读）

现引擎每 10 条窗口固定 **主物种 6 / 其他物种 2 / 通用 2**（`RankParams`，运营可在配置页改，三者之和必须等于窗口）。PRD AC17「10 个槽位猫 7 狗 3」若按字面让猫狗吃满整窗，就要把「其他物种」「通用」两桶清零，等于推翻现有配额模型、改运营配置语义。本 story 按 AD-11「槽位按权重分配」的最小改法：**用户名下的物种都算 MAIN，把 MAIN 配额按宠物数比例拆给各物种**，其他物种 / 通用两桶不变。效果：
- 默认配置下 2 猫 1 狗 → 每窗 猫 4、狗 2、其他 2、通用 2；
- AC17 的 7 / 3 在分配函数（`allocate(10, …)`）与「主配额 = 10」的引擎参数下逐字成立。
产品若要的是「整窗 10 条猫 7 狗 3」，只需运营把配置改成 10 / 0 / 0，代码不用动——见「待确认」1。

### 与前后 story 的边界（本 story 不做）

- 不建表、不加迁移（读时推导，PRD「不对存量内容回填物种」）。
- `content_pets` 与 `ContentPetQuery` 由 **3.1** 提供；本 story 只调用 `petsOfAll`。
- 1.2 只保证「多宠不抛异常」；语义在本 story。
- ① 的「作者等级加权」（等级线 Story 3.4）是打分系数，与本 story 的物种配额正交；两线合并时 `FeedRankEngine` 可能文本冲突，按「两者都保留」解（不在本 story 预埋 ① 的字段）。
- App 无改动；后台「推导来源」展示不变。

### 架构约束

- 护栏：不引 MQ / 缓存（物种每次读时算）；`ddl-auto=validate`（本 story 无 schema 变更）。
- 引擎保持纯函数：`SpeciesSlotAllocator` 无依赖、可穷举单测。
- 不新增 `SpeciesSource` 值，不改 `ContentSpecies` 常量。

### 待确认（实现按默认做法，不阻塞）

1. **AC17「10 个槽位」的口径**：默认 = 拆主物种配额（见上一节）。如需整窗 7 / 3，由运营改 `feed_rank_config` 三个配额，无需代码。
2. **Diary 的关联宠物全被删**：默认回落「作者全部宠物」规则（与 Moment 相同）；也可改为直接 NONE（→ 通用池）。
3. **PRD「余数给多的物种」与「最大余数法」不同**：如 3 猫 2 狗分 4 槽，最大余数法给狗（1.6 的小数 .6 更大）得 2 / 2，PRD 口径给猫得 3 / 1。默认按 PRD 字面。
