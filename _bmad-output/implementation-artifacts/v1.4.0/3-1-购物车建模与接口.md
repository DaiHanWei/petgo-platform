# Story 3.1: 购物车建模与接口

Status: review

## Acceptance Criteria
- [x] 购物车与用户一对一；行记录 `sku_id` + `qty`
- [x] 🔴 **单店模型，无店铺分组字段**（FR-96）
- [x] 数量上限受该 SKU **可售库存**约束，超出返回明确 ProblemDetail
- [x] 🔴 **失效商品（已下架 / 已售罄）单独成组**，不参与合计、不可勾选

- [x] 返回**件数**（非种类数）供角标
- [x] 🔴 **游客无购物车**（401）

## Dev Notes

### 🔴 不照搬 Shopee 的多店铺结构
平台自营是唯一卖家。加一层 `shop_id` 分组会让**购物车、结算、订单三处**都多出一层
**永远只有一个元素的嵌套**，而这层嵌套一旦进了 API 契约，前端与后续所有 Epic 都得跟着它走。
已有断言扫表确认无 `shop_id/seller_id/merchant_id/store_id` 列。

### 🔴 失效商品「单独成组」而不是「静默删除」
用户加过什么应该看得见 —— 悄悄删掉会让他以为自己记错了，而**下架/售罄恰恰是最需要解释的时刻**。

### 🔴 下架与售罄是两个不同的 `invalidReason`
**下架是永久的**（换个商品吧），**售罄是暂时的**（可以等）。给同一句话会让用户做错决定。

### 🔴 件数不是种类数
车里 3 种商品共 7 件时角标显示 3，用户会以为漏加了。角标要跟他脑子里的「我买了几件」对上。

### 🔴 失效判定在读时进行，不落库
商品下架、库存归零都发生在购物车之外，把状态冻进行里只会让它过时。数量上限同理。

### 游客无购物车是「能力缺席」不是「权限判断」
`CartService` 每个方法都以 `userId` 开头，**没有任何匿名路径**。
（对照：Toko 浏览与商品详情**刻意**对游客开放，FR-93A —— 两者不是同一个决定。）
