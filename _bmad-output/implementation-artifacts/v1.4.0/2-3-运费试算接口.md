## Dev Notes

### 🔴 免运抵扣是一条负数行，不是把 fee 改成 0
结算页要让用户看见「原本运费 20.000，因满额免运 −20.000」——
直接显示 0 会让用户**不知道自己省了钱**，免运门槛也就失去了拉高客单价的作用。
对账侧（AB-13D）同理：收入与优惠必须分开记，合并后无法回答「这个月免运送出去多少钱」。
`total` 恒等于各行之和，已有断言。

### 🔴 两个校验时机的差异是有意的
**保存地址不校验范围** —— 用户可能下个月搬过去、或先存着等平台开通；挡在保存这一步既没必要又损失数据。
**阻断发生在下单前的最后一刻。** 已有一条测试同时覆盖这两个时机。

### 🔴 门槛为 0 表示「不做免运」，不是「0 元即免运」
写成 `subtotal >= threshold` 而不加 `threshold > 0` 的判断，会让默认配置下**所有订单都免运费**。
