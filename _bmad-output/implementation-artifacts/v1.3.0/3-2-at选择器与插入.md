# Story 3.2: @ 选择器与插入

Status: ready-for-dev

## Story

As a 正在写评论的用户,
I want 打一个 @ 就弹出人名让我选,
so that 我不用记住对方昵称怎么拼，选一下就插进去了。

## Acceptance Criteria

**AC1 — 两处触发** `[L2] [L0]`
内容正文输入框与评论/回复输入框，输入「@」**都**弹出用户选择器浮层。
选择器是**全新叠加层**（现状输入框是纯文本框、无任何触发机制）。

**AC2 — 候选内过滤** `[L2]`
继续输入昵称文字 → **仅在候选集这 30 人内过滤**。
⚠️ 界面上那个输入框**不是搜索框**，文案与视觉不得让人以为能搜到任何用户。

**AC3 — 空态** `[L2]`
当前用户没有任何互动过的人 → 显示空态；**候选为空时不显示过滤输入框**。

**AC4 — 🔴 存 userId 不存昵称** `[L0]`
选中后正文里插入 @昵称，同时**在数据层绑定该用户的 userId**。
存昵称则对方改名后历史 @ 全部失效、点不动，也无法判断拉黑关系。

**AC5 — 上限 5 人** `[L2]`
单条内容或单条评论最多 @ **5 人**，达上限后不能再插入并给出提示（防骚扰）。

## Dev Notes

### 现状（动手前读）

`petgo_app/lib/features/content/presentation/comment_composer.dart`：
纯文本 `TextField`（底部固定 pill 输入条），`maxLength` 200 且触达上限给一次 toast，**无任何 @ 触发机制**。

正文输入在发布页（`publish_compose_page.dart` 一类），同样是纯文本。

### AC4 的存储形态

正文里显示的是昵称，但**必须另存一份结构化的 @ 列表**（userId 数组），或在文本里用可解析的标记承载 userId。
两种都行，但**必须能在渲染时按 userId 反查当前昵称** —— 这是 Story 3.3 高亮与跳转的前提，也是拉黑判定的前提。

### ⚠️ 别把过滤框做成搜索框

这是全局性的范围红线：**没有全局用户搜索**（留在 1.6.0）。
界面上如果长得像搜索框、文案写"搜索用户"，用户会期待搜到任何人，而实际只能搜 30 个——这比没有更糟。
