# Story 6.4: D3 算法参数页整改与变更记录抽屉

Status: ready-for-dev

> 自包含 story。后台模板 + 一个新的只读 fragment 端点；`POST /admin/algo-params` 与全部校验**不变**。依赖 2-3a / 2-3b。

## Story

As a 产品，
I want 算法参数页去掉编号术语、11 项一行一项两栏排布，历史变更点按钮进抽屉筛着看，
so that 页面清爽、历史可查而不占版面。

## Acceptance Criteria

**AC1 · 页头与分组**
**Given** `/admin/algo-params` 套 `tpl-d-config-card`
**Then** 页头无「FR-95」等编号；分组名「算法参数」（原「首页推荐 / 打分参数」）；右栏底部保留「不对普通运营开放 / 生效范围」提醒 `[L2]`

**AC2 · 参数排布**
**Then** 全部参数（现表单 14 个输入：新鲜度 / 互动度 / 评论权重 / 曝光衰减 / 抖动 / 限流系数 / 曝光窗口 / 配比窗口 / 属性配比 ×3 / 物种配比 ×3）一行一项、两栏排布填满卡宽；PRD 写「11 项」，**以代码 14 项为准**（见 Dev Notes）`[L2]`
**And** 保存 = 确认弹层复述改前改后（模板 D 通用三态，同 6.3）；校验错误行内呈现（配比之和 / 区间等 `admin.err.config.*` 现有码全部保留）`[L1/L2]`

**AC3 · 变更记录进抽屉**
**Then** 页尾常驻表删除；页头「变更记录」按钮 → `GET /admin/algo-params/changes/drawer?field=&from=&to=&page=` 返抽屉 fragment：时间（WIB）/ 参数 / 改前 / 改后 / 操作人，每页 20，按参数下拉（14 个字段名 message key）与时间段筛选；默认最近 20 条 `[L1/L2]`
**And** 数据来自 `config_change_logs` `config_type=FEED_RANK`（现状 `findTop20…` 只取 20 条，本 story 改为分页 + 筛选查询）`[L1]`

**AC4 · 权限不变**
**Then** 查看 / 修改沿用 `AdminAlgoParamController` 现有 `VIEW` / `EDIT` 常量；抽屉端点用 `VIEW` `[L1]`

**AC5 · 三语与回归**
**Then** 新 key `admin.v130.algo.*`（按钮 / 抽屉标题 / 筛选标签 / 空态）三包；既有 `admin.algo.*` key 中含「FR-95」「打分参数」的文案改词；`AdminAlgoParam` 相关测试全绿 `[L0/L1]`

## Dev Notes

### 🔴 PRD「11 项」与代码 14 个输入不一致——以代码为准

`FeedRankForm` 实际字段：freshnessWeight、interactionWeight、commentWeight、exposureDecay、shuffleStrength、throttleFactor、seenWindowDays、windowSize、attrFun/Edu/LifeQuota、speciesMain/Other/GeneralQuota = **14**。PRD/UI 稿写 11 是把三个配比组各算一项。一行一项就是 14 行，两栏 7×2。已回报给上游，story 不等 PRD 改。

### 🔴 变更记录已是 WIB

现状表头 `admin.algo.col.at`=「时间（WIB）」，值经 `@adminTime.wib(...)`，抽屉照抄即可，**不要**自己另起格式化（AD 模式规则：WIB 单一出口 `AdminTime`）。

### 🔴 校验逻辑一行不动

`AdminConfigService.updateFeedRank` 十余条 `require` 与 `AttributeTemplate.rejectUnusableQuotasDetailed` 是「保存通过了但生成出来的模板是坏的」的唯一防线；本 story 只改展示。
