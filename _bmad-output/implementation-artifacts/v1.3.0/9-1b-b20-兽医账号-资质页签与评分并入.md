# Story 9.1b: B20 兽医账号——资质页签与评分并入

Status: ready-for-dev

> 自包含 story，可本地或云端 L0 执行。与用户沟通用中文。执行纪律见根 `CLAUDE.md`。
> 本 story 在 9.1a 的抽屉壳里填充「资质」「评分」两个页签，并退役三个独立页；**写端点零变更**、零迁移。

## Story

As a 运营，
I want 在兽医抽屉里直接录入 / 续期 / 审核资质，并看到这位兽医的评分明细，
so that 资质审核和评分查看不再各占一个页面。

## Acceptance Criteria

**AC1 · 资质页签（vet-qualification 全字段并入）**
**Given** 9.1a 抽屉已存在
**When** 切到「资质」页签（`GET /admin/vets/{id}/drawer?tab=qual` 或页签内 hx-get 片段，`vet.qualify_view` 或 `vet.qualify`）
**Then** 「当前资质」卡：状态（`QualificationStatus`）+ 驳回理由（若有）+ 证图预览（KTP / SIPDH / STRV / 学位证 / PDHI / 档案照，走既有预签名 URL，**证件 key 与签名 URL 绝不落日志审计**）`[L1]`
**And** 「直录 / 续期」表单：KTP 编号；SIPDH 编号 / 机构 / 有效期 / 证图 key；STRV 编号 / 机构 / 有效期 / 证图 key；学位证 / PDHI / 档案照 key；专长（多选）；`mode=record|renew` 二选（续期只更新证件与有效期，不重置认证状态——UI 稿 6-5）；提交 `POST /admin/vets/{id}/qualification`（`vet.qualify`），`QualificationForm` 字段名不变 `[L1]`
**And** 审核区：通过 `POST …/qualification/approve`；驳回 `POST …/qualification/reject` 理由必填（`reason`），data-confirm `[L1]`
**And** htmx：成功返抽屉 fragment + oob 行（资质态列刷新）；422 行内 err；403 禁用态注明缺 `vet.qualify` `[L1]`

**AC2 · 评分页签（vet-ratings 并入）**
**When** 切到「评分」（`rating.view`）
**Then** 摘要：均分 / 已评数 / 未评数 / 总问诊量；逐条评价列表（星级 / 评价 / 时间 WIB）；「未评问诊单」区（会话 / 原因 / 时间，Story 6.2 既有 `unratedConsults`）`[L2]`
**And** 无 `rating.view` 时页签渲染为禁用并注明所缺权限，不 403 整个抽屉 `[L1]`

**AC3 · 评分总览页退役，摘要指标并入列表**
**Given** `GET /admin/ratings`（`ratings.html`，按均分 / 问诊量排序的总览）与 `GET /admin/vets/{id}/ratings`（`vet-ratings.html`）
**Then** 两路由方法与两模板删除；列表页「评分」列保留均分数字并支持按均分 / 问诊量排序（`sort=avgDesc|avgAsc|volumeDesc`，复用 `AdminRatingService.overview` 的排序逻辑）；`from` / `to` 评价时间段筛选并入列表筛选栏 `[L1]`
**And** `templates/admin/vet-qualification.html` 与 `GET /admin/vets/{id}/qualification` 删除 `[L1]`
**And** 导航「兽医与问诊」组去掉「评分查看」（`admin.nav.ratings`）；旧地址 404 不跳转（D-23）`[L1]`

**AC4 · 写端点零变更**
**Then** `POST /admin/vets/{id}/qualification`、`…/approve`、`…/reject` 路径 / 参数 / `@PreAuthorize` 不变 `[L0]`

**AC5 · 三语 + 测试 + 回归**
**Then** 新 key `admin.v130.vets.qual.*`、`admin.v130.vets.rating.*` 三包同批 `[L0]`
**And** 既有 `vetqual/VetQualificationIntegrationTest`、`VetQualificationReviewIntegrationTest`、`GrandfatherQualificationIntegrationTest`、`SipdhExpiryScanIntegrationTest`、`rating/AdminRatingOverviewIntegrationTest`、`VetRatingDetailIntegrationTest` 全绿（总览 / 详情两页的 GET 用例改为列表排序 + 抽屉页签断言）`[L1]`

### 🔴 「未成功请求」维度的评价不并入

UI 稿 6-6 caption：「未成功请求维度评价（含原因）仍在独立页 6-8（低频取证场景，不并入）」。评分页签只并入 `vet-ratings.html` 的内容（均分 / 明细 / 未评问诊单）；不要把 B21 的东西搬进来。

### 🔴 续期语义

`mode=renew` 走 `VetQualificationService.renew`：只更新证件与有效期，**不重置认证状态**；`mode=record` 走 `recordByOps`。表单里两个提交钮（`admin.qualpage.submitRecord` / `submitRenew`）分别带 `mode`，现状如此，保留。

### 🔴 SIPDH 到期扫描不受影响

`SipdhExpiryScanner`（03:00 UTC）读同一张表；本 story 只改展示层，回归 `SipdhExpiryScanIntegrationTest` 即可。生产曾把兽医 4 的 `sipdh_expiry` 置空以免被扫回 EXPIRED（memory），不要在录入表单加「有效期必填」。

### 与 9.1a 的边界

页签容器 id 沿用 9.1a 的 `#vets-drawer-tab-qual` / `#vets-drawer-tab-rating`；只填内容不改壳。

### 测试标准

沿用 `test/.../admin/vetqual/**`、`admin/rating/**` 既有集成测试类；fragment 断言不含 `<html`。

### Project Structure Notes

改动落 `admin/vetqual/web`、`admin/rating/web`、`admin/web/AdminWebController`、`fragments/drawer-vets.html`；删除三个模板与一个 Controller（或方法）。
