## Story

As a 运营，
I want 品类是数据库里的一行数据而不是写死在 Java 枚举里，
so that 上一个新品类不用等一次发版、一次迁移、一次找技术。

### 现状一：品类是编译期常量，四值写死在三个地方

`petgo-backend/src/main/java/com/tailtopia/shop/domain/ProductCategory.java`（全文 18 行）：


同一份四值另外写死在：

| 位置 | file:line | 形态 |
|---|---|---|
| 数据库 CHECK | `db/migration/V20260817_1154__init_shop_products_and_skus.sql:40-41` | `CHECK (category IN ('MAKANAN','OBAT_VITAMIN','CAMILAN','PERAWATAN'))` |
| App Dart 枚举 | `petgo_app/lib/features/shop/domain/shop_product.dart:10-32` | `enum ShopCategory { makanan('MAKANAN'), … }`，注释 `:11-13` 明写「🔴 固定四值……新增品类须走 PRD 变更，不是加一行枚举」 |

**上一个品类要走三处同改 + 一次 CHECK 重建 + 一次发版。** 这正是 SHOP-FR-19 要消掉的东西。

### 现状二：🔴 CHECK 重建是本仓反复出事的地方

根 `CLAUDE.md` 纪律 5：「改 CHECK 约束必须重列全集……**此处已出过三次事故**（V72、V20260818_0358 各丢一批值），每次都是照着过期列表抄。」

`ck_shop_products_category` 今天有四个值。加第五个品类 = `DROP + ADD` 重列五值。加第六个 = 重列六值。**每一次重建都是一次「照过期列表抄」的机会**，而且抄错不会当场报错 —— 它表现为某个品类的商品在几周后突然存不进去。

👉 **AD-S1 用外键取代 CHECK 的全部理由就在这里**：外键的「合法值集合」是 `shop_categories` 表里的行，**没有任何地方需要重新誊写一遍值列表**。增删品类是 INSERT / UPDATE，不是 DDL。事故模式被根除，不是被缓解。

## Dev Notes

### 迁移骨架（照抄这个顺序）

```sql
-- V1.3.0 shop-v2 Story 6-1（SHOP-FR-19 · AD-S1）：品类从 Java 枚举改为数据表。时间戳版本号（E7）。
--
-- 🔴 为什么用外键取代 CHECK 约束：
--    ck_shop_products_category 把四个品类值写死在库里。加一个品类 = DROP + ADD 重列全集，
--    而 CLAUDE.md 纪律 5 记着：本仓在「重建 CHECK 时照着过期列表抄」上**已经出过三次事故**
--    （V72、V20260818_0358 各丢过一批值），每次都是照着一份过期列表誊写。
--    外键把「合法值集合」搬进 shop_categories 表 —— 增删品类变成 INSERT / UPDATE，
--    **再也没有任何需要誊写的值列表**。事故模式被根除，不是被缓解。
--
-- 🔴 三步顺序不可换：必须先灌完四条种子再加外键，否则存量 shop_products 当场违反外键、迁移失败。
-- ⚠️ shop_products.category 的列名与类型（VARCHAR(24) NOT NULL）一个字符都不改，存量数据零 UPDATE。
-- ⚠️ idx_shop_products_listing (category, sort_weight DESC, id DESC) 不动 —— 列没变，索引仍然有效。
-- ⚠️ sort_weight 用 INT 不用 SMALLINT：Hibernate int 实体映 int4，SMALLINT 会让 ddl-auto=validate 变红
--    （V95__add_id_card_numbers.sql:21 的成文教训）。

-- ① 建表 + 灌四条存量（code 逐字等于旧枚举值；显示名取现 ARB 文案）
CREATE TABLE shop_categories (
    id          BIGINT      GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    code        VARCHAR(24) NOT NULL,   -- 稳定编码，创建后不可改（实体 updatable=false）
    name_id     VARCHAR(40) NOT NULL,   -- 印尼语显示名（SD-15）
    name_en     VARCHAR(40) NOT NULL,   -- 英语显示名（SD-15）
    sort_weight INT         NOT NULL DEFAULT 0,
    is_active   BOOLEAN     NOT NULL DEFAULT TRUE,   -- 停用不删除
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT uq_shop_categories_code UNIQUE (code)
);

INSERT INTO shop_categories (code, name_id, name_en, sort_weight) VALUES
    ('MAKANAN',      'Makanan',        'Food',                40),
    ('OBAT_VITAMIN', 'Obat & Vitamin', 'Medicine & Vitamins', 30),
    ('CAMILAN',      'Camilan',        'Snacks',              20),
    ('PERAWATAN',    'Perawatan',      'Grooming',            10);

-- ② 删掉写死值集合的 CHECK
ALTER TABLE shop_products DROP CONSTRAINT ck_shop_products_category;

-- ③ 换成指向 shop_categories.code 的外键
ALTER TABLE shop_products
    ADD CONSTRAINT fk_shop_products_category FOREIGN KEY (category)
        REFERENCES shop_categories (code);

COMMENT ON TABLE  shop_categories IS '商品品类（SHOP-FR-19）。运营可增改停，只做一级。code 创建后不可改。';
COMMENT ON COLUMN shop_categories.code IS '稳定编码，UPPER_SNAKE，创建后不可改；shop_products.category 外键指向它。';
COMMENT ON COLUMN shop_categories.name_id IS '印尼语显示名。🔴 由后端按 Accept-Language 下发给 App —— 这是「App 不渲染后端显示串」模型的有意例外（AD-S1-E），例外仅限品类名。';
COMMENT ON COLUMN shop_categories.name_en IS '英语显示名。同上。';
COMMENT ON COLUMN shop_categories.is_active IS '停用不删除。停用后 C 端全链路不可见、购物车该品类行失效；历史订单照常显示（订单行是快照）。';
```

`sort_weight` 用 40/30/20/10 而不是 1/2/3/4：留出插空位，运营在两个品类之间插一个新品类时不必重排整列。

### 排序口径一致性

`shop_categories` 用 `sort_weight DESC` 与 `shop_products.sort_weight DESC`（`ShopProduct.java:107`，索引 `V20260817_1154:54`）**同向** —— 全项目「权重大的排前面」。反过来会让运营在两个页面调权重时方向相反。
