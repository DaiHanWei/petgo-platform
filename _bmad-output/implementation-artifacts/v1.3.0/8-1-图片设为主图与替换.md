## Story

As a 运营，
I want 一键把某张图设为主图、或原位替换某张图，
so that 我不用「上传 → 拖到首位 → 删旧图」三步，也不怕删错。

### 现状五：这个控件是**三种模式共用的**，改它会一次性影响三条上传线

| objectKey 模式 | `data-mode="objectkey"` + `data-field-main` | **商品表单**、banner 表单 | 有 |

## Acceptance Criteria

**AC1 · 一键设为主图** `[L0]`
**Given** 商品表单的图片区有 ≥2 张缩略图
**When** 点击任一张（非第一张）上的「设为主图」
**Then** 该缩略图被移动到**第 0 位**，其余图片的**相对顺序保持不变** `[L0]`
**And** 「封面」角标随之移到这一张（复用既有 `markCover`，不新写一套角标逻辑）`[L0]`
**And** 隐藏字段 `f-mainImage` 变成这张图的 objectKey、`f-gallery` 变成其余 8 个 key（顺序为移动后的顺序）—— **写回逻辑必须仍是 `sync(root)` 这一条路**，不得在按钮处理器里直接写字段 `[L0]`
**And** 第一张自己的「设为主图」按钮**不渲染或处于禁用态**（点它是无操作，不要给一个点了没反应的控件）`[L0]`
**And** 🔴 **平铺模式（`data-field-keys` 在场，退货质检照片）下「设为主图」按钮一律不渲染** —— 那组图刻意没有封面概念（`admin.js:286-292`）`[L0]`
**And** 保存商品后刷新页面，第 0 位仍是这一张（`existingImages` 的组装顺序 `AdminShopProductController:154-167` 未被改坏）`[L1]`

**AC2 · 原位替换** `[L0]`
**Given** 图片区第 N 张缩略图
**When** 点它上面的「替换」并选一个新文件
**Then** 上传成功后，**第 N 张的位置不变**，只是它的 `data-key` / `data-url` / `data-w` / `data-h` 与 `<img>.src` 被换成新图 `[L0]`
**And** 图片总张数**不变** `[L0]`
**And** 若被替换的是第 0 张，则 `f-mainImage` 与 `f-mainImageW/H` 同步换成新图的值（走 `sync`，不特判）`[L0]`
**And** 🔴 **上传失败时原缩略图原封不动**（key / url / 尺寸 / 位置全不变），只在错误区显示一条失败原因 —— 复用既有 `showError`（`admin.js:452-455`），**不得先把旧图移除再传** `[L0]`
**And** 替换用的是既有上传端点 `POST /admin/shop/products/images`（模板 `:123` 的 `data-upload-url`），**不新增任何端点**（AB-19A）`[L0]`

**AC3 · 🔴 满 9 张时仍可替换** `[L0]`
**Given** 图片区已有 9 张（`MAX`）
**When** 点某一张的「替换」并选新文件
**Then** 上传**正常发出并成功**，不弹 `admin.js:374` 那个 `data-msg-limit` 的 `window.alert` `[L0]`
**And** 同一状态下点「新增」（`[data-seed-file]`）仍然被 `MAX` 拦住并弹原提示 —— **张数上限只对「新增」生效，对「替换」不生效** `[L0]`
**And** 单张大小上限（`data-max-bytes`，`admin.js:381-385`）对替换路径**照样生效** —— 放开的是张数，不是体积 `[L0]`
**And** 服务端校验不变：`AdminShopProductService.validate:161-163` 的「图集最多 8 张」仍是权威，替换不改变张数所以恒过 `[L1]`

**AC4 · 拖拽排序原样保留** `[L0]`
**Then** `dragstart`/`dragover`/`drop`（`admin.js:485-501`）的行为逐字不变：拖到谁身上就插到它前面，落定后 `sync` `[L0]`
**And** 新增的两个按钮**不劫持拖拽**：在按钮上按下鼠标不得触发 `dragstart`（缩略图 `draggable="true"` 在父元素上）；实现时给按钮加 `draggable="false"`，并在按钮 click 处理器里 `preventDefault` + 不冒泡到别的处理器 `[L0]`

## Dev Notes

### 「设为主图」为什么不是后端功能

主图在库里是 `shop_products.main_image_key`（`ShopProduct.java:52`，配套 `mainImageW:65` / `mainImageH:68`），图集是 `galleryKeys`（`:73`，JSONB）。表单提交的是两个文本字段 `f-mainImage` / `f-gallery`（模板 `:164` / `:166`），服务层 `AdminShopProductService.create:54-59` / `update:71-76` 原样收下。

所以「哪张是主图」这件事，在**提交那一刻**就已经由字段内容决定了 —— 前端把某张挪到第 0 位、`sync` 写字段、保存，整条链路一个后端改动都不需要。

🔴 **反过来说：不要为此新造一个 `POST /admin/shop/products/{productId}/main-image` 端点。** 那既违反 AB-19A 零端点变更（本 story 不在 AD-S13 的例外清单里），也会制造「图片状态先改了、商品其它字段还没保存」的半提交态。

### 替换为什么必须复用同一个上传端点

`POST /admin/shop/products/images`（`AdminShopProductController:205-218`）做的事只有一件：`images.upload(file, "shop-product")`（`:210`）。闸门全在 `AdminSeedImageService`：`MAX_BYTES = 10MB`（`:36`）、白名单 `{image/jpeg, image/png, image/webp}`（`:39`）、HEIC 显式拒绝。返回体是 `UploadedImage(url, w, h, warning, objectKey, sizeBytes)`（`petgo-backend/src/main/java/com/tailtopia/admin/seed/dto/UploadedImage.java:16-17`）—— **替换需要的字段一个不缺**。

### 🔴 旧图不删：F21 是全局纪律

替换之后，旧 objectKey 就没人引用了。**不要顺手去删 OSS 对象** —— `AliyunOssClient:197-198` 内联写明删除禁令，`MediaDeletionService` 全部方法是 no-op（F21）。身份证卡快照曾因为级联删 OSS 头像而出现死链，这条纪律就是那次事故的修法。孤儿对象的清理是另一件事，不在本 story。

### 共用 JS 的回归面

改 `admin.js` 的这个 IIFE，会一次性影响**至少三条上传线**：

| 线 | 模板 / 控制器 | 模式 |
|---|---|---|
| 商品图片 | `shop-product-form.html:117-153` · `AdminShopProductController:205` | objectKey |
| banner 图 | `AdminShopBannerController:96-99` | objectKey |
| 退货质检照片 | `AdminReturnController:211-215` | 平铺（`data-field-keys`） |
| 内容单条发布 | `AdminSeedAssistController:56-59` | URL |
| 批次素材 | `AdminSeedBatchWorkspaceController:305-309` | 另一个 IIFE（`:514` 起），不受本 story 影响 |

原则：**新增行为一律靠新属性开启，缺属性的老模板行为逐字不变**（沿用 `admin.js:379-380` 的既有做法：「没有 `data-max-bytes` 的老模板自动跳过本检查」）。

### 与 8-3 的改动冲突

Story 8-3（SKU 级图片）也要改这同一个 IIFE（把 `var MAX = 9` 改成可配的每根节点上限）。两条 story 若并行：**先做 8-1，8-3 在 8-1 之上叠加**；若 8-3 先落地，8-1 的 T3 要按当时的 `upload()` 签名调整。任一顺序下都不要各自复制一份 JS。
