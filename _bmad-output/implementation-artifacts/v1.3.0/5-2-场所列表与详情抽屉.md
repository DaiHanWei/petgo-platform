# Story 5.2: 场所列表与详情抽屉（B6）

Status: ready-for-dev

> 自包含 story，可本地或云端 L0 执行。与用户沟通用中文。执行纪律见根 `CLAUDE.md`。
> 本 story 是**只读**页面（列表 + 抽屉展示），处置动作在 5.3、新建在 5.4。依赖 5.1 的表与实体、2.3a 的 fragment 响应约定、2.3b 的模板 B 壳与 `admin-drawer.js`。

## Story

As a 运营，
I want 「内容 → 场所管理」列表与抽屉查看每个场所的信息、照片、评论、打卡，
so that 巡查场所内容有统一入口。

## Acceptance Criteria

**AC1 · 页面与导航**
**Given** 登录账号持 `place.manage`
**When** 打开 `/admin/places`
**Then** 页面套模板 B 壳（`fragments/tpl-b-list.html`），侧导航「内容」组第 7 项「场所管理」高亮；无 `place.manage` 的账号菜单项不渲染、直接访问 403 `[L1]`

**AC2 · 筛选栏**
**Then** 筛选 = 名称 / 地址关键词（文本框 + 显式「查询」钮）· 类型（下拉，data-autosubmit）· 状态（全部 / 上架 / 已下架 / 已合并，data-autosubmit）；关键词对 `name` 与 `address_text` 做 `ILIKE %q%` `[L1]`

**AC3 · 摘要条**
**Then** 四个数字随筛选联动：上架场所数 · 今日新增（WIB 自然日）· 待处理举报数（`place_reports.status='PENDING'` 计数，**点击跳 A1 场所举报页签** `/admin/manual-review?type=PLACE_REPORT`）· 累计打卡数；单条 `COUNT(*) FILTER` 聚合查询实现 `[L1]`

**AC4 · 表格**
**Then** 列 = 名称 ｜ 类型 ｜ 标签（胶囊，最多显示 3 个 + `+N`）｜ 文字地址（截断悬浮全文）｜ 标记人（昵称，注销置灰）｜ 照片数 ｜ 评论数 ｜ 打卡数 ｜ 推荐·不推荐（`12 · 3` 形式）｜ 状态（色点 + 徽标）｜ 创建时间（WIB）；默认创建时间倒序；每页 20；`deleted_at IS NULL` `[L1]`
**And** 表头三语、按 ID 最长文案不截断（nowrap + 省略号）`[L2]`

**AC5 · 详情抽屉（只读）**
**When** 点任一行（或带 `?open=<id>` 打开页面）
**Then** `GET /admin/places/{id}/drawer` 返回 480px 抽屉 fragment，五区：① 基本信息（名称 / 类型 / 标签 / 描述 / 文字地址 / 纬度 / 经度 / 标记人 / 状态 / 创建时间；`MERGED` 时显示「已并入 → 保留场所名」可点跳其抽屉）② 照片墙（缩略图 + 上传者昵称，签名 URL 由 `SignedUrlService` 现签，**不落库**）③ 评论列表（正文 + 作者 + 态度徽标 👍/👎 + 时间，分页 20）④ 打卡计数 ⑤ 操作条占位（按钮由 5.3 填充，本 story 渲染为禁用态并注明「处置动作见 5.3」不算缺陷）`[L2]`
**And** 抽屉内摘要块用 2×2 弹性网格（UX-DR11）`[L2]`

**AC6 · 空态与边界**
**Then** 无场所时空态文案「暂无场所」；搜索无结果「无匹配场所」；`MERGED` / `DELISTED` 行状态徽标灰 / 黄，抽屉正常打开 `[L2]`

**AC7 · 测试与回归**
**Then** MockMvc 四条：整页 200、`HX-Request` 返抽屉 fragment、无权限 403、非法 id 404 fragment `[L1]`；三语 key 齐 `[L0]`

## Dev Notes

### 🔴 本 story 与 5.3 / 5.4 的切线

- 5.2：列表 + 抽屉**只读**，操作条按钮渲染为禁用占位。
- 5.3：把操作条接上编辑 / 下架 / 恢复 / 删照片 / 删评论 / 合并六个端点。
- 5.4：右上「＋新建场所」按钮 + 抽屉表单；A1 场所举报页签。
这样切是为了每条 story 单会话可完成，且 5.3 的服务层可以在 5.2 的读模型上直接加写方法。**不要在 5.2 里顺手实现处置端点**。

### 🔴 UI 稿 2-20 与逐页规格 B6 的列不一致，以逐页规格为准

UI 稿 2-20 列表帧画的列是「场所 / 类型 / 城市 / 地址备注 / 状态」+ 筛选「全部城市」，逐页规格 B6 的列是 11 列（含标记人、照片数、评论数、打卡数、推荐·不推荐、创建时间）且无「城市」。**D-8 只说页面数量与归组以 UI 稿为准，列内容以逐页规格为准**（架构 UX-DR14）。本 story 按 B6 的 11 列实现；「城市」不是数据模型字段（`places` 表无 city 列），筛选栏不做城市下拉。若产品要城市维度，需先补字段——记入开放问题。

### 🔴 待处理举报数跳转目标

摘要条第三格「待处理举报数（跳 A1）」链接到 `/admin/manual-review?type=PLACE_REPORT`。该页签在 5.4 才存在，本 story 先按此 URL 渲染链接即可（5.4 合入前点过去落到无筛选的 A1 页，不报错）。

### 🔴 照片 URL 现签、不落库、不进日志

`place_photos.object_key` 存 OSS objectKey。抽屉渲染时用 `shared/media/SignedUrlService` 现签短时效 URL（照身份证 / 种子素材的既有做法）。CLAUDE.md 明令日志禁记签名 URL，`AdminPlaceQueryService` 与 Controller 不得 `log.info` 任何含 URL 的对象。
