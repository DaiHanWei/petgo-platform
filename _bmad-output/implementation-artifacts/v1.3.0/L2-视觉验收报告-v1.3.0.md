## 一、验收方法

1. **部署**（T1）：`git checkout dev_1.3.0 && git pull && ./scripts/deploy-backend-stag.sh`
   → `curl -s https://api-stag.tailtopia.id/actuator/health` 应为 `UP`
   → `docker exec petgo-postgres psql -U petgo -d petgo_stag -c "select version, description from flyway_schema_history order by installed_rank desc limit 12"`
2. **造数**（T2）：2 个测试后台账号（CUSTOM / 客服角色）、1 个仅缺 `payment.view` 的账号、
   2 个待合并场所、1 篇冷帖；虚拟账号池已有则复用。
3. **逐页截图**（T3）：登录 → 依路由清单访问 → 截全页 → 打开首行抽屉再截。
   与 Story 11.2 的 ID 截图**共用同一次部署与同一套脚本**，但产出两份报告（11.2 比语言，本报告比形态）。
4. **人工对照 UI 稿逐帧勾表**（下表）。
5. **缺陷回对应 story 修 → 回归 → 更新本报告**。

> ℹ️ 截图脚本云端**没有**代写：这里既跑不起后端也没装 playwright 包，写出来的是一份没跑过的自动化 ——
> 而本仓库的规矩是「一条从来没绿过的护栏等于没有」。本地首次执行时现写现调，比拿一份未验证的脚本去调更快。
