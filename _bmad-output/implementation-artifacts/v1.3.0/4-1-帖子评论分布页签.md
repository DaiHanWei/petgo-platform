## Story

As a 运营，
I want 在评论管理页切到「帖子评论分布」，按评论数、时间、物种筛出冷帖，摘要条给我双口径的篇均评论数，
so that 找冷帖不用一个个点开帖子。

## Acceptance Criteria

**AC1 · 页面结构：评论管理升级两页签**
**Given** 现有 `/admin/comments`（Story 9.9 列表页，`AdminCommentModerationController.list`）
**When** 页顶加常驻页签条「评论巡查｜帖子评论分布」
**Then** 页签一 = 现状功能不变（列表 + 下架 / 恢复端点与权限不变）`[L1]`
**And** 页签二 `GET /admin/comments/distribution` 用 htmx 局部切换（`hx-get` 替换页签内容区，不整页刷新）`[L2]`
**And** 页签二权限：`SUPER_ADMIN` 或 `comment.virtual_post`（可评）或 `content.view`（只看，「去评论」按钮禁用并注明所缺权限）`[L1]`

**AC2 · 筛选**
**Then** 筛选项：评论数区间（快捷 `=0` / `≤3` / 自定义 `≤N`，N 正整数）· 发布时间段（起止 WIB 日期，默认近 7 天）· 物种（全部 / CAT / DOG / OTHER / GENERAL，走 `ContentSpeciesResolver` 的有效物种）· 帖子状态（全部 / 可见 / 已下架，**默认全部**）· 「排除虚拟账号内容」开关（**默认开**）`[L1]`
**And** 「排除虚拟账号内容」判定 = 帖子作者 `users.account_type = 'VIRTUAL'`（虚拟账号池）；真实身份池（`seed_real_account_grants`）的帖**照常参与** `[L1]`
**And** 下拉即选即查（`data-autosubmit`），自定义 N 输入框配显式「查询」钮 `[L2]`

**AC3 · 列表**
**Then** 列 = 帖子摘要（正文前 40 字，点击可开 B1 内容抽屉 `?open=`）｜ 作者（昵称，虚拟账号带后台可见标识）｜ 发布时间（WIB）｜ 评论数（0 红标、1～3 黄标）｜ 其中虚拟评论数 ｜ 操作「去评论」（Story 4.2 接入，本 story 先渲染按钮并带 `data-post-id`）`[L2]`

**And** 评论数口径 = **可见评论**（`comments.deleted_at IS NULL AND moderation_status='VISIBLE'`，一级 + 二级）`[L1]`

**AC4 · 摘要条（数据分析用，随筛选联动）**
**Then** 四格：筛选范围内帖子数 · 篇均评论数**双口径并列**（含虚拟 / 剔除虚拟）· 0 评论帖数与占比 · 虚拟评论占比 `[L1]`

**And** 四格由**一条聚合 SQL** 算出（不逐帖循环），随筛选条件联动 `[L1]`

**AC5 · 空态与边界**
**Then** 筛选无结果：空态文案 `admin.v130.comments.distribution.empty`；帖子已删（`deleted_at` 非空）不出现在任何状态筛选下 `[L2]`

## Dev Notes

### 🔴 「虚拟账号池」的判定与 3-1 的 `isSyntheticAccount()` 不是同一个集合

PRD AB-20A 明写「排除虚拟账号内容 = 只排除**虚拟账号池**发布的帖子，真实身份池的帖照常参与」。代码里虚拟账号池就是 `users.account_type = 'VIRTUAL'`（`AccountType.VIRTUAL`，V82 建列并把历史 `seed-tailtopia-%` 也回填成 VIRTUAL；`AdminVirtualAccountService.create` 用 `User.newVirtual` 落 VIRTUAL）。

而 3-1 的 `User.isSyntheticAccount()`（AD-8）还额外包含 `role=ADMIN` 的旧运营号——那是看板「真实用户」口径用的。**本页签用 `account_type = 'VIRTUAL'`**，与 PRD 字面一致；`CommentRepository.countByRealAuthor()` 已经是这个写法（`u.accountType = REAL`），照抄。
⚠️ 回报给架构：AD-8 说三处（看板 / 暖评身份池 / 暖贴入队）「只调它」，但暖评这两处按 PRD 应是 VIRTUAL 判定；建议 AD-8 拆成 `isSyntheticAccount()`（看板）与 `isVirtualPoolAccount()`（暖评，= accountType==VIRTUAL）两个出口。

### 分布聚合 SQL 草案

```sql
-- 帖子过滤片段（列表与摘要共用）
WITH base AS (
  SELECT cp.id, cp.author_id, cp.created_at, cp.status, cp.body,
         COALESCE(cp.species_override, u.account_species) AS species,
         u.account_type = 'VIRTUAL' AS author_virtual
  FROM content_posts cp
  JOIN users u ON u.id = cp.author_id
  WHERE cp.deleted_at IS NULL
    AND (:excludeVirtual = false OR u.account_type <> 'VIRTUAL')
    AND (:status IS NULL OR cp.status = :status)        -- 可见 = 'PUBLISHED'，已下架 = 'UNDER_REVIEW' 之外由 deleted_at/软删语义决定，见下
    AND (cp.created_at AT TIME ZONE 'Asia/Jakarta')::date BETWEEN :fromDate AND :toDate
    AND (:species IS NULL OR COALESCE(cp.species_override, u.account_species) = :species)
),
cc AS (
  SELECT c.post_id,
         COUNT(*)                                          AS total_visible,
         COUNT(*) FILTER (WHERE cu.account_type = 'VIRTUAL') AS virtual_visible
  FROM comments c JOIN users cu ON cu.id = c.author_id
  WHERE c.deleted_at IS NULL AND c.moderation_status = 'VISIBLE'
  GROUP BY c.post_id
)
-- 列表
SELECT b.id, b.body, b.author_id, b.created_at, b.author_virtual,
       COALESCE(cc.total_visible,0) AS comment_count,
       COALESCE(cc.virtual_visible,0) AS virtual_count
FROM base b LEFT JOIN cc ON cc.post_id = b.id
WHERE COALESCE(cc.total_visible,0) <= :maxCount        -- =0 时 maxCount=0
ORDER BY comment_count ASC, b.created_at DESC
LIMIT 20 OFFSET :offset;

-- 摘要条（同 WHERE，不带 LIMIT）
SELECT COUNT(*)                                                   AS posts,
       AVG(COALESCE(cc.total_visible,0))                          AS avg_all,
       AVG(COALESCE(cc.total_visible,0) - COALESCE(cc.virtual_visible,0)) AS avg_real,
       COUNT(*) FILTER (WHERE COALESCE(cc.total_visible,0) = 0)   AS zero_posts,
       SUM(COALESCE(cc.virtual_visible,0))::numeric
         / NULLIF(SUM(COALESCE(cc.total_visible,0)),0)            AS virtual_share
FROM base b LEFT JOIN cc ON cc.post_id = b.id
WHERE COALESCE(cc.total_visible,0) <= :maxCount;
```

- 「帖子状态」筛选映射：可见 = `status='PUBLISHED' AND deleted_at IS NULL`；已下架 = **软删或非 PUBLISHED**。`content_posts` 的运营下架是软删（`deleted_at`）——所以「已下架」要用 `deleted_at IS NOT NULL` 的分支，而 base 里 `deleted_at IS NULL` 那行须按状态筛选条件动态放开。实现时把这一段做成三选分支，别写死。
- 切日一律 `AT TIME ZONE 'Asia/Jakarta'`（NFR-5 / OQ-B3）。
- 评论表已有 `moderation_status`（story 3 加的，V1.3.0 代码在 `Comment.java`），SQL 头注释里「stag 库暂无该列」已过期，不要沿用旧 SQL 的写法。
