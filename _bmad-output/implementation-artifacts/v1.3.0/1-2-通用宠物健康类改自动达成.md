# Story 1.2: 通用宠物健康类改自动达成

Status: ready-for-dev

## Story

As a 养「其他」类宠物的用户，
I want 「第一次看兽医」和「第一次健康检查」像猫狗一样只能真做了才点亮，
so that 成就的含金量对所有物种一致。

---

> **补齐 1.1.2 FR-86 的漏网项。** FR-86 当初按后缀 `M3/M4/M5/M9` 取消打卡，通用清单的 `G-M1`（看兽医）/ `G-M2`（健康检查）后缀不命中，**至今仍是打卡类** —— 同一件事猫狗要真问诊/真录记录才点亮，其他宠物点「已打卡」就行。属规则漏网，非有意差异。
>
> **本 story 最容易被漏掉的一半是存量迁移。** `pet_milestones.trigger_type` **建档那一刻就物化成行**，而铺清单入口 `MilestoneService.assignRoster` 有 `existsByPetProfileId` 短路、**对已建档宠物永不回改**。只改编译期目录 → 只对新建档宠物生效，**存量宠物照旧渲染打卡按钮**。先例：V77 正是为同类问题补的迁移。

## Acceptance Criteria

### AC1 — 目录改判（L0）

**Given** 编译期里程碑目录
**When** 读取 `G-M1` / `G-M2` 的触发类型
**Then** 为 `SYSTEM_AUTO`，不再是 `USER_CHECKIN` `[L0]`

### AC2 — 🔴 存量迁移（L1，最易漏）

**Given** 一只本次上线**之前**已建档的 `OTHER` 类宠物
**When** 迁移执行完毕后查询其 `pet_milestones`
**Then** `G-M1` / `G-M2` 的 `trigger_type` 已改为 `SYSTEM_AUTO` `[L1]`
**And** 客户端不再为这两条渲染打卡按钮 `[L1]`
**And** 迁移文件名为时间戳制 `V<yyyyMMdd_HHmm>__<snake>.sql` `[L0]`

### AC3 — 触发源接入（L1）

**Given** 一只 `OTHER` 类宠物
**When** 一次**真人**兽医咨询结束
**Then** 自动完成 `G-M1` `[L1]`
**When** 一次 AI 分诊结束
**Then** **不**完成 `G-M1`（AI 不发 `ConsultClosedEvent`，模块隔离天然满足，**不得再加一层 AI 判断分支**） `[L0]`

**Given** 一只 `OTHER` 类宠物
**When** 录入 `VACCINE` 类型健康记录
**Then** 自动完成 `G-M2`（决策 A-1：只认疫苗，不新增「体检」类型） `[L1]`

### AC4 — 打卡护栏与候选过滤（L1）

**Given** 任一客户端
**When** 对 `G-M1` / `G-M2` 发起打卡请求
**Then** 后端拒绝 `[L1]`
**And** 这两条不出现在「已打卡候选内容」的可选列表中 `[L1]`

### AC5 — 存量完成态不回滚（L1）

**Given** 一只已通过打卡完成 `G-M1` 或 `G-M2` 的宠物
**When** 迁移执行完毕
**Then** 其完成态保持不变，不回滚 `[L1]`

### AC6 — 文案三处同步（L0）

**Given** `G-M1` / `G-M2` 的说明文案
**When** 在 Java 中文目录、印尼语标题表、客户端 en/id 双语表三处查看
**Then** 打卡引导措辞已作废，改为与猫狗 `M5` / `M3` 同类的说明文案 `[L0]`
**And** 三处同步，跨库测试通过 `[L0]`

### AC7 — 不扩散（L0）

**Then** 不改动自动完成的寻址实现（属 Story 1.1） `[L0]`
**And** 不改动灰徽章点击去向（属 Story 1.3） `[L0]`
**And** 不新增「体检」健康记录类型 —— `health_records.type` 的 CHECK 约束**一字不动** `[L0]`

## Dev Notes

### 🔴 头号陷阱：只改目录不写迁移 = 对存量用户完全失效

`MilestoneService.assignRoster` 只在 `!existsByPetProfileId(petProfileId)` 时铺行。已建档宠物的 `trigger_type` 是**建档当时物化的快照**，之后任何目录改动都不会回写。
**验收时务必用一只上线前就存在的宠物测**，用新建档的测不出问题。
