# Story 11.4: 权限矩阵与导航一致性收口

Status: ready-for-dev

> 自包含 story，L0/L1 为主。与用户沟通用中文。
> 目标：`AdminPageCatalog`（1.5 引入、2.3a 迁至 `admin/shared`）成为导航、角色矩阵、账号权限面板、`@PreAuthorize` 四方的唯一页面目录，四方之间没有孤儿。

## Story

As a 超级管理员，
I want 导航上有的页面在权限矩阵里都能找到、矩阵里勾的码都真的门控着某个端点、没权限的人既看不到菜单也进不了页面，
so that 权限配置所见即所得。

## Acceptance Criteria

**AC1 · 目录完备（Catalog ↔ 路由）**
**Given** `AdminPageCatalog`（约 35 个页面维度，8 个导航组）
**Then** 每个页面级 GET 路由（Story 11.1 after 列表，排除 login / oauth / drawer / 导出 / 片段）在目录中恰有一条；目录中每条都有存活路由；测试 `AdminPageCatalogCoverageTest` 双向断言 `[L1]`

**AC2 · 权限码完备（Catalog ↔ AdminPermissions）**
**Then** `AdminPermissions` 全部常量（基线 72 + 本版新增 `place.manage`、`comment.virtual_post` = 74）每一个都出现在矩阵的「查看 / 编辑 / 其他操作」某一格；矩阵中每个码都是常量（无手写字符串）；测试断言集合相等 `[L0]`
**And** 已撤销的 `content.stats_view` / `content.stats_export` 不出现（现状注释：整页 2026-08-28 撤销，存量账号残留字符串不清）`[L0]`

**AC3 · 门控完备（Catalog ↔ @PreAuthorize）**
**Then** 写操作清单（11.1）里每条端点的 `@PreAuthorize` 表达式中出现的每个 `hasAuthority('x')` 码 ∈ `AdminPermissions`；每个页面 GET 的门控码 = 目录中该页的「查看」码（或 SUPER_ADMIN）；脚本 `scripts/ci/check-admin-permission-consistency.sh` 输出零差异 `[L0]`
**And** 代码现状不规整项**如实保留并在矩阵注脚说明**（FR-21A-7）：评论管理无独立查看码沿用 `content.view`；退款管理 / Toko 退货 / 开封判例共用 `refund.*`；复购效果走 `config.view` 或 `order.view`；**本 story 不拆码** `[L0]`

**AC4 · 导航 ↔ 权限行为**
**Given** 一个仅持单一权限码 X 的 CUSTOM 测试账号
**When** 登录
**Then** 侧导航只渲染目录中「查看码 = X」的页面所在组与项；其余页面直接 GET 返 403（`adminAccessDeniedHandler`）；组内全部无权限则整组不渲染 `[L1]`
**And** 对 74 个码逐个跑上述用例（参数化测试），无一例外 `[L1]`

**AC5 · 账号面板 ↔ 角色矩阵同构**
**Then** 后台账号页 CUSTOM「编辑权限」面板（1.6）与角色配置页矩阵（1.5）使用同一 `PermissionMatrixBuilder` 输出：分组顺序、页面维度、码归属完全一致；模板渲染单测比对两处 DOM 的分组标题序列 `[L2]`

## Dev Notes

### 现状事实

- `AdminPermissions.java`：常量按 Epic 分组注释（兽医 / 用户 / 内容审核 / 问诊 / 评分 / 客服 / 退款 / 订单 / 虚拟账号 / 种子 / 运营配置 / 月结 / 支付 / 风险 / 电商 / 后台账号），2026-09-09 计 72 个；文件尾部有 `GROUPS` 派生模型注释（账号页勾选区只遍历 GROUPS）。**`PermissionMatrixBuilder` 应以 `GROUPS` 为源重排到 8 个导航组，而不是再写一份手工列表**——否则第三份真相。
- 页面门控写法两种：`@PreAuthorize("hasRole('SUPER_ADMIN') or hasAuthority('vet.view')")` 内联，或类常量 `VIEW_AUTH` / `AUTH`（vetqual、failedrequest、payment 等）。脚本提取要覆盖常量引用（先解析常量定义再替换）。
- `layout.html` 现状每个导航项手写 `sec:authorize` 表达式并注释「与 Controller 的 @PreAuthorize 逐字一致（权限自查 2026-08-26 补）」——说明历史上靠人肉对齐出过问题，这正是 `AdminPageCatalog` 要消灭的。

### 🔴 不拆码、不清残留

FR-21A-7 / 就绪度报告：三处不规整如实记录；`content.stats_*` 残留字符串不写迁移清（现状注释明确「不划算」）。本 story 是**核对**，发现问题回 1.5 / 1.6 / 2.2 修，不在这里新增权限模型。

### 74 还是 72

基线 72 + 本版新增 2（`place.manage`、`comment.virtual_post`）。若 Epic 3～6 实现中又加了码（如看板付费卡若最终不用 `payment.view` 而新建码），以 after 时点的常量表为准并在报告注明。
