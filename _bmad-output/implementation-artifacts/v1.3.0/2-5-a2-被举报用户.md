# Story 2.5: A2 被举报用户

Status: review

> 自包含 story。与用户沟通用中文。执行纪律见根 `CLAUDE.md`。
> 本 story 是页面重构 + **一处功能级微调**（PRD §5 ③ 第 1 条）：`warn` 增加必填 `reason`，**只写审计不改通知文案**。其余端点路径 / 参数 / 权限零变更。
> 前置：2-3a、2-3b。

## Story

As a 运营，
I want 在双栏工作台里对被举报账号做警告 / 限流 / 封号 / 驳回，警告必须写理由，支持批量，
so that 账号级处置有据可查且清队列更快。

## Acceptance Criteria

**AC1 · 页签、筛选与作用域**
**Given** `/admin/tickets`（`VIEW_AUTH` = SUPER_ADMIN or `content.view_tickets`）
**Then** 页签 = 待处置 ｜ 已处置（各带计数）；筛选 = 举报类型 · 关键词（账号 id / 昵称）`[L1]`
**And** 本页只管 `ACCOUNT_REPORT`（账号级处置）；内容 / 名称 / 头像归 A1，两页队列同源不同类，保持分立 `[L0]`

**AC2 · 左栏队列行**
**Then** 第一行 = 被举报账号昵称 `targetNickname` + 状态点；第二行 = 类型标签 + `reporterCount` 人 / `reportCount` 次 + 优先级分 `score` + 最早举报 `earliestAt`；默认 `score` 降序；**行首勾选框**（批量模式）`[L2]`
**And** 「待处理｜已处理」两态；已处理 = 处置结果徽标（警告 / 封号 / 驳回 / 限流）+ 操作人 + 时间 + 理由 `[L1]`

**AC3 · 右栏四区**
**Then** ① 账号卡：头像 / 昵称 / `targetUserId` / 注册时间 / 历史处置 `disposalCount`（点开处置历史列表）；② 举报明细逐条（举报人 · 类型 · 时间 · 摘要），高频举报人打标（`frequentCount` 口径）；③ 该账号近期内容抽样（快照流，点开大图）；④ 操作区 `[L2]`

**AC4 · 处置区两段式（09-03 修订）**
**Then** 先单选处置方式 chips：警告 / 限流 / 封号 / 驳回；选中后该方式的参数区才内联展开，参数不全按钮禁用；**参数常驻处置卡内不进弹层** `[L2]`
**And** 警告 = **理由必填**（新增 `reason` 参数）；限流 = 粒度 × 期限 chips；封号 = 原因 + 期限 + `data-confirm` 复述昵称；驳回 = 无参数 `[L2]`

**AC5 · 操作表（除 `warn` 增 `reason` 外零变更）**

| 按钮 | 端点 | 参数 | 权限（现状常量） | 确认 | 成功后 |
|---|---|---|---|---|---|
| 警告 | `POST /admin/tickets/warn` | `targetUserId`, `reportId?`, **`reason`（新增，必填）** | `DISPOSE_AUTH` = SUPER_ADMIN or `content.dispose_account` | 无 | 下一条 |
| 封号 | `POST /admin/tickets/suspend` | `targetUserId`, `reportId?` | `SUSPEND_AUTH` = SUPER_ADMIN or (`content.dispose_account` **and** `user.deactivate`) | `data-confirm` 复述昵称 | 下一条 |
| 驳回 | `POST /admin/tickets/dismiss` | `reportId` | `DISPOSE_AUTH` | 无 | 下一条 |
| 批量封号 / 驳回 | `POST /admin/tickets/batch` | `action`, `ticketIds[]` | `content.dispose_account`（封号项服务层再校 `user.deactivate`） | `data-confirm` 复述数量 | 清勾选 |
| 限流曝光 | `POST /admin/throttles` | `scope`, `targetId`/`accountTargetId`, `duration`, `reportId?`, `reason?`, `back?` | `AdminThrottleController.MANAGE`（`content.throttle_manage`） | 粒度 × 期限常驻，未选全禁用 | 停留本条 |
| 解除限流 | `POST /admin/throttles/lift` | `throttleIds[]`, `back?` | 同上 | 无 | 停留本条 |

**Then** 除 `warn` 的 `reason` 外，其余端点路径 / 参数名 / `@PreAuthorize` 与现状逐字一致 `[L0]`

**AC6 · 警告理由只入审计（PRD §5 ③ ①）**
**Given** `AccountDisposalService.warn(targetUserId, reportId, actorAccountId)` 现状无理由
**When** 增加 `reason`（服务层新重载或新参数，Controller 侧 `@RequestParam("reason") @NotBlank`）
**Then** `reason` 写入 `AdminAuditService.record(...)` 的 detail（`ACCOUNT_WARNED`），**summary 不含 PII / 内容原文**；`AccountDisposal` 记录如有备注字段可一并落，无则不加列 `[L1]`
**And** 用户端通知文案 `NotificationType.ACCOUNT_WARNED` 的标题 / 正文**一字不改**，不透出理由、不透出举报人、不透出次数 `[L1]`
**And** 顺序不变：先落 `AccountDisposal` → 收档 + 审计 → 最后 `notificationService.send`（REQUIRES_NEW，类注释明写不可倒序）`[L0]`
**And** `batch` 的批量警告（若 action 含 WARN）同样要求 `reason`；批量条只提供封号 / 驳回两钮，故批量警告入口不渲染（服务层保留兼容）`[L1]`

**AC7 · 批量模式**
**Then** 勾选 ≥2 → 顶部浮出批量条（数量 + 批量封号 / 批量驳回 + 取消）；无 `SUSPEND_AUTH` 者批量条不显示封号钮；批量 `data-confirm` 复述数量；完成后清勾选、计数刷新 `[L2]`
**And** 勾选行时右栏折叠为摘要，单选恢复完整详情 `[L2]`

**AC8 · 权限态与边界**
**Then** 缺 `user.deactivate` → 封号 chip 禁用 + 悬浮所缺权限中文标签；被举报账号已注销（`targetDeleted`）→ 只可驳回 `[L1]`
**And** 处置走 htmx：200 + 右栏 fragment（`data-next-id`）+ oob 左栏行与计数 + `HX-Trigger admin:badge-refresh`；422 行内 err；非 htmx 维持 PRG；**不做键盘 ↑/↓**（D-14）`[L1]`

**AC9 · `tickets/detail` 退役**
**Then** `GET /admin/tickets/detail`（`content.view_tickets`）并入右栏 fragment `GET /admin/tickets/{id}/detail` 后删除原路由；全库无 `th:href` 指向它 `[L1]`

**AC10 · 测试与三语**
**Then** MockMvc 四条 + `warn` 缺 `reason` → 422 + `warn` 审计 detail 含 reason 且通知文案不变（L1）；既有 `UnifiedTicketController` / `AccountDisposalService` 测试全绿 `[L1]`
**And** 新 key `admin.v130.tickets.*`（含 `warn.reasonRequired`），三包同批；ID 语言无截断 `[L2]`

## Dev Notes

### 🔴 唯一的功能级改动：`warn` 的 `reason`，且只进审计

`AccountDisposalService.warn` 类注释写明三条铁律：① 先落记录再收档再通知，顺序不能反；② summary 严禁 PII / 内容原文 / 令牌；③ 通知里不说是谁举报、因哪条内容、第几次。`reason` 是运营内部追溯用，**只能进审计 detail**，绝不能拼进 `notificationService.send` 的正文。

### 🔴 `SUSPEND_AUTH` 是 AND 关系

`content.dispose_account and user.deactivate`（`UnifiedTicketController:56`），注释明写「不能因为他能处理工单就顺带把停用权给了」。模板用 `sec:authorize` 表达式与该常量**逐字一致**（`AdminThrottleController` 注释里的 AC5 同理）；缺权限时 chip 禁用并注明所缺权限中文标签，不隐藏。
