## Story

As a 运营负责人 / 财务，
I want 三张经营报表统一为「图表卡在上、维度切换、明细表在下」的只读报表形态，
so that 看数口径和首页看板一致，不会误以为能在报表页改东西。

## Acceptance Criteria

**AC1 · C2 复购引擎效果**
**Given** `/admin/shop/repurchase-dashboard`（权限 `config.view` **或** `order.view`，与其余两页不同码——如实按现状）
**Then** 区块字段**现状原样**：触发（按类型 / 总数 / 转化 / 关闭 / 转化率 / FR-109 覆盖率）· 归因（补货卡 / 档案推荐 / 全部订单行 + 底账核对表）· 30 日复购率 · 粮量预估准确度（样本 / 平均偏差 / 区间）；数字卡图表化（Chart.js 只在有时间序列的区块使用，其余数字卡）；顶栏只读标识 `[L2]`

**AC2 · C3 销售与毛利**
**Given** `/admin/shop/margin`（`shop.finance_view`）
**Then** 核心卡（销售额 / 成本 / 毛利 / 毛利率 / 退款商品额 / 净额 / 售后成本）· 运费与手续费卡 · 售后成本按退货类型卡 · 按 SKU 下钻明细表；期间筛选 htmx 局部替换；只读标识 `[L2]`
**And** 进货价 / 成本相关数字**只对 `shop.finance_view` 可见**（本页整体门控，不再细分）`[L1]`

**AC3 · C4 库存周转**
**Given** `/admin/shop/inventory-turnover`（`shop.finance_view`）
**Then** 统计窗口（天，默认 30）筛选 + 售罄 SKU 计数卡 + 各 SKU 表（库存 / 库存金额 / 窗口销量 / 最近售出 / **建议动作**列保留）；只读标识 `[L2]`

**AC4 · 三页共性**
**Then** 无 form、无写端点、无导出（现状无，不新增）；三页拆为三帧独立路由（UI 稿 09-04 拆帧），不得合成一页多分区 `[L0]`
**And** 三个 GET 路径与权限不变；`HX-Request` 分支返卡区 fragment `[L1]`

> 报表页的数**全部是聚合出来的** —— 没有一个字段是可以就地改的。一旦这三页里长出一个写入口
> （哪怕只是「标记已核对」这种看起来无害的），运营就会把整页当成可以在这里改数的地方，

🔴 **这条守门第一版是假的，注入验证当场抓出来了**：断言写的是 `doesNotContain("@PostMapping")`，
而我注入的写端点用的是全限定注解 `@org.springframework.web.bind.annotation.PostMapping(...)` ——
**守门照常绿**。改成钉 `PostMapping`（不带 `@`）+ `RequestMethod.POST` 之后才真正报红。
带 `@` 的写法对全限定注解完全无感，这一点已写进测试注释。
