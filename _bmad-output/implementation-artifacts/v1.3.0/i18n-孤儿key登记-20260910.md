# 三语孤儿 key 登记（V1.3.0 Story 11.3 · AC4）

> 生成日期 2026-09-10 · 共 **164** 个 key（以 `messages_zh_CN.properties` 为基准，四包同键同在）。
>
> **判据**：key 在 `src/main` 的 java / html / js / sql 里**一次都没出现**，且不属于任何动态拼接前缀
> （`#{'admin.qual.' + ${x}}` 这类，脚本会把前缀下的 key 全部排除，避免误杀）。

## 处置：**保留，不删**

按 AC4：这些 key 允许留着，但要登记在案。**不删的理由不是懒**——

1. 判据是「静态扫不到引用」，而**动态拼接**永远可能漏（Java 里 `"admin." + module + ".title"` 这种写法扫不出来）；
2. 四包同删才安全，漏删一包就破坏 `check-i18n-keys.sh` 的集合相等；
3. 删 key 换不来任何运行期收益（properties 全量加载，几百个键的体量可以忽略），却换来一次真删错就上线报 `NoSuchMessage` 的风险。

**清理的时机是 Epic 10 落地、全站页面定型之后**，届时按本表逐组核一遍再删。

🔴 **不在本表里的 key 一律不许当孤儿删**，尤其 `admin.qualpage.*` / `admin.ratings.col.*` / `admin.vets.*`：
它们的整页虽然退役了，但**文案被抽屉页签原样复用**（Story 9.1a / 9.1b），删了抽屉就空一片。
