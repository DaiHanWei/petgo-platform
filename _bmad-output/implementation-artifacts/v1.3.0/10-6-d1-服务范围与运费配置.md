**新增 L0 护栏：`AdminNoNestedFormTest`（2 条，做过注入验证）**

这条守门不只服务本 story —— 它扫**全部 148 份 admin 模板**：

> HTML 解析器遇到嵌套 `<form>` 时**直接丢掉内层**，不报错、不警告。页面渲染一切正常：
> 按钮都在、输入框都在、样式也对。真按下去时，内层那些输入连同按钮一起属于**外层**那个 form，
> 提交到外层的 action、带上外层的全部字段。在本项目里这不是理论风险：模板 D 的 `configCard`
> **自身就是 `<form>`**，而「一卡多行、每行一个写端点」的形状一不留神就会把行级 form 塞进卡里。

第二条断言把「D1 区域卡刻意不套 `configCard`」这个决定钉住 —— 否则下一个人看到「卡②卡③都套了」
会顺手把卡①也套上，而页面照常渲染。**注入验证**：把启停 form 挪进 upsert form 内部，守门立刻报
`shop-shipping.html（嵌套深度 2）`。

**自查修复 2 处**

| # | 级别 | 问题 | 修复 |
|---|---|---|---|
| 1 | P2 | 区域行只有「停用 / 启用」按钮，**没有状态显示**。按钮上的字是**动作**不是状态 —— 「停用」既可读成「当前已停用」也可读成「点我停用」，而这两种理解会导出完全相反的操作（原先只给只读账号显示了状态徽标） | 状态徽标对**所有人**都渲染 |
| 2 | P2 | 三张卡被包在一层 `div.cfg-grid` 里，而 `cfg-grid` 这个 class **在 CSS 里不存在**；卡间距靠 `admin.css` 的 `.cfg-card + .cfg-card` 相邻选择器，夹一层 div 会让它整个失效（卡贴在一起，且不报错） | 去掉包装层，三张卡直接是兄弟；另给区域卡 `max-width: 980px`（5 列挤在 `.cfg-card` 默认的 720px 里每个输入只剩约 100px） |
