# Story 2.4: A1 统一复核工作台

Status: review

> 自包含 story。与用户沟通用中文。执行纪律见根 `CLAUDE.md`（后端→前端→联调、AC 标 L0/L1/L2、`mvn -B clean package`）。
> 本 story 是**纯页面重构**：不新增、不删除、不改任何写端点的路径 / 参数 / 权限；只把 `manual-review.html` 从「混排 + 类型筛选 + 独立 reports 页」改成模板 A 双栏工作台，并让 `reports.html` 页面路由退役。
> 前置：2-3a（`HxRequest` / 422·403 fragment / `HX-Trigger admin:badge-refresh` / `AdminExportWriter`）与 2-3b（`tpl-a-workbench` 壳、`admin-workbench.js`）。

## Story

As a 运营，
I want 内容送审、内容举报、名称审核、头像审核在一个双栏工作台里按页签清队列，处置完自动到下一条，
so that 早巡不用在四个页面间来回点。

## Acceptance Criteria

**AC1 · 页签与筛选（模板 A 顶部两行）**
**Given** `/admin/manual-review`（`QUEUE_AUTH` 不变）
**When** 打开
**Then** 页签行 = 内容送审（`CONTENT_SUBMISSION`）｜ 内容举报（`CONTENT_REPORT`）｜ 名称审核（`ACCOUNT_IDENTITY` 的 `NICKNAME` + `PET_NAME` 两 subType）｜ 头像审核（`USER_AVATAR` + `PET_AVATAR`），各带计数 `[L1]`
**And** 筛选行 = 违规类别（七选）· 优先级（P0/P1/P2）· 关键词（账号 id / 昵称）；名称 / 头像页签追加 subType 二选（用户 / 宠物）；下拉 `data-autosubmit`，文本搜索配显式「查询」钮 `[L2]`
**And** 现状的「type 筛选下拉 + 混排」删除，由页签取代；`?type=` 查询参数继续被接受（旧链接兼容，映射到对应页签）`[L1]`

**AC2 · 左栏队列行**
**Then** 行高 ~56px 两行式：第一行 = 对象标识（送审 / 举报 = `preview` 摘要；名称 = 待审名称文本；头像 = `targetNickname`）+ 右对齐状态色点；第二行 = 违规类别标签 + 优先级分 `score` + `earliestAt` 相对时间 `[L2]`
**And** `overdue=true`（送审挂起 >24h）整行红字 + 红点 + 挂起时长标签（现有规则原样保留）`[L1]`
**And** 默认排序：优先级分降序、同分按 `earliestAt` 升序；每页 20（`PAGE_SIZE` 沿用），滚动到底 htmx 加载下一页 `[L1]`
**And** 左栏顶部「待处理｜已处理」两态页签；已处理 = 只读回看（处置结果徽标 + 操作人 + 时间 + 理由，可筛结果 / 时间 / 关键词）`[L1]`

**AC3 · 右栏三卡（按页签渲染）**
**Then** ① 对象快照卡：送审 / 举报 = 帖子全文 + 全部图片（点开大图）+ 作者行（头像 / 昵称 / `targetUserId`，`targetDeleted` 置灰标注）；名称 = 新旧名称对照（大字号待审名）；头像 = 待审头像大图 + 当前生效头像对照 `[L2]`
**And** ② 上下文卡：举报 = 该帖全部举报列表（`reporterCount` / `reportCount` / `frequentCount` + 各条类型与时间）；送审 = 机审命中原因；名称 / 头像 = `disposalCount` 历史处置次数 `[L2]`
**And** ③ 操作区：按下表渲染；**选择参数类操作常驻操作区，未选全按钮禁用，不做「点按钮→展开面板」二级步** `[L2]`

**AC4 · 操作表（端点 / 权限 / 参数零变更）**

**AC5 · 处置动线 = htmx 局部更新**
**When** 右栏任一操作提交（带 `HX-Request`）
**Then** 成功 200：右栏 fragment（含 `data-next-id`）+ `hx-swap-oob` 带出左栏该行（转终态压暗）与页签计数 + 响应头 `HX-Trigger: {"admin:badge-refresh":{}}`；`admin-workbench.js` 读 `data-next-id` 自动请求下一条；toast 2s `[L1]`

**And** 非 htmx 请求（无 `HX-Request`）维持现状 PRG（同一 Controller 方法两条路径共用 Model）`[L1]`
**And** **不做键盘 ↑/↓ 切换**（D-14）`[L0]`

**AC7 · `reports` 页面退役**
**Then** `GET /admin/reports`（`AdminWebController:131`）与 `reports.html` 删除；`POST /admin/reports/{id}/takedown`、`/dismiss`、`/post/{postId}/dismiss-all`、`/batch` 四个写端点**保留**（页签调用；`batch` 本页不用但不删）`[L1]`
**And** 侧导航无「举报队列」项；`AdminPageCatalog` 中 `reports` 页面维度标记退役、其权限码 `content.view_reports` 仍在矩阵 `[L1]`

**AC8 · 边界与权限态**
**Then** 被审对象已被作者删除 → 快照卡「内容已删除」占位，下架钮禁用，驳回类可清队列；`targetDeleted` → 名称 / 头像单据只读作废态 `[L1]`
**And** 有 `QUEUE_AUTH` 无 `DECIDE_AUTH`（理论上 `content.manual_review` 已含在 DECIDE 内，此处覆盖仅 `content.view_*` 的组合）→ 操作区按钮禁用 + 注明所缺权限的中文标签 `[L2]`
**And** 某页签清空 → 空态插画 +「队列已清空 🎉」+「其他队列还有 N 条」去向链接 `[L2]`
**And** 页签结构可扩展：`TicketType` 新值（Story 5.4 的 `PLACE_REPORT`）加一行即出现新页签 `[L0]`

## Dev Notes

### 🔴 本 story 的红线：写端点一个字都不改

8 个写端点分散在 4 个 Controller（`ManualReviewAdminController`、`AdminWebController` 的 `reports/**`、`NameModerationAdminController`、`NameAvatarReviewAdminController`）。重构只允许：① 在方法内按 `HxRequest` 分叉返回 fragment；② 新增只读 GET fragment 端点。任何 `@PostMapping` 路径 / `@RequestParam` 名 / `@PreAuthorize` 表达式的改动都会让 Epic 11 的清单 diff 变红。

### 「拒绝原因常驻」的实现细节

现状 `reject` 端点参数 `category`（required=false）+ `note`。UI 拍板（09-01）拒绝原因七选 + 备注**常驻**操作区，**未选原因时拒绝钮禁用**——前端 `required` + `disabled` 联动即可，后端保持 `required=false` 不动（避免改端点契约）；服务端若收到空 category 仍按现状处理。

### fragment 响应形状（AD-9）

- 成功：`review-actions` 主片段（根元素 `data-next-id="<下一条 sourceId 或空>"`）+ `<tr id="review-row-<id>" hx-swap-oob="true">`（终态压暗）+ `<span id="review-tab-count-<tab>" hx-swap-oob="true">`；`HX-Trigger: {"admin:badge-refresh":{}}`。
- 422 / 403 由 2-3a 的 `AdminBusinessExceptionAdvice` 统一返回，本 story 只保证异常带正确 `errKey`。
- htmx 1.9.12：4xx 渲染靠 `admin-core.js` 的 `htmx:beforeSwap` 放行（2-3a 已做），本 story 不加扩展。

### 已处理两态的数据来源
