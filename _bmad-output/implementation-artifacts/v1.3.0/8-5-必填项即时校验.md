## Story

As a 运营，
I want 表单填错的地方当场就提示我，
so that 我不用填完一整屏、点了保存、再被一条 flash 打回来从头找哪里错了。

## Dev Notes

### 🔴 服务端为什么不能动

这条 AC 存在的原因很具体：**「加即时校验」这件事最自然的实现路径，就是顺手去改服务端。**

比如实施时很容易想：「前端要提示品牌最长多少字，可服务端没这条规则啊，那我在 `validate` 里补一条 `brandTooLong` 吧。」——这一改就越界了：

- 它**收紧了**一条规则。存量数据里可能就有超长品牌名，下次运营编辑那个商品会**保存不了**，而那个商品本来好好的。
- 它改变了 API 行为，却挂在一个标题是「必填项即时校验」的 story 上，Review 的人不会往那看。
- 本仓在别处已经出过同类事故（改 CHECK 约束时照着过期列表抄，丢了一批值，三次）。**「顺手改一下判定」是本项目的高频事故模式。**

所以本 story 的边界画得很死：**服务端说什么是错，前端只负责早一点说出来。**
前端提示只能是服务端规则的**子集或等集**（AC1 第四条）：漏提示 → 服务端仍拦住，可接受；多提示 → 运营被前端拦住但服务端本来放行，这是新造的 bug。

如果实施中真的发现某条规则前端没法在不改服务端的情况下表达，**停下来记在 Completion Notes 里，不要自行扩范围**。

### 🔴 敏感词为什么等 OD-4

SHOP-FR-20 的原文是「必填即时校验**与敏感词**」，两件事被写在一条需求里，但它们的性质完全不同：

- 即时校验针对的是**手滑**：运营知道规则，只是填错了。反馈越早越好，判定归服务端。
- 敏感词针对的是**内容风险**：谁在什么位置说了什么。

而**后台是可信角色**：进得来的人有登录态、有权限位（`shop.product_edit`）、每一次写操作都进 `AdminAuditService` 的哈希链。这与 App 端用户生成内容（匿名、海量、不可信）的审核口径不是一回事 —— 把用户侧那套审核直接套到后台商品文案上，得到的是误杀运营正常文案 + 一条没人看的告警。

现状核实：`admin/shop/` 下**零内容审核调用**（对应 OD-4 的「做不做还没定」）。所以本 story 把它整块划出去，AC7 用一条可 grep 的硬 AC 钉住，防止实施者「反正都在改这个表单了顺手加一下」。

### epics 说的「8 处」是错的 —— 但不影响结论

Context 现状一已列全：**12 个 `AppException.validation` 抛点 / 16 条规则**（其中一条属 🔒 进货价权限路径）。
「8」可能是数了 `validate(ShopProductForm)` 里的显式 `throw`（5 条）加上某个子集。**无论 8 还是 16，本 story 的结论都一样：服务端已经够用，缺的全在前端。** 表格里的行号才是实施依据。

### 为什么 AC2 要留两个分支

正常情况下，story 应该只给一条路。这里给两条，是因为**前置（Epic 10）还没落地，而它的产出决定了唯一答案**：

- 如果 Epic 10 老老实实按 AD-9 把商品表单落成模板 D + PRG（大概率），那么把 htmx 塞进这一页就是在**违反刚建立的横切约定**，而且只为了做错误提示 —— 收益远不抵一致性代价。
- 如果 Epic 10 出于别的原因把它改成了 htmx 局部提交，那 422 行内错就是现成通道，照 AD-9 走即可。

**判断依据是 Epic 10 实际交付的代码，不是本文档，也不是 epics 的字面。** 选完记进 Completion Notes —— 这是 epics（UX-S1）与 admin delta（AD-9）冲突的留痕点，以后有人问「为什么 8-5 没用 htmx」时要能答得出来。

### 回填链路：SKU 表单是缺口

AC10 里「其它已填内容不丢失」看起来是个 UX 要求，实际是个**代码事实问题**：

- 商品主体表单 `:40-218` 用 `th:object="${form}"` + `th:field="*{...}"`，控制器把 `form` 塞回 Model 就能自动回填。
- **SKU 表单 `:250-289` 完全不同**：`<input type="hidden" name="id"/>`:254、`name="specName"`:257、`name="price"`:262…… 全是裸 `name`，**没有 `th:field`、没有 `th:value`**。也就是说今天 SKU 保存失败后，运营填的规格名和价格**是真的会丢**。

这是本 story 最有实感的一处修复点，也是最容易被漏掉的一处（因为「表单回填」听起来像框架自带）。T3 把它单列成一条。
