# Story 7.2: B2 评论巡查页签套模板 B

Status: ready-for-dev

> 自包含 story。与用户沟通用中文。纪律见根 `CLAUDE.md`。
> 依赖 2.3a / 2.3b。**与 Story 4.1（AB-20A「帖子评论分布」页签二）共用 `comments.html` 的页顶页签条**——协作边界见 Dev Notes。端点零变更。

## Story

As a 运营，
I want 评论巡查列表有摘要条、抽屉看评论全文与所属帖子，
so that 与其他列表页一致。

## Acceptance Criteria

**AC1 · 页签条（与 4.1 共享）**
**Given** `/admin/comments`
**Then** 页顶常驻两页签「评论巡查」｜「帖子评论分布」，htmx 局部切换（`hx-get` 页签内容区 `#comments-tab`）；本 story 只实现页签一，页签二占位指向 `GET /admin/comments/distribution`（4.1 实现，未实现前返回「即将上线」fragment）`[L2]`
**And** 页签条 fragment 抽为 `fragments/comments-tabs.html`，4.1 复用不重写 `[L0]`

**AC2 · 筛选与摘要条**
**Then** 筛选：状态（全部 / VISIBLE / UNDER_REVIEW / TAKEN_DOWN / REJECTED / 已删除）· 帖子 ID · 关键词（显式查询钮）；现状 `service.recent()` 无筛选 → 新增分页查询方法（GET 查询增强，非写端点）`[L1]`
**And** 摘要条：总评论数 · 今日新增（WIB）· 已下架，随筛选联动，单条 `COUNT FILTER` `[L1]`

**AC3 · 表格**
**Then** 列 = ID ｜ 所属帖子（摘要 + 带图缩略；点击跳 B1 抽屉 `/admin/content?open=<postId>`）｜ 作者 ｜ 内容 ｜ 状态（色点 + 徽标）｜ 时间（WIB）；默认时间倒序，每页 20 `[L2]`

**AC4 · 详情抽屉**
**When** 点行 → `GET /admin/comments/{id}/drawer`
**Then** 评论全文 + 所属帖子摘要卡（首图预览 + 正文摘要 + 作者，可跳 B1 抽屉）+ 作者卡（昵称 / id / 注销置灰）+ 操作条 `[L2]`

**AC5 · 操作（端点零变更）**
| 按钮 | 端点 | 权限 | 确认 |
|---|---|---|---|
| 下架 | `POST /admin/comments/{id}/takedown` | `content.proactive_takedown` | data-confirm |
| 恢复 | `POST /admin/comments/{id}/restore` | `content.restore` | 无 |
**Then** 按钮显示条件沿现状：仅 `VISIBLE` 可下架；`TAKEN_DOWN` / `REJECTED` 可恢复；用户自删（`deleted`）只读展示删除态 `[L1]`
**And** htmx：200 + 抽屉 fragment + oob 行；422 行内 err；权限不足禁用注明 `[L1]`

**AC6 · 三语与回归**
**Then** 新 key `admin.v130.comments.*` 三包；`AdminCommentModerationIntegrationTest` 全绿；新增 MockMvc 四条 `[L0/L1]`

## Dev Notes

### 现状与改动边界

| 文件 | 现状 | 本 story | 保留 |
|---|---|---|---|
| `admin/comment/web/AdminCommentModerationController.java` | `GET /admin/comments`（`content.proactive_takedown`），`service.recent()` 无筛选无分页 | + 筛选/分页参数 + drawer 端点 | 权限表达式 |
| `admin/moderation/web/AdminCommentManageController.java` | `POST {id}/takedown`（`content.proactive_takedown`）、`POST {id}/restore`（`content.restore`） | + htmx 分支 | 路径参数 |
| `templates/admin/comments.html` | 单表：ID / 帖子 / 作者 / 内容 / 状态 / 时间 / 操作（行内两个表单） | 套模板 B + 页签条 + 抽屉 | 按钮显示条件 |

### 🔴 与 Story 4.1 的协作边界
- 本 story 拥有：页签条 fragment、页签一全部、`comments.html` 壳。
- 4.1 拥有：`GET /admin/comments/distribution*`、`fragments/comments-distribution.html`、「去评论」抽屉、`POST /admin/comments/virtual`。
- 4.1 **不得**改页签条以外的页签一内容；本 story **不得**实现分布查询。两者合并冲突点只有 `comments.html` 顶部的页签条 include 一行。
- 评论管理没有独立查看权限码（AB-21A 现状不规整项），本页继续用 `content.proactive_takedown`，不新增码。

### 🔴 「已删除」语义
现状按钮条件：`!c.deleted and moderationStatus=='VISIBLE'` 才能下架；`TAKEN_DOWN|REJECTED` 才能恢复。用户自删（`deleted_at` 非空）任何操作都不给，抽屉只显示删除态。不要把「已下架」与「已删除」混成一个状态。

### 端点零变更清单
`POST /admin/comments/{id}/takedown` · `POST /admin/comments/{id}/restore`。新增 GET：`/admin/comments/{id}/drawer`（查询参数增强不算新写端点）。

### 测试标准
`AdminCommentModerationIntegrationTest` 范式；筛选组合 × 分页；抽屉 fragment；四条 MockMvc。

### Project Structure Notes
改动落 `admin/comment/**`、`admin/moderation/web/AdminCommentManageController.java`、`templates/admin/comments.html`、`fragments/comments-tabs.html`、`fragments/drawer-comment.html`。
