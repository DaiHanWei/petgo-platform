# Story 9.1a: B20 兽医账号——列表、资料 / 账号页签、开户

Status: ready-for-dev

> 自包含 story，可本地或云端 L0 执行。与用户沟通用中文。执行纪律见根 `CLAUDE.md`（后端→前端→联调、AC 标 L0/L1/L2、`mvn -B clean package`）。
> 本 story **纯后台页面重构 + 两处路由退役**，零新迁移、零 App 端改动、**写端点零变更**。依赖 Story 2.3a（htmx 响应约定 / `HxRequest` / `AdminBusinessExceptionAdvice`）与 2.3b（`tpl-b-list` 壳、`admin-drawer.js`）已合入。

## Story

As a 运营，
I want 兽医账号页变成「列表 + 右侧抽屉」，在线状态并进列表和抽屉资料页签，开户和改密码封禁都在同一屏完成，
so that 管兽医不用在四个页面之间跳。

## Acceptance Criteria

**AC1 · 列表套模板 B**
**Given** `GET /admin/vets`（`vet.view`）
**When** 打开
**Then** 页面用 `fragments/tpl-b-list.html` 壳：筛选栏（账号状态 / 资质状态 / 在线态 三个下拉 `data-autosubmit` + 关键词 `q` 配显式「查询」钮）→ 摘要条 → 表格 → 抽屉容器 `[L1]`
**And** 摘要条四数字：兽医总数 · 在线数 · 资质待审 · 已封禁，随筛选联动（单条聚合查询）`[L1]`
**And** 表格列：ID ｜ 昵称 ｜ 账号 ｜ 状态 ｜ 资质态 ｜ 在线 ｜ **最后在线（WIB）** ｜ 评分 ｜ 创建日期；每页 20；行点击开抽屉 `[L1]`
**And** 「＋开户」按钮在筛选栏最右，`sec:authorize` 需 `vet.create`（UI 稿 6-1）`[L2]`

**AC2 · 抽屉四页签骨架 + 资料页签**
**Given** 点任一行
**When** `GET /admin/vets/{id}/drawer`（`vet.view`）
**Then** 返回抽屉 fragment，页签 = 资料 ｜ 资质 ｜ 评分 ｜ 账号；资质与评分页签本 story 只放占位（「由 9.1b 填充」），不报错 `[L1]`
**And** 资料页签 = 昵称 / 登录邮箱 / 联系手机 / 头像（上传钮）+ **在线态与最后在线时间**（原 `vet-online` 数据）+ 保存钮；提交 `POST /admin/vets/{id}`、`POST /admin/vets/{id}/avatar`（`vet.edit` 或 `vet.create`），**参数名与现状一致** `[L1]`
**And** htmx 提交：成功 200 返抽屉 fragment + `hx-swap-oob` 刷新该行；失败 422 行内 err；权限不足 403 禁用态 `[L1]`

**AC3 · 账号页签**
**When** 切到「账号」
**Then** 重置密码（新密码 ≥8 位，`POST /admin/vets/{id}/password`，`vet.reset_password`，data-confirm；成功后新密码**仅本次展示**明文 + 复制钮，关闭按钮文案强调「已记录」——UI 稿 6-4/6-7）`[L2]`
**And** 封禁 / 解封（`POST /admin/vets/{id}/status`，`vet.ban`，data-confirm 复述昵称；解封为封禁态下同位置按钮态切换；提示「封禁不影响历史订单」）`[L2]`

**AC4 · 开户**
**When** 点「＋开户」
**Then** 沿用现状模态框（UI 稿 6-3 明确照抄代码实现，不改抽屉）：显示名 / 登录邮箱 / 初始密码 / 联系手机（选填），必填不全禁用提交；`POST /admin/vets`（`vet.create`），`CreateVetForm` 校验不变 `[L1]`
**And** 创建成功后展示初始密码一次（常驻醒目提示 + 复制钮），关闭即不可再查（UI 稿 6-4）`[L2]`

**AC5 · 在线状态并入 + 两处退役（D-11 / D-23）**
**Then** 删除 `templates/admin/vet-online.html`、`vet-edit.html`；删除 `GET /admin/vets/online`、`GET /admin/vets/{id}/edit` 两个路由方法（`AdminWebController.vetOnline` / `editVetForm`）；旧地址 404，**不做跳转** `[L1]`
**And** `layout.html`（或 Story 2.2 后的 `fragments/nav.html`）「兽医与问诊」组去掉「在线状态」项；`admin.nav.online` key 可保留不用 `[L1]`
**And** `AdminVetService.onlineSnapshot(...)` 保留，改为给列表「最后在线」列与资料页签取数；`editForm(...)` 改为给抽屉资料页签取数 `[L0]`

**AC6 · 写端点零变更**
**Then** `POST /admin/vets`、`/admin/vets/{id}`、`/{id}/avatar`、`/{id}/password`、`/{id}/status` 路径 / 参数 / `@PreAuthorize` 与基线一致；写操作清单 diff 中本 story 无写端点增删 `[L0]`

**AC7 · 三语 + 测试 + 回归**
**Then** 新增 key 前缀 `admin.v130.vets.*`，zh/en/id 三包同批；切 ID 无截断 `[L0/L2]`
**And** MockMvc 四条（整页 200 / HX fragment / 422 / 403）+ 抽屉 fragment 测试；既有 `AdminVetCreateIntegrationTest` / `AdminVetEditIntegrationTest` / `AdminVetBanIntegrationTest` 全绿（改表单来源为抽屉，断言不变）`[L1]`

### 🔴 UI 稿把开户定成「模态框」而不是抽屉

UI 稿 6-3 caption 明写「这里用模态框而不是抽屉，是照抄代码原实现（vets.html 弹窗，校验失败/成功都重渲染本页并重开该弹窗）」。**不要**为了统一把开户搬进抽屉；只套视觉。

### 🔴 「最后在线」列数据来源

现状列表没有这一列，`vet-online.html` 用 `AdminVetService.onlineSnapshot(now)` 单独查。并入后要在 `list()` 里一次性把快照 join 进来（Map<vetId, lastSeen>），**禁止逐行查 Redis / 表**。在线态的口径不变：兽医手动选的持久态，无 TTL 兜底（memory：vet-presence-explicit-only），不要顺手加心跳判断。

### 🔴 密码明文只此一屏

`create` 与 `resetPassword` 的明文只在响应渲染一次；现状代码已保证不进审计 detail 与日志（UI 稿 6-4「后端不存明文、这一屏是唯一获取窗口」）。抽屉化后同样只放一次性 model 属性，不要放 session flash 之外的任何持久位置。

### 页面归组与顺序（AD-12 / D-8）

本页属「兽医与问诊」泳道（UI 稿泳道 6，4 帧 ≈ 3 个路由页面），不受电商线合入门控；可在 Epic 2 完成后立即开工。

### 与 9.1b 的边界

- 本 story：列表 + 抽屉壳 + 资料 / 账号页签 + 开户 + 退役 `vet-edit` / `vet-online`。
- 9.1b：资质页签、评分页签、退役 `vet-qualification` / `vet-ratings` / `ratings` 与导航「评分查看」。
- 抽屉壳的页签容器 id 前缀统一 `#vets-drawer-*`（AD-11 命名规则），9.1b 只填内容不改壳。

### 测试标准

- 沿用 `src/test/java/com/tailtopia/admin/vet/AdminVet{Create,Edit,Ban}IntegrationTest`（`ApiIntegrationTest` 真库）；表单端点不变故断言基本不动，只把 GET edit 的用例换成 GET drawer。
