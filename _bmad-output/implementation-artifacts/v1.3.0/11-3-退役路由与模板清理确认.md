# Story 11.3: 退役路由与模板清理确认

Status: ready-for-dev

> 自包含 story，L0 为主（grep + MockMvc 404），可云端执行。与用户沟通用中文。
> D-23：旧地址**不做跳转兜底**，直接 404；本 story 只确认清理彻底，不新增功能。

## Story

As a 工程负责人，
I want 所有并入抽屉 / 页签的独立页面，其路由、模板、模板内链接、导航项、i18n 孤儿 key 都被清干净，
so that 重构后不会残留半死不活的页面和指向 404 的链接。

**AC5 · 测试类同步**

## Dev Notes

### 🔴 数量对不上是正常的，以本表为准

epics 各处写「8 个独立详情页」是 B 类页并入抽屉的口径；加上 9.1a/9.1b 的兽医四页 + 评分总览、2.4 的 `reports`、7.5 的 `content-schedules`、2.5 的 `tickets/detail`，**实际退役 17 条 GET 路由 / 16 个模板**。11.1 的 GET 白名单与本表必须一致。

### 🔴 `/admin/reports` 的 POST 端点保留

2.4 只退役页面路由，`reports/{id}/takedown`、`reports/{id}/dismiss`、`reports/post/{id}/dismiss-all` 由 A1 内容举报页签继续调用（PRD §5 ①「端点保留」）。`tickets.html` 354/357 行、`manual-review.html` 154/160 行现状引用这些 POST，重构后仍会引用——grep 时只查 GET 形态。

### 🔴 不做跳转兜底

D-23 拍板：运营收藏链接自行更新。**不要**顺手加 `@GetMapping` 302 到列表页；那会让 11.1 的 GET diff 多出白名单外条目。
