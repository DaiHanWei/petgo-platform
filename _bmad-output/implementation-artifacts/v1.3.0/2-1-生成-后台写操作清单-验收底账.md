# Story 2.1: 生成《后台写操作清单》验收底账（D-27）

Status: ready-for-dev

> 自包含 story，可本地或云端 L0 执行。与用户沟通用中文。执行纪律见根 `CLAUDE.md`。
> 本 story **只产出一个 shell 脚本 + 一份 markdown 清单**，不改任何 Java / 模板 / 迁移。它必须在 Epic 2～10 任何页面重构之前完成，因为它就是「重构不丢一项」的分母。

## Story

As a 产品与 QA，
I want 一份从当前代码自动生成的后台全部写操作清单，
so that 重构前后逐操作核对「一个不丢」有唯一分母。

## Acceptance Criteria

**AC1 · 脚本产出写操作表**
**Given** `dev_1.3.0`（本分支基线 `4301227a`）当前代码
**When** 运行 `bash scripts/ci/list-admin-write-ops.sh`
**Then** 产出 `_bmad-output/implementation-artifacts/v1.3.0/后台写操作清单-<yyyyMMdd>.md`，第一张表每行一个写端点：HTTP 方法 / 路径 / Controller 类#方法 / `@PreAuthorize` 表达式（原文）/ 所属页面组（按 §Dev Notes 的路径前缀→泳道映射，`AdminPageCatalog` 落地后改读它） `[L0]`
**And** 行数与 `grep -rhoE "@(Post|Put|Delete)Mapping\(" petgo-backend/src/main/java/com/tailtopia/admin | wc -l` 一致（2026-09-09 为 **128**）；脚本末尾打印该计数并与自身行数比对，不等则 exit 1 `[L0]`

**AC2 · GET 页面路由表与退役标记**
**Then** 第二张表列出 `admin/**` 全部 `@GetMapping`（当前 79 个映射；去掉带路径参数 / `export` / `.csv|.xlsx` 后约 52 个页面路由），并对下列路由标 `⛔ 本版退役`：`/admin/content/{postId}`、`/admin/users/{userId}`、`/admin/consult-orders/{orderToken}`、`/admin/ai-orders/{orderToken}`、`/admin/vets/{id}`（编辑页）、`/admin/vets/{id}/qualification`、`/admin/vets/online`、`/admin/ratings`、`/admin/reports`、`/admin/content-schedules`、`/admin/tickets/detail`、`/admin/anomalies/{id}`、`/admin/refunds/{refundToken}`、`/admin/support-tickets/{ticketToken}`、`/admin/shop/orders/{token}` `[L0]`
**And** 表头注明「页面分母以本表 GET 路由为准，UI 稿 49 帧是形态比对口径」（D-8） `[L0]`

**AC3 · 可重复、可 diff**
**Then** 脚本幂等：同一提交重复运行输出逐字节一致（表按 路径+方法 排序，不含时间戳以外的易变内容）；Epic 11 Story 11.1 对重构后代码再跑一次做 `diff` `[L0]`
**And** 脚本风格与 `scripts/ci/check-flyway-versions.sh` 一致（`set -uo pipefail`、`::error::` 输出、`MIG_DIR` 式常量）；可选参数 `--out <path>` 覆盖输出位置 `[L0]`

**AC4 · 不动业务代码**
**Then** 本 story 的 diff 只含 `scripts/ci/list-admin-write-ops.sh` 与一份清单 md；`mvn -B clean package` 不受影响 `[L0]`

## Dev Notes

### 🎯 这份清单是 AB-19A「不动任何功能」的唯一机器证据

PRD AB-19A 的核心验收是「重整前后逐操作核对不丢一项」。原来依赖的 `后台功能全量清单-20260901.md` 不在仓库（D-27 决定不再找回），所以**从代码生成、随代码演进**。Epic 11 Story 11.1 用同一脚本对重构后代码再生成一次，两份 diff 里允许出现的只有：本版 PRD 定义的新增端点（AB-15A～22A + `reply_to_comment_id` 预留）和明示退役的路由。

### 🔴 现状计数（2026-09-09 核实）

| 项 | 数 | 取法 |
|---|---|---|
| Controller 类 | 45 | `grep -rl "@Controller\|@RestController" admin` |
| 写端点 `@Post/Put/DeleteMapping` | 128 | `grep -rhoE "@(Post\|Put\|Delete)Mapping\(" admin \| wc -l` |
| `@GetMapping` 映射 | 79 | 同法 |
| 页面路由（去 `{param}` / export / `.csv` / `.xlsx` / `drawer` / `/detail`） | ≈52 | 见 §AC2 |
| 模板文件 | 64（`templates/admin/*.html`）+ 3 fragments | `ls` |

`/admin/denied` 用的是 `@RequestMapping`（`AdminWebController:81`），不是 `@GetMapping`，脚本别漏。

### 🔴 `@PreAuthorize` 的三种写法都要能抓到

1. 字面量：`@PreAuthorize("hasRole('SUPER_ADMIN') or hasAuthority('payment.view')")`
2. 类内常量：`@PreAuthorize(VIEW_AUTH)`，常量在同文件顶部 `private static final String VIEW_AUTH = "…"`（`AdminPaymentController:23`）
3. 引用 `AdminPermissions` 常量拼接（`"hasAuthority('" + AdminPermissions.X + "')"`）——少见，抓到原文即可，不求展开

脚本输出**原文**，不做语义解析；Story 11.4 再用 Java 端 `AdminPageCatalog` 做一致性校验。

### 页面组映射为什么先写死在脚本里

`AdminPageCatalog`（页面 → 权限码 → 导航组）由 Story 1.5 引入、2.2 消费，本 story 在它之前执行，所以先用路径前缀表过渡。前缀表与 UI 稿 8 泳道一一对应（见 T2），`/admin/shop/shipping` 归商城组（D1 运费在商城泳道，Story 10.6）。

### 退役路由的现状注释要读一眼

`layout.html` 里对 `/admin/content-schedules` 有一段注释：「这个页面仍然保留可访问：改期 / 取消两个 POST 处理完之后要重定向回去，而且它带按发布账号筛选」。Story 7.5 把它并入批量内容页签时要处理这两个 POST 的重定向落点与 6 条集成测试——本 story 只在清单里标注 `⛔ 退役（7.5，注意 POST 重定向落点）`，不做判断。

### 脚本风格参考

`scripts/ci/check-flyway-versions.sh`：`#!/usr/bin/env bash` + 顶部规则注释 + `set -uo pipefail` + 大写常量 + `::error::` GitHub Actions 注解格式 + `fail=0` 累积后统一 exit。本脚本照抄这套。

### 与 CI 的关系

本 story **不**把脚本接进 CI（它是产出文档的工具，不是守门）。Story 11.1 决定是否加一条「写端点数量不得减少」的 CI 守门。
