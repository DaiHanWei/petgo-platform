# Story 2.3: 宠物档案访客视图（站内入口）—— Epic 4 复用

Status: review

## Story

As a 在别人主页上看到他养了只布偶猫的用户,
I want 点那只猫就能看到它的成长档案,
so that 我能看看别人是怎么养的，而不是只看到一个名字。

> 🔴 **本 story 交付的是共用件**：Epic 4 的推荐集合宠物卡点击**落同一个终点、走同一条通道**，不另建一套。
> 两个入口若各建一套，迟早分叉 —— 而分叉的表现是**私密数据从新入口漏出去**。

## Acceptance Criteria

**AC1 — 站内访客接口（AD-4）** `[L1]`
新建**按 petId 的站内访客接口**，返回只读投影，**复用 v1.1.6 已建的那层访客投影**，不新建第二套。
该投影**结构上就取不到**健康记录与问诊存档。
接口**仅对登录用户开放**；未登录一律拒绝。

**AC2 — 不下发分享 token** `[L0]`
🛡 **不向任何调用方下发对方宠物的分享 token**（B1-D1 否掉的方案：那等于把永久公开、可转发到站外的链接发给每个站内访客）。

**AC3 — 主页宠物区** `[L2]`
展示宠物卡片（头像 / 名字 / 物种 / 年龄），**可点击进入该宠物访客视图**。
卡上的 Tailsonality 角色小标位**天然空状态**（FR-117 在批次 B2），**不做占位设计**。

**AC4 — 站内进入隐藏来源横幅** `[L2]`
从站内入口进入 → **隐藏「由 XX 分享 · 仅可查看」横幅**（站内点击不存在"谁分享的"这个语境）。
从分享链接进入时该横幅**照旧显示**。
返回时回到上一页（主页），**不落首页**。

**AC5 — 没有日历** `[L2]`
⚠️ 访客视图**没有日历、没有「时间线/日历」切换行**（2026-08-18 与 08-28 两次拍板不做；UI 旧稿画错已于 2026-09-11 修订）。
**不要照旧稿补回去。**

### 🔴 两个入口，一层投影

新端点是 `/api/v1/...`（登录态、按 petId），既有端点是 `/api/v1/public/...`（游客、按 cardToken）。
**鉴权边界不同、投影必须同一份**。复制一份投影逻辑 = 将来改一处漏一处 = 私密数据从新入口漏出去。

### 🔴 AC5 别"补全"

`visitor_archive_view.dart` 里有一大段注释专门解释为什么没有日历，原话是「别再当成缺口补上去」。后端的访客日历接口**已建好且有测试**，是**有意留着的**——看到它不等于该接上。

### 页面要加"入口来源"概念

现在 `VisitorArchiveView` 只有 `token` 一个入参。本 story 要让它知道自己是**从分享链接**还是**从站内**打开的，据此决定横幅显隐与返回行为。加个枚举入参即可，**不要**为站内再复制一个页面。

### Completion Notes List

**已交付（L0 全绿）**

1. **站内访客接口**（AC1）：`GET /api/v1/pets/{petId}/visitor/{profile,stats,timeline}`
   → `InAppVisitorPetController`。
   - 🔴 **与分享入口落到同一层投影**（AD-4 Rule 2）：数据全部出自既有 `VisitorProjectionService`，
     新增的只有一句 `findVisibleProfileById(petId)` —— 它与按 token 那句**共用同一个可见性判定**
     （主人 active）。一条测试断言三个端点全部经过该投影。
   - **仅登录可用**：靠「不写 permitAll、落进默认的 authenticated 规则」实现，
     **没有改安全配置**（少动一次安全配置就少一次出错机会）。
   - 🔴 **主动拉黑者按 petId 直达也进不来**：主页那条已经 403，但本端点按 petId 寻址 ——
     只拦主页等于留了个绕过口（架构 S2）。只认 BLOCK，举报隐藏照常放行。
2. **不下发分享 token**（AC2）：主页宠物卡的响应 `PublicProfilePetResponse`
   **物理上就没有** cardToken —— 不是"记得别填"。前后端各有一条测试钉着这个形状。
3. **主页宠物区**（AC3）：`GET /api/v1/users/{userId}/pet` +「紫浅底行」宠物卡
   （头像 / 名字 / 物种 · 年龄 · Diary 数 /「Lihat →」），视觉与文案出口**逐项复用「我的」页那套**
   （`formatPetAge` / `petType*` / `meDiaryCount`）。
   - 没建过档案 → **204**，整块不渲染（「他还没养宠物」不需要一张空卡片说明）。
   - **Tailsonality 角色小标位是天然空状态**（FR-117 在 B2），**没做占位设计**。
   - 卡片本身游客可见（与主页同档），但**点进去**走 FR-0C 登录门控 —— 站内访客接口仅登录可用。
4. **站内态差异**（AC4）：`VisitorArchiveView` 从「只认 token」改成认 `ArchiveScope`，
   站内态**不渲染**「由 XX 分享 · 仅可查看」横幅；返回沿用既有 `canPop → pop`（回上一页，不落首页）。
   **没有为站内复制一个页面**。
5. **没有日历**（AC5）：站内入口**根本没有** calendar / day 两个端点，页面也没有切换行。
   公开那条路径上留着的 calendar/day 是有意保留的（Story 2.2 建好且有测试）——
   一条测试断言站内控制器的映射恰好只有 `/profile`、`/stats`、`/timeline` 三条。

**🔸 一条需要产品确认的口径（本 story 按架构原样保留，未改）**

访客视图的 Diary 时间线**含作者关闭同步的私密条目** —— 这是 PRD §2.9 §② 的既有拍板
（「分享宠物主页 = 授权访客查看该宠物完整 Diary」），投影层源码里写着「别顺手把私密条目滤掉」。
本 story **原样保留**，理由是 AD-4 Rule 2 明写「两个入口必须落到同一个投影，否则迟早分叉」。

⚠️ 但请留意：那条拍板的前提是**作者自己按下了分享键**；站内入口没有这个前提
（任何登录用户点一下别人主页上的宠物卡就到了）。而 `ContentVisibility` 的判定口径里，
「他人主页」是归在**按 PUBLIC 过滤**那一档的。两处口径在这个新入口上第一次撞上。
缓解现状：私密条目在时间线上**点不开**（`openableByVisitor=false`，点了给一句解释性 toast），
所以它不会越出这一屏；但卡片上的文字与图片是渲染出来的。
**改与不改都是产品决策，本 story 不自行决定**，在此标出待本地确认。

**code-review 复审后修掉的（4 findings 全修）**

1. 🔴 **三个访客 provider 仍是 keep-alive**：族键现在带 petId，而这一族是**可反复进出的站内页**。
   后果两条：同一只宠物再进来看到的是本次进程第一次取到的数据、永远不刷新；
   **换账号之后仍吃上一个账号的缓存，于是服务端那道拉黑守卫根本不会被调用**
   （与 bug 20260730-421 / 446 同型）。→ 三个都置 `isAutoDispose: true`。
2. **`return null` 出去的是 200 + 空 body，不是 204** —— 而 Javadoc、客户端注释、测试名都写着 204。
   → 改 `ResponseEntity.noContent()`，测试改为断言状态码。
3. **为了一个数算了五条查询**：宠物卡的 Diary 数原先走 `stats(...)`，那会连带算问诊次数、
   里程碑进度与**两次健康表计数** —— 而这是个游客可达、userId 可枚举的端点。
   → 投影层加一个 `diaryCount(profile)`（内部就是 `getStats` 用的同一句 `countGrowthMoments`），
   卡上那个数与点进去统计条上那个数仍是同一个实现。
4. **`scope.token ?? ''` 把 fail-fast 变成了畸形 URL**（`//` 会被 StrictHttpFirewall 判 400，
   不是注释里说的 404），且与旁边两个选择器仍用 `token!` 不一致。→ 统一回 `token!`。

**范围边界（有意不做）**

- **站内入口没有 calendar / day**（AC5），页面也没有视图切换行。
- **宠物卡上没有 Tailsonality 小标占位**（AC3 原文）。
- **`VisitorArchiveView` 的 const 构造器里没有 `assert(scope.isVisitor)`**：const 构造器的断言
  既不能调 getter 也不能读参数对象的字段，三种写法都会让 `const VisitorArchiveView(...)` 编译不过。
  作者态走不到这一屏由**调用方**保证（`GrowthArchivePage` 的状态分支 + 站内路由），源码里写了原因。
