# Story 2.1: 详情接口下发图片尺寸

Status: review

## Story

As a 客户端，
I want 详情接口告诉我每张图的原始宽高，
so that 页面在图片加载完成前就能留对高度、不跳动。

---

> **本 story 的存在本身是一处订正。** PRD 与工量预览都把 FR-113 归为「纯前端」，但 `ContentDetailResponse` **只有 `imageUrls`、没有尺寸** —— v1.1.6 AD-5 当初明写「既有五处图片读取点一处不动」，详情页正是其中之一。
>
> 没有这一条，Story 2.2 的「按原比例通栏」拿不到数据，实现者只能在「偷偷改后端 / 偷偷现场测量 / 全走占位」之间自选。
>
> **Epic 2 的第一条，后端单侧，零迁移**（尺寸列 v1.1.6 已建）。

## Acceptance Criteria

### AC1 — 响应新增尺寸（L1）

**Given** 一条含图内容
**When** 请求内容详情
**Then** 响应包含与图片数组**同序等长**的尺寸数组 `[L1]`
**And** 某张图无尺寸时该位为 `null` 占位以保持下标对齐 `[L1]`

### AC2 — 存量容错（L1）

**Given** 一条 v1.1.6 之前发布的存量内容（尺寸列为空）
**When** 请求内容详情
**Then** 尺寸数组各位为 `null`，接口正常返回、不报错 `[L1]`

### AC3 — 只下发原始宽高（L0）

**Given** 服务端
**When** 下发尺寸
**Then** 只下发**原始宽高** `[L0]`
**And** **不**下发已 clamp 的比例、**不**下发已算好的高度 `[L0]`

> 🔴 服务端先 clamp 一遍、客户端再 clamp 一遍会**双重裁切**（继承 v1.1.6 AD-6.6）。护栏依赖可视区高度，只能在客户端算。

### AC4 — 数据来源唯一（L0）

**Given** 尺寸数据
**When** 取值
**Then** 一律取 v1.1.6 已有的尺寸列 `[L0]`
**And** **不**新增测量路径、**不**现场测量 `[L0]`

> ⚠️ 母版假设 A-3「单帖实时加载可现场取尺寸」**不采纳**（AD-A12.2）：现场测量要等图片头部下载完才知道留多高，比现状更抖，且与 Feed 数据来源分叉。

### AC5 — 不扩散（L0）

**Then** 不改动 Feed 侧任何取数与响应 `[L0]`
**And** 不新增 Flyway 迁移 `[L0]`
**And** 不改动客户端（属 Story 2.2） `[L0]`

### Completion Notes List

**已交付（L0 全绿）**

1. **`ContentDetailResponse` 新增 `imageSizes`**（AC1）：`List<ImageSize>`，与 `imageUrls`
   同序等长，缺失位 `null`，无图时整个字段省略（NON_NULL）。
   **元素类型与 `FeedItemResponse.imageSizes()` 完全一致** —— 客户端两处共用一套解析，不分叉。
2. **新增 `ImageSizeResolver.alignForRead(imageUrls, stored)`**（AC1/AC2）：读路径的对齐。
   与既有 `normalize` 刻意分开，因为**「谁在说话」不同**：
   - `normalize` 处理**客户端上报**的数据 —— 可能算错、可能错位，所以长度不符要**整组作废**
     （错位的后果是图文不符，第 1 张图套用第 2 张的比例）；
   - `alignForRead` 处理**自己库里**的数据 —— 只需补齐下标，不需要不信任。库里存短了
     就按下标取到哪算哪，比让整条内容都没有尺寸要好。
3. **存量容错**（AC2）：V1.1.6 之前发布的内容整列为 `null` → 补成等长的全 `null`，接口正常返回。
   补齐而不是原样下发 `null` 的理由：客户端按下标取尺寸，给它一个「长度对得上、缺失位为 null」
   的数组，比给它 `null` 让它先判空再判长度**少一个出错点**。
4. **只下发原始宽高**（AC3）：有一条测试把线格式的 key 集合钉死为 `{w, h}`，并显式断言
   不含 `ratio` / `aspectRatio` / `displayHeight` / `height`。
5. **数据来源唯一**（AC4）：只读 v1.1.6 那一列，**没有新增任何测量路径**。
   有一条签名断言钉住 `alignForRead` 只吃「图片地址 + 库里存的尺寸」两个入参，
   没有 InputStream / URL fetcher 之类的口子。
   母版假设 A-3「单帖实时加载可现场取尺寸」**不采纳**（AD-A12.2）：现场测量要等图片头部
   下载完才知道留多高，比现状更抖，且与 Feed 数据来源分叉。

**范围边界（按 AC5）**

- **未改动 Feed 侧任何取数与响应**；**未新增 Flyway 迁移**（尺寸列 v1.1.6 已建）；
  **未改动客户端**（属 Story 2.2）。
- `ContentDetailResponse.of(...)` 多了一个 `imageSizes` 入参并在 javadoc 里写明
  「不要在这里现场取 `p.getImageSizes()`」—— 那是未对齐的原始列，存量内容整列为 null，
  下标会对不上。
