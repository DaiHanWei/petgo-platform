# Story 9.2: B21 未成功请求 + B22 历史会话查询

Status: ready-for-dev

> 自包含 story，可本地或云端 L0 执行。与用户沟通用中文。执行纪律见根 `CLAUDE.md`。
> 两个低频页套模板 B；**写端点零变更**、零迁移；两页**维持独立**（2026-09-04 拍板，UI 稿 6-9）。

## Story

As a 运营，
I want 「未成功请求」与「历史会话查询」两页和其他列表页一样有摘要条和抽屉，异常工单点「去取证」能直接落到对应会话，
so that 掉单巡查与纠纷取证走同一套操作习惯。

## Acceptance Criteria

**AC1 · B21 未成功请求套模板 B**
**Given** `GET /admin/failed-requests`（`vet.view`）
**When** 打开
**Then** 子区页签「活动 ｜ 已归档」（现状 `active()` / `archived()`）；摘要条：活动数 · SYSTEM_FAILURE 数 · 已跟进数（随页签联动）`[L1]`
**And** 表格列：请求 token ｜ 用户 ｜ 提交 / 取消时间（WIB）｜ 原因（`CancelReason`）｜ 当时在线兽医数 ｜ 跟进态 ｜ 备注摘要；SYSTEM_FAILURE 行红点强提示（UI 稿 6-8）`[L1]`
**And** 抽屉 `GET /admin/failed-requests/{id}/drawer`：完整字段 + 三个独立动作：保存备注（`POST {id}/note`，自由文本）· 标记跟进（`POST {id}/follow-up`，无参数）· 归档（`POST {id}/archive`，data-confirm）`[L1]`
**And** 🔴 归档前置不变：SYSTEM_FAILURE 未跟进 → 服务层抛错 → 422 行内 err「请先标记跟进」；抽屉在未跟进时把归档钮渲染为禁用并注明（防呆，UI 稿 6-8）`[L1]`

**AC2 · B22 历史会话查询套模板 B（只读）**
**Given** `GET /admin/consult-sessions`（`consult.view_sessions`）
**When** 打开
**Then** 查询条件四项（userId / vetId / from / to）+ 显式「查询」钮（**不** autosubmit）；结果表：会话 ｜ 用户 ｜ 兽医 ｜ 开始 ｜ 结束 ｜ 状态 ｜ 评分；空态文案 `[L1]`
**And** 行抽屉 = 会话取证视图：**只展示会话元数据 + 评分**（NFR5：绝不读 IM 正文 / AI 结论 / 媒体），页内常驻说明 `admin.sessions.note` `[L1]`
**And** 支持 `?open=<sessionId>` 页内深链自动开抽屉（`admin-drawer.js`）；A4 异常工单的「去取证」链接改为指向 `/admin/consult-sessions?open=<sessionId>` 新开标签（与 Story 2.6 对齐）`[L2]`

**AC3 · 两页维持独立**
**Then** 不合并、不共享筛选条；导航「兽医与问诊」组保留「未成功请求」「历史会话查询」两项 `[L0]`

**AC4 · 写端点零变更 + 三语 + 测试**
**Then** `POST /admin/failed-requests/{id}/{note|follow-up|archive}` 不变；历史会话页无写端点 `[L0]`
**And** 新 key `admin.v130.failed.*`、`admin.v130.sessions.*` 三包同批 `[L0]`
**And** MockMvc 四条 ×2；既有 `FailedConsultRequestIntegrationTest`、`ConsultSessionQueryIntegrationTest` 全绿 `[L1]`

### 🔴 三个动作是三件事，不是一件事的三种叫法

UI 稿 6-8 代码核实：「跟进」= 状态推进标记无参数；「归档」= 移出活动区，**SYSTEM_FAILURE 必须先跟进**；「备注」= 可选自由文本。抽屉里三个按钮独立渲染，不要合成一个「处理」下拉。

### 🔴 NFR5 隐私红线

`AdminConsultSessionController` 类注释明确「仅展示会话元数据 + 评分，绝不读 IM 正文 / AI / 媒体」。抽屉 = 取证视图 ≠ 聊天记录。用户 09-04 曾质疑「查不到内容就该合并」，已拍板维持并保留说明文案。不要为了「抽屉更丰富」去加任何内容读取。

### 页内深链 vs 旧路由跳转

`?open=<id>` 是 AD-9 的页内深链机制（列表页加载后由 `admin-drawer.js` 自动请求抽屉），与 D-23「旧独立页地址不做跳转」不冲突——这里没有旧页面被删。

### 测试标准

沿用 `test/.../admin/failedrequest/FailedConsultRequestIntegrationTest`、`admin/anomaly/ConsultSessionQueryIntegrationTest`；抽屉 fragment 断言不含 `<html`。
