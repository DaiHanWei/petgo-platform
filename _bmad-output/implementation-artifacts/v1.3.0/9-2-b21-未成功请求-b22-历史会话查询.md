# Story 9.2: B21 未成功请求 + B22 历史会话查询

Status: review

> 自包含 story，可本地或云端 L0 执行。与用户沟通用中文。执行纪律见根 `CLAUDE.md`。
> 两个低频页套模板 B；**写端点零变更**、零迁移；两页**维持独立**（2026-09-04 拍板，UI 稿 6-9）。

## Story

As a 运营，
I want 「未成功请求」与「历史会话查询」两页和其他列表页一样有摘要条和抽屉，异常工单点「去取证」能直接落到对应会话，
so that 掉单巡查与纠纷取证走同一套操作习惯。

## Acceptance Criteria

**AC1 · B21 未成功请求套模板 B**
**Given** `GET /admin/failed-requests`（`vet.view`）
**When** 打开
**Then** 子区页签「活动 ｜ 已归档」（现状 `active()` / `archived()`）；摘要条：活动数 · SYSTEM_FAILURE 数 · 已跟进数（随页签联动）`[L1]`
**And** 表格列：请求 token ｜ 用户 ｜ 提交 / 取消时间（WIB）｜ 原因（`CancelReason`）｜ 当时在线兽医数 ｜ 跟进态 ｜ 备注摘要；SYSTEM_FAILURE 行红点强提示（UI 稿 6-8）`[L1]`
**And** 抽屉 `GET /admin/failed-requests/{id}/drawer`：完整字段 + 三个独立动作：保存备注（`POST {id}/note`，自由文本）· 标记跟进（`POST {id}/follow-up`，无参数）· 归档（`POST {id}/archive`，data-confirm）`[L1]`
**And** 🔴 归档前置不变：SYSTEM_FAILURE 未跟进 → 服务层抛错 → 422 行内 err「请先标记跟进」；抽屉在未跟进时把归档钮渲染为禁用并注明（防呆，UI 稿 6-8）`[L1]`

**AC2 · B22 历史会话查询套模板 B（只读）**
**Given** `GET /admin/consult-sessions`（`consult.view_sessions`）
**When** 打开
**Then** 查询条件四项（userId / vetId / from / to）+ 显式「查询」钮（**不** autosubmit）；结果表：会话 ｜ 用户 ｜ 兽医 ｜ 开始 ｜ 结束 ｜ 状态 ｜ 评分；空态文案 `[L1]`
**And** 行抽屉 = 会话取证视图：**只展示会话元数据 + 评分**（NFR5：绝不读 IM 正文 / AI 结论 / 媒体），页内常驻说明 `admin.sessions.note` `[L1]`
**And** 支持 `?open=<sessionId>` 页内深链自动开抽屉（`admin-drawer.js`）；A4 异常工单的「去取证」链接改为指向 `/admin/consult-sessions?open=<sessionId>` 新开标签（与 Story 2.6 对齐）`[L2]`

**AC3 · 两页维持独立**
**Then** 不合并、不共享筛选条；导航「兽医与问诊」组保留「未成功请求」「历史会话查询」两项 `[L0]`

**AC4 · 写端点零变更 + 三语 + 测试**
**Then** `POST /admin/failed-requests/{id}/{note|follow-up|archive}` 不变；历史会话页无写端点 `[L0]`
**And** 新 key `admin.v130.failed.*`、`admin.v130.sessions.*` 三包同批 `[L0]`

### 🔴 三个动作是三件事，不是一件事的三种叫法

UI 稿 6-8 代码核实：「跟进」= 状态推进标记无参数；「归档」= 移出活动区，**SYSTEM_FAILURE 必须先跟进**；「备注」= 可选自由文本。抽屉里三个按钮独立渲染，不要合成一个「处理」下拉。

### 🔴 NFR5 隐私红线

`AdminConsultSessionController` 类注释明确「仅展示会话元数据 + 评分，绝不读 IM 正文 / AI / 媒体」。抽屉 = 取证视图 ≠ 聊天记录。用户 09-04 曾质疑「查不到内容就该合并」，已拍板维持并保留说明文案。不要为了「抽屉更丰富」去加任何内容读取。

### 页内深链 vs 旧路由跳转

`?open=<id>` 是 AD-9 的页内深链机制（列表页加载后由 `admin-drawer.js` 自动请求抽屉），与 D-23「旧独立页地址不做跳转」不冲突——这里没有旧页面被删。

### 测试标准

沿用 `test/.../admin/failedrequest/FailedConsultRequestIntegrationTest`、`admin/anomaly/ConsultSessionQueryIntegrationTest`；抽屉 fragment 断言不含 `<html`。

### Project Structure Notes

改动落 `admin/failedrequest/**`、`admin/anomaly/web/AdminConsultSessionController`、两模板 + 两抽屉 fragment。

### Completion Notes

**范围**：两个低频页套模板 B。**写端点零变更、零迁移** —— `POST /admin/failed-requests/{id}/{note|follow-up|archive}` 的路径 / 参数 / 权限逐字未动，新增的只有两个 drawer GET。

- **AC1 B21**：活动/已归档两张平铺表 → **页签（查询参数 `?tab=archived`，可存书签）+ 一张表**；摘要条三格 `total / systemFailure / followedUp` **随页签联动**（在「已归档」页签上给活动区的数是骗人的）；行内三个动作全部移进抽屉。抽屉里三个动作仍是**三个独立提交入口**，没有合成「处理」下拉。
- **AC1 归档前置**：服务层那道 `SYSTEM_FAILURE 未跟进不可归档` 判定**一个字没动**；抽屉只是**提前**把归档钮渲染为禁用并注明原因（防呆，不是安全边界）。htmx 分支上 `archive` **不再 try/catch**，让 422 经 `AdminBusinessExceptionAdvice` 落进抽屉行内错误槽。
- **AC2 B22**：查询条件四项 + **显式「查询」钮**（不 autosubmit）；抽屉是取证视图，与列表**同一个 `toRow`**，一个字段都不多（NFR5）；`?open=<sessionId>` 页内深链 + B21 抽屉的「去取证」链接。
- **AC3**：两页维持独立（2026-09-04 拍板），测试反证改为「一页里不出现另一页的控件」，而不是只看侧栏链接还在。
- 新增 `FailedConsultRequest.getSessionId()`：字段本来就在，只是一直没有访问器；抽屉的「去取证」要拿它拼深链。字段注释同步改为「仅后台可见、不进任何对客响应」。
- 新增 `ConsultSessionAdminQueryService.findMeta(long)`（复用 `toRow`）与 `AdminConsultSessionController#drawer`。

**复审后修复（本轮）**：

1. **🔴 行为变更（AC2 收紧，需知会）**：`GET /admin/consult-sessions` **一个查询条件都没填时不再查库**。原实现空条件走 `cb.and(new Predicate[0])`（恒真式）= 把整张 `consult_sessions` 摊平返回；这与本 story 新加的空态文案「先填查询条件再点『查询』」、模板注释、测试名三处说法都相反。取证页不是会话总账，「打开即全量」既是无谓全表扫描，也让一次误点把全站会话元数据摆上屏幕 —— 按文案收紧为**空条件零行**。AC2 只写了「空态文案」，没写默认是否列全量，这里按红线取严；**如需恢复「打开即全量」请拍板**。
2. **测试稳定性**：`theSummaryFollowsTheTabNotTheActiveQueueAlways` 原来钉「已归档页签 total = 0」，而 `ApiIntegrationTest` 不回滚、同包 `FailedConsultRequestIntegrationTest` 会永久归档记录且类名字母序在前 → 全量 L1 必红。改为钉**同一时刻库现状与页面数一致**，再加「刚 seed 的那条不出现在已归档页签、出现在活动页签」的反证。
3. **B22 抽屉零渲染覆盖**：`theSessionDrawerCarriesMetadataOnlyAndSaysWhy` 原来只断言 404，抽屉模板一行都没被渲染过。现在真造一条 `ConsultSession` 渲染抽屉，钉元数据字段 + `data-notice="session-nfr5"` + **不出现任何 IM/AI/媒体字段名**（`imConversationId`/`aiSymptomText`/`aiImageRefs`/`vetDiagnosis`）+ 全只读（无 `<form>` / `hx-post`）。
4. **🔴 深链失败留下一扇空白抽屉**：`admin-drawer.js` 用 `htmx.ajax(..., {target: .drawer-body})`，而 `.drawer-body` **没有 id** → htmx 不发 `HX-Target` → `AdminBusinessExceptionAdvice` 把错误退回表格下面的 `#admin-inline-error`，而那时它正被遮罩盖着；JS 又无条件展开抽屉 → `?open=<不存在的 id>` 的结果是一扇空白的 480px 抽屉，错误看不见。修法是给抽屉体加 id（`tpl-b-list` 与 `tpl-shared :: drawer`，`<res>-drawer-body`），错误就回填到抽屉里。**这是模板壳级修复，惠及全部模板 B 页面**。
5. `thetwoPagesStayIndependent` 拼写 + 近乎恒真 → `theTwoPagesStayIndependentInsteadOfBeingMerged`，改钉控件不互串。
6. 删孤儿 key `admin.failed.col.action`（行内动作列已随本 story 移进抽屉，四包同删）。
7. `FailedConsultRequest.sessionId` 的过期注释（「不外露」）与新增 getter 矛盾 → 改写。

**已知取舍（不改，已注明）**：无 JS 的整页 PRG 分支处置完一律回默认（活动）页签，不带回 `tab` —— 本 story 的硬约束是三个写端点**参数逐字不动**，为回跳加一个 `tab` 参数就破了这条；htmx 常态路径由页内 `#failed-refresh` 按当前页签整表重拉，不受影响。
