## 这一类为什么之前查不出来

AC4 的核对方法是「动态 key 前缀（`#{'admin.qual.' + ${x}}` 这种）在四包里数量相等」。
它验的是**已经有 key 的枚举有没有漏译**，而这里的问题是**压根没有 key**：

```html
<option th:each="s : ${vetStatuses}" th:value="${s}" th:text="${s}">ACTIVE</option>
```

模板直接把枚举常量名渲染出去。四包 key 集合完全相等（因为一个相关 key 都没有），
`check-i18n-keys.sh` 全绿，`grep 中文` 也查不到 —— **切到印尼语后这些下拉框显示
`ACTIVE` / `ILLEGAL` / `GENERAL` / `HOME_FEED`**。

判据改成**从模板侧出发**：`<option th:each="x : ${...}" th:text="${x}">` 且值里没有 `#{`。
这条已经固化进守门（它本来就在解析标签树）。

## 处置

本 story 是**验收**，按 AC3 的口径「发现问题回对应页面 story 修，不在本 story 改业务」。
唯一就地修掉的是**零新增 key** 的那一处：`seed-post.html:71` 的 `${types}`——
`admin.contentType.DAILY / GROWTH_MOMENT / KNOWLEDGE` 四包本来就有，模板没用而已。

其余登记如下，按泳道归属。**修的时候三件事一起做**：新建 key（四包同批）→ 模板改
`th:text="#{'<前缀>.' + ${x}}"` → 从白名单里删掉那一行（守门会立刻接管）。

### 🔴 收尾时补抓到的两处（不在原登记里，守门也扫不到）

原登记还点了一条：

> 另有 `shop-order-detail.html:149` 的 `Carrier` 走的是 `c.displayName()` —— 显示名**硬编码在 Java 里**，
> 属于同一类问题的另一种形态（不在模板层，守门扫不到），Epic 10 一并处理。

核实后分两件事：

1. **`shop-order-detail.html` 已于 Story 10.2 整页退役**（订单详情并进 B15 的抽屉），那一行不存在了。
   Carrier 的 `displayName()` 现在出现在 `fragments/drawer-shop-order.html` 的发货下拉里。
   **结论：不补 key，认定为长期例外** —— `JNE` / `SiCepat` / `Anteraja` 是**品牌名**，
   大小写按品牌官方写法，三语通用，与 `places.html` 的城市名同类。给 SiCepat 做印尼语翻译没有意义。
2. 🔴 **但同一个抽屉里被抓到两处真问题**（Story 10.2 引入，2026-09-11 收尾时修）：
   - 包裹表格用的是 `${p.carrier}`（枚举常量 `SICEPAT`），而同页发货下拉用的是 `${c.displayName()}`（`SiCepat`）
     —— 运营在下拉里选「SiCepat」，发完货表格里显示「SICEPAT」，看起来像选错了家。改用 `carrierName`。
   - 包裹状态列直接铺 `ShipmentStatus` 常量名（`SHIPPED`）。该枚举只有 `SHIPPED` / `DELIVERED`，
     与订单状态那两档同义，直接复用既有 `admin.v130.shopOrders.status.*`。

> ⚠️ **这两处暴露了守门的一个覆盖缺口**：`check-admin-hardcoded-text.sh` 的「枚举未走 key」判据只认
> `<option th:each="x : ${...}" th:text="${x}">` 这一种形态，**`<td th:text="${x}">` 不在判据内**。
> 放宽到「所有 `<td>` 里的 `${x}`」不可行 —— 那一类绝大多数是**数据**（商品名、单号、金额、用户昵称），
> 会淹没在假阳性里。这条缺口**如实登记，不改守门**：它属于「靠 code review 而不是靠机器」的那一档。
