# Story 2.6: 回复态显式化

Status: review

## Story

As a 用户，
I want 输入框明确告诉我这条是发新评论还是回复某人，
so that 我不会以为在回复、结果发成了新评论。

---

> **这不是全新功能。** `comment_composer.dart` 已有 `replyTargetProvider`，回复态会显示「@昵称」+ ✕ 按钮。
>
> **本 story 是四项增量**：① 纯文本行改胶囊样式 ② 占位文案随回复态切换（现状恒为通用 `detailCommentHint`）③ 清空文字也退出回复态（现状只有点 ✕）④ 回复成功后展开父评论并滚动定位（现状无）。
>
> 依赖 Story 2.3（底栏结构已重排完毕）。

---

## Acceptance Criteria

### AC1 — 胶囊样式（L2）

**Given** 用户点击某条评论的回复入口
**When** 输入框进入回复态
**Then** 输入框上方常驻「回复 @昵称」**胶囊**（不再是纯文本行）+ ✕ 取消按钮 `[L2]`

### AC2 — 占位文案随态切换（L2）

**Given** 处于回复态
**Then** 占位文案为「回复 @昵称…」 `[L2]`
**Given** 非回复态
**Then** 占位文案为发新评论的通用文案 `[L2]`

> 现状：占位恒为 `l10n.detailCommentHint`，**不随回复态变化** —— 这正是用户分不清自己在回谁的直接原因。

### AC3 — 两种退出方式（L2）

**Given** 处于回复态
**When** 点击 ✕
**Then** 退出回复态，占位恢复 `[L2]`
**When** 清空输入框文字
**Then** 同样退出回复态 `[L2]`

### AC4 — 默认是新评论（L2）

**Given** 用户未点击任何回复入口
**When** 开始输入
**Then** 一律作为新的一级评论 `[L2]`

### AC5 — 发布后定位（L2）

**Given** 回复发布成功
**When** 列表刷新
**Then** 自动展开该父评论的回复区 `[L2]`
**And** 滚动定位到新回复处 `[L2]`

### AC6 — 既有行为不变（回归保护，L2）

**Given** 父评论已不存在时的既有兜底
**When** 触发
**Then** 仍然清空回复态（现状 `clear()`，保留） `[L2]`
**And** 二级回复的时间正序不变 `[L2]`

### Completion Notes List

**L1/L2 待本地验收。** 本 story 的 AC 全部标 `[L2]`，价值完全在手感上，云端 headless 看不出。逐条列明真机要验什么：

| AC | 真机要验的具体动作 | 看什么 |
|---|---|---|
| AC1 | 点某条评论的「回复」 | 输入框上方出现**胶囊**（`cream2` 底 + 999 圆角 + 省略号截断长昵称），不是改前那行裸文字；✕ 图标 14px 但命中框已扩到 22px 左右，手指点得中 |
| AC2 | 进/出回复态各看一次占位 | 回复态是「Reply to @昵称…／Balas @昵称…」，非回复态回到通用占位。**两套语言都要看**（App 只发 EN/ID，无中文包） |
| AC3 | ① 点 ✕ ② 全选删光文字 | 两种方式都退出回复态、占位复位。**反向也要验**：刚点回复（框本来就空）时回复态不能自毁；只敲空格再删掉不受影响 |
| AC4 | 不点任何回复入口直接打字发送 | 发出的是一级评论，不挂在任何人下面 |
| AC5 | 回复一条**回复数 > 3** 的评论 | 发完自动展开该父评论的回复区 + 滚动到新回复处（底部对齐，300ms easeOut）。**关键场景**：回复区不止一页时要能翻到新回复那一页（最多翻 5 页） |
| AC5 | 回复一条**回复数上百**的评论 | 翻页有上限，不会卡在长时间连续请求上；翻不到就停在已加载末尾，不报错 |
| AC6 | 回复一条**已被别人删掉**的评论 | 仍是专属提示 + 退出回复态（既有行为）；二级回复时间正序不变 |
| 键盘 | 回复态下弹键盘 | 胶囊 + 输入框整体在键盘上方（底栏形态，宿主 `resizeToAvoidBottomInset: true`） |

**实现要点（复审时的着眼处）**：

1. **AC3 的退出只挂在「有字 → 没字」这一跳上**，不是「只要为空就退出」。后者会让刚点回复时（输入框本来就是空的）回复态当场自毁 —— 测试里有一条专门钉这个反向场景。
2. **AC5 的落点带新回复 id，不只是 parentId**。二级按时间正序，新回复落在**最后一页**；只展开第一页时，「回复数超过一页」这个最需要定位的场景恰恰定位不到。翻页上限 `_replyPagingGuard = 5`。
3. **落点在重拉之后消费**：`_reload()` 会清空 `_expanded`，先展开再刷新等于白展开。
4. **落点带 `seq`**：连着回同一条父评论两次，只存 parentId 的话第二次状态没变、监听方收不到通知。
5. **落点在 `dispose` 清掉**（与 Story 2.5 的会话置顶同一处理），否则没消费掉的落点会让下一个详情页莫名自己展开一条评论。

**未改动的既有语义**：AC6 的两条兜底（父评论已删 → `clear()` + 专属提示；二级时间正序）一字未动。
