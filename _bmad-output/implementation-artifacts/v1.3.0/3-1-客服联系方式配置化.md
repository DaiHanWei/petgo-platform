# Story 3-1: 客服联系方式配置化（AD-S8）

Status: ready-for-dev

> 自包含 story，可本地或云端 L0 执行。与用户沟通用中文。执行纪律见根 `CLAUDE.md`（后端 → 前端 → 联调、AC 标 L0/L1/L2、Flyway 时间戳版本号、`mvn -B clean package`）。
> 本 story = **后端新配置载体 + 免鉴权下发端点 + 后台配置页 + App 客服弹窗改读端点**。深链本身是 Story 3-3 的事，本 story 只负责把号码变成「一处配置、多处消费」。
> **它是 Epic 3 的第一块**：3-3 的 WhatsApp 深链直接消费本 story 产出的 provider 与端点，先做本条。

## Story

As a 运营，
I want 换客服号的时候改一个后台配置就生效，
so that 不用等 App 发版、也不用担心某个角落还留着旧号码。

## Dev Notes

### 🔴 为什么是单行表而不是 key-value 表

AD-S8 已拍板：**不建通用 key-value 设置表**。理由是仓库里已有的配置一律是「单行强类型表 + CHECK(id=1) + 种子 INSERT」（`pricing_config` / `pawcoin_config` / `feed_rank_config`），再引一套 key-value 会让「配置在哪张表里是真的」变成需要对账的问题，而且 key-value 天然丢类型与约束（号码列就没法上 `VARCHAR(20)`）。代价是每加一类配置要一支迁移 —— 在这个项目里一年也就几支。

### 🔴 `ck_config_change_type` 是这条 story 最容易踩的雷

`V20260824_1655` 的文件头已经把事故写清楚了：**只在 Java 枚举里加值不够**，写日志时会撞 DB 约束，表现是「保存配置报 500」，而错误栈指向 `config_change_logs` 不指向配置模块，极易被误判成审计模块坏了。CLAUDE.md 另记了三次「照着过期列表抄」的事故（V72、V20260818_0358）。所以：

- 值集**只从当前树里最后一条重建该约束的迁移**取，即 `V20260824_1655` 的四值；
- 一律 `DROP + ADD` 全量重建，禁止「我只 append 一个」的写法。

### 🔴 `AuthService` 的常量改实例方法，波及面比看上去大

`DEACTIVATED_MESSAGE` 是 `static final`、包内可见，`AuthService` 构造器已经 8 参。改造要一次做完三件事：删常量 / 加构造参数 / 改三个抛出点。**先 grep `new AuthService(`**，把所有单测构造点一次补齐，否则编译错误会散在十几个测试类里，看起来像是改崩了。

文案本身**保持中文原样**（App 直接把 ProblemDetail 的 detail 显示给用户，这是既有行为，本 story 不做 i18n 化 —— 那是另一个话题，别顺手做）。

### 🔴 「三处」其实是 2 + 1

规划文档多处写「三处硬编码」，实测源码只有 2 处（D.7 已勘误）。第三处是 3-3 要新建的深链。本 story 的正确心态是：**建立单一事实源 + 把现存 2 处接上去**，让 3-3 新建的第三处天然就是读同一份。验收 AC9 的「三处同批生效」在 3-1 单独交付时只能验 2 处，第三处随 3-3 一起验 —— 在 Completion Notes 写清。

### 🔴 免鉴权的边界

端点只吐「公司对外公布的客服号与邮箱」，本来就印在法务页和 App 弹窗里，非敏感。但要守住两点：① 路径**精确匹配**不通配（`/api/v1/support-tickets/**` 就在隔壁且是 USER 角色专属）；② 响应体永远只有这三个字段，将来想往里塞「客服在线时段」「工单 SLA」之类要重新评鉴权。

### 号码的两种形态

| 形态 | 值 | 用途 |
|---|---|---|
| `whatsappNumber` | `081290906953` | 展示、复制到剪贴板（印尼人认这个写法） |
| `whatsappE164` | `+6281290906953` | 深链（3-3 会去掉 `+` 拼 `wa.me/6281290906953`） |

`IndonesiaPhone.normalize` 返回**带 `+`** 的 E.164。`wa.me` 的路径段**不要 `+`**，剥 `+` 的动作放在 3-3 的 URL 构造里，provider 不做 —— 保持 provider 输出是标准 E.164。
