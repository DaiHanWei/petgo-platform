# Story 1.6: 后台账号页接入角色表

Status: review

> 自包含 story，可本地或云端 L0 执行。与用户沟通用中文。执行纪律见根 `CLAUDE.md`。
> 本 story **纯后台，无迁移**：改角色下拉的数据源、`changeRole` 支持自定义角色、账号级权限面板按 `AdminPageCatalog` 8 组重排、Epic 1 收口回归。仍在现有页面样式上做，套模板 B 归 Story 6.5。
> **依赖 1-4**（表、resolver）、**1-5**（`ROLE_TEMPLATE`、`AdminPageCatalog`、`AdminRoleService.list`）、**1-1**（bump）。

## Story

As a 超级管理员，
I want 后台账号页的「改角色」下拉能选到预置和自定义角色，权限勾选面板按新导航组分组显示，
so that 账号与角色两页口径一致，配权限时不用对着一长串码猜。

## Acceptance Criteria

**AC1 · 改角色下拉数据源**
**Given** 账号列表「改角色」`<select name="role">` 与创建表单的角色下拉
**Then** 选项 = `SUPER_ADMIN`（枚举）+ `OPS_MANAGER`（枚举）+ `admin_roles` 全部行（SYSTEM 四个用 `#{role.<CODE>}`，CUSTOM 用 `name`）+ `CUSTOM`（账号级勾选）；顺序：超管、运营主管、预置四个、自定义若干、自定义勾选 `[L2]`
**And** 选项值编码：枚举用枚举名，表角色用 `tpl:<roleId>`；Controller 解析后调服务层 `[L1]`

**AC2 · `changeRole` 支持表角色**
**When** 选中表角色提交 `POST /admin/accounts/{id}/role`
**Then** 服务层：预置角色 → `role=<CODE 枚举>, role_id=<id>`；自定义角色 → `role=ROLE_TEMPLATE, role_id=<id>`；枚举角色 → `role=<枚举>, role_id=NULL`；`admin_account_permissions` 处理沿用现状（切到 CUSTOM 时 carry 当前生效权限，切离 CUSTOM 时清勾选行）`[L1]`
**And** 🛡 既有护栏全部保留：超管上限、最后超管不降级、self 护栏（1-2）、幂等 no-op（同 role 且同 roleId）`[L1]`
**And** 成功后 `security_version` +1（1-1 已接）；横幅 `admin.flash.account.roleChanged` 文案含「（对方重新登录后生效）」（现状文案已是「下次登录生效」，改为与 D-2 措辞一致）`[L2]`
**And** 审计 `ACCOUNT_ROLE_CHANGED` summary 对表角色记 `code` 而不是 `ROLE_TEMPLATE`（可读性）`[L1]`

**AC3 · 创建账号支持表角色**
**When** 创建表单选表角色
**Then** `createAccount` 同 AC2 规则写 `role` / `role_id`；模板角色仍忽略勾选权限；审计 summary 记 code + 权限条数（条数经 resolver 取）`[L1]`

**AC4 · 账号级权限面板按 8 组重排**
**Given** 创建表单的勾选区与每行「改权限」`<details>` 面板（仅 CUSTOM 账号显示）
**Then** 分组数据源改为 `AdminPageCatalog.groups()`：一级标题 = 8 个导航组（三语 `admin.nav.group.<x>`），二级 = 页面名（`admin.page.<key>`），每页面下列出该页查看 / 编辑 / 其他码的复选框（复用 1-5 矩阵的渲染片段，做成 Thymeleaf fragment `fragments/perm-matrix.html` 两页共用）`[L2]`
**And** 🛡 码集合仍是 `AdminPermissions.ALL` 全集（测试断言面板渲染出的 checkbox value 集合 == ALL）`[L1]`
**And** `AdminPermissions.GROUPS`（view/edit 两组）不再被账号页引用；保留常量供其他引用（grep 确认后若无引用可标 `@Deprecated`，不删）`[L0]`
**And** 保存逻辑 `updatePermissions` 不变（含 1-1 bump）`[L1]`

**AC5 · 列表回显**
**Then** 「岗位角色」列：表角色显示三语名 / 自定义名 + 小徽标「自定义」；「权限」列对表角色显示「（按岗位角色授权）」+ 生效码（经 resolver），与 1-4 前展示一致 `[L2]`
**And** 角色权限预览区（创建表单选角色时即时显隐）数据源改为 `rolePermissions` map = 枚举 + 表角色（key 用 AC1 的选项值编码）`[L2]`

**AC6 · Epic 1 收口回归**
**Then** 创建 / 改名 / 换绑 / 改权限 / 改角色 / 停用 / 重新激活七个操作走一遍：超管上限 5、最后超管护栏、self 护栏、bootstrap 不可换绑全部有效；四类预置账号登录权限与迁移前快照一致（1-4 Parity）；`mvn -B clean package` 绿 `[L1]`

## Dev Notes

### 🎯 本 story 把 Epic 1 前五条串起来

1-1 版本号、1-2 改名/self、1-3 换绑、1-4 表与 resolver、1-5 角色页——都在账号页这一个界面上汇合。本 story 结束后账号页应具备 UI 稿 7-7 的全部行内操作（创建 / 改名 / 改角色 / 改权限 / 换绑 / 停用 / 激活），只差 Story 6.5 的模板 B 视觉。

### 🔴 `role` 列与 `role_id` 必须成对写

1-4 定了对照表：预置四值 `role=<CODE>` + `role_id`；自定义 `role=ROLE_TEMPLATE` + `role_id`；其余 `role_id=NULL`。任何一处只写一个字段都会让 `RolePermissionResolver` 走进「异常数据 → 空集 + warn」分支，用户表现为「改了角色后登录什么权限都没有」。所以 T2 强制用 `assignRole(role, roleId)` 一个方法写两字段。

### 🔴 option value 编码为什么不用 roleId 一把抓

SUPER_ADMIN / OPS_MANAGER / CUSTOM 三个没有表行；四个预置既有枚举又有表行。统一成字符串 `enum:X` / `tpl:<id>` 后 Controller 一处解析，模板 `th:selected` 比较也简单。**预置四个用 `enum:<CODE>`**（而不是 `tpl:<id>`），这样存量账号 `role=OPERATIONS` 的下拉默认选中不用查表映射。

### 🔴 权限面板重排 ≠ 改权限语义

D-9 方案 A：账号级 CUSTOM 勾选机制**保留并存**。本 story 只改面板的**分组展示**（`GROUPS` 两组 → `AdminPageCatalog` 8 组），提交的仍是 `permissionCodes[]` 全集里的码，`updatePermissions` 一行不改。测试用「checkbox value 集合 == ALL」钉住不丢码。
