# Story 1.5: 场所详情页

Status: review

## Story

As a 在列表里看到一家店的用户,
I want 点进去看清楚它到底怎么样、在哪儿、是谁标的,
so that 我能判断值不值得专门跑一趟。

## Acceptance Criteria

**AC1 — 页面元素** `[L2]`
照片横滑流 · 名称/类型/标签/距离/描述 · **文字地址 +「复制」** · 标记人 · **定位小地图 +「在地图中打开」** · 分享按钮 · 举报入口。**不含打卡按钮**。

**AC2 — 地址复制** `[L2]`
点「复制」→ 地址进剪贴板 + 轻提示。

**AC3 — 在地图中打开** `[L2]`
跳系统地图 App 并定位到该坐标（普通跳转链接，不算 API 调用、不计费）。

**AC4 — 标记人点击** `[L2]`
本 story 内走**现有的迷你主页卡**（现状能力）。
⚠️ Epic 2 退役迷你卡时统一改为直跳公开主页，**本 story 不依赖 Epic 2**。

**AC5 — 举报** `[L2]`
复用既有五类选项举报抽屉，文案一字不改。

**AC6 — 反向验收（FR-112.6）** `[L2]`
**没有**收藏、**没有**评分打星、**没有**营业时间/电话等商户字段、**没有**打卡按钮、**没有「编辑场所」入口**。

**AC7 — 已下架** `[L1]`
场所被运营下架后打开详情 → 统一「场所不存在」空态，不泄漏任何原内容。

**code-review 复审后修掉的（4 findings 全修）**

1. 🔴 **举报并发撞唯一约束 → 500**：`existsBy` 预查挡不住并发，后到的那条抛
   `DataIntegrityViolationException`，用户看到「举报失败」—— 正是代码注释里写着"报错也不行"
   的那个结果。同仓库的内容举报 `ReportService.submit` 对同形状约束是显式吞掉的，这次漏了。
   → `catch` 后按幂等返回，并补一条断言它不抛的测试。
2. 🔴 **`canLaunchUrl('geo:…')` 在 Android 11+ 恒为 false**：包可见性要求 manifest 的
   `<queries>` 里声明 `geo:` 的 VIEW intent，而那里只有 PROCESS_TEXT。后果是注释承诺的
   「让用户选系统里装的地图 App」**永远不会发生**，一律回落网页链接 —— 装了 Gojek / Waze
   而没装 Google Maps 的用户拿到浏览器页面。→ 补声明 + `map_usage_boundary_test` 加一条机械检查。
3. 🔴 **详情族键用原始坐标、且没有定位闸门**：定位未就绪时进页面（**深链正好总是这条路径**，
   Story 1.10 的分享链接就链到这里）会先发一次无坐标请求、渲染出内容，定位落定后族键变化
   → 换成一个**全新无值的 provider** → 已经渲染好的详情被整屏转圈顶掉，第二次再失败就落错误态。
   → 加列表页同样的 `isLoading && !hasValue` 闸门 + `placeDetailQueryFor` 做 ~110 m 归一
   （与列表同一套规则，顺带让两侧送往服务端的坐标精度一致）。
4. **`launchUrl` 的返回值被丢弃**：没有 activity 能处理时 url_launcher 是 `return false`
   而**不是抛异常**，所以 `catch` 里的失败提示在最可能的那条路径上是死代码 ——
   用户点「在地图中打开」完全没反应。→ 按返回值判定，两条都没打开才提示。
