# Story 3.1: 灯箱上提为共享组件并全屏化

Status: review

## Story

As a 用户，
I want 点开图片时它铺满整个屏幕，
so that 我能看清细节，而不是在一个留着顶栏的小框里看。

---

> **现状**：`_Lightbox` 是 `content_detail_page.dart` 内的私有 Widget，整页推入 + 黑色 AppBar（返回箭头 + 居中页码），**保留系统状态栏，不是沉浸态**，图片在剩余区域 `BoxFit.contain`。2026-08-28 用户对比小红书确认：问题就是「点开放大不是全屏放大」。
>
> **本 story 同时是批次 B1 的前置交付物** —— FR-112 场所照片直接接入本组件。因此接口设计不是内部实现细节。
>
> 建议排在 Epic 2 之后（详情页结构重排完再搬，只搬一次）。

---

## Acceptance Criteria

### AC1 — 全屏沉浸态（L2）

**Given** 详情页任一张图
**When** 点击打开查看器
**Then** 隐藏 AppBar，内容延伸至状态栏区域 `[L2]`
**And** 只保留悬浮的关闭 ✕（左上）与页码指示 `[L2]`
**And** 图片铺满屏幕宽度 `[L2]`

### AC2 — 页码胶囊（L2）

**Given** 多图内容
**When** 打开查看器
**Then** 页码为顶部居中的悬浮胶囊（如「3/9」），替代原黑色 AppBar 标题 `[L2]`
**And** 初始页为用户点击的那一张 `[L2]`

### AC3 — 退出恢复系统栏（L2）

**Given** 查看器已打开
**When** 以任意方式退出（✕ / 手势 / 系统返回键）
**Then** 系统状态栏恢复正常 `[L2]`
**And** **异常退出路径同样恢复**，不留下无状态栏的界面 `[L2]`

### AC4 — 🔴 组件接口（L0）

**Given** 查看器组件
**When** 被调用
**Then** 接口只接受：图片 URL 列表、初始下标、`heroTagPrefix`、`source` `[L0]`
**And** **不接受也不感知**内容帖 / 场所 / 任何业务实体 `[L0]`
**And** 组件位于共享层，`content` 与后续 `places` 两侧均可接入，不产生跨模块依赖 `[L0]`

> 🔴 后两个参数**是必需的，不是耦合**：
> - `heroTagPrefix` —— 飞入动画要 Hero tag。**从 URL 推导会炸**：B1 场所页是「头图 + 照片网格」，同一张图出现两次 → 同 tag 同屏 → Flutter 直接抛异常。
> - `source` —— 否则 `lightbox_opened` 无法区分帖子与场所，**FR-115 的指标从 B1 上线起就断裂**。这是对 AD-A23「不得增删属性」的**已登记显式例外**。

### AC5 — 🔴 两条既有 bug 修复必须保留（回归保护，L2）

**Given** 改写完成后回归
**Then** **单击图片或黑边即关闭**仍然有效（bug 20260701-192 的修复，代码注释在案） `[L2]`
**And** **单图进入查看器后仍可左右翻页**仍然有效（bug 20260727-372） `[L2]`

> 改写时顺手删掉就是回归。AD-A15 原先只列了悬浮控件与四个手势，没点名这两条。

### AC6 — 明确不做（L0）

**Given** 查看器内任一张图
**When** 长按
**Then** 不提供保存到相册 `[L0]`

> 理由：盗用顾虑 + 相册权限 + 与分享卡定位冲突。要保存只能走带水印的分享卡。

### AC7 — 不扩散（L0）

**Then** **不为场所场景做任何特化**（B1 工程师在其基础上接入） `[L0]`
**And** 不改动问诊病例图查看器与分享卡预览 `[L0]`
**And** 手势（属 3.2）与动画/加载态（属 3.3）不在本 story `[L0]`

**L0 已钉住的（复审时不必重复人工检查）**：

1. **接口只有四个参数**，且正则断言「多一个就红」—— 这是 AD-A14.2 的执行者。多一个 `postId` / `placeId`，组件就从通用查看器变回内容模块私有件，B1 要么反向依赖 `content`、要么再写一个灯箱。
2. **不 import 任何 `features/`**，文件在 `lib/shared/`；源码里不出现任何业务实体名。
3. **Hero tag 由 `前缀 + 下标` 拼出，绝不从 URL 推导**（`lightboxHeroTag`）—— B1 场所页「头图 + 照片网格」里同一张图出现两次，URL 相同会让两个 Hero 撞 tag 直接抛异常。
4. **两条既有 bug 修复的结构断言**（opaque + pop、仍走 PageView）。
5. **进沉浸态 / 退出恢复状态栏**：拦平台通道断言。⚠️ 实现细节：`SystemUiMode.manual` 在 Flutter 内部会转成 `setEnabledSystemUIOverlays`，所以断言按「状态栏（`SystemUiOverlay.top`）回来了」写，而不是按方法名。

**本 story 刻意没做（属后续 story，别当成遗漏）**：

- 四个手势（下滑关闭 / 双击缩放 / 放大态防误翻页 / 图内平移）→ **Story 3.2**；
- Hero 飞入飞出、加载态与失败重试、`lightbox_opened` / `lightbox_dismissed` 埋点 → **Story 3.3**。
  `heroTagPrefix` 与 `source` 在本 story 只是**被接住并记下**，3.3 才开始消费 —— 接口先定是因为它同时是 B1 的契约。
- **不为场所场景做任何特化**（AC7）；病例图查看器（`shared/widgets/case_image_viewer.dart`）与分享卡预览一字未动，并有断言钉住前者不依赖新组件。
