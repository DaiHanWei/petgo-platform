# Story 2.2: 详情页图片按原比例通栏

Status: review

## Story

As a 用户，
I want 从首页点进详情时图片不变形，
so that 我看到的还是我拍的那张图。

---

> **要消灭的问题**：详情页当前是 `AspectRatio(aspectRatio: 1)` + `BoxFit.cover`，强制裁成方图、两侧留边。从 Feed 点进详情，**同一张图会从原比例通栏跳变成 1:1 裁切**。
>
> **依赖 Story 2.1**（尺寸由它下发）。
>
> 🔴 **必须调用 Feed 的同一个出口函数**，不许照抄参数另写一套 —— 否则将来一边改了，跳变会重新出现。

---

## Acceptance Criteria

### AC1 — 元素顺序（L2）

**Given** 一条含图内容
**When** 打开详情页
**Then** 元素自上而下为：作者行 → 图片 → 文字 → 互动栏 → 评论区 `[L2]`
**And** 发布时间显示在作者名**下方**（不再在右侧） `[L2]`

### AC2 — 🔴 图片比例走同一套三段口径（L0 / L2）

**Given** 任一张图
**When** 计算图片区高度
**Then** 依次施加：取实际比例 → clamp 到 `0.75~1.34` **闭区间** → 高度护栏 `[L0]`
**And** 三步调用 Feed 使用的**同一个出口函数**（`feed_image_layout.dart`），不另写一套 `[L0]`
**And** 图片通栏全宽出血，不再 1:1 裁切、不再两侧留边 `[L2]`

### AC3 — 高度护栏按详情页重取口径（L2）

**Given** 高度护栏的可视区被减项
**When** 计算
**Then** 按**详情页实测**取值（详情页无底部导航栏、有固定底栏，与 Feed 不同） `[L2]`
**And** **不**照抄 Feed 的数字 `[L0]`
**And** 小屏机（360×640 量级）上极端长图不超出上限 `[L2]`

### AC4 — 多图（L2）

**Given** 一条多图内容
**When** 左右滑动
**Then** 容器高度按**首图**锁定，滑动过程中不变 `[L2]`
**And** 页码角标（右上）与装饰标签（左下）位置维持现状，两角互不遮挡 `[L2]`

### AC5 — 无图分支保留（回归保护，L2）

**Given** 一条无图内容（`detail.imageUrls.isEmpty`）
**When** 打开详情页
**Then** 不渲染图片轮播 `[L2]`
**And** 装饰标签显示为正文下方单独一行胶囊 `[L2]`

### AC6 — 时间显示（L2）

**Given** 一条发布超过 7 天的内容
**Then** 显示绝对日期，复用现成的 `formatDayMonthYear`（输出如「15 Jun 2025」），不新写格式化 `[L0]`
**Given** 未超 7 天
**Then** 显示相对时间 `[L2]`

### AC7 — 存量占位兜底（必做，L2）

**Given** 存量内容（无尺寸）
**When** 打开详情页
**Then** 有占位策略，加载完成前后的高度变化被压到最小 `[L2]`
**And** 占位比例与 Feed 同一套 `[L0]`

### AC8 — 不扩散（L0）

**Then** 不改动底栏（属 Story 2.3） `[L0]`
**And** 不改动评论区（属 2.5 / 2.6） `[L0]`
**And** 不改动灯箱（属 Epic 3） `[L0]`

### Completion Notes List

**已交付（L0 全绿）**

1. **AC1 元素重排**：作者行 → **图片** → 文字 → 互动栏 → 评论区。
   图片前置的理由：详情页是「看图」的页面，正文在图上面会把图挤到首屏之外。
   发布时间**本来就在作者名下方**（既有实现已满足），本次未动。
2. **AC2 走同一个出口函数**：图片比例经
   `resolveDetailImageAspect` → `resolveFeedImageAspect`（Feed 用的那一个）。
   新增的 `detail_image_layout.dart` 是**薄壳**，里面**没有任何比例计算** ——
   它只负责把详情页自己的护栏口径喂进共用出口。
   有一条测试逐张图比对「详情与 Feed 在同一护栏上限下结果完全相等」，
   哪天有人在详情侧偷加一句 clamp，它立刻变红。
3. **AC2 通栏出血**：撤掉 `AspectRatio(1)` 与 `ClipRRect` 圆角；
   滚动容器的横向 padding 撤到各子块上，图片那一块**刻意不包 Padding** ——
   通栏就是靠这一层缺席实现的。圆角是「卡片」的语言，详情页的图不是卡片。
4. **🔴 AC3 护栏口径按详情页重取，未照抄 Feed**。三点不同：
   - 详情页**没有「下一条露出」的概念** → 露出余量这一项整个不存在；
   - **有一条常驻底栏**（评论输入区）—— 但它已不在 `LayoutBuilder` 量到的视口里，
     所以护栏**不再重复扣一次**（`fixedBottomBar` 留成常量只为记录口径）。
     重复扣正是 Feed 那次实机复核抓到的同类错误（条目间隔被两边各记一遍）；
   - 正文不截断，且在图片**下方**，用户可下滚 → 只保留「首屏露出正文第一行」这一点。
   有两条测试反向钉住：`chrome` 常量**不得等于** Feed 的，且同一视口下详情页上限**必须更宽松**。
5. **AC4 多图按首图锁定**：`AspectRatio` 取 `sizes.first`，左右滑动时容器高度不变。
   按当前页算会让容器随翻页忽高忽低、正文跟着上下跳。页码角标（右上）与装饰标签（左下）位置未动。
6. **AC5 无图分支保留**：`imageUrls.isEmpty` 时不渲染轮播，装饰标签仍是正文下方单独一行胶囊。
7. **AC6 时间**：超过 7 天改显示绝对日期，复用现成的 `formatDayMonthYear`（如「15 Jun 2025」），
   **未新写格式化**。7 天以内维持相对时间。「173 天前」读者换算不过来，而详情页常有很久以前的内容。
8. **AC7 存量占位**：无尺寸 → `kFeedPlaceholderRatio`（与 Feed **同一个常量**）。
   存量内容不会回填尺寸（v1.1.6 AD-5），占位不可取消。

**范围边界（按 AC8）**

- 未改底栏（属 2.3）、未改评论区（属 2.5/2.6）、未改灯箱（属 Epic 3）。
- `feed_image_layout.dart` **只读复用、一字未改**（含 `ImageSize` ——
  它没有重写 `==`，测试里因此逐字段比对，给它加值语义不在本 story 范围内）。

**⚠️ 需真机复核的数值（不是"做完了"，是"待定"）**

`DetailImageMetrics` 的三个常量（`authorRow=52` / `gapAboveImage=12` / `bodyPeek=34`）
是**按当前布局推算**的，不是实机量的。Feed 那组常量当初也是推算值，2026-08-18 小屏实机复核后
`kFeedRevealMargin` 从 56 改成了 40 —— 本组同样需要这一步。判据不是数字本身，而是那句可观测的：
**小屏机上极端长图不超出上限，且图片下方至少能看到正文第一行**。
