Status: ready-for-dev

> 自包含 story，可本地或云端 L0 执行。与用户沟通用中文。执行纪律见根 `CLAUDE.md`（后端 → 前端 → 联调、AC 标 L0/L1/L2、Flyway **时间戳版本号**、打包一律 `mvn -B clean package`）。

> 🔴 **前置：admin 主题 Epic 10 完成。** 本 story 改的是 `templates/admin/shop-product-form.html` 这一页，而 admin 主题 Epic 10（Story 10.3，B16 商品管理）要把它整页迁到模板体系。**Epic 10 之前动它 = Epic 10 迁移时整体返工**（架构 delta §1「与 admin Epic 10 的边界」）。若代码冻结时 Epic 10 未完成，本 story 随第二批整组顺延（SD-16）。

## Story

As a 平台，
I want 驱虫保健类商品的每个规格能登记药品注册号，
so that 我们在印尼农业部对该品类的管辖要求下能拿得出这个号。

## Acceptance Criteria

**AC1 · 加列 `shop_skus.drug_reg_no`** `[L0]`
**Given** `shop_skus` 今天没有任何注册号列
**When** 新增一支 Flyway 迁移
**Then** 列定义为 `drug_reg_no VARCHAR(40) NULL`（AD-S12 原文口径）`[L0]`
**And** 迁移文件名为**时间戳版本号** `V<yyyyMMdd_HHmm>__add_shop_sku_drug_reg_no.sql`，取创建时刻（CLAUDE.md 纪律 5 / 架构 F-2）`[L0]`
**And** 🔴 **不加 CHECK 约束、不加唯一索引**：注册号格式由农业部规则决定、本版没有权威格式表；加错的 CHECK 会在运营录真号时把人挡在门外，而放宽 CHECK 要再走一次 `DROP+ADD` 全量重建 `[L0]`
**And** 列注释写明「印尼农业部药品注册号（SHOP-FR-21）；**仅驱虫保健（OBAT_VITAMIN）品类使用**；本版不区分处方/非处方（OD-8）；**有效期是批次属性、本版不做**（SD-18）」`[L0]`
**And** `bash scripts/ci/check-flyway-versions.sh origin/main` 通过 `[L0]`

**AC2 · 实体与表单字段** `[L0]`
**Then** `ShopSku` 增 `@Column(name = "drug_reg_no", length = 40) private String drugRegNo;`，位置紧随 `netWeightG`（:48-49）之后、`costPrice`（:55-56）之前 —— 🔴 **别放在 `costPrice` 后面**，那会让下一个人以为它和进货价一样受 `shop.cost_view` 门控 `[L0]`
**And** `apply(...)` 签名扩展以承载它；`create(...)` 是否带该参数由实施者决定，但**两条路径必须都能写入**（否则新建的 SKU 永远填不上号）`[L0]`
**And** `ShopSkuForm`（:16-23）增 `private String drugRegNo;` + getter/setter `[L0]`
**And** 🔴 **`updatable` 保持默认（可更新）**：注册号会换发，不是 `publicToken`/`productId` 那种钉死字段 `[L0]`

**AC3 · 后台表单：仅驱虫保健品类展示该字段** `[L0]`
**Given** 商品的品类挂在 `ShopProduct.category`（`ShopProduct.java:48`），SKU 上没有品类
**When** 打开某商品的编辑页
**Then** 该商品品类为 **`OBAT_VITAMIN`（驱虫保健）** 时，「新增/编辑规格」表单（`shop-product-form.html:250-289`）出现「注册号」输入行，且 SKU 只读表格（`:224-244`）多出「注册号」一列 `[L0]`

**And** 判据来自 Controller 放进 Model 的一个布尔（建议 `showDrugRegNo`），模板里**不写 `${product.category.name() == 'OBAT_VITAMIN'}` 这类表达式** —— 判据必须只有一处，7-1 品类改表时只改那一处（见 Context 现状二）`[L0]`

## Dev Notes

### 🔴 为什么不顺手把有效期一起加了

这一节存在的唯一目的，是拦住「反正都改这张表了，顺手加个 `expiry_date` 吧」这个念头。

**SD-18 原文**：「本版只做注册号，有效期不做（**有效期是批次属性，做对需批次管理**）。」

展开讲：注册号是**SKU 的属性**——同一个规格的药，注册号永远是同一个，放在 `shop_skus` 上语义正确。
有效期不是。同一个 SKU **每一批进货的效期都不同**，仓里同时躺着三个批次就有三个效期。把它塞进 `shop_skus` 只能存到一个值，那个值：

- 发货时不知道该发哪一批 → 对不上；
- 盘点时不知道哪一批要先出 → 先进先出做不了；
- 过期预警报的是一个跟实物无关的数字 → 比不报更危险。

做对它需要**批次模型**（批次表 + 库存按批次分桶 + 出库按批次扣减 + 先进先出），那是一整条工作线，不是一列。
所以本版的选择是：**宁可没有，也不要一个假的。** 一个恒定不准的效期字段会让运营以为「系统管着效期」，而实际上没有。

⚠️ 同理不要把 `ShopProduct.shelfLifeNote`（`ShopProduct.java:99`，len120，商品级**文字说明**，如「保质期 24 个月」）改写成批次效期 —— 它今天是文案，改成日期会静默改变全部历史行的语义。

### 品类语义：`OBAT_VITAMIN` = 驱虫保健

SD-15 已经就这件事更正过一次决策日志：「品类中文名以代码为准更正：`OBAT_VITAMIN`＝驱虫保健，`PERAWATAN`＝洗护。」
代码里的权威出处是 `ProductCategory.java:12-13` 的 javadoc。**后台三语文案按此**：印尼语用 `Obat & Vitamin`（枚举名本身就是印尼语），中文写「驱虫保健」，英文按运营既有译法（实施时与 admin 主题的既有译文对齐，不新造）。

### 判据为什么必须收敛到一个方法

Story 7-1（AD-S1）会做这三件事：`shop_categories` 建表、**删 `ck_shop_products_category`、用外键取代**、`ProductCategory` 枚举**退出持久层与 DTO**。

也就是说，今天写在模板里的 `${product.category.name() == 'OBAT_VITAMIN'}` 在 7-1 之后会编译不过或语义漂移。判据散在模板 + 控制器 + 服务层三处，7-1 就要找三处；漏一处就是「驱虫保健品类的注册号字段突然不见了」这种没人会立刻发现的 bug。

所以 AC3 把它钉成：**服务层一个方法 → 控制器放进 Model 一个布尔 → 模板只认这个布尔。**

### 不展示 ≠ 不设防

`AdminShopProductController.upsertSku`:270-274 已经给出了范式：

```java
// 🔒 进货价与 SKU 基础字段分开处理：无 cost_edit 权限时表单里的该值被直接丢弃
Long submittedCost = form.getCostPrice();
form.setCostPrice(null);
```

注册号照同一条路走：**模板不渲染 ≠ 请求里不会有这个参数**。运营在 A 商品（驱虫保健）填完注册号，浏览器前进后退到 B 商品（粮）再提交，字段就跟着过去了。丢弃是静默的——这不是攻击，没必要给运营弹一个他看不懂的错误。

### 开放项（实施时确认，本 story 不擅自扩范围）

1. **注册号要不要展示给消费者。** 印尼对该品类的管辖要求里，「登记」与「在售卖页面展示」是两件事。本 story 按 SHOP-FR-21 与 AD-S12 的字面范围只做登记、不下发（AC9）。**若法务复核（OD-8）认定必须展示**，那是一次明确的契约变更（`ShopSkuView` + App DTO + 契约 test 三处，C5），应当另开 story 或在 OD-8 定论时并入本条重做 AC9。**实施时不要自行决定展示。**
2. **注册号格式要不要校验。** 本 story 按 AC1 不加任何格式约束（没有权威格式表）。若后续拿到农业部的号段规则，加校验是**服务层**的事（`validateSku`），不是 CHECK 约束——CHECK 改一次要 `DROP+ADD` 全量重建，而格式规则会变。
3. **多个注册号。** 现设计是一个 SKU 一个号（varchar(40) 单值）。若出现「一个规格有多个批准文号」的真实案例，需要的是另一张表，不是把逗号分隔串塞进这一列。**出现即停手找产品。**
