# Story 1.1: 场所列表与场所本体建模

Status: ready-for-dev

<!-- 版本 v1.3.0 · 主题 batch-b1 · Epic 1 场所发现 · 本 epic 首条 -->

## Story

As a 想找宠物友好场所的用户,
I want 从首页进去看到已经有哪些场所,
so that 我能知道这个功能里已经攒了些什么地方，而不是面对一个空壳。

## Acceptance Criteria

**AC1 — 建表（AD-1）** `[L0]`
`places` 表含：名称 / 类型 / 标签集 / **纬度、经度两个独立数值列** / 文字地址 / 描述 / 照片列表 / 标记人 / 状态 / 不可枚举 token。
- 迁移文件名为 **时间戳版本号** `V<yyyyMMdd_HHmm>__init_places.sql`（取创建时刻），表名带模块前缀
- 表内**不含**任何地图厂商 POI id 列
- 表内**不预留** ⑧ 打卡相关的任何列（那是批次 B2 —— 预留即越界）

**AC2 — 列表接口** `[L1]`
`GET /api/v1/places` 未带坐标时按创建时间倒序，每项含：首图 · 名称 · 类型 · 距离位（此时 `null`）· 标签 · 照片数 · 评论数 · 推荐数 · 不推荐数。
- 列表项一次性**批量**取齐，**无 N+1**
- ⚠️ 本 story 内评论能力尚未交付，故评论数与两个计数**恒为 0**（字段先在契约里定下来，真实计数由 Story 1.8 接上）—— **不是前向依赖**

**AC3 — 对外标识** `[L0]`
返回体**不含自增 id**；场所标识一律是不可枚举 token。

**AC4 — 契约一致性（CROSS-STORY C5）** `[L0]`
后端字段集金标测试 + App 侧线上契约测试同时落地（详见 Dev Notes「契约测试怎么写」）。

**AC5 — 列表页渲染** `[L2]`
库里有场所时按 UX-DR2 渲染列表项（首图 + 名称 + 类型 + 标签 ≤2 个 +N + 照片数/评论数/推荐计数）。

**AC6 — 空态** `[L2]`
库里没有场所时显示空态，文案引导「标记一个场所」，复用既有空态组件。

**AC7 — 首页入口** `[L2]`
Sosial（首页 Feed）顶部新增**场所入口行**（单行导航条：图标 + 文字 + 箭头），点击进入场所列表页。
- ⚠️ **入口与列表页必须同条交付** —— 页面没有入口就不可达、无法验收
- AppBar（品牌标 + 通知铃）、分类 chips、瀑布流、底部 Tab **全部保留原样，一处不改**
- Epic 4 的宠物横滑行将加在本行**之下**，布局已在 UI 稿统一设计，**本 story 不需为其预留占位**

## Dev Notes

### 🔴 三条最容易做错的

1. **不要预留打卡字段。** ⑧ 场所打卡在批次 B2，连 `content_posts` 的场所关联列都不属于本批次。"顺手预留一下"会让 B2 的建模被一个没讨论过的形状绑死。
2. **不要装地理扩展。** 本库**零扩展**（全部迁移里没有一条 `CREATE EXTENSION`）。距离排序是 Story 1.2 的事，口径已在 AD-2 定死为「纯 SQL + 范围粗筛 + 两列索引」。本 story 只要把经纬度**存成两个可建索引的数值列**即可。
3. **入口和页面必须一起交付。** 只做页面不做入口 = 不可达 = 无法验收。

### 契约测试怎么写（AC4 的准确口径）

CROSS-STORY C5 原文写的是「后端 record + App data DTO + App mock + 契约 test 四处同步」。
⚠️ **`mock_backend.dart` 在当前代码里已经不存在了** —— 别去找、别新建。现在的等价做法是两条：

1. **后端**：字段集金标测试（纯 Jackson 序列化，无 DB）
2. **App**：线上契约测试 —— 用后端真实响应的字段名构造 JSON 走一次 `fromJson`，断言解析出**非零值**

> 第 2 条的存在理由（照抄那个测试的注释）：Dart 解析里的 `?? 0` 兜底会把字段名不匹配**悄悄吞掉** —— 页面照常渲染、不报错、日志里什么都没有，只是那个数字永远是 0。V1.1.6 真出过这个事故（后端 `diaryCount` vs 客户端 `happyMomentCount`）。

### Project Structure Notes

- 命名映射链：DB `snake_case` ↔ Java/Dart `camelCase` ↔ JSON `camelCase`；表复数 snake_case；主键 `id`(bigint)；时间戳 `created_at`/`updated_at`(`timestamptz`, UTC)；枚举落库 `varchar` + UPPER_SNAKE
- API 前缀 `/api/v1`，资源小写复数连字符 → `/api/v1/places`
- 错误统一 RFC 9457 ProblemDetail，**绝不外泄堆栈**
- 日志 SLF4J + logback JSON；**禁记 PII / 令牌 / 签名 URL / 位置坐标**（NFR-4）
- `ddl-auto=validate` —— schema 归 Flyway；打包一律 `mvn -B clean package`（不 clean 会把旧迁移一起打进 jar，Flyway 报重复版本启动即崩）

### 验证层级与云端边界

- **L0**：`mvn -B clean package` / `flutter analyze` / `flutter test`
- **L1**：需 Docker + postgres + redis 真跑（AC2）
- **L2**：需模拟器视觉（AC5/6/7）
- ☁️ 云端 headless **只跑到 L0**；L1/L2 留本地，Completion Notes 必须写「L1/L2 待本地验收」，**story 不得标 done**
