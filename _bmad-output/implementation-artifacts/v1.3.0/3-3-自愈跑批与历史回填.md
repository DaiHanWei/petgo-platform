# Story 3.3: 自愈跑批与历史回填（AD-3）

Status: ready-for-dev

> 自包含 story，可本地或云端 L0 执行。与用户沟通用中文。执行纪律见根 `CLAUDE.md`（异步只用 `@Scheduled` + DB 状态机，禁 MQ/调度中间件）。
> 纯后端：1 个 `@Scheduled` 物化器 + 1 个 stag 专用手动触发端点 + 配置项。无迁移、无页面。

## Story

As a 运营，
I want 看板每天自动补齐到昨天的数据，上线当天就能看到 7 月 17 日以来的完整趋势，
so that 不需要任何人手工回填或补跑。

## Acceptance Criteria

**AC1 · 缺日自愈算法**
**Given** `DashboardMaterializer`（`admin/dashboard/service/`）
**When** 运行一次
**Then** 计算 `[petgo.admin.dashboard.backfill-from（默认 2026-07-17）, 昨天(WIB)]` 内 `ops_daily_metrics` 缺失的日期集合（以 `findDistinctReportDates` 差集），按日期升序逐日物化 `[L1]`
**And** 每日 = 18 项 × 口径（9 项双口径 → 27 行）在**一个事务**内写入；任一项失败整日回滚，其余日不受影响 `[L1]`
**And** 已存在的日期不重算、不覆盖（行不可变）`[L1]`

**AC2 · 定时**
**Then** `@Scheduled(cron = "${petgo.admin.dashboard.cron:0 0 1 * * *}", zone = "Asia/Jakarta")`，即每天 WIB 01:00 `[L0]`
**And** 首次部署后第一次运行即完成 D-15 全量回填；模拟「某日失败」后下一次运行自动补齐（OQ-B2）`[L1]`

**AC3 · stag 手动触发**
**Given** `POST /admin/dashboard/materialize`（`@StagOnly`，`hasRole('SUPER_ADMIN')`）
**Then** 同步执行 AC1 一次并返回 `{materializedDates:[…], skipped:n, tookMs}` 的 fragment/JSON（后台内部用，可返 JSON）；生产 profile 下该 Controller **不注册**（Bean 不存在，非 403）`[L1]`

**AC4 · 日志与审计**
**Then** 应用日志只记日期与耗时，不记指标值；不写审计（系统行为）`[L0]`
**And** 单日失败 `log.warn` 含日期与异常类名，不含 SQL 参数值 `[L0]`

**AC5 · 配置**
**Then** `application.yml` 新增 `petgo.admin.dashboard.cron` 与 `petgo.admin.dashboard.backfill-from`（带默认值、可 env 覆盖）；`.env.example` 不需新增（有默认值）`[L0]`

**AC6 · 回归**
**Then** `mvn -B clean package` 通过；既有 4 个 admin 扫描器不受影响 `[L0]`

## Dev Notes

### 🔴 回填与补偿是同一段代码

不写单独回填脚本、不写手工补偿入口。「找缺日 → 逐日物化」这一个循环既完成上线首日的全量回填（起点 2026-07-17 = 参考 SQL 创建日），也在某天跑批失败后于次日自动补上。运维动作为零，这是 AD-3 的核心。

### 🔴 昨天 = WIB 的昨天

`LocalDate.now(ScheduleWindow.WIB).minusDays(1)`。cron 也用 `zone = "Asia/Jakarta"`（既有扫描器多用 UTC，本处必须 WIB：01:00 WIB 才保证「昨天」已完整）。不要用 `LocalDate.now()`（容器 UTC）。

### 🔴 单日一事务，跨日互不影响

18 项里有 LATERAL 全表打分（#11 #12），单日耗时可能数秒；用 `TransactionTemplate` 而非方法级 `@Transactional`，避免整个回填 50+ 天一个巨事务。失败日只记 warn，下次再补。

### 🔴 `@StagOnly` 是本版第一处 profile 门控

架构把 `@StagOnly` 定为 `admin/shared` 横切件（结构树已列）。现有代码没有 `@Profile("stag")` 用法，B12「模拟回调」的门控方式需 dev 时读 `AdminPaymentController` 核实；本 story 以 `@Profile("stag")` 组合注解建立第一处，Story 2.2（STAG 角标）与 8.5（模拟回调改造）复用。stag 环境 profile 名以 `scripts/deploy-backend-stag.sh` 注入的 `SPRING_PROFILES_ACTIVE` 为准，dev 时核对。
