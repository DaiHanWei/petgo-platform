# Story 2.4: 自己视角的主页

Status: review

## Story

As a 想看看别人眼里我的主页长什么样的用户,
I want 打开自己的主页看到同一套页面,
so that 我知道别人看到的是什么，也能顺手去改我的资料。

## Acceptance Criteria

**AC1 — 同页两视角** `[L2]`
自己看自己的主页用**同一套页面**，由接口下发的"是否本人"标识切换。

**AC2 — 无「···」** `[L2]`
顶栏**没有「···」**（不能对自己举报/拉黑）。

**AC3 — 编辑资料入口** `[L2]`
多一个「编辑资料」入口，位置在**身份行内、与头像同一行**，不塞进顶部 AppBar。
点击跳既有的资料编辑抽屉（头像 + 昵称可编辑 + 邮箱只读），**不重画**。

**AC4 — 运营标签照常显示** `[L2]`
自己看自己的主页时运营用户标签**照常显示**（自己也是被打标签的用户，不该因为是自己就消失）。

**AC5 — 「我的」Tab 不动** `[L0]`
「我的」Tab **保持现状、一行不改**；公开主页是独立展示页。

### Completion Notes List

**已交付（L0 全绿）**

1. **同页两视角**（AC1）：自己看自己的主页走**同一套页面**，由服务端下发的 `self` 切换。
   两种视角的差别**只有两处** —— 顶栏的「···」与身份行内的「编辑资料」，其余（头像 /
   昵称 / 标签 / 加入时间 / 签名 / 两个计数 / 宠物区 / 内容区）一字不差。
   🔴 `self` **信服务端**：客户端拿本地 id 自己比的话，两边口径迟早会漂（有一条用例钉着这点）。
2. **无「···」**（AC2）：自己视角顶栏不渲染它（不是渲染后禁用）。
3. **编辑资料入口**（AC3）：位置在**身份行内、与头像同一行**，**不塞顶部 AppBar** ——
   AppBar 那个槽位在他人视角上是「···」，两种视角共用一个槽位会让人第一眼分不清在看谁的主页。
   点击跳**既有**抽屉（头像 / 昵称 / 签名 / 只读邮箱），**一个像素没重画**。
   改完回到主页会重新取数（否则「我的」Tab 已经是新昵称、主页还是旧的，两处对不上更糟）。
4. **运营标签照常显示**（AC4）：自己也是被打标签的用户，不该因为是自己就消失。
5. **「我的」Tab 不动**（AC5）：见下面那一节。

**🔴 AC5 怎么做到的：抽取，不是复制**

AC3 要的是「跳**既有**抽屉、不重画」。而那个抽屉原本是 `me_page.dart` 里的**私有方法**，
主页调不到。两条路：复制一份，或者抽出来。
**复制的代价是没有任何测试会红** —— 昵称长度、签名上限、保存失败提示这些细节两处各改各的，
半年后就长成两个东西。所以抽：

- `_editProfile` / `_changeAvatar` / `_briefErr` / `_avatarSnack` → 新文件
  `me/presentation/profile_edit_sheet.dart`（`openProfileEditSheet` / `changeAvatar`）；
- `_InitialAvatar` → `shared/widgets/initial_avatar.dart`（两个文件都要用它）。

**搬运是逐行的**，除了三处机械改名（`_InitialAvatar`→`InitialAvatar`、
`_changeAvatar`→`changeAvatar`、`Uint8List` 改从 `dart:typed_data` 引入）之外，
字段、文案、校验、保存链路、注释**一字未改**。
两条 L0 测试守着这件事：① 两个页面都调 `openProfileEditSheet`；
② `me_page.dart` 里**不再有**抽屉本体（搜不到 `nicknameField` / `signatureField` /
`meEditSaveButton` / `updateProfile(`）—— 留着一份就等于又有两份实现。

**code-review 复审后修掉的（4 findings 修 3 条，第 4 条按 AC5 有意不改）**

1. 🔴 **主页那条 `ref.invalidate` 缺 `context.mounted` 守卫**：保存请求在途时用户按返回退页，
   这一行就会在已销毁的 ref 上调 invalidate —— riverpod 3 的 `_assertNotDisposed()`
   **是真抛 `StateError`**（不是 assert，release 也抛），而这里没有 catch，出去就是一条
   未捕获异步异常。→ 加守卫。
2. 🔴 **保存资料：`await` 之后才 `ref.read`**。在「我的」Tab 上看不出问题（那个 Tab 常驻），
   但抽屉现在也从**公开主页**弹出 —— 那是一条可 pop 的路由。退页后那次 `ref.read` 抛的
   `StateError` 正好落进外层 `catch (_)`：**服务端已经落库、本地 profile 不更新、
   用户还看不到任何提示**，「我的」Tab 一直显示旧昵称。→ 依赖全部在 await 之前取到手。
3. 🔴 **换头像同型且更严重**：它是 fire-and-forget 挂在「Ganti Foto」上的，要走
   「选图 → 上传 → PATCH」三段异步。上传期间收起抽屉 → 最后一段的 `ref.read` 抛错被吞：
   **图传上去了、`PATCH /me avatarUrl` 根本没发**，而这个函数的注释写着「失败不再静默吞」。
   → 同样把三个依赖提到 await 之前。
4. **昵称清空时整表当 no-op**（用户同时改的签名一并丢弃，且无校验提示、保存按钮不置灰）——
   **本 story 有意不改**：这是从「我的」Tab 原样搬过来的既有行为，而 AC5 / Dev Notes
   都要求本次抽取「行为与字段一字不改」。已在源码里标注 + 在此标出，**留给产品决定**。

> ⚠️ 上面 2 / 3 两条严格说也是既有问题，但**本次抽取正是它们第一次真正可达的时刻**：
> 「我的」Tab 常驻不卸载，公开主页却是可 pop 的路由。所以按新引入的问题修。

**范围边界（有意不做）**

- **「我的」Tab 的呈现与行为一行不改**（AC5）—— 只有"抽取"本身带来的调用点改写。
- **抽屉里不加「从哪儿打开的」分支**：两处的抽屉本来就该长得一模一样。
- 自己视角**不加** email 与相机角标：那两样是「我的」Tab 专属，公开主页两种视角都不给。
