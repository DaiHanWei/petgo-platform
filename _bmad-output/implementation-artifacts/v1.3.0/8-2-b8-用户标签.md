# Story 8.2: B8 用户标签（与内容标签同构，分配入口收进抽屉）

Status: ready-for-dev

> 自包含 story，可本地或云端 L0 执行。与用户沟通用中文。执行纪律见根 `CLAUDE.md`。
> **零端点变更**：五个写端点路径 / 参数不动；页面重构 + 两条 PRD 例外（§5 ③ 第 4 条「分配入口收进抽屉、独立批量分配按钮废除」、第 9 条「标签码自动生成不可填 + 分配记录补起止时间与生效/到期状态列」）。依赖 2.3a / 2.3b。

## Story

As a 运营，
I want 用户标签页只有一张标签表，点一个标签进抽屉就能改它、看它分给了谁、直接加人，
so that 给用户挂标签的动线和内容标签一样，不用在三块区域之间来回找。

## Acceptance Criteria

**AC1 · 主表套模板 B（逐页规格 B8）**
**Given** `/admin/user-tags`
**When** 打开
**Then** 摘要条 **生效标签数 · 生效中分配数**；主表**只有标签一张表**：**徽章预览 ｜ 标签码 ｜ 名称 ｜ 说明 ｜ 生效中分配数 ｜ 状态**（在线 / 已下线）；页面上现状的「新建标签」区块保留为右上「＋新建标签」按钮 → 抽屉表单；**现状「批量分配」区块与「分配记录」筛选区块整体移除**（并入抽屉页签）`[L1]`
**And** 标签码列只读展示 `ut-<id>`，任何表单不再出现标签码输入（代码 09-02 已改自动生成，本 story 只确认 UI 无输入位）`[L2]`

**AC2 · 抽屉页签一「编辑」**
**When** 点行 → `GET /admin/user-tags/{id}/drawer`
**Then** 编辑表单：标签码只读 / 名称（单字段，`name` 必填）/ 说明（`description` ≤140 必填）/ 图标（`iconFile` PNG·WebP，**必传**；编辑时不传 = 保留原图，沿用既有 `AdminTagEditKeepsIconTest` 语义）；**无徽章底色选项**（`UserTagBadgeColor` 已废弃，模板不渲染任何底色控件）；左侧小图预览 = App 最终呈现；未修改时保存钮禁用 `[L2]`
**And** 底部操作条：下线 / 重新上线（`POST /admin/user-tags/{id}/retire`，`retired` 参数；下线 data-confirm 复述「生效中分配数 N，下线后这些分配随之失效」）`[L1]`

**AC3 · 抽屉页签二「分配记录」**
**Then** 列 **用户 ｜ 分配时间 ｜ 起止时间（WIB，结束空 = 永久）｜ 状态（生效中 / 已到期 / 隐藏原因）｜ 操作人 ｜ 移除**；数据源 `UserAssignmentRow`（startsAt / endsAt / visible / hiddenReason），状态由 `now` 与 startsAt/endsAt 推导；账号已注销的行显示「永不展示」并只留移除 `[L2]`
**And** 「＋添加用户」= **分配唯一入口**：打开多选用户选择器（复用现状 `GET /admin/user-tags/pick?q=` 候选片段，注销账号不可选、虚拟账号标注），选人 + 生效起止（`startsAt` 必填 / `endsAt` 可空）→ `POST /admin/user-tags/assign`（`tagId` 定死为当前抽屉标签，`pickedUserIds` / 兜底 `userIds` 文本）；「单用户最多 3 个标签、满 3 顶掉最早」预告与确认复述原样保留 `[L1/L2]`
**And** 移除：`POST /admin/user-tags/assignments/{id}/remove` `[L1]`

**AC4 · 新建流程**
**When** 右上「＋新建标签」抽屉表单提交 `POST /admin/user-tags`（name / iconFile 必传 / description）
**Then** 成功后自动打开新标签抽屉并停在「分配记录」页签（`?open=<newId>&tab=assign`）`[L2]`

**AC5 · 端点与权限零变更**
**Then** `GET /admin/user-tags`（VIEW = `user_tag.view`）、`POST /admin/user-tags`、`POST {id}/edit`、`POST {id}/retire`、`GET /admin/user-tags/pick`、`POST assign`、`POST assignments/{id}/remove`（均 MANAGE = `user_tag.manage`）——路径与参数名不变；仅新增 `GET /admin/user-tags/{id}/drawer`（VIEW）`[L0]`
**And** 无 MANAGE 权限：抽屉内所有按钮禁用并注明所缺权限；无 VIEW：菜单不渲染 `[L1]`

**AC6 · 三语与回归**
**Then** 新增文案 `admin.v130.utags.*` 三语同批；既有 `AdminUserTagIntegrationTest`、`AdminTagEditKeepsIconTest` 全绿；新增四条 MockMvc `[L0/L1]`

## Dev Notes

### 🔴 「分配唯一入口」是动线收拢，不是功能删除
`POST /admin/user-tags/assign` 端点与参数（`pickedUserIds` / `userIds` / `tagId` / `startsAt` / `endsAt`）一个不动，`tagId` 由抽屉隐藏字段定死。多选、顶掉最早、注销不可选三条既有能力必须在抽屉内原样可用——写操作清单核对时这条端点必须仍在。

### 现状代码要点

| 文件 | 现状 | 改什么 | 保留 |
|---|---|---|---|
| `admin/usertag/web/AdminUserTagController.java` | `GET /admin/user-tags(tagId,userId)`、`POST /admin/user-tags(name,iconFile,description)`、`POST {id}/edit`、`POST {id}/retire(retired)`、`GET pick(q,page)`、`POST assign(pickedUserIds,userIds,tagId,startsAt,endsAt)`、`POST assignments/{id}/remove`；VIEW/MANAGE 用 `AdminPermissions.USER_TAG_VIEW/MANAGE` | + `GET {id}/drawer`；POST 加 `HxRequest` 分支 | 全部端点签名 |
