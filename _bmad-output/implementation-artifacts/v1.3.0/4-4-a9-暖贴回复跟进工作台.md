# Story 4.4: A9 暖贴回复跟进工作台

Status: review

> 自包含 story，可本地或云端 L0 执行。与用户沟通用中文。执行纪律见根 `CLAUDE.md`。
> 后台页面（模板 A）+ 两个写端点；无迁移（表在 4-3）、无 App 端改动。

## Story

As a 运营，
I want 在待办中心看到待跟进队列，右栏直接以被回复的虚拟账号身份回复或标记已读，
so that 暖贴闭环不反噬。

## Acceptance Criteria

**AC1 · 导航与页面**
**Given** `/admin/warm-replies` 套模板 A（UI 稿 1-12）
**Then** 待办中心组第 6 项「暖贴回复跟进」，角标 = 待跟进数（`WarmReplyQueueService.pendingCount()` 并入 `GET /admin/nav/badges` 聚合）；权限 `comment.virtual_post`（无权限不渲染菜单）`[L1]`
**And** 页签「待跟进｜已跟进（近 30 天）」各带计数 `[L2]`

**AC2 · 左栏队列**
**Then** 每行两行式：第一行 = 虚拟账号昵称 +「收到回复」+ 状态点（🔵）；第二行 = `帖 #<postId> · <真实用户昵称> 回复了暖评` + 相对时间（`last_reply_at`）；多条回复合并显示「+N 条新回复」 `[L2]`
**And** 默认 `last_reply_at` 倒序；每页 20 滚动加载 `[L1]`

**AC3 · 右栏**
**Then** 帖子卡（`#postId` + 正文摘要 + 作者昵称 + 可见评论数 + 「查看帖子 ↗」开 B1 抽屉）→ 评论线程（该虚拟一级评论 + 其下全部可见二级，时间正序；**入队后新收到的真实回复高亮**）→ 常驻回复区：`以 @<虚拟昵称> 继续回复（身份锁定为被回复账号）` 只读标签 + 文本框（≤200）+ 「发布回复」（空内容禁用）+ 「标记已读（不回复）」 `[L2]`
**And** 身份**不可切换**（无下拉）`[L2]`

**AC4 · 发布回复 = 二级评论走同链路（D-4）**
**Given** `POST /admin/warm-replies/{id}/reply`（form：`body`、`idempotencyKey`）
**Then** 服务层：项须 PENDING；调用 `CommentService.createReply(parentId = virtual_comment_id, authorId = virtual_user_id, body)`——与 App 端 `POST /api/v1/comments/{parentId}/replies` 同一方法；L1 命中 422 行内 err `[L1]`
**And** 成功后项置 `HANDLED / REPLIED / handled_comment_id`；审计 `COMMENT_VIRTUAL_POST`（同 4-2 摘要规则）；回复本身进审核链，通过后真实用户收「有人回复了你的评论」通知（既有 `ContentNotifyListener` 分支）`[L1]`
**And** 200 + 右栏 fragment（线程内该回复标「审核中」）+ `hx-swap-oob` 移除左栏行 + 页签计数 + `HX-Trigger: admin:badge-refresh`；toast「已提交，审核通过后显示」；自动选中下一条（`data-next-id`）`[L2]`

**AC5 · 标记已读**
**Given** `POST /admin/warm-replies/{id}/read`
**Then** 项置 `HANDLED / READ`；审计 `WARM_REPLY_READ`；同上 oob + 角标 + 下一条；无二次确认 `[L1]`

**AC6 · 已跟进页签与边界**
**Then** 已跟进 = `status=HANDLED AND handled_at >= now()-30d`，只读：处置徽标（已回复 / 已读）+ 操作人 + 时间；线程仍可看，操作区不渲染 `[L2]`
**And** 帖子已删或虚拟评论已删：右栏快照占位「内容已删除」，只允许「标记已读」 `[L1]`
**And** 队列空态「队列已清空 🎉」+「其他队列还有 N 条」去向提示（2.9 通用件）`[L2]`
**And** 有查看权无 `comment.virtual_post`：不渲染菜单（本页查看权即 `comment.virtual_post`，不另设只读码）`[L1]`

**AC7 · 三语 + 测试**
**Then** key `admin.v130.warmReplies.*` 三包同批；切 ID 无截断 `[L0/L2]`
**And** MockMvc：整页 200 / `HX-Request` fragment / reply 成功 / reply 空内容 422 / 已 HANDLED 项再操作 409→422 fragment / 无权限 403 `[L1]`

## Dev Notes

### 🔴 回复是二级评论，`parentId` 就是那条虚拟一级评论

`CommentService.createReply(parentId, authorId, body)`：`parent` 存在且未删 → `requireVisible(post)` → L1 校验 → 落 `UNDER_REVIEW`，`topLevelParentId` = parent（它本来就是一级）。传 `parentId = followup.virtual_comment_id`、`authorId = followup.virtual_user_id` 即可。真实用户再回这条二级，`parentAuthorId` 仍是虚拟账号（一级作者）→ 4-3 又会入队，闭环成立。

### 🔴 身份锁定是防串人设，别给运营留切换口

UI 稿 1-12 明写「身份锁定为被回复账号，不可切换」。服务层也**不接收** `virtualUserId` 参数，只从 followup 行取——前端改不了。

### 「新回复高亮」的判定

线程里哪几条是「运营还没看过的」：`comment.created_at >= followup.created_at` 且作者为真实用户。HANDLED 后再看不高亮（已跟进页签只读）。不需要额外「已读游标」列。

### 与 2.9 联调的接口

- 角标聚合：2.9 的 `GET /admin/nav/badges` 单条聚合查询里加一项 `warmReplies = pendingCount()`。
- 空态去向提示、权限禁用态、两态页签为模板 A 通用件（2.3b / 2.9），本页只填内容。
- 计数同源：页签计数与角标都读 `pendingCount()`。
