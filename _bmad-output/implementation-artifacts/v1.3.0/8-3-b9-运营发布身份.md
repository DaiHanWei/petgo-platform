# Story 8.3: B9 运营发布身份（双区块页套模板 B）

Status: ready-for-dev

> 自包含 story，可本地或云端 L0 执行。与用户沟通用中文。执行纪律见根 `CLAUDE.md`。
> **零端点变更**：两组控制器（虚拟账号 / 真实账号身份池）的写端点与确认页语义全部保留，只做形态重构。依赖 2.3a / 2.3b。

## Story

As a 运营，
I want 「运营发布身份」页两块（虚拟账号、真实账号身份池）都有摘要条与抽屉，建号、启停、改物种、纳入、移出都在页内完成，
so that 管理马甲和授权真人账号的动线与其他列表页一致。

## Acceptance Criteria

**AC1 · 区块一 · 虚拟账号（模板 B）**
**Given** `/admin/virtual-accounts`
**When** 打开
**Then** 摘要条 **虚拟账号数 · 启用中 · 累计已发布**；筛选：关键词 `q` + 物种下拉 `species`（`data-autosubmit`）；表格列 **ID ｜ 昵称 ｜ 头像 ｜ 状态 ｜ 已发布 ｜ 账号物种定位 ｜ 建号人**；右上「＋新建虚拟账号」→ 抽屉表单（`nickname` ≤20 必填 / `avatarFile` 可选 / `avatarUrl` 兜底折叠 / `accountSpecies` 必选）`[L1/L2]`
**And** 点行 → 抽屉 `GET /admin/virtual-accounts/{id}/drawer`：资料 + 物种定位改写（`POST {id}/species`，`accountSpecies`）+ 启停（启用 `POST {id}/enabled enabled=true` 无确认；**禁用**保留现状确认语义——弹层内展示待发布排期数 N 与「查看这些排期」链接（复用 `pendingScheduleCount` 口径），确认后 `POST {id}/enabled enabled=false`）`[L2]`

**AC2 · 区块二 · 真实账号身份池**
**Then** 搜索并纳入：`q`（用户 ID 或昵称，显式「搜索」钮）→ 候选表（ID / 昵称 / 状态 / 授权说明输入 / 纳入）→ `POST /admin/publish-identities`（`userId` + `authorizationNote` 必填 ≤500）；已在池内的候选显示「已在池内」禁用 `[L1/L2]`
**And** 池内表列 **ID ｜ 昵称 ｜ 头像 ｜ 授权说明 ｜ 纳入时间 / 纳入人 ｜ 状态 ｜ 经后台发布 ｜ 物种推导 ｜ 操作**；「移出」→ 确认弹层复述引用数（待发布排期 N + 「查看这些排期」链接）→ `POST /admin/publish-identities/{userId}/remove`；**被种子内容引用的身份不可移出**（按钮禁用 + 提示引用数，现状规则）`[L1/L2]`

**AC3 · 确认页并入弹层，路由退役**
**Then** 现状 `GET /admin/virtual-accounts/{userId}/disable` 与 `GET /admin/publish-identities/{userId}/remove` 两个**确认页 GET 路由**并入抽屉 / 弹层（fragment 返回同一确认内容），随后退役；两个 `POST` 端点不变；`publish-identity-confirm.html` 若无其他引用则删除（`seed-post` 的身份确认页 `publish-identity-select.html` **不在本 story 范围**，勿动）`[L1]`

**AC4 · 端点与权限零变更**
**Then** 虚拟账号：`GET /admin/virtual-accounts`（VIEW = `virtual_account.view` or `virtual_account.manage`）、`POST /admin/virtual-accounts`、`POST {id}/species`、`POST {id}/enabled`（均 `virtual_account.manage`）；真实账号：`POST /admin/publish-identities`、`POST {userId}/remove`（`seed.publish_as_real`）——路径参数权限不变；仅新增 `GET /admin/virtual-accounts/{id}/drawer`（VIEW）与确认 fragment 端点 `[L0]`
**And** 两块按各自权限渲染：无 `seed.publish_as_real` 时区块二整块不渲染（现状 `sec:authorize` 语义）`[L1]`

**AC5 · 三语与回归**
**Then** `admin.v130.publishIdentity.*` 三语同批；`AdminVirtualAccountIntegrationTest`、`AdminPublishIdentityIntegrationTest` 全绿；MockMvc 四条 `[L0/L1]`

## Dev Notes

### 🔴 双控制器、双权限，别合并
区块一 `AdminVirtualAccountController`（`virtual_account.*`）与区块二 `AdminPublishIdentityController`（`seed.publish_as_real`）是两套权限（UI 稿 3-12 备注）。套模板时两块各自 `sec:authorize`，不得把区块二挂到 `virtual_account.manage` 下。

### 🔴 禁用 / 移出的确认语义是业务护栏，不是装饰
现状确认页 `publish-identity-confirm.html` 的核心是「该账号还有 N 条待发布排期，禁用/移出后这些排期会怎样」+ 「查看这些排期」链接（`SCHEDULE_LIST_PATH?authorId=`）。并入弹层后这段信息必须原样呈现；只有禁用要确认，启用不要（控制器注释明写）。

### 现状代码要点

|---|---|---|---|
| `admin/virtual/web/AdminVirtualAccountController.java` | `GET /admin/virtual-accounts(q,species)`、`POST /admin/virtual-accounts(nickname,avatarUrl,avatarFile,accountSpecies)`、`POST {id}/species(accountSpecies)`、`POST {id}/enabled(enabled)`；AUTH = `virtual_account.manage`，VIEW_AUTH = view or manage | + `GET {id}/drawer`；POST 加 `HxRequest` 分支 | 端点签名 |

### 「已被种子内容引用的身份不可移出」
现状由服务层判定（引用数 > 0 拒绝）；抽屉里按钮禁用 + 提示引用数只是前置提示，服务层拒绝逻辑不动，422 走行内 err。

### 测试标准
沿用 `AdminVirtualAccountIntegrationTest` / `AdminPublishIdentityIntegrationTest`；新增 MockMvc 四条。

### Project Structure Notes
改动在 `admin/virtual/**` + 两个模板；无迁移。`publish-identity-select.html`（种子发布身份确认页，属 E1）不动。
