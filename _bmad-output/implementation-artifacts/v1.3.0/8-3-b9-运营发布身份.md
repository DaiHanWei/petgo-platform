# Story 8.3: B9 运营发布身份（双区块页套模板 B）

Status: review

> 自包含 story，可本地或云端 L0 执行。与用户沟通用中文。执行纪律见根 `CLAUDE.md`。
> **零端点变更**：两组控制器（虚拟账号 / 真实账号身份池）的写端点与确认页语义全部保留，只做形态重构。依赖 2.3a / 2.3b。

## Story

As a 运营，
I want 「运营发布身份」页两块（虚拟账号、真实账号身份池）都有摘要条与抽屉，建号、启停、改物种、纳入、移出都在页内完成，
so that 管理马甲和授权真人账号的动线与其他列表页一致。

## Acceptance Criteria

**AC1 · 区块一 · 虚拟账号（模板 B）**
**Given** `/admin/virtual-accounts`
**When** 打开
**Then** 摘要条 **虚拟账号数 · 启用中 · 累计已发布**；筛选：关键词 `q` + 物种下拉 `species`（`data-autosubmit`）；表格列 **ID ｜ 昵称 ｜ 头像 ｜ 状态 ｜ 已发布 ｜ 账号物种定位 ｜ 建号人**；右上「＋新建虚拟账号」→ 抽屉表单（`nickname` ≤20 必填 / `avatarFile` 可选 / `avatarUrl` 兜底折叠 / `accountSpecies` 必选）`[L1/L2]`

## Dev Notes

### 🔴 双控制器、双权限，别合并
区块一 `AdminVirtualAccountController`（`virtual_account.*`）与区块二 `AdminPublishIdentityController`（`seed.publish_as_real`）是两套权限（UI 稿 3-12 备注）。套模板时两块各自 `sec:authorize`，不得把区块二挂到 `virtual_account.manage` 下。

### 🔴 禁用 / 移出的确认语义是业务护栏，不是装饰
现状确认页 `publish-identity-confirm.html` 的核心是「该账号还有 N 条待发布排期，禁用/移出后这些排期会怎样」+ 「查看这些排期」链接（`SCHEDULE_LIST_PATH?authorId=`）。并入弹层后这段信息必须原样呈现；只有禁用要确认，启用不要（控制器注释明写）。

**复审（对抗式）修掉的 5 条 CONFIRMED**（另 2 条已在自查中修掉、1 条属既存缺口，见下）

1. 🔴🔴 **`?section=` 分流绕过了区块二的 `seed.publish_as_real` 门**。区块二在整页上靠模板那句
   `sec:authorize` 遮着，但 section 分流是**独立的 fragment 端点**，那层遮挡在那里不存在，
   而列表方法又无条件查了 `listRealAccounts()` / `searchCandidates(q)`。
   只持 `virtual_account.view` 的运营请求 `?section=identities` 就能拿到**整个真实账号身份池**
   （含**授权说明**、纳入人、经后台发布数），`?section=candidates&q=` 能拿到真实用户搜索结果 ——
   正是本页反复标红的「能管虚拟账号 ≠ 能以真人身份发言」被绕开的那条缝。
   改为：区块二的数据**自己判权限**（没有这个码就压根不查），且这两条 section 直接 403
   （不是回一张空表 —— 空表会被读成「池子是空的」）。
   对应测试原来只查整页 = 假绿，已补上按 section 直取的 403 断言。
2. 🟠 **`admin:identity-list-refresh` 全仓没有任何监听方**（模板里没有 `hx-trigger`、JS 里也没有），
   于是纳入成功后**候选表里那一行仍然是可点的「纳入」按钮**，运营再点一次拿到 422。
   改为**定点 oob 换那一行**（按 id 精确查一次，查不到就不渲染）——
   不整表重拉候选是因为重拉得带上当时的搜索词 `q`，而 POST 请求里没有它。
   那个没人监听的事件常量随之删掉（别留半套）。
3. 🟠 **旧 GET 路径退役后拿到的是 500 而不是 404**：`GET /admin/publish-identities/{id}/remove`
   路径上**同名的 POST 还在**（AC4 要求它逐字不变），路径匹配、方法不匹配 →
   `HttpRequestMethodNotSupportedException` 全仓无人处理 → 落进兜底 handler → 500 + 一条 ERROR 堆栈。
   补了一个 405 的 ProblemDetail handler（带 `Allow` 头）：运营的旧书签拿到的是「该地址不支持这种请求方式」，
   服务端也不再每次刷一条堆栈。测试断言随之改为 405。
4. 🟡 **列表刷新会把筛选丢掉**：刷新 span 的筛选值是**页面渲染那一刻**烤进 `hx-get` 的静态串，
   而筛选本身走 htmx 局部 swap（整页不重载、span 不会被重渲染）。
   筛完 → 在抽屉里改点东西 → 刷新事件按加载时的空筛选重拉 → 表格无声无息跳回全量。
   改为 `hx-include="closest form"`（与 `content.html` / `content-pins.html` 一致；GET 请求 htmx 默认不带 form）。
5. 🟡 孤儿 key 两条（`admin.publishIdentity.confirm.title`、`admin.virtualAccounts.list`）随整页删除后无人引用，已删。

**施工中自查修掉的一处（会让整个抽屉失灵）**

🔴 `th:with="res='virtual'"` 与 `th:replace` 写在**同一个标签**上。Thymeleaf 优先级
`th:replace` = 100、`th:with` = 600，数字小的先处理 ⇒ `th:with` 压根轮不到执行、变量静默消失。
后果：模板 B 壳按默认值把抽屉容器渲染成 `id="item-drawer"`，而抽屉 JS、oob 选择器
（`#virtual-drawer .drawer-body`）与 `?open=` 深链**全按 `virtual-drawer` 找** ——
表现是「点行什么都不发生」，页面上却看不出任何异常。
它比 `th:if` 那条更难发现：条件失效至少会多渲染一块看得见的东西，变量丢失只是让片段拿到默认值。
已修（`th:with` 挪到 `content` 那一层，与其它页一致），并加了第五条 L0 模板守门
`AdminTemplateStructureTest.noTagCarriesBothWithAndReplace`。

**确认弹层的实现选择**

复用既有的原生 `<dialog class="modal">` 基建（`data-open-dialog` / `data-close-dialog` / backdrop 关闭），
只补两个钩子：① htmx **换进来**的 `dialog[data-autoopen]` 也要打开（原来只在 DOMContentLoaded 扫一次，
那是给「服务端校验失败、整页回显」写的）；② 服务端发 `admin:confirm-close` 时收起弹层并清空宿主。

🔴 为什么要一个事件而不是让响应把宿主换空：确认表单的 `hx-target` 必须指向**弹层内部**的错误槽 ——
否则 422（如「被种子内容引用的身份不可移出」）一回来就把整个弹层连同排期提示一起换掉，
运营看到的是弹层凭空消失，而不是「为什么没成功」。成功路径因此没法顺带清宿主，只能靠这个事件。
（8.2 复审刚踩过同一族的坑：htmx 先 oob、后主 swap，主 swap 的目标是发请求时捕获的节点引用。）

**⚠️ 既存缺口（非本 story 引入，但不能按「现状规则已保留」验收）**

AC2 / Dev Notes 写「**被种子内容引用的身份不可移出**（现状由服务层判定，引用数 > 0 拒绝）」——

旧模板的「移出」按钮同样是无条件渲染、不显示引用数。改造前后都如此，属本 story 之前就没落地的 AC。
**留待拍板**：要么补服务层判定 + 按钮禁用态，要么把这条 AC 从规格里撤掉。
