# Story 6.3: D2 运营配置页整体套模板 D

Status: review

> 自包含 story。**纯后台模板层改造，零端点变更**（AB-19A「不动任何功能」）。依赖 2-3a（fragment 响应约定 / `AdminBusinessExceptionAdvice` 422 fragment）与 2-3b（`fragments/tpl-d-config-card.html` 壳 + `admin-core.js` beforeSwap 放行），以及 6-1 / 6-2 已落地的 KTP 卡与档位两表。

## Story

As a 运营，
I want 运营配置页四张卡（问诊定价 / KTP 模块高清图解锁定价 / PawCoin 档位 / 分享奖励）统一为每卡自带保存钮的配置卡，
so that 改哪张存哪张，不会误提交别的组，也不会把 0 或负数存进去。

## Acceptance Criteria

**AC1 · 四卡各自成表单**
**Given** `/admin/config` 套 `tpl-d-config-card`
**When** 打开
**Then** 四张卡：问诊定价（兽医价 / 分成 / AI 解锁价 / 月免费额度）· KTP 模块高清图解锁定价（6-1 三行）· PawCoin（溢价两项 + 暂停充值 + 档位两表 + 新建）· 分享奖励（四项 + 概览）；每卡独立 `<form>`，端点与参数**逐字不变**：`/admin/config/pricing` `/admin/config/ktp-pricing` `/admin/config/pawcoin` `/admin/config/share-reward` `/admin/config/tiers*` `[L1]`
**And** 组头**不标红「高危」**（D-8 拍板，危险感由确认弹层承载）`[L2]`

**AC2 · 保存钮三态**
**When** 卡内任一输入变化
**Then** 保存钮由禁用 → 激活并显示「已修改」标（`admin-core.js` 通用 dirty 检测：`form[data-card]` 内 `input/select` change → 对比初值）；未修改时禁用 `[L2]`
**And** 点保存 → 高危确认弹层复述**每个改动字段的旧值 → 新值**（前端由 `data-initial` 属性与当前值拼出，文案 key `admin.v130.config.confirm.diff`）→ 确认后提交 `[L2]`
**And** 提交成功 toast + 「已修改」标消退（PRG 后重渲染即自然消退）`[L2]`

**AC3 · 校验错误行内呈现**
**When** 服务层抛 `AppException.validation`（如负数、≥1、配比不合）
**Then** 整页提交路径维持现状 flash 回显；**htmx 提交路径**（表单加 `hx-post` + `hx-target="closest form"`）返回 422 卡片 fragment，错误字段红边 + 下方红字，保存钮禁用直到再次修改（UI 稿 7-1 卡二示范）`[L1/L2]`

**AC4 · 权限与只读态**
**Then** `config.view` 无 `config.edit` → 四卡输入只读、保存钮禁用并注明「需 config.edit」（分享奖励卡按其独立的 `config.share_reward_edit` 判）；`config.view` 都没有 → 菜单不渲染、直达 403 `[L1]`

**AC5 · 三语与回归**
**Then** 新 key `admin.v130.config.*`（已修改标 / 确认标题 / diff 模板 / 只读注释）三包同批；切 ID 无截断；既有 config 集成测试全绿；`GET /admin/config` MockMvc 四条（200 / HX fragment / 422 / 403）`[L0/L1/L2]`

## Dev Notes

### 🔴 零端点变更是验收底线

Story 2.1 生成的《后台写操作清单》里 `/admin/config/**` 的 7 个写端点（pricing / ktp-pricing / pawcoin / share-reward / tiers / tiers/{id}/enabled / algo-params 不在本页）路径、参数名、`@PreAuthorize` 一个不动。本 story 改的只是模板与 Controller 的「返回形状」。

### 🔴 「每卡自带保存钮」是 09-01 拍板，全局吸底保存条被否

逐页规格模板 D：未修改禁用 → 修改激活标「已修改」→ 高危确认 → 提交。现状 `config.html` 已经是「每卡一个 form」，本 story 不是合并而是**统一视觉与三态**。

### 🔴 分享奖励卡的权限与别的卡不同

`SHARE_REWARD_VIEW_AUTH` / `SHARE_REWARD_EDIT_AUTH` 是独立码（Story 18.3 AC5），只读态判断不能一刀切用 `config.edit`。
