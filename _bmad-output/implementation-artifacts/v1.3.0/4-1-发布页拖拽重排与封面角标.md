# Story 4.1: 发布页拖拽重排与封面角标

Status: review

## Story

As a 发帖用户，
I want 长按拖动照片调整顺序、并知道哪张是封面，
so that 我不用为了换个顺序把照片删了重选。

---

> **现状**：`publish_compose_page.dart` 的 `_imageRow` 按用户选择顺序排列，**没有任何排序手段**。选错顺序只能删掉重选。
>
> 首图同时决定 **Feed 卡片封面、详情页首图、分享卡主图** —— 三处都由这一个顺序决定。
>
> **零后端、零迁移、零依赖，可随时插队开工。**

---

## Acceptance Criteria

### AC1 — 拖拽重排（L2）

**Given** 发布页已选若干张照片
**When** 长按其中一张
**Then** 该张抬起（放大 + 阴影） `[L2]`
**When** 拖到目标位置并松手
**Then** 其余照片自动让位，顺序更新 `[L2]`

### AC2 — 封面角标（L2）

**Given** 照片网格
**When** 渲染
**Then** 第一张左上角常驻「封面」角标 `[L2]`
**And** 文案为 EN `Cover` / ID `Sampul`（新增 l10n key，项目内无现成） `[L0]`
**And** 重排后角标实时跟随新的第一张 `[L2]`

### AC3 — 顺序只有一份（L0 / L2）

**Given** 用户调整后的顺序
**When** 点击发布
**Then** 按调整后的顺序上传与展示 `[L2]`
**And** 界面顺序与上传顺序是**同一份数据**，不存在两套 `[L0]`
**And** 顺序的唯一住所是发布页的表单状态 `[L0]`

### AC4 — 🔴 上传期锁定（L2）

**Given** 上传已经开始（状态机已取走顺序快照）
**When** 用户尝试拖拽重排
**Then** 重排入口不响应 `[L2]`
**And** 封面角标不再跟随 `[L2]`
**And** 锁定持续到上传结束或失败回到可编辑态 `[L2]`

> 🔴 「上传中还能拖」必然产生两份顺序：界面一份、上传状态机手里的快照一份。

### AC5 — 部分成功后重试（L2）

**Given** 上传部分成功后重试
**When** 继续上传
**Then** 沿用开始时取的顺序快照，**不重新读取表单状态** `[L2]`
**And** 用户若要改顺序，须先整体取消回到可编辑态 `[L2]`

### AC6 — 仅发布前可调（L0）

**Given** 已发布的内容
**When** 查看
**Then** 不提供图片重排入口 `[L0]`

> 已发布内容的图片重排属内容编辑范畴，**本版本不做**。

### AC7 — 网格其余部分不变（回归保护，L2）

**Given** 照片网格
**Then** 3 列布局、虚线添加格、右上角 ✕ 删除均与现状一致 `[L2]`

### AC8 — 不引包（L0）

**Given** `pubspec.yaml`
**When** 本 story 提交
**Then** **未新增任何 reorder 类第三方依赖** `[L0]`

**实现要点（复审着眼处）**：

1. **「顺序只有一份」是靠"冻住 items"实现的，不是靠再存一份快照。** AD-A27.1 说状态机取快照，但真存一份 `List` 就**恰恰造出了第二份数据**，与 AC3「不存在两套」直接打架。这里的做法是：快照 = 被 `_orderLocked` 冻住的 `items` 本身。测试里有一条反向断言：控制器里 `List<ImageUploadItem>` 类型的字段**只能有一个**。
2. **锁的生命周期**：`publish()` 开始即锁；发布成功或抛异常（此时图都传完了，属可编辑态）解锁；**有失败件那条路 `return null` 时不解锁** —— 重试要沿用同一份顺序（AC5）。用户想改顺序，走新增的「取消」入口（`cancelUploadSession`）。
3. **没有「取消」入口的话，一次部分失败会把顺序永久锁死** —— 所以 AC5 的那句「须先整体取消回到可编辑态」在 UI 上必须有个按钮，它就挂在既有的「重试」旁边。
4. **封面角标不落字段**（AD-A16.3）：它只认下标 0，因此重排后天然跟随。测试断言控制器里没有 `coverIndex` / `setCover` 之类的东西 —— 另设字段迟早出现「界面第一张是 A、封面却是 B」。
5. **自实现，零依赖**：`LongPressDraggable` + `DragTarget`（Flutter SDK 自带）。测试扫 `pubspec.yaml` 确认没有 reorder 类包。
6. **AC6 不扩散**：`reorderImage` 全仓只出现在控制器与发布页两处（有断言）——已发布内容的图片重排属内容编辑范畴，本版本不做。
