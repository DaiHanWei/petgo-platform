# Story 1.5: 角色配置页（AB-21A）

Status: ready-for-dev

> 自包含 story，可本地或云端 L0 执行。与用户沟通用中文。执行纪律见根 `CLAUDE.md`。
> 本 story = 新页面 `/admin/roles`（列表 + 整页权限矩阵）+ 服务层 + 一支迁移（解决 1-4 开放问题 ①）+ `AdminPageCatalog`（页面目录，Epic 2 导航与 1-6 权限面板复用）。**功能在现有页面样式上落地**，套模板 B 归 Story 6.5。
> **依赖 1-4**（表与 resolver）、**1-1**（`bumpSecurityVersion`）。

## Story

As a 超级管理员，
I want 在「安全 → 角色配置」查看和编辑四个预置角色的权限、新建和删除自定义角色，
so that 岗位权限调整不再需要改代码发版。

## Acceptance Criteria

**AC1 · 页面与门控**
**Given** `GET /admin/roles`，`@PreAuthorize("hasRole('SUPER_ADMIN')")`（**仅超管**；epics 与就绪度评审确认）
**Then** 列表列：角色名称 / 类型（系统预置 · 自定义）/ 权限数 / 使用中账号数 / 操作；顶部摘要「角色总数 · 系统预置 · 自定义」；右上「＋新建角色」（UI 稿 7-8）`[L1]`
**And** 预置角色名称用 `#{role.<CODE>}` 三语，操作只有「编辑权限」；自定义角色显示 `name` 单语，操作「编辑」「删除」 `[L2]`
**And** 非超管访问 → 403；导航项「角色配置」只对超管渲染（本 story 在现有 `layout.html` 导航「安全」组下加一项，与「后台账号」并列；Epic 2 重排时随 `AdminPageCatalog` 迁移）`[L1]`

**AC2 · 权限矩阵（整页）**
**When** 点「编辑权限」（`GET /admin/roles/{id}/edit`）或「＋新建角色」（`GET /admin/roles/new`）
**Then** 整页矩阵（**不进抽屉**，UI 稿 7-9 / 7-10）：行 = 页面维度（按 8 个导航组分组），列 = 查看 / 编辑 / 其他操作权限；每格一个复选框对应一个权限码 `[L2]`
**And** 🛡 矩阵数据源 = `AdminPageCatalog`（本 story 新建，见 Dev Notes 草表）；测试断言：`AdminPageCatalog` 覆盖 `AdminPermissions.ALL` 的**每一个**码恰好一次（含 1-4 新增的 `place.manage` / `comment.virtual_post`；`content.manual_review` 别漏）`[L0]`
**And** 代码现状不规整项如实展示 + 注脚（PRD FR-21A-7）：评论管理无独立查看码（沿用 `content.view`）；退款管理 / Toko 退货审核 / 开封判例共用 `refund.*`；复购引擎效果 `config.view` 或 `order.view`；Toko 异常订单与订单履约同码；运费配置用 `config.*` `[L2]`

**AC3 · 编辑预置角色**
**When** 勾选变更后点保存 → 高危确认（`data-confirm`，文案复述「新增 N 项 / 移除 M 项，影响该角色下 K 个账号，重新登录后生效」）→ `POST /admin/roles/{id}/permissions`
**Then** 同事务：`admin_role_permissions` 按 diff 增删 → 该角色下**全部账号** `security_version` +1（`accounts.findByRoleId` → 逐个 `bumpSecurityVersion`，或一条 `UPDATE ... SET security_version = security_version + 1 WHERE role_id = ?`）→ 审计 `ROLE_UPDATED`（summary 记 code + 增删码列表，超长截断到 500 字符以内）`[L1]`
**And** 横幅 `admin.flash.role.updated`：「已更新角色 {0} 的权限（+{1} / −{2}），该角色下 {3} 个账号重新登录后生效」（D-2）`[L2]`
**And** 无变化 → no-op（不 bump、不审计）`[L1]`
**And** 🛡 提交的码必须全部 ∈ `AdminPermissions.ALL`，否则 `admin.err.account.badPermissionCode`（复用）`[L1]`
**And** 预置角色 `name` / `code` 不可改（表单无该字段；服务层忽略）`[L1]`

**AC4 · 新建自定义角色**
**When** `POST /admin/roles`（`name` + `permissionCodes[]`）
**Then** `name` trim 非空 ≤60 单语；至少勾 1 项（UI 稿 7-10「名称必填、至少勾选 1 项权限才可创建」）；`role_type=CUSTOM`；`code` 先插入拿到 id 再更新为 `role-<id>`（或用序列预取，二选一，写清）；`created_by = actor`；审计 `ROLE_CREATED` `[L1]`
**And** 名称与既有角色重复（含预置名的三语值？——**不**校验三语，只校验 `name` 列忽略大小写唯一）→ **新增** `admin.err.role.nameExists` `[L1]`

**AC5 · 编辑 / 删除自定义角色**
**Then** 编辑 = `POST /admin/roles/{id}`（改 `name` + 权限，权限 diff 与 AC3 同规则含 bump）`[L1]`
**And** 删除 = `POST /admin/roles/{id}/delete`：`countByRoleId > 0` → 拒绝 `admin.err.role.inUse`（带账号数）；为 0 → `data-confirm` 后删除（权限行 CASCADE），审计 `ROLE_DELETED`；DB `ON DELETE RESTRICT` 兜底 `[L1]`
**And** 对预置角色调编辑名称 / 删除端点 → 403（服务层判 `role_type == SYSTEM` 抛 `admin.err.role.systemImmutable`，Controller 映射 403 或 flash error，二选一写清）`[L1]`

**AC6 · 自定义角色的账号如何落 `admin_accounts.role`（解决 1-4 开放问题 ①）**
**When** 执行迁移 `V<yyyyMMdd_HHmm>__add_admin_role_template_value.sql`
**Then** `ck_admin_accounts_role` **DROP + ADD 重列全集**，新增值 `ROLE_TEMPLATE`；`AdminRole` 枚举加 `ROLE_TEMPLATE(List.of())`：`isTemplated()=true`、`accountType()=STAFF`、`titleCode()` 三语 key `role.ROLE_TEMPLATE`（「自定义角色」）`[L1]`
**And** `RolePermissionResolver`：`role == ROLE_TEMPLATE && roleId != null` → 读 `admin_role_permissions`；`roleId == null` → 空集 + warn `[L1]`
**And** 1-6 给账号赋自定义角色时写 `role=ROLE_TEMPLATE, role_id=<id>`；本 story 只备好枚举与解析 `[L0]`

**AC7 · 三语与回归**
**Then** 新增 key（`admin.roles.*` 约 15 个、`admin.flash.role.*` 3 个、`admin.err.role.*` 4 个、`role.ROLE_TEMPLATE(.desc)`、`admin.nav.roles`、`AdminPageCatalog` 页面名 `admin.page.<key>` 约 40 个）四包齐备 `[L0]`
**And** 既有测试全绿；新增 MockMvc 四条（整页 200 / 非超管 403 / 422 flash error / 保存成功 302）`[L1]`

### 🔴 「立即生效」不是本页的承诺——重登生效 + 踢人

D-2：角色权限变更对该角色下账号**重新登录后生效**。本 story 用 1-1 的版本号让他们「下一次请求被踢去重登」，重登后权限就是新的。横幅文案必须写「重新登录后生效」，不要写「立即生效」。

### 🔴 批量 bump 用一条 UPDATE

一个预置角色下可能有几十个账号，逐个 `findById → bump → save` 在同一事务里没问题但慢且啰嗦；`@Modifying` JPQL 一条完事。注意 `@Modifying(clearAutomatically = true)` 防止同事务内后续读到旧版本号。

### 🔴 `code` 自动生成 `role-<id>`

`admin_roles.code` 是 `NOT NULL UNIQUE`。两种做法：a) 先插入临时 code（如 UUID）拿 id 再 `UPDATE code = 'role-' || id`；b) `SELECT nextval('admin_roles_id_seq')` 预取。选 a) 更简单且不依赖序列名；同事务内完成。
