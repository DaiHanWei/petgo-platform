# Story 2.3: 互动栏与输入框合并为固定底栏

Status: review

## Story

As a 用户，
I want 点赞和分享一直在手边，
so that 我不用为了点个赞把页面滚回图片下方。

---

> **这不只是挪位置，是多了一个交互状态**（UI 稿 D1 原话：「比"挪位置"更深的交互状态变化」）。不定死的话，两个实现会对「打字时点赞按钮还在不在」「评论数在哪显示」给出不同答案。
>
> 🔴 **本 story 会重排详情页的整体结构**（`_interactionBar` 从 `SingleChildScrollView` 内迁到 `CommentComposer` 同级），**必须先于 Story 2.5 / 2.6**，否则评论区要改两遍。

---

## Acceptance Criteria

### AC1 — 合并为单条底栏（L2）

**Given** 详情页
**When** 页面渲染
**Then** 互动栏与评论输入框合并为**同一条固定底栏** `[L2]`
**And** 正文下方不再单独存在互动栏 `[L2]`
**And** 点赞/分享始终悬浮可点，不需滚动 `[L2]`

### AC2 — 两态互斥（L2）

**Given** 输入框未聚焦
**When** 查看底栏右侧
**Then** 显示点赞 + 分享 `[L2]`
**Given** 输入框已聚焦或已开始输入
**Then** 右侧切换为发送 `[L2]`
**And** 同一时刻只存在一组（两态互斥，无第三种组合） `[L0]`

### AC3 — 评论数口径（L0 / L2）

**Given** 评论数
**When** 在页面上查找
**Then** 只在评论区标题「KOMENTAR (N)」出现一次，底栏不再展示 `[L2]`
**And** N = 该帖**全部未删除评论数（含二级回复）** `[L0]`
**And** 与 Feed 卡片的评论数**同源同口径** `[L1]`

> 🔴 禁止「标题算一级、卡片算全部」这类分叉 —— 用户会看到首页显示 24、点进去标题写 9。

### AC4 — 热区（L0 / L2）

**Given** 点赞与分享图标
**Then** 可见尺寸 19px、间距 22px `[L2]`
**And** 可点击热区不小于 44×44（隐性扩展，不改变可见大小） `[L0]`

### AC5 — 明确不改（回归保护，L2）

**Given** 详情页顶栏
**Then** 分享入口**不在**顶栏；顶栏「···」仍为举报合规入口（2026-08-14 既有决策） `[L2]`
**And** 举报与删除互斥关系不变 `[L2]`
**And** `?focus=comments` 评论锚点行为不变 `[L2]`

### AC6 — 双击不点赞（L2）

**Given** 详情页图片
**When** 双击
**Then** **不**触发点赞 `[L2]`

> 2026-08-31 取消。理由：单击开灯箱会被双击判定拖慢 300ms，且与灯箱内「双击=缩放」语义冲突。点赞只走底栏。

### AC7 — 不扩散（L0）

**Then** 不改动评论列表项本身（属 Story 2.5） `[L0]`
**And** 不改动回复态（属 Story 2.6） `[L0]`

### Completion Notes List

**已交付（L0 全绿）**

1. **AC1 结构重排**：`_interactionBar` 从 `SingleChildScrollView` 内**整个删除**，
   点赞 / 分享并入 `CommentComposer` 这条固定底栏。正文下方不再单独存在互动栏。
2. **AC2 两态互斥**：判定抽成纯函数 `resolveBottomBarMode(focused, hasText)`
   （`domain/detail_bottom_bar.dart`），返回**只有两个值的枚举** ——
   「没有第三种组合」因此在类型上成立，而不是靠 build 里的 if 维持。
   - 条件是「聚焦 **或** 有输入」，不是「且」：点了输入框还没打字时显然要评论，
     这时摆着点赞分享是干扰；反过来有草稿但失焦时发送键必须还在，否则打的字没地方交。
   - `hasText` 以 **trim 后非空**为准 —— 只敲几个空格不算开始输入。
3. **AC3 评论数只出现一次**：底栏不再展示任何计数，评论数只在评论区标题
   「KOMENTAR (N)」出现。原互动栏里那个「评论图标 + 计数」**整个去掉** ——
   它的作用是「跳到评论框」，而评论框现在常驻底栏，这个跳转已无意义。
4. **AC4 热区隐性扩展**：可见图标 19px（`DetailBarMetrics.iconSize`）、间距 22，
   命中框用 `ConstrainedBox(minWidth/minHeight: 44)` 套在外面。
   有一条反向断言钉住「热区值不得等于可见尺寸」—— 相等就说明有人把图标画大了，
   那改变的是设计稿视觉密度，不是可达性。
5. **AC5 明确不改**：顶栏「···」未动（仍是举报入口）；举报 / 删除互斥未动；
   `?focus=comments` 锚点未动。分享**不在**顶栏。
6. **AC6 双击不点赞**：全仓 `grep onDoubleTap` 在 content 模块**零命中** ——
   双击点赞从来没实现过，本条无需改动，核查记录在此。

**🔴 两处需要你知道的发现**

**① 我自己引入又修掉的回归：游客差点失去分享入口。**
把分享从正文下方挪进底栏后，游客分支返回的是「只读提示框」、不含右侧动作 ——
于是游客**彻底没有分享入口**了。分享对游客本就允许（AD-15 Rule 6），这是把既有能力做没了。
已修：游客分支照常渲染右侧动作，且永远停在 actions 态（他没有输入框可聚焦、也没有草稿）。

**② AC3「与 Feed 同源同口径」—— 代码里其实有一处既有分叉，本 story 未动它。**
`CommentRepository` 的两个查询并**不逐字一致**，尽管注释声称如此：
- 详情页 `countVisibleForViewer`：含 hide-relation 过滤 + **父评论可见性**子查询；
- Feed 批量 `countVisibleForViewerIn`：**两者都没有**。

也就是说「父评论被删、子回复还在」或「存在拉黑关系」时，首页与详情页的数字**会不一样** ——
正是 AC3 要禁止的那种分叉。**我没有就地改它**：那条批量查询是 Feed 的取数主路径，
改它会连带影响首页所有帖子的计数，超出本 story「把互动栏挪进底栏」的范围，
且需要 L1 真实数据确认影响面。**建议单独立条**，已列进下方 L1 清单第 4 条。
