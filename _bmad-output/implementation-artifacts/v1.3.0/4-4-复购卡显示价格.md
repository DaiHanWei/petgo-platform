# Story 4-4: 复购卡显示价格

Status: review

> 自包含 story，可本地或云端 L0 执行。与用户沟通用中文。执行纪律见根 `CLAUDE.md`（后端→前端→联调、AC 标 L0/L1/L2）。

## Story

As a 用户，
I want 复购提醒卡片上能看到价格，
so that 我不用点进商品详情才知道再买一次要多少钱。

## 价格取哪个 SKU —— 核实结论：**触发 SKU，不是最低价**

复购触发源头是**订单行**，一路钉死在一个具体 SKU 上：

- `petgo-backend/src/main/java/com/tailtopia/shop/repurchase/service/RepurchaseScanService.java:120-149` 遍历 `orderLines.findByOrderIdOrderByIdAsc(orderId)`，`:126` `ShopSku sku = skus.findById(line.getSkuId())`，`:130` 取商品；`:178-179` 建触发器 `RepurchaseTrigger.foodLow(userId, petId, sku.getId(), order.getId(), depletion)`。
- `RepurchaseTrigger.getSkuId():115` / `getSourceOrderId():119`（`repurchase/domain/RepurchaseTrigger.java`）。
- Controller `:80` 就是 `skus.findById(t.getSkuId())`，且已经把 `sku.getPublicToken()` 当 `skuToken` 下发。

👉 **价格 = `sku.getPrice()`（用户当初买的那一档）。**
「最低价」逻辑（`ProfileRecommendationService.minPriceOf:226-229`）只服务**推荐位**，与复购卡无关，不要挪过来。

**为什么不取最低价**：复购卡的 CTA 是「Beli Lagi（再买一次）」。用户要再买的是他买过的那一档；在多规格商品上用最低价会**系统性低报**，等于用一个他付不到的价钱把他骗进详情页。

### ⚠️ 由此带来的一致性陷阱（AC3 的可测化定义就是为它写的）

`petgo_app/lib/features/shop/presentation/product_detail_page_v2.dart:315-317`：

```dart
final price = sku?.price ?? d.minPrice;
```

而 `:69-70` 明写 `_selectedSkuToken` **初值 null 且不在任何地方被自动赋值 —— 多规格必须由用户显式选择（FR-94A）**（`:7` 的类注释同）。

所以**多规格商品**上：复购卡显示触发 SKU 价，点进详情页落地时显示的是 `minPrice`，两个数可能不同。
**这不是 bug，也不能靠自动选中规格去「修」—— 那会违反 FR-94A。**
故 AC3 把「一致」定义为「复购卡价格 == 详情页**选中该规格后**的价格」，而不是「== 详情页落地价」。

### 开放项（实施时与产品确认，本 story 不擅自扩范围）

1. **卡片要不要同时显示规格名。** `RepurchaseCardView` 没有 `specName`，而价格取的是触发 SKU 的价 —— 多规格商品上会出现「有价、但看不出是哪一档」。补 `specName` 是同一次 C5 改动里最便宜的一次搭车；不补则依赖用户自己记得买过哪档。**实施时确认**；若产品要补，在本 story 同批做掉并把 AC1/AC4 的字段集扩成 13 个。
2. **`Beli Lagi` 要不要带 `skuToken` 跳转。** 现在跳 `/shop/products/${c.productToken}?from=REPURCHASE`（`toko_page_v2.dart:773-785`）。带上 skuToken 可以让详情页**高亮提示**「你上次买的是这一档」而**不自动选中**（FR-94A 只禁自动选中，不禁提示）。属体验增强，不在 SHOP-FR-03 范围内，**实施时确认**是否另开 story。

### 🔍 实现中的判断（各一行）

1. **`price` 追加在 record 末尾，不是 story 建议的「紧跟 `productName`」**。
   `RepurchaseCardView` 自己的注释里写着「⚠️ 只追加到 record 末尾，不动既有字段顺序（并行契约）」——
   这是写在本文件里的规则，而 story 那句是「位置**建议**」、理由是排版。**以代码为准**，已在字段注释里留痕。
2. **两处卡片同改**（T4 要求「实施时确认」）：确认二者是**同一份 `RepurchaseCard` 数据的两个入口** ——
   `toko_page_v2.dart` 是 Toko 首页复购条，`repurchase_zones_v2.dart` 的 `_Card` 经
   `RepurchaseTriggerCardV2` 用在成长档案页。同一个价格承诺在两个页面上不一致会更糟，故两处都加。
   ⚠️ 后者是**深色底**（`ShopColors.ink`），价格用 `ShopColors.surface` 而非首页那套 `accent` 玫红。
3. **顺带补了 `skuToken` 进 Dart 模型**（T3 允许）：后端一直在下发，Dart 侧一直丢着。
   本版**没有任何渲染用到它**，只是别再丢数据。
4. **`hasPrice` 收在 model 而不是散在 widget**：两处渲染各判一次迟早漏一处。
   负数也判为「没有价格」—— 不该出现，但真出现了也不画。
5. **契约测试特意钉了「null 价格在线上是整键消失」**：后端 NON_NULL 下 `price=null` 不是
   「键在、值为 null」，而是键不出现；Dart 的 `(j['price'] as num?)?.toInt()` 对缺键与 null
   同样得到 null —— 两端在此对齐。这正是 T2 要求钉死的那条。
