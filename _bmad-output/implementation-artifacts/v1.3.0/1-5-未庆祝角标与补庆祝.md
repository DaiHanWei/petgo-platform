# Story 1.5: 未庆祝角标与补庆祝

Status: ready-for-dev

## Story

As a 用户，
I want 我不在场时解锁的成就，下次进里程碑页时补一次庆祝，
so that 我不会莫名其妙错过自己达成的成就。

---

> **依赖 Story 1.4**（字段、回报端点、未庆祝计数均由 1.4 交付）。
>
> **本 story 是 Epic 1 唯一有可见新 UI 的一条**，但新 UI 只有一个角标 —— 庆祝页视觉**一字不改**（重绘属批次 C）。

---

## Acceptance Criteria

### AC1 — 档案 Tab 角标（L2）

**Given** 存在「已完成且未庆祝」的条目
**When** 打开成长档案 Tab
**Then** 里程碑进度条上显示角标（红点 / +N） `[L2]`
**And** 角标样式**直接复用** `notification_bell.dart` 的 `notificationBadge`（danger 红底 / min-width 16 / 圆角 8 / 白字 10px），不另画 `[L0]`
**And** 档案 Tab **不弹**全屏庆祝 `[L2]`

### AC2 — 列表页补弹（L2）

**Given** 存在未庆祝条目
**When** 进入里程碑列表页
**Then** 自动弹一次庆祝页，取级别最高的一条 `[L2]`
**And** 其余条目由 KOLEKSI 圆点带过 `[L2]`
**And** 本次展示覆盖的**全部条目**一并回报置位 `[L1]`
**And** 返回档案 Tab 后角标消失 `[L2]`

### AC3 — S 级也补（L2）

**Given** 未庆祝条目中有 S 级
**When** 进入列表页
**Then** 同样补弹，不按级别过滤 `[L2]`

### AC4 — 🔴「去发布」路径不连弹（L2）

**Given** 用户走「去发布」路径完成打卡
**When** 庆祝页弹出 → 关闭发布 sheet → 自动跳转里程碑列表页
**Then** 列表页**不再重复弹出**同一条庆祝 `[L2]`
**And** 该抑制由客户端在同一次导航内持有「刚庆祝过的 code 集合」实现 `[L0]`
**And** **不依赖**回报是否已落库 `[L0]`
**And** **不得**把回报改为同步来绕开（那会让发布流程卡在一个可失败的写上） `[L0]`

### AC5 — 重温不改状态（L1 / L2）

**Given** 已完成的徽章
**When** 点击重温庆祝页
**Then** 正常展示庆祝 `[L2]`
**And** **不**改写 `celebrated_at`、**不**产生回报 `[L1]`

### AC6 — 埋点（L1）

**Given** 任一次庆祝页展示
**When** 上报 `milestone_celebration_shown`
**Then** 携带 `code`、`level`、`path` `[L1]`
**And** `path` 值域为 `instant` / `catchup` / `revisit` 三值之一 `[L0]`
**And** 两台设备同时补弹会各报一次（**接受双计**，回报仍幂等） `[L0]`

### AC7 — 既有路径不变（回归保护，L2）

**Given** 即时庆祝路径与 500/800/1200ms 三次短轮询
**When** 本 story 改完
**Then** 全部保留，补庆祝是兜底不是替代 `[L2]`
**And** 「多条同解锁只弹最高一条」规则扩展为全路径统一（含补庆祝） `[L2]`
**And** 庆祝页三种关闭方式、解锁振动、已完成徽章重温**均不改动** `[L2]`

## Dev Notes

### 🔴 头号陷阱：「去发布」路径会连弹两次

既定时序是「发布成功 → 回填打卡 → **弹庆祝** → 关发布 sheet → **跳里程碑列表页**」。
回报是异步的（AD-A3.1 失败静默），列表页极可能在回报落库前读到 `celebrated_at IS NULL` → **两秒内连弹两次同一条**。
AD-A2 的 Prevents 原先只挡了「档案 Tab × 列表页」这一对，**恰好没挡真正会撞的这一对**。
