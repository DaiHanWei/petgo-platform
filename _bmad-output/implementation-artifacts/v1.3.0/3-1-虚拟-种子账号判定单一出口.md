# Story 3.1: 虚拟 / 种子账号判定单一出口（AD-8）

Status: review

> 自包含 story，可本地或云端 L0 执行。与用户沟通用中文。执行纪律见根 `CLAUDE.md`。
> 纯后端，无迁移、无页面。是 Epic 3 看板与 Epic 4 暖贴共用的前置件。

## Story

As a 平台，
I want 「这个账号是不是运营的马甲或种子号」只有一个判定入口，Java 与 SQL 两侧结果一致，
so that 看板、暖评身份池、暖贴入队三处口径不会各算各的。

## Acceptance Criteria

**AC1 · Java 单一出口**
**Given** `User` 实体
**When** 新增 `public boolean isSyntheticAccount()`
**Then** 返回 `accountType == VIRTUAL || role == ADMIN`；`googleSub` 为 null（Apple 登录）返回 false `[L0]`
**And** 同时提供静态兜底 `User.looksSyntheticBySub(String googleSub)`：`googleSub` 以 `admin:` / `virtual:` / `seed-tailtopia-` 开头为 true（null 安全）——**只用于一致性测试与迁移期校验，业务代码不得调用** `[L0]`

**AC2 · SQL 单一片段**
**Given** 新类 `admin/dashboard/metrics/SyntheticAccountSql`
**When** 定义常量 `EXCLUDE_WHERE`（形如 `u.account_type = 'REAL' AND u.role <> 'ADMIN'`）与 `IS_SYNTHETIC`（其否定）
**Then** 全部 Java 原生查询只引用这两个常量拼接，禁止散写 `LIKE 'virtual:%'` `[L0]`

**AC3 · 两侧一致（Parity）**
**Given** L1 测试库里构造 6 类账号：Google 真实、Apple 真实（google_sub NULL）、`admin:` 运营号（role=ADMIN）、`virtual:` 虚拟号（account_type=VIRTUAL）、`seed-tailtopia-` 种子号（account_type 已被 V82 回填为 VIRTUAL）、已注销真实用户
**When** 分别用 Java `isSyntheticAccount()`、SQL `IS_SYNTHETIC`、兜底 `looksSyntheticBySub()` 判定
**Then** 三者对 6 类样本结论逐一相等（真实 ×2 + 已注销 = false；其余 = true）`[L1]`

**AC4 · 全库无散写**
**Then** `grep -rn "virtual:%\|seed-tailtopia-%" src/main/java` 除 `User.looksSyntheticBySub` 与 `SyntheticAccountSql` 外为零 `[L0]`
**And** 既有 `ContentPostRepository.countByRealAuthor` / `CommentRepository.countByRealAuthor`（按 `accountType = REAL`）口径与本出口一致，不改动 `[L0]`

**AC5 · 回归**
**Then** `mvn -B clean package` 通过；`AdminDashboardService.overview()` 数字不变 `[L0/L1]`

## Dev Notes

### 🔴 判定依据用 `account_type`，不用前缀——这是对架构 AD-8 措辞的修正

AD-8 原文写的是「`googleSub` 以 `admin:` / `virtual:` / `seed-tailtopia-` 开头」。读代码后发现 **`users.account_type`（REAL|VIRTUAL）已在 V82 上线**，`seed-tailtopia-*` 存量已被 V82 回填为 VIRTUAL，`AdminVirtualAccountService` 建号写 VIRTUAL；概览看板现有 `countByRealAuthor` 也早已按 `accountType=REAL` 过滤。参考 SQL 头注释也说「等 account_type 上线后换成更直接的判断」。所以：

- **主判定 = `account_type='VIRTUAL' OR role='ADMIN'`**（列有 CHECK 约束、有索引可能、语义明确）。
- 前缀判定只保留为 `looksSyntheticBySub` 兜底，靠 AC3 的 parity 测试证明两者对现网数据等价；若将来某条虚拟号忘了设 account_type，parity 测试会红。
- `role='ADMIN'` 是 Story 3.1（V1.0）遗留的旧账密运营号（`User.newAdminUser` 写 `google_sub='admin:<email>'`），现后台账号在独立表 `admin_accounts`，这里排除它只是清历史残留。

⚠️ 需回写架构 AD-8 措辞（已在本 story 记录，架构 delta 的「§对上游文档的反向影响」补一行）。

### 🔴 Apple 用户不能被排除

`User.appleSub` 非空、`googleSub` 为 null 的用户是真实用户（D-6）。`account_type` 判定天然正确；前缀兜底必须 `sub == null → false`。参考 SQL 用 `COALESCE(google_sub,'')` 也是同一目的。
