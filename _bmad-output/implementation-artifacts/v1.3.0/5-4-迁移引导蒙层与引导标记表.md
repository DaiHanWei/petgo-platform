# Story 5.4: 迁移引导蒙层与引导标记表

Status: review

## Story

As a 老用户，
I want App 在我第一次进档案页时告诉我身份证挪去哪了，
so that 我不用自己找。

---

> **双侧 story**：新建一张键值表 + 读写端点 + 全新 coachmark 交互（项目内无现成组件可复用）。
>
> **按账号存，不按设备** —— 这与 v1.1.6 AD-14.1（一次性引导标记走本地 prefs、按设备）**不同**，理由见 Dev Notes。
>
> 与 Story 5.1 弱相关（引导指向 5.1 交付的入口条），但可并行开发。

---

## Acceptance Criteria

### AC1 — 键值表（L0 / L1）

**Given** 数据库
**When** 迁移执行完毕
**Then** 存在**键值形态**的用户一次性引导标记表（用户 + 标记键 + 首次触发时刻） `[L1]`
**And** 用户与键的组合唯一 `[L1]`
**And** 表中**不含任何 PII** `[L0]`
**And** 迁移文件名为时间戳制 `[L0]`

> 键值形态是为了避免「每加一个引导就往用户表加一列」。批次 C 的性格测试引导会用第二个键。

### AC2 — 首次触发（L2）

**Given** 一个从未看过引导的登录用户
**When** 首次进入成长档案页（**含**从建档庆祝页「查看档案」进入）
**Then** 展示一次性蒙层，高亮指向新入口条位置，说明身份证已移入其中 `[L2]`
**And** 看过后置位标记 `[L1]`
**And** 之后**不再弹出** `[L2]`

### AC3 — 按账号不按设备（L2）

**Given** 同一账号换一台设备登录
**When** 进入成长档案页
**Then** **不再弹出** `[L2]`

### AC4 — 离线降级（L2）

**Given** 离线状态下首次启动
**When** 读不到标记
**Then** 按「未看过」处理 `[L2]`
**And** 可能多弹一次，属**已接受的代价** `[L0]`

### AC5 — 🔴 聚光挖孔的实现禁忌（L2）

**Given** 蒙层的聚光挖孔
**When** 实现
**Then** **不使用超大 `box-shadow` 叠加在另一层半透明遮罩上** `[L0]`
**And** 采用分块遮罩或等价方案 `[L0]`
**And** 聚光区域实际比周围**更亮**，遮罩不出现双重叠加变暗 `[L2]`

> UI 稿第四步已实测：3000px box-shadow 叠加在半透明遮罩上会双重叠加，遮罩比设计意图更暗、聚光区并未变亮。同一处还踩到第二个坑 —— `display:flex` 容器内的文字与按钮被同容器内 `position:absolute` 的兄弟元素挡住不可见。

### AC6 — 键的隔离（L0）

**Given** 本批次的引导标记键
**Then** 只落「KTP 位置迁移」这一个键 `[L0]`
**And** 批次 C 的性格测试入口引导**必须另起一个键**，禁止共用 `[L0]`

### AC7 — 注销级联（安全攸关，L1）

**Given** 一个用户注销
**When** 执行注销级联
**Then** 其引导标记行按既有 D1/D2 口径处置 `[L1]`

### AC8 — 页头三态（L2）

**Given** 档案页头是三态共用组件
**When** 游客态或访客态
**Then** **不触发**该引导蒙层 `[L2]`

## Dev Notes

### 为什么按账号，而 v1.1.6 按设备

v1.1.6 AD-14.1 管的是**推送权限引导**，其判断依据「系统通知开关」本身就是设备级状态，标记跟着设备走是自洽的。

⚠️ **必须正面回应的反例**：AD-14.8 的手机号软引导**同样是账号级关切**（「已填手机号者永不提示」按服务端字段判定），当时**仍裁了按设备存**。所以「账号级关切 ⇒ 按账号存」这个推论在本项目**已有反例**。

**本条仍取按账号的实际理由**：AD-14.8 有服务端字段（`users.phone` 非空）天然兜底，标记存哪都不会重复打扰；本条**没有任何服务端事实可兜底** —— 除了这个标记本身，没有别的东西能说明「他已经知道 KTP 挪走了」。

**两条并存，各管各的场景，不得互相套用。**

**实现要点（复审着眼处）**：

1. **🔴 AC5 的挖孔用分块遮罩，不是 box-shadow**。UI 稿第四步实测过：3000px 阴影叠在
   另一层半透明遮罩上会**双重叠加** —— 遮罩比设计意图更暗，而聚光区并没有变亮
   （它只是"没有再暗一层"）。这里把高亮框之外拆成上/下/左/右四块各画一次，
   高亮那一格**什么都不画**。三条测试钉住：源码里没有 `BoxShadow`、恰好四块、
   四块**两两不重叠**（重叠处会比别处更暗，是同一个毛病的另一种形态）。
2. **UI 稿同一处的第二个坑**（flex 容器里的文字与按钮被绝对定位的兄弟挡住）：
   说明卡是 Stack 的**最后一个兄弟**（后来者在上），不塞进任何一块遮罩里。有测试点击验证。
3. **AC8 没有新写态判定**：触发方法挂在 `_ArchiveBodyState` 上，而这个 State
   **只在「已登录 + 有档案」那一支被构建**（游客态与访客态是另外两支）。
   所以游客/访客根本走不到这段代码 —— 不是"判断后不弹"，是压根没这段逻辑（AD-A24.4）。
4. **锚点挂在入口卡的外层**：给入口卡本身换 key 会动到它的 `ValueKey('diaryIdCardButton')`，
   那会把既有测试与埋点对照一起弄断。锚点**只用来量位置，不改行为**。
5. **先关蒙层再置位**：置位是一次网络往返，等它回来再关会让「知道了」点下去顿一下；
   置位失败的代价只是下次再弹一次（与离线首启同一档，已接受）。
6. **AC6 一个引导一个键**：后端 `OnboardingMarkKey` 是**枚举**（不是随便一个字符串）——
   端点只认登记过的键，未登记的 422。两侧各有一条测试钉住「本批次只有一个键」，
   批次 C 加键时**会红**，那是有意的：加键的人必须写下「我加的是第二个键，不是复用第一个」。
   另有一条跨语言断言：客户端常量与后端枚举的线格式必须是同一个字符串
   （两边各写一份字面量，错一个字母就是「引导永远不置位」）。
7. **AC7 注销级联**：新表接进 `AccountDeletionService`，且有测试钉住它发生在**删 user 行之前**
   （之后就没有 user_id 可识别了）。

**⚠️ 关于「按账号 vs 按设备」**：这与 v1.1.6 AD-14.1（推送权限引导走本地 prefs、按设备）**不同**，
且 AD-14.8 的手机号软引导是一个「账号级关切却仍按设备存」的**反例** —— 所以这个推论
在本项目并不自动成立。本条仍取按账号的实际理由写在迁移文件注释里：
AD-14.8 有服务端字段（`users.phone` 非空）天然兜底，标记存哪都不会重复打扰；
**本条没有任何服务端事实可兜底**。两条并存，各管各的场景，不得互相套用。
