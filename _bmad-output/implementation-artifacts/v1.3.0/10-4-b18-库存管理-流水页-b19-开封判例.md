# Story 10.4: B18 库存管理（抽屉四操作）+ 库存流水页（只读）+ B19 开封判例

Status: ready-for-dev

> ⛔ **门控（AD-12）**：本 story 属 Epic 10，**必须等 v1.4.0 电商线合入 `dev_1.3.0` 之后再启动**。启动前先执行下方「电商线合入后的重核步骤」。依赖 Story 2-3a（htmx 响应约定 / `admin/shared`）与 2-3b（五套模板壳 / `admin-drawer.js` / `admin-workbench.js`）已合入。
> 自包含 story，可本地或云端 L0 执行。与用户沟通用中文。执行纪律见根 `CLAUDE.md`（后端→前端→联调、AC 标 L0/L1/L2、Flyway 时间戳版本号、`mvn -B clean package`）。本 story **零后端功能改动、零新端点**（AB-19A 原则），只改模板 / Controller 返回形态 / 页面路由退役。

## Story

As a 仓库 / 商品运营与客服，
I want 库存页点行在抽屉里看流水摘要并做采购入库、退货入库、报损、盘点；流水账本只读可查；开封判例可检索可沉淀，
so that 库存动作有统一入口，判例一致性工具常驻可用。

## Acceptance Criteria

**AC1 · B18 列表套模板 B**
**Given** `/admin/shop/inventory`（`shop.inventory_view`）
**Then** 摘要条：售罄 SKU 数 · 低库存 SKU 数 · 锁定库存合计；表格列：商品名 ｜ 规格 ｜ 实际库存 ｜ 锁定库存 ｜ 可售库存（= 实际 − 锁定，查询期计算）｜ 状态（售罄行红底）；每页 20 `[L1]`

**AC2 · B18 抽屉四操作**
**Given** 点行 → 抽屉
**Then** 上半：该 SKU 流水摘要（最近 N 条 + 「查看全部流水」链接跳流水页）；下半四个操作页签：采购入库（供应商 / 采购单号 / 进货单价 / 数量，`POST inventory/purchase`）· 退货入库（`POST inventory/return-inbound`）· 报损（原因必填，data-confirm，`POST inventory/damage`）· 盘点调整（data-confirm **复述差异数**，`POST inventory/stocktake`）；权限 `shop.inventory_edit`，无权限页签禁用并注明 `[L1/L2]`
**And** 提交 htmx 局部刷新抽屉与列表行；参数与端点零变更；库存不变式（锁定 ≤ 实际、非负）由服务层现有校验兜底，422 行内 err `[L1]`

**AC3 · 流水页只读**
**Given** 现状流水路由是 **按 SKU** 的 `GET /admin/shop/inventory/{skuId}/movements`
**Then** 该页套模板 B 只读：时间（WIB）｜ 类型 ｜ 增减 ｜ 变更前后 ｜ 采购单号 ｜ 供应商 ｜ 进货单价 ｜ 原因 ｜ 操作人；无任何 form；顶栏只读标识 `[L2]`
**And** **不新建全局路由 `/admin/shop/inventory-movements`**（新增端点违反零变更）；UI 稿 5-7「独立账本页」按现状 per-SKU 路由实现；抽屉「查看全部流水」链到它 `[L0]`

**AC4 · B19 开封判例**
**Given** `/admin/shop/return-precedents`（查看 `refund.view`，沉淀 `refund.approve`）
**Then** 页头常驻业务定位提示（代码原文）：判例库是一致性工具不是风控工具——解决「同一情形不同客服判得不一样」；骗退风控由 90 日 ≤2 次频次上限承担，两者不可互相替代 `[L2]`
**And** 表格列：情形 ｜ 判定（枚举：算开封 / 不算开封）｜ 理由 ｜ 时间；检索框按情形或理由（显式查询钮）；「沉淀判例」抽屉表单（情形 / 判定二选一 / 理由，`POST return-precedents`）`[L1/L2]`
**And** 与 Banner 是两个不同路由 / 数据模型，各自独立页（UI 稿 09-04 拆帧）；A7 质检步「查判例」链接落本页并带 `?q=` 预填检索 `[L1]`

**AC5 · 回归**
**Then** `AdminShopInventoryEndpointIntegrationTest`、`AdminReturnEndpointIntegrationTest`（precedents 部分）全绿；写端点 inventory 4 + precedents 1 不变 `[L0/L1]`

### 🔴 流水页路由与 UI 稿不一致（需知悉）
逐页规格与 UI 稿 5-7 写的是「独立只读账本页 `/admin/shop/inventory-movements`」，**代码现状没有这个全局路由**，只有 per-SKU 的 `inventory/{skuId}/movements`。本 story 按零变更原则不新建路由：抽屉流水摘要 + 「查看全部流水」跳 per-SKU 页。若产品坚持要全局账本页，那是新增端点，需另立 story。

### 🔴 权限码共用（如实记录）
