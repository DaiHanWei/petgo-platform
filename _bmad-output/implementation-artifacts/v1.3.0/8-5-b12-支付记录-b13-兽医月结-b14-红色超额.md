# Story 8.5: B12 支付记录 + B13 兽医月结 + B14 红色超额（套模板 B）

Status: ready-for-dev

> 自包含 story，可本地或云端 L0 执行。与用户沟通用中文。执行纪律见根 `CLAUDE.md`。
> **零写端点变更**。三页现状都是单页无独立详情页，本 story 只加摘要条 / 抽屉 / htmx 提交。依赖 2.2（`@StagOnly` 门控注解，与 STAG 角标同源）、2.3a / 2.3b。

## Story

As a 运营 / 财务，
I want 支付记录、兽医月结、红色超额三页有摘要条、抽屉和统一的操作交互，支付记录的测试用「模拟回调」只在 staging 出现，
so that 钱相关的三页口径一致，生产环境不会出现测试按钮。

## Acceptance Criteria

**AC1 · B12 支付记录列表**
**Given** `/admin/payments` 套模板 B
**When** 打开
**Then** 筛选栏：用户 ID / 用途 / 状态 / 时间段（WIB，含止当天）+ 显式「查询」钮 + 「清空筛选」（现状 `userId / purpose / status / from / to` 参数不变）；摘要条 **本期支付笔数 · 成功金额 · 失败/过时数**（来自现状 `AdminPaymentSummary`：orderCount / paidCount / cashIncome / coinSpent，币种不一致时显示「币种不一致，不做换算」原提示；「本期」= 当前筛选集）；表格列 **用户 ｜ 支付号 ｜ 用途 ｜ 渠道 ｜ 金额 ｜ 币种 ｜ 状态 ｜ 时间（WIB）**，每页 20 `[L1]`
**And** 「导出当前结果」按钮：`GET /admin/payments/export.xlsx` 接收与列表同一套筛选参数（现状已如此），权限 `payment.list_export` 不变；实现改经 `AdminExportWriter.xlsx`（现状 `AdminPaymentExportService` 本就是 POI 范式，迁到统一写入器后行为不变）`[L1]`
**And** 点行 → 抽屉 `GET /admin/payments/{intentToken}/drawer`：支付意图全字段只读（含用途、渠道、金额、状态、创建 / 更新时间 WIB）`[L2]`

**AC2 · B12 模拟回调三钮 — 仅 staging**
**Given** 逐页规格 B12 描述的「🧪 模拟回调（成功 / 失败 / 过时三钮）」
**Then** 🔴 **代码核实：`dev_1.3.0` / main 上不存在任何模拟回调代码**（全库 grep `simulate` / `模拟` 无命中）；该能力只存在于 stag 分支的 stag-only 提交。本 story 在主线上**只预留门控与槽位**：抽屉操作条渲染一个 `th:if="${@stagGate.enabled}"`（`@StagOnly` 的模板侧表达）的「仅测试环境」区块，生产 / dev 不渲染；三钮本体与端点由 stag 分支合入时接入该槽位并加 `@StagOnly` `[L0]`
**And** 终态（PAID / FAILED / EXPIRED）行在 stag 也不渲染模拟钮（槽位内按状态 `th:unless` 终态）`[L0]`

**AC3 · B13 兽医月结**
**Given** `/admin/settlements` 套模板 B
**Then** 摘要条 **待打款单数 · 待打款金额合计 · 本月已打款**（status=PENDING_FINANCE 计数与 Σ payout；本月（WIB）status=PAID/ARCHIVED 的 Σ payout）；表格列 **兽医 ｜ 月份 ｜ 单数 ｜ 成交额 ｜ 到手 ｜ 状态 ｜ 凭证 ｜ 打款时间 ｜（操作移入抽屉）**；页首提示「每月 1 日生成上月月结…」保留 `[L1]`
**And** 点行 → 抽屉 `GET /admin/settlements/{id}/drawer`：该月结的订单构成列表（订单 / 金额 / 兽医分成快照）+ 凭证（现状 `proof` 为**文本参考号 ≤512**，不是文件上传——如实展示文本；逐页规格「凭证图」与现状不符，见 Dev Notes）+ 操作条 `[L2]`
**And** 操作：确认打款（`POST /admin/settlements/{id}/pay`，`proof` 文本，data-confirm 复述**兽医名 + 到手金额**）仅 `PENDING_FINANCE` 渲染；归档（`POST {id}/archive`）仅 `PAID` 渲染且**凭证为空时禁用**（现状仅服务层拒绝，抽屉前置禁用 + 提示）；`ARCHIVED` 只读；权限 `settlement.payout`，无权限禁用注明 `[L1/L2]`

**AC4 · B14 红色超额**
**Given** `/admin/red-overage` 套模板 B（与月结拆开的独立页、独立权限 `risk.view` / `risk.edit`）
**Then** 摘要条 **待核查用户数**（reviewStatus=TO_VERIFY 计数）；表格列 **用户 ｜ RED 计数 ｜ 复核态 ｜ 备注**；页首「仅观测，不自动处置」提示保留 `[L1]`

## Dev Notes

### 🔴 模拟回调三钮在主线不存在——这是本 story 最重要的事实
PRD / 逐页规格 / UI 稿都把「模拟回调（成功 / 失败 / 过时）」写成 B12 的现状功能，但 `dev_1.3.0`（= main 3c2581c5 + 文档提交）里 `grep -rn "simulate\|模拟"` 在 `admin/**`、`pay/**`、`templates/admin/**` 全无命中。逐页规格自己也写了「stag 专用（代码注明绝不合并主线）」。所以：
- 主线只能做**门控 + 槽位**，三钮和 `POST …/simulate-*` 端点属于 stag 分支的 stag-only 提交，合 stag 时接进槽位并套 `@StagOnly`。
- 写操作清单（Story 2.1）在主线跑不会出现模拟端点，属正常；Epic 11 diff 时若 stag 分支已合入才会出现，需在核对说明里标为「stag-only，非本版新增」。
- **需拍板 / 需知悉**：如果产品希望主线也带模拟回调能力（只在 stag 渲染），那是把 stag-only 代码正式化，超出本 story 范围，另开 story。

### 🔴 B13 凭证是文本，不是图
`AdminSettlementController.pay(id, proof)` 的 `proof` 是 `String` ≤512（模板 placeholder「打款凭证/参考号」），没有文件上传。逐页规格 B13 写「凭证图」与现状不符；本 story 按「零功能变更」如实做**文本凭证**，抽屉展示文本参考号。若要改为图片上传（OSS objectKey）属新功能，超出本 story，在 Completion Notes 记为待产品确认。

### `@StagOnly` 门控来源
Story 2.2 引入 `@StagOnly`（`spring.profiles.active` 含 `stag`）用于顶栏 STAG 角标；本 story 的模板侧判断用同一 bean（建议 `StagGate.enabled()`），不要自己再读 `Environment`。现状项目只有 `@Profile("dev")` 用法（`NotifyTestController` / `DevUserSeeder`），没有 stag 门控先例。
