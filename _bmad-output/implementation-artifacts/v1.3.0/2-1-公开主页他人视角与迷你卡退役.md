# Story 2.1: 公开主页（他人视角）与迷你卡退役

Status: review

## Story

As a 在 Feed 里刷到一条有意思的内容的用户,
I want 点作者头像就直接看到他的完整主页,
so that 我能判断这人是谁、值不值得继续看他的东西，而不是只弹一张什么都点不动的小卡片。

> ⚠️ **本 story 刻意不拆小**：迷你卡上现在挂着**举报 / 拉黑**两个入口。若先切入口、后做主页的「···」抽屉，中间会出现**用户找不到举报和拉黑**的功能回退期。入口切换与抽屉必须同一条 story 落地。

## Acceptance Criteria

**AC1 — 主页接口** `[L1]`
返回头像 · 昵称 · 运营用户标签 · **加入时间** · **个性签名 signature**；带「是否本人视角」标识供前端切换两种视角。
- 加入时间是**本批次新补**的字段；签名是既有字段，直接复用

**AC2 — 三处入口收口** `[L2] [L0]`
Feed 卡片头像 / 内容详情页作者行 / 评论区头像 → **直接进入完整主页**，不再弹迷你卡。
三处**逐处收口、一处不漏**；迷你卡组件在本 story 后**不再被任何入口引用**。

**AC3 — 操作抽屉** `[L2]`
他人主页顶栏「···」→ 底抽屉，含**举报 / 拉黑**两项（互斥）+ 底部「取消」按钮；样式沿用既有资料编辑抽屉那套（顶部圆角 + 手柄 + 上滑）。

**AC4 — 收尾行为保留** `[L2]`
在主页完成拉黑或举报后，迷你卡原有的**收尾行为一字不改地保留**：拉黑后退出详情页、从列表移除该作者的全部内容。
拉黑给成功提示，**举报一律静默**（提示会泄露「举报会隐藏内容」）。

**AC5 — 注销用户** `[L1] [L2]`
目标用户已注销 → 服务端**不下发**昵称 / 头像 / 签名等任何身份信息。
本 story 内前端以既有通用空态兜底即可；**完整「用户不存在」空态视觉由 Story 2.5 补** —— 本 story **不依赖** 2.5 即可验收。

### 🔴 收尾回调不能丢

`showMiniProfile` 的 `onBlocked` / `onReported` 是**成功路径专用**回调（取消与失败都不触发），作用是：拉黑/举报成功后让当前屏立刻跟上——移除该作者的卡片、详情侧退回列表。

**迁移时把这两个回调原样接到主页的抽屉操作成功之后**。漏掉的表现是：拉黑完回到 Feed，那个人的内容还在。

详见 `petgo_app/lib/shared/widgets/mini_profile_sheet.dart` 头部注释（写得很清楚，动手前读一遍）。

**🔴 「id 不存在」与「已注销」刻意合流（本 story 改掉的一个既有假设）**

原先照抄迷你卡写了「查不到 → 404」。**那个分支根本到不了**：`findAuthorViews` 对查不到的 id
**补齐匿名投影**（`deleted=true`），所以两种情况一直都是同一个 200。
这次没有把它「修成真 404」，而是**把代码改成与事实一致并写明理由**：能区分「这个 id 从没存在过」
与「这个 id 注销了」，等于给了一个按 id 遍历、确认谁注册过的枚举口子。客户端两侧也用同一句文案。
（⚠️ `MiniProfileController` 里那段同样的死分支没动 —— 那是既有端点，不在本 story 范围。）

**code-review 复审后修掉的（3 findings 全修）**

1. 🔴 **`publicProfileProvider` 漏了 `isAutoDispose: true`**：Riverpod 3 的 `FutureProvider.family`
   **默认 keep-alive**，缓存活满整个进程。后果四条，最重的是**同设备换账号**：
   B 会读到 A 缓存里的 `self: true`（于是 B 连举报 / 拉黑入口都没有）与 A 对第三人的
   `reported: true`（A 的举报历史泄漏给 B）—— 与 bug 20260730-421 / 446 同型。
   其余三条：举报完再进去「已举报」标记消失（用户会重复举报）、拉黑完再进去看到的是缓存的 200
   而不是「你已拉黑」、断网那次失败被永久缓存。→ 置 `isAutoDispose: true`，
   并加了一条「退出再进必须重新取数」的回归用例。
2. **`author == null → 404` 是不可达分支、其单测是假绿**（stub 了线上到不了的状态）→ 见上一节。
3. **Riverpod 3 的自动重试没关**：错误态会在「失败 / 加载中」之间自己横跳，用户点不到重试按钮；
   而本端点的失败以 403 已拉黑为主，退避重试只是替用户反复敲一扇永远不开的门。
   → `retry: (_, _) => null`（同 `blockedUsersProvider`），并断言失败后取数**恰好 1 次**。

**范围边界（有意不做）**

- **内容网格与获赞总数（Story 2.2）、宠物卡（Story 2.3）、自己视角的「编辑资料」（Story 2.4）都不做**。
  身份区之下**刻意不摆空网格占位**：一个恒空的「Postingan」区块会被当成「这人没发过东西」，
  那是错误信息，不是占位（有一条用例钉着页面上没有 GridView）。
  `self` 已经在下发，本页只用它做一件事：不渲染「···」。
- **迷你卡组件文件与后端 `/mini-profile` 端点保留**。AC2 的原文是「不再被任何入口引用」，
  而不是「删掉」；两者各自还挂着一批既有回归用例（拉黑 / 举报 / 埋点入口），删组件等于同时删那批覆盖。
  → 组件头部标注「已退役」，并有一条守门测试钉死 `lib/` 里零引用 + 五处入口各自已收口。
  **真正的删除是另一次改动**，前提是主页侧的等价用例稳下来。
