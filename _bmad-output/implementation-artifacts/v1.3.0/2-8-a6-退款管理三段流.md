# Story 2.8: A6 退款管理三段流

Status: review

> 自包含 story。与用户沟通用中文。执行纪律见根 `CLAUDE.md`。纯页面重构：五个写端点零变更；**退款职责分离护栏（A-1，最高危）必须原样保留并有回归测试**；`refund-detail.html` 与其 GET 路由退役。前置：2-3a、2-3b。

## Story

As a 客服 / 主管 / 财务，
I want 退款单按「判定 → 审批 → 打款」三段在一个工作台里流转，我只看到我这一段的按钮，
so that 职责分离在界面上就成立。

## Acceptance Criteria

**AC1 · 页签与左栏**
**Given** `/admin/refunds`（`VIEW_AUTH` = SUPER_ADMIN or `refund.view` or `refund.submit` or `refund.approve` or `refund.payout`）
**Then** 页签 = 待客服判定 ｜ 待主管审批 ｜ 待财务打款 ｜ 已完结·已驳回，按 `RefundStatus` 阶段映射，各带计数；左栏行第一行 = 退款单号 + 渠道标签 + 状态点，第二行 = 金额 / 净额 + 当前阶段 + 时间；**默认时间升序（先进先出）** `[L1]`

**AC2 · 右栏四区**
**Then** ① 金额卡：订单金额 / 净额 / 出款渠道 `payoutChannel` / 收款账号（**脱敏规则原样**，`payoutAccount` 为字段级加密密文，展示层只出脱敏串，绝不入日志）；净额 ≠ 订单金额 → 黄底提示差额来源；② 来源卡：订单号（跳订单抽屉）+ 来源客服工单（跳 A5 `?open=`）；③ 三段流程条：判定 → 审批 → 打款，当前段高亮，已完成段显示操作人 + 时间 + 备注，驳回终止显示驳回段与理由；④ 当前段操作区 `[L2]`

**AC3 · 操作表（零变更）**

| 段 | 按钮 | 端点 | 参数 | 权限（现状常量） | 确认 |
|---|---|---|---|---|---|
| 客服判定 | 批准退款需求 | `POST /admin/refunds/{refundToken}/approve` | — | `SUBMIT_AUTH` = SUPER_ADMIN or `refund.submit` | 无 |
| 客服判定 | 驳回 | `POST /admin/refunds/{refundToken}/reject` | （现状无参数，原因**前端必填**落备注，见 Dev Notes） | `SUBMIT_AUTH` | 无 |
| 主管审批 | 审批通过 | `POST /admin/refunds/{refundToken}/approval` | `note`（必填） | `APPROVE_AUTH` = SUPER_ADMIN or `refund.approve` | 无 |
| 主管审批 | 驳回申请 | `POST /admin/refunds/{refundToken}/approval-reject` | `reason`（必填） | `APPROVE_AUTH` | `data-confirm` |
| 财务打款 | 确认 Iris 打款 | `POST /admin/refunds/{refundToken}/payout` | （现状无参数；「附出款凭证上传」见 Dev Notes） | `PAYOUT_AUTH` = SUPER_ADMIN or `refund.payout` | `data-confirm` 复述金额 + 渠道 |

**Then** 五端点路径 / 参数 / `@PreAuthorize` 与现状逐字一致 `[L0]`

**AC4 · 只渲染权限匹配段**
**Then** 右栏操作区**仅**渲染登录者权限对应段的按钮：`refund.submit` → 判定段；`refund.approve` → 审批段；`refund.payout` → 打款段；其余段只读；SUPER_ADMIN 三段可见 `[L2]`
**And** 段状态不匹配（如已在审批段而登录者只有 submit 权）→ 无按钮，流程条显示已完成段 `[L1]`

**AC5 · 🔴 职责分离护栏原样保留**
**Given** `RefundService.guardDutySeparation`（A-1：submitter / approver / payer 两两不可为同一 `admin_id`，**SUPER_ADMIN 不豁免**，违规走独立事务 `auditRecorder.recordViolation` 后 `AppException.forbidden`）
**When** 同一账号尝试兼任两段（含超管）
**Then** 拒绝 + 违规审计；界面在 403 fragment 中显示「退款职责分离：同一人不可兼任提交/审批/打款」；**本 story 不得在模板层用「按钮不渲染」替代服务层护栏**（模板隐藏只是体验，护栏在服务层）`[L1]`
**And** 既有 `RefundService` 职责分离测试全绿 `[L1]`

**AC6 · htmx 动线**
**Then** 各段提交：200 + 右栏 fragment（`data-next-id`）+ oob 左栏行与四页签计数 + `HX-Trigger admin:badge-refresh`；已打款为绝对终态；422 / 403 fragment；非 htmx 维持 PRG；无键盘 ↑/↓ `[L1]`

**AC7 · 退役与深链**
**Then** `GET /admin/refunds/{refundToken}` 与 `refund-detail.html` 删除（并入 `GET .../{refundToken}/detail` fragment）；列表支持 `?open=<refundToken>` 自动开该条（A5「跳 A6」依赖）；不做旧路由跳转 `[L1]`

**AC8 · 测试与三语**
**Then** MockMvc 四条 + 三种权限各只渲染自己段 + 超管兼任被服务层拒绝并有违规审计；新 key `admin.v130.refunds.*`，复用 `admin.refunds.*` / `admin.refundDetail.*`；ID 无截断 `[L1/L2]`

## Dev Notes

### 🔴 最高危点：A-1 职责分离在服务层，界面只是镜子
`RefundService` 类注释与 `guardDutySeparation`（`:401-411`）：纯 `admin_id` 相等判定、不看角色、SUPER_ADMIN 不豁免、违规先 `recordViolation`（独立事务）再 `forbidden`。本 story 的「只渲染权限匹配段」是体验层；**不得**把任何判断下沉到模板后删服务层护栏，也不得为了让超管「顺畅」放宽。403 fragment 文案沿用异常消息。

### 收款账号 PII
`RefundRequest.payoutAccount` / `accountHolderName` 为字段级加密（AES-GCM）；现状 `refund-detail.html` 有「收款账号（脱敏）」展示。重构后 fragment 复用同一脱敏 helper；日志禁记。

### 现状代码要点

| 文件 | 现状 | 改什么 | 必须保留 |
|---|---|---|---|
| `admin/refund/web/AdminRefundController.java` | `GET /admin/refunds`、`GET /{refundToken}`（`VIEW_AUTH` 四码任一）；`approve` / `reject`（`SUBMIT_AUTH`）；`approval(note)` / `approval-reject(reason)`（`APPROVE_AUTH`）；`payout`（`PAYOUT_AUTH`） | fragment GET、Hx 分叉、删详情 GET | 四个 AUTH、五个 POST 签名 |
| `pay/refund/service/RefundService.java` | 三段流 + `guardDutySeparation` + `RefundAuditRecorder.recordViolation`（REQUIRES_NEW） | **不动** | 全部 |
| `templates/admin/refunds.html`（47 行）/ `refund-detail.html`（76 行） | 列表列：订单 / 退款单 / 客服判定…；详情含 `paymentProof` 展示、`note` / `reason` 必填输入 | 合为模板 A | key 复用；`required` 语义 |

### 页签 ↔ 状态映射
按 `RefundStatus` 枚举（`pay/refund/domain`）把状态分到四段；已驳回与已打款同入「已完结·已驳回」。实现时读枚举全集写成一个 `switch`，缺值编译期报错优于运行期漏。

### Project Structure Notes
落 `admin/refund/**` 与 `templates/admin/refunds.html` + `fragments/refund-*.html`；不碰 `pay/**`；无迁移。
