# Story 1.3: 标记一个场所

Status: ready-for-dev

## Story

As a 发现了一家能带狗进的咖啡店的用户,
I want 把它标记下来,
so that 别人也能找到这个地方，我自己下次也不用再翻记录。

## Acceptance Criteria

**AC1 — 字段全集（FR-112.1）** `[L0]`
名称必填 ≤80 · 类型单选**7 类全给**（咖啡店/餐厅/公园/商场/酒店民宿/宠物服务/其他）· 宠物友好标签多选 ≥1 且**6 个全给**（允许入内/户外座位/宠物餐食/宠物活动区/需牵引/大型犬友好）· 文字地址必填 · 照片 1–9 张单张 ≤10MB · 描述选填 ≤200。
⚠️ UI 稿 A5 的类型与标签是**示意省略**，实现必须按全集。

**AC2 — 保存按钮态** `[L2]`
必填未填满时「保存」**灰色禁用**；全部满足才变亮可点。不允许"点了没反应又不说少了什么"。

**AC3 — 位置来源** `[L2]`
本 story 位置取**当前定位**（地图选点在 Story 1.4 加，**本条不依赖它**）。未授权定位时明确提示需要位置，不静默失败。

**AC4 — 不可修改的前置告知** `[L2]`
表单渲染时即告知「提交后不可修改，请仔细核对」（本版用户不可编辑场所，2026-09-15 拍板）。

**AC5 — 服务端硬拒编辑** `[L0]`
服务端**不提供任何场所编辑接口** —— 硬拒而不是只在前端藏入口。

**AC6 — 成功态** `[L2]`
Toast「场所标记成功」并返回列表/详情。

**AC7 — 失败态** `[L2]`
字段级校验未通过时**只出内联错误**，请求**不真的发出**，**不叠加**通用「提交失败」横幅。

**AC8 — 审核与图片** `[L1]`
照片与文字走既有三方自动审核（先发后审）；照片走既有上传链路进**公开桶**并完成 EXIF 剥离兜底。

### 🔴 "不可编辑"要在三个层面一致

1. **前端**：表单前置告知 + 详情页无编辑入口（Story 1.5 的 AC）
2. **后端**：不提供编辑接口（本 story AC5）
3. **产品**：纠错走后台 AB-17A

只做第 1 层等于留了个半开的口子——有人直接调接口就改了。既有先例：宠物档案的「物种创建后不可修改」就是前端置灰 + 服务端硬拒两层。
