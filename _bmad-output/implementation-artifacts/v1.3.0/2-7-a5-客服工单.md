# Story 2.7: A5 客服工单

Status: ready-for-dev

> 自包含 story。与用户沟通用中文。执行纪律见根 `CLAUDE.md`。纯页面重构：四个写端点零变更；`support-ticket-detail.html` 与其 GET 路由退役。前置：2-3a、2-3b。

## Story

As a 客服运营，
I want 在双栏工作台里看工单正文与附件、关联订单、判定退款需求、结案，
so that 一条工单在一屏内处理完。

## Acceptance Criteria

**AC1 · 页签与左栏**
**Given** `/admin/support-tickets`（`VIEW_AUTH` = SUPER_ADMIN or `support.view` or `support.handle`）
**Then** 页签 = 待处理 ｜ 待联系（需联系=是 且 未联系）｜ 已结案，各带计数；左栏行第一行 = 工单标题 + 状态点，第二行 = 需联系标记 + CSAT（有则星值）+ 时间；默认时间倒序；每页 20 `[L1]`

**AC2 · 右栏五区**
**Then** ① 工单正文 + 附件（图点开大图）；② 联系卡：联系方式 / 需联系 / 已联系状态；③ 关联订单区：已关联 → 订单摘要卡（可跳订单详情抽屉 `?open=`）+ 按钮变「改绑订单」；未关联 → 订单号搜索框 + 「关联」钮；④ 退款需求判定区：批准（生成退款单，显示单号并可跳 A6 `?open=<refundToken>`）/ 驳回（原因必填）；⑤ 结案区 `[L2]`
**And** 未关联订单时判定区禁用（防呆 F7-4，先关联才有金额依据）；结案后进只读态，CSAT 回填后展示 `[L1]`

**AC3 · 操作表（零变更）**

| 按钮 | 端点 | 参数 | 权限（现状常量） | 确认 | 成功后 |
|---|---|---|---|---|---|
| 关联 / 改绑订单 | `POST /admin/support-tickets/{ticketToken}/link-order` | `orderToken` | `HANDLE_AUTH` = SUPER_ADMIN or `support.handle` | 无 | 停留本条 |
| 批准退款需求 | `POST /admin/support-tickets/{ticketToken}/refund-approve` | — | `REFUND_SUBMIT_AUTH` = SUPER_ADMIN or `refund.submit` | `data-confirm` 复述金额来源订单 | 停留本条（显示退款单号） |
| 驳回退款需求 | `POST /admin/support-tickets/{ticketToken}/refund-reject` | （现状无参数） | `REFUND_SUBMIT_AUTH` | 原因必填（**前端必填 + 备注写入内部备注**，端点不加参数——见 Dev Notes） | 停留本条 |
| 已联系 + 已解决结案 | `POST /admin/support-tickets/{ticketToken}/resolve` | — | `HANDLE_AUTH` | `data-confirm` | 下一条 |

**Then** 四端点路径 / 参数 / `@PreAuthorize` 与现状逐字一致 `[L0]`

**AC4 · 权限态**
**Then** 有 `support.view` 无 `support.handle` → 关联 / 结案禁用；无 `refund.submit` → 退款判定区两钮禁用，均注明所缺权限中文标签 `[L2]`

**AC5 · htmx 动线**
**Then** 关联 / 改绑 / 退款判定：200 + 右栏 fragment（停留本条）；结案：200 + 右栏 fragment（`data-next-id`）+ oob 左栏行与页签计数 + `HX-Trigger admin:badge-refresh`；422 行内 err；非 htmx 维持 PRG；无键盘 ↑/↓ `[L1]`

**AC6 · 退役**
**Then** `GET /admin/support-tickets/{ticketToken}` 与 `support-ticket-detail.html` 删除（并入 `GET /admin/support-tickets/{ticketToken}/detail` fragment）；无 `th:href` 残留；不做跳转 `[L1]`

**AC7 · 测试与三语**
**Then** MockMvc 四条 + 未关联订单时判定区禁用断言 + 结案后只读；既有 `AdminSupportTicketController` / `SupportTicketService` 测试全绿；新 key `admin.v130.support.*`，复用 `admin.support.*` / `admin.ticket.*` `[L1/L2]`

## Dev Notes

### 🔴 「驳回原因必填」与「端点零变更」的取舍
逐页规格 A5 写驳回「原因必填」，但现状 `refund-reject` 端点无参数。AB-19A 原则是不改端点；本 story 采用**前端必填 + 原因落内部备注**（`ticket_internal_notes` 表存在于 schema，见 `docs/reference/db-schema-reference.md`）。若内部备注没有可复用的写入口，则前端仍必填、原因暂不落库，并在 Completion Notes 记为 Deferred 交 Epic 11 汇总——不要为此新增 `@RequestParam`。
