## Story

As a 想找「能带狗进去坐的咖啡店」这类具体地方的用户,
I want 在场所列表里按类型和宠物友好标签筛一下,
so that 我不用把整张列表一条条翻完、再逐个看标签。

## Acceptance Criteria

### 后端（先做）

**AC1 — 列表接口接受筛选参数** `[L0]`
`GET /api/v1/places` 新增两个**可选、可重复**的 query 参数：`type`（`PlaceType` 枚举值，可多个）与 `tag`（`PlaceTag` 枚举值，可多个）。
不传 = 不筛（与现状完全一致，老版本 App 不受影响）。

**AC2 — 筛选语义** `[L1]`
- **类型之间是「或」**：`type=CAFE&type=PARK` → 咖啡店**或**公园。
- **标签之间是「且」**：`tag=OUTDOOR_SEATING&tag=PET_MENU` → 同时具备两个标签的场所（用户勾多个宠物友好条件，期待的是「都满足」）。
- 类型与标签之间是「且」。

**AC3 — 筛选在截断之前** `[L1]`
筛选条件**写进 SQL 的 WHERE**，在 `MAX_LIST_SIZE`（200）截断**之前**生效 —— 不得「先取 200 条再在内存里筛」（那会把 201 名之后的匹配项静默丢掉）。
「按距离」与「按最新」**两条分支都要带上**筛选（AD-2 Rule 5：两条分支仍各自独立，不合并成一条 SQL）。

**AC4 — 非法值 422** `[L0]`
`type` / `tag` 出现不认识的枚举值 → **422 ProblemDetail**，不静默忽略（同本类对坐标的处理：静默忽略会让用户以为筛过了）。单个参数重复次数上限 = 该枚举的成员数（7 / 6），超出 422。

**AC5 — 距离分支回落带着筛选** `[L1]`
距离分支粗筛为空时现有逻辑回落「按最新」；带筛选时回落的「按最新」**也必须带同样的筛选**，`sortMode` 如实回 `recent`。

**AC6 — 不引入新索引 / 扩展** `[L0]`
标签用 JSONB 包含判断（`tags @> CAST(:tagsJson AS jsonb)`，原生查询）；V1 场所量级（百级）下**不加 GIN 索引**、不加任何 PostgreSQL 扩展。类型走现有列等值 `IN`。无迁移。

### 前端

**AC7 — 筛选条（UI 稿 A1）** `[L2]`
列表 AppBar 下方一行两个 chip：`Jenis ▾` 与 `Tag ▾`，下接一条通栏分隔线，再接列表。有无定位两态（A1/A2）都显示，位置在「开启定位」提示条**之下**。

**AC8 — 选择面板** `[L0]`
点 chip → 底部弹层，列出全部类型（7）/ 全部标签（6），多选勾选；底部「Terapkan」应用、「Reset」清空该维度。
文案**复用**现有 `PlaceType.label` / `PlaceTag.label`（`place_labels.dart`），不新写类型/标签名。

**AC9 — 已选态** `[L0]`
某维度有选中时，对应 chip 变为选中样式（品牌紫底/字）并显示数量，如 `Jenis · 2 ▾`；未选时恢复描边样式。

**AC10 — 查询键含筛选** `[L0]`
筛选进入列表 family 的族键（与坐标并列的 record 字段），改筛选 = 新请求；同一组筛选命中缓存。筛选**只在本次页面生命周期有效**（退出列表即清空，不持久化）。

**AC11 — 筛选后为空（区别于「一个场所都没有」）** `[L0]`
有筛选且结果为空 → 显示「没有符合条件的场所」空态 + 「Hapus filter」按钮（清空全部筛选）；**不**显示「标记一个场所」空态（那是全库为空的引导，语义不同）。

**AC12 — 埋点 / 日志** `[L0]`
不新增埋点；筛选参数不含 PII，可以出现在访问日志（坐标打码规则不变，见 `ApiAccessLoggingFilter.redactQuery` 与 App 侧 `_redactQueryKeys`）。

## Dev Notes

### 🔴 为什么标签必须在 SQL 里筛
列表没有分页，靠 `MAX_LIST_SIZE = 200` 截断（`PlaceQueryService:59`）。先截 200 再在内存筛，第 201 名之后的匹配项会被静默丢掉 —— 用户筛「户外座位」看到 3 个，其实库里有 30 个。
JPQL 不支持 JSONB 包含，所以标签条件用原生查询：`AND tags @> CAST(:tagsJson AS jsonb)`，`:tagsJson` 由服务端用已校验的枚举名拼成 `["OUTDOOR_SEATING","PET_MENU"]`（**只拼枚举名，绝不拼用户原始输入**，杜绝注入）。

### 两条分支仍然独立（AD-2 Rule 5）
不要借机把「按距离 / 按最新」合并成一条带可空坐标的 SQL（1-2 AC4 钉着）。筛选条件是**两条分支各自加**。距离分支里「矩形粗筛 + 应用层算距离 + 半径复筛」的逻辑不动，只是粗筛 SQL 多了筛选条件。
