# Story 3.5: 看板权限与验收对照

Status: ready-for-dev

> 自包含 story。与用户沟通用中文。执行纪律见根 `CLAUDE.md`。
> 后端权限门控 + stag 验收脚本；无迁移。

## Story

As a 产品，
I want 付费卡只对有财务查看权的人显示，且看板任一天任一指标能和口径表对上，
so that 数据既不泄露也可信。

## Acceptance Criteria

**AC1 · 付费卡权限（D-17）**
**Given** 登录账号无 `payment.view`（支付记录页 `AdminPaymentController.VIEW_AUTH` 同码）且非 SUPER_ADMIN
**When** 打开首页或请求 `/admin/charts`
**Then** 响应中不含付费卡（fragment 服务端按 `sec:authorize` / `hasAuthority('payment.view')` 决定是否渲染，且 `DashboardQueryService` 不为其取付费四项数据）；其余四卡正常 `[L1]`
**And** 有权限或 SUPER_ADMIN → 五卡齐全 `[L1]`

**AC2 · 页面可达**
**Then** 看板对所有后台账号可进（与现首页一致），不新增 permission_code；`AdminPageCatalog` 中首页维度的查看权限标记为「全员」 `[L1]`

**AC3 · 验收对照**
**Given** stag 已物化
**When** 运行 `scripts/local/verify_dashboard_parity.sh <date1> <date2> <date3>`（对 stag 只读库执行口径表 SQL）
**Then** 输出 3 日 × 18 项（含 REAL 口径 9 项）的「页面 JSON 值 / `ops_daily_metrics` 值 / 口径 SQL 直跑值」三列对照，全部相等；不等项标红 `[L2]`
**And** 脚本只读，用 `ops_readonly` 账号（memory：运营只读库账号）`[L0]`

**AC4 · 边界**
**Then** 不做导出、不做布局自定义；页面无 PII；付费卡口径提示常驻（D-17 不改口径只改可见性）`[L0]`

**AC5 · 回归**
**Then** MockMvc：`payment.view` 有/无两账号各一条 `[L1]`

## Dev Notes

### 🔴 权限码用 `payment.view`，与支付记录页同码

`AdminPaymentController.VIEW_AUTH = "hasRole('SUPER_ADMIN') or hasAuthority('payment.view')"`（代码核实）。看板付费四项数据源是 `payment_intents` 等付款表，与支付记录页语义一致，故不新增码（D-17）。发货专员、客服等预置角色若无此码则看不到付费卡；四个预置角色的权限清单见 Story 1.4 迁移。

### 🔴 服务端不下发，比模板隐藏更重要

fragment 把 JSON 内嵌在 HTML 里，模板 `th:if` 隐藏卡片但数据仍可能在源码里。必须在 `DashboardQueryService` 层按权限决定是否查付费四项；模板层门控只是第二道。

### 验收口径（D-26）

「任一天任一指标 = 口径表定义」的验收在 stag 做三方对照：页面 JSON = 长表 = 口径 SQL 直跑。口径 SQL 以 3-2 Dev Notes 的改写版为准（显式 WIB 切日、REAL 双口径、#5 按人），**不是**原参考 SQL。
