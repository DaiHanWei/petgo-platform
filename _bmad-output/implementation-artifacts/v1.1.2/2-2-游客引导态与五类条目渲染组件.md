# Story 2.2: 游客引导态与五类条目渲染组件

Status: ready-for-dev

> **所属**：V1.1.2 Epic 2 第二个 Story（**纯前端 · 本 Epic 最重的一条**）。交付两样东西：
> 1. **FR-80 游客引导态**——未登录用户看到的示例成长本（示例宠物 Milo，9 条）
> 2. **五类条目渲染组件**——本版本的关键共享件，Story 3.3 的真实时间线**必须复用**它
>
> ⚠️ **NFR-7 硬约束**：游客示例与真实时间线**共用同一套渲染组件**。若两条 story 各写一套，样式会随时间走样——游客被种草的那本「成长本」跟他注册后真正拿到的不是一个东西，FR-80 的整个承诺就落空。
> ⚠️ **本 Story 同时定义 `itemType` 词表**，Story 3.2 的后端必须采纳，不得另立一套取值。
> ⚠️ **门控在 2.4 才解**，本 Story 完成时游客走不到该页——通过 2.1 的分发入口直接构造验收。
> ⚠️ **示例内容以 UI 稿 A1 为权威**（2026-08-03 产品拍板）：示例宠物为**猫 Mochi**（非 PRD 初稿的金毛 Milo）；9 条内容以 A1 为准（PRD FR-80 示例表已分叉，作废）。**只有 3 条需要配图**，其余 6 条是默认卡片。

## Story

As a **还没注册的访客**,
I want **一打开 App 就看到一本别人家宠物的成长本长什么样**,
so that **我会想「我也想给我家宠物记一篇」，而不是先被要求登录（FR-80）**。

## Acceptance Criteria

> **验证层**：**L0**（analyze / widget test / 契约词表）· **L2**（模拟器视觉 + 飞行模式）。本 Story 无 L1（零后端依赖）。

### AC1 — 游客引导态页面结构（L2 · UX-DR4）

**Given** UI 稿 A1 屏
**When** 游客进入 Diary
**Then** 页面自上而下为：**真实 Diary 页头**（编辑入口 + 健康记录卡 + 身份证图标按钮 + 个性签名行）、**Hero 示例时间线**、**情感化标题 + 一句话说明**、**唯一主 CTA**
**And** ⚠️ **页头结构以现网实现为准，不照 UI 稿 A1/A3 的入口卡画法**（2026-08-03 核实并拍板）：健康记录入口是**实心卡**（标题 + 副文案），身份证入口是 **38×38 纯图标按钮**（徽章图标），**无标题、无编号**。UI 稿把身份证画成了带 `#00842` 编号的卡片，**该处作废、不实现**
**And** 主 CTA 文案**不出现「登录」字样**，点击进入 V1.0.0 既有建档引导流程（FR-0G）
**And** 页面**不含**「已有账号？登录」次要入口（2026-07-30 已删，只保留一个主 CTA）

### AC3 — 五类条目渲染组件 + `itemType` 词表（L0 · NFR-7 · UX-DR10 · AD-13 Rule 4，本 Story 核心交付物）

**Given** 游客示例与真实时间线必须共用同一套条目渲染组件
**When** 实现完成
**Then** 存在**一套**统一的五类条目渲染组件，按 UI 稿 **A6 屏样式基准**实现：

| 类 | 样式 |
|---|---|
| ① 普通快乐时刻 | 标准照片卡（图 + 简短配文 + 日期），**无任何徽章/标记** |
| ② 打卡关联型里程碑 | 照片卡 + 右上角**小金色徽章角标**（🏆 + 里程碑名），保持「这是一条内容」的观感 |
| ③ 系统自动型里程碑 | **横向通栏庆祝 banner**，无需照片，图标 + 大字标题，视觉上是「事件」而非「内容」 |
| ④ 健康/问诊类记录 | **胶囊/标签式条目**，图标 + 一行字，明显小于照片卡 |
| ⑤ 身份证解锁 | **独立证件卡样式**（圆角 + 证件质感 + 照片/名字/编号排版） |

**And** 该组件的输入为携带 `itemType` 标识的条目数据，**不关心数据来源**
**And** ⚠️ **组件只负责渲染，不得内置任何跳转行为**——点击回调由**调用方注入**。原因：游客态点 banner 是弹建档引导（AC8），真实态点 banner 是跳里程碑列表（Story 3.3 AC5），**两边语义不同**；若把跳转写死在组件里，游客态就只能另写一套 tile，NFR-7 当场破功
**And** 类② 的金色徽章角标为**独立可点区域**，其回调同样由调用方注入
**And** ⚠️ **Diary 页头同样抽为共用组件**（编辑入口 + 健康记录卡 + 身份证图标按钮 + 个性签名行），入口可点性由调用方以参数控制——Story 3.3 要求真实态页头与游客态一致，会复用本组件
**And** ⚠️ **本 Story 同时定义 `itemType` 的五个取值词表**（UPPER_SNAKE，与上表一一对应），作为前后端共同契约；**Story 3.2 的后端实现必须采纳该词表，不得另立一套取值**
**And** 游客态通过**内置常量数据**喂给该组件，**未另写一套渲染**
**And** Story 3.3 的真实时间线将复用同一组件

### AC4 — 零网络依赖（L2 · NFR-5 · AD-13）

**Given** 游客态是 App 门面
**When** 设备处于**飞行模式 / 无网络**
**Then** 页面**完整渲染**，不出现白屏、loading 态或错误态
**And** 9 条文案走现有双语文案体系（`app_{en,id}.arb`）
**And** **3 张时间线配图 + 1 张宠物头像**为 **App 内置资源**（`assets/`）——**不是 9 张**，其余 6 条无需配图
**And** 游客态**不调用**任何需要宠物档案的后端接口（现有档案接口对无档案用户抛 404）

### AC5 — 软性登录触发点拆分（L0 · FR-79）

**Given** FR-0B 软登录浮层不适用于 Diary 游客态
**When** 游客在 Diary 页滚动
**Then** **不触发**任何滚动式或弹层式登录推荐
**And** 登录引导**仅**由页面内常驻主 CTA 承担
**And** Discovery 侧 FR-0B「浏览至第 3 页触发」逻辑**完全不变**（UX-DR2 为回归基准）

### AC6 — 占位允许（L0）

**Given** OQ-1（印尼语文案已在 A1 稿中给出；**3 张配图 + 1 张 Mochi 头像**尚未到位）
**When** 本 Story 实现
**Then** 允许使用**占位文案与占位图**完成全部结构与样式
**And** 素材到位后仅需替换资源，**不需改结构**
**And** 占位资源以可检索的命名标注（便于日后替换时不遗漏）

### AC8 — 示例内容可无登录查看详情（L2，2026-08-03 新增）

**Given** 游客在示例时间线上点击条目
**When** 点击 **3 条带图内容**（#3 玩水 / #7 深夜 / #8 晒太阳）
**Then** **直接进入示例内容详情，无需登录**
**And** 详情内容全部来自**内置常量**（图片 + 配文 + 日期），**零网络请求**（延续 AC4）
**And** 详情页视觉与真实内容详情页一致，让游客形成「我也能有这样一条」的观感

**When** 点击**其余 6 条**（banner ×3 / 胶囊 ×2 / 证件卡 ×1）
**Then** **触发主 CTA 的建档引导**（等同于点了主 CTA）
**And** **不得**跳转里程碑列表页 / 健康记录列表页 / 身份证页——这三处在真实时间线里是跳转目标，但**均为受控页**，游客点了会在种草页中间撞上登录框

**When** 在示例详情页点击**点赞 / 评论 / 举报**
**Then** 三个按钮**正常展示**（保持真实详情页的完整观感）
**And** 点击**任意一个都触发建档引导**，不执行真实互动

**And** ⚠️ **路由陷阱（必须避开）**：示例详情**不得**挂在 `/profile/...` 路径下——AD-7 规定 `/profile` 前缀默认受控、仅精确放行 `/profile` 主页本身，放在该前缀下的示例详情会被 redirect 拦截，游客点进去直接被弹回
**And** ⚠️ **不得**复用 `/content/:id` 真实详情路由——示例条目无后端 ID，会 404
**And** 推荐实现：**页内推入的示例详情视图**（不新增受控路由）或挂在非 `/profile` 前缀的独立路径

### AC7 — 验收路径说明（L0）

**Given** 门控在 Story 2.4 才解除，本 Story 完成时游客尚无法从 Tab 走到该页
**When** 验收本 Story
**Then** 通过 Story 2.1 的状态分发入口直接构造游客分支验收（widget test + debug 路由）
**And** 真实游客可达性由 Story 2.4 交付
**And** 本 Story **不得**为了自测而提前放行门控

## Dev Notes

### 关键约定

- **组件先于页面**。先把五类 tile 和 `itemType` 词表定下来，再拼游客页。顺序反了容易把示例数据的形状写进组件里，3.3 复用时就要返工。
- **内置示例数据要用真实条目契约的形状构造**（携带同样的 `itemType`），这样才能直接喂给同一组件。
- **零网络依赖是硬要求**：这是游客看到的第一屏，白屏代价极高。AC4 的飞行模式验收不可省。
- **占位不影响验收**：OQ-1 素材是外部依赖，结构与样式先做完。

### 强制护栏

- **禁止为游客态另写一套渲染**（NFR-7 / AD-13 Rule 4）。
- **tile 组件不得持有跳转行为**——点击回调一律由调用方注入（游客态与真实态语义不同）。
- 游客态**禁止调用**需要宠物档案的接口。
- **不得提前解门控**（属 2.4）。
- **示例详情不得挂在 `/profile/...` 前缀下**（AD-7 会拦截），也不得复用 `/content/:id`（无后端 ID → 404）。
- 示例详情**仍须零网络**（NFR-5 延续到详情层）。
- 其余 6 条**不得**跳转里程碑/健康记录/身份证页（受控页，会在种草页中间弹登录框）。
- Discovery 的 FR-0B 逻辑一行不改。
