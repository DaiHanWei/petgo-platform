# Story 3.4: 日历联动结构化健康记录与当天详情排序

Status: ready-for-dev

> **所属**：V1.1.2 Epic 3 第四个 Story（**后端小 + 前端中**）。交付：日历格子按大类优先级只显一个标记、结构化健康记录首次进日历、**修复纯文字日记错显 🏥 的现网缺陷**、当天详情按大类排序。
> ✅ **后端比 PRD 以为的做得多**：`DayCell` 现有五维（`day` / `firstImageUrl` / `hasHappyMoment` / `hasHealthEvent` / `healthRecordType`），结构化健康记录已于 bug `20260722-352` 并入。**实际只缺「是否多条」一维**。
> ✅ **纯文字日记错显 🏥 是纯前端缺陷**：后端 `hasHappyMoment` 早已与「有无图片」解耦，是前端渲染只判断 `firstImageUrl` 才落到问诊图标兜底。**修它零后端改动**。
> ⚠️ **当天详情不是"改排序"这么简单**：现状只含快乐时刻 + 问诊健康事件，**结构化健康记录根本没纳入**，须先补源再改排序（AD-10）。
> 与 Story 3.3 无依赖，可并行。

## Story

As a **已建档的用户**,
I want **日历上能看出哪天带宠物打了疫苗、哪天只写了文字日记**,
so that **我翻月历时不用点进去才知道那天发生了什么（FR-84）**。

## Acceptance Criteria

> **验证层**：**L0**（analyze / 图标常量 / 契约 test）· **L1**（Docker pg：多条判定、当天详情三源）· **L2**（模拟器视觉）。

### AC1 — 后端仅补「当天健康记录条数」一维（L1 · AD-9 Rule 1）

**Given** `CalendarMonthResponse.DayCell` 现有五维已包含结构化健康记录
**When** 实现完成
**Then** 后端**仅新增一维**：当天结构化健康记录的**条数**（或「是否多于一条」布尔）
**And** **未重建**任何已存在的维度（`day` / `firstImageUrl` / `hasHappyMoment` / `hasHealthEvent` / `healthRecordType` 原样复用）

### AC2 — 格子「三大类取其一、只显一个」（L2 · UX-DR11 · FR-84）

**Given** 格子渲染规则改为按优先级只显一个标记（覆盖 FR-37 原「照片 + 🏥 角标叠加」）
**When** 用户查看月历
**Then** 按下表优先级取当天存在的最高优先级大类，**只渲染它的单一表示**：

| 优先级 | 条件 | 显示 |
|---|---|---|
| ① | diary 带图 | 该日**最早一条的首图缩略图**铺满格子，**不再叠加任何角标** |
| ② | 有 diary 但**全部无图**（纯文字日记） | **通用 diary 标记** `edit_note_outlined` |
| ③ | 无 diary，但有问诊/AI 健康事件 | **`local_hospital_outlined`** 🏥 |
| ④ | 无 diary、无问诊，但有结构化健康记录 | 单条 → 该类型图标；**多条 → 通用医疗箱 `medical_services_outlined`** |
| ⑤ | 无任何记录 / 未来日期 | 沿用 FR-37 现状（日期数字 + 淡色「+」/ 灰色不可点） |

### AC3 — 修复纯文字日记错显 🏥（L2，现网缺陷）

**Given** 后端允许「图片和文字二选一」发布，纯文字日记真实存在
**When** 某天只有纯文字日记
**Then** 该日格子显示**通用 diary 标记**
**And** **图片加载失败**时显示图片占位符或降级为通用 diary 标记
**And** ⚠️ **任何情况下都不得回退到问诊图标**
**And** 本项为**纯前端修复**，判定依据改用后端已下发的 `hasHappyMoment`（不再只看 `firstImageUrl`）

### AC4 — 图标总表（L0）

**Given** PRD FR-84 图标总表（2026-07-29 定稿）
**When** 实现完成
**Then** 取值如下：

| 用途 | 图标 | 颜色 | 状态 |
|---|---|---|---|
| 疫苗 | `vaccines_outlined` | coral 红 | 现状不变 |
| 驱虫 | `medication_outlined` | triageGreen 绿 | 现状不变 |
| 绝育 | `healing_outlined` | mint | 现状不变 |
| **月经** | **`water_drop`（实心）** | **红色** | **本版本变更** |
| 自定义 | `description_outlined` | muted 灰 | 现状不变 |
| 问诊/AI 健康事件 | `local_hospital_outlined` | coral 红 | 现状不变 |
| **通用健康**（当天多条） | **`medical_services_outlined`** | — | **本版本新增** |
| **通用 diary**（纯文字无图） | **`edit_note_outlined`** | — | **本版本新增** |

**And** 日历格子与健康记录列表页**共用同一套图标，未新设第二套**
**And** 月经图标改红**同时作用于健康记录列表页**（覆盖 V1.1.0 FR-45B）
**And** **未使用任何字面 emoji**（无法着色、老安卓渲染为豆腐块）
**And** 通用健康图标**不得**用 💊 药丸（驱虫已占用，会撞车）
> 月经红色具体色值见 **OQ-11B**（需与 coral `#F0425A` 拉开距离）；**不阻塞**，可先用 coral 占位，出色值后替换。

### AC5 — 当天详情先补第三源再改排序（L1 · AD-10 · UX-DR12）

**Given** `getDayDetail` 现仅含快乐时刻 + 问诊健康事件
**When** 实现完成
**Then** **先补入结构化健康记录第三个数据源**
**And** 再按大类排序 **diary > 问诊 > 健康记录**，类内按时间（覆盖 FR-37 原「按发布时间正序」）
> ⚠️ 估工时勿把本项当成「只改排序」。

### AC6 — 与时间线的优先级不对称是刻意的（L0 · AD-16）

**Given** 时间线健康记录优先、日历 diary 优先，方向相反
**When** 同一天既有带图日记又有疫苗记录
**Then** **日历显示日记首图、时间线显示两条**（照片卡 + 健康胶囊）
**And** 该不对称为**刻意设计**（粒度不同：时间线逐条分类，日历整天取一个代表标记）
**And** 代码注释须标明「**不得对齐**」，防止后续开发者误判为缺陷而擅自统一

### AC8 — 日历与当天详情的失败态（L2 · CROSS-STORY F13，2026-08-03 补）

**Given** F13 统一口径明确覆盖「FR-37 时间线 / **日历** / **当天详情页**失败」，而本版本 UI 稿的 A5 只画了时间线失败态
**When** 日历月视图或当天详情加载失败
**Then** 按 F13 同一口径处理：已加载内容保留、提供重试入口、不整页白屏
**And** 与 Story 3.3 的时间线失败态**复用同一套失败态组件**，不新设一套

### AC7 — 契约三处同步（L0 · NFR-8）

**Given** `DayCell` 新增一维
**When** 实现完成
**Then** **后端 record、App data DTO、后端契约 test 三处已同步**（App mock 层已随 `8e85b40d` 删除，不适用）

## Dev Notes

### 关键约定

- **后端改动比 PRD 描述的小得多**（AD-9）。PRD 说「需后端补结构化健康记录字段」，实际今年 7 月修 bug 时已并入，只缺条数。估工别按 PRD 描述来。
- **当天详情改动比 PRD 描述的大**（AD-10）。PRD 只说改排序，实际结构化健康记录根本没进这个接口，要先补源。
- **纯文字日记错显 🏥 修起来很便宜**——纯前端，后端数据一直是对的。
- **图标要抽公共常量**：日历与健康记录列表页共用一套，避免日后改一处漏一处。

### 强制护栏（违反即返工）

- 格子**只渲染一个标记**，不得保留任何角标叠加。
- **任何情况下不得回退到问诊图标**（含图片加载失败）。
- 通用健康图标**不得用 💊**（与驱虫撞车）。
- **不使用字面 emoji**（着色/老设备渲染问题）。
- 日历优先级**不得**与时间线「对齐」（AD-16）。
- 契约三处同步。本 Story **无 Flyway 迁移**。

### Project Structure Notes

- 后端修改：`profile/dto/CalendarMonthResponse.java`（+条数维）、`profile/service/TimelineService.java`（`getCalendarMonth` 计数 / `getDayDetail` 补源与排序）。
- 后端新增测试：日历与当天详情契约 test、L1 多条判定与三源排序 test。
- 前端修改：`widgets/archive_calendar.dart`、`presentation/day_detail_page.dart`、`presentation/health_list_page.dart`（月经图标）、`domain/calendar_month.dart`、`domain/day_detail.dart`。
- 前端新增：图标公共常量表。
- **无 Flyway 迁移。**
