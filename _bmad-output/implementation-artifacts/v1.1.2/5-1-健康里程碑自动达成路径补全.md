# Story 5.1: 健康里程碑自动达成路径补全

Status: review

> **所属**：V1.1.2 Epic 5 第一个 Story（**纯后端 · 小**）。交付：补全健康类里程碑的自动达成映射——`NEUTER → M9`，以及 M5「第一次看兽医」订阅既有 `ConsultClosedEvent`。
> ✅ **落点比 PRD 描述的小得多**：自动完成逻辑早已存在（`MilestoneAutoCompleteListener.onHealthRecordCreated` 的类型映射 switch），加 M9 就是多写一行；M5 的挂钩点 `ConsultClosedEvent` 也已存在。
> ✅ **OQ-17「M5 只算真人兽医、不含 AI 问诊」自动满足**——该事件只在 `consult` 模块发布，AI 分诊（`triage` 模块）根本不经过该链路，**无需另写排除逻辑**。
> ⚠️ **本 Story 不动打卡路径**。取消打卡归 Story 5.2（前端隐藏 + 后端护栏同批交付）。本 Story 完成后两条路径暂时并存、系统自洽——这是刻意的顺序，反过来会出现「打卡按钮可见但点了报错」。

## Story

As a **会认真录健康记录的用户**,
I want **录完绝育、看完兽医后对应里程碑自己就亮**,
so that **我不用再手动去打一次卡（FR-86）**。

## Acceptance Criteria

> **验证层**：**L0**（映射/订阅单测）· **L1**（Docker pg：真事件触发、幂等、AI 不触发）。本 Story 无 L2（纯后端）。

### AC1 — 类型映射补 `NEUTER → M9`（L1 · AD-11 Rule 1）

**Given** 现有类型映射为 `VACCINE→M3` / `DEWORM→M4` / `MENSTRUATION, NEUTER, CUSTOM→null`
**When** 实现完成
**Then** 新增 **`NEUTER → M9`**
**And** `MENSTRUATION` / `CUSTOM` **维持不映射**（无对应里程碑节点）
**And** 猫 C 系列、狗 D 系列、通用 G 系列**同规则**

### AC2 — M5 订阅既有 `ConsultClosedEvent`（L1 · AD-11 Rule 2）

**Given** M5「第一次看兽医」需在**真人兽医咨询会话结束**时触发
**When** 实现完成
**Then** 订阅既有 `ConsultClosedEvent`（`ConsultCloseService` 已发布），**首次触发、幂等**
**And** 因该事件只在 `consult` 模块发布、AI 分诊不经过该链路，**未另写任何 AI 排除逻辑**
**And** 存在**测试锁定**：AI 问诊无论进行多少次都**不解锁 M5**
**And** 沿用既有范式：`@TransactionalEventListener`(AFTER_COMMIT) + `@Async`，**不引入任何新中间件**

### AC3 — M5 与 S4 是两个独立触发事件（L1 · AD-11 Rule 3）

**Given** FR-16 的问诊存档是**用户可跳过的选择**
**When** 用户问诊后**跳过存档**
**Then** **M5 已解锁**（"看过兽医"这件事已经发生）、**S4 未解锁**
**And** 用户**日后补存**时 S4 补触发
**And** 两者**未被合并实现**
**And** 用户当场存档时两者同时解锁（庆祝合并归 Story 5.2）

### AC4 — 本 Story 不动打卡路径（L1）

**Given** 取消打卡归 Story 5.2（前后端同批交付）
**When** 本 Story 完成
**Then** 两条路径**暂时并存**、幂等、先到先得，系统处于**自洽状态**
**And** **未提前隐藏或拒绝**任何打卡入口
> ⚠️ 提前做后端拒绝会造成「按钮还在但点了报错」的破损中间态。

### AC5 — 非健康类里程碑不受影响（L1）

**Given** 非健康类里程碑（如「第一次玩水」D-S13）
**When** 用户打卡
**Then** 打卡机制**完全不变**，正常解锁
**And** 打卡机制本体**未被删除**

### AC6 — 存量不回溯（L1 · AD-11 Rule 5）

**Given** 存量数据不回溯
**When** 实现完成
**Then** 已通过打卡完成的历史里程碑**保持已完成状态**
**And** **不重新判定、不撤销**

### AC8 — 「健康类里程碑」集合的单一定义（L0，2026-08-03 新增）

**Given** 「健康类四条」这个概念被三条 story 引用（5.2 打卡护栏与候选过滤、6.1 埋点 T-12 校验、3.2 分类判定的语境）
**When** 实现完成
**Then** 存在**唯一一处**定义：健康类里程碑 code 集合 = **{M3, M4, M5, M9}**（含 C/D/G 系列前缀解析）
**And** 下游 story **引用该定义，不得各写一份**
**And** 该定义位置写入 Completion Notes，供后续 story 直接引用

### AC7 — 无 schema 变更、无新中间件（L0）

**Given** 本 Story 只改监听器映射与订阅
**When** 实现完成
**Then** **未新增任何 Flyway 迁移**
**And** 未引入任何新中间件（继承 NFR-10：禁 MQ / 调度中间件 / 通用缓存层）
**And** L4「完成全部健康里程碑」(M3+M4+M5) 逻辑不变（只看三项是否完成、不看完成方式）

## Dev Notes

### 关键约定

- **这条 story 很小，别过度设计**。核心就两处：switch 多一行 + 多一个事件订阅。
- **OQ-17 靠模块边界天然满足**，不要为了"保险"再加一个 `if (!isAiTriage)` ——那是冗余且会误导后人以为两个模块的事件会串。
- **M5 与 S4 不可合并**：M5 看「有没有看兽医」，S4 看「有没有存档」。用户可以只做前者。

### 强制护栏（违反即返工）

- 本 Story **不得**隐藏或拒绝打卡（属 5.2，同批交付前端隐藏）。
- 异步只用 `@Async` + `@TransactionalEventListener`，**禁 MQ / Quartz / 新中间件**。
- 幂等：重复事件不产生重复完成记录。
- 无 Flyway 迁移。

### Project Structure Notes

- 后端修改：`profile/service/MilestoneAutoCompleteListener.java`（+NEUTER 映射、+ConsultClosedEvent 订阅）。
- 后端新增测试：映射 L0 单测、M9/M5/AI 隔离 L1 测试。
- **无 Flyway 迁移。**
