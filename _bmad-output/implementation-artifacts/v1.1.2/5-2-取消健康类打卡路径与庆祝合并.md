# Story 5.2: 取消健康类打卡路径（前后端同批）与庆祝合并

Status: review

> **所属**：V1.1.2 Epic 5 第二个 Story（**后端护栏 + 前端**）。交付：健康类四条里程碑取消打卡路径 + 多里程碑同时解锁时庆祝合并。
> ⚠️ **这是 2026-07-31 产品拍板的反转**：PRD 2026-07-30 原写「打卡路径保留、两条并存」，现改为**健康类只能自动达成**。PRD 两份副本已回改。
> ⚠️ **AC0 与 AC1 必须同批交付**：只做后端拒绝 → 可见按钮点了报错；只做前端隐藏 → 护栏形同虚设（接口仍可被直接调用）。
> 依赖 Story 5.1（自动路径已就位，否则 M9/M5 会暂时无法达成）。

## Story

As a **用户**,
I want **里程碑页面不再给我一个点了也没用的打卡按钮**,
so that **我不会以为疫苗里程碑可以靠发日记解锁（FR-86）**。

## Acceptance Criteria

> **验证层**：**L0**（analyze / 文案核对）· **L1**（Docker pg：护栏拒绝、候选集合）· **L2**（模拟器视觉与庆祝动效）。

### AC0 — 后端显式拒绝健康类打卡（L1 · AD-11 Rule 4 · NFR-11，护栏不可省）

**Given** 健康类四条（**M3 疫苗 / M4 驱虫 / M5 第一次看兽医 / M9 绝育**）取消打卡路径
**When** 客户端或**任何调用方直接请求**对这四条打卡
**Then** 后端 `MilestoneCheckInService` **显式拒绝**并返回业务错误（RFC 9457 ProblemDetail，不外泄堆栈）
**And** **打卡候选列表接口的返回集合中不包含这四条**
**And** ⚠️ **仅前端隐藏按钮不满足本 AC**——接口仍可被直接调用
**And** ⚠️ **本 AC 与 AC1 必须同批交付**

### AC1 — 里程碑列表页隐藏四条打卡入口（L2 · AD-11 Rule 4）

**Given** 健康类四条已取消打卡路径
**When** 用户查看里程碑列表页
**Then** M3 / M4 / M5 / M9 四条**隐藏「去打卡 / 去发布」按钮**
**And** 其**徽章弹层改为说明达成方式**（如「录入健康记录后自动点亮」），**不提供打卡入口**
**And** **其余里程碑的列表页表现完全不变**
> ⚠️ 本 Story 起，AD-11 不再声称「里程碑列表页零改动」。

### AC2 — 打卡引导文案部分作废（L0）

**Given** V1.0.0 打卡引导文案
**When** 实现完成
**Then** `milestone-checkin-prompt-copy.md` 中**健康类四条的文案作废**
**And** **其余条目文案保留**

### AC3 — 多里程碑同时解锁的庆祝合并（L2 · AD-12）

**Given** 同一操作同时解锁多个里程碑（**通用规则，不专属 S4/M5**）
**When** 用户完成该操作
**Then** 庆祝弹层**只弹一次**，不连弹多次
**And** **复用现有 `showMilestoneCelebration()` 单条组件**原样展示**最高级别**那一条，**零新增视觉设计**
**And** 同批其余里程碑由弹层底部**既有「已解锁收藏」圆点带**（含 +N 溢出）自然承载
**And** 同批其余里程碑正常写入里程碑列表页并标记为已完成，只是不各自弹一次
**And** 文案取最高级别里程碑的**既有文案**，**未新写**「一次解锁多个」的特殊文案

### AC4 — S4/M5 三种场景（L2）

**Given** S4/M5 是合并规则最常命中的场景但**并非必然合并**
**When** 用户分别：① 问诊结束**当场存档** ② **跳过存档** ③ **日后补存**
**Then** 分别表现为：① 两者同时解锁 → **合并庆祝一次**（按 M 级）② 只解锁 M5 → **正常单条庆祝** ③ 此时才解锁 S4 → **再单条庆祝一次**

### AC5 — 非健康类打卡不受影响（L1）

**Given** 非健康类里程碑
**When** 用户打卡
**Then** 打卡按钮正常显示、打卡正常成功
**And** 打卡内容选择器（置灰已关联内容）逻辑不变

### AC6 — 存量与达成路径唯一化后果（L1）

**Given** 存量不回溯
**When** 实现完成
**Then** 已通过打卡完成的历史健康类里程碑**保持已完成状态**，不撤销
**And** **已接受的后果**：不录结构化健康记录、也不看真人兽医的用户，这四条**永远无法解锁**；连带 L4「完成全部健康里程碑」也只能靠自动路径达成

## Dev Notes

### 关键约定

- **AC0 与 AC1 必须同批**。这是 Epic 5 内部顺序的核心约束：拆开做任一侧都会造出用户可见的坏状态。
- **健康类 code 判定要抽一处**：护栏与候选过滤共用，否则日后加健康类里程碑会漏改一边。
- **庆祝合并零新增视觉设计**（AD-12）：现有弹层底部本就有「已解锁收藏」圆点带含 +N 溢出，同批解锁的其余条目会自然出现在那里。不要为此新设计界面。

### 强制护栏（违反即返工）

- **后端拒绝不可省**（NFR-11，安全攸关节点）。只藏按钮不合格。
- 非健康类打卡机制**完全不变**，不得连带删除。
- 庆祝弹层**不得**新增视觉设计、不得新写「一次解锁多个」文案。
- 存量已完成记录不回溯。
- 无 Flyway 迁移；不引入新中间件。

### 决策来源与反转记录

PRD 2026-07-30 原写「原有打卡路径保留不变，两条路径并存（纠正早期"取消打卡路径"的表述）」，并在 §2.3 补了「无例外」段。**2026-07-31 产品重新拍板取消健康类打卡**，PRD 两份副本、架构 delta AD-11、epics 均已回改。实现以本 Story 与 AD-11 Rule 4 为准。

### Completion Notes List

  集合**引用 Story 5.1 抽出的 `HealthMilestones`**，未另写一份。
  > 「只在前端隐藏按钮」不合格：绕过 UI 直接调接口仍能打卡就等于规则没落地 —— 断言里对 C/D/G 三系六个 code 逐一验证被拒，并额外验证**非健康类仍走正常流程**（错误信息不同即为通过护栏）。

  `milestoneHintAutoHealth`（「录健康记录或看完兽医会自动点亮」）；其余里程碑渲染完全不变。
  判定用 `isAutoOnlyHealthMilestone(code)`（不看 `triggerType`）——历史数据的 trigger 字段不可信。
- **AC3/AC4 庆祝合并**：`_pollNewlyUnlocked` 由「遇到第一条新解锁就返回」改为**收集全部新解锁 → 取最高级别**（`highestLevelMilestone`，L>M>S、同级取第一条，纯函数可测）。同批其余条目仍由弹层底部既有「已解锁收藏」圆点带（含 +N）承载，**未新增任何视觉设计**。
