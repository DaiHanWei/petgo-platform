# Story 3.3: 时间线前端五类渲染

Status: review

> **所属**：V1.1.2 Epic 3 第三个 Story（**纯前端**）。交付：真实时间线按后端下发的 `itemType` 渲染五类条目。
> ⚠️ **必须复用 Story 2.2 建立的渲染组件**（NFR-7 / AD-13 Rule 4）。本 Story **不得另写一套**——两套渲染会随时间走样，游客被种草的那本册子跟他注册后拿到的就不是一个东西。
> ⚠️ **跨 Epic 软耦合**：2.2 与本 Story 共用组件。排期上建议相邻或指派同一人。
> ⚠️ **接口设计要点**：两边点击语义不同（游客态点 banner 是弹建档引导，真实态是跳里程碑列表），因此**组件只能渲染、不能持有跳转**——见 AC6。这是两条 story 之间最容易踩错的地方。
> 依赖 Story 3.2（后端下发 `itemType`）。

## Story

As a **已建档的用户**,
I want **时间线里不同类型的事看起来就不一样**,
so that **我一眼能分清哪条是随手拍的、哪条是里程碑、哪条是系统替我记的（FR-82）**。

## Acceptance Criteria

> **验证层**：**L0**（analyze / widget test）· **L1**（真后端联调）· **L2**（模拟器视觉）。

### AC1 — 复用同一套渲染组件（L0 · NFR-7）

**Given** Story 2.2 已建立五类条目渲染组件
**When** 渲染真实时间线
**Then** **复用同一套组件**，仅数据来源由内置常量改为后端下发
**And** **未新写第二套渲染实现**
**And** 游客示例与真实时间线的同类条目**视觉完全一致**（可用同一 widget test 断言两侧产出相同 tile 类型）
**And** ⚠️ **组件只负责渲染，不得内置任何跳转行为**——点击语义由**调用方注入**（见 AC6）

### AC2 — 正常态与近空态（L2 · UX-DR7 · UX-DR8）

**Given** UI 稿 A3（正常态）与 A4（刚建档近空态）
**When** 用户查看
**Then** 两态均按稿渲染
**And** 含与游客态一致的 **Diary 页头**结构（编辑入口 + 健康记录卡 + 身份证图标按钮 + 个性签名行）
**And** ⚠️ **身份证入口维持现网的 38×38 纯图标按钮**，**不显示编号**——UI 稿 A3 里的「Kartu Identitas #00842」卡片**作废、不实现**（2026-08-03 拍板）
**And** ⚠️ **复用 Story 2.2 建立的页头共用组件**，仅以参数打开真实态的入口可点性；**不得**在本 Story 另写一份页头布局
**And** 近空态（条目极少）不出现布局塌陷或空洞

### AC3 — 加载失败与重试（L2 · UX-DR9 · CROSS-STORY F13）

**Given** UI 稿 A5 加载失败态
**When** 网络或服务器错误
**Then** 按 F13 统一口径：**已加载内容保留**、仅增量失败时**底部提供重试入口**
**And** **不出现整页白屏**
**And** 首屏失败时提供整页重试入口 +「加载失败，请检查网络后重试」文案

### AC4 — 问诊未存档时的里程碑呈现（L2 · UX-DR13）

**Given** UI 稿 A9
**When** 用户问诊后**跳过存档**
**Then** M5 渲染为**类③通栏 banner**
**And** 用户**补存**后，改由**类④胶囊条**承载、banner 不再出现
**And** 本屏为 Story 3.2 AC3（实时计算）的**可视化验收**

### AC5 — 交互跳转（L1）

**Given** 后端已下发各类跳转目标标识
**When** 用户点击条目
**Then** 类① / 类② → 内容详情页（类②的角标可**再次点击**跳里程碑列表页）
**And** 类③ → 里程碑列表页
**And** 类④ → 健康记录列表页（FR-45B）**对应条目**（带 `?focus=<记录 id>` 滚动 + 短暂高亮）；**时间线内不提供编辑入口**
**And** 类⑤ → 该宠物身份证页（FR-49）

> 📌 **「定位到对应条目」只对类④ 成立**（2026-08-04 code-review 决策 D3）。原文对类②角标与类③
> 也写了「对应条目」，但里程碑列表页不接受定位参数，实际是跳到列表顶部。经拍板**不扩展该能力**
> （里程碑总数有限、页面本身就一屏可扫完，收益不抵改动面），故此处措辞改为「里程碑列表页」，
> 与实现对齐。若日后里程碑数量增长到需要定位，再照类④ 的 `?focus=` 范式补。

### AC6 — 点击行为由调用方注入，组件不持有跳转（L0，2026-08-03 新增）

**Given** 游客态与真实态**共用同一套 tile 组件，但点击语义完全不同**：

| 条目类别 | 游客态（Story 2.2 AC8） | 真实态（本 Story AC5） |
|---|---|---|
| 类① / 类② 照片卡 | 示例详情（内置数据、零网络） | 真实内容详情页 |
| 类③ banner | **建档引导** | 里程碑列表页 |
| 类④ 胶囊 | **建档引导** | 健康记录列表页对应条目 |
| 类⑤ 证件卡 | **建档引导** | 身份证页 |

**When** 实现完成
**Then** tile 组件**不得内置** `context.push(...)` 之类的跳转；点击回调由**调用方按 `itemType` 注入**
**And** 真实时间线注入 AC5 的四类真实跳转
**And** 游客态注入示例详情 / 建档引导（Story 2.2 负责）
**And** 类② 的**金色徽章角标为独立可点区域**，其回调同样由调用方注入
**And** 存在测试锁定：同一 tile 组件在两套不同回调下产出相同视觉、触发不同行为
> ⚠️ 若把跳转写死在组件里，游客态就只能另写一套 tile —— **NFR-7 当场破功**。这是本 Story 与 Story 2.2 之间最容易踩的接口设计错误。

## Dev Notes

### 关键约定

- **本 Story 的成败首先看 AC1**：有没有复用 2.2 的组件。如果发现 2.2 的组件不够用，正确做法是**回去改 2.2 的组件**，不是在这里另写一个。
- **页头结构要与游客态一致**——游客看到的和注册后看到的是同一套（A1 与 A3 稿的页头相同）。
- **失败态按 F13 既有口径**，不新设一套。

### 强制护栏（违反即返工）

- **禁止新写第二套条目渲染**（NFR-7 / AD-13 Rule 4）。
- **tile 组件不得持有跳转行为**——点击回调一律由调用方注入。发现组件内有 `context.push` / `go` 即违规。
- 若需扩展 tile 组件能力，**回去改 2.2 的组件**，不得在本 Story 复制一份改。
- 不新建 `itemType` 枚举（复用 2.2）。
- 时间线内不提供健康记录/里程碑/身份证的编辑入口（只读镜像）。
- 前端**不得自行推断分类**——一律按后端 `itemType`（AD-2 Rule 1）。
