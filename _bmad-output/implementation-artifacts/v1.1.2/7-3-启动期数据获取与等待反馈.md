# Story 7.3: 启动期数据获取与等待反馈

Status: in-progress

> **所属**：V1.1.2 **Epic 7 第三个 Story** —— **纯前端 · 零 schema · 零后端改动 · 零新依赖**。
> 交付：`/me` 与动效**并行**发起、超时 **3s → 5s**、**取消「当天只播一次」门控**，并把等待反馈从「假 spinner」换成「**出现即信息**」的进度线 + 慢网提示。
>
> ⚠️ **依赖 Story 7.2**：进度线与慢网提示的出现时机（1860ms / 2290ms）是**从 7.2 定稿的 1.54s 动效时长推导出来的**。7.2 未落地则这两个阈值没有参照。
> ⚠️ **本 Story 不改落地分流**（矩阵变更与超时兜底的迟到纠正 —— 全属 Story 7.4）。

## Story

As a **网速不好的用户**,
I want **等待的时候能看出来 App 是真的在加载，而不是卡死了**,
so that **我不会以为 App 坏了就把它划掉（FR-89）**。

## Acceptance Criteria

### AC1 — `/me` 改为与动效并行发起（L0 · FR-89 · 决策 C-4）

**Given** 现状 `/me` 与动效**串行** —— `await ref.read(authControllerProvider.notifier).ensureRestored()` 写在 `app_router.dart` 的 `onComplete` 回调内，**动效播完才发请求**
**When** 实现完成
**Then** 改为**并行**：Flutter 首帧（`t≈320ms`）即发起会话恢复
**And** 动效播放与数据获取**互不等待**
**And** ⚠️ `ensureRestored()` 返回的是**共享的恢复 future**（`_restoreFuture ?? Future.value()`，见 `auth_state.dart:44`）—— 并行化只是**提早触发**它，不要新造第二条恢复路径，否则会出现两次 `/me`

### AC2 — 超时上限 3s → 5s（L0 · FR-89 · 决策 D-2）

**Given** 现状为 `.timeout(const Duration(seconds: 3), onTimeout: () {})`
**When** 实现完成
**Then** 改为 **5s**
**And** 该值使慢网提示有 **2.7s** 可读时间（见 AC5 推导）
**And** ⚠️ `.timeout()` **只停止等待、不取消底层请求** —— 恢复完成后仍会写回 `AuthState`。**这是既有行为，本 Story 不改**；由它引出的「兜底态是中间态」问题归 Story 7.4

### AC3 — 取消「当天只播一次」门控（L0 · FR-89 · 决策 C-3 / 缺陷 B-7）

**Given** 现状 `splash_page.dart` 的 `_decide()` 读 prefs 判断当天是否已播，`animate = !shownToday && !_reduceMotion`
**When** 实现完成
**Then** **取消门控，每次冷启动都播**（reduce-motion 仍然直落终态，那是 AC 之外的无障碍要求，不受本条影响）
**And** 一并清理：`AppPrefs` 的 `_kSplashLastShownDate`（`'petgo.splash_last_shown_date'`）常量、`splashLastShownDate` getter、`setSplashLastShownDate` setter、`_todayKey()` 辅助方法 —— **全部删除，不留死代码**
**And** ✅ **连带效果：`prefs` 不再是启动依赖，缺陷 B-7 自然消失** —— 现状 `_decided` 标志在 `AppPrefs.create().timeout(300ms)` 返回前不渲染 mark，造成首帧 300ms 空窗。取消门控后 `_decide()` 不再需要读 prefs，`_decided` 门闸与那 300ms 一并去掉
**And** 🔴 **`test/onboarding/splash_test.dart` 的用例 2「当天已播过：静止终态，~1.4s 后过场」须删除或重写** —— 该场景不再存在（Story 7.2 已改过这两条的版本号断言与时序，本 Story 处理这条用例的存废）
**And** 须有测试锁定「**连续两次冷启动都播动效**」

### AC4 — 进度线：出现即信息（L0 · FR-89 / UX-DR27 / 设计侧挑战 X-4）

**Given** 现状是一个常驻 spinner（定位 `bottom: 108`），从头转到尾、不反映任何真实进度（真实等待由 `Timer` 控制），属**假反馈**；该 spinner 已由 Story 7.2 删除
**When** 动效播完（`1540ms`）但会话恢复**仍未就绪**
**Then** 进度线在 **`1860ms+`** 才出现 —— **它的出现本身就是信息**（区别于旧的常驻 spinner）
**And** 容器高度**预留**，进度线出现/消失**不引起布局位移**
**And** 底部元素自 **92** 起，进度线与慢网提示**共用同一容器**（尺寸规格见 7.2 AC5）

### AC5 — 慢网提示（L0 · FR-89 / UX-DR28 · 决策 C-5、D-3）

**Given** 慢网需要可见提示，但不能打扰快网用户
**When** 进度线出现后**再等 430ms**（即 `2290ms+`）仍未就绪
**Then** 慢网文字提示**淡入**，到 5s 兜底跳转 —— **可读时间 2.7s**（5000 − 2290 = 2710ms）
**And** 文案为**占位** `Koneksi kamu lambat, tunggu sebentar…`（决策 D-3，OQ-22 待母语同事审核后替换）
**And** 🔴 **两语言 ARB 均须登记**（`app_id.arb` + `app_en.arb`），**严禁源码硬编码**；改完必须 `flutter gen-l10n`
**And** 字体为同族 Fraunces 500 / `opsz` 12 / 12.5px / 白 55%（字体本体由 7.2 AC6 接入，本 Story 只用）

### AC6 — 快网路径不出现任何等待指示（L0 · FR-89 · 阈值设计的验收核心）

**Given** 阈值设计的全部意义在于「**快网用户永远看不到那行字**」
**When** 会话恢复在 `≈0.9s` 返回（快网，早于 1.54s 动效结束）
**Then** **不出现进度线，也不出现慢网提示**，动效播完直接进入分流
**And** 🔴 **须有测试锁定该路径无任何等待指示** —— 这是最容易被实现成「先显示再隐藏」的地方，那样快网用户会看到一次闪现

### AC7 — 三方初始化不得阻塞首帧（L0 · NFR-13）

**Given** splash 是首屏，任何初始化卡住都会直接拖慢启动
**When** 三方初始化（如 `Analytics.init()` 的 `Posthog().setup`）卡住或超时
**Then** 带超时上限、失败吞错，**不得拖慢 `runApp`**
**And** 📌 现状 `main.dart` 已在 `runApp` 前 `await Analytics.init()`，而 `Analytics.init()` 内部已有 `.timeout(3s)` 且 try/catch 吞错 —— **本条以核实为主，若已满足则记录「现状已合规」，不必改动**

### AC8 — 严守本 Story 边界（L0）

**Given** 落地分流与迟到纠正属 Story 7.4
**When** 本 Story 实现
**Then** **不改落地矩阵**（`user_state.dart` 的 `landingLocation` 一行不动）
**And** **不加迟到纠正机制**（超时兜底后的重判属 7.4）
**And** **不改 `onComplete` 之后的分流顺序**（pending 深链 > 落地矩阵，保持原样）
**And** **不改视觉规格**（尺寸 / 字体 / 动效三拍均已由 7.2 定稿，本 Story 只加「何时显示等待指示」）
**And** `flutter analyze` 零警告、`flutter test` 全绿、`flutter build apk --debug` 通过

## Dev Notes

### 时点推导（这四个数字是一条链，改一个要重算全部）

| 时点 | 值 | 来自哪 |
|---|---|---|
| 动效结束 | `1540ms` | Story 7.2 AC4 定稿 |
| 进度线出现 | `1860ms` | 动效结束 + 320ms 缓冲 |
| 慢网提示淡入 | `2290ms` | 进度线 + 430ms（决策 C-5 的阈值） |
| 兜底跳转 | `5000ms` | 决策 D-2 的超时上限 |
| **提示可读时间** | **2710ms** | 5000 − 2290 |

**所以：动了 7.2 的动效时长，这四个数全要重算。** 不要把它们当独立常量各自硬编码，宜由「动效时长」派生。

### 现状核实结果（2026-08-04，实施基线）

**`petgo_app/lib/core/router/app_router.dart`**（`/splash` 路由的 `onComplete`）：
- `await ref.read(authControllerProvider.notifier).ensureRestored().timeout(const Duration(seconds: 3), onTimeout: () {})` —— **串行**，动效播完才发起
- 之后：`pendingDeepLinkProvider` 优先 → `appUserStateOf(auth).landingLocation` → T-1 埋点 → `ctx.go(target)`
- **本 Story 只改「何时发起、超时多久」，分流那一段一行不动**（属 7.4）

**`petgo_app/lib/features/auth/domain/auth_state.dart`**：
- `Future<void> ensureRestored() => _restoreFuture ?? Future<void>.value();`（`:44`）—— **共享 future**，重复调用不会重复发请求
- `_restoreSession()`（`:50`）按本地 token 的 role 分别走 `/vet/me` 或 `/me`

**`petgo_app/lib/features/onboarding/presentation/splash_page.dart`**：
- `_decide()`（`:92-119`）：`AppPrefs.create().timeout(300ms)` → 比对 `splashLastShownDate` → `animate = !shownToday && !_reduceMotion` → `setState(_decided = true)` → `_master.forward()` 或 `_master.value = 1.0`
- 跳转：`Timer(animate ? animatedHold : staticHold)` → `widget.onComplete ?? context.go('/home')`
- `_decided`（`:48`）注释写明「prefs 决策完成前不渲染 mark，避免静→动闪烁」← **B-7 首帧空窗的直接成因**
- debug 定屏：`kDebugMode && DEV_ROUTE == '/splash'` → 不起 Timer

**`petgo_app/lib/core/storage/prefs.dart`**：
- `_kSplashLastShownDate = 'petgo.splash_last_shown_date'`（`:31`）+ getter（`:32`）+ setter（`:34`）—— 本 Story 全删

**`petgo_app/test/onboarding/splash_test.dart`**（52 行 / 2 用例）：
- 用例 1「当天首开：播完整动效…~4.5s 后过场」
- 用例 2「当天已播过：静止终态，~1.4s 后过场」← **本 Story 须处置其存废**
- 两条都断言过 `SplashPage.version`（已由 7.2 处理）

- **`AppsFlyerClient.init()`：只有 try/catch 吞错、`sdk.initSdk(...)` 没有超时** —— 而它同样在 `main.dart` 里被 `runApp` **前** await，一旦 initSdk 不返回就会**无限期拖慢首帧**。已按与 Analytics 相同的口径补 `.timeout(3s)`。超时后 `_initialized` 保持 false ⇒ 归因不上报，与初始化抛错的降级行为一致。

#### 交棒时序的实现口径（一处需要说明的设计选择）

设计稿的 5s 兜底是**从启动算**（2290 + 2710 = 5000）。若沿用改前"splash 到点就交棒、由路由层 await 5s"的结构，5s 会从交棒时刻（1720ms）起算 ⇒ 最坏 6720ms，与设计稿不符。

故把「等就绪」搬进 splash：交棒条件为 **动效停留走完 且（已就绪 或 到 5s 兜底）**，5s 自 splash 启动起算。路由层的 `await ensureRestored().timeout(5s)` **保留不动** —— 此时通常已完成、立即返回；保留是为深链直达等绕过 splash 的路径兜底。`onComplete` 的调用契约与分流顺序（pending 深链 > 落地矩阵）一字未改（AC8）。

另加 `_completed` 一次性标志：就绪与兜底两条路径都可能触发交棒，**只交一次**（已加测试断言 `onComplete` 仅被调用 1 次）。

#### 进度线为何保留动画（与 7-2 的「装饰性动画要停」不矛盾）

`_IndeterminateLine` 在 reduce-motion 下**仍然动**。这不是疏漏：设计侧挑战 X-3 的原则是「**无限动画只允许用于 loading 指示**」——呼吸光晕是装饰所以要停，而进度线**本身就是 loading 指示**，承载真实语义，故保留（UX-DR29 亦明确「进度线保留」）。
