# Story 2.3: 已登录未建档用户的建档引导态

Status: ready-for-dev

> **所属**：V1.1.2 Epic 2 第三个 Story（**纯前端 · 小**）。交付：状态 A 未建档用户进 Diary 看到建档引导；**V1.0.0 FR-0H 首页提示条整条废止**。
> ⚠️ **状态 A 未建档 与 状态 B/C 是两种完全不同的人**，PRD 特意拆开：对 A 推建档是对的（他说了有宠物，只是没填）；对 B/C 推建档等于无视他刚在 onboarding 里给出的回答。

## Story

As a **已登录但还没填宠物档案的用户**,
I want **打开 Diary 直接看到建档引导**,
so that **我不用再被当成新访客重新种一次草（FR-81）**。

## Acceptance Criteria

> **验证层**：**L0**（analyze / widget test / 埋点下线核对）· **L1**（真后端，A 未建档与 B/C 两种账号）· **L2**（模拟器视觉）。

### AC1 — 状态 A 未建档的建档引导（L2 · UX-DR5）

**Given** 用户为状态 A（已回答「我有宠物」）且未建档
**When** 进入 Diary
**Then** 走 Story 2.1 分发入口的对应分支，复用 V1.0.0 既有宠物档案创建引导（**FR-0G，可跳过**）
**And** **不展示** FR-80 的预览种草内容（避免对已登录用户重复种草造成体验割裂）
> 视觉基准：UI 稿 A2 屏。

### AC2 — 状态 B/C 零改动（L1 · UX-DR6）

**Given** 用户为状态 B（计划养宠）或 C（喜欢宠物但未养）
**When** 主动点进 Diary
**Then** 展示 V1.0.0 既有「有宠专属 + 修改宠物状态入口」页
**And** **不引导建档**、页面**零改动**
**And** 用户经该入口把状态改为 A 后，按既有逻辑进入 FR-0G 建档引导
> 视觉基准：UI 稿 A2b 屏（回归基准，非新设计）。

### AC3 — V1.0.0 FR-0H 首页提示条整条废止（L0 · FR-81）

**Given** V1.0.0 FR-0H 定义的「选择状态 A 但未建档的用户，首页顶部显示建档提示条，前 3 次重启均显示、第 3 次关闭后不再显示」
**When** 实现完成
**Then** 该提示条**不再实现**，相关代码移除
**And** Discovery 顶部**不再预留**提示条区域
**And** 其**曝光 / 点击 / 关闭埋点事件已移除**，相关看板指标下线
**And** 状态 A 未建档用户的建档引导渠道**收敛为唯一一条**——本 Story 的 Diary 分支
**And** 不再有「前 3 次重启」这个次数上限（Diary 落地引导每次冷启动都在，但它是页面本身而非打断式提示条）

## Dev Notes

### 关键约定

- **A 未建档 与 B/C 必须分开对待**。混为一谈会导致对刚回答「我没有宠物」的用户反复催建档。
- **FR-0H 废止的理由**：它挂在首页顶部，而首页改名 Discovery 并移到第 4 位后，状态 A 未建档用户的落地页是 Diary，几乎不会主动去 Discovery，提示条曝光趋近于零。Diary 首屏本身已是完整的建档引导，重复催没有必要。
- **埋点必须一并下线**，否则会留下一个恒为 0 的指标。

### 强制护栏

- B/C 页面**零改动**——本 Story 碰它的渲染即越界。
- FR-0H 是**整条废止**，不是「保留代码但不显示」。
- 不得在 A 未建档分支展示 FR-80 的种草内容。

### Project Structure Notes

- 前端修改：`growth_archive_page.dart`（填 A 未建档分支）、`features/content/presentation/home_page.dart`（移除 FR-0H 提示条）。
- 前端删除：FR-0H 提示条组件及其计数持久化、埋点调用。
