# Story 4.2: 发布页同步开关与「我的」页私密标识

Status: ready-for-dev

> **所属**：V1.1.2 Epic 4 第二个 Story（**纯前端**）。交付：发布页「同步到 Moment」开关 + 默认类型调整 +「我的」页私密标识。
> 依赖 Story 4.1（`visibility` 字段与接口）。
> ⚠️ **UI 稿有一处 PRD 没写的交互**：关掉同步开关后，主按钮文案从 **Bagikan（分享）变为 Simpan（保存）**。照 PRD 实现会漏掉。
> ⚠️ **口径合并**：代码里已有「在成长档案 Tab 点 [+] 且有档案 → 预选成长日历」（bug 20260703-244），与 FR-83「全局默认 Diary」重叠，须合并为单一口径。

## Story

As a **想给自己留点私人记录的用户**,
I want **发日记时能一键关掉「同步到 Moment」**,
so that **有些只想自己看的事，不用发到大家都能刷到的地方（FR-83）**。

## Acceptance Criteria

> **验证层**：**L0**（analyze / widget test）· **L1**（真后端联调）· **L2**（模拟器视觉）。

### AC1 — 默认 Diary + 同步开关默认开启（L2 · UX-DR14）

**Given** UI 稿 P1 屏
**When** **有宠物档案**的用户进入发布页
**Then** **默认选中 Diary**
**And** 出现「同步到 Moment」开关且**默认开启**
**And** 含「Untuk: {宠物名}」归属行
**And** 开关副文案说明「保存在 Diary 且展示在探索」
**And** 主按钮为 **Bagikan（分享）**

### AC2 — 关闭同步时主按钮文案联动（L2 · UX-DR16，PRD 未提及）

**Given** UI 稿 P2 屏
**When** 用户**手动关闭**同步开关
**Then** 主按钮文案由 **Bagikan（分享）变为 Simpan（保存）**
**And** 该条内容发布后**仅进成长档案时间线**，不进 Discovery、不进话题聚合页、不进任何平台公开位
**And** 作者本人可在「我的发布」看到该条
> ⚠️ 该文案联动为 **UI 稿独有要求**，PRD 未提及，须落 AC 不得遗漏。

### AC3 — 无宠物档案默认 Moment（L2 · UX-DR15）

**Given** UI 稿 P1b 屏
**When** **无宠物档案**的用户（状态 B/C 或状态 A 未建档）进入发布页
**Then** **默认选中 Moment**
**And** Diary 选项维持 V1.0.0 的**灰置状态**与「需要先创建宠物档案」提示
**And** 点击 Diary 灰置项跳转建档引导的既有逻辑**不变**
> 理由：FR-83 若照字面「默认 Diary」实现，无档案用户会出现「默认选中一个灰色不可点的选项」。

### AC4 — Moment / Tips 不出现同步开关（L2 · UX-DR17）

**Given** UI 稿 P3 屏
**When** 用户选中 Moment 或 Tips
**Then** **不出现**同步开关（二者本就公开进 Feed）
**And** 显示「🌐 公开发布，展示在探索」提示

### AC5 — 类型选择器顺序调整（L0 · UX-DR19）

**Given** 类型选择器现状顺序为 Moment / Tips / Diary
**When** 实现完成
**Then** 调整为 **Diary / Moment / Tips**（与默认选中项及 FR-83 表述一致）

### AC6 — 与既有 Tab 语境预选逻辑合并口径（L0）

**Given** 既有逻辑「在成长档案 Tab 点 [+] 且有档案 → 预选成长日历」（bug 20260703-244）与 FR-83「全局默认 Diary」**重叠且口径不同**
**When** 实现完成
**Then** 两者**合并为单一口径**并在代码中注明
**And** **不存在**两处互相覆盖的默认类型判定
> 本版本明确**不改**发布入口位置（OQ-10 暂不做），但既有预选逻辑是该方向的雏形，合并后为日后改造留单一入口。

### AC7 — 同步状态发布后不可更改（L1 · FR-83）

**Given** 同步状态**发布时一次性确定**
**When** 内容已发布
**Then** 内容详情页、「我的发布」列表、内容编辑流程中**均不出现**任何同步开关或「转为私密 / 取消同步」入口
**And** 用户让内容不再被他人看到的**唯一途径是删除该条内容**
> 设计取舍：不做事后可切换，是为避免「已公开内容被撤回」的衍生问题（他人已产生的点赞评论如何处置、已分享出去的卡片链接失效等）。

### AC8 — 「我的」页私密与公开区分（L2 · UX-DR18）

**Given** UI 稿 P4 屏
**When** 作者查看「我的」页
**Then** **完整展示自己全部 Diary（含未同步的私密内容）**
**And** 私密内容与公开内容有**明确的视觉区分标识**
**And** 页面按真实 `me_page` 结构，含 ProfileHeadCard、AKTIVITAS 入口组、POSTINGANKU 列表
**And** 「我的发布」排序仍按 `created_at` 倒序（CROSS-STORY F9，不与档案的 `event_date` 混用）

### AC9 — 不绕过内容审核（L1 · CROSS-STORY F10）

**Given** 发布须走三方自动审核（文字关键词 + 图像识别 stub）
**When** 本 Story 改动发布页
**Then** 审核流程**未被绕过**
**And** **私密 Diary 同样经过审核**

### AC10 — 图片区维持现状（L0）

**Given** 本版本发布页图片区维持 V1.0.0 现状
**When** 实现完成
**Then** **未提前适配** FR-71 的图片比例规范化与裁剪流程（已随内容运营能力整体移至 V1.1.4）
**And** 不预留、不提前改造图片区

## Dev Notes

### 关键约定

- **默认开启 = 与现状一致**。这次反转后，用户侧**无感知变更**——老用户发布结果和以前一样，想私密的人才需要手动关。文案上**不宜再把「私密」当核心卖点主打**（FR-83 对 FR-80 文案方向的约束）。
- **主按钮文案联动是 UI 稿独有的**。它其实很对——不同步的日记确实不是在"分享"。靠 widget test 防回归。
- **口径合并要留痕**：合并后在代码注明，否则下一个人看到 bug 20260703-244 的注释会以为逻辑还在那里。

### 强制护栏（违反即返工）

- **发布后不得提供任何事后同步开关**（FR-83 明确；下游 V1.1.4 依赖「不存在运行中状态翻转」这一确定性）。
- 无档案用户**不得**默认选中灰置的 Diary。
- **不得绕过内容审核**（F10）。
- **不得**提前适配 FR-71 图片区改造（属 V1.1.4）。
- 「我的发布」排序按 `created_at`，不与档案 `event_date` 混用（F9）。

### Project Structure Notes

- 前端修改：`features/content/presentation/publish_compose_page.dart`（顺序/默认/开关/按钮文案）、`shared/widgets/app_shell.dart`（预选口径合并）、`features/me/presentation/me_page.dart`（私密标识）、内容模型与发布请求 DTO、`l10n/app_{en,id}.arb`。
- 前端新增测试：默认值 test、开关文案联动 test、无事后开关 test。
