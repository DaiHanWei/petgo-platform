# Story 2.2: 身份绑定

Status: ready-for-dev

<!-- 主题 analytics-pipeline，不归属任何版本（App 侧随 V1.5.0 切换）。分支 feat/analytics-pipeline，基于 main。 -->

## Story

作为数据使用者，
我想要每条事件带上发生时的身份，登录前后能连成同一个人，
以便按「人」统计准确，换号补发也不会记错人。

## Acceptance Criteria

本 story **只改 App，没有后端段**。L1 依赖 Epic 1 的 Story 1.4、1.5、1.6 已部署到 stag。L0 = `flutter analyze` / `flutter test`；L1 = Android 模拟器装 profile 或 release 包连 stag（debug 包不上报），查 stag 埋点库。

1. **〔L0〕入队即绑定**：事件入队时写入当时的匿名 id 和用户标识（`distinctIdFor`）；之后登出或换号，已入队事件的身份不变。
2. **〔L0〕身份关联事件**：`identifyUser` 上报一条 `user_identified`，**不带** `internal_user_id` 等明文标识；`reset()` 只清用户标识，不重置匿名 id。
3. **〔L0〕换号前先发**：切换账号（`app.dart` 的 reset → identify 序列）前，先尝试把队列里上一账号的事件发出去，失败不阻塞切换。
4. **〔L0〕带 JWT**：请求有 JWT 时带上。
5. **〔L1〕两个账号不串**：模拟器上先登 A 再登 B，stag 关联表有两行，A 的事件不记到 B 头上。

## Dev Notes

### 前置

Story 2.1 已完成：`SelfHostedSink`、`AnonymousId`、`event_names.dart`（含 `AnalyticsEvents.userIdentified`）、独立 Dio 都已存在。本 story 在其上加身份。

### 现有代码（已核实，2026-11-12）

- `Analytics.identifyUser`：依次给 AppsFlyer / TikTok / Meta 设 `distinctIdFor(userId)`，再 `Posthog().identify(userId: distinctIdFor(userId), userProperties: personProperties(...))`。`personProperties` 返回 `scrub({'internal_user_id': userId, 'role': ?role})` —— 明文 id 是「PostHog 专项豁免」（2026-08-18），**自建库不沿用这个豁免**：AC2 明确不带 `internal_user_id`；埋点库内部的 `user_id`（bigint）由后端从 JWT / 关联表得出（A4），不由 App 上报。
- `Analytics.reset`：清三家归因的 user id，再 `Posthog().reset()`。
- `lib/app.dart` `build()` 里的 `ref.listen<AuthState>`：收口了 identify / reset，还负责缓存失效、推送和 IM 换号。本 story 不改这里的任何逻辑。
- `Analytics.distinctIdFor(int)`：`sha256.convert(utf8.encode('tailtopia-user-$userId')).toString()`，保留不动。

### 为什么 `user_identified` 要立即发

后端 Story 1.5 在「带 JWT 的请求里有 `user_identified`」时追加关联行，A7 再用关联表放行跨账号补发。若 A 的 `user_identified` 在队列里拖到 B 登录后才发，它会带着 B 的 JWT 到达 —— 后端如果按 token 用户建关联就会建错，如果按事件 `userId` 比对就会因不等于 token 用户而被判 `identity_unverified`，A 的关联行缺失。所以 identify 后立即 flush，让它随 A 自己的 JWT 送达。离线时做不到立即，此时依赖后端按事件里的 `userId` 与 token 用户比对，不一致则不建关联（需 Story 1.5 实现时确认，见下）。

### 跨 story 契约（需与后端对齐）

- Story 1.5 的 AC 写的是「带 JWT 的请求里有 `user_identified` → 追加一行」，**没写明是用 token 用户还是事件 `userId`**。App 侧保证：`user_identified` 的 `userId` 恒等于发生时登录的用户。建议后端只在「事件 `userId` == token 用户的 `distinctIdFor`」时追加关联行。开发时若后端 1.5 已实现，读一下 `IdentityResolver` / `IdentityLinkRepository` 确认；不一致的，在 Completion Notes 写明并提醒后端。
- 关联靠的是信封上的 `anonymousId` + `userId`，`user_identified` 自身属性只放 `role`（非标识）。

### 必须遵守

- 用户标识只用 `distinctIdFor` 的哈希；**不上报明文数字 id**（护栏「对外暴露标识不可枚举」，NFR-3）。
- 登出 / 换号**不重置匿名 id**（A3、FR-5）。
- 埋点请求不得复用 `dioProvider`，不得触发续期或登录态变化。
- JWT 不落盘、不进日志。
- 不整文件 `dart format`。
