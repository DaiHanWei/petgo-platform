## Story

As a 电商、产品和内容运营,
I want 查到电商交易占日活、付费用户占日活、新用户与回访用户,
so that 这几项能和日活放在同一口径下比较。

## Acceptance Criteria

> 原样取自 `_bmad-output/planning-artifacts/analytics-pipeline/epics.md` Story 4.7。L0 = 编译 / 单测；L1 = 本地 postgres + redis 真跑；L2 = stag / 生产实测。

**Epic 4 通用规则（本 story 全部适用，违反即返工）**

- 只算生产数据且 `is_suspicious=false`；用户维度只算 `role = 'USER'` 且 `account_type = 'REAL'`。
- 按「人」去重：带用户标识的事件归该用户；匿名事件按关联表归属（事件前有关联 → 最近一次；之前没有、之后有 → 第一个；从未关联 → 匿名 id）。
- WIB 自然日；周 = 周一至周日；月 = WIB 自然月。
- 每日去重人数不跨天相加：凡「统计周期内去重人数」的指标，同时写日表、周表、月表（周期结束次日计算并回补）；比率类月指标（取每日比率平均）由日表现算。
- Toko 已付款 = `shop_orders.paid_at IS NOT NULL`，按 `paid_at` 的 WIB 日期；退款 / 取消仍算。业务库关联一律用 public token，读业务库只做窄查询，不做跨库 SQL。
- 汇总表不含 `user_id`、匿名 id 等可识别个人的字段；每张新表在迁移里授权给 `analytics_reader`。

**本 story 验收**

1. **Given** 迁移建 `agg_daily_ratio` **Then** 每天记有已付款 Toko 订单的人数（S4 分子）、有非 Toko 付费解锁的人数（产品 #3 分子，判据按各业务表逐项列出）、当天注册人数（内容 #1），分子均读业务库〔L1〕
2. **And** 分母日活按 `analytics.dau-source` 取：`GA4` 时取 GA4 全版本日活，`SELF` 时取自建日活（含游客，按人）；表里同时存分母来源〔L1〕
3. **And** 切到 `SELF` 时在 `metric-definitions.yaml` 的 S1 条目写切换日期〔L0〕
4. **And** 回访用户 = 当天日活 − 当天新用户；月比率取每日比率的平均，写进口径〔L0〕

**本 story 补充的可验证细则**

5. 迁移 `db/analytics-migration/V20261113_1420__agg_daily_ratio.sql`，表授权只读账号，无任何人标识列〔L1〕
6. 汇总 SQL 在 `analytics/rollup/ratio.sql`，日期作为参数，不出现 `now()` / `CURRENT_DATE`〔L0〕
7. 分母缺失（GA4 当天未拉到、stag 无 GA4 凭证）时，`dau`、两个比率、`returning_users` 为 NULL，分子照常写；GA4 回拉补上后，下一次运行（3 天回补）自动填上〔L1〕
8. 每个分子与直接查业务库同日同口径的结果一致（构造数据集：PawCoin 与 QRIS 两种渠道各一笔、同人同日两笔只算一人、兽医 / 虚拟号 / 门店进货单被排除、UTC 与 WIB 跨日）〔L1〕
9. `analytics.dau-source=SELF` 而 S1 条目没有切换日期时，启动打 WARN 并经 TECH 渠道告警一次（不阻断启动）〔L0〕

## Dev Notes

### 依赖与范围

- 依赖 4.1（`agg_daily_activity`、框架）、4.2（`ga4_daily_snapshot`、`analytics.dau-source`）。
- 只有日表；月比率由 AI 用日表现算（通用规则「比率类月指标由日表现算」），不建月表。
- 只改后端；不改业务 schema。

### 分母规则（FR-24）

- `analytics.dau-source = GA4`（默认，对账观察期内）：`dau` = 当天 GA4 **全版本**日活（含游客）。注意不是对账用的「V1.5.0+ 日活」。
- `= SELF`：`dau` = `agg_daily_activity` 的自建日活（含游客，按人）。
- `dau_source` 列记每行实际用的来源。切换后只有回补窗口（3 天）内的行会被改写成新来源；更早的行保留旧来源——这是预期，口径条目写明「以每行 `dau_source` 为准」。
- 分母取不到 → `dau`、`s4_ratio`、`p3_ratio`、`returning_users` 置 NULL，不用 0 顶替。

### S4 分子（`toko_buyers`）

```sql
SELECT DISTINCT o.user_id
FROM shop_orders o JOIN users u ON u.id = o.user_id
WHERE o.paid_at >= :from AND o.paid_at < :to
  AND u.role = 'USER' AND u.account_type = 'REAL';
```

退款 / 取消仍算（D-13）。`paid_at` 只有部分索引，顺扫可接受（见 4.5）。

### 非 Toko 付费判据（产品 #3 分子，D-13 要求逐表列出，已核对代码）

🔴 **PawCoin 付款不经过 `payment_intents`**：PawCoin 扣币直接写各业务购买行，只有 QRIS 才建支付意图。所以不能只查 `payment_intents.status='PAID'`（ai-query-agent 现有说明书 §5.3 就是这么写的，4.8 会修正）。

| 列 | 类型 | 判据（时间列 → WIB 归日） | 出处 |
|---|---|---|---|
| `payers_ktp` | KTP 高清解锁 | QRIS：`payment_intents` `purpose='ID_HD' AND status='PAID'`，按 `updated_at`；PawCoin：`id_card_hd_purchases` `pay_channel='PAWCOIN'`，按 `purchased_at` | `V60`、`V75`、`V92`；`IdCardHdService.java:94-111`（QRIS 在发起时就写 attempt 行，故 QRIS 不能按购买行数） |
| `payers_tailsonality` | Tailsonality 结果 + 配型解锁 | `keepsake_purchases` `sku IN ('TAILSONALITY','TS_MATCH') AND status='PAID'`，按 `paid_at` | `V20260930_2152`、`V20261009_0113` |
| `payers_passport` | 护照快照 + 登机牌 | `keepsake_purchases` `sku IN ('PASSPORT_SNAP','BOARDING_PASS') AND status='PAID'`，按 `paid_at` | 同上 |
| `payers_pet_slot` | 宠物名额月租 | `pet_slot_purchases` `status='PAID' AND kind IN ('RENT','RENEW')`（排除运营补发 `ADMIN_GRANT`），按 `paid_at` | `V20261018_1601` |
| `payers_ai_unlock` | AI 问诊解锁 | `ai_consult_orders` `status='COMPLETED'`，按 `paid_at` | `V65` |
| `payers_vet_consult` | 兽医问诊 | `consult_orders` `paid_at IS NOT NULL`（含后来退款的，与 D-13 一致），按 `paid_at` | `V66` |
| `payers_gift`（参照） | 送礼 | `gift_orders` `status IN ('DELIVERED','UNDELIVERED_REFUND_PENDING','UNDELIVERED_REFUNDED','REFUND_MANUAL')`，按 `delivered_at`，无则 `created_at`；付款人列是 `sender_id` | `V20261018_1700` |
| `payers_topup`（参照） | PawCoin 充值 | `payment_intents` `purpose='PAWCOIN_TOPUP' AND status='PAID'`，按 `updated_at` | `V60` |

- **`nontoko_payers`（产品 #3 分子）** = 前六类（KTP、Tailsonality、护照、名额、AI 解锁、兽医问诊）的**去重并集**人数。
- 送礼与充值只作参照列、**不进分子**：团队原文是「付费解锁（KTP、Tailsonality 和其他非 Toko 功能）」；充值是买币不是解锁，计入会与之后的扣币解锁重复，送礼不是解锁。这是按推荐定的默认口径——写进产品 #3 条目的「已知偏差 / 待确认」，并在 Completion Notes 列为「需 Dai 确认」。若 Dai 改口径，只改并集定义，表结构不变。
- 一律排除：`SHOP_ORDER`（Toko）、`MERCHANT_PO`（门店进货单，`payment_intents.user_id` 为负的门店 id，与用户不相交；join `users` 时自然被排除，仍在代码注释写明）。
- `keepsake_purchases` 的 `DUPLICATE_PAID` / `ORPHAN_PAID`（到账但发放失败、交人工）不算，只认 `PAID`。
- `payment_intents` 没有 `paid_at` 列，`updated_at` 是到账时刻的近似（之后若再有更新会漂移），口径注明。
- 所有查询带时间区间并 join `users` 过滤 `role='USER' AND account_type='REAL'`；只返回 `user_id`，不读金额以外的任何个人字段（本 story 连金额都不需要）。

### 内容 #1（`new_users`、`returning_users`）

- `new_users` = 业务库 `users.created_at`（`V2__init_auth.sql`）的 WIB 日期 = 当天、`role='USER' AND account_type='REAL'` 的人数。与 4.1 用 `signup_succeeded` 事件算的注册数（S3）口径不同，条目里写明两者区别（业务库含旧版 App 注册、不受新版覆盖率影响）。
- `returning_users` = `dau − new_users`；`dau` 为 NULL 时为 NULL。可能为负（GA4 与业务库口径差），不截断，口径注明。

### 表结构（迁移 `V20261113_1420__agg_daily_ratio.sql`）

```sql
CREATE TABLE agg_daily_ratio (
    stat_date           DATE         PRIMARY KEY,          -- WIB 日期
    dau                 INTEGER,                           -- 分母；取不到为 NULL
    dau_source          VARCHAR(8)   NOT NULL,             -- GA4 | SELF
    toko_buyers         INTEGER      NOT NULL,             -- S4 分子
    s4_ratio            NUMERIC(9,6),                      -- toko_buyers ÷ dau
    nontoko_payers      INTEGER      NOT NULL,             -- 产品 #3 分子（六类并集）
    p3_ratio            NUMERIC(9,6),                      -- nontoko_payers ÷ dau
    payers_ktp          INTEGER      NOT NULL,
    payers_tailsonality INTEGER      NOT NULL,
    payers_passport     INTEGER      NOT NULL,
    payers_pet_slot     INTEGER      NOT NULL,
    payers_ai_unlock    INTEGER      NOT NULL,
    payers_vet_consult  INTEGER      NOT NULL,
    payers_gift         INTEGER      NOT NULL,             -- 参照，不进分子
    payers_topup        INTEGER      NOT NULL,             -- 参照，不进分子
    new_users           INTEGER      NOT NULL,             -- 内容 #1
    returning_users     INTEGER,                           -- dau − new_users
    computed_at         TIMESTAMPTZ  NOT NULL,
    CONSTRAINT ck_agg_daily_ratio_source CHECK (dau_source IN ('GA4', 'SELF'))
);
```

- 计数列 `INTEGER`，不用 `SMALLINT`。授权只读账号（沿用 1.2 写法）。
