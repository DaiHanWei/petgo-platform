# Story 3.1: 运营位曝光与点击核对

Status: ready-for-dev

<!-- 主题 analytics-pipeline，不归属任何版本（App 侧随 V1.5.0 切换）。分支 feat/analytics-pipeline，基于 main。 -->

## Story

作为电商和内容运营，
我想要每个弹窗和 banner 的曝光、点击都能按运营位统计，
以便算出点击率和点击后 7 天的带单数。

## Acceptance Criteria

> 以 `_bmad-output/planning-artifacts/analytics-pipeline/epics.md` Story 3.1 为准，原样带入。

1. **〔L0〕** 现有 `ops_popup_shown` / `ops_popup_tapped`（`ops_popup_coordinator.dart`）、`toko_banner_shown` / `toko_banner_tapped`（`shop_banner_carousel.dart`、`toko_page_v3.dart`）和新人券弹窗（`toko_newbie_coupon_popup_shown` 等）这三类事件，统一带 `placement_type`（`ops_popup` / `toko_banner` / `newbie_coupon`）和 `placement_token`（运营位或活动的 public token），原有属性保留。
2. **〔L0〕** 曝光统一按「露出超过 50% 计一次」，与 Toko 横幅现有定义一致；不一致的改齐。
3. **〔L0〕** 核对结果（运营位清单、事件名、token 来源表）写进 `metric-definitions.yaml` 的 S5 条目。
4. **〔L1〕** 模拟器上展示并点击一次弹窗和横幅，stag 明细层能按 `placement_token` 查到曝光和点击各一条。

## Dev Notes

### 运营位清单与 token 来源（核对结论，S5 条目照此写）

| placement_type | 事件（曝光 / 点击 / 其他） | placement_token 取值 | 业务库来源表 | 曝光时机 |
|---|---|---|---|---|
| `ops_popup` | `ops_popup_shown` / `ops_popup_tapped` / `ops_popup_closed` | `OpsPopupCandidate.token` | `ops_popups.public_token` | 弹窗首帧后（整窗露出）；游客也报 |
| `toko_banner` | `toko_banner_shown` / `toko_banner_tapped` | `ShopBanner.bannerId` | `shop_banners.public_token`（V20261030_0330 加列） | 当前页露出 >50%，同次进入同张一次 |
| `newbie_coupon` | `toko_newbie_coupon_popup_shown` / `toko_newbie_coupon_popup_tapped`（`action=register` 才算点击；`close` 不算） | `NewbieCampaign.campaignToken` | `shop_coupons.public_token`（新人券模板，`GET /shop/coupons/newbie-campaign` 下发） | 本 story 改为弹窗首帧后 |

- 架构 A12 定运营位为三类：弹窗（`ops_popups`）、Toko 横幅（`shop_banners`）、运营推送（`ops_notification_campaigns`）。运营推送的打开由 Story 3.2 的 `push_opened` + `campaign_token` 覆盖，不在本 story。新人券弹窗是 epics 补进来的第四个落点，按 `newbie_coupon` 类型计。
- **不算运营位**（S5 条目里写明排除）：`growth_backfill_popup_shown`、`growth_celebration_shown`（成长体系功能弹窗）、`app_update_prompt_shown`（升级提示）、`login_guide_*`（登录引导）、`pet_readonly_banner_shown`（名额只读条）。它们不是后台运营配置，没有运营位 token。
- 首页（`home_page.dart`）只有 `AppUpdateBanner`，没有运营 banner；全 App 搜过 `banner` / `_shown`，没有其他运营配置的展示位。

### 点击判定（S5 条目要写清，4.4 汇总按此算）

- `ops_popup`：`ops_popup_tapped`。注意它在弹窗 pop 后上报，`target` 无效（`OpsNoAction`）时图片不可点，只能点按钮，也算点击。
- `toko_banner`：`toko_banner_tapped`。`target=NONE` 的 banner 不可点，不会有点击事件，点击率按 0 记而不是缺失。
- `newbie_coupon`：`toko_newbie_coupon_popup_tapped` 且 `action = 'register'`。
- 「是否推广 Toko」由 Story 4.4 读业务库运营位配置的跳转目标决定（FR-17 第 3 条）；新人券弹窗恒属 Toko。本 story 不在 App 端上报跳转类型维度（`toko_banner_tapped` 已有 `target_type`，保留即可）。

### S5 条目要写的内容（`metric-definitions.yaml`）

按 D-9 字段：编号 S5；定义（团队原文：每个弹窗 / banner 的展示次数、点击次数、点击率，推广 Toko 的另算点击后 7 天已付款 Toko 订单数）；来源事件与上表；token 来源表；曝光规则「露出超过 50% 计一次」；点击判定；排除规则（非运营位弹窗、生产标记、`role='USER' AND account_type='REAL'`）；已知偏差（见下）；SQL 位置留空或写「Story 4.4 填」；变更记录一条（日期、本 story、内容）。

已知偏差（写进 S5）：
- **V1.5.0 之前的旧版 App 不带 `placement_*`**，但旧版事件根本不进自建库（PostHog 已停用，自建只收新版），所以自建库里不存在「缺 `placement_*` 的旧事件」；无需兼容映射。
- 运营弹窗另有服务端曝光计数（`_reportImpression`，只记登录且非兽医用户），与埋点曝光（游客也报）口径不同，两者不能直接对比。
- 横幅曝光以「当前页」为单位，自动轮播翻到的每张各算一次曝光。
- 新人券弹窗只对游客展示，点击（注册）后到登录完成之间可能流失，点击 ≠ 领券；领券看 `toko_coupon_claimed{source=newbie}`。

### 必须保留的现有行为

- 运营弹窗：本地频次写入、登录用户曝光上报、`ops_popup_closed`、点击后 `_openTarget` 跳转，一律不动。
- 横幅：800ms 连点去重、`TickerMode` 关时清空已曝光集合、自动轮播计时，一律不动。
- 新人券弹窗：「先记弹过、再立即弹，中间不 await」的顺序（`toko_page_v3.dart` 第 136–141 行，8.1 复审 #3）不能被曝光改造打乱；曝光只挪到弹窗内部首帧。

### 护栏

- 属性值只能是 public token 与受控枚举，不加任何自增 id、文案、标题（`OpsPopupCandidate.title` 等绝不上报）。
- 新属性名 snake_case；不改任何事件名（事件名已在 1.2 登记）。
- 不新增依赖（不要引 `visibility_detector`）。
- 不 `await` 埋点调用；`unawaited(...)` 写法保持原样。
