# Story 1.9: 服务端事件改走自建

## Story

作为运营和产品，
我想要支付、优惠券推送、分享页这些服务端事件进入自建库，
以便后端一上线就有服务端数据。

## Acceptance Criteria

本 story 只改后端，没有前端段。**云端只跑 L0，L1 / L2 留本地**，在 Completion Notes 标注「L1/L2 待本地验收」。

1. **[L0] 新接口与机械替换**：`AnalyticsClient` 新增 `captureForUser(long userId, String event, Map props)` 与 `captureForVisitor(String visitorId, String event, Map props)`，原 `capture(distinctId, …)` 标为废弃；约 12 处调用点改用新方法（机械改动）。
2. **[L1] 自建实现**：新增 `SelfHostedAnalyticsClient`：`captureForUser` 写 `source=SERVER`、`user_id` 直接给出并视为已校验；`captureForVisitor` 写 `source=H5`、匿名 id 用访客 id，不进关联表。
3. **[L1] 故障不伤业务**：队列满、熔断或管道停用时，服务端事件丢弃并计数，不抛异常、不影响业务。
4. **[L0] 清理 PostHog**：删除 `PostHogAnalyticsClient`、`analytics.posthog.*` 配置和 `POSTHOG_*` 环境变量占位。
5. **[L0] 护栏保留**：`AnalyticsEventGuard` 等现有防护照常生效。
6. **[L2] stag 核对**：stag 上触发一次测试支付，`shop_payment_paid` 进入明细层，与当天 `paid_at` 不为空的订单数一致。

## Dev Notes

### 前置依赖

1.1（埋点数据源、管道停用状态）、1.2（`EventCatalog`）、1.3（`events_raw` DDL）、1.4（`IngestQueue` 入队接口、`IngestFlusher`、未登记判定）、1.6（明细层，用于 L1 / L2 核对）。以已落地代码的实际类名和方法签名为准。

### 现状（已 grep 核实）

- `AnalyticsClient` 现在只有一个实现 `PostHogAnalyticsClient`：`@Async("analyticsExecutor")`、`analytics.posthog.key` 为空即关闭（本地 / 测试默认），HTTP 打 PostHog capture 端点，并注入 `distinct_id` / `app_env` / `$geoip_disable`。
- `AnalyticsEventGuard`：事件名白名单（整条丢）+ 属性键 / 值白名单（只丢键），**任何路径不抛异常**；白名单引用各监听器的事件常量。本 story 只把它接到新实现上，**白名单内容不改**。
- `AnonymousVisitorId`：H5 访客 id，cookie `tt_vid`，32 位十六进制，`readCookie` 已做形态校验。
- `AnalyticsDistinctId.of(long)` = `sha256("tailtopia-user-" + id)`，与 App 逐字一致；是 `user_key` 的唯一算法。
- 所有调用方要么是 `@TransactionalEventListener`（事务提交后），要么是分享页请求线程；它们都依赖「埋点不抛、不阻塞」。

### 必须遵守

- 埋点故障只丢埋点，不伤业务：`SelfHostedAnalyticsClient` 任何路径不抛异常。[Source: architecture.md 横切关注点 6、队列]
- 服务端事件无法重试：队列满或熔断时丢弃计数，不阻塞、不排队等待。[Source: architecture.md 接收与资源「队列」]
- H5 访客不是 App 设备：不进匿名 id 关联表、不算日活。[Source: architecture.md 技术约束]
- 埋点库内部的 `user_id`（bigint）不对外暴露，不违反「对外标识不可枚举」。[Source: architecture.md A4]
- 不双写、不保留 PostHog 兜底（PostHog 已停用）。[Source: architecture.md 过渡与收尾；.decision-log.md 架构阶段]
- 不新增依赖、不新增中间件。
