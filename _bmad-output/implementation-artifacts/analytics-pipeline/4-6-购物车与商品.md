## Story

As a 电商,
I want 查到购物车停留情况和最有潜力、售罄但受关注的商品,
so that 知道哪些商品该推、哪些该补货。

## Acceptance Criteria

> 原样取自 `_bmad-output/planning-artifacts/analytics-pipeline/epics.md` Story 4.6。L0 = 编译 / 单测；L1 = 本地 postgres + redis 真跑；L2 = stag / 生产实测。

**Epic 4 通用规则（本 story 全部适用，违反即返工）**

- 只算生产数据且 `is_suspicious=false`；用户维度只算 `role = 'USER'` 且 `account_type = 'REAL'`。
- 按「人」去重：带用户标识的事件归该用户；匿名事件按关联表归属（事件前有关联 → 最近一次；之前没有、之后有 → 第一个；从未关联 → 匿名 id）。
- WIB 自然日；周 = 周一至周日；月 = WIB 自然月。
- 每日去重人数不跨天相加：凡「统计周期内去重人数」的指标，同时写日表、周表、月表（周期结束次日计算并回补）；比率类月指标（取每日比率平均）由日表现算。
- Toko 已付款 = `shop_orders.paid_at IS NOT NULL`，按 `paid_at` 的 WIB 日期；退款 / 取消仍算。业务库关联一律用 public token，读业务库只做窄查询，不做跨库 SQL。
- 汇总表不含 `user_id`、匿名 id 等可识别个人的字段；每张新表在迁移里授权给 `analytics_reader`。

**本 story 验收**

1. **Given** 迁移建 `agg_daily_cart`、`agg_daily_product` **Then** 购物车**只存聚合**：按商品、按天记加购数、移出数、已购买数、仍在车里数、停留时长分布、购物车数、每车商品数、购物车总价值（单价 × 数量）；不存用户（电商 #7）〔L1〕
2. **And** 「已购买」以业务库订单行（按 `sku_token` 关联）为准；在其他设备或后台清空的购物车行无法观测，口径注明〔L1〕
3. **And** 「是哪个用户」的逐件明细只在明细层 3 个月内可查，口径条目写明并告知电商〔L0〕
4. **And** 商品维度每天记详情浏览次数、加购次数，以及读业务库得到的库存与近 30 天已付款件数（电商 #8、#9）〔L1〕

**本 story 补充的可验证细则**

5. 迁移 `db/analytics-migration/V20261113_1410__agg_cart_product.sql`，两张表授权只读账号；表内无 `user_id`、匿名 id、`person_key`〔L1〕

7. 构造数据集测试：加购→改数量→移出 记为移出；加购→购物车下单并付款 记为已购买；加购→「立即购买」同 SKU 下单 **不**算购物车购买；加购后 7 天无动作 记为仍在车里；下单未付款单列；跨午夜按 WIB 归日；兽医 / 非生产 / 可疑被排除〔L1〕

### 购物车算法（cart.sql）

1. **加购件**：明细层 `toko_add_to_cart_tapped`，按（`person_key`, `sku_token`, `stat_date`）取当天第一条为一「件」，`t_add` = 该条时间；同一人同一 SKU 当天多次加购只算一件，但 `add_events` 计全部条数。
2. **去向**（观察窗 `[t_add, :window_end 24:00 WIB)`，取最早发生者）：
   - `REMOVED`：同人同 SKU 的 `toko_cart_item_removed`，按 `reason` 再分 `manual` / `invalid_cleared`
   - `PURCHASED`：同 `user_id`、同 `sku_token` 的 `checkout_source='CART'` 订单，`created_at >= t_add`，且 `paid_at IS NOT NULL`
   - `ORDERED_UNPAID`：同上但 `paid_at IS NULL`（已离开购物车但未付款；超时取消的单也在这里）
   - `IN_CART`：窗口内以上都没有
   - 结束时刻：移出事件时间 / 订单 `created_at`；`IN_CART` 取窗口结束
3. **停留时长分布**（`t_end − t_add`）：`< 1 小时`、`1 小时–1 天`、`1–3 天`、`3–7 天`；`IN_CART` 单独计数不入分桶；另存全部件（`IN_CART` 按窗口结束截断）的中位数分钟。
4. `toko_cart_quantity_changed` 不改变去向，只用于更新件的数量（取窗口内最后一次 `quantity_after`；没有则用加购时数量）——用于价值计算。
5. **聚合**：
   - `PRODUCT` 行（每个 `product_token` 一行）：`add_events`、`add_items`、各去向件数、分桶、中位数、`cart_value_idr` = Σ(`unit_price` × 数量)
   - `TOTAL` 行（`product_token = ''`）：上述各列的全体值，外加 `carts` = 当天有加购件的去重人数、`items_per_cart_avg` = 加购件数 ÷ `carts`
6. 匿名人（`user_id IS NULL`）的件只可能是 `REMOVED` 或 `IN_CART`（游客无车，App 端加购需登录；归属规则可能把它们事后归到人）。
7. 🔴 **已知偏差，必须写进口径**：其他设备或旧版 App 上的移出 / 清空不可观测（会被算成 `IN_CART`）；后台清空不可观测；同一 SKU 先「立即购买」不影响购物车件；`unit_price` 是加购时 App 上报的单价，非成交价。

**业务库读取（购物车下单行）**——Java 先读后写临时表 `tmp_cart_orders(user_id, sku_token, product_token, created_at, paid_at)`：

```sql
SELECT o.user_id, s.public_token AS sku_token, p.public_token AS product_token, o.created_at, o.paid_at
FROM shop_orders o
JOIN users u            ON u.id = o.user_id
JOIN shop_order_lines l ON l.order_id = o.id
JOIN shop_skus s        ON s.id = l.sku_id
JOIN shop_products p    ON p.id = s.product_id
WHERE o.checkout_source = 'CART'
  AND o.created_at >= :from AND o.created_at < :to      -- [stat_date 00:00 WIB, window_end+1 00:00 WIB)
  AND u.role = 'USER' AND u.account_type = 'REAL';
```

### 商品算法（product.sql）

业务库快照（Java 读出写临时表 `tmp_product_snapshot`，每商品一行）：

```sql
SELECT p.public_token AS product_token, p.name, p.is_active,
       COALESCE(SUM(GREATEST(i.actual - i.locked, 0)), 0) AS sellable_stock
FROM shop_products p
JOIN shop_skus s           ON s.product_id = p.id
LEFT JOIN sku_inventory i  ON i.sku_id = s.id
GROUP BY p.public_token, p.name, p.is_active;

-- 近 30 天已付款件数：paid_at ∈ [stat_date−29 00:00 WIB, stat_date+1 00:00 WIB)，USER + REAL 下单人
SELECT p.public_token AS product_token, SUM(l.qty) AS paid_qty_30d
FROM shop_orders o JOIN users u ON u.id = o.user_id
JOIN shop_order_lines l ON l.order_id = o.id
JOIN shop_skus s ON s.id = l.sku_id JOIN shop_products p ON p.id = s.product_id
WHERE o.paid_at >= :from AND o.paid_at < :to
  AND u.role = 'USER' AND u.account_type = 'REAL'
GROUP BY p.public_token;
```

- 件数按 `qty` 计，**不扣** `refunded_qty`（D-13：退款仍算已付款），口径注明。
- 行集合 = 业务库全部商品（含下架，带 `is_active`），约百行 / 天。明细层里出现、业务库查不到的 `product_token`（已删除商品）丢弃并在日志打计数。
- `is_sold_out` = `sellable_stock = 0`。

**库存快照**：库存只有「此刻」值，没有历史。`sellable_stock`、`is_sold_out`、`stock_captured_at` 只在该 `(stat_date, product_token)` 行**首次插入**时写（`ON CONFLICT DO UPDATE` 的 SET 里不含这三列）；回补重算只更新计数列和 `paid_qty_30d`。口径注明「库存为汇总任务运行时（次日约 03:00 WIB）的快照」。

### 表结构（迁移 `V20261113_1410__agg_cart_product.sql`）

```sql
CREATE TABLE agg_daily_cart (
    stat_date             DATE         NOT NULL,             -- WIB 日期（加购日）
    scope                 VARCHAR(8)   NOT NULL,             -- PRODUCT | TOTAL
    product_token         VARCHAR(32)  NOT NULL DEFAULT '',  -- TOTAL 行为 ''
    add_events            INTEGER      NOT NULL,
    add_items             INTEGER      NOT NULL,
    removed_items         INTEGER      NOT NULL,
    removed_manual        INTEGER      NOT NULL,
    removed_invalid       INTEGER      NOT NULL,
    purchased_items       INTEGER      NOT NULL,
    ordered_unpaid_items  INTEGER      NOT NULL,
    in_cart_items         INTEGER      NOT NULL,
    dwell_lt_1h           INTEGER      NOT NULL,
    dwell_1h_1d           INTEGER      NOT NULL,
    dwell_1d_3d           INTEGER      NOT NULL,
    dwell_3d_7d           INTEGER      NOT NULL,
    dwell_p50_minutes     INTEGER,
    cart_value_idr        BIGINT       NOT NULL,             -- Σ 单价 × 数量（IDR）
    carts                 INTEGER,                           -- 仅 TOTAL 行
    items_per_cart_avg    NUMERIC(8,2),                      -- 仅 TOTAL 行
    is_final              BOOLEAN      NOT NULL,             -- 7 天观察窗已关闭
    computed_at           TIMESTAMPTZ  NOT NULL,
    PRIMARY KEY (stat_date, scope, product_token),
    CONSTRAINT ck_agg_daily_cart_scope CHECK (scope IN ('PRODUCT', 'TOTAL')
        AND ((scope = 'TOTAL') = (product_token = '')))
);

CREATE TABLE agg_daily_product (
    stat_date          DATE         NOT NULL,                -- WIB 日期
    product_token      VARCHAR(32)  NOT NULL,
    product_name       VARCHAR(120) NOT NULL,                -- 业务库当前名称（非 PII）
    is_active          BOOLEAN      NOT NULL,
    detail_views       INTEGER      NOT NULL,                -- 电商 #8 / #9
    add_to_cart        INTEGER      NOT NULL,                -- 电商 #8
    paid_qty_30d       BIGINT       NOT NULL,                -- 电商 #9（近 30 天已付款件数）
    sellable_stock     BIGINT       NOT NULL,                -- 快照，只首次写
    is_sold_out        BOOLEAN      NOT NULL,                -- 快照，只首次写
    stock_captured_at  TIMESTAMPTZ  NOT NULL,                -- 快照，只首次写
    computed_at        TIMESTAMPTZ  NOT NULL,
    PRIMARY KEY (stat_date, product_token)
);
```

- `TOTAL` 行和 `PRODUCT` 行同表，口径条目要提醒 AI：**按商品求和时只取 `scope='PRODUCT'`**，否则翻倍。
- 计数列 `INTEGER`，不用 `SMALLINT`。授权只读账号（写法见 4.5「授权陷阱」：stag 角色名不同，沿用 1.2 的解法）。
