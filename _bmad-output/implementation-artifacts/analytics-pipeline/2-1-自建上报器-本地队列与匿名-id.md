# Story 2.1: 自建上报器、本地队列与匿名 id

Status: review

<!-- 主题 analytics-pipeline，不归属任何版本（App 侧随 V1.5.0 切换）。分支 feat/analytics-pipeline，基于 main。 -->

## Story

作为产品和运营，
我想要 App 的事件可靠地送到自建后端，断网和被杀都不丢，
以便埋点数据完整，又不拖慢 App。

## Acceptance Criteria

本 story **只改 App（`petgo_app/`），没有后端段**。L1 联调依赖 Epic 1（至少 Story 1.3、1.4、1.6）已部署到 stag。L0 = `flutter analyze` + `flutter test`（云端可跑）；L1 = Android 模拟器装 **profile 或 release 包**连 stag 后端（`--dart-define=PETGO_API_BASE_URL=https://api-stag.tailtopia.id`，debug 包不上报），查 stag 埋点库；L2 = 真机 / TestFlight / 商店包。

1. **〔L0〕匿名 id**：新增 `anonymous_id.dart`。首次启动生成 UUIDv4 存 `shared_preferences`（**不放 secure storage**）；卸载前不变；读取同步可用，早于任何事件入队。
2. **〔L0〕门面换底**：新增 `self_hosted_sink.dart`、`event_queue_file.dart`；业务代码调用 `Analytics.capture` / `capturePurchase` / `buttonTapped` 等时，门面签名不变，事件经现有白名单和 `scrub()` 后进本地队列；金额属性允许保留。
3. **〔L0〕事件信封**：每条事件带 `messageId`（UUIDv4）、`timestamp`、`anonymousId`；发送时填 `sentAt`；请求体外层 camelCase、属性 snake_case。
4. **〔L0〕攒批与补发**：每 20 条或 30 秒发一批（先到者为准）；切到后台立即发；网络恢复后补发；冷启动时补发上次未发完的。
5. **〔L0〕本地队列**：队列存成 `path_provider` 下的文件，读写串行；上限 1,000 条或 7 天，超出丢最旧。
6. **〔L0〕返回码处理**：202 删批次；429 按 `Retry-After`，缺失时按默认退避；503 / 5xx / 断网指数退避；400 / 413 整批丢弃。
7. **〔L0〕不打扰主流程**：debug 包不发送，`debugCaptureSink` 测试钩子照常可用；上报异常一律吞掉，UI 代码不 `await` 埋点调用。
8. **〔L1〕端到端不丢不重**：模拟器上产生 50 条事件 → 断网 → 杀进程 → 重启联网，stag 明细层能查到全部 50 条且无重复。

- [x] T4 新建 `lib/core/analytics/self_hosted_sink.dart`（AC: 3、4、6、7）
  - [x] **入队**：`enqueue(String event, Map<String, Object>? props)` 同步组装信封并交给队列：
    ```json
    {
      "messageId": "<uuidV4>",
      "event": "toko_add_to_cart_tapped",
      "timestamp": "2026-11-12T03:04:05.678Z",
      "anonymousId": "<AnonymousId.value>",
      "userId": null,
      "properties": { "product_token": "...", "price": 50000 },
      "context": {}
    }
    ```
    `timestamp` 是事件发生时刻的 UTC ISO-8601（带毫秒和 `Z`）。`userId` 本 story 恒为 null，由 Story 2.2 填（入队时绑定）；`context` 本 story 为空 map，由 Story 2.5 填。字段名采用 Segment 写法（`userId`、`properties`、`context`），见 Dev Notes「契约」。
  - [x] 单条事件序列化后超过 **32 KB**（A6）直接丢弃并计数，否则整批会 413 被丢。
  - [x] **发送**：`POST {kApiBaseUrl}/api/v1/analytics/batch`，请求体 `{"batch": [ ...事件 ]}`，发送前给本批每条事件填同一个 `sentAt`（UTC ISO-8601）。单次请求最多 100 条且序列化后 < 450 KB（后端上限 500 KB），积压多时分多次发。
  - [x] **用独立的 `Dio`**，`baseUrl` 取 `dio_client.dart` 的 `kApiBaseUrl`（唯一来源，默认值不许改），**不要**用 `dioProvider`：那上面挂着 `AuthInterceptor`，一个 401 就会把用户踢成游客并弹登录框；还有 `ApiLogInterceptor`、`GrowthActionInterceptor`。超时 connect 10s / receive 15s。JWT 由 Story 2.2 加，本 story 不带。
  - [x] **触发**：(a) 队列新增后累计 ≥ 20 条；(b) 30 秒周期定时器；(c) App 进入 `paused` / `hidden`（sink 自己注册一个 `WidgetsBindingObserver`）；(d) App 回到 `resumed`（兼作「网络恢复后补发」，见 Dev Notes）；(e) 启动完成加载旧队列后立即一次。同一时刻只允许一个发送在途（`_sending` 标志），在途时的触发合并为发送结束后再检查一次。
  - [x] **返回码**（与架构「接口格式」逐条一致）：
    - 202 → 从队列删除本批 `messageId`；
    - 429 → 保留，按 `Retry-After`（秒数或 HTTP 日期）暂停，缺失或解析失败时按默认 60 秒；暂停期内所有触发都不发；
    - 503 / 其他 5xx / 网络异常 / 超时 → 保留，指数退避（5s 起，×2，封顶 5 分钟，±20% 抖动），成功一次后归零；
    - 400 / 413 → **整批丢弃**并计数（防止坏批次永远卡在队头）；
    - 其他非预期状态（如 404：后端还没部署该接口）→ 按 5xx 退避，**不丢**。
  - [x] **开关**：`enabled = !kDebugMode`（profile / release 发送）。debug 下 `enqueue` 直接返回，不写文件、不起定时器。测试用 `@visibleForTesting` 构造参数注入 `enabled: true`、假传输函数、假时钟、内存队列，不依赖真实网络和真实等待。
  - [x] **定时器只在 `enabled` 时启动**：widget 测试会 pump 整个 `TailTopiaApp`，debug 下残留周期定时器会让测试以「A Timer is still pending」失败。
  - [x] 任何异常（文件、网络、JSON）都在 sink 内部吞掉，只 `debugPrint` 条数 / 状态码，**绝不打印事件内容和 `messageId` 以外的字段**。

### 现有代码（已核实，2026-11-12）

- `lib/core/analytics/analytics.dart`（398 行）：静态门面类 `Analytics`。`capture()` 先 `scrub()`，再调 `debugCaptureSink`，再分发 AppsFlyer（白名单 `appsflyerEvents`）、Meta / TikTok（仅 `af_complete_registration`、`af_purchase`），最后 `Posthog().capture(eventName, properties: posthogProperties(clean))`。`capturePurchase()`、`captureSignupSucceeded()`、`buttonTapped()` 都经 `capture()`，所以只改 `capture()` 一处即可覆盖。
- `scrub()` 三道规则（PII 键 + 后缀、自由文本键、字符串 > 64 字符）、递归处理 map 和 list —— **继续生效，不要改**。
- `captureSignupSucceeded` 的属性里有嵌套 map `$set_once`（PostHog 语义的遗留）。本 story 原样入队，不做特殊处理；它在自建库里只是一个普通属性，是否保留由 Story 1.2 的事件清单决定。
- `lib/main.dart`：`unawaited(Analytics.init())` 在 `runApp` 之前；注释解释了为何不 await。`_loadSavedLocale()` 在其后、`runApp` 之前 await `AppPrefs.create()`。
- `lib/core/network/dio_client.dart`：`kApiBaseUrl = String.fromEnvironment('PETGO_API_BASE_URL', defaultValue: 'https://api.tailtopia.id')`。stag 包通过 dart-define 指向 stag，所以 sink 用它就天然满足「stag 包只发 stag 后端」（FR-6，2.5 验收）。
- 现有依赖已足够：`path_provider 2.1.6`、`shared_preferences 2.5.5`、`dio 5.10.0`。**不加任何新依赖**（没有 `connectivity_plus`，也不要加）。

### 「网络恢复后补发」怎么做

不引入网络状态监听。断网时发送失败进入指数退避（封顶 5 分钟），加上 30 秒周期触发和回前台触发，网络恢复后最迟一个退避周期内补发成功。回前台触发时把退避计时清零立即试一次（429 的 `Retry-After` 暂停期除外）。

### 契约（与 Epic 1 对齐）

- 端点 `POST /api/v1/analytics/batch`，可不带 JWT。必填字段 `messageId`、`event`、`timestamp`、`sentAt`、`anonymousId`（UUID），其余缺失不拒收（Story 1.4）。
- 架构和 epics **没有写明请求外层信封和用户标识字段名**。本 story 定为：外层 `{"batch": [...]}`，单条事件 `messageId / event / timestamp / sentAt / anonymousId / userId / properties / context`（Segment 写法）。**开工前先看后端 Story 1.4 的 `IngestRequest` / `IngestEvent` 是否已实现**：已实现就以后端为准改这里；未实现就按本约定，并在 Completion Notes 写明，提醒 1.4 对齐。
- 单条 32 KB、请求 500 KB 为后端上限（A6），App 侧预先挡掉，避免整批 413。
- 后端按 `messageId` 去重（FR-9），所以「202 前被杀、重启后重发」造成的重复由后端吸收，App 不需要额外去重。

### 必须遵守

- 匿名 id 存 `shared_preferences`，**不放 secure storage**（A3，避开 BAD_DECRYPT 导致首页无限加载的历史坑）。
- UI 代码不准 `await` 埋点调用；`Analytics.capture` 返回的 Future 内部已吞错。
- 日志只打条数和状态码；**不打事件内容**（架构「处理规则 · 日志」）。
- 不改 `scrub()` 规则、不改 `ButtonId` 白名单、不改 AppsFlyer / Meta / TikTok 分发。
- 不整文件 `dart format`（存量未格式化，会带出几百行无关 diff）。

### 已知偏差（记录，不在本 story 处理）

- Android 未设置 `android:allowBackup`（默认 true）。开启了 Google 备份的设备卸载重装后，系统可能恢复 `shared_preferences`，匿名 id 会沿用旧值，与 A3「卸载重新生成」不一致。是否关闭备份影响全 App 偏好，需 Dai 拍板，本 story 不改 manifest。
