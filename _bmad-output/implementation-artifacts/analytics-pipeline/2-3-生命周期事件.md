# Story 2.3: 生命周期事件

Status: review

<!-- 主题 analytics-pipeline，不归属任何版本（App 侧随 V1.5.0 切换）。分支 feat/analytics-pipeline，基于 main。 -->

## Story

作为市场和产品，
我想要新装、升级、打开三个事件与以前口径一致，
以便安装量、留存、日活能接着算。

## Acceptance Criteria

本 story **只改 App，没有后端段**。L1 依赖 Epic 1 已部署到 stag。L0 = `flutter analyze` / `flutter test`；L1 = Android 模拟器装 profile 或 release 包连 stag（debug 包不上报），查 stag 埋点库。

1. **〔L0〕新装**：新增 `lifecycle_events.dart`。设备上既没有自建安装标记、也没有旧版本地数据时，首次启动报 `Application Installed` 并写安装标记与当前版本号。
2. **〔L0〕升级**：有旧版本地数据但没有安装标记的设备，首次启动报 `Application Updated`，**不报 Installed**；之后版本号每次变化也报 Updated（带前后版本）。
3. **〔L0〕判据键**：「旧版本地数据」的判据键在 story 内核实并写明：必须是旧版每台设备首启必写、未登录和未完成引导的用户也有的键。→ 见 Dev Notes「旧版本地数据判据（已核实）」。
4. **〔L0〕打开**：每次冷启动和每次从后台回到前台都报 `Application Opened`，属性 `from_background` 区分；静默推送唤醒不报。
5. **〔L0〕纯函数**：判定逻辑抽成纯函数，单测覆盖新装、升级、同版本重启、版本再变四种情况。
6. **〔L1〕模拟器**：全新安装 → Installed + Opened；先装旧版 APK 再覆盖装新版 → 只有 Updated + Opened。

## Dev Notes

### 旧版本地数据判据（已核实，2026-11-12）

判据：**`SharedPreferences` 里存在任一以 `petgo.` 为前缀的键**，并且快照必须在 `main()` 最早处、任何新代码写键之前取。

核实过程（`lib/core/storage/prefs.dart` 及全仓 `SharedPreferences` 写入点）：

| 键 | 谁写 | 是否每台设备首启必写（含游客、未引导） |
|---|---|---|
| `petgo.push_permission_asked` | `PushPermissionBootstrap.requestOnFirstLaunch()`（`main.dart` 首帧后启动链，ATT 落定后执行；ATT 未落定时由 `AttGate.installForegroundRetry` 落定后补执行） | **是**。2026-08-07（`fbdd353c6`）起首启即申请通知权限，无论同意与否都写 true；存量用户首次跑到该版本时也会补写。**主判据** |
| `petgo.push_permission_last_granted` | 同一流程里 `PushPermissionChangeReporter.record()`（V1.4.0 起） | 是（与上一键同时写），作辅证 |
| `petgo.splash_last_shown_date` | 2026-06-22 ~ 08-04 期间的版本每次冷启动写；V1.1.2 起被 `AppPrefs.create()` 删掉 | 覆盖最早期安装，但已被后续版本清理；快照放在 `_loadSavedLocale()` 之前，仍能看到尚未清理的残留 |
| `petgo.locale`、`petgo.pet_status`、`petgo.phone_prompt_shown` 等 | 用户操作后才写 | 否，仅作辅证 |

用「任一 `petgo.*` 键」而不是单一键，是为了把上表全部辅证都算上，减少漏判。安全令牌 `petgo.access_token` 在 secure storage 里，**不读**（BAD_DECRYPT 风险，且未登录用户没有）。

**已知偏差**（写进 Completion Notes，交口径文档）：
- 装过旧版但首启时在权限弹窗出现前就被杀、之后再没打开过，又直接升级到新版的设备，没有任何 `petgo.*` 键，会被记为 Installed（多算新装，量极小）。
- Android 未设 `allowBackup`（默认开启）：开启了 Google 备份的设备卸载重装后，系统可能恢复 `shared_preferences`，此时安装标记还在 → 重装不报 Installed（少算），与 FR-3「卸载重装算新装」不一致。是否关闭备份需 Dai 拍板，本 story 不改 manifest。

### 现有代码（已核实）

- `lib/main.dart`：`WidgetsFlutterBinding.ensureInitialized()` → Android 选图器设置 → `await initializeDateFormatting()` → `unawaited(Analytics.init())` → 锁竖屏 → `await _loadSavedLocale()`（内部 `AppPrefs.create()` 会删废弃键）→ `runApp` → 两个首帧后回调（Firebase；归因 / ATT / 通知权限 / 版本检查链）。
- `Analytics.init()` 目前设置了 PostHog `captureApplicationLifecycleEvents = true`。PostHog 已停用，这些自动事件无人接收；本 story **不碰** PostHog 配置，2.6 整体删除。
- `lib/app.dart` 的 `_TailTopiaAppState.didChangeAppLifecycleState` 已用于推送 / 角标 / 版本检查。本 story **不改它**，生命周期事件用自己的观察者，避免和那段已经很拥挤的回调耦合（2.1 的 sink 也是同样做法）。
- `package_info_plus 8.3.1`、`shared_preferences 2.5.5` 已在依赖里，不加新依赖。

### 口径对齐

- 事件名用 Segment 写法 `Application Installed` / `Application Updated` / `Application Opened`（架构「命名」：只有这三个例外于 snake_case），常量取 2.1 的 `AnalyticsEvents`。这些名字和属性需在 Story 1.2 的 `event-catalog.yaml` 里登记；本 story 新增的属性 `version`、`build`、`previous_version`、`previous_build`、`from_background` 若清单里没有，在 Completion Notes 列出，提醒后端补登记（未登记的属性会被明细层过滤掉，D-4）。
- 卸载重装算一次新装（FR-3 口径注明，与 PostHog 行为相同）。

### 必须遵守

- 启动链里不加任何 await 到首帧之前的耗时操作：快照只读内存里的 prefs；`PackageInfo` 和事件发送都在 `unawaited(Analytics.init())` 里。
- 新增的键一律 `tailtopia.analytics.` 前缀。
- 不整文件 `dart format`。
