## Story

作为市场和产品，
我想要查到 D1 / D3 / D7 留存、新用户 W1 留存和安装后建档比例，
以便评估投放质量和新手引导。

## Acceptance Criteria

本 story 只改后端，没有前端段。L0 = 编译 / 单测；L1 = 本地 postgres + redis 真跑；L2 = stag / 生产实测。云端只跑 L0。

**Epic 4 通用规则（全部适用）**

- 只算生产数据且 `is_suspicious=false`；用户维度只算 `role = 'USER'` 且 `account_type = 'REAL'`。
- 按「人」去重：带用户标识的事件归该用户；匿名事件按关联表归属（事件前有关联 → 最近一次；之前没有、之后有 → 第一个；从未关联 → 匿名 id）。
- WIB 自然日；周 = 周一至周日；月 = WIB 自然月。
- 每日去重人数不跨天相加：凡「统计周期内去重人数」的指标，同时写日表、周表、月表（周期结束次日计算并回补）；比率类月指标（取每日比率平均）由日表现算。
- Toko 已付款 = `shop_orders.paid_at IS NOT NULL`，按 `paid_at` 的 WIB 日期；退款 / 取消仍算。业务库关联一律用 public token，读业务库只做窄查询，不做跨库 SQL。
- 汇总表不含 `user_id`、匿名 id 等可识别个人的字段；每张新表在迁移里授权给 `analytics_reader`。

**验收标准（原样取自 epics.md Story 4.3）**

1. **Given** 迁移建 `agg_cohort_retention` **Then** 以安装日为组（首次 `Application Installed`，按归属规则归到人），记组人数和第 X+1、X+3、X+7 天再次 `Application Opened` 的人数；未满 N 天的组该列为空（市场 #1–#3）〔L1〕
2. 以 `onboarding_completed` 日为组，记组人数和其后第 7–13 天内任意一天打开过的人数（产品 #5）〔L1〕
3. 按月（`agg_monthly_install_profile`）记当月新装人数中有 `pet_profile_create_submitted` 的人数（产品 #1）〔L1〕
4. 每次运行回补仍在观察窗口内的组（最长 13 天）〔L1〕
5. 按周加权的留存由组表现算，口径写进 `metric-definitions.yaml`〔L0〕

### 成熟度与回补（AC1、AC4）

- 每次运行 `as_of` = WIB 昨天。`retention` 族的重算窗口是 `[as_of − 15, as_of]`：W1 需要 X+13，再留 3 天给晚到数据（架构 D-6），所以组日期最早回到 `as_of − 15`。4.1 框架按 `recomputeDays = 16` 自动处理，缺跑的日子由 `agg_progress` 续上。
- 列是否「已满 N 天」只看 `X+N ≤ as_of`，不看单元日期。框架的手动重跑也传当前的 `as_of`，所以补跑旧组日期时，成熟度按今天判断，已有值不会倒退成 NULL。
- 超出窗口的组不再刷新：之后晚到的事件不会改它（已知偏差：「晚到超过 3 天不回算」）。

### SQL 口径

公共条件沿用 4.1 的「标准过滤」：`is_production AND NOT is_suspicious AND source = 'APP'` + 排除用户，经 `v_events_person` 拿 `person_key`。

```sql
-- 组成员（以 INSTALL 为例；ONBOARDING 把事件名换成 onboarding_completed）
WITH firsts AS (
  SELECT p.person_key, min(p.event_date) AS first_date
  FROM v_events_person p
  LEFT JOIN tmp_excluded_users x ON x.user_id = p.person_user_id
  WHERE p.event = 'Application Installed'
    AND p.event_date BETWEEN :lookback_start AND :stat_date
    AND p.is_production AND NOT p.is_suspicious AND p.source = 'APP'
    AND x.user_id IS NULL
  GROUP BY p.person_key
), cohort AS (SELECT person_key FROM firsts WHERE first_date = :stat_date),
opened AS (
  SELECT DISTINCT p.person_key, p.event_date
  FROM v_events_person p
  LEFT JOIN tmp_excluded_users x ON x.user_id = p.person_user_id
  WHERE p.event = 'Application Opened'
    AND p.event_date BETWEEN :stat_date + 1 AND LEAST(:stat_date + 13, :as_of)
    AND p.is_production AND NOT p.is_suspicious AND p.source = 'APP'
    AND x.user_id IS NULL
)
SELECT count(*) AS cohort_size,
       CASE WHEN :stat_date + 1 <= :as_of THEN count(*) FILTER (WHERE EXISTS (
            SELECT 1 FROM opened o WHERE o.person_key = c.person_key AND o.event_date = :stat_date + 1)) END AS d1_retained
       -- d3 / d7 同理；W1 用 o.event_date BETWEEN :stat_date + 7 AND :stat_date + 13
FROM cohort c;
```

这只是口径示意，实现时按需改写（例如把 `opened` 收窄到组成员），但必须满足：日期全部来自参数；按 `event_date` 而不是 `event_time` 定日；`person_key` 不落表。

- `onboarding_completed` 只认「首次」：同一人重装后再走一次引导，只按第一次分组（在明细保留期内判断）。
- 产品 #1 的分母（当月新装）与 S2 同口径；分子不要求建档晚于安装，只要求同月。

### 按周加权的留存（AC5，现算，不建表）

写进口径条目，例如 D1 的周值：

```sql
SELECT sum(d1_retained)::numeric / NULLIF(sum(cohort_size), 0)
FROM agg_cohort_retention
WHERE cohort_type = 'INSTALL'
  AND cohort_date BETWEEN :week_monday AND :week_monday + 6
  AND d1_retained IS NOT NULL;   -- 只算已满 N 天的组
```

这等于「当周每日组的留存按组人数加权平均」（市场 #1 原文）。D3 / D7 / W1 同理。比率不入库，按需现算。

### 已知偏差（写进口径条目）

卸载重装算新装、新组；「首次」只能在明细层保留期（约 3 个月）内判断；`Application Opened` 冷启动和回前台都会报，只要当天有一次即算打开；员工与测试账号按正常用户算；晚到超过 3 天不回算；V1.5.0 之前无数据，前 13 天的组 W1 不完整。
