# Story 3.3: 购物车事件补全

Status: ready-for-dev

<!-- 主题 analytics-pipeline，不归属任何版本（App 侧随 V1.5.0 切换）。分支 feat/analytics-pipeline，基于 main。 -->

## Story

作为电商，
我想要加购、移出、改数量都有事件，
以便算出商品在购物车里停留多久、为什么没转化（电商 #7）。

## Acceptance Criteria

> 以 `_bmad-output/planning-artifacts/analytics-pipeline/epics.md` Story 3.3 为准，原样带入。

1. **〔L0〕** `toko_add_to_cart_tapped`（`product_detail_page_v3.dart`、`sku_picker_sheet.dart`）补齐属性：`product_token`、`sku_token`、数量、单价。
2. **〔L0〕** 新增 `toko_cart_item_removed`：手动删除或清空失效商品时按商品各报一次，带 `product_token`、`sku_token`、数量、`reason`（`manual` / `invalid_cleared`）。
3. **〔L0〕** 新增 `toko_cart_quantity_changed`：带 `product_token`、`sku_token`、修改前后数量。
4. **〔L0〕** 下单成功后商品离开购物车，不报 `toko_cart_item_removed`。
5. **〔L1〕** 模拟器上加购 → 改数量 → 删除，stag 明细层依次有三条事件，属性齐全。

### 属性命名（本 story 定，yaml 与代码一致）

| 事件 | 属性 |
|---|---|
| `toko_add_to_cart_tapped` | `product_token`、`sku_token`（已有）+ `qty`（整数）、`unit_price`（整数 IDR，SKU 当前售价） |
| `toko_cart_item_removed` | `product_token`、`sku_token`、`qty`、`unit_price`、`reason`（`manual` / `invalid_cleared`） |
| `toko_cart_quantity_changed` | `product_token`、`sku_token`、`qty_before`、`qty_after`、`unit_price` |

- 数量沿用仓库已有键名 `qty`（`toko_order_submitted.items[]` 已用），不新造 `quantity`。
- `unit_price` 是 epics「单价」的落地名；`removed` / `quantity_changed` 也带单价，供电商 #7「购物车总价值 = 单价 × 数量」直接用，不必回查加购事件。
- 金额允许进自建库（PRD FR-1）。若本分支 `analytics.dart` 里 `posthogMoneyKeys` 仍在（Story 2.6 未合入），把 `unit_price` 加进去，保持「金额不进 PostHog」的 11-08 规则直到 PostHog 移除。

## Dev Notes

### 现状（读过的代码）

- `CartLine`（`lib/features/shop/domain/shop_cart.dart`）有 `skuToken`、`productToken`（可空）、`price`、`qty`、`invalidReason`；`CartView` 分 `lines`（有效）与 `invalidLines`（失效）。
- `CartController`（`cart_repository.dart` 第 132 行起）是全局单例，所有写操作经 `_mutate`：取单调序号 → 请求 → 只接受最新序号的结果；失败抛 `CartMutationError`。`_mutate` 正常返回 = 服务端已执行。
- 删除入口：有效行 `_ValidLineState._remove`（含 undo）、失效行 `_InvalidLineState._remove`、清空失效 `clearInvalid`、结算页 `_removeFromCart`。改数量入口只有 `_ValidLineState._setQty`（`ShopStepper`）。
- 加购入口两处：详情页 `_onDockTapped`、`showSkuPickerSheet`（商品卡「＋」）。`ShopSku.price` 是整数 IDR。
- 下单后购物车只 `refresh()`，没有逐行删除调用。

### 已知偏差（写进 Completion Notes，交 Story 4.6 写进电商 #7 口径）

- **撤销删除**：删除后点 undo 会以 `entrySource: 'CART_UNDO'` 重新加购（`cart_page_v3.dart` `_undoRemove`），这条不报 `toko_add_to_cart_tapped`。于是明细里会留一条 `removed`，而商品其实回到了车里。撤销率低，本 story 不处理；4.6 可按「同用户同 `sku_token` 在 `removed` 后 5 秒内无新加购事件」判断，或把撤销作为已知偏差写进口径。需要改成「撤销时补报」的，交 Dai 拍板。
- **加购事件在请求之前报**（点确认即报，游客放弃登录、加购接口失败也算一次），这是团队文档定义的「加购」口径，沿用不改。
- 在其他设备或后台清空的购物车行没有事件，无法观测（4.6 AC 已写）。
- `qty` 为加购时选的数量，服务端合并同 SKU 后车里实际数量可能更大；停留价值以车内行为准时，应以最近一次 `quantity_changed.qty_after` 为准。

### 护栏

- 只上报 token、整数数量与金额、受控枚举；不报商品名、规格名（`productName` / `specName` 是自由文本，`scrub` 也会因 `_name` 后缀丢掉）。
- 不改任何触发时机、不改购物车请求流程与序号逻辑；上报放在 `_mutate` 返回之后，不影响状态覆盖。
- 不 `await` 埋点。
