# Story 2.4: 页面浏览事件

Status: review

<!-- 主题 analytics-pipeline，不归属任何版本（App 侧随 V1.5.0 切换）。分支 feat/analytics-pipeline，基于 main。 -->

## Story

作为电商和产品，
我想要页面浏览照旧记录，页面名不变，
以便 Toko 浏览、漏斗第一步等指标不断档。

## Acceptance Criteria

本 story **只改 App，没有后端段**。L1 依赖 Epic 1 已部署到 stag。L0 = `flutter analyze` / `flutter test`；L1 = Android 模拟器装 profile 或 release 包连 stag（debug 包不上报），查 stag 埋点库。

1. **〔L0〕路由观察者**：自有路由观察者取代 `app_router.dart` 里的 `PosthogObserver()`，路由 push 产生 `screen_viewed`（属性 `screen` = 现有页面名，如 `toko_page`）。
2. **〔L0〕手工补报**：`Analytics.screen()` 现有调用（底部 Tab `goBranch` 切换、冷启动落地页补报）同样产生 `screen_viewed`。
3. **〔L0〕不重复**：同一页面不因路由重建重复上报（沿用现有去重逻辑）。
4. **〔L1〕名字一致**：模拟器上依次切四个底部 Tab 并进入商品详情，stag 明细层的页面名与 PostHog 时期一致。

> **AC1 / AC3 的措辞与现有代码有出入，以本 story 的「行为对齐」为准**（已核实，见 Dev Notes）：路由观察者产生的页面名是**路由路径模板**（如 `/shop/products/:token`），`toko_page` 这类 `<产品叫法>_page` 来自 `Analytics.screen()` 手工补报；`PosthogObserver` 本身**没有去重逻辑**，「不重复」的含义是「逐条复刻 PosthogObserver 的触发时机，不多报也不少报」。

### 当前页面上下文

PostHog SDK 会给**每条**事件自动附 `$screen_name`（最近一次 `screen()` 的名字），`buttonTapped` 的注释正是依赖这一点（「当前屏幕由 SDK 以 `$screen_name` 注入」）。换成自建上报后这项能力会消失。为了不丢这个维度，本 story 维护 `_currentScreen`，由 Story 2.5 把它放进每条事件的 `context.screen`。如果 2.5 已先完成，本 story 直接把 `screen` 加进 2.5 的 context 组装处。

- 页面名不改、不加工（除 `'/'` 的既有改写）。改名会让 Toko 浏览、漏斗第一步断档。
- 路由层不得直调任何埋点 SDK，一律经 `Analytics` 门面（`late_landing_correction_test.dart` 有源码断言）。

### Review Findings（代码复审 2026-11-12）

对照 `posthog_flutter-5.33.0/lib/src/posthog_observer.dart`、`go_router-17.3.0` 源码，并在 widget 测试里实挂 `TailTopiaApp` 探测真实事件序列后的结论：

- **R1 · 中 · CONFIRMED · 已修**：`AppShell` 补报只挂在 `didUpdateWidget`（分支索引变化），外壳**新挂载**时不报。冷启动深链直达 Tab 根（推送 / 运营位 `go('/shop')`，`deepLinkNeedsBaseRoute` 为 false，且深链路径不走落地补报）、以及从已把外壳移出栈的顶层页（`go('/places')` 等）再 `go('/shop')`，实测只有路径模板 `/shop`、没有 `toko_page` —— 正是汇总修订要堵的「go 进 Toko 漏报」。修：`initState` 同样调 `_reportBranchEnteredIfMissing(currentIndex)`；普通冷启动落地 / 迟到纠正都在 `go` 之前已补报，按 `currentScreen` 去重跳过（实测冷启动 `diary_page` 仍 1 条、迟到纠正 `social_page` 1 条）。新增 L0「外壳新挂载（从顶层页 go 回 Tab）也补报且只报一次 toko_page」，已验证去掉修复即红。代价：深链需要底座时（`go(落地页)` 再下一帧 push 深链目标），会为底座 Tab 补一条 `<tab>_page`（PostHog 时期该处已有路径模板一条，口径同向）。
