# Story 1.8: 失败时知道原因并重试

Status: review

<!-- 主题 ops-ai-query，不归属任何版本。分支 feat/ops-ai-query，基于 main。 -->

## Story

作为后台账号，
我想要在查询失败时看到原因和下一步，
以便不用重新输入问题。

## Acceptance Criteria

1. **[L1]** 任务为 `FAILED`、`TIMEOUT` 或 `AGENT_RATE_LIMITED` 时，在原位置显示对应原因和“用原问题重试”（D1～D3）；**[L2]** 失败用 `{colors.danger}`，超时和额度用尽用 `{colors.warn}`。
2. **[L1]** 点击重试：用原问题创建新一轮 `PENDING`，遵守未完成任务限制。
3. **[L1]** 错误为 `AGENT_AUTH_FAILED` 时提示联系管理员，不提供重试，输入框禁用（D4）；后端记 error 日志，不含问题和答案。
4. **[L2]** 错误提示经 `role="alert"` 播报。

## Tasks / Subtasks

- [x] `AiQueryFailure`：status + error_code → 失败 / 超时 / 额度用尽 / 授权失效（AC1、AC3）
- [x] 失败卡：原位显示标题 + 下一步，危险色 / 警告色，`role="alert"`；可重试的带「用原问题重试」（复用 Story 1.7 `requery`）（AC1、AC2、AC4）
- [x] 授权失效锁 `AiQueryAuthLock`：输入框禁用、占位「暂时无法提问」、不提供重试；服务端同样拒绝追问 / 重新查询 / 重试（AC3）
- [x] 授权失效 error 日志（Story 1.5 扫描器已实现，本 story 补测试：只含 token）（AC3）
- [x] 三语文案；L0 `AiQueryFailureTest`；L1 `AiQueryFailureIntegrationTest`、扫描器日志断言

## Dev Notes

- 归类：`TIMEOUT`（ops 15 分钟）与 `AGENT_TIMEOUT`（agent 10 分钟）都显示「查询超时」；`AGENT_LOST` / `AGENT_REJECTED` / `AGENT_ERROR` 显示「查询没有成功」。页面不出现技术错误码。
- 授权失效锁 = 对话最新一轮授权失效 **且此后全系统没有任何查询成功**：订阅 token 是全局的，管理员更新后只要有人查询成功，锁自动解除；新建对话不加锁（总得有人验证新 token）。
- 重试 / 重新查询按钮只在能提交时显示（功能开启、对话不忙、未被锁），避免点了拿 422。
