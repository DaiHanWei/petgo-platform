# Story 1.5: 后台扫描器推进任务

Status: review

<!-- 主题 ops-ai-query，不归属任何版本。分支 feat/ops-ai-query，基于 main。 -->

## Story

作为有权限的后台账号，
我想要提交的任务在后台持续推进，
以便 ops 重启后不丢结果。

## Acceptance Criteria

1. **[L0]** `AI_QUERY_MODE`、`AI_QUERY_AGENT_URL`、`AI_QUERY_AGENT_SECRET` 全部经 env 注入，`.env.example` 只放占位，`AI_QUERY_MODE` 默认 `off`。
2. **[L0]** `AI_QUERY_MODE=off` 时扫描器不提交、不轮询。
3. **[L1，agent stub]** 存在 `PENDING` 任务时扫描器（fixedDelay 3 秒）提交给 agent，成功后转 `RUNNING`；agent 返回 429 或不可达时保持 `PENDING`，下轮重试。
4. **[L1，agent stub]** 对话已有 `agent_session_id` 时，追问请求带 `resumeSessionId`，完成后保存返回的 `sessionId`。
5. **[L1，agent stub]** `RUNNING` 任务完成或失败时写入答案、`files`、`agent_secs`、`agent_turns`、`cost_usd` 并转 `DONE` 或 `FAILED`，记录 `error_code`。
6. **[L1，agent stub]** agent 对任务返回 404 时任务转 `FAILED`。
7. **[L1]** 任务超过 15 分钟未结束时转 `TIMEOUT`。
8. **[L1]** 同一任务被重复处理时，带旧状态条件的 UPDATE 只成功一次，不重复派发或覆盖结果。
9. **[L0]** 状态机单元测试覆盖提交、完成、失败、超时、幂等重复提交和状态条件更新。
10. **[L1，agent stub]** ops 在任务运行中重启后，提交幂等，仍能取回结果。

**复审（code-review）修复项：**
- agent 返回超长 / 未知 `errorCode` 或异常 `sessionId` 会让 UPDATE 失败、整轮中断（一条坏数据卡住其后所有任务）→ 错误码白名单、会话 id 格式校验。
- 提交收到 403 / 404 等被判为请求非法、任务永久失败 → 仅 400 / 413 判死，其余视为配置问题保持 PENDING。
- 文件清单 `size` 为空导致整条结果反序列化失败 → agent 侧文件项用包装类型。
- agent 不可达时逐个任务等读超时、拖住调度线程 → 本轮立即停止。
- 密钥不符时每 3 秒一条 error 日志 → 限频 5 分钟一次。
- 派发时逐条查对话（N+1）→ 批量 `findAllById`；删除测试死代码。
- 未改：超时起点保持规划原文（创建后 15 分钟）；测试 `setUp` 重置共享表未完成任务是为把扫描范围限定在本类数据，保留。
