# Story 1.6: 在页面上跟踪查询进度

Status: review

<!-- 主题 ops-ai-query，不归属任何版本。分支 feat/ops-ai-query，基于 main。 -->

## Story

作为提交了问题的后台账号，
我想要看到每个查询的进度，
以便离开后回来时知道哪些已完成。

## Acceptance Criteria

1. **[L1 + L2]** 存在未完成任务时每 3 秒同时更新左栏状态和右栏内容；全部结束后不再轮询。
2. **[L1]** 任务排队或查询中时显示状态文字和已用时长，提示可以离开，不显示取消按钮（B3、B4）。
3. **[L2]** 用户切到其他对话时，原任务仍在运行，左栏继续显示进度和计时（B5）。
4. **[L2]** 用户离开标签页期间任务完成，标签页标题显示“(1) 已完成”，回到页面后恢复。
5. **[L2]** 轮询请求失败时显示连接中断提示，恢复后自动继续（E2）。
6. **[L1]** 对话超过一页时，滚动左栏用现有 `q-more` 加载更多（E3）。
7. **[L2]** 状态经 `aria-live="polite"` 播报；开启减少动效时圆点动效停止，状态仍有文字。

## Tasks / Subtasks

- [x] `GET /admin/ai-query/poll?w=&m=&c=`：只返回本人未过期的左栏行 / 右栏轮次；当前对话的未完成轮次结束时连同输入框一起返回（AC1）
- [x] `GET /admin/ai-query/rows?after=`：游标分页的 `q-more`（AC6）
- [x] 左栏行 / 右栏轮次：状态圆点 + 文字、计时（排队中「已等待」、查询中「已用时」）、`data-aiq-unfinished` 关注标记；不提供取消（AC2、AC3）
- [x] `admin-ai-query.js`：仅在有未完成任务时每 3 秒 fetch，按元素 id 替换；离开期间完成改标签页标题、回来恢复；失败显示 E2 提示并退避重试；无权限 / 会话过期停止轮询（AC1、AC4、AC5）
- [x] `aria-live="polite"`、`prefers-reduced-motion` 停止圆点动效（Story 1.3 已加样式）（AC7）
- [x] 三语文案；L1 测试 `AiQueryProgressIntegrationTest`

## Dev Notes

- 轮询用自写 fetch 循环而不是 htmx `every 3s`：需要按页面上实际未完成的元素决定是否继续、在失败时显示 E2、在离开时改标题；htmx 1.9 没有公开的手动 swap API。左栏滚动加载仍用 htmx `q-more`。
- 左栏分页用游标 `(updated_at, token)`：列表在页面打开期间会变（新对话、扫描器刷新 updated_at），offset 分页会重复或漏行。游标只含时间与不可枚举 token，不暴露自增 id。
