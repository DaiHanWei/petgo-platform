# Story 2.3: 访客态页面渲染（作者态减法）

Status: review

## Story

As a 收到分享链接的人，
I want 页面干净、没有我用不了的按钮，
so that 我一眼就知道自己是在看别人的宠物。

## Acceptance Criteria

**AC1 · 接入单一状态判定入口**
**Given** PRD 明令「复用作者态页面结构做减法、不得另画一套」
**When** 实现访客态
**Then** 接入 Diary 页现有的**单一状态判定入口**，作为**新增的一个状态分支**与既有四状态互斥分发 `[L0]`
**And** 🛡 **不新建独立页面** `[L0]`
**And** 依据是 V1.1.2 AD-15 Rule 2：「该入口由先落地的那条建立，后落地的那条**只增加自己的分支，不得另起判定**」

**AC2 · 🛡 减法清单**
**Given** 访客只能浏览
**When** 渲染访客态
**Then** 以下**全部移除**：入口网格两张卡（健康记录 / 身份证）**整块**、标题行的分享名片与编辑铅笔按钮、点赞 / 评论 / 举报 / 打卡等一切互动与管理入口 `[L2]`
**And** 🛡 **身份证入口必须整块移除** —— 它跳的是**当前登录用户自己的**身份证页，访客点进去必然出错 `[L1]`
**And** 🛡 **不引入「陪伴天数」字段**（那是 H5 独有的，Diary 页没有）`[L2]`
**And** ✅ 分享 FAB **已不存在**（2026-08-04 已从右下 FAB 挪到标题行），只需处理标题行那个

**AC3 · 条目点击的公私分流**
**Given** 时间线里既有公开内容也有作者关掉同步的私密日记
**When** 访客点击某个条目
**Then** **公开内容**可点开、进既有内容详情页 `[L2]`
**And** 🛡 **私密日记不可点开**，点击给一句解释性提示 —— 私密内容因此**始终不越出链接边界** `[L2]`
**And** 提示文案须出 **id / en 两版**并入 ARB（产品给的中文仅为意图，不可直接落地）`[L0]`
**And** 「公开」的判定是**可见范围为公开 且 状态为已发布**两条同时成立 `[L1]`
**And** 🔴 该判定**在后端算**、随条目下发一个布尔位；前端**不得**自己拿可见范围再推一遍 —— 见 Dev Notes「契约缺口」

**AC4 · 🛡 不把边界扩散到全局路由**
**Given** 内容详情页是全局路由
**When** 访客从访客视图点进公开内容
**Then** 🛡 **禁止**在详情页为访客场景新增「这条是否属于某个已授权宠物」的二次校验层 —— 那会把链接边界扩散到全局路由上 `[L0]`
**And** 公开即公开、私密就地拦（AD-3 Rule 4）

**AC5 · 带 token 的独立路由**
**Given** 访客视图对未登录开放
**When** 实现路由
**Then** 🛡 访客视图必须是**带 token 的独立路由**，**不得复用作者态的档案路由**（AD-2 Rule 6）`[L0]`
**And** ⚠️ 这与 AC1「复用页面结构」**不矛盾**：正解是**路由独立、Widget 复用** —— 见 Dev Notes「结构切分」
**And** 未登录也能进（否则会把用户推回浏览器）`[L2]`

**AC6 · 顶部来源横幅**
**Given** 访客需要一眼看出「这是别人的宠物」
**When** 渲染访客态
**Then** 页面顶部有一条来源横幅（UI 稿 P1 的 `.ro-banner`）：眼睛图标 + 「由 {昵称} 分享 · 仅可查看」`[L2]`
**And** 文案同样 id / en 两版入 ARB `[L0]`

## Dev Notes

### 🔴 结构切分：路由独立、Widget 复用

AC5「带 token 的独立路由」与 AC1「复用页面结构、不新建独立页面」**看起来矛盾**，正解是把两件事分开：

| 层 | 做法 |
|---|---|
| **路由** | **独立**新增 `/pet/:token`（AD-2 Rule 6）—— 作者态路由 `/profile` 对未登录会落游客示例页，复用它与「深链落到被分享的那只宠物」直接冲突 |
| **页面 Widget** | **复用** `GrowthArchivePage` / `_ArchiveBody` / `DiaryHeader` / `TimelineItemTile`，只是多一个状态分支 + 多几个「不渲染」开关 |
| **数据** | 同一套 provider，按 `ArchiveScope` 区分 `me` 与 `visitor(token)` |

> ⚠️ 开发时**不要二选一**（要么另建页面、要么复用作者路由）—— 两种都违反其中一条 AC。

### 🔴 契约缺口：前端没有「是否私密」这个数据

- `TimelineItem`（Flutter 模型）**没有任何可见性字段**，全文件零命中
- `GrowthMomentView`（后端 content 模块投影）**也没有**
- `VisitorTimelineItem`（Story 2.1 建）同样没有

所以 AD-3 Rule 2「私密不可点开」在前端**无数据可依**。T1 补这条链路。

**判定放后端算**，前端只读一个布尔位。理由：判定是「可见范围公开 **且** 状态已发布」两条**联合**成立，
把它散到前端就等于允许两处各写一遍 —— 而写漏的那一次是静默的（私密内容变得可点开）。

### 🔴 减法的三个具体拦路点（代码实读 2026-08-18）

1. **编辑铅笔无法只靠传 null 隐藏**：它是无条件渲染的，`onTap: null` 只让它变灰、图标仍在。必须加不渲染开关。
2. **入口网格是无条件调用的**：整块移除要在渲染处加条件，不是把两张卡的回调置空（AD-2 Rule 5 明确要求**整块移除**，「留个锁」不算）。
3. **分享按钮已是 null-safe**：不传 `titleAction` 即整块消失，这一处最省事。

### 🔴 数据 provider 全是「我的」作用域

四个 provider（档案 / 统计 / 时间线首页 / 日历月）走的都是 `/pet-profiles/me/*`。
AD-1 Rule 3 **禁止**在 `/me` 查询上加访问者参数来复用，所以访客必须走 2.2 建的 `/api/v1/public/shared-pets/{token}/*`。

而 `_ArchiveBody` / `_TimelineView` / `ArchiveCalendar` 是**直接 watch 这些 provider 的**，
不参数化就无法复用 —— 这是 T2 存在的唯一理由。

> 🛡 **一套 provider、两个 scope**，不要复制第二套。两套实现会漂移，且漂移方向永远是访客那套更宽松。

### 架构约束

- **AD-2 Rule 2**：访客视图对未登录开放；已登录非作者与未登录访客看到**同一套**只读视图
- **AD-2 Rule 3**：作者本人经该链接进入 → 落自己档案页（**Story 2.4 的分流职责，本 story 不实现**）
- **AD-2 Rule 5**：无任何写入能力、无分享入口、健康记录与身份证两张入口卡**整块移除**
- **AD-2 Rule 6**：带 token 的独立路由
- **AD-3 Rule 1/2/3/4**：公开可点开 · 私密就地拦 + 提示 · 提示须 id/en 两版 · **禁止在详情页加二次校验层**
- **AD-4**：作为 AD-15 的新增分支 · 复用作者态结构做减法 · 不引入陪伴天数 · 切换文案 `Linimasa` / `Kalender`
- **AD-1 Rule 8**：统计条三列复用作者态唯一统计实现，不得自行重算；Diary 计数**含私密条目**
- **AD-15 Rule 2**（V1.1.2）：后落地的 story **只增加自己的分支，不得另起判定** ← 本 story 加分支的授权依据
- **AD-16**：时间线与日历的分类优先级**刻意不对称**，访客态做减法时不得顺手「对齐」

### 现状实读（2026-08-18）

**Diary 页渲染顺序**：`DiaryHeader`（标题行 + PetInfoCard + 统计条 + 入口网格 + 里程碑进度）→ 视图切换 → 时间线（始终挂载、切日历时隐藏）→ 日历。

**四状态**：`guest`（未登录种草）· `nonOwner`（B/C 态）· `ownerWithoutProfile`（建档引导）· `ownerWithProfile`（真实档案）。
判定入口只有一处，源码注释写明「本页任何其它位置不得再判用户状态」。

**已不存在、无需处理的**：分享 FAB（已挪到标题行）· 打卡入口（在里程碑列表页，Diary 页只有跳转）· 点赞/评论/举报（在内容详情页）。

**深链现状**：`tailtopia://card/...` 目前**直接丢弃 token** 落到 Diary 根，游客因此看到示例页 —— 那正是 Story 2.4 要改的，本 story 不改。

**测试面**：`growth_archive_state_branch_test.dart`（四态互斥 + 分发 + 枚举穷尽硬断言）· `timeline_five_class_render_test.dart`（五类跳转逐个断言，改跳转必受影响）· `diary_gating_and_landing_test.dart`（深链门控与落地矩阵，2.3/2.4 主回归面）。

**测试惯例**：无共享 pumpWidget helper，每个文件自建局部 `_wrap`；Riverpod 用 `ProviderScope(overrides: [...])`；伪 auth 控制器覆写 `build()`；l10n 挂 `AppLocalizations.localizationsDelegates`。

### 📐 UI 稿覆盖情况

P1 屏（访客只读视图）**只画了「已登录·非作者」的时间线态**，含来源横幅、PetInfoCard、统计条三列、里程碑进度、视图切换、三条时间线条目；**入口网格已整块删除**。

**未画**：私密条目的不可点提示样式（建议复用既有轻提示组件）· 访客态日历屏 · 访客态某天详情屏。
遇视觉口径不明**回头请示产品**，不要自创。

落地前先量了影响面：这四个 provider 被 **18 个 lib 文件 + 21 个测试文件（60 处引用）** 用着，
其中绝大多数与访客毫不相干（发布页、问诊、我的页在发布/改状态后失效刷新统计等）。
全改成 family 等于让一次访客改动波及半个 App，**回归风险远大于收益**。

改为：**取数实现只有一份**（`TimelineRepository` 每个方法加一个作用域参数，
按作用域选地址），作者态调用点**一处未动**（参数有默认值）；
访客态另立几个一行的 provider；组件通过 `xxxProviderFor(scope)` 选择器拿 provider，
**分叉只存在于那几个选择器里**，不散落在每个 `ref.watch` 旁边。

> story 原文那句「只保留一套 provider」的本意是「别复制两套取数实现」——
> 这个目标达到了，且没有连带改动 40 个文件。

**2. 🔴 「私密不可点」在前端原本无数据可依 —— 补了契约，判定放后端**

`TimelineItem`（前端）、`GrowthMomentView`（后端内部投影）、`VisitorTimelineItem`
三者原先都<b>没有任何可见性字段</b>。本 story 打通这条链路，并把判定放在后端算成一个布尔位。

⚠️ 两个刻意的选择：
- **不下发原始可见范围**，只下发结论。判定是「可见范围公开 <b>且</b> 状态已发布」两条<b>联合</b>成立，
  散到前端就等于允许两处各写一遍，而写漏的那次是<b>静默的</b>（私密内容悄悄可点开）。
- **前端 `openable` 为 null 时按不可点处理**（fail-closed）。万一后端漏发这个字段，
  默认可点是隐私事故，默认不可点最多是「本该能点的点不开」——后者一眼可见。
- 后端的 `GrowthMomentView` 新增字段<b>刻意不给默认值</b>：安全相关字段「忘了传就默认公开」
  正是要避免的失守方式（代价是改了 5 个测试文件的 10 处构造，纯机械）。

**3. AC5 与 AC1 的表面矛盾按「路由独立、Widget 复用」解**

新增 `/pet/:token` 顶层路由（AD-2 Rule 6），builder 复用同一个 `GrowthArchivePage`，
由第五个状态分支 `visitor` 承接 —— 没有新建页面类（AC1）。

✅ **门控无需改动**：`/pet` 不落在任何受控前缀下，天然对未登录开放。
🔴 **但这也意味着一条隐性约束**：将来<b>不能</b>把它挪到 `/profile/...` 之下 ——
门控是前缀匹配、安全默认是拦，一挪就会让未登录访客被弹去登录，
而这种错<b>只有真机点链接才发现得了</b>。已写成一条 L0 用例钉住。

**4. 页头复用需要先解开与作者档案类型的绑定**

页头组件原先直接吃作者态的 `PetProfile`，而访客档案字段少得多（没有内部 id、没有 token —— 服务端根本不下发）。
硬塞就得给 id / token 编假值，<b>而假值迟早会在某处被当真</b>。
故抽出一个「页头到底需要哪几样」的视图模型，两种档案各自产出它 ——
顺带说明了一件事：页头本来就不需要 id 和 token。

**5. 减法必须是「不渲染」而不是「不可点」**

`DiaryHeader` 加了只读开关。⚠️ 把回调传 null 只会让编辑铅笔变灰、图标仍在，看上去像坏了；
而<b>身份证入口跳的是当前登录用户自己的卡</b>，访客点进去要么看到自己的宠物、要么直接出错 ——
AD-2 Rule 5 因此要求两张入口卡<b>整块移除</b>。已用 `findsNothing` 钉死，并做过反向验证。

**6. 访客时间线不照搬作者态的分页状态机**

访客侧服务端一次给最近 N 条、不分页（访客是「看一眼别人的宠物」，不是「翻完整个档案」；
且每多一个对外参数就多一处要防的输入）。故访客视图直接渲染条目列表，
但**五类条目仍复用同一个渲染组件** —— 视觉一致性这条没有打折。
另外时间线接口的 `limit` 在服务端<b>夹紧到 100</b>：这是对公网开放的匿名接口。

**7. 本 story 不实现「作者本人点自己的链接落回自己档案页」**（AD-2 Rule 3）——
那是 Story 2.4 深链分流的职责。当前行为：作者点自己的链接会看到只读态，2.4 会纠正。

**8. 📐 三处无 UI 稿**（story 已标注）：访客态日历屏、访客态某天详情屏、私密条目的不可点提示样式。
提示复用了既有轻提示组件。Story 2.4 之后若做 L2 视觉验收，这三处需产品过目。
