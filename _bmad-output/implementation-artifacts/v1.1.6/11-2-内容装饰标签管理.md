# Story 11.2: 内容装饰标签管理

Status: review

## Story

As a 运营，
I want 在后台建装饰标签（如「本周最佳」）并给公开内容打标、设生效时间，
so that FR-75 的装饰标签不再是个没有开关的空壳。

---

> App 侧 FR-75 已交付（Epic 5，story 5-2），表 `content_tags` / `content_tag_assignments` 已建（V110）。
> **后台没有任何页面能建标签、能打标** —— 现在线上装饰标签恒为空。

---

## Acceptance Criteria

### AC1 — 标签增 / 改 / 下线（L1）

**Then** 标签字段：名称 + 图标 + **一句说明文案**（用户端点标签图标时展示）`[L1]`
**And** 支持**下线**：下线后**不可再分配**，但**已分配的记录照旧生效到各自 `ends_at`** `[L1]`

> 🔴 **这是本 Epic 唯一需要新迁移的地方**：`content_tags` 表**没有下线列**
> （字段只有 `id / code / name / icon / description / created_at / updated_at`）。
> 下线**不能用删除代替** —— `content_tag_assignments` 有 FK 指向标签，删不掉；
> 而且删了历史分配记录就一起没了。
>
> ⚠️ 「下线后已分配的照旧生效」是刻意的：下线是"不再发新的"，不是"把已发的追回"。
> 若要立即全部失效，运营应逐条取消分配 —— 那是另一个动作，别合并。

### AC2 — 🔴 只允许对公开内容打标（L1）

**Then** 🛡 只允许对**已发布的公开内容**打标 `[L1]`：`DAILY` / `KNOWLEDGE` / 已同步为公开的 `GROWTH_MOMENT`
**And** 🛡 全量内容管理列表里对**未同步的 Diary** **隐藏打标入口** `[L1]`

> 给只有作者自己能看到的内容挂「本周最佳」，等于让他看见一个无人可见的徽章 —— 没有激励意义（OQ-19）。
>
> 🔴 **枚举名别照 PRD 字面抄**：代码里没有 `MOMENT`。产品口语的 "Moment" = `DAILY`，
> "Diary" = `GROWTH_MOMENT`。

### AC3 — 分配 / 取消 / 生效时间窗（L1）

**Then** 为内容分配或取消标签，支持设生效开始/结束时间；**不设结束时间 = 永久分配** `[L1]`
**And** 🛡 生效判定**查询时**按 `[starts_at, ends_at)` 算，`ends_at IS NULL` = 永久 `[L0]`
**And** 🛡 **不建状态列、不建定时扫描器** `[L0]`（AD-9 Rule 2 —— 表就是照这个建的）
**And** 时间输入按 **WIB** 解释、入库转 UTC，**控件旁明示「WIB」** `[L1]`

### AC4 — 🔴 打标界面必须提示排序副作用（L1）

**Then** 🛡 打标 / 取消打标的操作界面**必须明示**：装饰标签生效中会给该内容 **×1.3** 曝光加权 `[L1]`
**And** 取消打标 / 标签到期时，须提示曝光会回落 `[L1]`

> **打标同时是一个流量动作**，运营不一定知道。不提示的两个后果：
> ① 把打标后的数据上涨误读成"这条内容本来就这么火"；
> ② 取消打标后曝光回落被误判为线上故障。
>
> 建议文案：「取消打标 / 到期时，曝光将取消标签带来的曝光权重」。
> ⚠️ 权重数值以算法文档为准；算法侧调整后本处文案需同步（本条只是界面文案要求，不改任何功能行为）。

### AC5 — 分配记录列表（L1）

**Then** 按内容 / 按标签**两种维度**查看当前生效的分配情况，支持按标签筛选 `[L1]`
**And** 内容被删除时其装饰标签分配记录一并失效 `[L1]`（表上 `ON DELETE CASCADE` 已保证）

### AC6 — 权限与导航（L0 / L1）

**Then** 🛡 **双权限码**：查看一个、编辑（建标签/打标/取消）一个 `[L0]`
**And** 🛡 **入口门与侧栏 `sec:authorize` 条件逐字一致** `[L0]`
**And** 🛡 改导航名**四处同源**：侧栏名 / 页内标题 / 页面说明 / 权限显示名 `[L0]`

### Completion Notes List

**与 11-1 同样是"接上来"。** 打标机制（含「只有公开内容可打标」的校验）与生效判定早在
Story 5.2 就随 `ContentTagQueryService` 落地了 —— 那个 story 的注释原话：
「后台入口本轮不做，只依赖'后台不展示'这条 AC 在本轮等于没有实现，所以校验落在这里」。
本 story 把它接上入口，并补上当时没有的两件事：**标签的增改下线** 与 **取消打标**。

**唯一的迁移：`content_tags.retired_at`**（时间戳号 `V20260821_1741__add_content_tags_retired.sql`）。
用**可空时间戳而不是布尔**：「什么时候下线的」也一并留档，布尔只能回答「是不是」。
🛡 下线语义严格按 AC：**只挡新分配，已分配的照旧生效到各自 `ends_at`** ——
下线是"不再发新的"，不是"把已发的追回"。回显文案也把这句写进去了，否则运营会以为下线等于全部收回。

**🔴 收拢了第三份「内容还能不能对外展示」判定。** 11-1 抽出 `ContentDisplayability` 时只收了 Feed 那份；
这次发现 `ContentTagQueryService` 里还有一份同款私有实现（Feed 一份、这里一份、后台顶置差点再写一份）。
已改为委托。各写一遍的后果不是重复代码，而是**口径漂移** ——
某天有人给其中一处加了条件，表现是「同一条内容在 Feed 里不见了、却还能被打标」，无人会立刻发现。

**🔴 顺手修掉一个我在 11-1 引入的真 bug，并给它补了回归测试。**
共享的内容选择器查询原先写成 `(:kw IS NULL OR LOWER(p.text) LIKE LOWER(CONCAT('%', :kw, '%')))`。
关键词绑 null 时 Postgres 推不出参数类型，直接 500：`function lower(bytea) does not exist`。
**而"不带关键词"正是页面首次加载的那一次**（选择器 `hx-trigger="load"`，没有 q）。

Story 11.1 的测试当时是绿的 —— 只因为它第一次调用带了关键词；本 story 的测试恰好把无关键词那次放在最前，
当场炸出来。修法是模式串在 Java 侧拼好（无关键词 → `"%"`），SQL 侧不再绑 null。
配套加了 `COALESCE(p.text, '')`：**纯图片帖 `text` 为 NULL，而 `NULL LIKE '%'` 结果是 NULL 而非 true**，
不 COALESCE 会把这些帖子整批漏掉。两条回归测试都补在 11-1 的测试类里（无关键词首调 / 纯图片帖）。

**🔴 ×1.3 排序副作用提示写成了测试。** 那是一段**纯提示文案**，没有任何功能行为 ——
删掉之后页面照样渲染、其它测试照样绿，而运营会开始把打标后的数据上涨误读成
「这条内容本来就这么火」、把取消打标后的曝光回落误判成线上故障。
测试断言页面里同时出现「流量动作」「1.3」「曝光」三处要点。
⚠️ 权重数值以算法文档为准；算法侧调整后本处文案需同步。

**踩到并修掉的一处（我测试写错）**：标签码有唯一约束，而这是**共享库** ——
我第一版用了固定码（`WEEKLY_PICK` / `RETIRE_ME` 等），第二次运行就撞唯一约束、4 条报错。
改成每次带唯一序号。**与今天早先那次"用 findAll() 做全库断言"是同一类毛病：把共享状态当独占状态。**
现已验证重跑幂等。

**导航**：11-1 建的「内容运营」分组加第二项「装饰标签」，分组门放宽为
`content.pin_view or content.tag_view`（只持其中一个也要看得见分组）。

**顺手加固了 Feed 分页测试 —— 这条是我的新测试数据暴露出来的。**
11-1 补的"纯图片帖也要能出现在候选里"造了一条**正文为 NULL** 的帖子。
**Feed 是全局的**：任何测试造的公开帖都会流到 Feed 分页测试里，
而那个测试写的是 `item.get("body").asText(null)` —— 假设 `body` 字段总在。
正文为 null 时该字段**整个不出现**，于是当场 NPE。
在从没有测试造过纯图片帖之前，这个假设一直成立。已改成先判字段是否存在。
（生产里纯图片帖是常态 —— 这也正是那条 `COALESCE(p.text, '')` 存在的理由。）

**留 L2 的**：浏览器上看提示条的观感、HTMX 选择器手感、`data-confirm` 弹窗。
