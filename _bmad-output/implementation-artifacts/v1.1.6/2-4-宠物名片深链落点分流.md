# Story 2.4: 宠物名片深链落点分流

Status: review

## Story

As a 收到分享链接的人，
I want 点开链接就看到那只宠物，
so that 我不会莫名其妙看到另一只不认识的宠物。

## Acceptance Criteria

**AC1 · 按访问者身份分流**
**Given** 现状点名片深链进 App，落的是给游客做的「示例成长本」种草页（**不是被分享的那只宠物**）
**When** 改造深链落点
**Then** 按访问者身份分流 `[L2]`：
- **作者本人** → 自己的档案页、**保留全部管理入口**
- **已登录非作者** → 访客只读态
- **未登录** → 同样落访客只读态

**AC2 · 🛡 带 token 的独立路由**
**Given** 访客视图对未登录开放
**When** 实现路由
**Then** 🛡 访客视图必须是**带 token 的独立路由**，**不得复用作者态的档案路由** `[L0]`
**And** ✅ **Story 2.3 已建立** `/pet/:token`；本 story 只改「深链映射到哪里」
**And** ⚠️ 现状映射**直接丢弃 token** 落到 Diary Tab 根 —— 这正是「看到另一只宠物」的根因

**AC3 · 不要求登录**
**Given** 同一个链接在浏览器里无需登录即可看完整 Diary
**When** 未登录用户在 App 内点开
**Then** 不要求登录、直接看到访客只读态（否则会把用户推回浏览器）`[L2]`

**AC4 · 🛡 作者本人不落只读态**
**Given** 作者也会点到自己分享出去的链接（比如从自己的聊天记录里）
**When** 作者本人打开
**Then** 落**自己的档案页**、保留编辑 / 分享 / 健康记录 / 身份证等**全部管理入口**（AD-2 Rule 3）`[L1]`
**And** 🛡 判定必须走 Diary 页的**单一状态判定入口**（AD-15），**不得**在路由层或页面其它位置另起判断 `[L0]`
**And** ⚠️ 未登录时**不得**为了做这个判定去拉取自己的档案 —— 没有令牌，请求会 401 并弹出全局强登录窗

## Dev Notes

### 🔴 现状：token 被直接丢弃

深链映射目前把 `tailtopia://card/{token}` 整个映射成 `/profile`（Diary Tab 根）——
**token 连解析都没解析**。于是：
- 未登录的人点开 → 看到给游客做的**示例成长本**（一只叫 Mochi 的示例猫）
- 已登录有宠的人点开 → 看到**自己家的宠物**

两种都不是「被分享的那只」。这就是本 story 要修的那一件事。

### 前置已就绪（Story 2.3 建立）

- 路由 `/pet/:token` 已存在，页面复用 `GrowthArchivePage`，由第五个状态分支 `visitor` 承接
- `/pet` **不落在任何受控前缀下**，天然对未登录开放（已有 L0 用例钉住，且钉住了「不得挪到 `/profile/` 之下」）
- 访客读取面（档案 / 统计 / 时间线 / 日历 / 某天详情）全部就绪

**所以本 story 的代码量很小** —— 主要是映射那一行 + 作者识别 + 测试。

### 🛡 作者识别为什么放在状态判定入口

AD-15 的硬约束：Diary 页的状态判定**只有一处**，源码注释写着「本页任何其它位置不得再判用户状态」。
把「这个 token 是不是我自己的」放到路由层判，等于开了第二处判定 ——
两处迟早各改各的，而分叉的表现是**作者看到只读态**（丢管理入口）或**访客看到管理入口**（后者严重得多）。

判据：已登录 **且** 自己的档案 `cardToken` == 深链 token。

⚠️ **未登录时绝不拉档案**：Story 2.3 已经踩过同一件事的边 —— 没有令牌的请求会 401，
而 401 会触发全局强登录窗，正好把「不要求登录」这条 AC 打破。

### 架构约束

- **AD-2 Rule 2**：访客视图对未登录开放；已登录非作者与未登录访客看到**同一套**只读视图
- **AD-2 Rule 3**：**作者本人**经该链接进入 → 落自己的档案页、保留全部管理入口
- **AD-2 Rule 6**：带 token 的独立路由，不得复用作者态档案路由
- **AD-15**（V1.1.2）：Diary 页状态判定单一入口

### Completion Notes List

**1. 根因确认：token 从头到尾没被解析过**

深链映射原先直接 `return '/profile'` —— 不是「解析了但用错」，是**根本没解析**。
所以未登录的人看到给游客做的示例成长本，已登录有宠的人看到自己家的宠物。
修法就是把 token 从 path 取出来带到 `/pet/{token}`。

⚠️ token **只从 path 取，不接受 query**（`tailtopia://card?token=abc` 退回 Diary 根）——
少一个可被构造的入口。已写成用例。

**2. 作者识别放在单一状态判定入口，不在路由层**

判据是「已登录 **且** 自己的档案 `cardToken` == 深链 token」。
放路由层判等于开第二处状态判定（AD-15 明令禁止），两处迟早分叉，
而分叉的两个方向里 **「访客拿到管理入口」是越权**，比「作者丢管理入口」严重得多。

**3. 🛡 未登录时不去拉自己的档案**

为做作者比对而无条件拉档案，会在未登录时打出 401 → 触发全局强登录窗，
**正好打破「点分享链接不要求登录」这条 AC**（而这条的意义是：不弹登录，用户才不会被推回浏览器）。
已加一条计数器用例钉住「未登录路径下档案拉取次数为 0」。

**4. 档案未加载完时按访客处理，不加 loading 拦截**

加载完会自然重建切换。反过来先拦一道 loading，会让**所有**访客白等一次网络往返 ——
而访客里绝大多数不是作者。

**5. 既有断言已更新并说明原因**

`diary_gating_and_landing_test.dart` 里有一条钉着旧落点 `/profile` 的用例。
改成新落点，并在注释里写明**为什么变**（旧落点正是缺陷本身），
同时保留这条一直在守的东西：**落点对游客可达、不弹登录窗**。

⚠️ 两处测试写法上的坑（已在用例里注明）：
- 访客页加载中是**无限转圈动画**，`pumpAndSettle` 永远等不到静止 → 改用定量 pump
- Tab 壳层会把上一个 Diary 页留在树里，所以**不能**断言「示例页不存在」——
  那条会因壳层实现而红，与要守的东西无关。改为断言访客视图确实在最上面

**6. Epic 2 至此闭环**：投影层（2.1）→ 日历与某天详情（2.2）→ 页面渲染（2.3）→ 落点分流（2.4）。
剩余待办见下方「遗留」。

**7. 📐 遗留（需产品/真机确认）**
- 访客态**日历屏**、**某天详情屏**、**私密条目提示样式**三处**无 UI 稿**（Story 2.3 已标注），
  按「复用作者态做减法」实现，建议一次 L2 视觉验收时一并过目
- 深链的**真机验证**（冷启动 / 热启动两条路）属 L2，需真机点链接
