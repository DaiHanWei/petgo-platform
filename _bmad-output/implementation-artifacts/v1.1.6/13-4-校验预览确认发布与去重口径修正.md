# Story 13.4: 校验预览、确认发布与去重口径修正

Status: ready-for-dev

## Story

As a 运营，
I want 批量提交前能逐行看到校验结果、只发通过的行，
so that 50 行里错 3 行不会变成 3 条线上真帖。

---

> 🔴 **前置：13-1 / 13-2 / 13-3**。本 story = AB-3K 的 Step 3 + 去重口径修正。
>
> **现状最严重的一点**（已实读确认）：**没有校验预览、没有确认入库，提交即上线** ——
> 50 行错 3 行就是 3 条线上真帖，只能逐条去找、逐条下架。

---

## Acceptance Criteria

### AC1 — 逐行校验预览（L1）

**Then** 逐行展示：行号 / 正文摘要 / 图片缩略图 / 发布账号 / 内容类型 / 关联物种 / 计划发布时间 / 校验结果 `[L1]`

### AC2 — 🔴 只发通过的行，失败行不阻塞整批（L1）

**Then** 🛡 校验失败的行**不阻塞整批**，通过的行可直接确认发布 `[L1]`
**And** 失败行以**草稿态保留在该批次内，可修改后再次提交** `[L1]`
**And** 确认发布后，按批次级 / 行级的计划发布时间决定**立即发布**还是**转入排期**（13-5）`[L1]`

### AC3 — 异常场景处理（L1）

**Then** `[L1]`：

| 场景 | 处理 |
|---|---|
| 图片文件名在本批素材中找不到 | 该行失败，注明缺失的文件名；其余行不受影响 |
| 图片格式 / 大小不符 | 13-2 上传阶段即拦截，不进入录入 |
| 同批图片文件名重复 | 13-2 上传阶段即拦截 |
| 单批素材超 200 张 / 500MB | 13-2 **选择文件时**即拦截 |
| 发布账号不在身份池内 / 已禁用 / 已移出 | 该行失败，注明行号与原因 |
| 发布账号**留空** | 🔴 **正常放行**，继承批次默认（**覆盖** V1.1.0 原「留空报错」） |
| 内容类型 / 关联物种值不在枚举内 | 该行失败，注明合法取值 |
| 内容类型填了 `GROWTH_MOMENT` | 该行失败，注明批量不支持、请走 12-2 单条发布（模板下拉已不含该值，此处拦手工改写模板的情形） |
| 与已发布内容重复（去重命中） | 🔴 **标记为提示，不静默跳过**（见 AC4） |
| 正文与图片皆空 | 该行失败（沿用 App 端的最低内容门槛） |

### AC4 — 🔴 去重口径三处修正（L1）

**Then** 🔴 去重维度**加入作者** —— 同一文案不同账号各自独立 `[L1]`
**And** 🔴 命中**不再静默跳过**，改为在预览里标记提示、由运营决定是否仍要发布 `[L1]`
**And** 🔴 **内容被删除时清理对应的指纹记录** `[L1]`

> 三处现状均已实读确认：`seed_content_hashes` 以 **`content_hash` 单列为主键**
> （表里有 `author_id` 列，但**不参与键**），命中即静默跳过、界面只显示一个跳过条数，
> 且**没有任何清理逻辑**。
>
> 两个实际后果：
> ① 同一文案想用两个不同账号各发一遍（内容运营常规操作，引入运营真实账号后会更频繁），
>    **第二次会被吞掉**；
> ② 已发布内容被删除后指纹记录不清理，**同样的文案永久无法重发**。
>
> ⚠️ 加作者维度 = **改这张表的主键**。既有行的 `content_hash` 本就唯一，
> 所以 `(content_hash, author_id)` 也必然唯一，改键安全、无需去重清理。
> 🔴 迁移用**时间戳号**（E6）。
>
> ⚠️ 「删除时清理」要挂在**所有**删除路径上：作者自删、运营下架、账号注销级联。
> 漏一条就是那条路径删掉的内容对应的文案永久无法重发。

### AC5 — 批次审计（L1）

**Then** 每个批次记录操作人、时间、以及批次内容清单（**含各行最终生成的内容 ID**）`[L1]`

> 内容清单同时是后续「整批撤回」的数据基础（本版本不做，OQ-22）。

### AC6 — 内容类型范围（L0）

**Then** 放开为 `DAILY` + `KNOWLEDGE` `[L0]`
**And** 🛡 `GROWTH_MOMENT` **仍不纳入批量** `[L0]`

> 已实读确认现状硬编码为单一类型（`new ContentPostCreateRequest(ContentType.DAILY, ...)`）。
> 这是 V1.1.0 AB-1.1-02 的**原有要求**，属**实现偏差而非需求变更** —— 本 story 只是把它恢复。
>
> 🔴 PRD 写的 `MOMENT` 在代码里不存在，就是 `DAILY`。
