# Story 1.3: 失效页印尼化 + 新增加载失败页

Status: review

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 收到分享链接的人，
I want 链接失效或服务器出错时看到一个看得懂的页面，
so that 我知道发生了什么、而不是对着一片白屏或一段英文发愣。

---

> **两件事，性质完全不同。**
> **① 失效页**：模板**已存在**（`card_gone.html`），是**改写**——全篇英文改印尼语 + 换成剪贴簿视觉。
> **② 加载失败页**：模板**根本不存在**，是**新增**——而且它不只是一个模板文件，
> 还需要一个**把服务端异常接住并渲染它**的落点（当前异常直接落到 Spring 的默认错误页）。
>
> ⚠️ **两页的语义必须区分清楚**（视觉稿原话）：**E3 是终局**（档案没了，只能去别处逛）、
> **E4 是暂时**（网络问题，可重试）。所以 E3 的按钮是「去逛别的」，E4 是「Coba lagi」，
> **两者不可共用一套**。
>
> ✅ **与 Story 1-2 无文件冲突**：1-2 改的是 `card.html`，本条改 `card_gone.html` + 新增模板。可并行。

## Acceptance Criteria

### AC1 — 失效页印尼化 + 剪贴簿视觉（L2）

**Given** 失效页当前是全篇英文，而正常页是全篇印尼语（同一条链接换个状态就换种语言）
**When** 按 E3 屏重做失效页
**Then** 全篇改为印尼语，视觉与主页面同一套 `[L2]`

> **现状实读**：`card_gone.html` 25 行，`lang="en"`，文案 `This card is no longer available` /
> `The pet card you're looking for can't be found.` / `Discover pets on TailTopia`，
> 主色 `#C8874A`（橙棕）—— 与正常页的绿、与品牌紫**三套色**互不相干。
>
> **E3 定稿文案**（照抄视觉稿）：
> - 标题：`Halaman ini` / `sudah tidak ada`（两行）
> - 副文：`Paspor hewan ini sudah dihapus atau tautannya tidak berlaku lagi.`
> - 按钮：`Jelajahi hewan lain`
>
> **视觉**：剪贴簿语汇 —— **照片被撕走、只剩四个相角和一小片胶带残痕**
> （`.e-corners` 146×146 容器 + 四个 34×34 的 L 形相角 `#CFC6DF` + 顶部 `.e-residue` 胶带残痕）。
> 这是相册里最直白的「这里原本有东西，现在没了」。
> 🛡 `lang` 属性要从 `en` 改成 `id`（页面语言标记与内容一致，否则浏览器可能误判并提示翻译）。

### AC2 — 两条链路共用，须都验（L1）

**And** 🛡 **该模板被「宠物名片」与「里程碑分享」两条链路共用**，验收须**两条链路都走一遍**确认都已生效 `[L1]`

> **已实读确认共用**：`CardPageController:348` 与 `MilestoneSharePageController:150` 都 `return "card_gone"`。
>
> ⚠️ **一个 story 没提、但必须知道的口径冲突**：
> **里程碑分享页是双语的**（`MilestoneSharePageController:64` `boolean isId = "id".equals(share.getLocale())`，
> 按**分享者分享时快照的语言**输出 `TONGGAK TERBUKA!` / `MILESTONE UNLOCKED!` 两套文案），
> 而失效页本条要改成**纯印尼语**。
> **这不是矛盾，是无解**：失效意味着 token 查不到记录，**根本拿不到 `locale`**，无从按语言渲染。
> 故失效页**只能单语**，取印尼语（主力市场）。
> 🛡 **不要为此去给失效页加语言分支** —— 没有数据可依；也不要用 `Accept-Language`
> （那会让同一条失效链接在不同人手机上显示不同语言，与「统一响应」的防枚举口径相冲）。
> 结论写进模板注释，免得后来者以为是漏做。

### AC3 — 新增加载失败页（L1）

**Given** 后端模板目录下不存在任何「加载失败」模板，服务异常时访客看到浏览器默认报错白屏
**When** 按 E4 屏新增该模板
**Then** 服务端异常时渲染该页面而非白屏，页面含重试按钮 `[L1]`
**And** 点击重试重新请求当前链接 `[L2]`

> **现状实读**：`templates/` 下只有 `admin/` · `card.html` · `card_gone.html` · `milestone_share.html`
> —— **确实没有任何错误页模板**，也**没有自定义 `ErrorController`**
> （`PingErrorController` 名字像但不是，它是 dev profile 的诊断端点）。
> 所以异常时走 Spring Boot 默认的 Whitelabel 错误页。story 说的「白屏」基本准确。
>
> **E4 定稿文案**：标题 `Gagal memuat` / `halaman`（两行）· 副文
> `Periksa koneksi internetmu, lalu coba lagi.` · 按钮 `Coba lagi`（带一个回环箭头图标）
> **视觉**：**「还没显影的空白拍立得」**（`.e-blank` 186px 白框 + 166px 灰底相纸 + 断线 WiFi 图标）
> 配手写 `belum muncul…`（还没出来）。

### AC4 — 🔴 加载失败页的落点必须选对（L0 / L1）

**Given** 「服务端异常」可能发生在控制器内，也可能发生在控制器之外（模板渲染、过滤器、无路由 404）
**When** 决定把这个页面挂在哪里
**Then** 🛡 **必须能接住控制器之外的异常**，否则「服务器出错」最常见的几种情形恰好都漏掉 `[L1]`
**And** 🛡 **不得影响 API 的错误响应** —— API 异常必须继续返回 RFC 9457 ProblemDetail **JSON**，
不能变成一张 HTML 页 `[L1]`
**And** 🛡 **不得影响运营后台**（`templates/admin/` 那一整套）的错误页观感 `[L1]`

> **三种可选落点，各自的代价**：
>
> | 方案 | 做法 | 问题 |
> |---|---|---|
> | A | 直接加 `templates/error.html` | Spring Boot 会**全局**采用它 —— 运营后台出错也会看到宠物剪贴簿页 ❌ |
> | B | 在两个控制器里 `try-catch` | **接不住控制器之外的异常**（模板渲染失败、过滤器异常），而那恰是「服务器出错」的常见形态 ❌ |
> | C | 自定义 `ErrorController`，**按请求路径分流** | 稍复杂，但落点正确 ✅ |
>
> **取 C**：`/p/**` 与 `/m/**` 且客户端要 HTML → 渲染本页；其余一律**保持现有行为不变**。
> ⚠️ 实现时注意：API 异常先被 `GlobalExceptionHandler` 的 `@ExceptionHandler` 接走、
> **根本不会到 `/error`**，所以 C 天然不影响 API 的正常错误路径；
> 但**未被覆盖的**（如无路由 404、过滤器抛错）会到 `/error`，那时必须按 `Accept` 做内容协商。

### AC5 — 防枚举口径不变（L1）

**Given** 失效口径须防枚举
**When** 访问的 token 不存在 / 档案已删除 / 作者账号已注销
**Then** 🛡 **三种情况返回同一个失效页**，不得用不同文案或状态码区分（沿用现有防枚举做法）`[L1]`

> **这是既有行为，本条是回归**：`CardPageController` 已对「token 不存在」与「账号注销」
> 走同一个 `gone()`（同视图 + 同 404）。`CardPageControllerTest.deletedAccountRendersSameGonePageNoEnumerationLeak`
> 已经在守这条。
> ⚠️ **改文案时不要"顺手"加原因说明**（比如「该账号已注销」）—— 那正是防枚举要防的。
> E3 的副文 `sudah dihapus atau tautannya tidak berlaku lagi`（已删除**或**链接失效）
> 用「或」把两种原因糊在一起，是刻意的。

### Debug Log References

实现期五次红灯，其中两次改变了方案：

1. **Spring Boot 4 挪了包名**：`AbstractErrorController` 与 `ErrorAttributes` 从
   `boot.autoconfigure.web.servlet.error` / `boot.web.servlet.error` 搬到了
   `boot.webmvc.autoconfigure.error` / `boot.webmvc.error`（`ErrorAttributeOptions` 仍在 `boot.web.error`）。

2. 🔴 **方案 C 只做对了一半 —— 光有 `ErrorController` 根本不生效。**
   本项目的 `GlobalExceptionHandler` 有 `@ExceptionHandler(Exception.class)` **兜住了所有异常**，
   请求压根到不了容器的 `/error` 出口。也就是说：页面做了，但 H5 出错时访客看到的仍是一坨 JSON。
   **改法**：在 `GlobalExceptionHandler` 的两个兜底分支里做内容协商 —— H5 路径 + 要 HTML → 返回视图，
   否则原样返回 ProblemDetail。`H5ErrorController` 保留，两者互补：
   前者接控制器抛出的，后者接过滤器层与容器级的。

3. ⚠️ **语义修正：无路由 404 不该给「重试」按钮。**
   一开始把 `NoResourceFoundException` 也导向了加载失败页，但那是**终局**（链接错了，重试无用），
   按 E3/E4 的划分应走失效页。改成：404 → `card_gone`、5xx → `card_error`。

4. **测试用错了触发方式**：原本用「路径不存在」冒充 5xx，那验的其实是 404。
   新增 `H5BoomTestController`（仅 `src/test`）制造真正的 500。
   踩到两个坑：路径必须**两段**（一段会与 `/p/{cardToken}` 撞 Ambiguous mapping）；
   且**不能**再包一层 `@TestConfiguration` + `@Bean`（会被注册两次，同样 Ambiguous）。

5. **CSS 注释里的中文会外泄**（Story 1.2 的老坑复现）：`<style>` 内的 `/* */` 不吃
   Thymeleaf 解析器级注释那套，只能删掉或改英文。

**一个范围外的发现，建议交产品判断**
`AccountQueryService.isActive()` 只看**注销**（`deletedAt`），**不看停用**（`status=DEACTIVATED`）。

本 story 只管「失效页长什么样」、不管「什么情况算失效」，故未改动 —— 但这条口径值得产品明确：
封号是否应连带让其分享页失效？
