# Story 11.5: 标签图标上传与尺寸规范

Status: review

## Story

As a 运营，
I want 在后台**上传**标签图标，而不是往一个文本框里填 emoji，
so that 标签的视觉由设计决定，而不是由「运营手头能打出哪个 emoji」决定。

---

> 🔴 **这是实现与 PRD 不符，不是新需求**。FR-74 原文：「每个标签**自定义上传一张小图标** + 一句说明文案」；
> FR-75 原文：「每个标签**自定义上传图标/样式** + 一句说明文案」。
> 而现有实现把 `icon` 做成了 `varchar(255)` 的**纯文本输入框** —— 运营只能填 emoji。
> 2026-08-25 实机比对时发现（同一轮还发现装饰标签胶囊的视觉也与 UI 稿不符）。
>
> ✅ **基建已有**：Story 12-2 的 `AdminSeedImageService` 已有「格式白名单 + 从字节量真实宽高 +
> 大小上限 + HEIC 双重拒绝 + `putPublicObject` 取公开 URL」整套，**照它做，别从零起**。

---

## Acceptance Criteria

### AC1 — `icon` 的语义改为图片 URL（L1）

**Then** 两个标签模块（用户标签 AB-12A / 内容装饰标签 AB-10C）的 `icon` 一律存**公开图片 URL** `[L1]`
**And** 🛡 **不新增列** —— 沿用既有 `icon` 列（产品 2026-08-25 明确：「icon 就应该图片，而不是文本」）`[L0]`
**And** 🛡 列宽 `varchar(255)` 足够（公开 URL 约 100~120 字符），**不需要迁移改列** `[L0]`

> ⚠️ **存量 emoji 值的处置**：本版本尚未发版，生产不可能有真实标签数据；
> 本地/测试库里有 emoji 存量。App 侧做一层**过渡兼容**（见 AC5），
> 🔴 那是**过渡**不是双模式 —— 待确认无非 URL 图标后应移除。

### AC2 — 上传与校验（L1）

**Then** 后台建/改标签时可**上传图标文件** `[L1]`
**And** 校验逐条（每条都要给出**能照着改**的报错，不许笼统说「格式不对」）`[L1]`：

| 规则 | 取值 | 为什么 |
|---|---|---|
| 格式白名单 | `image/png` / `image/webp` | 🔴 **拒绝 JPEG**，理由要写进报错：图标叠在**橙红渐变胶囊**上，JPEG 不支持透明底 ⇒ 会出现一个白方块 |
| 最小尺寸 | **72×72** | 渲染尺寸约 9~11 逻辑像素，3 倍屏需 33px；给到 72 留余量 |
| 最大尺寸 | 1024×1024 | 再大只是浪费流量，图标不需要 |
| 长宽比 | **1:1**（容差 ±5%） | 非方图在方形槽位里会变形或留边 |
| 文件大小 | ≤ 512 KB | 🛡 **不要沿用种子图片的 10MB** —— 那是给内容照片定的，图标用不到 |

**And** 🛡 尺寸从**字节**量（沿用 12-2 的做法），不是传上去再回读 `[L0]`

### AC3 — 🔴 后台界面必须写明尺寸规范（L1）

**Then** 上传控件旁**常驻**说明文案 `[L1]`：格式、最小尺寸、长宽比、大小上限、**为什么要透明底**
**And** 展示**当前图标的预览** `[L1]`
**And** 🛡 说明文案用 `data-notice` 标记，测试按标记断言 `[L0]`

> 🔴 产品明确要求「给定上传图标的尺寸大小数据/说明在后台」。
> ⚠️ 不写的后果不是运营填错一次，而是**每换一个人就问一遍**，且传了不合规的图只会看到一句报错，
> 不知道该改成多少。

### AC4 — 「删除不再用的标签」= 既有的下架，不新增彻底删除（L0）

**Then** ✅ **「下架 / 恢复」已存在**（`retire` 开关），它就是「删除不再用的标签」的答案 —— 本 story **不动它** `[L0]`
**And** 🛡 **不做彻底删除**（产品 2026-08-25 决定）`[L0]`

> 🔴 理由记在这里免得后人当成漏项：标签是**审计对象** ——
> 「这条内容当时挂的是哪个标签」在争议时是唯一依据。彻底删除会把这段历史一起删掉，
> 而「下架」已经能达到运营的目的（列表里不再出现、不能再分配），代价却小得多。
> ⚠️ 所以后台**不该有**删除按钮：给了它就会有人在「建错了」之外的场合按下去。

### AC5 — App 侧渲染图片（L1）

**Then** 装饰标签胶囊与用户标签行的图标一律按**图片**渲染 `[L1]`
**And** ⚠️ **过渡兼容**：值不是 `http(s)` 开头时按**文本**渲染（存量 emoji）`[L1]`
**And** 🛡 图片加载失败 / 值为空 → **不占位、不显示碎图**，只显示名称 `[L1]`

> 🔴 最后一条要紧：图标挂在 OSS 上，网络差时它会晚到甚至不到。
> 那时胶囊必须仍然可读（名称在），而不是留一个碎图框。

### AC6 — 本 story 不做的（L0）

**Then** 🛡 `[L0]`：不做图标裁切/编辑器（运营给什么用什么）、不做图标库/复用选择器、
不改标签的其余字段与分配流程、不动「下架」既有行为

### Completion Notes List

**1. 一处不得不做的小重构**

量宽高那个函数原先是 `AdminSeedImageService` 的**包内静态方法**。让 `admin.tagicon` 去依赖
`admin.seed` 只为拿一个工具函数、方向不对；放宽成 `public` 又等于把内部实现细节写进那个服务的对外 API。
提成了 `ImageBytesMeasurer`。

⚠️ 顺带查清一件事：注释说它与 `ImageSizeBackfillService#measure`「同源」，**不是重复代码** ——
一个读**远程 URL**（带超时、走网络），一个读**已在手里的字节**。已在新类注释里写明「别去合并它们」。

**2. 三条与种子图片上传**刻意相反**的规则**

| | 种子内容图片 | 标签图标 |
|---|---|---|
| 量不出尺寸 | 放过（Feed 有占位兜底） | 🔴 **拦住** |
| 大小上限 | 10 MB | 512 KB |
| JPEG | 收 | 🔴 **拒** |

🔴「量不出来就拦住」要紧：尺寸与比例校验**是本 story 的核心**，量不出来等于没校验。
反证时改成「放过」，那条断言立刻红。

🔴 **拒 JPEG 的理由写进了报错文案**：图标叠在橙红渐变胶囊上，JPEG 存不了透明 ⇒ 会是白方块。
只说「格式不支持」，运营会换张 JPG 再试一次。反证「合并进格式不支持」→ 两条断言红。

**3. 🔴 `null` 图标 = 保留原图标（很容易埋成清空）**

编辑标签时 file input 为空是**常态**（运营只改一个错别字）。服务层若直接把 null 写进去，
那次编辑会把图标**清空** —— 而后台界面上看不出来，只有 App 上图标消失才会被发现。
两个服务都改了并单独测，反证过。

**4. 🔴 顺手修了一个真问题：上传失败给运营 500 白页**

控制器只 `catch (AppException)`，而 OSS 抛的不是 —— 凭证缺失 / 对象存储不可用 / 网络超时
**都会 500**。校验错误已经给了人话，唯独「传不上去」给 500 是最难排查的一种（运营只会说"存不了"）。
现在是一句可读报错，且 🛡 **不外泄桶名 / endpoint / 签名信息**，只在服务端日志里记异常类名。

**5. 🔴 连带影响：建标签变成了依赖外部服务**

图标改成必传之后，「建标签」这条原本纯 L1 的路径在**无凭证的本机变成了 L2** ——
连「重复标签码要被拦下」这种与上传无关的规则都验不了（两条既有集成测试因此红）。

处置：`AliyunOssClient.putPublicObject` 在**无凭证时走打桩**（直接返回 URL、不打网络）。
沿用 Gemini 的 `mode=stub` 先例。
🔴 **判据是「凭证是否配了」而不是某个开关** —— 生产必然配了凭证 ⇒ 必然走真实上传，
不存在「忘了关 stub 导致线上图没真的传上去」这种事故。

**6. ⚠️ 顺带订正了两个角位的边距（同一轮比对发现）**

UI 稿里 `.pin-corner` 是 **9**、`.deco-on-card` 是 **10** —— **两个本来就不一样**。
而原实现两处都写了 8。改完连带四条既有位置断言要更新（`content_tag_test` / `feed_carousel_test` /
`pinned_slot_test` / `promo_card_test`），都按规格改并在注释里注明「不是笔误」。

**7. i18n：只加 zh_CN + en，不加 id**

⚠️ 我一开始写了三语，是**做多了**：后台的语言集是 **zh_CN / en**（`AdminLocaleConfig` 注释明写
「App 为 id/en，后台为 zh-CN/en」），切换入口也只认这两个。
`messages_id` 里只有 244 个键（举报/审核那一块），`admin.seed.*` 一条都没有。
🔴 已删掉印尼语那 11 条 —— 留着永远不会被读到，还会让人以为后台支持印尼语。
（产品随后提出「后台加一门印尼语」，那是独立需求，规模是 870 条键 + 回退策略 + 切换器，
另开 story，见 §待办。）

**8. App 侧新组件 `TagIcon`**

URL → 图片；存量 emoji → 文本（⚠️ 标为**过渡兼容不是双模式**，注释里写了该删的条件）；
🛡 加载中 / 失败 / 空值 → **收缩为零不占位**，让标签只剩名称，而不是留碎图框。
（图标挂在对象存储上，网络差时会晚到甚至不到。）

**9. 三次反证**

| 反证 | 变红 |
|---|---|
| JPEG 合并进「格式不支持」 | `jpegIsRejectedWithTheTransparencyReason` + `jpegByFilenameIsAlsoRejected` |

| 编辑时直接写 null 图标 | `nullIconKeepsTheExistingOne`（`不该被清空`） |

**10. 零迁移** —— `icon` 沿用既有 `varchar(255)`（公开 URL 约 100~120 字符）。flyway-guard 无关。

**11. 留 L2 的**
- **真实 OSS 上传**（本地走打桩）：需真实凭证，确认图标真落公开桶且 App 能取到
- 后台上传控件与尺寸说明的**视觉验收**
- 真机上看图标从 emoji 换成图片后的观感（尤其 9px 的装饰标签图标是否还看得清）
