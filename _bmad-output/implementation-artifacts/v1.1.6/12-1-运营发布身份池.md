# Story 12.1: 运营发布身份池

Status: ready-for-dev

## Story

As a 运营，
I want 后台的「发布账号」除了虚拟号，还能选公司那几个人格化 IP 真实账号，
so that 那类内容（有宠物档案、有粉丝、主页不空）真的发得出来。

---

> 🔴 **本 story 必须最先做**：12-2 与 Epic 13 的「发布账号」选择器数据源就是它。
>
> **背景**：虚拟账号没有宠物档案（发不了成长日历）、没有粉丝积累、主页是空的 ——
> 替代不了人格化 IP 号。而当前后台的发布账号只接受虚拟账号。

---

## Acceptance Criteria

### AC1 — 身份池容纳两类账号（L1）

**Then** 「虚拟账号管理」页升格为「运营发布身份」管理，分两区：【虚拟账号】【运营真实账号】`[L1]`
**And** 🛡 虚拟账号侧的既有能力**全部不变**（创建 / 列表 / 启停 / 导出）`[L1]`

### AC2 — 🛡 不新增账号类型（L0）

**Then** 🛡 运营真实账号的 `account_type` **保持"真实用户"不变** `[L0]`
**And** 只加一张授权关联表（用户 ID + 授权说明 + 纳入人 + 纳入时间 + 状态）`[L0]`
**And** 🔴 唯一需要放开的是批量发布服务里那句作者类型硬断言 `[L1]`

> 已实读确认现状：`AdminSeedBatchService` 里有
> `if (author.getAccountType() != AccountType.VIRTUAL) { ... }`。
> 改为"在身份池内即可"，**不要**去改账号类型 —— 一旦真实号被改成别的类型，
> 它在 App 内的一切行为（登录、发帖、被查看）都会走进未被验证的分支。

### AC3 — 纳入与移除（L1）

**Then** 纳入：按用户 ID / 昵称搜索既有真实用户 → 填**授权说明（必填）** → 确认 `[L1]`
**And** 🛡 **不做 App 端验证**（不要求员工扫码或输验证码）`[L0]`（A-6：风险边界是"内部人冒充内部人"，审计追责比技术强绑定划算一个量级）
**And** 移除后该账号**不可再被选为新内容的发布者**；历史内容作者归属与内容本身**完全不受影响** `[L1]`
**And** 🛡 **移出 ≠ 封号** —— 只收回"后台可代其发布"这一项，该账号在 App 内的一切行为不受影响 `[L1]`

### AC4 — 🔴 移出前必须提示待发布排期数（L1）

**Then** 🛡 移出确认弹窗须显示「该账号当前有 **N 条**待发布排期，移出后这些内容到点将发布失败」`[L1]`
**And** 提供跳转链接直达按该账号过滤的排期列表 `[L1]`
**And** 🛡 **不阻止移出** —— 运营可能正是要停掉这个号 `[L1]`
**And** 🛡 排期**不自动取消、不自动转草稿** —— 保持"到点标记失败并注明原因" `[L1]`
**And** ⚠️ 虚拟账号的**「禁用」操作同样适用本提示** `[L1]`

> 不做这条的后果很具体：那 N 条会在未来若干天里**陆续、分散地失败**，运营要等到失败才发现，
> 而届时内容的时间窗（如配合某活动）多半已经错过。
> 移出是个瞬间的、有明确操作人的动作，是成本最低的提示时机。
>
> **为什么不自动改状态**：自动取消是替运营做决定；失败记录带原因比静默转草稿更可追溯。
>
> ⚠️ 虚拟账号禁用这条 V1.1.0 原文没有（当时还没有定时发布能力），属本次引入排期后的连带影响。

### AC5 — 🔴 独立权限码，与虚拟账号管理解耦（L0）

**Then** 🛡 新增独立权限码 `seed.publish_as_real`，控制两件事 `[L0]`：
① 运营真实账号的纳入 / 移除；② **以运营真实账号身份发布内容**（12-2 单条 / 13-x 批量 / 13-5 定时，三处）
**And** 🛡 与既有 `virtual_account.manage` / `virtual_account.view` **完全解耦** `[L0]`
**And** **本版本仅分配给超级管理员**，不下放（OQ-24）`[L0]`
**And** 后台账号权限勾选清单同步新增该项 `[L1]`

> **能管虚拟账号 ≠ 能以真人身份发言。** 权限码独立存在的意义是后续如需下放，
> 只改权限配置、不改代码。
> ⚠️ 权限码一旦落地即**冻结**（改名会切断已授予关系），只有显示名可改。

### AC6 — 🔴 选错身份的防呆（三处发布入口统一）（L1）

**Then** 🛡 所有「发布账号」选择器统一遵守 `[L1]`：
- **分组展示，不平铺**：【虚拟账号】/【运营真实账号】
- 真实账号项带**显著视觉标记 + 后果说明**（建议：「⚠️ 真实账号 · 内容会出现在该账号个人主页并推送给其粉丝」）
- 🛡 **默认不预选任何账号**，强制显式选择
- 🛡 **仅当选中运营真实账号时**弹二次确认（虚拟账号不弹，避免拖慢常用路径）

> 以运营真实账号误发的后果**不可撤回** —— 内容会出现在那个真人的个人主页并推送给他的粉丝，
> 事后删除也已经推送过了。

### AC7 — 列表字段与审计（L1）

**Then** 列表：用户 ID / 昵称 / 头像 / 授权说明 / 纳入时间 / 纳入操作人 / 状态 / **经后台发布内容数** / **物种推导结果 + 来源** `[L1]`
**And** 🛡 **「经后台发布内容数」只统计经后台代发的内容** —— 该账号在 App 内自主发布的不计入 `[L1]`
**And** 纳入 / 移除记审计（操作人、时间、目标账号、授权说明）`[L1]`
**And** 🛡 **以运营真实账号发布的每条内容，记录实际操作的后台账号** `[L1]`

> 最后一条是与虚拟账号最大的差别：虚拟账号是平台身份，运营真实账号是**某个真人的账号**，
> 出事要能追到具体是谁操作的。
>
> 「物种推导结果 + 来源」是只读自查列：运营真实账号**没有**「账号物种定位」字段
> （那是虚拟账号补偿"无宠物档案"的专属字段），所以**未建档或养多物种的号推不出具体物种**。
> 本列的用途就是让运营提前知道哪些号属于这种情况，否则无从察觉。

### AC8 — 两个写入方的边界（L1）

**Then** 🛡 **后台不阻止持有人在 App 内删除后台代发的内容** —— 那是他自己的账号，系统去锁定反而越权 `[L1]`
**And** 但**后台的批次记录须能反映该条"已被删除"**，不可继续显示为在线 `[L1]`
**And** 🛡 持有人在 App 内自主发布的内容**不进后台批次/排期记录**，也不计入「经后台发布内容数」`[L1]`

> 运营真实账号有**两个写入方**（后台代发 / 持有人本人），这是"引入真实账号"这一决策的
> **固有代价，不是能设计掉的问题**。本条只把边界写明，使运营有预期。虚拟账号不存在此问题。

### AC9 — 不做的（L0）

**Then** 🛡 `[L0]`：
- **不支持员工私人账号** —— 身份池只接纳公司资产性质的 IP 号（A-7：一旦支持，技术上就再无法区分公司号与私人号，风险敞口无法收口）
- **不做 App 端绑定验证**（A-6）
- **运营真实账号的点赞 / 评论不在本条范围** —— 那仍归 AB-3F（未上线版本），本条只放开**发布**
