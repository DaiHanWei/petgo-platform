# V1.1.6 Epic 2「App 内访客只读视图」L2 视觉验收报告

- **日期**：2026-08-18
- **环境**：模拟器 `petgo_phone`（Android 16 / API 36.1）+ 本地后端（真 PostgreSQL / Redis）
- **范围**：Story 2.1 ~ 2.4（投影层 · 日历与某天详情 · 页面渲染 · 深链落点分流）
- **结论**：**发现 3 个缺陷，已全部修复并回归**；1 项因环境原因未能实机确认（有测试覆盖）

## 一、验收方法

L2 之前先做了一轮**接口层自查**——如果数据在接口就已经泄露，界面再对也没有意义。

造了一只「**别人的**宠物」（另一个账号名下的 Mochi），内容刻意铺满各种边界情况：

| 造的数据 | 期望 |
|---|---|
| 3 条公开日记 | 出现、可点开 |
| 1 条**私密**日记 | 出现、**点不开**、给提示 |
| 1 条**审核中**日记 | **不出现** |
| 1 条**已下架**日记 | **不出现** |
| 1 条**健康记录**（疫苗，带备注） | **整条不出现** |
| 1 条**问诊存档**（含症状摘要、AI 分级、医嘱） | **整条不出现** |

接口层自查结果：8 项敏感内容（症状摘要 / AI 分级 / 医嘱 / 疫苗名 / 医疗备注 / 审核中 / 已下架 / 健康字段名）**命中数全部为 0**。

## 三、发现并修复的缺陷

### 🔴 缺陷 1：统计条 Diary 恒显示 0

**现象**：页面上明明列着 4 条日记，统计条的「Diary」却是 **0**。

**根因**：后端把这个字段叫 `diaryCount`，客户端读的是 `happyMomentCount`。
而客户端解析时有个兜底默认值，**把这个不匹配悄悄吞掉了** ——
页面照常渲染、不报任何错、日志里什么都没有，只是那个数字永远是 0。

**为什么测试没抓到**：之前所有测试都直接构造统计对象，**没有一条真的走过 JSON 解析**，
整条契约缝隙没有任何东西守着。

**修复**：字段名统一为 `happyMomentCount`（与作者态一致——客户端两边用同一个模型解析）。
补了 4 条**契约测试**，直接拿后端真实响应的字段名做解析断言。

> 📌 产品口径叫「Diary」是**展示文案**的事，由客户端多语言决定，不该反过来改线上契约的字段名。

### 🔴 缺陷 2：从访客页按返回键直接**退出 App**

**现象**：从分享链接进来后按返回，直接回到了桌面/浏览器，人就这么走了。

**根因**：App 已在运行时收到深链，走的是「替换整个导航栈」。
在此之前名片深链落的是 Diary 标签页（一个 Tab 根），替换掉栈也无所谓 ——
用户落在带底部导航的主界面里，哪儿都去得了。
Story 2.4 之后落点变成了访客页，一个**在 Tab 之外**的顶层路由：
既没有底部导航，也没有返回栈。

**为什么严重**：对一个从 WhatsApp 点链接进来的人，这是一条**死路** ——
而这条链路的全部意义正是把人**引进** App。

**修复**：热启动深链改走与冷启动同一条逻辑（先落底座页、再把深链叠上去，这样可返回）。
冷启动那条路早就处理过这件事，热启动一直没跟上——因为在此之前它没有 Tab 外的落点。

### 🟡 缺陷 3：访客页缺返回箭头

**现象**：UI 稿 P1 的标题行左侧有返回箭头，实现里漏了。

**为什么要紧**：访客页在 Tab 之外、没有底部导航，这是**回到 App 的唯一可见出口**。

**修复**：补上。栈里没有上一页时（深链直达）回落到首页，而不是让返回变成空操作。

## 五、供产品判断的口径问题（非缺陷，未改）

**统计条说 5 条日记，列表只列出 4 条。**

原因：统计口径**包含审核中的帖子**（这是当初刻意定的，见既有注释），
而访客的时间线**不含**审核中条目。于是访客看到的数字会比实际能看到的条目多。

- 现有验收标准要求「统计三列与作者态数字一致」，所以**保持现状**。
- 若认为这会弱泄露「有内容正在审核」，需**先改验收标准再动实现**。
