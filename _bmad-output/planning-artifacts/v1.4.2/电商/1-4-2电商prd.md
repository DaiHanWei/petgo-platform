## 1. 版本目标

1. **减少下单阻力**——现有下单流程在多个环节阻挡用户的下单意愿（见 §2），本次围绕「从想买到付完款」重做主链路
2. **给运营基础促销能力**——优惠券（拉新首单 + 日常促销）与可配置的首页 banner
3. **资金闭环**——堵住三处「用户付了钱却可能收不回」的漏洞，这是在引入优惠券之前必须先修好的底线

**核心指标：** 下单转化漏斗为主指标，其余三项辅助。

- 下单转化漏斗：商品详情 → 进入结算 → 提交订单 → 支付成功，各步转化率
- 首单转化率：新注册用户 30 天内完成首单的比例
- 优惠券核销率：领取（或发放）→ 使用
- 支付成功率：出码 → 到账

### 2.1 下单链路的阻力点

以新用户从商品详情页到付完款为路径：

| # | 环节 | 现状 |

| D | 同机扫码 | ~~二维码面板不支持存图~~ **1.4.1 已上线「保存二维码」到相册**；但二维码有效期仍未与订单付款时限对齐（见 FR-128），存下的二维码在订单取消后可能仍能付款 |

| G | 信任信息 | 详情页只显示评价均分与条数，不显示评价内容（数据已拉取但未展示） |

### 2.2 资金闭环的三处漏洞

| # | 漏洞 | 后果 |
|---|---|---|
| ① | 支付回调丢失后没有兜底——主动查单能力已写好（`PaymentReconciliationService`），但没有任何调用方（无定时任务、无接口调用；App 支付面板的轮询只读本地状态，不向网关查） | 用户已付款，订单仍显示待支付，超时后被取消 |
| ② | 订单超时取消后才到账的款项：取消时支付记录已置为失败，之后到达的付款回调被**直接丢弃**，多数情况连日志都没有（2026-11-03 复核，比 09-30 所记「只记一条日志」更严重）；后台看到的仍是支付失败 | 钱停在网关，用户既没收到货也没拿回钱，客服和财务都查不到 |
| ③ | 异常订单（缺货）处置：整单取消只退 PawCoin 部分、不退现金部分（现金部分只写进审计记录）；部分取消某一行完全不退款 | 用户损失现金部分 |

> 2026-11-03 补充：
>
> - 订单付款时限为 **60 分钟**，写死在代码中，不可配置；向 GemPay 申请二维码时仍不传有效期（FR-128）。
> - 1.4.0 的「退款扣回 Tailrent 成长值」只接在 PawCoin 退款上；③ 的现金部分、问诊挂起的 QRIS 退款都没有扣回。Roadmap 已把这两条路径的扣回列为 1.4.2 修复项。③ 的现金部分已拍板：退为 PawCoin 时退回即扣，线下打款时在财务后台「标记已打款」时**自动扣回**（FR-134、AB-28，2026-11-04）；问诊挂起见 `1-4-2退款扣回成长值修复prd.md`。
> - 送礼线（1.4.0）已有「关单后到账自动退为 PawCoin」的处理，电商线没有。② 已拍板由客服处理（FR-134）：优先由客服重新下单继续履约，没有库存时才退款；不照搬送礼线的自动退款。

### 2.3 1.4.1 商家平台带来的新约束（2026-11-03 补）

- Toko 订单在下单时记录用户绑定的**归属门店**，门店返佣按每行「下单单价 − SKU 批发价」的差价计算，计算在商家平台仓库（`tailtopia-merchant`）完成，本仓库只提供数据
- **用券后返佣基数不变（2026-11-04 拍板）**：门店返佣仍按每行「下单单价 − SKU 批发价」计算，券的抵扣不分摊进单价、不降低返佣，券的成本由平台全额承担（FR-130）。部分取消、退货时返佣按被取消行的原口径扣回；整单取消（含已发货后取消）按各行原口径全额扣回（2026-11-05）；与 FR-134 ③ 的券分摊（只影响退给用户的金额）互不影响

## 3. 功能与需求

### 3.0 用户旅程与页面跳转（2026-11-04 新增）

本节把 FR-127 ~ FR-172 串成用户实际走的路径，作为研发与设计的总览；各步骤的规则以对应 FR 为准。各步骤均为已拍板规则或线上现状（2026-11-04 核 1.4.1 代码）。

#### 页面清单

| 页面 | 从哪进 | 能去哪 |
|---|---|---|
| Toko 首页 | 底部导航 | 商品详情、搜索页、banner 目标、购物车 |
| 搜索页 | 首页吸顶行放大镜 | 商品详情 |
| 商品详情 | 首页 / 搜索 / banner / 订单详情商品行 | 规格弹层、购物车、结算页（立即购买）、送达地区选择 |
| 购物车 | 首页与详情页的购物车图标 | 商品详情、结算页 |
| 结算页 | 购物车「去结算」/ 详情「立即购买」 | 地址选择与新增（页内）、支付面板 |
| 支付面板 | 结算页提交 / 订单「去支付」 | 支付成功 → 订单详情 |
| 订单列表 | 「订单 → 电商订单」 | 订单详情、我的券 |
| 订单详情 | 订单列表 / 支付成功 | 支付面板（待付款）、商品详情、选择退款方式、联系客服（配送异常时） |
| 我的券 | 订单列表页顶部入口 | — |
| 地址簿 | 「我的」→ 地址管理 | 新增 / 编辑地址 |

#### 旅程 A：加入购物车后下单

1. 从首页 / 搜索 / banner 进入**商品详情**，看到价格、可领的券、送达地区、「运费 Rp X 起」、免运进度（FR-127、FR-133）
2. 点「加入购物车」→ 弹出规格弹层，选 SKU 与数量 → 确认后提示「已加入购物车」，**留在详情页**，购物车图标角标更新
   - 未登录：先登录，登录后回到详情页
   - SKU 缺包裹重量或体积：不可加入，按钮显示「暂不可售」（FR-172）
3. 进入**购物车**：勾选商品、改数量；底部显示免运进度与预估应付（规则见 FR-133 购物车）
4. 点「去结算」→ 带着已勾选的商品进入**结算页**（旅程 C）
5. 提交订单后，已下单的商品从购物车移除；没勾选的留在购物车

#### 旅程 B：立即购买

1. 商品详情点「立即购买」→ 规格弹层选 SKU 与数量 → 确认后**直接进入结算页**
2. 不写入购物车，也不改动购物车的勾选（FR-128）
3. 从结算页返回，回到商品详情，什么都不保存

#### 旅程 C：结算与付款

1. **进入结算页时的默认值：**
   - 收货地址：**每次都默认选中地址簿里的默认地址**；在结算页换了别的地址只对这一单有效，下次进来仍回到默认地址（2026-11-04 拍板，同线上）。没有任何地址时，地址区显示「新增收货地址」，快递区不询价，提交按钮不可用
   - 快递：按所选地址向 Biteship 询价，列表按运费从低到高，默认选中最便宜的一家（FR-172）
   - 优惠券：默认选中最优组合（FR-130）
   - PawCoin：有可用余额时默认勾选（FR-131）
2. **在结算页内可以改的：**
   - 换地址或新增地址（页内完成，新增的地址存入地址簿）→ 重新询价 → 快递、免运、免运券重算。换地址后若原快递仍可选则保留，否则改为最便宜的一家
   - 换快递、勾选或取消保价 → 金额明细重算
   - 换券或不用券；勾选或取消 PawCoin
3. **不能提交的情况：** 地址不在开通区域或没有快递可达（提示「该地区暂不支持快递配送」）；询价失败（提示暂时无法获取运费并提供重试）（FR-127、FR-172）。提交后失败（库存不足、券失效等）的处理见 FR-128「提交订单失败」
4. **提交订单：** 锁定快递、运费与保价（FR-172），然后：
   - PawCoin 足额支付 → 直接支付成功，不出二维码
   - 否则拉起**支付面板**：二维码、付款倒计时（60 分钟）、本次需扫码支付的金额、保存二维码、「我已付款」（FR-128）
5. **关掉支付面板没付：** 订单进入「待付款」，倒计时继续；用户可在订单列表或订单详情点「去支付」重新拉起同一个支付面板
6. **超时未付：** 订单自动取消，券退回（FR-130）。已扣的 PawCoin 一并退回，研发核对线上现有处理
7. **支付成功：** 显示支付成功页（应付金额、「查看订单」「继续逛」），点「查看订单」进入订单详情，订单状态为「待发货」

#### 旅程 D：发货、收货与完成

1. 运营在后台向 Biteship 下运单（AB-38），订单**仍是「待发货」**；仓库 / 运营确认已打包后在后台标记已发货，或 Biteship 回传「已揽收」时自动变为已发货，订单进入「待收货」（2026-11-05 拍板；两种来源只在后台可查）
2. 订单详情显示快递名称、运单号与物流状态：待揽收 → 已揽收 → 运输中 → 派送中 → 已签收（FR-172）。运营手工填写的运单不显示物流状态，只显示快递名称、运单号与「去承运商官网查询」
3. Biteship 回传签收 → 订单自动标为已送达；回传缺失时运营可在后台手工标记（FR-172）
4. 用户在「待收货」时可以随时点「确认收货」，不必等签收（线上现状）
5. 送达后 7 天自动完成（线上现状）；退货规则不在本次范围
6. 线上「发货起 7 天自动标记送达」的兜底改为 14 天：接入 Biteship 后送达以回传为准，印尼偏远地区 7 天可能还没送到
7. 带物流异常标记（揽收失败、退回、物流停滞、丢件破损）的订单**不参与**自动送达与自动完成，标记清除后再按原规则计时（2026-11-05）

#### 旅程 E：领券到用券

1. 获取：新人券在首次进入 Toko 时发放，出现在 Toko 首页「给你的券」里；Toko 首页「给你的券」直接领取；商品详情点「领取」；Toko 首页 banner 跳转领券；在「我的券」页输入兑换码（FR-130）
2. banner 的「领券」跳转：运营给 banner 绑定一张券，用户点击即领取并提示「已领取，可在我的券查看」；已领过则提示「已领取过」，不另做领券中心页
3. 查看：「订单 → 电商订单」页顶部的「我的券」入口（另有 Toko 首页「给你的券」右上角的入口），按可用 / 已使用列出，已过期的券不展示
4. 使用：购物车按最优券预估；结算页默认选中最优组合，可更换（FR-130、FR-133）
5. 退回：待付款时取消、超时取消、平台原因整单取消时券退回；部分取消、物流异常中用户原因取消不退（FR-130、FR-172）

#### 旅程 F：取消与退款

1. **待付款**：用户可自行取消订单，券退回（线上现状仅待付款可自助取消）
2. **待发货及之后**：用户不能自助取消，需联系客服
3. **缺货等平台原因取消**：运营在后台「异常订单」页处理（AB-28），PawCoin 部分立即退回；现金部分在订单详情出现「选择退款方式」，用户选退为 PawCoin 或线下打款（FR-134 ③）
4. **运单失败或揽收失败取消**：运营联系用户后按平台原因整单取消处理，同上（FR-172）

### 3.2 结算页一页完成（FR-128）

**目标：** 从进入结算到看到付款二维码，全程不离开结算页（§2.1 B、C、D、H）。

#### 已确认项（2026-09-30 拍板）

- **地址在结算页内新增与选择**，不跳出结算页；新增的地址保存进地址簿

- **二维码有效期与订单付款时限一致**：生成二维码时须把订单剩余付款时间传给支付网关，订单到期时二维码同时失效，用户在订单取消后无法再用存下的二维码付款。这是二维码存图功能的前置条件——现状向网关申请二维码时不传截止时间，二维码在网关侧能付多久由网关默认设置决定，可能长于订单时限。**研发须先确认 GemPay 支持设置二维码有效期**。⚠️ 2026-11-03：存图已随 1.4.1 先上线、有效期仍未对齐，这一风险**已在线上**，本条优先级相应提高（订单付款时限现为写死的 60 分钟）
- 支付方式维持 **QRIS + PawCoin**，不新增 e-wallet 直连、COD、虚拟账户

#### 结算页结构（2026-10-02 拍板）

自上而下：

1. **收货地址**：点击展开本页内的地址选择 / 新增
2. **快递**：列出 Biteship 对本单返回的可选快递，用户自选其一，可勾选保价（FR-172，2026-11-03 新增，保价 11-04 新增）。页面上只显示已选的一家，点开抽屉查看全部并更换（2026-11-04 拍板）

   - 其下保留线上的「开封不退」同意勾选（FR-104，默认已勾，取消勾选则不能提交，文案按本单最严的退货政策取，与商品详情页共用文案）（2026-11-05 拍板）

### 3.4 优惠券（FR-130）

**目标：** 拉新首单 + 给运营日常促销的手段。券的具体面额、门槛、发放均由运营在后台配置，App 端不写死任何一张券。

#### 已确认项（2026-09-30 拍板）

**券类型：** 本次只有两种

| 类型 | 作用 |
|---|---|
| 满减券 | 商品金额满门槛后减固定金额 |
| 免运券 | 减免本单运费（减免额封顶，见 FR-172） |

**获取方式：** 三种，均需运营在后台配置后才存在——**没有系统默认自动发放的券**

- 新人券：运营配置后，符合条件的新用户自动获得
- 领取：用户在 App 内主动领取
- 兑换码：用户输入运营发出的兑换码获得

**叠加：** 每单最多使用 **1 张满减券 + 1 张免运券**。

**满额免运与免运券并存（2026-09-30 拍板）：**

- 现有的全站满额免运（运营设置门槛，商品实付金额达到门槛即减免运费，减免额封顶，见 FR-172）**继续保留**，与免运券并存
- **二者取减得多的一个（2026-11-04 拍板，取代 09-30「已满额免运时免运券不可用」）**：本单同时满足满额免运与某张免运券时，系统自动采用减免额较大的一个，结算页在该行说明本单用的是「满额免运」还是哪张免运券；两者减免额相同时用满额免运。未被采用的免运券不扣，仍为可用

**计算顺序（2026-09-30 拍板）：**

```
商品金额
− 满减券
+ 运费
− 满额免运 或 免运券（二者只会生效其一；减免额封顶，见 FR-172）
+ 保价费（用户勾选保价时，见 FR-172）
= 应付金额
  → 应付金额由 PawCoin 与 QRIS 分担（PawCoin 是支付手段，不是折扣，见 FR-131）
```

- **运费相关的优惠一律按商品实付金额判断是否减免**（2026-10-06 拍板，取代 09-30「按券前商品金额」的口径）：满额免运门槛、免运券门槛都以**商品实付金额 = 商品金额 − 满减券**为准；用了满减券后实付金额低于门槛，则不满足免运。PawCoin 是支付手段，不影响实付金额
- 满减券的门槛按券前商品金额判断

#### 券的使用规则细节（2026-10-06 拍板）

- 满减券的适用范围为「指定品类 / 指定商品」时，门槛只计算适用范围内的商品金额
- **免运券设了适用范围时，本单所有商品都须在范围内才可用**；有任何一件不在范围内，按不满足条件处理，不减运费（2026-11-04 拍板）
- 券抵扣额不超过其作用对象：满减券不超过适用商品金额，免运券不超过本单运费且受 FR-172 的减免封顶
- **结算页默认自动选中最优组合**（抵扣额最大的满减券 + 可用的免运券），用户可手动更换或不使用
- 不可用的券单独成组，标明原因：未达门槛 / 不在适用范围 / 已过期 / 满额免运减得更多
- **退券**：订单在支付前取消或超时取消、平台原因整单取消（缺货、运单失败、揽收失败、快递原因的物流异常）、丢件破损赔付时，券退回账户（仍在有效期内才可再用）；部分取消、用户原因被退回的取消，券不退回，部分取消的退款金额按 FR-134 ③ 的分摊口径计算（2026-11-05 按后台 AB-28 取消原因类别补全）

#### 券的入口（2026-10-06 拍板）

- **我的券**：入口放在「订单 → 电商订单」页面与 Toko 首页「给你的券」右上角；按可用 / 已使用列出，**已过期的券不展示**（2026-11-05 拍板：用户只需要知道哪些能用、哪些已用）；页内有兑换码输入框
- **Toko 首页「给你的券」**（2026-11-05 拍板新增）：首页横滑展示该用户当前可领的券（直接「领取」，已领的显示已领取）与已到账的新人券（标「新人专享」）；没有可展示的券时整块不出现；游客不显示。只是首页上的一个模块，仍不另做领券中心页
- **领券**：商品详情页显示该商品可领的券，点击领取；Toko 首页 banner 可跳转到领券（FR-132）
- **新人券到账**：新用户获得新人券时，不弹窗，在 Toko 首页「给你的券」里置顶展示，标「新人专享」（2026-11-05 拍板）

#### 新人与新人券（2026-11-04 拍板）

- **新人的定义**：注册 **1 个月内**，且**从未在电商下过订单**的已注册用户。未注册的游客不算新人
- **发放时机**：新人**首次进入 Toko 时**发放，在「给你的券」里展示（见上「新人券到账」）
- **吸引游客注册**：运营配置了新人券活动时，游客进入 Toko 弹窗展示新人券，引导注册；注册后首次进入 Toko 即发放

#### 新人券细节（2026-11-04 拍板）

- 「下过订单」只算**已支付**的订单；下单后未付款、超时取消的不算，仍是新人
- 「1 个月」按注册时间起算 30 天，以首次进入 Toko 的时刻判断；进入时已超过 30 天则不发
- 新人在新人券活动开始前已进过 Toko 的：活动开始后、仍满足新人条件时，下一次进入 Toko 补发
- 游客弹窗：同一设备每个活动只弹一次；弹窗显示券面额与门槛，按钮「注册领取」进入注册，关闭后不再弹
- 后台同一时间只允许一张新人券在发放期内（AB-24），弹窗展示的就是这一张（2026-11-05）

#### 券的状态（2026-11-04 拍板）

```
已领（可用）→ 下单后被待付款订单占用 → 付款后：已使用
                                    → 订单取消：退回为可用（已过有效期则为已过期）
已领（可用）→ 过了有效期：已过期
已领（可用）→ 运营停用并选择作废：已失效
```

- **已失效（2026-11-05 拍板）**：运营停用券并选择作废已领未用的券时（AB-24），这些券变为已失效，**用户端不显示**（「我的券」与结算页都不出现），不通知用户；**已被待付款订单占用的那张照样可用于该订单**，该订单取消时变为已失效、不再退回

- 被占用的券在「我的券」与其他订单的结算页中都不可选
- **券是否有效按下单那一刻判断**（2026-11-04 拍板）：下单时在有效期内，即使付款前过期，这一单照样可用；该订单取消时券已过期则不再退回为可用
- 退回规则见上「退券」：支付前取消、超时取消、平台原因整单取消、丢件破损赔付时退回；部分取消、用户原因被退回的取消不退
- **发放期与使用有效期分开（2026-11-05）**：券在后台有「发放期」（能领取、能兑换、新人券能发放的时间）与「使用有效期」两组时间（AB-24）。领取、兑换、banner 是否展示看发放期；结算能否用看使用有效期

#### 券快过期提醒（2026-11-04 拍板）

#### 兑换码与过期提醒细节（2026-11-04 拍板）

### 3.8 资金闭环（FR-134）

#### 已确认项（2026-09-30 拍板）

以下三项为本次必做（问题见 §2.2）：

- **① 支付回调丢失的兜底**：对「已出码、未收到回调」的订单，系统须主动向网关查询支付结果，查到已付款即按正常到账处理
- **② 超时取消后才到账的款项**：二维码有效期与订单时限对齐后（FR-128），只剩「临近到期付款、到账通知晚于订单取消」这一种极少数情况，**由客服处理**，系统不自动恢复订单、不自动退款。2026-11-04 补充：用户付了钱就是想要这单，客服**优先重新下单继续履约**，没有库存时才走退款（见下方实现口径与后台 AB-28）
- **③ 异常订单取消必须退还现金部分**：整单取消时 PawCoin 与现金部分全额退回；部分取消某一行时，退回该行对应的金额
- **现金部分的退款去向（2026-10-02 拍板）**：沿用现有退货流程的两种去向——**退为 PawCoin**（即时到账）或**财务线下打款**到用户银行账户；PawCoin 部分只退回 PawCoin

#### 实现口径（2026-10-06 拍板）

- **① 查单时机**：用户在支付面板点「我已付款」时立即查一次；此外对待支付订单在付款窗口内定时轮询，付款窗口到期前做最后一次查询，查询失败不关单
- **③ 部分取消的退款分摊**：该行用过满减券时，按该行商品金额占适用商品金额的比例分摊券抵扣，退「该行实付」部分
- **③ 部分取消的 PawCoin 与现金拆分（2026-11-05 拍板）**：按原订单 PawCoin 与现金的支付比例拆，PawCoin 部分向下取整，零头算在现金；部分取消不退运费、不退保价费；被取消的是剩下的最后一行时按整单取消处理，退回剩余未退的应付金额（含运费、保价费）（后台 AB-28）
- **③ 整单取消按原因区分（2026-11-05 拍板）**：后台整单取消须选原因类别——平台原因全额退、给补偿、退券；用户原因被退回扣除用户实际支付的运费与保价费、不给补偿、不退券；丢件破损按 FR-172 赔付、给补偿、退券（后台 AB-28「整单取消：取消原因」）。此前有部分取消已退过款的，整单取消时减去已退金额
- **② 让客服看得到这笔款**：现状这笔回调被直接丢弃，多数情况连日志都没有（见 §2.2 ②），客服无从查起。「订单已取消但款项到账」时，系统须把这笔到账记到该订单上（不再丢弃），后台订单详情标记「取消后到账」并显示到账金额
- **② 客服的处理顺序（2026-11-04 拍板）**：
  1. **优先重新下单**：客服先联系用户，征得同意并核对券、PawCoin 余额、库存后，在后台为用户重新下一张订单，关联原来已取消的订单；已到账的钱用于支付 QRIS 部分，券与 PawCoin 正常扣除，继续履约。原订单用过的券已被用掉时不能重新下单；券已过期仍可用于这张新订单
  2. **用户不同意、条件不满足或没有库存时退款**：由客服触发退款，App 订单详情出现「选择退款方式」，按 ③ 的去向处理（退为 PawCoin 或线下打款）。这类退款不给转 PawCoin 补偿（用户付款晚于时限，不属平台原因）
  - 原订单取消时券已退回，不再处理；不提供「恢复原订单」，统一用重新下单
- **② 用户侧显示（2026-11-04 拍板）**：原订单详情显示「已为你重新下单」并可跳到新订单；新订单详情注明「由订单 #xxx 重新下单」；重新下单后给用户发一条通知
- **去向由用户选择**：订单详情页出现「选择退款方式」入口（复用现有退款方式页），选择线下打款时填写收款银行账户；用户选定前款项不退出。线下打款的渠道沿用退款方式页现有代码：BCA 转账（免手续费）、OVO、GoPay（各收 Rp 2.500 手续费，从退款金额中扣）（2026-11-05 拍板）
  - **线下打款的进度（2026-11-04 拍板）**：用户选线下打款并提交收款账户后，订单详情显示「退款处理中，预计 3 个工作日内到账」；财务在后台标记已打款后显示「已退款」（后台见 AB-28「退款打款」）。到账时长待财务确认后替换
  - **退为 PawCoin 的补偿（2026-11-04 拍板）**：平台原因的退款——缺货取消、运单失败或揽收失败取消、快递原因的物流异常（含丢件破损赔付）——用户选退为 PawCoin 时，按后台现有的「平台责任补偿」配置（线上异常订单现用的那一套，不是退货的转币激励）额外给一笔补偿，与线上退货流程对平台责任的口径一致；**用户原因被退回的取消不给补偿**。补偿**只对现金部分中选退为 PawCoin 的金额**发放，原本用 PawCoin 支付的部分原路退回、不另给（2026-11-05 拍板）
  - **用户迟迟不选（2026-11-05 拍板）**：不给用户发推送，7 天仍未选择时由后台提醒客服联系用户（AB-28）
  - **打款失败（2026-11-05 拍板）**：财务转账失败（账户信息有误、被退回）时，订单详情提示「退款打款失败，请重新填写收款账户」，用户可再次进入退款方式页重填，也可改选退为 PawCoin。**不发推送**，由客服联系用户告知（2026-11-05 拍板）

### 3.10 物流接入 Biteship（FR-172）

**目标：** 运费按真实包裹报价、由用户自选快递，运单与物流轨迹自动化，取代现在按 Kecamatan 配置的固定运费、运营手工录运单号与人工时间线（§2.1 E、FR-133 物流现状）。

**Biteship 是什么：** 印尼的物流聚合商。传入发货地、收货地与包裹重量、体积，返回多家快递的报价；也可通过它下运单，并回传物流轨迹。

#### 已确认项（2026-11-03 拍板）

- **物流服务商为 Biteship**，用于三件事：结算时报价、付款后下运单、之后回传物流轨迹
- **能不能送须同时满足两个条件**：① 收货地址在运营开通的区域内（运营借此控制想卖哪些区域）；② Biteship 对该地址至少返回一家快递报价。任一不满足即不可下单。开通区域从此只决定卖不卖，**不再决定运费**，原按区域配置的固定运费停用
- **多家报价由用户自选**：结算页列出 Biteship 返回的快递，用户选择其一
- **运费由用户支付**：所选快递的运费计入应付金额，按 FR-130 的计算顺序
- **商品详情页显示最低价**：「运费 Rp X 起」，取当前送达地区所有快递报价中最低的一家（FR-127）
- **满额免运与免运券都保留，减免额封顶**：减免额不超过以下二者中较小的一个——① 本单所有可选快递中最低的运费；② 运营配置的上限（满额免运在后台配一个全局上限，免运券每张券配自己的上限，见后台 AB-38 / AB-24）。用户选了更贵的快递，超出部分自己付
  - 例：本单最低报价 Rp15.000，运营上限 Rp20.000，用户选了 Rp28.000 的快递 → 减免 Rp15.000，用户付运费 Rp13.000
- **包裹重量与体积必填**：每个 SKU 须填包裹重量与长宽高，作为报价依据；**没填的 SKU 不能卖**（App 端不可加入购物车、不可立即购买）。存量在售 SKU 须在上线前由运营补齐（后台见 AB-38）
- **运单通过 Biteship 下单**：用户付款后，运营在后台按用户所选快递向 Biteship 创建运单，自动拿到运单号（后台见 AB-38）
- **物流状态由 Biteship 回传**：订单详情显示当前物流状态，取代现在的人工时间线（FR-133；第一版只显示状态，见下「物流状态与减免额展示」）

#### 报价、运单与订单状态规则（2026-11-03 拍板）

- 结算页快递列表**按运费从低到高排列**
- **提交订单时锁定所选快递与运费**，之后不再变动
- Biteship 询价失败（接口异常、超时）时，结算页提示暂时无法获取运费并提供重试，**不可提交**；不退回旧的固定运费
- Biteship 对该包裹无可用快递（如超重、超尺寸）时，按「该地区暂不支持快递配送」处理
- 报价与下运单的起点为后台配置的**发货地址**（只有一个，见 AB-38）
- **运单创建后订单仍是「待发货」**（2026-11-05 拍板）：仓库 / 运营确认已打包后在后台标记已发货；兜底是 Biteship 回传「已揽收」时自动变为已发货。两种来源只在后台可查，用户侧一律显示「待收货」（AB-38）
- Biteship 回传签收后，订单**自动标记为已送达**；后台手工「标记送达」保留作为兜底。之后的确认收货、退货窗口规则不变
- **Biteship 下运单失败**时，订单标记为运单失败并返回给运营，由运营决定：用同一家快递重新下单（适用于超时、接口报错、无可约取件时段、账户余额不足等临时问题），联系用户后取消订单，或手工填写运单（见 AB-38）。**研发须对重新下单做报警**：短时间内重新下单次数快速上升时通知技术排查（2026-11-04）。取消按平台原因整单取消处理：PawCoin 与现金部分全额退回（FR-134 ③，现金去向由用户选择），已用的券退回（FR-130）

#### 购物车运费、询价与保价（2026-11-04 拍板）

- **购物车显示运费**：购物车预估应付 = 所选商品金额 + 本单所有可选快递中最低的运费 − 默认最优券组合 − 满额免运减免，并显示「已省 Rp X」（FR-133）
- **控制询价次数**：Biteship 每次询价都要付费，研发实现时须避免重复询价，具体做法由研发决定
- **询价传参由研发决定**：传给 Biteship 哪些数据（商品明细、重量、体积等）由研发对照 Biteship 接口确定
- 进入结算页时**默认选中运费最低的一家**，用户可改选
- 提交前**换收货地址或改商品时重新询价**
- **保价（Asuransi）可选**：结算页快递区提供保价选项，由用户决定是否加入；保价费为商品价值的 0.5%（例：订单商品 Rp300.000 → 保价费 Rp1.500），由用户支付，计入应付金额（FR-130）；提交订单时与快递、运费一起锁定，下运单时一并传给 Biteship

#### 其余细节（2026-11-04 拍板）

- 商品详情页「运费 Rp X 起」按当前所选 SKU 与数量询价
- **地址与询价参数（2026-11-05）**：地址的省 / 市 / 区维持线上由后台开通区域配置的三级选择，不改用 Biteship 的地区数据；地址已有必填的 5 位邮编。⚠️ **待研发确认**：只用邮编向 Biteship 询价，在偏远地区（一个邮编覆盖范围大）报价是否准确；不准时再评估是否需要映射到 Biteship 的地区编号
- 购物车询价的收货地用默认地址；未登录或无地址时用详情页选过的送达地区，都没有则显示「选择地址后计算运费」、预估应付暂不含运费。购物车询价失败时同样处理（2026-11-04 拍板）
- 结算页快递列表每项显示快递名称、服务类型、预计时效、运费
- 保价：默认不勾选；商品价值按商品实付金额（商品金额 − 满减券）计算；保价费不受满额免运、免运券减免；Biteship 显示某家快递不支持保价时，选中该快递则不显示保价选项

#### 物流状态与减免额展示（2026-11-04 拍板）

- **第一版只显示物流状态**，不做逐条轨迹时间线：订单详情显示快递名称、运单号（可复制）与当前状态，保留「去承运商官网查询」
- 用户看到的状态：**待揽收 → 已揽收 → 运输中 → 派送中 → 已签收**；Biteship 回传的状态与这五个文案如何对应，由研发对照 Biteship 接口确定
- **结算页显示实际减免额**：金额明细中满额免运 / 免运券一行显示本单实际减掉的金额（例：运费 Rp28.000，满额免运 −Rp15.000）；订单详情同样显示

#### 物流异常（2026-11-04 拍板）

用户付款、运单创建之后，可能出现以下四类异常。后台的标记与处理入口见 AB-38。

| 类型 | 典型原因 | 怎么发现 |
|---|---|---|
| ① 揽收失败 | 快递没来取件、找不到快递员 | Biteship 回传 |
| ② 派送失败被退回 | 地址错、联系不上收件人、用户拒收；或快递自身原因派送不到 | Biteship 回传退回 |
| ③ 卡件 | 中转积压等 | 物流状态 **3 天**没有更新 |
| ④ 丢件、破损 | 快递责任 | 长时间卡件后经 Biteship 确认，或用户向客服反馈 |

**② 被退回，按原因区分谁出运费：**

- **快递原因**（例如快递自身派送不到）：**平台承担**，免费重新发货；同时运营须向快递 / Biteship 处理责任认定与索赔，后台对该订单留「待索赔」提醒（AB-38）
- **用户原因**（地址错、联系不上、拒收）：**原订单取消**，已花掉的运费不退；商品须退回仓库，运营确认入库后退还商品款。用户仍想要的，**重新下单**购买，平台按新订单发货

**③ 卡件：** 物流状态 3 天没有更新时，后台自动标「物流停滞」，提醒运营去 Biteship 追件。

**④ 丢件、破损：**

- 用户**买了保价**：按商品价值赔付
- 用户**没买保价**：由客服与用户协商处理（退款或其他方式）
- 平台向快递 / Biteship 索赔，与 ② 快递原因一样留「待索赔」提醒

**用户侧显示：** 订单被确认为 ② 或 ④ 类异常时（③ 卡件期间不提示，见下），订单详情只显示一个简单状态「**配送异常，请联系平台客服**」，并放「联系客服」按钮；不向用户展示退回中、理赔中等内部状态。需要用户做选择（重新下单、取消、协商赔付）时由客服联系用户。

**线上已有的「拒收」流程不复用（2026-11-04 核 1.4.1）：** 后端已有完整的拒收退款流程——用户在「已发货」时提交拒收申请，订单进入「退款中」，客服批准后跳过寄回与质检直接退款，并且**按平台责任处理**（全额退款，转 PawCoin 还加补偿溢价）。但 App 端退货入口自 1.3.0 起已换成「退货暂不可用」说明页，后台也只能审核用户提交的申请、不能代为发起，**这条流程实际上没人能触发**。它把拒收算作平台责任，与本节「用户原因不退运费」相反，因此不复用，拒收按 ② 用户原因处理。

**其余细节（2026-11-04 拍板）**

- ① 揽收失败按「Biteship 下运单失败」同样处理：运营重新下单、手工填运单或联系用户取消；三种处理执行前系统都先取消 Biteship 上的旧运单。用户侧不提示异常，继续显示当前状态（待发货，或运营已标记发货时的「待收货 · 待揽收」）（2026-11-05）
- 带异常标记（揽收失败、退回、物流停滞、丢件破损）的订单不参与「14 天自动送达」与「送达 7 天自动完成」；「确认收货」在任何异常下都照常可点——可能只是物流没更新、用户其实已收到货；被标为「配送异常」（退回、丢件破损）时与「联系客服」并列。用户确认收货后订单照常完成，异常标记自动清除并提醒运营核对（已在索赔的由运营自行撤回）（2026-11-05）
- ③ 卡件期间，用户侧继续显示最后一个物流状态；只有运营确认为 ② 或 ④ 时才改为「配送异常」
- 用户原因取消时，退款 = 应付金额 − 用户实际支付的运费（运费减去满额免运或免运券后的部分）− 保价费，按 FR-134 ③ 的去向退回；券不退回
- 丢件破损赔付：买了保价的，退款 = 应付金额 − 用户实际支付的运费 − 保价费（即商品实付）；没买的，按客服与用户协商的金额，不超过前者。券退回，现金部分选退为 PawCoin 时给补偿（2026-11-05，后台 AB-28）
- 快递原因重新发货时，在原订单上新建一张运单，原运单保留在记录中；订单详情显示最新的运单号与物流状态
- 用户反馈破损时，客服请用户提供照片作为索赔凭证
