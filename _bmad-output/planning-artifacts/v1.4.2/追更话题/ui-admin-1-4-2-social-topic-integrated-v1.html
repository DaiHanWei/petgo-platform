已定的设计决定（现行结论）：
· 话题列表默认按近 7 天热度倒序（F1）；首页话题行序号由运营定：打开开关排到最后，改序号与原位互换，关掉或隐藏 / 禁用后面前移，不足 5 个 App 按热度补齐（F1 / F8）。改序号后提示「已调整首页话题行顺序」，序号只能填 1–N
· 升级为官方后不能降回用户话题，活动结束用「隐藏」；官方话题不做封面，活动视觉用话题页顶置的推广卡（F2–F4）
· 恢复：隐藏话题直接恢复只出 toast；禁用话题恢复要原生 confirm（F7）
· 话题编辑抽屉（F4 / F5，隐藏话题也有）有「话题页顶置」区块：生效中 1 条 + 排期中最多 3 条，可新建、可跳全部排期；禁用话题没有该区块（F7）
· 顶置管理分「首页 Feed」｜「话题页」两个页签；话题页页签是话题列表（只列正常和隐藏），点一行进该话题排期页，在那里新建（G1 / G1a / G1b / G2）；内容顶置只能选该话题下的帖子
· 话题禁用后话题页不可访问，顶置立即结束，用户端看不到；恢复后不自动恢复
· 系统通知：② 预计触达和 ④ 确认都显示扣除没有宠物后的净人数；1 万人手动输入门槛按净人数判断；净人数为 0 拦截发送（I6）；发送记录显示「跳过 N（没有宠物）」，「触达人数」列加宽（I5）

实现提示（研发注意，已写在各屏说明里）：顶置管理加页签，话题页需新增话题汇总列表接口与按话题的排期页（AdminContentPinController 的 slots 加 TOPIC_PAGE，顶置记录按话题区分，新建抽屉由当前页带入坑位与话题）；后台没有开关组件；二次确认是浏览器原生 confirm；通知输入框要从 input / textarea 换成可显示整体标签的编辑区，并去掉 maxlength 改 JS 校验。
