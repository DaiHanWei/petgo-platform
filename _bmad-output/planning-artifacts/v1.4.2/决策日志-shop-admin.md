## 2026-11-06 按推荐定下（可推翻）

- **O-3 用户原因退回的顺序按 PRD**：先入库、后取消。电商线实现的是先取消（REFUNDING、不出退款单）、`confirmReturnInbound` 再回补库存并出单；后台线改为先入库，取消时直接出退款单、**不再回补库存**。入库方式见 O-15。
- **O-4 部分缺货可重新下单按 PRD**：电商线 `reorderFromLatePayment` 要求全部有货，后台线放宽为至少一行有货；缺货行照常入新单但不锁库存，新单自动标缺货、未处置前不能下运单，部分取消该行时不回补库存（AD-11）。
- **O-5 原快递不可用**：重下单仍不询价；下运单时若原快递已不在 Biteship 报价内，自动改选当前最便宜一家，差额进运费净成本（AD-11）。
- **O-6 签收后才报破损**：已签收 / 已完成订单可标丢件破损，同样标待索赔（PRD）、进异常订单队列；D5 表单走 `compensate`（S-9），不改订单状态。
- **O-7 优惠券权限**：新增 `shop.coupon_view`、`shop.coupon_edit`，不预授角色，由管理员在角色页分配（券是真实成本，不沿用 banner 的商品权限）。
- **O-8 退款打款权限**：页面 `refund.view` 或 `refund.payout` 可看，操作只限 `refund.payout`；列表账号打码，完整账号只在抽屉给 `refund.payout`。
- **O-9 转账截图**：私有对象存储，查看走短时效签名 URL，不用 banner 的公开上传。
- **O-10 提醒通道**：飞书群自定义机器人，客服 / 运营 / 技术三个 webhook 各一个 env，未配置时只写 WARN 日志；电商线已有的技术类告警改走技术群（AD-5）。
- **O-11 审计改前改后**：`AdminAuditService` 没有前后值字段且摘要有长度上限，摘要只写**有变化的字段**（`字段: 旧→新`），不加新表。
- **O-12 职责分离不豁免超管**，被拦截的尝试用独立事务写审计（沿用 V1.1 退款审批先例）。
- **O-13 stag 入口**：`/admin/stag/shop/**` 保留为 stag 工具；`return-inbound` 入口改调新的按行入库方法，`confirmReturnInbound` 删除。
- **O-18 已发货的揽收失败可重新提交运单**（PRD「无论是否已标」）：放开到已发货且无活动运单，订单状态不变。
- **O-19 重复付款单**（已付款订单又到账一笔）：只显示「退还到账款」，不显示重新下单。
- **O-20 手工运单状态**：按 UI H7 与现有 `ship()`，保存即转已发货；PRD 操作表「不变」以此为准回改。
- **O-21 部分取消与运单**：已有活动运单的订单不能部分取消，须先取消运单，避免包裹与订单对不上。
- **O-22 账号展示**：列表打码优先于 UI E1；户名显示。审计只记账号末 4 位，优先于 PRD 审计表「账号」。转账截图只给 `refund.payout`。
- **O-23 门店返佣**：S-5 未实现，审计表「门店返佣扣回」本版不记。
- **O-24 对账运费**：按下单口径，不冲减已退运费；退款仍在原「退款」卡。
