# 发帖支持短视频 · 调研 02：目标、范围与规格（已确认）

> 分支 `research/video` · 2026-10-16 · 前置：[调研 01 现有链路](video-post-01-current-chain-2026-10-16.md)
> 本文所有条目**已与用户确认**，可作为后续 PRD 的输入。

## 1. 目标与阶段

- **业务目标**：提高用户的 App 使用时长。
- **内容定位**：以 AI 小短剧为主。
- **第一期**：只有官方账号和指定账号能发视频，**所有人都能看**。
- **后续**：以付费会员（VIP）的形式向普通用户开放发视频的权限。

## 2. 会员等级（最简版）

| 项 | 决定 |
|---|---|
| 字段 | `users.vip_level`，类型 **integer**（不用 SMALLINT），NOT NULL，默认 1 |
| 取值 | 默认 1；发视频门槛为 **≥10**；中间值留给以后的付费档位 |
| 设置入口 | 后台用户详情页「设置等级」，需要新的权限码，写入 `AdminAuditService.record` 审计 |
| 下发 | `/api/v1/me` 返回 `vipLevel` |
| 前端门控 | `vipLevel ≥ 10` 才显示「发视频」入口 |
| **服务端门控** | 视频类 content-type 的上传签名、`mediaType=VIDEO` 的发帖，等级不够一律返回 403（不能只靠前端隐藏入口） |
| 以后接付费 | 付费结果映射成等级，结构不变 |

## 3. 视频规格

| 项 | 规格 |
|---|---|
| 混发 | **不支持**：一条帖子要么 1 个视频，要么 ≤9 张图 |
| 时长 | 3s ~ **90s** |
| 方向 | 以竖屏 9:16 为主，横屏和方形也允许，按原比例显示，不裁切 |
| 分辨率 | 短边 ≤ **720**（竖屏 720×1280）；超过的在端上压到 720，低于的不放大 |
| 视频编码 | **H.264**（HEVC 一律转成 H.264） |
| 色彩 | HDR / 杜比视界一律转为 SDR |
| 帧率 | ≤30fps（60fps 降到 30） |
| 码率 | 目标约 2Mbps，上限 3Mbps |
| 音频 | AAC-LC 128kbps |
| 封装 | MP4，**必须 faststart**（moov 在文件头，边下边播） |
| 体积 | 压缩后 90s 约 25MB；**服务端硬上限 50MB** |
| 封面 | 默认取第 1 秒的帧，发布者可以自选一帧；JPEG，宽 720；单独上传 |
| 分发 | 单一 MP4 直链，第一期**不做 HLS / 多码率 / 云端转码** |

### 压缩方案
- **在端上压缩**（免费、上传快；第一期发布者少，手机性能可以承受）。
- 压缩库选用调用系统原生编码器的那一类（Android MediaCodec / Media3 Transformer，iOS AVFoundation），**不引入 ffmpeg**（安装包会增加几十 MB，且已停止维护）。
- ⚠️ **选型验收项**：Android 原生封装默认把 moov 写在文件末尾，选中的库**必须实测输出是 faststart**，否则需要补一步 moov 前移；iOS 需要设置 `shouldOptimizeForNetworkUse = true`。
- 端上已经符合规格的文件（≤720、H.264、≤30fps、码率达标）跳过重编码，直接上传。
- 服务端第一期只做**校验**：content-type、大小、归属，以及客户端上报的时长和宽高。不做转码。

## 4. 播放形态（第一期）

**不做抖音式上下滑动**。初期视频少，滑两下就到底或开始重复，体验反而差。

| 场景 | 形态 |
|---|---|
| 推荐流 / 关注流 / 主页网格 / 时间线 | 只显示**封面 + 播放角标 + 时长**，不自动播放 |
| 点击 | 进入**全屏竖屏播放页**：黑底，按原比例显示（横屏视频上下留黑，App 保持竖屏、不旋转） |
| 播放页叠加层 | 作者（可点进主页、可关注）、正文、点赞 / 点赞人、评论（底部抽屉）、分享、举报 / 删除，复用现有详情页的这些能力 |
| 控制 | 单击暂停/继续；进度条可拖动；默认**有声**播放（用户是主动点进来的） |
| 播完 | **单条循环** |
| 网络 | 移动网络下不额外提示（720p、约 25MB 可以接受）；加载中显示封面加转圈 |
| 缓存 | 第一期不做磁盘缓存，以后视频多了再评估 |

### 为以后预留
- **剧集**：AI 短剧「看完自动下一集」是拉时长的核心手段。第一期就在数据结构里预留 `series_id` / `episode_no`（可为空），不做 UI。等内容够了，再做「选集 / 自动下一集」和上下滑动。

## 5. 审核（第一期）

- 发视频的只有官方和指定账号（等级 10），**第一期视频帖不走机审**，参照 Lark 定时发帖的 `publishTrusted` 直接发布。
- 保留：后台下架、用户举报（沿用现有举报预处置）、审计日志。
- 正文文本**仍走**现有文本审核（代价小，可以防止指定账号误发敏感文案）。
- **开放给付费会员之前必须补上**：阿里云视频审核（异步，按时长计费）+「先审后发」状态机。

## 6. 旧版 App 兼容

- 1.3.4 及以前的版本不认识视频帖，会显示成一张静态封面，点进去也播放不了。
- **服务端过滤**：请求没有带 `X-App-Version`（≤1.3.3），或者版本号低于视频版本的，Feed、关注流、主页、时间线、详情一律**不返回视频帖**。详情直接 404，与「已删除」口径一致。
- 推送、通知里指向视频帖的跳转，在旧版上同样会落到 404 文案。属于可接受的降级。

## 7. 数据与埋点

| 事件 | 属性 |
|---|---|
| `video_play_start` | postId、来源（feed / following / profile / timeline / push） |
| `video_progress` | postId、25 / 50 / 75 |
| `video_complete` | postId、第几次循环 |
| `video_watch_time` | postId、本次观看秒数（离开页面时上报） |
| `video_publish` | 时长、压缩前后体积、耗时 |

> 这些埋点和视频功能同版本上线，否则无法评估「使用时长」这个目标。

## 8. 改动清单（在调研 01 §4 的基础上收窄到第一期）

### 后端
1. 迁移：`users.vip_level`；`content_posts` 增加 `media_type`（IMAGE / VIDEO，默认 IMAGE）、`video_url`、`video_cover_url`、`video_duration_ms`、`video_width`、`video_height`、`video_size_bytes`、`series_id`、`episode_no`。时间戳迁移号，CHECK 约束全量重建。
2. 上传签名：content-type 白名单（jpeg/png/webp/heic/mp4）；视频要求等级 ≥10；扩展名映射补上 `.mp4`。
3. 发帖：`mediaType=VIDEO` 需要等级 ≥10；与图片互斥；时长、宽高、体积校验（发帖时用 OSS HEAD 校验真实体积 ≤50MB）；**视频、封面和图片统一做归属校验**（顺手修掉调研 01 发现的外链问题）；视频走免审路径，文本仍审。
4. 读取侧：Feed / 关注流 / 主页 / 我的 / 详情 / 时间线 / 分享 DTO 增加 `mediaType` 与视频字段；`firstImageUrl` 对视频帖下发封面；按 `X-App-Version` 过滤视频帖。
5. 会把视频当图片的地方分支处理：访客 / 名片 `exifStrippedDeliveryUrl`、推荐封面 SQL、Gemini 自动评论（第一期视频帖跳过）、暖评缩略图、顶置首图、H5 分享页、后台 4 个模板（视频帖展示封面 + `<video>`）。
6. 后台：用户「设置等级」+ 权限码 + 审计；内容列表 / 抽屉能预览视频并下架。

### 前端
1. 权限：Info.plist 加 `NSMicrophoneUsageDescription`，相机 / 相册文案提及视频；Manifest 加 `READ_MEDIA_VIDEO`；`media_permission.dart` 增加 `videos`。
2. 发帖：`vipLevel ≥10` 显示「视频」入口 → 选视频 → 校验时长 → 端上压缩 → 选封面 → 流式上传（进度百分比、超时、可取消）→ 发帖。
3. 依赖：`video_player`（系统播放器，免费，体积增量小）+ 一个原生压缩库（实测 faststart）。
4. 展示：模型增加字段；卡片 / 网格 / 时间线 / 日历 / 分享显示封面 + 角标 + 时长；`AppImage.ossResized` 跳过视频地址。
5. 全屏播放页（§4）。
6. 埋点（§7）。

## 9. CDN（2026-10-16 补充）

- 生产环境当初评估后**没有接 CDN**，图片直连 OSS 源站。
- **这一版只让视频走 CDN**：新增独立配置（如 `media.oss.video-cdn-base-url`），只有新的视频字段（`video_url` / `video_cover_url`）用 CDN 域名；**图片配置和存量数据不动**。
- 原因：如果把图片也切到 CDN 域名，会有两个影响。
  1. 旧版 App 的 `AppImage.ossResized` 只给 `*.aliyuncs.com` 的地址拼缩略图参数（`petgo_app/lib/shared/widgets/app_image.dart:30`），换成 CDN 域名后，旧版会在信息流里下载最大 2048px 的原图。
  2. 后端 `AliyunOssClient.objectKeyOfPublicUrl` 只认一个域名前缀，改掉后存量的源站地址就校验不过了。
- 视频对旧版没有影响：旧版本来就会被服务端过滤掉视频帖。
- CDN 配置要点：回源到 OSS 私有桶（对象本身是 public-read）；开启 Range 回源（支持拖动进度和边下边播）；MP4 缓存时间设长一些。
- 图片要不要接 CDN，等旧版本占比下降后再单独评估。届时新版 App 的 `ossResized` 也要认 CDN 域名。

## 10. 仍待确认 / 待验证

1. **生产 CDN**：每千次完整播放约 25GB 外网流量。上线前确认 CDN 的流量单价，并完成 §9 的配置。
2. **F21 存储**：OSS 对象永不删除，而视频体积大。是否对视频配置 OSS 生命周期规则，或重新拍板 F21。
3. **压缩库选型**：已完成模拟器验证，推荐 `pro_video_editor`，见 [调研 03](video-post-03-compressor-spike-2026-10-16.md)；还剩 HDR 实拍素材和真机耗时两项需要真机验证。
4. **视频版本号**：§6 过滤用的最低版本，等确定视频随哪个版本发布再定。
