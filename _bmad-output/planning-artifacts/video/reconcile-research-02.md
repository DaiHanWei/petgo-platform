# 对照查漏：调研 02（范围与规格）vs PRD / addendum

- 输入文档：`research/video-post-02-scope-and-spec-2026-10-16.md`
- 对照对象：`PRD-video.md`、`addendum-video.md`、`决策日志-video.md`（决策优先于输入文档）
- 约定：「PRD」指 PRD-video.md，「附录」指 addendum-video.md。原文位置写调研 02 的章节号。

## 一、真缺口（建议补）

### G-1 视频帖在「时间线 / 日历」中的展示与过滤没有覆盖（中高）
- 原文位置：§4 播放形态表（「推荐流 / 关注流 / 主页网格 / 时间线」）、§6（过滤范围含「时间线」）、§7（来源含 `timeline`）、§8 后端 4（读取侧含「时间线 / 分享 DTO」）、§8 前端 4（「卡片 / 网格 / 时间线 / 日历 / 分享」）。
- 缺口：FR-14 的展示位置只列了推荐流、关注流、个人主页、我的发布、顶置位；FR-18 的过滤范围同样没有时间线、访客/名片。两处都没提「时间线」「日历」。V-12 禁止视频帖用于成长日记，但调研 02 仍把时间线列入展示和旧版过滤范围，PRD 没说明时间线是否会出现视频帖。埋点来源枚举里的 `timeline` 在 FR-21 也被合并成了「其他」。
- 建议落点：FR-14 和 FR-18 的位置清单各补「时间线、日历（若视频帖会出现在其中）」。如果决定不会出现，就在 §5 或决策日志补一条「视频帖不进时间线 / 日历」，并同步删掉埋点来源里的 `timeline`。同时在 FR-18 补「访客 / 名片」「分享 DTO」。

### G-2 视频分发 CDN 域名与归属校验的冲突点没有进 PRD / 附录（中高）
- 原文位置：§9 原因 2（`AliyunOssClient.objectKeyOfPublicUrl` 只认一个域名前缀）、§8 后端 3（视频、封面、图片统一做归属校验）。
- 缺口：调研 02 说换域名会让地址校验失效，所以图片不动。但视频和封面字段本身要存 CDN 域名，FR-12 又要求校验视频 / 封面归属。FR-20 只写了「原因见调研 02」，没有说明视频地址入库和归属校验怎么共存。附录 D 只写了「复用 `objectKeyOfPublicUrl`」。需要明确入库存的是对象 key 还是 CDN 完整地址，以及校验时认哪个前缀。
- 建议落点：附录 D 加一条「`objectKeyOfPublicUrl` 需要同时识别视频 CDN 前缀（或入库存 objectKey、下发时拼 CDN 域名）」；FR-12 可测条件补「用视频 CDN 地址提交的视频 / 封面，归属校验仍然生效」。

### G-3 客户端上报「宽高」的服务端校验丢了（中）
- 原文位置：§3 压缩方案末条（「校验 content-type、大小、归属，以及客户端上报的时长和宽高」）、§8 后端 3（「时长、宽高、体积校验」）。
- 缺口：FR-12 只校验时长（3–90 秒）、大小、归属，宽高没有校验条件。附录 C 保存了 `video_width` / `video_height`，但没有规定合法范围（例如拒绝 0 或负数、超大值）。
- 建议落点：FR-12 可测条件补一条「宽高为正整数且在合理范围内，否则拒绝」，范围值留给架构 delta。

### G-4 视频规格里的几个硬数值只剩一半（中）
- 原文位置：§3 视频规格表。
- 缺口（逐项）：
  1. 码率：调研 02 是「目标约 2Mbps、**上限 3Mbps**」，FR-7 只有「约 2Mbps」。
  2. 音频：调研 02 是 AAC-LC 128kbps，FR-7 只写「AAC」，没有码率。
  3. 封面：调研 02 是 **JPEG、宽 720**，FR-8 写的是「短边 720」，格式未提。横屏视频或方形视频下，「宽 720」与「短边 720」得到的封面尺寸不同，是矛盾点。
  4. 体积：调研 02 区分「压缩后 90s 约 25MB」与「服务端硬上限 50MB」，FR-7 只有「处理后 ≤ 50MB」，没有说明 50MB 是服务端硬上限，25MB 是预期值（§8.3 成本里有 25MB，但规格表里没有）。
  5. 分辨率细节：竖屏 720×1280 的示例、「方形也允许」没有写进规格表。
- 建议落点：FR-7 规格表补「码率上限 3Mbps」「AAC-LC 约 128kbps」「预期体积 90 秒约 25MB」；FR-8 把封面写成「JPEG，宽 720（或与短边 720 二选一，由产品拍板）」。封面尺寸以哪个为准需要用户确认后再改。

### G-5 「移动网络不额外提示」这条定性要求被丢了（中）
- 原文位置：§4 播放形态表「网络」行（移动网络下不额外提示，720p、约 25MB 可以接受）。
- 缺口：PRD 的 FR-15、UJ-2、§8.3 都没有这条。没有它，开发或测试可能自行加上「正在使用移动数据」弹窗。
- 建议落点：FR-15 可测条件补「移动网络下直接播放，不弹流量提示」。

### G-6 「第一期不做磁盘缓存」只在附录里（低）
- 原文位置：§4 播放形态表「缓存」行。
- 缺口：附录 B 有，PRD §5 明确不做列表里没有。
- 建议落点：PRD §5 补一行「视频磁盘缓存（以后视频多了再评估）」。

### G-7 压缩库选型验收项：faststart 实测、iOS 参数（中）
- 原文位置：§3 压缩方案（⚠️ 选型验收项）。
- 缺口：
  1. 调研 02 要求「选中的库必须实测输出是 faststart，否则补一步 moov 前移」。附录 A 只写了「已合规但没有 faststart 的视频要 remux」，没有把「重编码后的输出也要验证 faststart」作为验收项。FR-7 可测条件里「支持边下边播」只在跳过重编码的分支里出现。
  2. iOS 需要设置 `shouldOptimizeForNetworkUse = true`，附录没有。
  3. 「不引入 ffmpeg」的约束（安装包增大几十 MB、已停止维护）没有在附录 A 或 PRD 出现，只有 §8.1 的安装包增量上限间接约束。
- 建议落点：附录 A 补三条；FR-7 可测条件补「处理后的文件 moov 在文件头（含重编码输出）」。

### G-8 麦克风权限：附录与调研 02 相反，且没有决策记录（中）
- 原文位置：§8 前端 1（Info.plist 加 `NSMicrophoneUsageDescription`，相机 / 相册文案提及视频）。
- 缺口：附录 E 写的是「不做现场拍摄的话，不需要麦克风权限」，「相册文案要提到视频」，没有提相机文案。这与调研 02 直接相反，决策日志没有对应的推翻记录（V-1 说调研 02 全部确认）。
- 建议落点：要么在附录 E 恢复调研 02 的写法（加 `NSMicrophoneUsageDescription`、相机文案提视频），要么在决策日志补一条「不做拍摄，不加麦克风权限」的决策并写明依据（例如 App Store 审核对多余权限的要求）。

### G-9 CDN 配置要点缺两项（低）
- 原文位置：§9 最后一段「CDN 配置要点」。
- 缺口：附录 D 有「回源到 OSS、开启 Range 回源」，缺「回源到 OSS **私有桶**（对象本身是 public-read）」和「**MP4 缓存时间设长**」。FR-20 可测条件有分段请求，但没有缓存要求。
- 建议落点：附录 D 补两条。

### G-10 图片以后接 CDN 时 `ossResized` 的后续动作（低）
- 原文位置：§9 最后一句（届时新版 App 的 `ossResized` 也要认 CDN 域名）。
- 缺口：PRD §5 只写「图片切到 CDN」不做，没有留下这条后续提醒。
- 建议落点：附录 E 或 §10 补一句「以后图片接 CDN 时，新版 `AppImage.ossResized` 要认 CDN 域名」。

### G-11 举报沿用「预处置」、下架审计（低）
- 原文位置：§5 审核（「保留：后台下架、用户举报（沿用现有举报预处置）、审计日志」）。
- 缺口：PRD §8.2 只写「用户举报、运营下架照常适用」，没有提「举报预处置」「审计日志」。
- 建议落点：§8.2 补一句「举报预处置沿用现有逻辑；下架写审计日志」。

### G-12 开放给付费会员前要补的审核能力描述不具体（低）
- 原文位置：§5 最后一条（阿里云视频审核，异步，按时长计费，加「先审后发」状态机）。
- 缺口：PRD §6.2 有「视频机器审核、先审后发」，但没有「异步、按时长计费」这一成本提示。不影响本版，仅备注。
- 建议落点：§6.2 括号补充，或不处理。

### G-13 埋点细节：`timeline` 来源与「离开页面」含义（低）
- 原文位置：§7 埋点表。
- 缺口：
  1. 来源枚举 feed / following / profile / timeline / push，FR-21 合并成「推荐流 / 关注流 / 主页 / 推送 / 其他」，`timeline` 丢失（与 G-1 关联）。
  2. `video_watch_time` 要「离开页面时上报」，FR-15 又规定切后台暂停。切后台、被杀进程时是否上报没有定义，会影响 SM-3。
  3. `video_play_error` 是 PRD 新增（附录 F 与 FR-21 都有），调研 02 没有，属于合理扩展，不算冲突。
- 建议落点：FR-21 来源列表与 G-1 的结论保持一致；附录 F 补「切后台时按暂停处理，是否上报 watch_time 由架构定」。

## 二、已覆盖或基本一致（备查，无需处理）

- 目标、阶段、会员等级字段（integer NOT NULL 默认 1，不用 SMALLINT）、门槛 ≥10、新权限码 + 审计、`/me` 下发、前端门控、服务端 403：FR-1 ~ FR-5、FR-11、附录 C。
- 混发互斥、时长 3–90 秒、H.264 / SDR / ≤30fps、faststart 边下边播（规格表层面）、端上压缩、合规文件跳过重编码、单一 MP4 不做 HLS：FR-6、FR-7、§5。
- 不做上下滑、列表不自动播放、全屏黑底竖屏页、横屏留黑不旋转、叠加层互动、单击暂停、拖动进度、默认有声、单条循环、封面加转圈：FR-14 ~ FR-16。
- 视频帖不走机审、正文仍走文本审核、`publishTrusted`：FR-10、§8.2、附录 D。
- 旧版过滤：缺 `X-App-Version` 或低于视频最低版本，详情 404，推送 / 通知落到「不存在」：FR-18、UJ-3。
- 视频独立 CDN 配置、图片和存量不动、Range 回源：FR-20、附录 D。
- 视频与图片统一归属校验：FR-12、FR-13。
- 迁移（时间戳号、CHECK 全量重建）、读取侧 `firstImageUrl` 下发封面、视频当图片处理的各处分支（exifStrippedDeliveryUrl、推荐封面 SQL、Gemini 自动评论、暖评缩略图、顶置首图、H5 分享页、后台 4 模板）：附录 C、D。
- 前端权限 `READ_MEDIA_VIDEO`、`media_permission.dart` 增加 `videos`、流式上传（进度、超时、取消）、`video_player`、`ossResized` 跳过视频：附录 A、B、E、FR-6、FR-9。
- 待确认项四条：CDN 单价、F21 存储、压缩库真机验证（HDR、耗时）、视频最低版本：PRD §10 第 1 ~ 4 条，另加 V-0 规定最低版本做成配置项。
- 「App 切后台」：调研 02 未涉及，FR-15 新增「切后台暂停，回前台不自动续播」，属于 PRD 补充。
- 「默认有声」：FR-15 已保留。

## 四、建议优先处理顺序

1. G-1（时间线 / 日历 / 访客 / 名片的范围，影响 FR-14、FR-18 与埋点）
2. G-2（CDN 域名与归属校验，实现层会踩）
3. G-4（封面「宽 720」vs「短边 720」矛盾，需用户拍板；码率上限、音频码率补齐）
4. G-5、G-8（定性要求与权限文案，需要确认后落到 FR-15 / 附录 E）
5. G-3、G-7（服务端宽高校验、faststart 实测验收项）
6. 其余低优先级项合并一次文档修订处理
