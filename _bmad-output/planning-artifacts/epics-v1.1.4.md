# TailTopia V1.1.4 - Epic Breakdown（Delta）

## Overview

本文件是 V1.1.4 **增量** epic/story 分解，承接 PRD（10 条 FR + §3 埋点）、架构 delta（**17 条 AD，权威**）、两份 UI 视觉稿（App 28 屏 / H5 4 屏）与决策台账（D-1~D-7）。

**V1.0 / V1.1 / V1.1.2 已上线冻结；未提及处一律继承。** 冲突序见 frontmatter。

核心主题 = **一批彼此松耦合的内容运营与增长能力**，加上宠物主页对外分享的收口。与 V1.1.2 不同，本版本**不是**一条强耦合主线，而是 10 条可独立排序的能力——唯一的强耦合是**图片规范化与 Feed 通栏化必须合并为一个 Epic**（改同一卡片组件、共用同一次取数改造）。

**本轮范围仅 App 侧 + 服务端。** 运营后台 10 模块单独走一轮；其中 4 条（顶置管理 / 装饰标签管理 / 手机号查看 / 用户标签管理）**不上线则对应 App 功能是空壳**，排期须并行核对。

## Requirements Inventory

### Functional Requirements

沿用全局 FR 编号，不重新分配（编号非连续，跳号属其它版本）。

- **FR-68**：顶置坑位与内容顶置（**本版本仅 Feed 坑位**，话题页坑位不在范围内）。Feed 顶部 1 个坑位，由运营在后台配置指定时间段展示的内容；可顶置对象二选一互斥：(a) 已发布的**公开**内容（顶置是额外展示，原时间线位置不受影响）、(b) 推广卡片（图片+标题+跳转，不对应真实帖子）。含定时上下线、WIB 时区口径、排期不可重叠、顶置期间内容被下架自动结束。顶置角标固定卡片右上角。
- **FR-70**：手机号采集入口。二合一：**一次性软引导**（复用「首次问诊后 / 建档后取最早」时机，**全局仅弹一次**，不跟随 FR-85 多触发点模型）+ **「我的」页常驻可编辑入口**。选填、仅印尼格式基础校验、**不做 OTP 验证、不用于登录**；已填写态按脱敏展示；**允许留空保存写 null**（撤回权）；保存成功/失败各一条 Toast。
- **FR-71**：图片上传裁剪与展示规范化。沿用单列 Feed；原始宽高比落在 **0.75~1.34 闭区间**内免裁剪，超出者弹裁剪框、提供 **1:1 / 4:5 两档预设**（**不提供横图预设**，超宽图只能裁成这两档，属已知接受结果）；同批次内"需裁剪的图"之间锁定同一目标比例，容差区间内的图不受锁定影响。**Feed 多图改为可左右滑动轮播**（覆盖 V1.0.0 FR-17「只展示第一张」），圆点叠在图片区内底边居中；容器高度按首图锁定、滑动时高度不变。存量内容一律 clamp 到该区间。裁剪页退出按钮在**左上角 ✕**。
- **FR-73**：内容详情页分享卡片。三类内容（Diary / Moment / Tips）均支持，**含作者关闭同步的私密 Diary**（用户主动分享属授权行为）。卡片含首图/正文摘要/作者/品牌水印；**无图用纯文字模板**；双尺寸 9:16 与 1:1；页脚含**下载二维码**（内容=该条内容分享链接、留白≥4 码元、导出分辨率下边长≥140px、纯文字模板须白色底板）。分享链接按访问者身份分流；**严格只看被分享的那一条**，不得由此进入宠物主页——与主页分享**必须是不同链接类型 + 不同落地页**。卡片生成基建**本版本首次搭建**，须按供后续复用标准设计。
- **FR-74**：用户标签。运营在后台创建（图标 + 说明文案）并分配；**四处展示位**（Feed 卡昵称旁 / 内容详情页作者区 / 评论区昵称旁 / 迷你主页预览卡），不做差异化；点击弹 tooltip；**同时最多展示 3 个**，超出按分配时间倒序取最近 3 个；空间不足时**昵称完整显示优先、标签倒序丢弃、不截断昵称、不做「+N」折叠**；支持定时生效/失效与永久分配。用户不可自主申请/购买/摘除。
- **FR-75**：内容装饰标签。运营创建（图标/样式 + 说明文案）并打标；**可打标范围仅公开内容**（Moment / Tips / 已同步的 Diary）；**三处展示位**（Feed 卡左下角 / 内容详情页 / 宠物日记页内）；点击弹 tooltip；支持定时生效/失效。详情页位置按有无配图切换：**有图叠首图角落 / 无图置正文下方单独一行**（2026-08-10 订正）。⚠️ **装饰标签生效中会给推荐排序 ×1.3 加权**——打标是流量动作，非仅荣誉徽章。
- **FR-76**：里程碑完成通知补齐。**S/M 级里程碑完成时新增写入通知中心记录（不发 push）**，文案复用现有庆祝文案；L 级维持现状（push + 通知中心）。覆盖 V1.0.0 FR-42 通知行为**与 FR-34 通知类型清单**（新增一类）。跳转落成长档案→里程碑列表页；**计入未读角标**；**存量不回填**；同一操作解锁多个 → **写 N 条且每条写明具体里程碑名称**（庆祝弹层仍只弹一次）。
- **FR-85**：多触发点推送权限唤醒（覆盖 V1.0.0 FR-22D「全局仅一次/拒绝后不再弹」）。改为**每个触发点相互独立、各自最多触发一次**；前置闸门"已开启则跳过"。触发点：1 首次问诊后 / 2 建档后 / 4 **打开通知中心（新增）** / 5 **兽医切换为在线（新增，兽医端）**。⚠️ **触发点 4 永不唤起原生系统弹窗**（一律 App 内引导条 + 跳系统设置），原生弹窗机会保留给 1/2/5 中最先到达者。⚠️ **触发点 5 不受"各一次"限制**，每次上线且通知关闭时都提示、**不做硬拦截**。标记位**按设备存储**；与 FR-70 软引导是**两套独立计数**，不可共用标记位；同时命中按"先推送权限、后手机号"串行。
- **FR-92**：宠物主页对外分享的视觉改版与访客可见范围（扩展 V1.0.0 FR-14）。**§① H5 视觉改版**（剪贴簿方向；覆盖三个模板：主页面重做 / 失效页**印尼化**并重做 / **新增加载失败页**；接受 Google Fonts 依赖）。**§② 访客可见范围**（覆盖 FR-14「只读预览」未定义部分）：可见=头像/名字/陪伴天数、基础档案、里程碑徽章与进度含锁定态、**Diary 时间线含私密条目**、日历视图、统计条含问诊**次数**；**不可见=健康记录、问诊记录、宠物身份证入口、互动能力、管理入口、二次转发**。**§③ 不做分享前的授权范围告知**。**§④ 双 CTA 合并为单 CTA**（覆盖 FR-14 双 CTA 设计），已装 App → 深链落该宠物 Diary 访客只读态，未装 → 应用商店。
- **FR-93**：Feed 卡片通栏化与首页互动（覆盖 V1.0.0 FR-17 卡片结构、FR-23 点赞展示位）。**① 容器通栏化**：去描边/圆角/屏边距，图片全宽出血，条目间 1px 分隔线 + 上下 12px；元素顺序**作者行 → 图片 → 操作行 → 正文 → 时间**；保留内容类型徽章；正文不加作者名前缀。**② 开放首页点赞与评论入口**（打破 FR-17「点赞/评论数不在卡片展示」与 FR-23「点赞数只在详情页」及其"先不做首页点赞"的旧旁注）：操作行在图片正下方，点赞就地切换、评论跳详情页**并定位到评论区**；不做 Feed 内联评论；未登录点赞触发既有登录引导；点赞成功仍触发既有推送。**④ 既有点赞事件须新增来源属性**（feed / detail）。

> **FR 数量口径订正**：PRD §6.1 写「本版本现共 9 条 FR」，该句写于 FR-93 加入（2026-08-07）之前，**已过期**。实际为**上列 10 条**。

### NonFunctional Requirements

**本版本零新增 NFR**，全部继承基线。以下三条是本版本实际压在其上的既有 NFR，story 中不得违反：

- **NFR-5（继承）**：游客首屏零网络依赖。→ 约束 FR-92 访客视图与既有 Diary 游客态的关系（AD-4 不得把访客态混入零网络的示例页分支）。
- **NFR-8（继承）**：作者已注销时的渲染口径（本地化「已注销用户」+ 默认头像、头像不可点）。→ 约束 FR-74 用户标签在四处展示位遇注销作者时的表现、以及 FR-92 访客视图遇作者注销时走失效页。
- **NFR-12（继承）**：绝不在 App 首次启动时请求推送权限（授权率极低）。→ 约束 FR-85 新增触发点，且是 AD-14「触发点 4 永不唤起原生弹窗」的同源判断。

**另继承底线约束（架构 delta 已列，story 中一律适用）**：`ddl-auto=validate` schema 归 Flyway；禁 MQ / 禁调度中间件 / 禁通用缓存层；对外标识不可枚举 token；凭证 env 注入不入库；错误统一 RFC 9457；**日志禁记 PII / 健康数据 / 令牌 / 签名 URL**（本版本新增手机号即 PII）。

### Additional Requirements

来自架构 delta 的 17 条 AD。以下为对 story 拆分有直接约束力的技术要求：

- **访客只读投影层**（AD-1）：新建独立取数层，**结构上不持有健康记录与问诊仓库**（沿用 V1.1.2「分类器不持有 Repository」手法）；H5 与 App 两出口**共用同一层**；**禁止**在既有 `/me` 作用域查询上加访问者参数复用；访客投影**只含已发布未删除内容**；**统计条复用作者态唯一统计实现，不得重算**。
- **访客视图 token 与路由**（AD-2）：复用现有名片 token、不新发、无撤销能力；**对未登录开放**；必须是**带 token 的独立路由**，不得复用作者态档案路由（否则未登录会落 V1.1.2 的游客示例页）；失效口径**不存在/已删/已注销返回同一响应**（防枚举）。
- **私密内容不越出 token 边界**（AD-3）：公开内容可点开进既有详情页；私密 Diary 不可点 + 提示（须出 id/en 两版 ARB）；**禁止**在内容详情页为访客场景新增二次校验层。
- **访客态接入单一判定入口**（AD-4）：作为 V1.1.2 AD-15 的新增状态分支，复用作者态结构做减法，不另画页面；Diary 页**无陪伴天数字段**，不得引入。
- **图片尺寸列**（AD-5）：与图片列并排、**同序等长**的 JSONB，缺失位 null 占位；既有五处读取点不动、存量零回填；客户端上报 + 服务端兜底测量；**写入责任在发布服务单一入口**，App 发布与后台种子发布两个调用方都必须经过它。
- **图片渲染三段顺序**（AD-6）：按实际比例 → clamp 0.75~1.34 闭区间 → 高度护栏；**服务端只下发原始宽高，clamp 与护栏一律客户端施加**（禁双重裁切）；多图按首图锁定后再套护栏；**存量占位兜底为必做项**。
- **Feed 取数扩张一律批量**（AD-7）：整组图片 / 是否已赞 / 评论数三项沿用既有批量聚合模式；**禁逐条查、禁新增冗余计数列**。
- **顶置只首屏让位**（AD-8）：仅从第一页排除，**排除后须补足页大小**；顶置走独立取数、失败不连带 Feed 失败；坑位维度必须是配置项；顶置配置归 content 模块内部。
- **时间窗判定唯一实现**（AD-9）：三处定时一律查询时判定、不落状态列、不建扫描器；副作用走事件订阅；**判定必须只有一份实现，四处共用**（三处取数 + 后台列表展示）。
- **两套独立标签表**（AD-10）：不共用配置表、不用多态外键（PostgreSQL 无法对多态外键建约束）。
- **标签 7 处展示位一律批量取数**（AD-11）：评论列表尤其禁止逐条。
- **印尼语里程碑标题**（AD-12）：Java 编译期常量与中文目录并列同文件，仅供 H5；**两处同步责任须写入 story 验收清单**；总数按物种取现成值（猫 31 / 狗 31 / 通用 16），视觉稿的 7/30 与 +23 是示意数字。
- **S/M 通知新类型**（AD-13）：不发 push、计入未读角标、写 N 条各写明名称、存量不回填。
- **FR-85 四键物理隔离**（AD-14）：走本地非敏感偏好存储、按设备；**存量旧标记不迁移、不删除、新模型不读它**；兽医端无标记位；触发点 4 护栏可线上告警校验。
- **分享卡客户端生成**（AD-15）：复用宠物身份证既有做法；**四样底层能力均已在生产使用、无新依赖**；身份证导出**已在用「按目标画布宽度反算截图倍率」**——正是二维码「按导出分辨率算边长」所需同一手法，照抄不另起；水印可参照身份证做法。
- **H5 埋点服务端上报**（AD-16）：复用既有埋点客户端、不引前端 SDK；点击与结果**必须拆两个事件**；需匿名持久化标识串漏斗；**两段 identity 不合并、不承诺访客登录态属性**；**权限状态快照是 FR-85 唯一裁决指标、P0 前置不可后置**。
- **性别与手机号字段**（AD-17）：性别补成真字段（现为前端占位，选了不入库）、存量为空须容错；手机号选填/允许清空写 null/禁入日志/脱敏在展示层。
- **Flyway**：从 **V100** 起单调分配（基线 V99）；story 内占位写 `V<n>__`，实际号按执行顺序顺延，**勿照搬示例号**。
- **App 端唯一依赖增量**：FR-71 裁剪交互项目现无可用库（只有选图能力），需引第三方裁剪库或自研选区交互——属实现选择。**服务端零依赖增量。**

### UX Design Requirements

来自两份视觉稿（App 28 屏 / H5 4 屏）。每条对应具体屏号，可直接生成可验收 story。

**H5 宠物主页分享页（4 屏）**

- **UX-DR1**：H5 主页面按 **E1 屏**（完整态）与 **E2 屏**（零数据降级态）重做为剪贴簿/贴纸拼贴方向。主色由现状绿系纠正为品牌紫。含照片簇交叠、手绘涂鸦层、自述荧光笔标记、故事数字做成票根、区块标题做成胶带小片。
- **UX-DR2**：H5 引入 4 个 Google Fonts（可变字体宠物名与数字 / 正文 UI / 手写体小字 / 票根等宽数字）。**保留 `display=swap`、须补 `preconnect`**；视觉稿 `<head>` 已写好，**照抄，不自行拼装字体 URL**。两项须真机复核（沙箱无网络时字体回退、测不出正常观感）：手写体小字、可变字体的宽度轴。
- **UX-DR3**：H5 失效页按 **E3 屏**重做并**改为印尼语**（现状全篇英文，而主页面全篇印尼语——同一条链接换个状态就换种语言）。⚠️ 该模板**被宠物名片与里程碑分享两条链路共用**，一次修复覆盖两处。
- **UX-DR4**：**新增** H5 加载失败页，按 **E4 屏**实现（含重试按钮）。⚠️ 该模板**当前不存在**，服务器异常时访客看到浏览器默认报错白屏——属**新增页面**，不属"重做视觉与排版"。

## Epic List

### Epic 1: 宠物主页对外分享页改版（H5）

分享给朋友的网页不再是与品牌不符的绿色、状态页不再是看不懂的英文、服务器出错时不再是浏览器白屏；页面上有里程碑徽章墙作为拉新钩子，底部只有一个明确指向下载的按钮。

**FRs covered:** FR-92 §①③④（+ 埋点 E-23~E-27）
**依赖:** 无（本 Epic 是本版本的零依赖起点之一）
**共享文件提示:** 三个 Thymeleaf 模板 + 名片页控制器。埋点接入与模板改造同文件，故并入本 Epic，避免两次改动同一文件。

### Epic 2: App 内访客只读视图

装了 App 的人点开别人分享的宠物链接，看到的是**被分享的那只宠物**（现状错误地落在给游客做的示例页），且**看不到健康记录与问诊记录**；私密日记条目点不开、有解释；访客不能二次转发。

**FRs covered:** FR-92 §②
**依赖:** Epic 1 的性别字段（访客视图的基础档案区同样展示性别）。反向不依赖。
**⚠️ 安全攸关 Epic:** AD-1 / AD-3 是本版本两个安全攸关节点，story 内不得埋违反点。

### Epic 3: Feed 卡片改造与图片规范化

用户竖拍的宠物照片进首页不再被拦腰砍掉、多图帖能在首页左右滑动看完、首页可以直接点赞和看评论数；发布时只有真正的长图/超宽图才需要过裁剪框。

**FRs covered:** FR-71 + FR-93
**依赖:** 无
**合并理由（AD-6/AD-7 + 工作拆分预览 §4.2）:** 两条 FR 改同一个卡片组件，且"整组图片下发"与"是否已赞 / 评论数"是**同一次 Feed 取数改造**；多图圆点之所以改到叠在图片内底边，正是因为 FR-93 把操作行放到了图片正下方。**分两个 Epic 会改两遍同一处代码。**

### Epic 4: 内容顶置坑位

运营能把活动、功能上新或官方话题顶到首页顶部，按排期自动上下线；被顶置的内容在首屏不会与列表里的自己重复出现。

**FRs covered:** FR-68
**依赖:** Epic 3（顶置条目与普通条目同构，卡片改版未定稿会改两次）
**⚠️ 可用性依赖后台:** 需 AB-10A 顶置管理，否则运营无处配置、App 端为空壳。代码上本 Epic 仍独立完整。

### Epic 5: 运营标签体系（用户标签 + 内容装饰标签）

被运营认定的优质用户在四处露出身份标签、优质内容在三处露出荣誉标签，点一下能看到这个标签是什么意思。

**FRs covered:** FR-74 + FR-75
**依赖:** Epic 3（两类标签都要落在改版后的 Feed 卡上）
**合并理由:** 两者机制同构（图标 + 说明文案 + 定时生效 + tooltip），**共用同一个 tooltip 组件**与**同一份时间窗判定**，且展示位重叠（都要改 Feed 卡与内容详情页）。数据层按 AD-10 仍是两套独立表。
**⚠️ 可用性依赖后台:** 需 AB-12A 与 AB-10C。

### Epic 6: 增长与召回（手机号采集 + 里程碑通知补齐 + 推送权限唤醒）

关掉通知的用户在真正有理由开通知的时刻会被重新提醒（换设备后再给一轮机会）；由别人互动触发的里程碑达成不再悄悄发生；兽医每次上线时若通知关着会被提醒，不至于收不到派单；运营能拿到用户手机号做流失召回。

**FRs covered:** FR-70 + FR-76 + FR-85（+ 埋点 E-21）
**依赖:** 无代码依赖（E-21 权限快照置于本 Epic 首位，是 FR-85 的 P0 前置）
**合并理由:** 三条 FR 共享两处会打架的东西——① **同一段时机判定**（手机号软引导借用"首次问诊后 / 建档后取最早"，而推送权限触发点 1/2 就是这两个时机），且 PRD 要求两者"先推送权限、后手机号"**串行**，该串行逻辑归两个 Epic 各自拥有必然分叉；② **同一个通知中心页面**（FR-76 加 S/M 记录、FR-85 加顶部引导条）。PRD §1 目标第 2 条本身即把手机号与推送权限归为「增长与召回基建」一类。
**⚠️ 可用性依赖后台:** 仅手机号那条需 AB-11A（查看与批量催填）；FR-76 / FR-85 零后台依赖。

### Epic 7: 单条内容分享卡

用户能把某一条内容变成一张图分享到 WhatsApp / Instagram Stories，看到图的人扫码就能回到**那条内容**；访客只能看被分享的这一条，进不去这只宠物的其它记录。

**FRs covered:** FR-73
**依赖:** Epic 2（AD-15 要求单条分享与主页分享必须是不同链接类型 + 不同落地页；主页分享链路先定型，本 Epic 才知道不能撞什么）
**基建性质:** 卡片生成基建**本版本首次搭建**，须按供后续分享卡功能复用的标准设计。四样底层能力均已在生产使用、无新依赖。

### Epic 8: 埋点收尾（App 侧）

产品能回答"这一版这些改动到底起没起作用"——各触发点该留该砍、容差区间取值对不对、开放首页点赞是净增长还是零和。

**FRs covered:** §3 埋点 E-1~E-20 / E-22（E-21 在 Epic 6 首位；E-23~E-27 H5 组在 Epic 1）
**依赖:** 前述各 Epic 的功能须先在（沿用 V1.1.2「埋点集中一条收尾 story」的既定惯例）
**⚠️ 唯一例外:** E-21 权限状态快照是 FR-85 的裁决指标、**P0 前置不可后置**，已提前至 Epic 6 首位。
