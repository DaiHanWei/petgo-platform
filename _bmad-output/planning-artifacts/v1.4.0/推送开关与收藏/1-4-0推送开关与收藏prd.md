## 1. 版本目标

1. **让用户能关掉不想要的推送，而不是关掉全部推送**：1.3.4 上线关注和互动通知优化后推送量上升，现在用户只有「系统权限全开 / 全关」一个选择，嫌吵就只能全关，连订单、礼物等重要提醒也一起丢了。
2. **让用户能留住想再看的内容和场所**：现在看到好的科普帖、想去的宠物友好场所，没有地方存，只能靠记忆。

**核心指标：** 各推送分类的关闭率 · 系统推送权限关闭率（对比上线前）· 收藏人数 / 人均收藏数 · 收藏列表的回访点击率

## 2. 现状（2026-10-13 核实代码，以 origin 为准）

| 维度 | 现状 |
|---|---|
| 推送开关 | **没有任何按用户或按类型的推送设置**，后端也没有用户偏好表。App 设置页 AKUN 分组里的「通知」开关**只反映系统权限**：打开时申请权限，关闭时只能引导去系统设置 |
| 推送链路 | `NotificationService`（`send` / `sendWithCopy` / `sendInteraction`）先写库、加未读角标，再调 `NotificationPusher` → 腾讯 IM 离线推送。**运营公告 `OPS_ANNOUNCEMENT` 不经过 `NotificationService`**，由 `OpsNotificationDispatcher` 直接调 `pushToUserNow` |
| 不推送的类型 | 只有 S/M 级里程碑 `MILESTONE_SM_NODE` 只进通知中心、不推送 |
| 角标 | 铃铛未读数来自 Redis 计数，与是否推送无关；系统桌面图标角标恒为 0 |
| 场所收藏 | **不存在**（没有表、接口、页面）。场所详情页代码注释写明「没有收藏」，1.3.0 PRD 将其列为不做 |
| 帖子收藏 | 不存在 |
| 点赞计数 | 没有冗余计数列，实时 COUNT（`content_likes`）。场所表和关注计数已有冗余计数列的先例 |
| 帖子不可见的情况 | 作者删除、运营下架（软删 + 发 `ContentUnavailableEvent`）；作者注销（状态改为 AUTHOR_DEACTIVATED，不发逐条事件）；举报预处置（UNDER_REVIEW，不发事件）。**没有「发布后转私密」的功能**，可见性只在发帖时选 |
| 详情页操作栏 | `comment_composer.dart` 的 `_actions()`：点赞、分享卡两个按钮 |
| 「我的」页 | 居中名片 →「Hewanku」宠物区 →「我的订单」所在的活动区 →「Postinganku」 |
| 推荐算法 | 只读点赞和评论两个互动信号 |

## 3. 功能与需求

### 3.1 推送分类开关（FR-150）

#### 已确认项（2026-10-12 / 10-13 拍板）

- 通知类型合并为 **9 个分类开关**（2026-10-12 定 8 个，2026-10-13 新增「@ 提及」单独一类）；**开关只管系统推送，通知中心照常收到、铃铛角标照常累加**
- **默认全部打开**；开关**存在服务端、跟着账号走**（换手机、多设备一致）
- 入口：「我的 → 设置 → 通知设置」
- 系统通知权限关闭时的处理见下方「通知设置页」
- 「**订单与账号**」分类**不能关**
- 免打扰时段本版本不做

**分类与通知类型对照**

| 分类 | 能否关 | 包含的通知类型 |
|---|---|---|
| **点赞** | 能 | `CONTENT_LIKED` |
| **评论与回复** | 能 | `CONTENT_COMMENTED`（含回复）、`PLACE_COMMENTED`（场所评论） |
| **@ 提及** | 能 | `CONTENT_MENTIONED`（在帖子或评论里被 @；2026-10-13 拍板单独成类） |
| **新粉丝** | 能 | `USER_FOLLOWED` |
| **礼物** | 能 | `PET_GIFT_RECEIVED`（③） |
| **宠物提醒** | 能 | `PET_BIRTHDAY`、`COMPANION_ANNIVERSARY` |
| **成就与等级** | 能 | `MILESTONE_NODE`（L 级与一周岁节点）、`MILESTONE_SM_NODE`（本身不推送）、`GROWTH_LEVEL_UP`（①） |
| **活动与优惠** | 能 | `OPS_ANNOUNCEMENT`（运营公告 / 站内信）、`LIFECYCLE_D1` / `D3` / `D7` / `WINBACK`（新手引导与召回；2026-10-13 拍板：属平台营销类，随「活动与优惠」可关）、`REPURCHASE_FOOD_LOW`（复购提醒，1.4.2 下线；2026-10-13 拍板：引导下单的营销提醒，可关）、`CSAT_SURVEY`（客服满意度问卷；2026-10-13 拍板：向用户要反馈，偏营销性质，可关；与工单结案同时发出时，工单结案照常推送、问卷按此开关）；1.4.2 的「优惠券到账」届时归入此类 |
| **订单与账号** | **不能** | 订单与支付：`SHOP_ORDER_SHIPPED`、`SHOP_ORDER_EXCEPTION`、`SHOP_RETURN_UPDATED`、`REFUND_REJECTED`、`PET_SLOT_EXPIRING`、`PET_SLOT_EXPIRED`（②）、`GIFT_UNDELIVERED_REFUND`（③）；客服：`TICKET_RESOLVED`（工单结案；2026-10-13 拍板）；审核与处置：`CONTENT_REMOVED`、`CONTENT_REVIEW_REJECTED`、`CONTENT_REVIEW_TIMED_OUT`、`REPORT_REVIEWED`、`NAME_RESET`、`AVATAR_RESET`、`ACCOUNT_WARNED`、`ACCOUNT_SUSPENDED`；兽医：`VET_REPLY`（兽医线已暂停；2026-10-13 拍板：付费服务的进展、可能涉及宠物健康，不能关）；从未发送的占位类型 `CONSULT_CLOSED`、`CONTENT_REVIEW_APPROVED`、`IDENTITY_REQUIRE_MODIFY` 也归此类 |

- 兽医端的 `NEW_CONSULT_REQUEST` 发给兽医账号，不属于用户侧开关；为满足「每个类型都有分类」的单元测试，**映射上归入「订单与账号」**（兽医账号没有通知设置页，不受影响）
- Roadmap 原写「订单与账号」包含「版本更新」：版本更新是 App 内弹窗（FR-124），**不是推送**，不受本开关影响
- **以后新增通知类型，必须在本表里指定分类**（开发须知见影响面）

**通知设置页**
- 顶部：系统通知权限状态（已开启 / 已关闭 +「去开启」）
- 下方 9 行开关，每行写一句说明（如「点赞：有人赞了你的帖子」）；「订单与账号」显示为常开、置灰不可点，说明「订单、支付和账号安全相关的提醒不能关闭」
- 系统权限关闭时，**9 个开关仍可操作**（2026-10-13 拍板）：设置照常保存，开启系统权限后按设置生效；顶部提示文案为「系统通知已关闭，开启后按下方设置推送」+「去开启」
- 原设置页 AKUN 分组的「通知」开关**改为进入「通知设置」页的一行入口**（2026-10-13 拍板），不再是系统权限开关；行右侧小字显示状态「已开启」/「系统通知已关闭」。原开关显示权限、引导开启的作用由通知设置页顶部提示接管
- 切换即保存，不需要确认按钮；保存失败时开关回弹并 Toast 提示

**旧版本 App**
- 旧版本没有通知设置页，账号的推送设置保持默认（全开）；用户在新版本里改过的设置，旧版本设备上同样生效（设置在服务端）

#### 边界与不做项

- 不做按单条通知 / 单个用户屏蔽推送
- 不做免打扰时段
- 不做通知中心按分类筛选
- 不改通知中心的显示逻辑：关闭推送的分类照常进通知中心

#### 验收标准

- **AC1**：关掉「点赞」后，别人赞我的帖子，通知中心有这条、铃铛未读 +1，手机没有推送；打开后恢复推送
- **AC2**：关掉「活动与优惠」后，运营公告仍进通知中心，但不推送（运营公告不经 `NotificationService`，也要被拦住）
- **AC2a**：关掉「活动与优惠」后，客服处理完工单：「工单已处理」照常推送，满意度问卷只进通知中心、不推送
- **AC2b**：关掉「@ 提及」、保持「评论与回复」开启时，被 @ 不推送，被评论照常推送
- **AC3**：「订单与账号」开关无法关闭；订单发货、月租到期、账号处罚等推送不受其他开关影响
- **AC4**：在手机 A 关掉「新粉丝」，登录手机 B 打开通知设置，「新粉丝」显示为关闭，B 上也不收这类推送
- **AC5**：系统通知权限关闭时，设置页顶部显示提示与「去开启」，点击跳到系统设置
- **AC5a**：设置页 AKUN 分组里「通知」是一行入口，右侧显示「已开启」或「系统通知已关闭」，点击进入通知设置页
- **AC6**：每一个通知类型都属于且只属于一个分类（单元测试覆盖全部枚举值）

#### 影响面

- **后端：** 新增用户推送设置存储（2026-10-13 拍板：**只存「关闭」的分类，没有记录即为开启**；以后新增分类，存量用户自动默认开启，无需补数据）；读写接口（照 `PATCH /api/v1/me` 的模式）；通知类型 → 分类的映射（代码内常量）
- **推送闸门：** 在 `NotificationService` 中**落库与加角标之后、调用 pusher 之前**判断「该用户是否关闭了这一分类」，覆盖 `send`、`sendWithCopy`、`sendInteraction` 三条路径；**`OpsNotificationDispatcher` 单独再判断一次**（它不经过 `NotificationService`）。闸门不放在 `NotificationPusher` / IM 客户端层（那一层拿不到通知类型，且是异步）
- **开发须知：** 增加一条单元测试，断言 `NotificationType` 的每个枚举值都在映射表里——以后任何分支新增通知类型，没指定分类就会测试失败
- **App：** 新增通知设置页；设置页「通知」行改为入口
- **注销：** 推送设置随账号注销显式清理（users 行只匿名化，不能靠级联）

### 3.2 收藏（FR-151）

#### 已确认项（2026-10-12 / 10-13 拍板）

**收藏什么**
- **帖子**：公开的 Diary / Moment / Tips
- **场所**：宠物友好场所（2026-10-13 拍板与帖子收藏一起新建）

**入口**
- 帖子：**内容详情页底部操作栏**，与点赞、分享卡同排（2026-10-17 UI 流程更正：③ 送礼定稿的送礼按钮在正文后的礼物区，不在操作栏）；Feed 卡片上不加
- 场所：**场所详情页右上角收藏按钮，与「⋯」（举报）按钮并排**（2026-10-13 拍板；2026-10-17 UI 流程更正：代码中分享按钮在正文里、不在右上角，原写「与分享按钮并排」），不占正文、不与底部「打卡」主按钮抢视觉
- 未登录用户点收藏：沿用点赞的处理，提示登录
- **收藏成功反馈**（2026-10-17 UI 流程拍板）：收藏时 Toast 提示可在「我的」查看；取消收藏不提示，按钮变回即可；收藏 / 取消失败时按钮弹回并 Toast

**我的收藏**
- **入口：「我的」页「Postinganku」区块改为「发布 / 收藏」两个 Tab**（2026-10-13 拍板），「发布」即现有的我的发布列表，「收藏」为我的收藏
- 「收藏」Tab 内再分**帖子 / 场所**两个子分类（分段切换）
- **隐私提示：**「收藏」Tab 标签旁带一个小锁图标，并在列表顶部写「仅自己可见」，避免用户误以为收藏和发布一样对外公开；**他人主页的帖子区不出现「收藏」Tab**
- 列表按**收藏时间倒序**；帖子显示首图、标题 / 正文摘要、作者；场所显示首图、名称、类型、地址

**不可见的内容**
- 帖子被作者删除、运营下架、作者注销、举报预处置中，或我与作者有拉黑关系时：收藏列表**保留这一条**，显示「内容已不可见」，可以手动移除（2026-10-17 UI 流程拍板：**点不可见条目弹出底部抽屉，内含「从收藏中移除」**，移除后 Toast）；内容恢复可见后自动恢复正常显示
- （原写法「帖子转私密后」不适用：现在没有发布后转私密的功能）
- 场所被删除或下架时同样处理（2026-10-13 拍板）：保留这一条，显示「**场所已不可见**」、图片置灰，可手动移除；场所恢复后自动恢复正常显示

**计数与通知**
- 帖子收藏数**只对作者本人展示**（2026-10-13 拍板）：作者看自己帖子的**详情页**时，在点赞数旁显示「🔖 N 收藏」并带小锁图标（提示仅自己可见）；其他人看同一帖子时不显示这一项；「我的发布」列表卡片上不显示
- 场所收藏数**本版本不展示**（2026-10-13 拍板），数据照常记录，供以后做「最多人收藏的场所」等用途
- 被收藏**不通知作者**
- 帖子作者得少量**成长值**：被收藏 +2，与被赞 / 被评论共用每日 50 上限（由 ① 实现，本分支只发事件）
- **取消收藏扣回**作者的这 2 成长值（只扣当初实际入账的部分）；同一个人对同一条帖子，收藏成长值**终身只发一次**（2026-10-13 拍板，与点赞的防刷规则一致；已同步 ① PRD 扣回规则表与 AC14a）。**用户从收藏列表移除「已不可见」的条目时，不扣回作者成长值**（2026-10-14 拍板，与 ①「内容下架不扣被收藏成长值」一致）：实现上移除不可见条目**不发** `ContentUncollectedEvent`，① 无需改动
- **可以收藏自己的帖子，但不得成长值**（2026-10-13 拍板，与自赞、自评不计分同一原则）；作者看到的收藏数**不计自己这一次**；自己收藏自己的帖子**照常发** `ContentCollectedEvent`（1.4.2「第一次收藏内容」里程碑也要用），由 ① 在收藏人 = 作者时不入账
- **场所被收藏不发成长值**（2026-10-13 拍板）：场所价值主要来自场所本身，热门场所会让创建者持续拿分；创建者已有打卡里程碑等激励

**推荐**
- 收藏行为本版本**只记录，不接入首页推荐算法**

#### 边界与不做项

- 不做收藏夹分组 / 自定义收藏夹
- 不做收藏列表搜索
- 不在 Feed 卡片上加收藏按钮
- 不做「谁收藏了我的帖子」列表

#### 验收标准

- **AC7**：在帖子详情页点收藏，按钮变为已收藏，「我的」页「Postinganku → 收藏 → 帖子」最上方出现这条；再点取消，列表中移除
- **AC7a**：未登录用户在帖子详情页或场所详情页点收藏，提示登录（与点赞一致）
- **AC8**：在场所详情页点收藏，「Postinganku → 收藏 → 场所」出现这个场所
- **AC8a**：「收藏」Tab 带锁图标、列表顶部有「仅自己可见」；看他人主页时没有「收藏」Tab
- **AC9**：收藏的帖子被作者删除后，收藏列表里这条显示「内容已不可见」，可以移除
- **AC9a**：收藏的场所被下架后，收藏列表显示「场所已不可见」、图片置灰，可以移除；场所恢复后正常显示
- **AC10**：作者看自己帖子的详情页能看到收藏数（带锁图标），其他人看不到；作者自己也收藏了这条时，收藏数不计自己
- **AC11**：A 收藏 B 的帖子，B 得 2 成长值、不收到通知；B 当天被动成长值已满 50 时不入账
- **AC11a**：作者收藏自己的帖子，没有成长值流水
- **AC11b**：A 对 B 的帖子「收藏 → 取消 → 再收藏」，B 的成长值最终 +0；场所被收藏，创建者没有成长值
- **AC11c**：B 的帖子被下架后，A 从收藏列表移除这条「内容已不可见」的条目，B 的成长值不变
- **AC12**：收藏不影响首页推荐排序

#### 影响面

- **后端：** 新增帖子收藏表（user_id, post_id, created_at，唯一键）与场所收藏表（user_id, place_id, created_at，唯一键）；收藏 / 取消 / 列表接口；收藏数实时 COUNT（与点赞一致，不加冗余计数列）；列表读取时判断内容可见性（作者注销、举报预处置不发事件，必须读时判断）；帖子详情与场所详情接口返回「我是否已收藏」，帖子详情另返回（仅作者本人可见的）收藏数
- **事件：** 发 `ContentCollectedEvent(postId, collectorId, authorId)` 与取消收藏事件，供 ① 成长值入账 / 扣回、1.4.2「第一次收藏内容」里程碑使用
