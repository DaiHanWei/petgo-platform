真钱渠道只有 QRIS（FR-100）

真钱侧不做多渠道选择器。复用 V1.1.0 FR-43 通用支付组件。

⚠️ 两处文档口径不一致，本设计取较新者：
· v1-1-0PRD.md FR-43（07-08）写「QRIS、DANA」
· Roadmap.md 1.1.0（07-15 更新）写「目前仅支持 QRIS，DANA 尚未接入」

不支持 GoPay/OVO 直连、不支持银行转账/VA。但 QRIS 本身可被各家 e-wallet 扫码，副标题需说清这点，避免用户误以为不能用 GoPay。

PawCoin 可购买实物 · 混合支付（FR-100A 规则 2）

2026-08-10 产品拍板：PawCoin 可用于购物，但须增加使用规则。（覆盖设计侧原「首版不可」建议）
  • 余额优先全额抵扣，差额由 QRIS 补足，不阻断下单
  • 为什么支持混合：PawCoin 余额主要来自退款转入（多为零头）与 4 个固定充值档位。若要求整单 PawCoin，绝大多数余额将无法用于实物商品，这个能力等于白开
  • 结算页必须同时展示两段金额（抵扣多少 / 还需付多少），不能只显示一个总数
  • 单笔 PawCoin 支付上限 Rp 1.000.000（AB-6D 可配，OQ-33 待财务确认）。用途是故障/欺诈爆炸半径 + DEP-7 监管姿态，不是控浮存——限制消费只会让浮存降得更慢（见 .decision-log L-7）。客单约 Rp 285.000，该上限几乎不触发，定低反而有害

⚠️ 防套现是这条规则的根（FR-100A 规则 1）

PawCoin 支付的部分，退款只能退回 PawCoin。

FR-50D 规定 PawCoin 不支持一般性提现。但实物商品可以退货——若允许退真钱，就形成
充值 PawCoin → 买实物 → 申请退货 → 退回真钱
的路径，等于变相提现，直接击穿 FR-50D。

所以结算页就要把这句话告诉用户（页面中部蓝色提示条），不能等到退款时才说。
  • 混合支付订单按原支付比例拆分退款：PawCoin 段只退 PawCoin，QRIS 段仍可选退真钱（FR-43D）
  • 该拆分天然保证 用户拿回的真钱永远不超过其投入的真钱

运费与免运（FR-99）

  • 运费为「配送方式 × 区域」固定值表（后台 AB-11C），首版不接承运商实时计费 API
  • 理由：首发仅 Jabodetabek，区域差异小，固定表足够，可省一整条 API 工期
  • 免运抵扣展示为独立负数行，让用户看见省了多少，而不是直接把运费写成 0
  • 超重/超体积附加费首版不做——SKU 上限受控，最大件为 7.5kg 级狗粮，差异由固定表吸收

开封不退的第 2 处明示（FR-104）

三处明示中的第二处（详情页 → 结算页 → 退货申请页）。放在提交按钮上方，确保用户在付款前看到，而不是事后在规则页里找到。

提交 ≠ 扣款

  • 「Buat Pesanan」= 创建订单 + 锁定库存 + 进入待支付
  • 此时尚未扣款；待支付超时 60 分钟后自动取消并释放库存
  • 60 分钟明显长于兽医咨询的限时支付窗口——实物购买的决策节奏不同，沿用短窗口会造成大量误失效订单
