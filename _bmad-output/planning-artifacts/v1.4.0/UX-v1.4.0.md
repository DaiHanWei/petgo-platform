## §1 设计 token —— 与线上代码一致 ✅（顺带更正一条过期台账）

| 来源 | 品牌主色 |
|---|---|
| 原型 `shared.css` | `--color-brand-primary: var(--violet-500)` = **`#845EC9`** |
| 线上 `petgo_app/lib/core/theme/colors.dart:19` | `static const Color mint = Color(0xFF845EC9);` |

**两者一致，无需换算。** `colors.dart` 的常量名虽仍叫 `mint`，值已是 violet-500——文件里注释明写「原型 `#845EC9` 体系，常量名沿用 `mint*` 不改，业务代码照旧编译」。

> ⚠️ **`CROSS-STORY-DECISIONS.md` 的 F8 已过期。** 它写「UX 品牌真相 = `colors.dart` 薄荷绿 `#7FD1AE`」，那是 2026-06-04 换肤时的结论；此后已再次改为 violet，`#7FD1AE` 现仅存于 `momoBody`（吉祥物色）。**F8 的「真相在 `colors.dart` 而非 UX markdown」这条方法论仍然成立，只是它引用的具体色值需要更新。**

原型 `shared.css` 的 `:root` 是 fallback，声明「值取自 `1.项目总述/UI&UX/imports/tokens.css`，勿手改」。各页另有 `<link>` 指向该 tokens.css（**仓库内不存在，15 页全部命中**），脱离源目录打开时由 fallback 兜底，渲染正确。

## §3 08-15 拍板产生的偏差（原型早于决策）

### 3.1 FR-108 出局，牵连两屏

**`decision-log` C-11：FR-108 健康记录触发复购整体挪 Roadmap 1.2.0。**

| 屏 | 处置 |
|---|---|
| `09-Diary复购触发卡.html` | 🚫 **整屏移出本版本范围**，随 FR-108 顺延 1.2.0。不拆 story、不实现 |
| `01-Toko首页-有复购触发.html` | ⚠️ **需改版**：区域① 现画了**两张卡**——一张 FR-108（`Jadwal obat cacing Mochi hampir tiba`，驱虫）、一张 FR-109（`Makanan Mochi diperkirakan habis`，粮量）。**本版本只保留 FR-109 那张**，驱虫卡删除 |

> **连带影响区域① 的布局：** PRD 说区域① 最多 2 张卡。FR-108 移出后**只剩 FR-109 一个来源**，跨类型优先级本版本不必定（SPEC-16 已据此缩小范围），但**多个 Makanan SKU 同时见底时的排序仍需定**。原型未覆盖该情形。

### 3.2 `08-退货申请.html` 缺两处（C-12 / FR-104A）

| 缺口 | 需补 |
|---|---|
| **去程运费提示** | 原型只标了**回程**运费归属（每个退货原因右侧写 `Ongkir retur ditanggung TailTopia / pembeli`），**没有任何去程运费说明**。C-12 定的是「**整单退 → 去程运费全退；部分退 → 不退**」，且 PRD 要求**在退货申请页明示**——这是堵免运门槛凑单-退货套利的唯一告知点，缺了会变成客诉源 |
| **同订单单申请的置灰态** | C-12 定「同一订单同时仅允许一张进行中的退货申请」。原型无该状态。需要一个「已有退货申请处理中」的入口置灰态（在订单详情页，非本屏） |

> **交互建议（待 UX 确认）：** 勾选状态在「全选」与「部分选」之间切换时，去程运费行应**实时变化**（全选 → `Ongkir dikembalikan`；部分选 → `Ongkir tidak dikembalikan`），让用户在提交前就看见代价，而不是提交后才知道。

### 3.3 `10-档案推荐区.html` 的降级态正好是 L-9 的入口

原型降级态画的是 **`Lengkapi berat badan Bruno`（补全 Bruno 的体重）+「Lengkapi profil」按钮**——**明确要的就是体重**。

这与 `decision-log` **L-9** 完全咬合：`PetProfile.java` 当前**没有体重字段**，FR-109 因此恒不触发。**原型预设了体重字段存在**，所以：

1. **L-9 的加列 story 必须排在 FR-107/FR-109 之前**，否则这张降级卡点进去无处可填
2. 这张卡就是 PRD 说的「存量用户回填引导」的落点，**不需要另设计入口**

### 3.4 换货（C-13）—— 原型未受影响 ✅

全套 15 屏**没有任何换货相关界面**（无换货入口、无换货状态、无补发流程）。C-13 砍换货**不产生任何原型返工**。仅需在商品详情页的退货规则标识文案上，把三值改为 `可退 / 开封不退 / 不可退`。

## §5 UX 设计需求（UX-DR，供 epics 步骤取用）

- **UX-DR6**：新增**地址簿列表页**（≤20 条 + 默认地址标识 + 编辑/删除 + 删除默认后的自动升级提示）
- **UX-DR7**：补齐**订单详情其余 6 态**的状态标签、主操作按钮与文案
- **UX-DR8**：补齐 **Toko 首页 2 种用户状态**（已登录未建档的建档引导卡复用 FR-0G，不新建；状态 B/C 的区域①② 整区不渲染）
- **UX-DR9**：补齐**购物车空态**与**商品评价列表空态**（`不伪造或预填评价`）
- **UX-DR10**：商品详情页退货规则标识文案改二义三值 `可退 / 开封不退 / 不可退`（C-13）
- **UX-DR11**：**「开封不退」三处明示的一致性核查** —— PRD 要求商品详情页、结算页、退货申请页三处都明示。原型已在退货申请页做到（第 3 处），需核对前两处是否也有
