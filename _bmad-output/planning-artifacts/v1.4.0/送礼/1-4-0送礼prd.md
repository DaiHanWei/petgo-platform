## 1. 版本目标

1. **给用户一个表达喜爱的新方式**：刷到可爱的宠物，除了点赞评论，还能送一份礼物。
2. **新增一条平台收入**：送礼金额**全部是平台收入**，收礼方不分账。
3. **给 Tailrent Level 提供付费成长路径**：送礼人和收礼宠物的主人都得成长值。

**核心指标：** 送礼付费用户数 · 送礼客单价 · 送礼渠道占比（PawCoin / QRIS）· 收礼宠物数 · 送礼人复购率（30 天内再次送礼）

## 3. 功能与需求

### 3.1 送礼（FR-148）

#### 已确认项

**送给谁、在哪里送**（2026-10-12 拍板）
- 礼物**送给宠物**（不是送给人、也不是送给某条内容）
- 入口一：该宠物的 **Diary Tab**（站内访客视图 `/pets/:petId`）页头的「送礼」按钮
- 入口二：**Diary 类型内容详情页**的礼物展示区「送礼」按钮，送给这条内容关联的宠物；**关联多只时先选送给哪只**。Moment / Tips 详情页没有送礼入口
- 入口三（2026-10-17 UI 流程拍板）：该宠物**礼物页**（访客视角）底部固定「送礼」按钮；主人看自己宠物的礼物页不显示
- **不能给自己的宠物送礼**：自己的 Diary Tab 和自己的 Diary 详情页不显示「送礼」按钮
- **只读宠物（月租到期）可以收礼**；已删除的宠物不能
- **拉黑规则只拦单向**（2026-10-13 拍板，与内容详情页现状一致）：**送礼人拉黑了宠物主人**时，看不到「送礼」按钮，接口也拒绝；**宠物主人拉黑了送礼人**时，不额外拦截。注意：Diary Tab 访客视图本身已双向拦截（被对方拉黑时打不开），所以这种情况下只可能从 Diary 详情页送出；礼物照常送达，**给宠物主人的通知按现有互动通知的屏蔽规则处理**（与点赞通知一致，被拉黑者的互动不通知）
- **宠物主人被封号 / 停用时，仍可以给这只宠物送礼**（2026-10-13 拍板）：礼物照常记在宠物名下、主人照常得成长值和通知，恢复账号后可见。实际入口只剩他人 Feed / 收藏里的 Diary 详情页（访客视图与 H5 名片对封号账号显示失效）。**主人注销**时，按注销流程宠物档案已被删除，属于「已删除的宠物不能收礼」，不能送

**礼物目录**
- 礼物、图标、价格由**运营后台配置**（AB-35）
- **专属礼物**是单独的礼物，**送礼人的 Tailrent Level 达到要求才能看到、才能送**（第一批：绿段位 Lv5 起；第二批：紫金段位 Lv15 起；具体每个礼物的门槛在后台配置）
- **未解锁的专属礼物不展示具体礼物**（2026-10-13 拍板）：送礼面板礼物网格的**最后放一个「专属礼物」小区块**，只显示一个锁和「Lv5 解锁更多礼物」，不透露是什么礼物，保留神秘感。用户的等级决定区块文案：Lv1–4 显示「Lv5 解锁更多礼物」；Lv5–14 已能看到第一批专属礼物，区块显示「Lv15 解锁更多礼物」；Lv15 及以上全部解锁，不显示区块。点区块跳到等级页（① FR-144）。区块里的解锁等级取「下一批尚未解锁的专属礼物中最低的等级门槛」，随后台配置变化

- **按收礼宠物的物种排序**（2026-10-13 拍板）：后台给每个礼物标**适用物种**（猫 / 狗 / 其他，可多选；都不选视为「通用」）。送礼面板按价格档从低到高分组；**每个档内，适用于收礼宠物物种的礼物排最前，通用礼物其次，其余最后**；同组内按后台排序值。⚠️ 现有宠物物种只有「猫 / 狗 / 其他」三类，蛇、仓鼠、乌龟、兔子等都属于「其他」，彼此之间无法再细分排序；要做到更细，需先扩展宠物物种分类（不在 1.4.0 范围，**已排入 1.4.4「扩展宠物物种分类」**）
- Rp1,000 与 Rp5,000 档单个只能用 PawCoin 付（QRIS 最低 Rp10,000，按总价判断，买多个凑够即可用 QRIS）

**送礼流程**
1. 点「送礼」→ 弹出**送礼面板**：礼物网格（图标、名称、价格），默认选中排序后的第一个
2. 选数量：**支持一次送多个**（2026-10-13 拍板）：快捷按钮 ×1 / ×5 / ×10，默认 ×1；旁边 +/− 微调，**最多 ×99**（防手误）；总价实时显示，如「🦴 × 5 = Rp5,000」
3. 底部显示总价，点「送出」→ **送礼面板收起**，弹出现有的**选渠道抽屉**（`PayChannelPicker`，header 放所选礼物摘要），QRIS / PawCoin 二选一（不支持混合支付，沿用虚拟商品单渠道规则）。两个抽屉依次弹、不叠层（设计规范：抽屉只一层）；关闭选渠道抽屉回到送礼面板并保留选择（2026-10-17 UI 流程拍板）
   - PawCoin 扣款期间选渠道抽屉保持打开、主按钮转圈，成功后关闭；失败时抽屉保留可重试
   - 点「先充值」充值完成后，自动重新打开选渠道抽屉、礼物与数量保留（参照 `vet_timed_pay_page` 的 await 写法；现状通用组件充完不回原流程）
   - QRIS 过期 / 被拒时用 `onAborted` 弹提示「Pembayaran kedaluwarsa. Coba lagi.」/「Pembayaran gagal. Coba lagi.」（与 ② 名额支付一致）
   - 解锁后的专属礼物在网格里价格档之后单独一组「Eksklusif」，第一批在前、第二批在后，锁区块在最后
4. PawCoin：当场扣款、当场送达；QRIS：弹出二维码，付款成功后送达
5. 送达后：面板关闭，播放一个 **1–2 秒的送出动效**（2026-10-13 拍板；所有礼物共用一套：礼物图标飞向宠物头像 + 少量粒子，送多个时数字「×N」跳动），随后 Toast「已送给 Mochi 🎁」

**支付规则**（2026-10-12 拍板）
- QRIS 和 PawCoin 由送礼人自选
- **QRIS 单次最低 Rp10,000**（按总价判断）：总价低于 Rp10,000 时，选渠道抽屉里 QRIS 置灰，只能用 PawCoin，并提示「充值 PawCoin 送礼更方便」
- PawCoin 余额不足时，沿用现有处理：PawCoin 行置灰、可点「先充值」
- 送礼金额**全部为平台收入**；收礼宠物的主人**不获得任何现金或可用余额**，只得到成长值和礼物展示
- **虚拟礼物送达后不退款**（付款前在送礼面板底部以小字说明）；唯一例外是付款后无法送达，见下方「异常情况」

**成长值**（规则由 ① 实现，本分支只发事件）
- 送礼人：每 Rp1,000 = 5；收礼宠物的主人：每 Rp1,000 = 4；按总价换算、不设上限
- 送礼成功后发 `GiftSentEvent`，① 的成长值引擎据此入账

**我的送礼记录**（2026-10-13 拍板）
- 入口：「我的」→ **PawCoin 钱包页**里新增「送礼记录」入口（与钱相关的放在一起，不新占「我的」页位置）
- 只列自己**送出**的礼物，时间倒序；每行：时间、收礼宠物（头像 + 名字）、礼物 × 数量、金额、支付方式、状态（已送达 / 等待付款 / 已退回 PawCoin）
- 点宠物头像跳到它的 Diary Tab；宠物已删除时显示「该宠物已不存在」、不可跳转
- 收到的礼物不在这里重复展示（看自己宠物的礼物墙）
- PawCoin 钱包页流水：送礼扣款显示「Kirim hadiah」、退回显示「Hadiah dikembalikan」（App 按关联类型显示，钱包服务命名不变；2026-10-17 UI 流程拍板）。入口仍在钱包页（「我的」页无钱包入口，接受深度，退回有通知直达）

**异常情况**
- QRIS 付款窗口内（60 分钟）用户离开页面，之后付款成功：礼物照常送达，收礼方照常收到通知，送礼人在「我的送礼记录」里能看到
- QRIS 未付款过期 / 失败：不送达，不扣钱
- **QRIS 付款期间收礼宠物被删除、主人注销或送礼人拉黑了主人**，付款成功后无法送达（2026-10-13 拍板）：**自动把等额 PawCoin 退回送礼人的钱包**（退给自己，不是转给他人，不违反「PawCoin 不可转让」），并发一条站内通知说明原因，如「你送给 Mochi 的礼物未能送达（该宠物已不存在），25,000 PawCoin 已退回你的钱包」；送礼人**不得**送礼成长值；后台送礼记录标为「已付款未送达」。不采用「只收款不告知」：存在消费者保护合规风险，且发生概率极低，不值得

#### 边界与不做项

- 不做匿名送礼（送礼人公开）
- 不做礼物转赠、礼物兑换现金或 PawCoin
- 不做送给人 / 送给某条内容（只送给宠物）
- 不做 QRIS + PawCoin 混合支付
- 不做送礼排行榜（全站榜）
- 不做直播式的礼物特效全屏播放

#### 验收标准

- **AC1**：在别人宠物的 Diary Tab 和 Diary 详情页都能看到「送礼」按钮；自己宠物的页面看不到；Moment / Tips 详情页看不到
- **AC2**：关联两只宠物的 Diary 详情页点「送礼」，先选送给哪只，再进入送礼面板
- **AC3**：Lv4 用户在送礼面板看不到任何专属礼物，网格最后有一个「Lv5 解锁更多礼物」的锁区块，点击进入等级页；升到 Lv5 后第一批专属礼物出现在网格里，锁区块变为「Lv15 解锁更多礼物」
- **AC3a**：给猫送礼时，Rp1,000 档里标了「猫」的小鱼干排在最前，通用礼物其次，只标「狗」的骨头排最后；给狗送礼时顺序相应调整
- **AC4**：总价 Rp5,000 时 QRIS 不可选，只能用 PawCoin，并有充值提示；总价 Rp10,000 时两种都可选
- **AC5**：用 PawCoin 送 Rp10,000 礼物：余额扣 10,000，礼物立刻出现在对方宠物的礼物墙，送礼人 +50 成长值、对方主人 +40
- **AC6**：用 QRIS 送礼，付款前关闭 App，之后完成付款：礼物照常送达，对方收到通知
- **AC7**：QRIS 二维码过期未付款：不送达、没有任何成长值和通知
- **AC8**：同一笔 QRIS 回调和轮询同时到达，礼物只送达一次
- **AC9**：A 拉黑了 B，A 看不到 B 宠物的「送礼」按钮，直接调接口也被拒绝；B 拉黑了 A，A 在 B 的 Diary 详情页仍可送礼，礼物送达，B 不收到通知
- **AC10**：给只读宠物送礼可以成功
- **AC10a**：发起 QRIS 送礼后、付款前宠物主人删除了这只宠物，付款成功后礼物不送达，送礼人钱包到账等额 PawCoin、收到说明原因的站内通知，没有送礼成长值
- **AC10b**：送礼人在 PawCoin 钱包页进入「送礼记录」，能看到每一笔送礼的状态；QRIS 等待付款的显示「等待付款」，付款后变为「已送达」；未送达退回的显示「已退回 PawCoin」

#### 影响面

- **后端：** 新增礼物目录表、送礼订单表（送礼人、收礼宠物、宠物主人、礼物、**礼物名称 / 图标 / 单价快照**、数量、总价、渠道、payment_intent、状态、幂等键）、礼物汇总表（按宠物 × 礼物计数，供礼物墙读取）；付费流程照 `KeepsakePurchaseService` 的范式实现，但**幂等键按每一笔送礼生成**（Keepsake 的键是「一个业务对象只买一次」，不适用于可重复送的礼物）；PawCoin 渠道调用 `wallet.debit(SPEND)`，**命名中不得出现 gift / transfer 等字样进入钱包服务**（CI 守卫）；QRIS 渠道按现有口径不记总账

## 6. 开发注意与接口约定

### 6.1 合并顺序

**① Tailrent Level → ② 多宠物 → ③ 本分支 → ④ 推送开关与收藏**（详见 ① PRD §6.1）。本分支依赖 ① 的等级与成长值、② 的内容多宠关联，排第三；①② 合入 dev 后，跨线衔接在从 dev 切出的对齐分支上做（merge 本分支，不 rebase，见 ① PRD §6.1）。

### 6.2 本分支使用、由其他分支提供的部分（本分支不要再做）

| 内容 | 提供方 | 本分支只需要 |
|---|---|---|
| 支付用途 `GIFT` | ① 的支付用途约束迁移 | 直接使用，**不改约束** |
| 通知类型 `PET_GIFT_RECEIVED`、`GIFT_UNDELIVERED_REFUND` | ① 的通知类型约束迁移 | 写文案与触发，**不改约束** |
| 成长值入账 | ① 监听 `GiftSentEvent` | 只发事件，**不写成长值逻辑**。`GIFT` 不走 ① 的「消费返成长值」，由 ① 保证不重复计算 |
| 专属礼物的等级判断 | ① `GrowthQueryService.getLevel(userId)` | 调用即可；虚拟号返回「不参与」，视为不能送专属礼物 |
| 后台抽屉「收送礼记录」页签 | ① 加页签头和空容器 | 只往容器里填内容，**不改页签头** |
| 内容关联的宠物 | ② `ContentPetQuery.petsOf(postId)` | Diary 详情页取关联宠物 |
| 宠物信息与主人 | ② `PetQueryService.get(petId)` | 判断宠物是否存在、取主人；**不校验只读状态**（只读宠物可以收礼） |
| 互动通知聚合 | 1.3.4 follow-notify 的 `sendInteraction` | `aggregateKey = GIFT:PET:{petId}` |

### 6.3 本分支对外提供的接口

| 接口 | 字段 | 调用方 |
|---|---|---|
| `GiftSentEvent` | `giftOrderId, senderId, receiverOwnerId, petId, totalAmount` | ① 成长值入账（字段已在 ① PRD §6.4 约定，**不要改字段**） |
| 通知类型 `PET_GIFT_RECEIVED` 的触发 | — | ④ 映射到「礼物」推送分类 |

### 6.4 开发须知

- **不要在 `PawCoinWalletService` 里加任何 gift / transfer 命名的方法**，也不要给钱包方法加第二个 userId 参数——CI 守卫测试会拦。送礼的 PawCoin 扣款就是一次普通的 `debit(SPEND)`，礼物逻辑全部放在送礼模块
- 付款期间宠物被删等原因导致无法送达时，PawCoin 退回走普通的 `credit`（退给送礼人自己），同样不涉及跨用户。**总账口径须与财务确认**：QRIS 实收的现金转成 PawCoin 余额，应参照充值记 CASH_IN → FLOAT_LIABILITY（现有 QRIS 直付不记总账，这里是新出现的入账点）；PawCoin 付款的退回则冲回原 PLATFORM_REVENUE
- `ContentDetailResponse`、`VisitorStats`、`CardPageController` 在 1.3.4 `app-ux-revamp` 分支也改过，1.3.4 合并后再在其基础上加字段
