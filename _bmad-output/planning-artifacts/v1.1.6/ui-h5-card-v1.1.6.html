定稿方向：剪贴簿 / 贴纸拼贴。「成长记录」本质上就是一本剪贴簿，所以整页做成手作贴纸簿。照片簇取代单张拍立得（主张 + 右后 + 左下前三张交叠、各自角度，主张左上角压一片和纸胶带）；快乐时刻是真交叠拼贴（4 张不同尺寸角度叠成一块）；手绘涂鸦层（指向主照片的箭头 + 手写「si bos」、名字下的手绘下划线、爱心、小星、便签上的回形针）；自述加荧光笔标记；故事数字做成贴在纸上的票根（原为三个悬空色圆——全页唯一不属于剪贴簿语汇的元素，显空且突兀）；区块标题是胶带小片。
CTA 吸底悬浮：不随内容长度浮动、滚动全程可见，顶部渐变遮罩让内容自然淡出，内容底部留 96px 并用 env(safe-area-inset-bottom) 兜底。底色 violet/50 #F8F2FF + 字色 violet/600 #6C48AE（均取自 tokens.json，对比 6.03:1 过 AA）。
行为（FR-92 §④，覆盖 V1.0.0 FR-14 双 CTA）：已装 App → Deep Link 打开该宠物 Diary 页；未装 → 跳对应应用商店。原 FR-14 的两个 CTA 行为完全相同，是两套文案一个行为，已合并。

空态按「刚开本子」来设计，不是把模块藏掉。一本刚开始记的剪贴簿本来就是「一张照片 + 一堆等着贴的空相位」——所以照片簇里那两张缺失的照片保留为虚线空相位，配手写「baru mulai!」，让"空"读成刚起步而不是坏了。
降级逻辑全部对齐线上 card.html 的 th:if：① hasMilestones=false → 徽章条只剩空位槽，且票根里的「Tonggak」整列隐藏（剩 2 列，不是补 0）；② 最近里程碑动态整段不渲染；③ hasMoments=false → 照片流换成占位，文案取线上原文 Unduh App untuk lihat lebih banyak konten；④ 本例无 intro，该行不占空间；⑤ 无主人昵称 → 陪伴天数走第二套文案（此处已并入贴纸与副行）。

card_gone.html · ⚠️ 修一个线上真实 bug：这一页目前是英文的（“This card is no longer available” / “Discover pets on TailTopia”），而 card.html 全篇印尼语——同一条链接、同一个用户，换页就换语言。本稿给出印尼语版。
视觉沿用剪贴簿语汇：照片被撕走、只剩四个相角和一小片胶带残痕——这是相册里最直白的「这里原本有东西，现在没了」。安全口径不变：对「不存在 / 已删除 / 已注销」三种情况统一响应、不泄漏 token 曾否存在（防枚举），因此文案不区分具体原因。

方向存档（A / B / C / D / F 均未选中，不再画屏）：
A · 温暖浅色纪念卡——圆角卡片 + 柔和阴影 + 居中构图，最安全但最没记忆点，发到 WhatsApp 里与其它宠物 App 的分享页难以区分。
B · 海报 × 成长护照（2026-07-27 选中 → 2026-08-06 否）——落戳概念成立，但只用紫色一种、视觉单调普通，且把照片压到 118px、放弃了宠物脸这个最强钩子。
C · 收藏卡 / 证件卡质感——暗色烫金全息，收藏感最强但把宠物做成「卡牌」偏游戏化，与「陪伴记录」调性有距离，暗色底在 WhatsApp 缩略预览里辨识度也差。
D · 大图沉浸式（2026-08-06 提出）——照片全幅 392px 做主视觉，情感冲击最直接、用足四个品牌色；未选中原因：与 E 相比缺少「实物感」，本质仍是常规的图文落地页排版。
F · 彩色分区杂志（2026-08-06 提出）——六个满幅色块各配一个品牌色，滚动即色彩节奏，品牌一致性最好、工程最省；未选中原因：色块分区偏「营销物料」，离宠物成长记录的私人感最远。
