## 1. A-1【必做，1.1.6 开发期内】FR-68 顶置坑位必须套用拉黑过滤

**这是重编号留下的唯一一个真缺陷风险，且不能等上线后再补。**

**问题：** 1.1.4 的 FR-94（用户拉黑）定义了一条通用规则——**「凡是向该用户展示他人内容的位置，一律套用同一层拉黑过滤；若某运营位命中被拉黑作者，则对该用户视为该位为空，按该功能自身的『位为空』回退逻辑处理」**。

但本版本 `改版1-1-6prd.md` 的 **FR-68 正文里完全没有提这件事**——它只定义了两条回退触发条件：「坑位为空（当前无生效配置）」和「顶置期间内容被下架（作者删除 / 举报判违规下架 / 作者账号被封禁）」。**拉黑不在其中。**

这个缺口是 2026-08-11 解耦时刻意留下的：为了保证两个版本零耦合，当时没有去改本版本 FR-68 的正文。

**不做的后果（很具体）：** 用户拉黑了某个账号，**首页顶置位照样每天给他看这个账号的内容**。拉黑功能在用户最显眼的那个位置失效——顶置位是首屏第一条，比 Feed 里任何位置都刺眼。研发只读 FR-68 不会知道要加这层过滤。

**为什么不能等上线后补：** 等 1.1.6 上线后才发现，就已经是线上缺陷了，而且要改代码。

**怎么做：**

1. 在 `改版1-1-6prd.md` FR-68 的「坑位为空时」条款后**补一条**：

   > **被拉黑作者的顶置内容（补充说明，2026-08-11 因版本重编号补入）**：若顶置内容的作者已被当前查看者拉黑（V1.1.4 FR-94），则对**该查看者**视为坑位为空，按上方「坑位为空」规则回退为普通内容填充；**不为该用户单独选替补顶置内容**，其他用户不受影响。这是 FR-94 已定义的通用规则在本坑位的落地，不是本 FR 新增机制。

2. 实现上**不需要新写过滤逻辑**——1.1.4 落地时已经在 Feed 查询里做了一层「按查看者隐藏」（拉黑 + 举报者隐藏合并的那一层），顶置内容的作者查询套同一层即可。

**补这一条不破坏解耦：** 1.1.4 届时已上线，这是**向后引用已上线版本**，完全符合「PRD 只向后引用」的既定约定。

**顺带核一遍其它「展示他人内容」的位置（本版本新增的）：**

| 位置 | 是否需要拉黑过滤 | 判断 |
|---|---|---|
| **FR-68 顶置坑位** | ✅ **需要** | 见上，必须补 |
| **FR-74 用户标签**（展示在头像/昵称旁四处：迷你主页预览卡 / 内容详情页作者区 / 评论区昵称旁 / Feed 卡片昵称旁） | ⚪ 不需要单独处理 | 标签挂在「用户」上，被拉黑用户的内容与评论本身已被过滤掉，标签随宿主一起消失 |
| **FR-93 Feed 卡片通栏化 / FR-71 图片展示** | ⚪ 不需要 | 纯渲染层改动，不参与候选池筛选，过滤在它们之前已完成 |
| **FR-92 宠物主页对外分享 H5** | ⚪ 不需要 | 无登录态访客视图，没有「当前用户」可用于过滤（FR-94 已明确排除该场景） |
| **FR-75 内容装饰标签** | ⚪ 不需要 | 同 FR-74，挂在内容上，宿主被过滤即随之消失 |
