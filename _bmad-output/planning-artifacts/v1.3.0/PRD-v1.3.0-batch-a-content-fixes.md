## 2. 里程碑业务现状（节选自母版 §2，作为 FR-111 逻辑变更的现状基线）

> 本节是里程碑模块**当前线上行为**的完整描述，作为本批次 FR-111 逻辑变更的现状基线。V1.0.0 PRD FR-42 已按本节订正（母版特殊处理，本文档不重复处理）。

**清单与维护方式**

- 清单为后端编译期常量（`MilestoneCatalog`，唯一事实源），运营不可编辑。猫 31 / 狗 31 / 通用 16，各含 1 个 S 级聚合里程碑「Lulus Pemula」（C-S16 / D-S16 / G-S9，6 项新手任务全完成自动解锁）
- 每个里程碑有稳定 code（`C-S1` 形式）、级别 S/M/L、触发类型三选一：系统自动（SYSTEM_AUTO）/ 用户打卡（USER_CHECKIN）/ 推送+当天发布（PUSH_PUBLISH）
- 展示标题一律在 App 客户端按设备语言取（en / id 双表），后端中文标题仅内部用、印尼语标题仅供 H5 分享页渲染；三处由跨库测试钉住，改任何里程碑文案须三处同步

**完成路径**

- **打卡类**：里程碑列表页点未完成徽章 → 底抽屉（徽章 + 标题 + 级别 + 说明文案）→「已打卡」关联一条本人成长日历内容（已关联过其它里程碑的内容置灰）/「去发布」跳发布页预选成长日历类型，发布成功后自动以新内容回填打卡（失败静默，可回列表页手动关联）
- **健康类四条（M3 疫苗 / M4 驱虫 / M5 看兽医 / M9 绝育）已取消打卡**：只能由健康记录录入 / 真人兽医咨询结束自动完成；列表页点这四条的未完成徽章**直接跳健康记录页并预选记录类型**，不弹抽屉。⚠️ 该规则按 code 后缀 M3/M4/M5/M9 判定，**通用宠物的 G-M1（看兽医）/ G-M2（健康检查）后缀不在集合内，仍是打卡类**——即取消打卡实际只对猫狗生效（本批次 FR-111 会修正这一漏网项，见下）
- **系统自动类**（建档、首图、首帖、被赞、被评、陪伴天数、记录条数、健康组合、新手毕业）：后端事件驱动，事务提交后异步落库
- **推送+发布类**（L1 生日 / L2 100 天 / L3 365 天）：提醒由 FR-40 / FR-41 推送承担，用户当天（生日 ±1 天）发布成长日历记录后自动完成

**庆祝页（所有级别共用一套，无级别分叉；本批次不改动视觉，仅供背景了解）**

- 全屏纯深色页（#141019）；渐变大徽章 + 徽章下沿级别小标签（L 金 / M 紫 / S 绿，这是级别差异的唯一视觉表达）；掉落彩纸循环；解锁瞬间一次短振动（原生通道，绕过系统触感开关）
- 内容：解锁标头 · 按 code 取的双语庆祝标题/正文（含宠物名占位）· 宠物名 + 完成日期胶囊 · KOLEKSI 已解锁合集预览（级别色圆点，两排放不下折叠「+N」）· 「分享到社区」按钮 · 「查看全部里程碑」入口
- 关闭方式：右上角 ×、左右滑动、点遮罩
- **分享产物是 H5 链接**（服务端渲染分享页，不可枚举 token，携带客户端本地化文案与合集级别串），所有级别都有分享按钮
- **已完成徽章点击 → 重温同一庆祝页**（含分享入口）

**庆祝触发时机**

- 打卡「已打卡」路径：关联成功后立即弹
- 「去发布」路径：发布成功 → 回填打卡 → 弹庆祝 → 关发布 sheet → 跳里程碑列表页
- 健康记录保存路径：后端完成为异步，App 保存后按 500 / 800 / 1200ms 三次重拉列表 diff 出新解锁；**三次都没拉到则静默、当场无庆祝**（解锁不受影响，但用户不会再被告知）。仅当所存类型有解锁可能时才轮询
- **同一操作同时解锁多条 → 只弹一次，取级别最高的一条**，其余由 KOLEKSI 圆点带过（健康路径已实装）
- 系统自动类里程碑在用户不在场时解锁（如被点赞）：**无庆祝**，仅通知中心留痕
- 健康记录保存无新解锁时不弹任何里程碑文案（2026-08-05 拍板）

**通知**

- L 级完成：通知中心 + 系统推送，点击深链到里程碑列表页
- S/M 级完成：只写通知中心、不推送（FR-76）
- 存量不回填；一次多条则写多条

## 3. 功能与需求

### 3.1 宠物年龄换算分享卡（FR-65）

**功能描述：** 将宠物年龄换算为人类年龄当量，生成卡片一键分享至 WhatsApp / Instagram Stories，驱动裂变拉新。**本版本仅支持猫、狗；其他宠物入口显示「暂不支持」**（无公认换算标准，且不同物种寿命差异过大，通用系数只能是娱乐数字，不上）。

**基建：** 复用 FR-73 卡片生成基建（`share_card_template.dart` / `share_card_preview_page.dart`：文字排版、水印能力（本卡不启用，见下）、9:16 + 1:1 双尺寸、系统分享面板）。本 FR 只替换内容模板。默认 9:16。

#### 换算规则（2026-08-26 调研结论）

**调研范围：** AVMA / AAHA 兽医协会换算指引（经 AKC、PetMD 转述）、AAFP + International Cat Care + AAHA 三方联合猫龄指引、UCSD Wang et al. 2020（*Cell Systems*）表观遗传时钟研究、消费级产品（Pedigree 年龄计算器、多家在线计算器）。

**结论：采用兽医协会的三段式分档模型，不采用 UCSD 对数公式。** 理由：① 三段式是 AVMA/AAHA/AAFP 共同背书、消费级产品普遍采用的口径，用户拿卡片去对照任何一家宠物网站都对得上；② UCSD 公式 `16 × ln(年龄) + 31` 只基于 104 只拉布拉多单一品种，AKC 亦指出其变量不足；且其结果反直觉（1 岁 = 31 人岁、2 岁 = 42），做社交分享会引发「算错了」的质疑而非传播。

| 物种 | 规则 | 依据 |
|---|---|---|
| 猫 | 第 1 年 = 15 人岁；第 2 年 +9（满 2 岁 = 24）；之后每年 +4 | AAHA / AAFP / International Cat Care 联合指引 |
| 狗 | 第 1 年 = 15 人岁；第 2 年 +9（满 2 岁 = 24）；第 3 年起按体型每年递增：**小型 +4 / 中型 +5 / 大型 +6 / 超大型 +7** | AVMA 基础口径（中型 +5）+ 主流按体型分档 |

- 体型分档（成年体重）：小型 < 9 kg · 中型 9–23 kg · 大型 23–41 kg · 超大型 > 41 kg。卡片生成时**用户四选一**，档位名旁标注体重区间辅助判断；不落档案字段、不持久化、不校验（娱乐工具）
- 不足整年部分按月线性插值；结果四舍五入取整，卡面展示「≈ N 人岁」
- 未满 1 岁按月龄比例（如 6 个月的猫 = 7.5 → ≈ 8 人岁）
- 宠物年龄按档案生日与生成当日计算；生日为建档必填完整日期，无缺失兜底

> Roadmap 原文「猫前 2 年各 ≈15 人岁（2 岁 = 30）」与所有调研来源不符，已按调研结论修正为 15 + 9。

### 3.3 内容详情页优化（FR-113）

#### 已确认项（2026-08-28 拍板）

1. **元素顺序**（自上而下）：作者行（发布时间移至作者名下方）→ 图片 → 文字 → 互动栏 → 评论区

3. ~~双击图片点赞~~ **2026-08-31 取消**——避免单击开灯箱被双击判定拖慢 300ms、且与灯箱内「双击=缩放」语义冲突；点赞只走互动栏
4. **时间显示**：发布超 7 天由相对时间改显示绝对日期
5. **互动栏与评论区操作体验重做**：现状点赞/评论按钮视觉差、点击热区小且操作繁琐，回复评论时评论区观感与操作流程差——互动栏视觉重绘 + 扩大热区，评论区视觉与回复操作流重设计（与 FR-114 回复态显式化联动），具体方案 UI 阶段出稿

### 3.4 评论体验优化（FR-114）

#### 已确认项

- 回复发布成功后自动展开该父评论回复区并滚动到新回复处

1. **评论点赞**：一级与二级评论均可点赞/取消，心形小图标 + 计数（新增 `comment_likes` 表——本 FR 唯一数据模型新增）

### 3.5 图片查看体验优化（FR-115）

**边界（已拍板）：** 只管点开后的大图查看器；FR-71 管 Feed 卡片层，互不覆盖。范围 = 详情页灯箱（**FR-112 场所照片复用本组件，FR-112 属于批次 B1，见 `v1-3-0prd-B.md`——本批次只需交付通用灯箱组件，不需要为场所场景特化**）；问诊病例图查看器与分享卡预览不在范围。

**现状：** 灯箱是普通页面（整页推入）：**保留系统状态栏与顶部 AppBar（返回箭头 + 页码），不是全屏沉浸态**，图片在剩余区域内 contain 显示；横滑翻页 + 捏合缩放 + 点击关闭。2026-08-28 用户实机对比小红书确认：问题在于「点开放大不是全屏放大」。

#### 已确认项

**全屏沉浸式查看（2026-08-28 拍板，对标小红书）**

- 点开图片 → 进入全屏沉浸态：隐藏 AppBar，内容延伸至状态栏区域（沉浸式，仅保留悬浮的关闭 × 与页码指示，如小红书顶部居中「1/9」样式），图片铺满屏幕宽度显示
- 捏合/双击放大时图片可超出屏幕、全屏平移查看
- 退出灯箱恢复正常系统栏

**配套交互（2026-08-28 拍板，全部通过）**

1. **下滑关闭**：单指下拖图片跟手、背景渐透明，过阈值松手关闭、未过回弹；已放大状态下滑为图内平移，不触发关闭
2. **过渡动画**：点缩略图图片从原位置放大飞入全屏，关闭时缩回原位（开关双向）
3. **双击缩放**：适应屏幕 ↔ 2.5 倍之间切换，以双击点为缩放中心
4. **放大态防误翻页**：放大时横滑为图内平移，平移到图片边缘后继续拖才切下一张
5. **加载态**：先显示已有缩略图（模糊过渡到清晰），失败给重试按钮
6. 保留：点击关闭、初始页为点击那张
7. **明确不做**：长按保存到相册——要保存只能走带水印的分享卡（盗用顾虑 + 相册权限 + 与分享卡定位冲突）
