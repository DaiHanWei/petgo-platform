## 2. 功能与需求

### 2.1 宠物友好场所发现 MVP（FR-112，本批次范围：①~⑦、⑨，不含 ⑧ 打卡）

**范围（已拍板）：** 用户标记场所 · 按距离排序的列表浏览 · 场所详情（信息 + 照片 + 评论）· 运营预置雅加达冷启动数据。**地图视图不在本版本**（拆为 FR-112B 待排期）。**⑧ 场所打卡不在本批次**，见下方分阶段说明。

#### 已确认项（①~⑦、⑨ 均已定稿；位置获取方式 2026-08-28 由「必须现场标记」改为地图选点）

**① 场所数据模型**

| 字段 | 规则 |
|---|---|
| 名称 | 必填，≤80 字符 |
| 类型 | 单选：咖啡店 / 餐厅 / 公园 / 商场 / 酒店民宿 / 宠物服务 / 其他 |
| 宠物友好标签 | 多选 ≥1：允许入内 / 户外座位 / 宠物餐食 / 宠物活动区 / 需牵引 / 大型犬友好 |
| 位置 | **轻量地图选点（2026-08-28 拍板）**：标记时弹小地图（flutter_map + OpenStreetMap 免费底图，仅作选点控件、不构成地图浏览视图），默认定位到当前位置，可拖动大头针选任意位置——人不在现场也能标 |
| 文字地址 | **必填**，作为位置备注（如「Jl. Senopati No.75, Kebayoran Baru」）——详情页展示并提供**一键复制**，其他用户可复制到 Google Maps 搜索导航；平台不做地理编码、不校验地址与坐标一致性 |
| 照片 | 1–9 张，单张 ≤10MB（复用发布上传链路） |
| 描述 | 选填，≤200 字符 |

- 照片与文字走既有三方自动审核；先发后审，违规由运营处置

**② 列表**：默认按距离升序（无定位权限 → 按最新，顶部提示开定位）；列表项 = 首图 + 名称 + 类型 + 距离 + 标签（≤2 个 +N）+ 照片数/评论数；按类型 / 标签筛选；空态引导「标记一个场所」

**③ 详情**：照片横滑流（点开进 FR-115 灯箱，组件已在批次 A 交付，直接接入）· 名称/类型/标签/距离/**文字地址（一键复制）**/描述/标记人（点开进用户主页，本批次 FR-118）· **一级评论 only，不能盖楼回复**（≤200 字，复用评论审核）——场所评论是攻略提示性质，无对话需求；**评论可附可选的二元态度（2026-09-01 拍板）**：提交评论时可选「推荐 👍 / 不推荐 👎」（可为空），负面反馈由评论正文 + 二元态度共同承载（评分打星仍不做）；详情页展示推荐/不推荐两个计数（2026-09-01 拍板），本版不做列表降权/警示标，先积累数据 · **分享按钮（见 ⑨）** · 举报入口（复用五类选项）· 他人可为场所补充照片（标注上传者，2026-08-28 确认保留）

> **本批次不含内容：** 详情页**暂不显示「打卡」按钮**，⑧ 场所打卡的全部交互（含打卡后 Diary 联动、发帖关联）延后到批次 B2，见 §2.1「分阶段上线说明」。

**④ 入口**：探索 Tab 顶部新增入口（形态 UI 阶段定；**须与 FR-121 探索 Tab 顶部横滑卡片行做统一的顶部区域布局设计**，两者同属本批次，UI 阶段一并出稿，不得各画各的叠成一堆）；不动底部 Tab 结构

**⑤ 冷启动**：运营预置雅加达核心场所 10–20 个，须在本版本上线前备齐；预置录入用后台地图选点（`[2026-09-01 修订]` 原「代填经纬度」改为与用户端同交互的选点，坐标自动写入）；标记人显示为运营官方账号

**⑥ 不做**：收藏、评分打星、营业时间/电话等商户字段、三方 POI、地图浏览视图、客户端去重（重复由运营合并）

**⑦ 运营配套（2026-08-28 拍板纳入本版本）**：场所管理后台（下架/编辑/合并重复/冷启动预置录入）随本批次交付，承载于 `v1-3-0后台prd.md` AB-17A——**AB-17A 是本批次上线的硬阻塞项**，由后台工程师承接，需与后台排期对齐

**⑨ 场所详情页对外分享（2026-08-28 新增拍板）**：约朋友同去是场所页的核心使用场景——详情页加分享按钮，走系统分享面板（WhatsApp 主场景）

- 分享产物为 **H5 场所页链接**（复用里程碑分享页的服务端渲染模式）：场所名/类型/标签/文字地址（可复制）/照片/简介 + Open Graph 标签（WhatsApp 预览卡）+ App 下载引导双 CTA

- **不接入 FR-96 分享奖励**（2026-08-31 拍板：奖励渠道仅年龄卡/Tailsonality 卡/护照卡三个）

### 2.2 用户公开主页·访客浏览（FR-118，2026-08-28 由 1.6.0 前移，补编号）

- ⚠️ 迁移波及面（工程须逐处收口）：迷你卡现挂在 Feed 卡片头像、详情页作者行、评论区头像三处，全部改为直跳主页；迷你卡上原有的 onBlocked/onReported 收尾逻辑（拉黑后退出详情页、从列表移除该作者内容）**行为保留，触发点移到主页内操作后**

#### 页面元素清单（2026-09-01 逐项拍板定稿）

- 入口：Feed/详情/评论区头像与昵称点击、@ 提及（本批次 FR-119）、场所标记人（本批次 FR-112）

- **宠物区**：宠物卡片（头像/名字/物种/年龄）——**可点击 → 进入该宠物成长档案的访客视图**（⚠️ 现状站内访客视图仅凭分享 token 进入，需后端补一条按 petId 的站内访客访问，只读渲染复用既有 VisitorArchiveView；这也是「里程碑他人可见（Diary 承载）」成立的前提）；宠物卡上挂 **Tailsonality 角色小标**（测过则显示，FR-117 导流——**FR-117 在批次 B2 才上线，本批次上线时该位置天然是空状态，不需要为此做占位设计**）
- **内容区**：该用户全部 **PUBLIC** 内容的时间倒序列表（**Diary/Moment/Tips 混排**——成长日历公开帖一并混入，不分流）→ 点击跳内容详情页；**发帖总数** 与 **获赞总数**（聚合计数）

### 2.3 @ 提及（FR-119，2026-08-28 由 1.6.0 前移，补编号）

**依赖声明：** @ 点击落点是用户公开主页，**FR-119 依赖 FR-118，两条必须同版本**（两者同属本批次，无跨批次依赖问题）。

**范围（2026-09-01 全部过审定稿）：**

- 可用位置：**内容正文 + 评论/回复**输入时输入「@」触发用户选择器
- 选择器候选（2026-08-28 拍板；无全局用户搜索——搜索在 1.6.0 未前移）：**互动过的人**——评论过我 / 我评论过 / 赞过我的 / 与我互相回复对话过的用户，取最近 **30 人**（2026-08-31 拍板）；**存在任一方向拉黑关系的用户互相不出现在候选集**（我拉黑的、拉黑我的都排除，2026-09-01 拍板）；输入昵称仅在该候选集内过滤，**@ 不到没打过交道的陌生人**
- 展示：@昵称 高亮，点击跳该用户公开主页（FR-118）
- 通知：被 @ 者收到通知中心消息 + 推送（新通知类型，深链到对应内容/评论）；单条内容/评论 @ 上限 5 人，防骚扰
- 审核：@ 不改变内容审核链路；存在任一方向拉黑关系时不发通知、不高亮
- 存量：仅新发内容/评论解析 @，存量文本不回溯

- 删评论/删内容后已发出的 @ 通知**不撤回**（2026-08-28 拍板）：对方点进显示「内容已删除」统一空态，不做撤回链路

#### @ 通知文案（2026-09-01 定稿，三语对照）

**架构约定**：系统推送文案由后端下发**印尼语**（沿用里程碑推送模式）；通知中心条目由 App 客户端按设备语言渲染（en / id 双表，后端只传类型与 targetRef，杜绝中文泄漏）；中文列仅为内部对照，不出现在任何界面。

| 场景 | Bahasa Indonesia | English | 中文（内部对照） |
|---|---|---|---|
| 推送标题（正文/评论通用） | Ada yang menyebutmu 📣 | Someone mentioned you 📣 | 有人提到了你 📣 |
| 推送正文 · 帖子提及 | {nickname} menyebutmu di sebuah postingan. Ketuk untuk lihat! | {nickname} mentioned you in a post. Tap to view! | {昵称} 在帖子里提到了你，点击查看 |
| 推送正文 · 评论提及 | {nickname} menyebutmu di komentar. Ketuk untuk lihat! | {nickname} mentioned you in a comment. Tap to view! | {昵称} 在评论里提到了你，点击查看 |
| 通知中心 · 帖子提及 | {nickname} menyebutmu di sebuah postingan | {nickname} mentioned you in a post | {昵称} 在帖子里提到了你 |
| 通知中心 · 评论提及 | {nickname} menyebutmu di komentar | {nickname} mentioned you in a comment | {昵称} 在评论里提到了你 |

**术语表**：提及 = mention = menyebut ｜ 帖子 = post = postingan ｜ 评论 = comment = komentar。深链：帖子提及 → 内容详情页；评论提及 → 内容详情页并锚定评论区（复用 `?focus=comments`）。

### 2.4 宠物 Diary 推荐集合（FR-121，2026-09-01 定稿）

**定位：** 补上站内「主动逛别人的宠物」的浏览路径（FR-118 的宠物卡片是被动路径：碰到人 → 主页 → 宠物）。

#### 入口（2026-09-01 拍板）

- **Diary Tab · 未建档状态**：登录但尚未建档的用户，Diary 页展示推荐宠物集合（替代当前空态引导的填充位）——**先只做未建档态**，游客态维持现状（演示数据）不动
- **探索 Tab · 顶部横滑卡片行**「逛逛别人家的毛孩子」：横滑 6~10 张宠物卡 + 末尾「查看全部」→ 全屏集合页（网格）。⚠️ **与 FR-112 场所入口同处探索 Tab 顶部，两个模块必须在 UI 阶段做统一的顶部区域布局设计**，不得各画各的叠成一堆（两者同属本批次）

#### 推荐逻辑（2026-09-01 拍板：纯自动规则，零后台依赖）

- 候选：近 14 天有新**公开** Diary 帖的宠物；门槛：有头像 + 公开成长记录 ≥ 3 条
- 排序：最近更新倒序，同日按互动量
- **不复用 FR-95 打分**——FR-95 是内容级算法，本 FR 是宠物级简单规则，两套独立；运营精选位留待有数据后再议，本版不加后台需求

#### 宠物卡（2026-09-01 拍板，细节 UI 阶段按效果取舍）

- 头像 + 名字 + 物种/年龄 + 最近一张公开照片 + 陪伴天数（「一起 238 天」）
- 点击 → 该宠物 **Diary 访客视图**——与 FR-118 宠物卡片共用同一条按 petId 的站内访客路径，后端能力一次两用，本 FR 不新增依赖

#### 边界（2026-09-01 拍板）

- 只推荐有公开内容的宠物；互相拉黑关系的双方不互推；注销用户的宠物不入池
- 不做「不想被推荐」的 opt-out 设置——公开内容本就公开，上线后有反馈再补
