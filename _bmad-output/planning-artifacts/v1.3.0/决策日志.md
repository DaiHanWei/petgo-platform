## 2026-09-10 · 批次 A 入库核对（PRD-v1.3.0-batch-a-content-fixes）

四条分歧由 Dai 于 2026-09-10 拍板。前三条**需回写母版 `1-3-0prd.md`**（PRD-A 是母版节选，母版未同步）。

### A-1 · G-M2「完成第一次健康检查」只由「疫苗」触发（FR-111）

- **分歧**：PRD §3.2 写「G-M2 由录入『体检』或『疫苗』类型健康记录自动完成」，但健康记录类型只有 `VACCINE / DEWORM / MENSTRUATION / NEUTER / CUSTOM` 五种，**不存在「体检」**。
- **拍板**：**只由 `VACCINE` 触发**，不新增「体检」类型。理由：新增类型要动数据库 CHECK 约束、EN/ID 文案、图标表、健康页筛选栏，跑出本批次范围。
- **已知代价**：只带宠物做体检、没打疫苗的用户点不亮 G-M2。可接受，后续如新增体检类型再补触发源。
- **落地约束**：G-M2 灰徽章点击预选类型 = `VACCINE`。

### A-2 · 顺手修「看兽医 / 绝育」点了白点的现网 bug（FR-111）

- **分歧**：PRD §2 把「健康类四条（M3/M4/M5/M9）点未完成徽章直跳健康记录页」写为现状，**实际只有 M3 疫苗 / M4 驱虫 两条如此**。前端 `healthPresetTypeFor` 只映射 M3→VACCINE、M4→DEWORM；M5（看兽医）/ M9（绝育）落到 `_showBadgeSheet` 弹打卡抽屉，而后端 `MilestoneCheckInService` 依 `HealthMilestones.SUFFIXES`（含 M5/M9）**拒绝打卡** → 用户点「已打卡」是白点。
- **拍板**：**本批次顺手修**。本批次本就要把健康类判定由「后缀集合」改「显式列举」，一并覆盖。
- **落地约束**：
  - M9 绝育 → 预选 `NEUTER` 类型，跳健康记录页。
  - M5 看兽医 **无对应健康记录类型**（由真人兽医咨询触发），不能跳健康记录页 —— **点击去向待定，见 OQ-1**。
  - G-M1 同为「看兽医」语义，与 M5 同去向。

### A-3 · 年龄卡二维码指向 App 下载页（FR-65）

- **分歧**：现有 `ShareCardTemplate` 底部品牌带**硬绑二维码**（`CardQr.minExportSide=140px` 可扫底线 + 构造期 assert），而年龄卡按 PRD 纯客户端生成、**无 H5 回流页**，二维码无 URL 可指。对应母版假设 A-1。
- **拍板**：二维码**指向固定的 App 下载页链接**，不带任何 token。保留品牌带与扫码回流路径，符合 PRD「无水印 + 下载引导」与裂变拉新目标。
- **落地约束**：下载页 URL 走配置项，不硬编码。

### A-4 · 批次按分支拆分

- **拍板**：一批次一分支。批次 A = `feat/1.3.0-batch-a-content-fixes`；批次 B、C 由 Dai 另开分支，各自合回 `dev_1.3.0`。
- 三批 epics 各自独立文件，不共用 Epic 号段（README §2 登记表已注明）。

## 2026-09-10 · 架构评审对现状描述的两处订正

三路评审逐条核对代码后，**推翻了 A-2 拍板时我给出的问题描述**（拍板决定本身不变，范围按订正后为准）：

- ❌ 我说的「M5 看兽医 / M9 绝育点了弹打卡框，后端拒绝，是白点」**不成立**。前端早已对四条健康类都不渲染打卡按钮，后端也不会被调用到。**真实缺口是**：M3/M4 点徽章会跳健康记录页，而 **M5/M9 点开只有一段只读说明、没有任何去处**。
- 🔴 **另有一个我当时没发现、更严重的真 bug**：健康记录→里程碑的完成映射按「物种前缀 + 语义后缀」寻址，**通用宠物录一条疫苗记录会点亮 `G-M3`「陪伴满 30 天」、录驱虫点亮 `G-M4`「记录满 10 条」**。这是**正在发生的线上数据错误**，不是隐患。修复已并入本批次（架构 delta AD-A4）。
