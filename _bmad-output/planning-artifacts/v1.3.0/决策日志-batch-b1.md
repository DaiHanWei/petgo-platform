# 批次 B1 决策日志

> 本主题的产品决定。**与 PRD / UI 稿冲突时以本文件为准**（跨 story 契约仍以 `../../implementation-artifacts/CROSS-STORY-DECISIONS.md` 为准）。
> 起因见 `代码核对报告-batch-b1.md`。

## 2026-09-11

### B1-D1 宠物访客视图走**新建的站内接口**，不复用分享链接码

- **决定**：按 PRD 原方案，后端新建一条「按宠物 id 的站内访客访问」，只对登录用户开放，取只读投影。
- **否掉的选项**：由用户主页下发对方宠物的分享链接码、复用现成分享接口。虽零新接口，但等于把对方宠物的**永久公开分享链接**发给每个访客，可被转发到站外。
- **影响**：后端多一条 story（访客投影 + 鉴权）；FR-118 宠物卡与 FR-121 宠物卡**共用这一条路径**，一次两用，不各建一套。

### B1-D2 Diary 推荐集合**同时覆盖**「未建档」与「声明未养宠 / 计划养宠」两态

- **决定**：扩到 PRD 原文之外——登录但没有宠物档案的两类用户都看得到推荐集合。
- **理由**：这两批人同样看不到自己的宠物，「声明未养宠 / 计划养宠」恰是「逛别人家毛孩子」最该触达的人群；代码里本来就是两屏各自独立，追加成本很小。
- **影响**：FR-121 的入口 story 要覆盖两屏，验收各走一遍；游客态维持现状（演示数据）不动，不受本条影响。

### B1-D3 场所的 👍 / 👎 是**评论自带的态度**，不是独立投票

- **决定**：维持 PRD 原文——只有提交评论时能顺带选推荐 / 不推荐（可为空），详情页两个计数 = **评论态度的累计**；不写评论就不能表态。
- **对 UI 稿的要求**：A4 现在把两个圆钮放在输入条右侧、与发送键并列，视觉上像「给场所点赞 / 点踩」的独立动作。**要收进评论输入的展开态**，不能与发送键并列。
- **影响**：不新建投票数据结构；计数口径写进 story 验收条件。

### B1-D4 场所详情的看图**先抽旧灯箱成公共组件**，不等批次 A

- **决定**：把现有内容详情页里那个私有灯箱（可左右翻页 + 双指缩放）抽成公共组件供场所详情复用；批次 A 的新版灯箱（FR-115）落地后再整体替换。
- **理由**：B1 不被批次 A 堵住，两批次不形成先后依赖。
- **影响**：B1 多一条小重构 story（抽组件，内容详情页行为不得变化）；替换时机归批次 A。

### B1-D5 宠物访客视图**确认不做日历**，UI 稿 C6 按此修正

- **决定**：维持 2026-08-18 / 08-28 两次拍板——访客视图只有时间线，没有日历。
- **对 UI 稿的要求**：C6 帧里画的「Linimasa / Kalender」两个切换钮删掉，帧下说明文字里同名描述一并删掉。
- **补充**：后端的访客日历接口已建好且有测试，是有意留着的；将来要开，前端加回切换行即可，服务端零改动。

### B1-D6 场所分享链接用**猜不出来的随机码**，不用场所名字

- **决定**：沿用现有三类分享页的做法（短前缀 + 随机码），不用场所名拼 URL。
- **对 UI 稿的要求**：A9 地址栏那行是示意，但要一并改成随机码样子，防止研发照抄。

### B1-D7 通知类型清单的重列要求**写进 story 硬约束**

- **决定**：加「有人提到了你」类型时，必须以代码里的类型枚举为唯一准、整张清单重列，并复查并行分支（电商线、admin 线）同期有没有加值。
- **理由**：这处历史上翻车四次，每次都是照过期清单抄、漏值，结果那几类通知一写就报错、服务起不来。
- **落点**：写进 FR-119 通知 story 的验收条件，不是注意事项。

### B1-D8 定位权限：**隐私政策不用改，只改应用商店信息 + 两端权限文案**

- **核实结论**：现行隐私政策「自动收集的信息 · 位置」一节**已经覆盖**了三类——SIM/IP 的大致位置、开启后的 GPS 精确位置、以及**用户自己添加到内容里的位置信息**。场所标记正好落在第三类，服务条款也无需新增条款。
- **仍要做的**：
  1. Google Play「数据安全」表单勾选位置（大致 / 精确）及用途；App Store 隐私标签加 Location —— Play 侧属需重新过审的改动，排期留时间；
  2. 两端各加权限声明 + 授权弹窗那句给用户看的用途说明（印尼语，要说清「用于按距离排序附近的宠物友好场所」）；
  3. 若接入第三方地图 SDK，Play 数据安全表单里还要声明与第三方共享 —— 上线前请法务过一眼即可，隐私政策通用条款（服务提供商）已覆盖。

### B1-D9 地图改用 **Google 地图**：只用在「标记时选点」，详情页不嵌地图

**这条推翻 PRD §2.1 ① 里「flutter_map + OpenStreetMap 免费底图」的写法，以本条为准。**

- **标记场所时**：App 内嵌 Google 地图作为选点控件，默认定位当前位置，可拖大头针选任意位置（PRD 要求的「人不在现场也能标」完整保留）。
- **场所详情页**：**不嵌地图**。只有文字地址 + 一键复制 + 一个「在 Google 地图打开」按钮，跳到用户手机上的 Google Maps（可直接导航，比嵌一张不能导航的静态图有用）。
- **数据库只存经纬度 + 文字地址**，不存任何地图厂商的对象/POI id，将来换厂商不动数据。
- **要落实的前置条件**（属于账号/配置，不是写代码）：
  1. 开通 Google Maps Platform 账号并**绑信用卡**，申请 iOS / Android 两套密钥；后台冷启动录入（PRD ⑤）是 Web 端，**还要第三套 Web 密钥**；
  2. 密钥一律 **env 注入、绝不入库**（架构硬规定），示例文件里只放占位；
  3. 给每把密钥加平台限制与调用配额上限，避免泄漏后被刷量产生账单；
  4. 地图只出现在选点那一屏，调用量最小、费用最可控 —— story 里不要顺手在列表页或详情页再嵌地图。
- **连带影响**：Play 数据安全表单要声明与第三方共享（见 B1-D8）。
