# 决策日志 · shop-v2（电商板块 V2）

> 本主题的产品决定，冲突时以此为准。
> 来源：2026-09-15 PRD 首轮校验（`validation-2026-09-15-shop-v2/`）后，产品（Dai 转述）逐项拍板。
> 编号用 `SD-n`（shop-v2 decision）。电商一期决策日志 `planning-artifacts/v1.4.0/decision-log.md` 已占用 `S-n`，v1.3.0 admin 主题已占用 `D-n`，勿混用。
> 状态：**SD-1~SD-18 已全部回写 PRD**（2026-09-15，两轮校验后）。

| # | 拍板项 | 决定 | 回写 PRD 的落点 |
|---|---|---|---|
| **SD-1** | 支付失败怎么定性 | **不做一次性查库定性**。在支付相关页面与交互环节做好行为数据监控，**运营在 PostHog 看数据**、持续追踪即可。 | 删除原 ACT-1 / R-1「整份让路」分支；购买闭环组解除挂起；新增 SHOP-FR-02「支付环节监控」；原 FR-112「后台展示支付失败原因」移出本版。<br>⚠️ 已知盲区（如实写入 PRD）：「用户已付款但系统未收到到账通知」在 App 与服务端事件里都表现为超时，只能靠支付网关后台 / 对账发现。 |
| **SD-2** | 拒收、发货前取消给不给额外补偿 | **一律没有额外补偿**，只退应退金额。与电商一期 PRD 退款规则 7 一致。 | 本版退货整体不做（SD-5），此条作为**下一版实现退货时必须遵守的规则**写入 §8。系统现状「拒收会发补偿溢价」偏离该规则，列入下一版已知问题。<br>`[ASSUMPTION]` 「平台责任补偿」与「选 PawCoin 退款的激励」两种都不发 —— 按字面理解，产品未单独确认。 |
| **SD-3** | 「不做批发」的原意 | **不做批发价格**：商品只有单一销售价格。原 PRD 把它读成「不做批量发货」是误读。另行拍板：**批量发货本版也不做**。 | §1.4 排除表分列「批发价 / 阶梯价」与「批量发货」两行，各自引本条。 |
| **SD-4** | 退货进度页砍掉后：撤销申请、驳回原因、申诉入口 | **退货相关功能下版本再做**。 | 合入 SD-5。 |
| **SD-5** | 已送达能否退款、不可退商品能否取消拒收；兼 SD-4 范围 | **本版不做任何退货退款功能**；App 端**现有的退货相关入口与文案一并隐藏**。 | 原售后出口组（FR-115~120）整组移出；新增 SHOP-FR-05「隐藏 App 端退货入口与文案」（仅前端，后端与运营后台退货功能保留）；原 FR-133 退货窗口文案纠正随之不做；§8 汇总下一版须处理的退货问题。 |
| **SD-6** | 购物车只买部分商品时的计算口径 | **全部按选中的商品算**：免运费门槛、PawCoin 抵扣上限、库存锁定。 | SHOP-FR-04 验收标准。`[ASSUMPTION]` 默认全选；下单后未选中的商品留在购物车；取消勾选不删除商品。 |
| **SD-7** | 与 v1.3.0 admin 主题（后台 UI 重构）改同一批电商后台页面 | **以后台 UI 重构为准，按先后顺序理解（读法 A）**：admin 主题 Epic 10 先重构电商后台页面，shop-v2 的后台功能在重构后的页面上叠加；运营提效组保留。 | §1.5 依赖说明；风险 SHOP-R-1；行动项 ACT-A（通知 admin 主题负责人解除 Epic 10 的「等电商线合入」跳过——电商代码已在 dev_1.3.0）。 |
| **SD-8** | 商品编码与 SKU 货号方案 | **商品编码 = SPU ID；SKU ID = 唯一商品 ID；SPU 与 SKU 一对多**（同一商品链接下多个规格）。编码**对用户不可见**，生成方式由技术定。 | SHOP-FR-06：系统自动生成、全局唯一、人可读、运营不可改，仅后台与 Excel 可见；Excel 编号列留空＝新建、填已有编号＝更新。规格维持单一维度（不做多维规格）。 |
| **SD-9** | Excel 导入含不含图片 | **填图片地址，来源为外部链接**。 | SHOP-FR-07：导入时系统下载并转存到自有存储；域名 / 大小 / 格式限制；下载失败的行挂错误不丢弃。 |
| **SD-10** | WhatsApp 深链用哪个号 | **全 App 统一用 081290906953**（App 客服弹窗现有号码；另一候选 081399779133 不用）；**号码做成后端下发的配置项**，深链与既有客服弹窗读同一配置。 | SHOP-FR-26。开放项 OD-11：产品回复带问号，号码待最终确认；确认为公司专用号而非个人号。 |
| **SD-11** | 本版随哪个版本发布 | **随 V1.3.0 发布**。「V1.4.0」目前没有任何计划，PRD 中所有把 V1.4.0 当版本号的说法忽略。 | 已上线的第一期电商统一称「电商一期」；其规划文档目录 `planning-artifacts/v1.4.0/` 为历史遗留名，引用时写路径。 |
| **SD-12** | 品类改为可配置后怎么迁、要不要多级 | **只有现有四个一级分类，不考虑多级**。 | SHOP-FR-19：四个品类原样迁移为可配置数据；只做一级。`[ASSUMPTION]` 运营可新增 / 改名 / 停用；停用后该品类商品不在 App 展示、数据保留；物种（狗 / 猫 / 通用）保持现状不做可配置。 |
| **SD-13** | 退货不做但线上链路仍开着（老版本 App、运营后台），怎么兜底 | **两步**：① 上线前在运营后台 PawCoin 配置中把「平台责任补偿比例」「转 PawCoin 激励比例」都设为 0，零开发让现状符合 SD-2；② 给运营一份售后处理流程。**不**在后端关闭用户提交退货。 | 新增 SHOP-FR-35「本版售后兜底流程」；SHOP-R-5；ACT-C。连带：老版本 App 的质量问题退货本版也无补偿（订单量近零，接受）。 |
| **SD-14** | Excel 导入能否改价格与库存 | **新建时可填售价与初始库存；更新已有商品时售价、库存列一律忽略**，改价改库存只走批量操作。更新时空单元格＝保留原值。 | SHOP-FR-07 列规则。 |
| **SD-15** | 品类可配置的三个细节 | 品类超过 4 个时首页入口**横向滑动**；运营填写**印尼语 + 英语**两种名称；停用后**购物车内该品类商品不可结算、历史订单照常显示**。 | SHOP-FR-19、SHOP-FR-04。品类中文名以代码为准更正：`OBAT_VITAMIN`＝驱虫保健，`PERAWATAN`＝洗护。 |
| **SD-16** | admin 主题 Epic 10 赶不上 V1.3.0 怎么办 | **V1.3.0 代码冻结时 Epic 10 未完成 ⇒ 运营提效组整组顺延到下一版**；App 端、客服、缺陷收口照常随 V1.3.0 发布，不等。 | §1.5 发布规则与分批表；SHOP-R-1。 |
| **SD-17** | 税务三条本版做不做 | **本版不做**。系统目前没有任何算税与开票功能；三条转为「将来引入开票时必须遵守的约束」。 | SHOP-FR-32~34 移出（编号保留为已移出），OD-2 / OD-3 关闭，内容转附录 B。 |
| **SD-18** | 药品有效期怎么处理 | **本版只做注册号，有效期不做**（有效期是批次属性，做对需批次管理）。 | SHOP-FR-21 改为只做注册号；§1.4 排除表加「药品有效期」。 |
