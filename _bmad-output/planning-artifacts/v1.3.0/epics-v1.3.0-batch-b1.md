## Requirements Inventory

### Functional Requirements

沿用母版 FR 编号（FR 编号跟着功能走、不随版本变更），子项用小数位细分以便逐条追踪。

**FR-112 宠物友好场所发现 MVP（不含 ⑧ 打卡）**

- **FR-112.1** 场所数据模型：名称（必填 ≤80）、类型（单选，7 类：咖啡店/餐厅/公园/商场/酒店民宿/宠物服务/其他）、宠物友好标签（多选 ≥1，6 个：允许入内/户外座位/宠物餐食/宠物活动区/需牵引/大型犬友好）、位置（地图选点，默认当前位置，可拖针选任意位置）、文字地址（**必填**，仅作展示与复制）、照片（1–9 张，单张 ≤10MB）、描述（选填 ≤200）
- **FR-112.2** 场所列表：默认按距离升序；无定位权限 → 按最新 + 顶部开启定位提示；列表项 = 首图 + 名称 + 类型 + 距离 + 标签（≤2 个 +N）+ 照片数/评论数 + **推荐/不推荐计数**（B1-D11）；按类型 / 标签筛选；空态引导「标记一个场所」
- **FR-112.3** 场所详情：照片横滑流（点开进灯箱）· 名称/类型/标签/距离/文字地址（一键复制）/描述/标记人（点开进 FR-118 主页）· **定位小地图 +「在地图中打开」**（B1-D9）· 一级评论 only（≤200 字，不能盖楼）· 评论可附二元态度（推荐 👍/不推荐 👎，可为空）· 展示推荐/不推荐两个计数 · 分享按钮 · 举报入口（复用五类选项）· 他人可补充照片（标注上传者）。**不含打卡按钮**
- **FR-112.4** 入口：Sosial（首页 Feed）顶部新增场所入口，与 FR-121 横滑行做**统一顶部区域布局**；不动底部 Tab 结构
- **FR-112.5** 冷启动：运营预置雅加达核心场所 10–20 个，后台用与用户端同款地图选点录入（坐标自动写入），标记人显示为运营官方账号
- **FR-112.6** 明确不做：收藏、评分打星、营业时间/电话等商户字段、三方 POI、地图浏览视图、客户端去重
- **FR-112.7** 运营配套 AB-17A（场所管理后台）：**归 admin 主题实现**，本批次不含其 story，但**是本批次上线的硬依赖**（2026-09-14 已确认后台在做）
- **FR-112.9** 对外分享：详情页分享按钮 → 系统分享面板；产物为 **H5 场所页**（服务端直出，复用既有模式）：场所名/类型/标签/文字地址（可复制）/照片/简介 + **Open Graph 预览卡** + App 下载引导双 CTA；已装 App 者先唤起进 App；场所下架后统一「场所不存在」文案；链接长期有效；**不接入 FR-96 分享奖励**

**FR-118 用户公开主页 · 访客浏览**

- **FR-118.1** 迷你主页卡**整体退役**：现挂的三处（Feed 卡片头像、详情页作者行、评论区头像）全部改为直跳完整主页；迷你卡原有的拉黑/举报收尾逻辑（拉黑后退出详情页、从列表移除该作者内容）**行为保留，触发点移到主页内操作后**
- **FR-118.2** 页面元素：**基础身份区**（头像 · 昵称 · 运营用户标签 · 加入时间 · 个性签名 signature）· **宠物区**（宠物卡片：头像/名字/物种/年龄，**可点击 → 该宠物 Diary 访客视图**；卡上挂 Tailsonality 角色小标位，FR-117 在批次 B2，本批次天然空状态、**不做占位设计**）· **内容区**（该用户全部 PUBLIC 内容时间倒序，Diary/Moment/Tips 混排，点击跳详情；**发帖总数** 与 **获赞总数**）
- **FR-118.3** 操作区：他人主页顶栏「···」→ 举报 / 拉黑（互斥底抽屉，样式沿用详情页「···」模式）
- **FR-118.4** 自己视角：同一套页面两种视角——自己看无「···」、多一个「编辑资料」入口（跳既有资料编辑抽屉）；「我的」Tab 保持现状不动
- **FR-118.5** 被拉黑者访问拉黑者主页：显示模糊空态「暂无内容（对方的隐私设置）」，**不明示拉黑**；Feed 与评论**不屏蔽**；@ 屏蔽见 FR-119。⚠️ 本条是对 1.1.4 FR-94「被拉黑方完全无感」的**有意例外**（仅主页维度）
- **FR-118.6** 注销用户主页：统一「用户不存在」空态
- **FR-118.7** 明确不放：里程碑徽章墙（Diary 访客视图承载）、护照集章数、打卡足迹、主页 H5 分享、关注/粉丝、访客记录、另设 bio 字段

**FR-119 @ 提及**

- **FR-119.1** 可用位置：内容正文 + 评论/回复，输入「@」触发用户选择器
- **FR-119.2** 候选集：互动过的人（评论过我 / 我评论过 / 赞过我的 / 互相回复过），取最近 **30 人**；**任一方向拉黑关系的双方互不出现**；输入昵称**仅在该候选集内过滤**，**无全局用户搜索**（@ 不到陌生人）
- **FR-119.3** 展示：@昵称高亮，点击跳该用户公开主页（FR-118）
- **FR-119.4** 通知：被 @ 者收到通知中心消息 + 推送（**新通知类型**，深链到对应内容/评论）；单条内容/评论 @ 上限 **5 人**
- **FR-119.5** 审核：@ 不改变内容审核链路；存在任一方向拉黑关系时**不发通知、不高亮**
- **FR-119.6** 存量：仅新发内容/评论解析 @，存量文本不回溯；删评论/删内容后已发出的 @ 通知**不撤回**，点进显示「内容已删除」统一空态
- **FR-119.7** 文案：印尼语/英语双表由客户端按设备语言渲染，推送由后端下发印尼语；中文仅内部对照、不进界面

**FR-121 宠物 Diary 推荐集合**

- **FR-121.1** 入口 A（Diary Tab）：登录但**没有宠物档案**的用户在 Diary 页看到推荐集合，追加在现有引导之下（原引导不删）。⚠️ **覆盖两态**（B1-D2）：「养宠但未建档」与「声明未养宠 / 计划养宠」；游客态维持现状（演示数据）不动
- **FR-121.2** 入口 B（Sosial Tab 顶部）：横滑 6~10 张宠物卡 +「查看全部」→ 全屏集合页（2 列网格）；与 FR-112.4 入口**统一顶部区域布局**
- **FR-121.3** 推荐逻辑（纯自动规则，零后台依赖）：候选 = 近 14 天有新**公开** Diary 帖的宠物；门槛 = 有头像 + 公开成长记录 ≥3 条；排序 = 最近更新倒序，同日按互动量；**不复用 FR-95 打分**（那是内容级算法，本 FR 是宠物级规则）
- **FR-121.4** 宠物卡：头像 + 名字 + 物种/年龄 + **最近一张公开照片** + 陪伴天数（「一起 238 天」）；大图与左下角小圆头像是**两个不同字段**（帖子配图 vs 宠物档案头像）；点击 → 该宠物 Diary 访客视图（与 FR-118.2 共用同一条通道）
- **FR-121.5** 边界：只推荐有公开内容的宠物；互相拉黑的双方不互推；注销用户的宠物不入池；**不做 opt-out 开关**

### NonFunctional Requirements

- **NFR-1** 对外暴露标识一律**不可枚举 token**，自增 id 不外露（基线护栏；场所分享链接尤其不得用场所名或序号）
- **NFR-2** 拉黑过滤、可见范围过滤一律**服务端判定**；客户端过滤只是"看不见"，抓包照样拿得到
- **NFR-3** 注销用户一律匿名化/不泄漏身份（主页、推荐池、@候选、场所标记人四处都要覆盖）
- **NFR-4** 日志**禁记** PII / 健康数据 / 令牌 / 签名 URL；**位置坐标同样禁记**
- **NFR-5** 埋点属性**禁传**场所名、文字地址、经纬度（埋点层有兜底黑名单，传了也会被整条丢弃）
- **NFR-6** 列表与聚合取数**一律批量**，禁 N+1、禁为聚合新增冗余计数列（Redis 计数器为经拍板的例外，见 AD-9）
- **NFR-7** `ddl-auto=validate`，schema 归 Flyway；新迁移**一律时间戳版本号**；打包一律 `mvn -B clean package`
- **NFR-8** **禁引入新中间件 / 禁通用缓存层**；异步只用 `@Async` + DB 状态机
- **NFR-9** 新增定位权限须完成商店合规（Play 数据安全表单 + App Store 隐私标签 + 两端权限声明与用途文案）；隐私政策与服务条款**已覆盖、不用改**
- **NFR-10** 加载失败 / 输入失败走统一口径（CROSS-STORY F13）：保留已加载内容、给重试入口、输入类失败保留输入
- **NFR-11** 图片 EXIF 剥离：客户端为主 + 公开桶服务端兜底（CROSS-STORY E4）——场所照片进公开桶，必须走兜底
- **NFR-12** 契约一致性是可证伪验收（CROSS-STORY C4/C5）：改任一对外 DTO 必须同步改后端 record + App data DTO + App mock + 契约 test，**四处不同步即 PR 不绿**
- **NFR-13** 内容与评论走既有三方自动审核（先发后审）+ 举报双层（CROSS-STORY F10）；场所照片与评论同此链路
- **NFR-14** 全程**无视频**（CROSS-STORY F4）：场所照片仅图片

### Additional Requirements

来自 `architecture-v1.3.0-batch-b1-delta.md`（AD-1~AD-10）与跨 story 台账：

- **AD-1** `places` 只存名称/类型/标签/**纬度经度两个独立数值列**/文字地址/描述/照片/标记人/状态；**不存任何地图厂商 POI id**；文字地址是纯展示字符串，**不得被任何逻辑当结构化地址解析**
- **AD-2** 距离排序 = **经纬度矩形范围粗筛 + 直线距离排序**，纬度经度各建索引；🛡 **禁装 PostGIS/cube/earthdistance、禁接三方 LBS**；无定位时走"按最新"的**独立查询分支**，不得用"距离为 null 排最后"混在一条 SQL 里
- **AD-3** 地图 SDK **只做显示 + 打自己的点**；🔴 **禁调地点搜索/自动补全、地址与坐标互转、路线规划**；地图只出现在**选点弹层**与**详情页小地图**两处，列表页不得嵌地图；三套密钥（iOS/Android/后台 Web）env 注入 + 平台限制 + 每日配额上限
- **AD-4** 宠物站内访客：**新建按 petId 的入口（仅登录可用）**，**复用 v1.1.6 AD-1 那层只读投影**，两个入口必须落同一投影；🛡 **不下发对方宠物的分享 token**；站内进入隐藏「由 XX 分享」横幅、返回回上一页；⚠️ **访客视图没有日历**（两次拍板不做，UI 旧稿画错已修订）
- **AD-5** 场所 H5：路径 `/place/{不可枚举 token}`；下架 → 统一空态 + 404 + noindex；🔴 **放 OG 预览图是对名片/里程碑页"不放图"边界的有意例外**（场所照片不含个人与宠物隐私），**写明防被当漏做改掉**；唤起链沿用名片页 + **安卓清单同步声明深链 host**
- **AD-6** 主页/推荐/@候选取数一律批量；**发帖总数已有可直接复用**，要新补的是**加入时间**与**获赞总数**
- **AD-7** 拉黑过滤四处（场所评论/公开主页/@候选/宠物推荐）**共用既有同一个读取口**，禁各写各的；被拉黑者看到的模糊空态**必须与"真的没有公开内容"复用同一组件同一文案**
- **AD-8** 场所评论**独立建表** `place_comments`，不改既有 `comments`、不用多态外键；审核链路**复用不共表**；二元态度落在本表的列上
- **AD-9** 推荐/不推荐计数进**列表页热路径** → **Redis 计数器 + DB 回算自愈**（沿用未读角标同款）；🔴 **不构成"缓存层解禁"**：真值永远在表里，给列表整页结果做缓存仍在禁止之列；本版这两个数**只展示、不参与排序**
- **AD-10** @ 候选集**独立建表**（不每次现扫）；正文/评论里的 @ **存 userId 不存昵称**；加通知类型必须 **DROP + ADD 重列 CHECK 全集**（此处已出过四次事故）
- **E7/NFR-7** Flyway 时间戳版本号，基线 `V20260902_1620`
- **C1** 当前用户资源统一 `/api/v1/me`，不用 `/users/me`
- **C3** 新表带模块前缀命名（`place_*`），勿用裸名
- **批次间**：B1 **不预留** ⑧打卡的任何字段/列（那是 B2）；灯箱先抽既有私有组件成公共件，**不等批次 A**

### UX Design Requirements

来自 `ui-v1.3.0-batch-b1-places-social.html`（24 屏 / 5 泳道，2026-09-11 修订版）：

- **UX-DR1** 探索（Sosial）顶部统一区（B1 屏）：场所入口为**单行导航条**（图标+文字+箭头），宠物推荐为**单独一行横滑卡片**，两者分层不叠成一堆；AppBar / 分类 chips / 瀑布流 / 底部 Tab 全部保留原样

- **UX-DR5** 地图选点弹层（A6）：拖动大头针选点，默认落当前位置；**全新依赖**
- **UX-DR6** 提交成功（A7 Toast + 返回）/ 失败（A8）：失败**只做字段级内联错误**，字段没过时请求不真的发出，**不叠加通用"提交失败"横幅**
- **UX-DR7** 场所分享 H5 两态（A9 存在 / A10 已下架）：全屏图片 hero + 深色渐隐 + 悬浮白卡 + 邀约文案 + 社交佐证数 + 4 张缩略图（末张显示 +N）+ 双商店徽章；地址栏用**随机码**示意（不得用场所名）
- **UX-DR8** 公开主页四态（C1 他人 / C2 自己 / C4 被拉黑者视角 / C5 已注销）：复用既有「我的」页三段结构（身份区/宠物区/2 列内容网格）；C2 的「编辑资料」在**身份行内、与头像同行**（不塞进 AppBar）；C4 只替换内容区、身份区正常展示
- **UX-DR9** 主页操作抽屉（C3）：复用既有举报/拉黑两项 + 抽屉样式；**补底部「取消」按钮**
- **UX-DR10** 宠物访客视图（C6）：复用既有页面；⚠️ **无日历切换**（旧稿画错已删）；站内入口**隐藏「由 XX 分享」横幅**
- **UX-DR11** @ 选择器两态（D1 默认 / D2 无候选）：全新叠加层；「Cari nama…」**不是全局搜索**，只在候选集内过滤；候选为空时**不显示过滤框**
- **UX-DR12** 通知中心新增「有人提到了你」（D3）：复用既有样式（按日分组 / 图标块 / 未读左紫条+浅紫底），紫色图标块与兽医回复同色系
- **UX-DR13** 提及通知点进去内容已删除（D4）：统一空态，不做撤回链路
