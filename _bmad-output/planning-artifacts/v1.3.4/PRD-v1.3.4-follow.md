## 1. 版本目标

1. **让用户之间建立持续的关系（FR-140）**——目前用户只能「刷到一条帖子 → 点赞评论」，看完即走，没有「以后还想看这个人」的抓手。关注关系也是后续「关注 Feed」「追更提醒」的前提。
2. **让互动通知值得点开（FR-141）**——现在的点赞 / 评论通知只写「有人赞了你的内容」，看不出是谁、哪条帖子；高互动帖子会刷出一串一模一样的通知。改版后文案写明「谁 + 做了什么」，同类合并，并按时间分段。

**核心指标：** 人均关注数 · 周活用户中有关注关系的占比 · 通知中心点击率（按类型）· 互动类推送打开率

## 2. 现状（2026-10-09 核实代码）

### 2.1 关注

- **完全不存在**：两仓均无关注 / 粉丝的表、实体或接口。代码里曾明确标为不做——`public_profile_page.dart:118` 注释写「关注 / 粉丝……不是还没做，是明确不做」；`FeedService.java:35` 写 Feed「无关注」。本版本推翻这一决定，相关注释须同步更新。
- 他人主页（FR-118）`GET /api/v1/users/{userId}/profile` 现返回：昵称、头像、签名、标签、加入时间、`postCount`（只数 PUBLIC）、`likeCount`（获赞总数）、`reported` 等，**无关注相关字段**。
- 我的页（`me_page.dart`）现为：个人信息 → 宠物卡 → 活动（我的订单）→「MY POSTS」小标题 + 帖子网格。**我的页不显示帖子数 / 获赞数**（他人主页有）。

### 2.2 拉黑与举报（关注规则须与之协调）

- 表 `user_hide_relations`（holder, target, source），`source` 为 `BLOCK`（主动拉黑，可解除）或 `REPORT`（举报账号后自动建立，永不删除）。
- 拉黑后，拉黑者进对方主页会得到 403「你已拉黑该用户」。被拉黑者看拉黑者主页时计数归零、内容为空，与「真没发过内容」的响应一致，刻意不暴露被拉黑。Feed、评论、互动通知均会过滤。

### 2.3 通知中心

| 维度 | 现状 |
|---|---|
| 数据表 | `notifications`：type / title / body / deep_link_* / target_ref / is_read……**无触发人（actor）列，无聚合计数** |
| 通知类型 | 31 种，受 CHECK 约束 `ck_notifications_type` 限制，最新为 `V20260915_1614`；改约束必须 DROP + ADD 重列全集（已出过 4 次漏值事故） |
| 点赞 / 评论生成 | **每次赞 / 评论各发一条，不合并**；不带触发人、不带帖子信息；自赞自评不发；回复二级评论时额外通知一级评论作者 |
| 列表文案 | App 按 type 显示本地写死的文案（如「New like / Someone liked your post」），不读后端 title / body |
| 列表样式 | 左侧为**类型图标**（爱心、评论、奖杯……） |
| 时间分组 | 只有两组：**Today / Earlier** |
| 未读样式 | 奶油色底 `cream2` + 圆点 |
| 全部已读 | 已有（2026-08-19 加入口） |
| 推送 | 腾讯 IM 离线推送；除 S/M 级里程碑外所有类型都推送，包括每一次赞 / 评论 |
| 场所评论通知 | **不存在**——notify 模块无场所相关类型 |
| 语言 | App 只有 EN / ID；推送文案由后端按账号语言取 |

## 3. 功能与需求

### 3.1 用户相互关注（FR-140）

#### 已确认项

**关注关系**
- 单向关注：A 关注 B 不需要 B 同意；双方互相关注即为「互关」，无额外标识
- **宠物设为私密的用户也可以被关注**（设计稿）——关注的是人，不是宠物；被关注后对方能看到的内容范围不变（只看 PUBLIC）

**按钮三态**

| 状态 | 条件 | 样式 | 点击 |
|---|---|---|---|
| **Follow** | 我未关注对方，对方也未关注我 | 紫色实心 | 关注 → 变 Following |
| **Follow Back** | 我未关注对方，**对方已关注我** | 紫色实心 | 关注 → 变 Following |
| **Following** | 我已关注对方 | 白底灰框 | 取消关注 → 变回 Follow / Follow Back |

- 取消关注：**再点一次 Following 按钮即取消**（设计稿），**不弹二次确认**（2026-10-12 拍板），误触可以再点回来

**Following 按钮的显示范围（2026-10-12 拍板）**
- **常驻显示 Following 的只有两处**：**对方个人主页**、**我自己的 Following 列表**。用户想取消关注，只能去这两处
- **其他所有位置**（Feed 卡片、帖子详情、别人的关注列表、我的 Followers 列表、通知中心新粉丝条目）**已关注的用户不显示按钮**
- **刚点关注的当下例外**：在上述位置点 Follow / Follow Back 后，按钮立即变为 Following 并留在原位，此时**可以立刻再点 Following 取消关注**（防误触）；**刷新后**该用户已关注，按钮隐藏
- **同一用户的其他位置马上隐藏**（2026-10-12 拍板）：点关注后，当前页面及其他页面中**同一用户的其他按钮立即隐藏**（如 Feed 里同一作者的其他卡片），只有被点的那个按钮保留 Following 直到刷新。App 端须维护一份全局共享的关注状态，各处按钮统一读取（AC1 跨页面一致同样依赖这份状态）
- UI 稿据此绘制：设计稿中上述位置画了 Following 按钮的，删除 Following 按钮的显示即可

**我的页与他人主页整体重排（2026-10-12 拍板，取代设计稿与此前「签名下一行计数」「按钮在 Edit 位置」两条）**——采用「居中名片」布局，自上而下：
1. 头像（居中；我的页带相机角标）→ 昵称 → 签名 → 加入时间（**仅他人主页**，灰色小字）
2. **一行四格数据**：Postingan（帖子数）/ Suka（获赞数）/ Mengikuti（关注数）/ Pengikut（粉丝数）。后两格可点，进入关注列表并定位到对应 Tab。帖子区表头**不再重复**帖子数与获赞数
3. **整宽主按钮**：我的页为「Edit Profil」；他人主页为 Ikuti / Ikuti Balik / Mengikuti（三态规则见上）
4. 宠物区（小节标题）：
   - **我的页「Hewanku」**：自己的宠物一行卡片——头像、名字、物种 · 年龄，diary 数为独立小标签
   - **他人主页「Hewan」**：**圆形头像**，头像右上角数字为 diary 数，下方名字 + 物种 · 年龄；点头像进该宠物档案
   - ⚠ **多宠物不在本版本**（2026-10-12）：本版本每个用户只展示一只宠物。宠物区按「头像一排、超过 4 只横向滑动」的结构实现，数据与组件按列表做，为后续多宠物预留扩展，本版本不做多宠物逻辑
   - **宠物只显示物种**（Kucing / Anjing / Lainnya），不显示品种
5. 我的页保留「Aktivitas · Pesanan Saya」
6. 帖子区（小节标题 Postinganku / Postingan）+ 现有网格

- 他人主页关注 / 取关后，Pengikut 计数即时 ±1（设计稿）
- 无宠物时不显示宠物区；无公开帖子时四格中帖子数 / 获赞数为 0，帖子区显示现有空态
- 我的页不再显示邮箱

**入口三：Feed 卡片与帖子详情头部**
- 关注按钮放在发帖人头像、昵称右侧，再右侧为「…」（设计稿）
- **内容类型标签（Moment / Diary / Knowledge & Tips）移到发布时间右侧**，与时间同一行（设计稿）——原因是昵称长短不一，标签跟在昵称后面会参差不齐
- **Feed 卡片与帖子详情页只对还没关注的发帖人显示按钮**（Follow / Follow Back），避免满屏 Following（2026-10-12 拍板，回应 Albar 开放问题 1）。点关注后的显示规则见上方「Following 按钮的显示范围」
- 自己的帖子不显示关注按钮

**关注列表页**
- 顶部标题为该主页用户的昵称，下方两个 Tab：**Following / Followers**（设计稿）
- Following Tab 是我关注的人，Followers Tab 是关注我的人；每行为头像 + 昵称 + 按钮
- **删除设计稿中每行右侧的「⋮」**（2026-10-12 拍板）——列表行内不提供移除粉丝、拉黑、举报等操作，这些仍从对方主页的「…」进入
- 列表可滚动，长昵称截断加省略号（设计稿）
- **我自己的 Following 列表**：每行常驻 Following 按钮，可直接取关。**取关后不立即从列表移除**，按钮变回 Follow，刷新后才消失——防误触（设计稿）
- **我的 Followers 列表、别人的关注列表**：每行按「我」与此人的关系显示——未关注显示 Follow / Follow Back，已关注不显示按钮（见「Following 按钮的显示范围」）；列表中是我自己的那一行不显示按钮
- 点击行（头像 / 昵称）→ 进入对方主页（2026-10-12 拍板）
- **可以看别人的关注列表**（2026-10-12 拍板）：他人主页的 Following / Followers 计数同样可点，进入该用户的列表页

**列表为空时：推荐关注**
- **只有看自己的关注列表、且当前 Tab 为空时**，显示「Suggested for you」用户推荐列表（设计稿；2026-10-12 拍板限定为自己的列表）
- 看别人的关注列表时 Tab 为空，只显示空状态提示，不显示推荐
- **推荐名单口径（2026-10-12 拍板，取代设计稿「只推荐虚拟账号」）**：由后端返回，取**所有发过 PUBLIC 内容的用户账号**（虚拟号与真实用户都包括），按**近 30 天获赞数**倒序排列，**最多显示 30 个**（2026-10-12 拍板）；排除自己、已关注、已拉黑以及已注销 / 封号的账号；本版本运营不可配置

**取消关注不通知（2026-10-12 拍板）**
- **所有取消关注行为都不给任何人发消息**——不进通知中心、不发推送。包括用户主动取关、拉黑导致的自动取关
- 被取关的一方只会看到自己的 Followers 计数减少，不会收到任何提示

**拉黑与关注（2026-10-12 拍板，回应 Albar 开放问题 2）**
- **A 拉黑 B 时，A 对 B 的关注同步取消**，A 的 Following 与 B 的 Followers 计数相应减少
- **B 不知道**：不发任何消息（同上条），B 那边不出现任何提示
- **B 对 A 的关注保留不动**——若一并删除，B 会在自己的 Following 里发现少了 A，等于暴露被拉黑
- **B 看 A 的主页时，关注数与粉丝数显示真实数字**（2026-10-12 拍板）；帖子计数与内容区沿用现有伪装（归零 / 为空）
- **拉黑期间 A 不能关注 B**，需先解除拉黑
- **A 的 Following 列表里没有 B；A 的 Followers 列表里 B 仍在**（B 对 A 的关注未变），**该行不显示任何按钮**（拉黑期间 A 不能关注 B，不显示 Follow Back）（2026-10-12 拍板）
- **解除拉黑后不恢复 A 对 B 的关注**
- `REPORT` 来源的隐藏关系**不影响**关注（举报不等于拉黑）

**其他规则（2026-10-12 拍板）**
- **注销 / 封号用户**：从列表或任何入口点进其主页，显示「该用户不存在」（沿用现有 `profileNotFound` 文案）
- **计数显示**：≥10,000 显示为「1.2K」式缩写，与现有获赞数格式一致
- **频率限制**：单个用户每分钟最多 30 次关注操作，每日最多新增 500 个关注；超出时提示「操作太频繁」，防刷
- **虚拟号**：可以被关注、会出现在列表中；虚拟号**不会主动关注真人**
- **未登录用户（游客）**：现有他人主页（FR-118）对未登录用户可见。未登录用户在他人主页、Feed 卡片上看到关注按钮时，点击 → 拉起登录，登录后不自动完成关注

#### 边界与不做项

- **不做「关注 Feed」**（只看关注的人的帖子）——本版本关注关系**不影响首页推荐算法**
- 不做私密账号 / 关注审批
- 不做关注单只宠物（Roadmap 中 V1.4.2「追更宠物」另行承载）
- 不做关注列表内搜索
- 不做关注列表行内操作菜单（「⋮」已删除）

#### 验收标准

- **AC1**：他人主页、Feed 卡片、帖子详情、关注列表、通知中心五处，按钮按上表与「Following 按钮的显示范围」显示；在任一处操作后，回到其他页面状态一致
- **AC2**：关注 / 取关后，对方主页的 Followers 与我的 Following 计数即时更新，刷新后与服务端一致
- **AC3**：对方已关注我、我未关注对方时显示 Follow Back
- **AC4**：在我自己的 Following 列表取关，该行不消失、按钮变为 Follow；下拉刷新后该行消失
- **AC5**：自己的关注列表某个 Tab 为空时显示推荐关注列表（别人的空列表只显示空状态），包含发过公开内容的虚拟号与真实用户，按近 30 天获赞数倒序、最多 30 个；列表中不出现自己、已关注、已拉黑、已注销 / 封号的账号
- **AC6**：A 关注 B 后拉黑 B，A 对 B 的关注被取消、双方计数正确；B 的通知中心与推送均无任何消息
- **AC7**：我的页与他人主页按「居中名片」布局显示一行四格（帖子 / 获赞 / 关注 / 粉丝），点关注 / 粉丝进入对应 Tab；帖子区表头不重复数量；他人主页宠物区为圆形头像一排；**我的页不显示邮箱**
- **AC8**：Feed 卡片与详情页的内容类型标签位于发布时间右侧
- **AC9**：任何取消关注（主动取关、拉黑导致的取关）均不产生通知或推送
- **AC10**：除对方主页与我自己的 Following 列表外，已关注的用户不显示按钮；在这些位置点 Follow 后按钮变为 Following 且可立即点击取关，刷新后按钮隐藏；同一用户在其他卡片 / 页面上的按钮立即隐藏；关注列表行内无「⋮」
- **AC11**：从任何入口进入已注销 / 封号用户的主页，显示「该用户不存在」

#### 影响面

- **后端**：新增关注关系表（follower_id, followee_id, created_at，唯一键）；新增关注 / 取关 / 列表 / 推荐接口；主页、Feed、详情接口须返回关注状态与双向计数。计数建议冗余存储（用户表或 Redis），避免每次实时 count
- **拉黑接口**须在同一事务中删除拉黑者对被拉黑者的关注，且不触发任何通知
- **App**：我的页、他人主页、Feed 卡片头部、详情页头部改版，新增关注列表页；同步更新 `public_profile_page.dart:118` 等「明确不做」注释
- **新增通知类型 `USER_FOLLOWED`**（见 FR-141）
- **Feed 卡片头部改版影响首页所有卡片**，须回归测试长昵称、运营顶置角标、本人待审帖等组合

### 3.2 通知中心优化（FR-141）

#### 已确认项

**列表样式**
- **通知中心不放图片**（2026-10-12 产品决策）：各类型通知左侧沿用现有的类型图标；新增的 `USER_FOLLOWED`、`PLACE_COMMENTED` 需各补一个类型图标
- **未读样式基本沿用现有代码**：浅紫底 `cream2` #F8F2FF + 紫色圆点（2026-10-12 拍板，取代设计稿「去掉圆点」）；**圆点位置由条目最右侧移到类型图标右上角**，右侧留给回关按钮（2026-10-12 确认）
- 时间分段改为五段：**Today / Yesterday / Last 7 Days / Last 30 Days / Earlier**（设计稿）
- 每条显示时间：今天内显示「N min ago / N h ago」（沿用现有），其余显示「8 Oct, 15:57」（设计稿）
- **系统推送的文案与通知中心条目文案保持一致**（设计稿）

**各类型文案与点击行为**

| 类型 | 文案（EN 示例，设计稿） | 点击 |
|---|---|---|
| 举报已处理 | Report reviewed / Your report has been handled… | **无动作**（设计稿） |
| 评论了你的帖子 | **Doggo** commented on your post + 评论内容 | 进入帖子 |
| 回复了你的评论 | **Doggo** replied on your comment + 回复内容（与「评论了你的帖子」共用 CONTENT_COMMENTED 类型，按评论对象区分文案，2026-10-12 拍板） | 进入帖子 |
| 评论了你创建的场所 | **Pet Walker and 5 others** commented on the place you added（2026-10-12 拍板，替换设计稿的「place you mark」，ID 文案同步） | 进入场所 |
| 点赞 | **Catto and 10 others** liked your post | 进入帖子 |
| 新粉丝 | **Pet lover daycare** started following you.（未回关时条目右侧带 Follow Back 按钮；已回关不显示按钮） | 进入对方主页；按钮可直接回关 |
| 成就 | 成就标题 + 描述（如「Postingan pertama live!」） | 进入里程碑页 |

- 点赞：显示**最新一位**点赞人 +「and N others」（设计稿）
- 场所评论：只显示**最新一位**评论人 +「and N others」，**不显示评论内容**（设计稿）
- 帖子评论 / 回复：显示评论人 + **评论原文**，单行截断（设计稿）

#### 聚合规则

- **点赞（2026-10-12 拍板）**：只要这条帖子的点赞通知**还没读**，新的赞就并进去（更新最新点赞人、人数 +1、时间刷新并移到最上）；已读之后再有新赞，新起一条
- **场所评论（2026-10-12 拍板）**：同一场所按点赞的同样规则合并
- **帖子评论 / 回复（2026-10-12 拍板）**：**不合并**，每条单独显示——要展示评论内容
- **新粉丝（2026-10-12 拍板）**：每人一条，不合并（需要逐个显示回关按钮）
- **点赞推送去抖（2026-10-12 拍板）**：同一帖子的点赞推送 **10 分钟内最多一条**，文案取推送时刻的聚合结果；评论 / 回复 / 关注每次都推送
- 「and N others」中的 N 不含已拉黑、已注销的账号；取消点赞**不回退**已生成的通知（2026-10-12 拍板）

#### 新增类型

- **`USER_FOLLOWED`**：被关注时发给被关注者。同一人取关后再关注，24 小时内不重复通知（2026-10-12 拍板）
- **`PLACE_COMMENTED`**：有人在**我自己创建的 pet friendly 场所**下评论时，通知该场所的创建者（2026-10-12 拍板）。仅打过卡、收藏过的场所不通知；创建者自己评论不通知
- 取消关注不新增任何通知类型（见 FR-140）

#### 边界与不做项

- 不做通知分类 Tab（与 FR-138 一致，所有类型同列展示）
- 不做按类型的推送开关（属 V1.4.0 待定项）
- 举报已处理点击后仍无跳转
- 其余 20 余种系统通知（订单、客服、生命周期等）只跟随新的时间分段与未读样式，文案与图标不变

#### 验收标准

- **AC1**：通知中心按 Today / Yesterday / Last 7 Days / Last 30 Days / Earlier 分段，**按手机本地时间划分**（2026-10-12 拍板，沿用现有通知中心「今天」的判断方式）
- **AC2**：未读为浅紫底 + 紫色圆点，**圆点位于类型图标右上角**（2026-10-12 调整，避免与右侧回关按钮挤在一起）；点开后变为白底、圆点消失；点「全部已读」后全部变为白底
- **AC3**：点赞 / 评论 / 关注通知的文案中显示触发人昵称；通知中心任何条目都不显示头像、帖子图或场所图；帖子已删除时点击提示「内容已不存在」
- **AC4**：同一帖子 3 人连续点赞且通知未读时，通知中心只出现一条「最新点赞人 and 2 others liked your post」
- **AC5**：评论通知显示评论原文；评论已删除时显示「评论已删除」
- **AC6**：在新粉丝通知上点 Follow Back 可直接回关，按钮变为 Following 且可立即点击取关，不会进入对方主页；刷新后按钮隐藏
- **AC7**：推送文案与通知中心条目文案一致（同语言、同触发人、同人数）
- **AC8**：各类型点击跳转符合上表；举报已处理点击无反应

#### 影响面

- **数据表须新增字段**：actor_user_id（最新触发人）、actor_count（聚合人数）、聚合键（如 `LIKE:POST:{id}`）。触发人昵称在**读取时**按 actor 现查，不落库（昵称会改）
- **约束重建**：新增 `USER_FOLLOWED`、`PLACE_COMMENTED`，与主 PRD FR-138 的运营通知类型**合并到同一个迁移**，DROP + ADD 重列全集
- **文案**：互动类通知要带参数（人名、人数、评论内容），App 不能再只按 type 显示写死的文案。**这几种类型的文案由后端统一拼好**（2026-10-12 拍板）：后端按账号语言用同一套模板拼出完整文案——推送在发送时拼；通知中心列表在**返回列表时**现拼（取触发人当前昵称、聚合人数与评论当前状态，如评论已删除则拼「评论已删除」），App 直接显示，不再按 type 写死
- **存量通知**：上线前已有的点赞 / 评论通知没有触发人，按旧文案（通用文案）显示，不回填
- **列表接口性能**：每页 20 条须批量查询触发人昵称，禁止逐条查询
- **评论内容会进入锁屏推送**：须走与评论相同的敏感词过滤；被审核拦截的评论不发通知
