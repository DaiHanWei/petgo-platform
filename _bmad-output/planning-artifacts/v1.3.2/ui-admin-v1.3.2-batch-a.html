◇ 落地前须知（研发重点）
  • 用户详情抽屉须由 480px 加宽至 600px——六个页签在中/英/印尼三种语言下都放不下 480px。场所等其余抽屉维持 480，后台由此存在两种抽屉宽度，这是有意的、不是不一致。
  • 定价下限 100 IDR，DB 四列 CHECK 须随迁移由 >= 1 改为 >= 100；配置页不得出现任何「0 = 限免」字样。
  • 支付记录的用途筛选为多选：purpose 由单值变多值后，分页链接、整表刷新、导出 xlsx 三处都要带完整多值参数，漏改任一处会在翻页或导出时静默丢掉筛选条件。
  • 专属章的上传／替换／移除是三个独立动作，不并入场所编辑表单（那是纯文本 htmx 表单，不是 multipart）；移除须二次确认并写明影响已盖出的章。
  • 已购解锁页签只读，不得出现退款／撤销／补发按钮；数据读各业务表而非支付表，PawCoin 付费的解锁也要能查到。
  • 三语文案中，第六页签的 ID 文案与三个新 purpose 的三语 key 为拟稿，需随开发补进语言包。

连带：后台将出现两种抽屉宽度（用户详情 600 / 其余 480）。这是有意的取舍，不借本条目统一加宽全部抽屉。
ID 与 EN 文案取自 messages_id.properties / messages_en.properties 真实值；第六页签的三语为拟稿，需随开发补进语言包。宽度为 Chrome 实测渲染结果。
