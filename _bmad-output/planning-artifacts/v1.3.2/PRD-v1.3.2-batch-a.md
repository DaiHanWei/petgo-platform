## 2. 里程碑业务现状（FR-111 视觉重绘的现状基线）

> 本节是里程碑模块**当前线上行为**的完整描述，视觉重绘须完整覆盖以下全部触发路径与展示场景，不能只改静态图。V1.3.0 已上线的逻辑变更（`celebrated_at` 补庆祝机制、G-M1/G-M2 自动达成）已经生效，以下描述已包含该现状。

**清单与维护方式**

- 清单为后端编译期常量（`MilestoneCatalog`，唯一事实源），运营不可编辑。猫 31 / 狗 31 / 通用 16，各含 1 个 S 级聚合里程碑「Lulus Pemula」（C-S16 / D-S16 / G-S9，6 项新手任务全完成自动解锁）
- 每个里程碑有稳定 code（`C-S1` 形式）、级别 S/M/L、触发类型三选一：系统自动（SYSTEM_AUTO）/ 用户打卡（USER_CHECKIN）/ 推送+当天发布（PUSH_PUBLISH）
- 展示标题一律在 App 客户端按设备语言取（en / id 双表），后端中文标题仅内部用、印尼语标题仅供 H5 分享页渲染；三处由跨库测试钉住，改任何里程碑文案须三处同步

**完成路径**

- **打卡类**：里程碑列表页点未完成徽章 → 底抽屉（徽章 + 标题 + 级别 + 说明文案）→「已打卡」关联一条本人成长日历内容（已关联过其它里程碑的内容置灰）/「去发布」跳发布页预选成长日历类型，发布成功后自动以新内容回填打卡（失败静默，可回列表页手动关联）
- **健康类六条（猫狗 M3/M4/M5/M9 + 通用 G-M1/G-M2，V1.3.0 已扩展至通用宠物）已取消打卡**：只能由健康记录录入 / 真人兽医咨询结束自动完成；列表页点这些条目的未完成徽章**直接跳健康记录页并预选记录类型**，不弹抽屉
- **系统自动类**（建档、首图、首帖、被赞、被评、陪伴天数、记录条数、健康组合、新手毕业）：后端事件驱动，事务提交后异步落库
- **推送+发布类**（L1 生日 / L2 100 天 / L3 365 天）：提醒由 FR-40 / FR-41 推送承担，用户当天（生日 ±1 天）发布成长日历记录后自动完成

**庆祝页（所有级别共用一套，无级别分叉——本版本视觉重绘对象，见 §3.1）**

- 全屏纯深色页（#141019）；渐变大徽章 + 徽章下沿级别小标签（L 金 / M 紫 / S 绿，这是级别差异的唯一视觉表达）；掉落彩纸循环；解锁瞬间一次短振动（原生通道，绕过系统触感开关）
- 内容：解锁标头 · 按 code 取的双语庆祝标题/正文（含宠物名占位）· 宠物名 + 完成日期胶囊 · KOLEKSI 已解锁合集预览（级别色圆点，两排放不下折叠「+N」）· 「分享到社区」按钮 · 「查看全部里程碑」入口
- 关闭方式：右上角 ×、左右滑动、点遮罩
- **分享产物是 H5 链接**（服务端渲染分享页，不可枚举 token，携带客户端本地化文案与合集级别串），所有级别都有分享按钮
- **已完成徽章点击 → 重温同一庆祝页**（含分享入口）

**庆祝触发时机（含V1.3.0 已上线的漏庆祝收口逻辑）**

- 打卡「已打卡」路径：关联成功后立即弹
- 「去发布」路径：发布成功 → 回填打卡 → 弹庆祝 → 关发布 sheet → 跳里程碑列表页
- 健康记录保存路径：后端完成为异步，App 保存后按 500 / 800 / 1200ms 三次重拉列表 diff 出新解锁；三次都没拉到则静默、当场无庆祝（**V1.3.0 已上线补庆祝机制**：进入里程碑列表页会自动补弹）
- **同一操作同时解锁多条 → 只弹一次，取级别最高的一条**，其余由 KOLEKSI 圆点带过（含补庆祝路径，全路径统一规则）
- 系统自动类里程碑在用户不在场时解锁（如被点赞）：**无庆祝**，仅通知中心留痕（同样吃V1.3.0 的补庆祝机制）
- 健康记录保存无新解锁时不弹任何里程碑文案

**通知**

- L 级完成：通知中心 + 系统推送，点击深链到里程碑列表页
- S/M 级完成：只写通知中心、不推送（FR-76）
- 存量不回填；一次多条则写多条

### 3.1 里程碑庆祝页与徽章视觉重绘（FR-111，本版本范围：仅视觉部分）

> **范围说明：** 逻辑变更（漏庆祝收口、G-M1/G-M2 自动达成）已随 V1.3.0 上线，本版本不重复开发，只做以下视觉重绘。

**基线（已拍板）：** 统一庆祝页为唯一庆祝形态，不做按级别分叉的页面结构。

#### 已确认项（本版本开发范围）

**庆祝页与徽章视觉方向（2026-08-28 拍板）**

- **L 级需要更强的仪式感**（具体形式 UI 阶段出方案，但不引入按级别分叉的页面结构——统一页基线不变）
- **庆祝页整体视觉替换**，不是微调
- **里程碑徽章视觉系统整体替换，风格要大胆创新、有活力**——现状是「统一奖杯图标 + 级别色圆底」的占位级视觉。替换波及四处，须同套系统一：庆祝页大徽章 / 里程碑列表页徽章墙 / 庆祝页 KOLEKSI 合集圆点 / H5 分享页徽章渲染
- **徽章形态（2026-08-28 拍板）：逐条专属插画，按语义去重**——跨物种语义相同的里程碑（陪伴 30/100/365 天、被点赞、被评论、建档、首图、首帖、生日、Lulus Pemula 等）**共用一枚插画，以「尾巴」为主视觉元素**（一图跨猫/狗/通用复用）；物种特有的（钻纸箱、咕噜、摇尾巴、玩球、游泳等）**分开单独画**。按现清单估算：跨物种共用约 22 枚 + 猫特有 8 枚 + 狗特有 8 枚 ≈ **38 枚插画**（非 78 枚逐 code 画）
- **产制方式（2026-08-28 拍板）：AI 生成 + 人工要求调整**，与 FR-117 的 16 套角色插画同一产线、风格统一
- 资产交付须同时覆盖 App 端与 **H5 分享页**（服务端渲染，徽章图两端共用同一套资源）；插画与 code 的映射表随三处文案同步机制一并维护

**保留清单（2026-08-28 拍板：本次改版明确不动）**
- 庆祝页三种关闭方式（右上角 × / 左右滑动 / 点遮罩）
- 解锁瞬间振动（原生通道，绕过系统触感开关）
- 存健康记录无新解锁时不弹任何里程碑提示（2026-08-05 既有拍板）
- 已完成徽章点击重温庆祝页
- `{name}` 占位符与 en/id 双语文案机制

### 3.2 Tailsonality 宠物人格测试（FR-117，2026-08-28 由待排期功能池移回，补编号）

**定位：** 本版本第二个拉新钩子（与 FR-65 并列）——测试结果卡是高分享意愿的社交货币；**同时是本版本的内容型付费点**：免费态足以支撑传播，深度解读与无水印高清卡付费解锁，拉新与变现互不挤占。

**范围（沿用池内已定稿设计，本节只列要点与本次变化；用户旅程、付费与重测规则以本节为准，池内存档中关于重测与变现的旧表述全部作废）：**

- 4 轴 × 2 极 = 16 种角色人格；**18 题**混合题型（15 道行为观察 + 3 道图片选择）；结果角色 Jaksel 混搭风格命名
- **字母体系（2026-09-18 定稿，替换 2026-09-14 的 S/O·G/C·R/Z·T/L 与更早的「社交能量/驱动力/情绪表达/生活节奏」）**：四轴对齐大众熟悉的四字母形态——**社交取向 E↔I · 探索倾向 N↔S · 情绪反应 T↔F · 驱动力 J↔P**，外加**能量水平后缀 -H↔-L**（High / Low energy）。最终代号形如 **`ENTJ-H`**，在结果页与两张分享卡上展示
- **⚠️ 合规红线：App 内、商店文案、运营素材一律不得出现「MBTI」字样**，也不得宣称与之等价。MBTI 为注册商标；四字母组合本身不受商标保护（16Personalities 即先例：借四字母外形、内核换 Big Five、以 -A/-T 后缀切割），但那个词不能用。对外一律称 **Tailsonality**
- **⚠️ 情绪轴计分方向与其余四轴相反**：其余四轴先写的字母为正分（E/N/J/-H），**唯独 T↔F 的正分是后写的 F**（反应大 = 敏感 = F）。按「轴名里 T 在前所以 T 是正极」实现会导致 16 个角色有 8 个整片对调，且测试跑得通不报错。验收用例见内容设计文档
- **题库按物种分套**：猫一套、狗一套，其他物种走通用套；三套**共用同一批四轴与 16 个角色**，插画仍为 16 套、不按物种翻倍。题库按宠物档案的物种字段自动选择，不询问用户
- **16 格分布不做阈值校准**：接受自然分布，冷门角色即稀有款，不为均分用户而扭曲阈值
- 进入方式：~~档案创建后自动引导~~（**2026-09-01 删除**，由档案页首进蒙层引导替代，见 FR-65「迁移与新功能引导」）+ **「Know more about your pet」综合入口内**（不再单设独立入口）
- CP 匹配不在本版本（依赖 1.6.0 社交图谱，预留）

### 3.3 宠物护照与场所盖章（FR-120，2026-08-28 立项——KTP 留存改造）

**问题：** KTP 付费效果好，但它是一次性仪式（领证 → 付费下载 → 分享 → 结束），功能单薄导致用完即走、留存差。本 FR 把 KTP 模块从「一张静态卡」扩展为「会长大的收集品」，提升留存与平台参与度。

**方案：宠物护照 + 场所打卡盖章**（KTP 卡面成长与限定卡面两个方向记入 Roadmap 功能灵感池，等数据后再议）。

#### 规格

- **护照签发**：护照号按既有设计 `2.数据算法/宠物身份码护照编码规则.md` 第二套编码（类型 + 顺序号，不含可解码宠物信息，后台关联表反查身份码）——该编码规则设计已久、首次获得功能承载。宠物首次进入护照页或首次打卡时自动签发，免费
- **盖章**：每次场所打卡（本版本 §3.4）= 护照盖一枚章。章面按场所**类型**区分（咖啡店/餐厅/公园/商场/酒店民宿/宠物服务/其他，7 款章面插画，与 FR-111 徽章、FR-117 角色同产线：AI 生成 + 人工调整）；**同一场所的章唯一**，重复到访在章上累计次数角标（×2、×3…）

  > **⚠️ 首次与重复的反馈不同（2026-09-23 UI 阶段拍板，补 PRD 原文空白）：** 原文「每次场所打卡 = 护照盖一枚章」与「同一场所的章唯一」之间有矛盾——重复到访并不产生新章，只是计数 +1，此时「盖章瞬间做落章动效」没有落章对象。规则定为：
  > - **首次到该场所**（盖出新章）：打卡成功页给小尺寸落章轻反馈 +「去看护照」入口 → 护照页播**整页落章完整仪式**
  > - **重复到访**：打卡成功页只给**角标 ×2 跳动的轻反馈**，**不播整页落章、不主动引导去护照页**；护照页内该章仅更新角标
  > - 理由：没有新章可落，重复看同一套仪式会从惊喜变成干扰
- **章面素材（2026-09-24 拍板，替换原「按场所类型 7 款插画」）：一个场所一枚专属章，由运营在后台为该场所上传。**
