## 1. AB-18A：一次性解锁定价配置

**背景：** 本条目 2026-09-01 随护照解锁（FR-120）立项于 V1.3.0。2026-09-18 FR-120 与 FR-117 整体移出 V1.3.0、独立成 V1.3.2，本条目失去在 V1.3.0 的服务对象，随之移入本版本，与付费点同版本交付。

**本版本新增的三个付费解锁点（全部由本条目承载定价）：**

| 解锁项 | 对应 App 端 FR | 默认售价 | 计价单位 |
|---|---|---|---|
| 护照 · 护照内页 | FR-120 | **Rp2,000** | **每次快照解锁**（章变多后想要新版本要再买一次） |
| 护照 · 登机牌 | FR-120 | **Rp1,000** | **每张**（每宠物每场所各一张），一次性 |
| Tailsonality · 结果解锁 | FR-117 | **Rp5,000** | 每次测试结果，一次性 |

> **⚠️ 改价约束：护照内页（快照）的价格必须 ≥ 登机牌（单张）的价格。** 快照含当前全部章，单张登机牌只含一个地点；如果快照定得比单张便宜，用户一次买快照就拿到所有章的无水印图，登机牌这个 SKU 会彻底卖不动。配置页四行虽然各自独立，但这一条要写进运营说明——**后台不做强校验，靠运营知道**。

> **2026-09-24 变更 A：护照内页改为快照解锁。** 本行价格的含义从「买断护照内页这款样式」变为「解锁**当前这一版**快照」——用户之后盖了新章，想要含新章的版本需再付一次。这是全 App 唯一一个会重复收费的 SKU。

> **2026-09-24 变更 B：登机牌改为按张计价。** 配置项本身不变（仍是一行、一个价格输入），变的是这个价格的**含义**：原为「解锁登机牌这一款样式（整本一次）」，现为「解锁**一张**登机牌（一个宠物在一个场所的那张卡）」。
> **配置页上这一行的标签与说明文案必须改**，否则运营会按旧理解定价——用户去 10 个地方就是 10 次 Rp1,000，与「一次 Rp1,000 买断」是完全不同的收入模型与心理价位。建议行标签写作「护照 · 登机牌（每张）」，行下附一句说明。

> **2026-09-21 变更：** 原第四项「Tailsonality · 配型解锁 Rp3,000」已取消——主人 × 宠物配型改为整体免费，配型卡的无水印能力并入结果解锁。本组因此**少一行**。

**页面位置与流程：** 既有**运营配置页**内的「定价配置」组扩充——KTP 卡高清下载（**自原组保留、不迁出**）+ 上表三行，共四行；每行样式名只读 + 价格输入；**每卡自带保存钮**（未修改禁用 → 修改激活并标「已修改」→ 高危确认弹层复述新旧值 → 提交），沿用现状每组各自提交的模式。**不新增页面、不新增菜单项。**

**规则：**

- 新增解锁项上架时由工程随发版在配置组内加行（解锁项本身为发版内容，后台只管价格）
- 改价即时生效，只影响**新发起**的解锁购买；已解锁用户不受任何影响（一次性永久语义）
- **四行各自独立配置、互不联动**——改 KTP 价不联动护照价，改护照内页价不联动登机牌价
- **登机牌行的价格是单张价**，改价只影响此后新发起的单张解锁；用户已解锁的那些场所的卡不受影响，也不会因为改价而需要补差价
- 价格校验：非负整数（IDR）
- **允许配 0 = 该项限时免费解锁**（运营活动用），0 价解锁同样落购买记录
- **⚠️ 零价短路必须与本条目同版本实现。** `[2026-09-01 代码核验，结论仍适用]` 现有 KTP HD 购买链路**无 0 价短路**——price 直接进 PawCoin 扣减 / QRIS 建单，0 元建单大概率被渠道拒。需工程新增 `price == 0` → 跳过支付直接发放解锁并落 0 元购买记录。**若本版本不实现该短路，则「0 = 限免」这个值不可用**，配置页须把 0 校验为非法值挡住，不能让运营配了一个会导致支付失败的价格
- 成交价以**购买记录中的历史值**为准，改价不得回溯影响已产生的订单与对账
- 所有改价操作经统一审计入口落审计日志
- 权限：沿用既有定价配置项的 permission_code，不新增

**⚠️ 本条目已有代码在开发中（2026-09-18 确认）：** 代码原按 V1.3.0 的三行范围（KTP 卡 HD + 护照两款）编写，现需扩到四行（加 Tailsonality 结果解锁一行）。**处置：已写代码合入本版本分支、不进 V1.3.0 发版**——工时不浪费，也避免「配置项已存在但无消费方」的死配置期。原方案中「把 KTP 卡 HD 从原定价配置组迁入新组并更名」的动作，按下方【建议】处理。

#### 【建议】配置组组名（待过审）

本条目在 V1.3.0 立项时拟名为「**KTP 模块高清图解锁定价**」，当时只含 KTP 与护照。本版本纳入 Tailsonality 结果解锁后，该组名已明显不准确——Tailsonality 不属于 KTP 模块，运营按组名会找不到它。

建议改为「**一次性解锁定价**」或「**付费解锁定价**」，并在组说明里一句话点明「本组管理全部一次性付费解锁项的售价」。更名只动展示文案，不动配置 key、不动权限、不动数据，无迁移成本。

#### UI 说明

V1.3.0 的后台整合稿（`../V1.3.0/ui-admin-g0-templates-integrated-v1.html` 帧 7-1 / 7-2）画过该组的三行形态与高危确认弹层，可作为版式参考。本版本需在同一张分组卡内**按既有行样式扩到四行**，并同步更新示例价格（护照两款为 Rp1,000，不再是 Rp5,000）。若采纳上方【建议】更名，则同时改卡头文案。

## AB-18B｜场所专属章素材管理（FR-120）

**页面位置：** 既有**场所管理**的单个场所编辑页内新增一个「专属章」字段区，与场所基础信息同页同一次保存。**不新增页面、不新增菜单项、不做独立的素材库**——章是场所的属性，一个场所一枚，没有复用场景。

**运营能做什么**
- 为该场所上传一枚专属章素材；已上传时显示当前章的预览 + 「替换」「移除」
- 移除后该场所回落到**按类型的默认章**（7 款：咖啡店 / 餐厅 / 公园 / 商场 / 酒店民宿 / 宠物服务 / 其他）

**规则**
- **未上传即走兜底，不是错误态。** 运营不可能给每个场所画章，绝大多数场所会一直用默认章；编辑页不得把「没传专属章」标成警告或阻断保存
- **换章对已盖出的章生效。** 章是场所的属性而非打卡快照——同一场所的用户看到的是同一枚章，换了就都换。这条要写进运营说明，避免运营以为只影响新打卡
- **上传校验必须做**（规范由设计给，后台按规范挡）：格式、尺寸、**单色**（颜色由客户端统一着色，素材本身不带色）、透明底、图形须落在圆形安全区内。**没有校验的话，运营传一张彩色照片进去，护照页的视觉统一当场就没了**——这是本条目最主要的风险
- 场所合并时：保留方的专属章生效，被合并方的素材随场所一并归档
- 场所下架时：章素材**保留**（已盖的章要继续显示）

**⚠️ 待设计给的输入**：章面素材规范（格式 / 尺寸 / 单色要求 / 安全区），后台校验规则依赖它，规范没给之前这条无法开发。
