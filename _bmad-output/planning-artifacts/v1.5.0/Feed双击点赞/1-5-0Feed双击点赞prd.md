# PRD：TailTopia 宠物 App——Feed 双击点赞

## 0. 文档说明

在 Feed 卡片的图片上双击即可点赞，交互参照 Instagram 首页：双击 → 图片偏右（左右 6:4）弹出大红心 → 下方爱心按钮同步变红、计数 +1、手机轻震。

| 编号 | 功能 | 来源 |
|---|---|---|
| **FR-209** | 图片区双击点赞（手势、规则、生效范围） | 2026-11-12 操作者提出，同日定入 1.5.0 |
| **FR-210** | 点赞状态按帖子统一管理（双击与爱心按钮同步；Feed 点赞写回各列表，顺带修复切页签后点赞状态回退） | FR-209 的前置改造 |
| **FR-211** | 双击爱心动效与触感反馈 | FR-209 |

**版本：** **V1.5.0**，11/19 交付（2026-11-12 拍板）。

**编号：** 接 FR-195，本文用 **FR-209 ~ FR-211**。本文没有后台需求（AB），后端不改。

**代码基线：** `petgo-platform` 远端 `origin/main`（`4fed8dd66`，2026-11-11）。数据为 PostHog 2026-10-20 ~ 11-07（11/8 起断流，不含之后）。

**本文不含：**
- **详情页 / 大图查看页的双击点赞**：本版不做（2026-11-12 拍板）。详情页点图片是打开大图，大图里双击是放大，两处语义冲突
- **纯文字帖的双击**：没有图片区，正文区有 @ 和 #话题 可点，叠加双击容易误触
- **双击取消点赞**：双击只点赞，取消仍点爱心按钮
- **新手引导 / 提示「可以双击点赞」**：首版不做，看上线后双击占比再决定
- **评论点赞的双击**
- **首日推荐页（「首日与新手任务」FR-173）宠物卡上的图片**：那里图片本身就是点赞入口，不加双击

**UI 稿状态：** 待出。动效是本需求的主要视觉，交付物为整合稿 HTML（含动效演示与研发执行说明）。

## 1. 版本目标

**降低在 Feed 里点赞的成本，提高点赞量。** 现在 Feed 里点赞只能点卡片下方 20×20dp 的小爱心；而用户看图时手指本来就在图片上。点赞是作者收到反馈、愿意继续发帖的主要信号（被赞会推送给作者），点赞量提升直接作用于发帖留存。

10/20–11/07 点赞（不含取消）：

| 位置 | 点赞次数 | 点赞人数 |
|---|---|---|
| Feed 卡片 | 4,943 | 615 |
| 详情页 | 1,651 | 237 |

Feed 已占点赞的 75%，是点赞的主场景。

**核心指标（上线前后对比，不做 A/B）：**
- Feed 人均点赞次数（点赞次数 ÷ Feed 浏览人数）、Feed 点赞人数占 Feed 浏览人数的比例
- 双击点赞占 Feed 点赞的比例（埋点 `trigger`，见 §4）
- 作者侧：日均被赞的帖子数、被赞作者数
- 游客双击带来的注册数（`entrySource` = `double_tap_like`）
- **护栏**：
  - 从 Feed 进详情页的人均次数——单击图片进详情会多等约 220ms（见 FR-209），不得明显下降
  - 取消点赞率（取消次数 ÷ 点赞次数）——不得明显上升，上升说明误触点赞多
  - 详情页点赞次数——下降是正常的（部分点赞前移到 Feed），和 Feed 增量合计看是否净增

> 口径：事件数据从自家服务器读（2026-11-11 起埋点改报自家服务器）；迁移完成前的历史基线在 PostHog。点赞总量以业务库 `content_likes` 为准，事件只用于拆分来源和触发方式。1.5.0 同期上线首日推荐页点赞和新手任务，会一起推高点赞量，看本功能效果以双击占比和 Feed 人均点赞为主。

## 2. 现状（2026-11-12 核实代码 `origin/main`）

| 维度 | 现状 |
|---|---|
| Feed 版式 | 单列通栏卡片（V1.1.6 改版），图片全宽贴屏幕两边。组件 `shared/widgets/masonry_card.dart`（名字是历史遗留，实际不是瀑布流） |
| 用到这张卡的页面 | 首页「发现」、首页「关注」、话题页（`topic_page.dart`） |
| 卡片手势 | 作者行 → 迷你主页；「···」→ 更多；**图片和正文单击 → 进详情页顶部**；图片和正文长按 → 举报菜单；爱心 → 就地点赞；数字 → 点赞人列表；评论 → 详情页评论区；分享 → 分享卡 |
| 多图 | 图片区是左右滑动的轮播（`feed_image.dart` PageView），底部居中有圆点 |
| 图片区叠加层 | 三个角位架构定死（AD-8 Rule 6，`feed_overlay_test.dart` 盯着）：底部居中轮播圆点、右上顶置角标、左下装饰标签 |
| 顶置卡 | 运营顶置的帖子在列表顶部单独出一张卡，**同一条帖子可能同屏出现两次**（顶置卡 + 普通卡） |
| 点赞逻辑 | 全部在 `like_button.dart` 组件内部：先翻转 UI → 调接口 → 按后端返回校正 → 失败回滚；请求进行中再点无效；未登录弹登录窗。注释要求「直接复用、不得重写」 |
| 点赞接口 | `POST/DELETE /api/v1/content-posts/{id}/like`，**幂等**：已赞再赞不重复计数、不重复通知作者；自己赞自己不通知 |
| 已有双击处理 | 大图查看页自己判断单击 / 双击（`lightbox_gestures.dart`，窗口 220ms），不用系统自带双击——系统自带的会让单击等满 300ms |
| 点赞埋点 | `post_like_tapped`：`liked`、`source`（`feed` / `detail`）、`feed_tab`、`rank_mode`、关注流的 `reason`。事件名不能改（会断历史数据） |
| 动效 / 触感 | 没有爱心动效（现有 Rive 只有 `tailtopia_stamp.riv` 盖章）；点赞相关代码里没有震动 |

### 2.1 Feed 点赞不写回列表数据（2026-11-12 查代码确认）

各列表的数据和爱心按钮的显示是两份：

| 列表 | 数据来源 | Feed 卡片上点赞后会更新吗 |
|---|---|---|
| 首页「发现」 | `feedProvider` | **不会** |
| 首页「关注」 | `followingFeedProvider` | **不会** |
| 发现页顶置卡 | `pinnedSlotProvider` | **不会** |
| 话题页（帖子 / 顶置） | `topicPostsProvider` / `topicPinnedProvider` | **不会** |

- 只有**详情页**点赞 / 评论后会调 `syncFeedCounts` 写回「发现」和「关注」两个列表（bug 20260923-538 的修复）；Feed 卡片上的爱心按钮没接这个回写，顶置卡和话题页连详情页的回写也收不到
- 爱心按钮还在屏幕上时，它自己存的状态是对的，所以平时看不出来。**按钮被重新创建时就会读回旧数据**：
  - 「发现」里点赞 → 切到「关注」→ 切回「发现」：「发现」页是整页换掉重建的（`home_page.dart` 按页签二选一），回来后这张卡**显示回未赞、计数少 1**，下拉刷新才对
  - 同一条帖子在「发现」点了赞，切到「关注」看到的还是未赞
  - 顶置卡和下方普通卡是同一条帖子时，点其中一张，另一张不变
- 以上是读代码得出的结论，没有在真机上复现；上线前按 FR-210 验收标准实测
- 双击点赞之后，Feed 点赞会更多，这个问题会更常被看到，所以本版一起解决（FR-210）

## 3. 功能与需求

### 3.1 图片区双击点赞（FR-209）

#### 生效范围

- **页面**：首页「发现」、首页「关注」、话题页——即所有用 Feed 卡片的地方
- **区域**：只在**图片区**生效。正文区、作者行、操作行不响应双击
- **卡片**：普通帖子卡和顶置帖子卡都生效；运营推广卡（`promo_pinned_card`，不是帖子）不生效
- 纯文字帖没有图片区，不支持

#### 规则

| 情况 | 结果 |
|---|---|
| 未赞 + 双击 | 点赞（等同点爱心）+ 大红心动效 + 轻震（FR-211）+ 爱心按钮变红、计数 +1 |
| 已赞 + 双击 | **不取消**；只播大红心动效，不震、不发请求、不报点赞事件 |
| 点赞请求进行中再双击 | 只播动效，不发第二次请求 |
| 点赞失败 | 爱心按钮和计数回滚（沿用现有逻辑）；大红心照常播完，不额外提示 |
| 自己的帖子 | 和点爱心一致（可以赞，后端不通知自己） |
| 游客双击 | 弹登录窗（2026-11-12 拍板），和游客点爱心一致；不播动效、不震；`entrySource` 记 `double_tap_like`。登录后不自动补上这次点赞（沿用爱心按钮的现有游客行为） |
| 帖子已删除 / 不可见 | 接口报错 → 回滚，同点爱心 |

#### 单击和双击的判断

- 图片区**不能**直接用系统自带的单击 + 双击：单击会等满 300ms 才进详情。改为自己判断，**复用大图页的做法**（`lightbox_gestures.dart` 的 `kLightboxSingleTapDelay`，220ms）：
  - 第一下抬起后 220ms 内在附近再点一下 → 双击
  - 220ms 内没有第二下 → 单击，进详情页
- **代价**：单击图片进详情会比现在晚约 220ms。正文区单击不受影响（正文不挂双击）
- 双击后 220ms 内的第三下忽略（不进详情、不重复触发），避免连点三下误进详情
- 两次点击距离超过系统双击判定距离（`kDoubleTapSlop`）→ 按两次单击处理（第一次进详情）

#### 和其他手势的关系

| 手势 | 要求 |
|---|---|
| 多图左右滑 | 双击在任何一页都生效，**不翻页**；第二下手指有轻微位移不能被识别成滑动 |
| 上下滚动 | 手指按下后开始滚动 → 不算点击（不进详情、不算双击） |
| 下拉刷新 | 不受影响 |
| 长按 | 仍是举报菜单；长按不参与双击判断 |
| 顶置角标 / 装饰标签 | 不可点的叠加层，双击落在上面照常生效 |
| 系统读屏（TalkBack / VoiceOver） | 读屏模式下「双击」是系统的激活手势，自定义双击不生效；读屏用户继续用爱心按钮，图片区的语义仍是「打开详情」 |

#### 验收标准

- AC1：未赞的帖子，双击图片 → 爱心按钮变红、计数 +1，后端 `content_likes` 新增一行，作者收到点赞通知
- AC2：已赞的帖子，双击图片 → 只出大红心，按钮保持红色、计数不变，不发请求、不震
- AC3：单击图片 → 约 220ms 后进详情页顶部；双击不进详情
- AC4：多图帖在第 2 / 3 张双击 → 点赞成功，轮播不翻页
- AC5：快速连点三下 → 只点赞一次，不进详情
- AC6：游客双击 → 弹登录窗，不出大红心；登录完成后这条帖子仍是未赞
- AC7：正文区、作者行双击 → 不点赞（正文区第一下单击照常进详情）
- AC8：断网双击 → 大红心播完，按钮回滚为未赞、计数恢复
- AC9：滚动中手指划过图片 → 不进详情、不点赞
- AC10：长按图片 → 举报菜单，和现在一致

#### 影响面

- `masonry_card.dart`：图片区手势从系统单击改为自定义单击 / 双击判断
- `feed_image.dart`：图片区新增动效层（见 FR-211）
- 话题页、关注流跟着首页一起生效（同一组件），需一并回归

### 3.2 点赞状态按帖子统一管理（FR-210）

两个问题一起解决：
1. 双击发生在图片上，爱心按钮在卡片下方，现在按钮自己存状态，图片区没法让它点赞
2. Feed 卡片上点的赞不写回任何列表，切页签、同一帖多处显示时状态对不上（见 §2.1）

#### 要求

- 点赞状态（是否已赞、点赞数、请求是否进行中）按帖子编号存一份，爱心按钮和图片双击读写同一份
- **点赞结果落定后写回所有持有这条帖子的列表**：「发现」、「关注」、发现页顶置卡、话题页帖子与顶置。没建过的列表不为了写回去创建它（沿用 `syncFeedCounts` 的做法）
- 详情页点赞 / 评论后的写回范围同样补上顶置卡和话题页
- **现有点赞逻辑一条不能少**：先翻转 UI、按后端返回校正、失败回滚、请求进行中不重复发、未登录弹登录窗、刷新列表后跟随新数据（但不能覆盖进行中的乐观更新）、埋点属性（`source` / `feed_tab` / `rank_mode` / `reason`）
- 爱心按钮的外观、热区、点赞人列表入口不变

#### 验收标准

- AC11：顶置卡和普通卡是同一条帖子时，双击或点爱心其中一张，两张卡的爱心和计数同时变化
- AC12：点爱心按钮的全部行为和改造前一致（`like_button` 现有测试全部通过，不改测试预期）
- AC13：Feed 点赞后下拉刷新，状态以后端为准，不闪回未赞
- AC14：Feed 点赞 → 进详情页 → 详情页显示已赞；详情页取消 → 返回 Feed 显示未赞
- AC15：「发现」点赞（双击或点爱心）→ 切到「关注」再切回 → 仍显示已赞、计数正确
- AC16：「发现」点赞 → 切到「关注」，同一条帖子显示已赞
- AC17：话题页点赞 → 返回首页，同一条帖子显示已赞；反之亦然

#### 影响面

- `like_button.dart`：状态外提。组件注释写明「不得重写」——本条是有意改造，改造后更新该注释，说明状态已统一管理
- `feed_controller.dart` 的 `syncFeedCounts`、`following_feed_controller.dart`、`pinnedSlotProvider`、`topic_providers.dart`：补写回
- 详情页底栏的爱心也是同一组件，需回归

### 3.3 双击爱心动效与触感反馈（FR-211）

#### 动效

- **颜色**：点赞红 `AppColors.likeHeart`，和爱心按钮一致（2026-11-12 拍板）；带柔和投影，保证浅色图片上看得清
- **位置**：图片区横向 60%（左右 6:4）、纵向居中，不跟手指位置；所有图片比例一致，按截住后的可见图片区算（2026-11-13 改，原为正中央）
- **样式**：圆胖心形 + 左上白色高光，点赞红系渐变（#FF8FA0 → #F0425A → #D42A55；两端为新色，须先在 `colors.dart` 新增 `likeHeartLight` / `likeHeartDeep`，该文件规定业务代码禁止写死 hex）+ 同色柔光；双心 + 小圆点（2026-11-13 定）：大心弹出，右上小心晚 70ms 冒出，5 颗 6dp 小圆点（`AppColors.coral` / `gold` / `dashedViolet`，与送礼落点粒子同一套，画法参照 `gift_send_animation.dart`）80ms 起约 450ms 内从大心中心四散淡出
- **层级**：图片之上、三个角位叠加层之上；不占用三个角位，不改图片区结构。这是 AD-8 Rule 6 之外新增的「临时中央层」，需架构确认并更新 `feed_overlay_test.dart`
- **实现**：Flutter 原生动画，不用 Rive（单一形状缩放 + 透明度，原生足够，省一份素材和加载）
- 数值：
  - 大心约 75dp；小心约 34dp，在大心右上（中心偏右 36、偏上 32），歪 14°（11-13 由 88 / 40 缩小 15%）
  - 弹出：0.3 → 1.12（约 180ms，强 ease-out）→ 0.96 → 1.0（约 150ms），不从 0 长出
  - 停留约 100ms
  - 退场：上飘 12dp（小心 22dp）、缩到 0.92、淡出，约 170ms
  - 小心比大心晚 70ms，同节奏；全程约 670ms
  - 小圆点位移见 UI 稿 D1（`DOT_SPEC`）
  - 播放中再双击：从放大处重播，不从最小重新长，屏上始终只有一组心
- 下方爱心按钮在双击时同步做一次小幅弹跳（1.0 → 1.2 → 1.0，约 200ms）；点爱心按钮本身也加同样的弹跳，两种入口反馈一致
- **重复触发**：动效播放中再双击 → 从头重播（不叠第二个红心）
- **减弱动效**：系统开启「减少动态效果」时，不缩放、不上飘、无圆点，只淡入淡出（约 400ms）
- **离开屏幕**：卡片滚出屏幕或页面被覆盖时动效直接结束，不残留
- **降级**：动效出错不影响点赞本身

#### 触感（2026-11-12 拍板：加震动）

- 双击点赞时（未赞 → 已赞）轻震一次，用 `HapticFeedback.lightImpact`，和红心弹出同时
- 已赞再双击、游客双击不震
- 点爱心按钮点赞时也轻震一次，取消点赞不震——两种入口反馈一致
- 手机系统关了触感反馈时不震（系统自动处理）

#### 验收标准

- AC18：双击后红心在图片区偏右（横向 60%、纵向居中）弹出并消失，全程不超过 1 秒，不遮挡后续操作（动效层不拦截点击）
- AC19：横图、方图、竖图（含被高度上限裁过的长图）大心中心都在可见图片区横向 60%、纵向居中
- AC20：动效中再次双击 → 从放大处重播（不从最小重新长），屏上始终只有一组心
- AC21：开启系统「减少动态效果」→ 只淡入淡出，无缩放、上飘和小圆点
- AC22：动效播放中滚走卡片再滚回 → 不残留心和小圆点
- AC23：同屏多张卡快速各双击一次 → 各自动效互不干扰，滚动不掉帧（中低端安卓机实测）
- AC24：双击点赞成功 → 手机轻震一次；已赞再双击 → 不震（iOS / 安卓各测一台）

## 4. 数据埋点需求

**不新增事件**，扩展现有 `post_like_tapped`（事件名不改）：

| 属性 | 值 | 说明 |
|---|---|---|
| `trigger`（新增） | `button` / `double_tap` | 点爱心 / 双击图片。旧版本没有这个属性，按 `button` 算 |
| `source`、`feed_tab`、`rank_mode`、`reason` | 不变 | 双击点赞带上和爱心按钮相同的值（`source` = `feed`） |

- 只有真正发起点赞时才报；已赞再双击、请求进行中再双击**不报**（否则会把点赞量算大）
- 游客双击弹登录窗：登录转化走现有 `signup_succeeded`，`entrySource` = `double_tap_like`
- 后端 `content_likes` 不加来源字段（点赞总量看库，拆分看事件）
