## 1. 版本目标

用一个比单买便宜得多的组合包，让用户一次把高清 KTP、性格测试、多宠物、送礼这几样付费功能都体验一遍；对还没付过费的用户，它是门槛最低的**第一次付费**。

**观察指标：** 礼包购买率（看到礼包页的人里买了的比例）、各档占比、首次付费用户里通过礼包付费的占比、复购（第 2 次及以后）的比例、买礼包的人之后 30 天内再次付费的比例、权益次数的使用率与过期率。

## 2. 现状（2026-11-11 核 `origin/dev_1.4.2`）

| 项 | 现状 |
|---|---|
| KTP | 8 款模板：KTP、Paspor、KITAS、SIM、学生证 4 种配色（Bintang / Malam / Ceria / Klasik）。**创建免费、不限次数**；付费的是**每张卡的高清解锁**，各款同价，线上 **Rp1.000 / 张**（后台 `id_hd_download_price`；代码迁移里的初始值是 Rp5.000，线上已在后台改过，以操作者 11-11 口径为准），没解锁的卡带水印 / 低清 |
| 性格测试 | 做测试免费；**解锁结果** Rp5.000 / 份（`tailsonality_unlock_price`），按每份结果解锁；配对解锁另收 Rp3.000（不在礼包内） |
| 宠物名额月租 | Rp5.000 / 个 / 30 天；名额总数 = min(5, 默认 1 + 等级送的 + 租的)；到期前 3 天提醒、到期后多出的宠物只读；后台已能 0 元赠送名额（`ADMIN_GRANT`） |
| 送礼 | Rp1.000 档礼物（如 Ikan teri、Telur puyuh 等，具体以后台礼物目录为准）；付款只认 PawCoin / QRIS；**QRIS 最低 Rp10.000 只卡送礼** |
| 支付 | PawCoin（1 PawCoin = Rp1）或 QRIS（GemPay，60 分钟有效，**无最低金额**）；数字服务不能混合支付；每种付费用途一个 `PaymentPurpose` |
| 优惠 / 次数 | **没有通用的「次数 / 权益」表**；优惠券只能用于商城订单 |
| 消费返 EXP | 数字服务每 Rp1.000 = 5 EXP（新用途默认归数字服务档） |
| 推广位 | 运营开屏弹窗（人群可选「新用户」= 注册 ≤ 7 天；跳转 App 页面只有 首页 / 发布 / Toko / Know Your Pet / 健康）；没有首页 banner |

## 3. 功能与需求

### 3.1 三档内容（FR-194）

| 档位 | 价格 | 内容 | 单买合计 |
|---|---|---|---|
| 档 1 | Rp8.000 | 8 款 KTP 模板**各 1 次高清解锁**（8 × Rp1.000）+ 性格测试结果解锁 1 次（Rp5.000） | Rp13.000 |
| 档 2 | Rp11.000 | 档 1 全部 + 宠物名额 1 个 · 30 天（Rp5.000） | Rp18.000 |
| 档 3 | Rp13.000 | 档 2 全部 + 免费送 Rp1.000 礼物 5 次（Rp5.000） | Rp23.000 |

- 「8 款各 1 次」（2026-11-11 拍板）：每次高清解锁**只能用在对应那款模板的卡上**（如 KTP 次数不能拿去解锁 SIM）
- 页面上显示「单买合计」划线价，突出划算（2026-11-11 定）。**单买合计按后台当前单价实时算**，运营改了单价这里跟着变
- 价格后台可改（AB-41），内容首版固定、不可配置（2026-11-11 定）

### 3.2 谁能买、买几次（FR-194，2026-11-11 拍板）

- **谁都能买**（2026-11-12 定），不限新用户、不限是否付过费
- **可以买多次、可以买不同档**（操作者 2026-11-11 确认）；每次都是买**一整档礼包**，**不做补差价升级**（例：买过档 1 再想要档 3，就再花 Rp13.000 买一整份档 3）
- **任意一档买完后 7 天内不能再买**（任何一档都不能买）；从支付成功时刻起算满 7 × 24 小时
- 冷却期内：「我的」页礼包格显示「{n} 天后可再买」（2026-11-11 定），付费抽屉里的推荐行不显示；从开屏弹窗进入礼包页时三档按钮置灰并显示同一句
- 虚拟号、停用账号看不到；游客点入口先走登录
- **QRIS 待支付的礼包订单没完成前，不能再下第二单**：礼包页主按钮换成「继续支付」，回到这一单的二维码；这单也在「我的订单」里（见 §3.4）。过期或失败后可以重新下单

### 3.3 入口（FR-194，2026-11-11 定）

1. **「我的」页**：「活动」小节（AKTIVITAS）改成一张卡、一行三格（2026-11-13 定）：「我的订单」/「Koin & Jatah」（金币和免费次数，见 §3.5）/「超值礼包」。线上「我的订单」整宽卡改成格子，副标题由「含 PawCoin 余额」改为「查看订单进度」；礼包停售时礼包格不显示，剩两格
2. **付费抽屉里的推荐行**：高清解锁抽屉（`hd_paywall_sheet`）、性格测试解锁抽屉里，在付款按钮上方加一行「Rp8.000 解锁全部 8 款 KTP + 性格测试 →」，点了进礼包页；冷却期内、或该抽屉本来就能用权益次数免费解锁时不显示
3. **运营开屏弹窗**：开屏弹窗的跳转目标新增「礼包页」，运营自己配人群和频率（不由本需求写死）

### 3.4 礼包页与支付（FR-194）

- 一页三张档位卡，**默认选中档 3**，标「Paling hemat」（中文：最划算）；每张卡列内容、价格、单买合计
- 底部吸底主按钮「用 Rp{价格} 购买」→ 付款方式抽屉（改版后的 `pay_channel_picker`，见 §3.8）
  - PawCoin 不够：同线上，引导充值或改用 QRIS
  - QRIS：同线上二维码流程（60 分钟过期、失败可重试）
- **购买成功页**：列出到账的内容、权益次数的到期日（3 个月后）、宠物名额的到期日，以及各自去哪用（「去做 KTP」「去做性格测试」「去送礼物」）
- **计入 App「我的订单」**（2026-11-11 拍板）：每次购买一条订单，列表显示「超值礼包 · 档 {n}」、金额、支付方式、状态、时间；点开订单详情列出这一档的全部内容、到期日、订单号
  - **QRIS 待支付的单也显示**（2026-11-12 定），照 PawCoin 充值待支付单的做法：状态「待支付」、警示色、带「继续支付」按钮，点了回到二维码。注意线上 KTP / 性格测试解锁的待支付单**不进**订单页，礼包和它们不同
  - 过期没付的单从列表消失（同充值待支付单）；付款成功后变为「已完成」
- 用权益次数免费解锁 / 送礼**不生成订单**（记在「Koin & Jatah Saya」页的免费次数记录里）
- 购买按**数字服务**返 EXP（Rp8.000 = 40 / Rp11.000 = 55 / Rp13.000 = 65），之后用免费次数不再返
- **不退款**（同其他数字服务）；QRIS 重复支付等异常走现有人工处理

### 3.5 权益次数与「Koin & Jatah Saya」页（FR-195）

- **有效期：到账起 3 个月**（2026-11-11 拍板），到期没用完的作废；宠物名额不适用（见下表，按 30 天租期）
- **多次购买叠加**：每次购买的次数各自算有效期；使用时**先扣最早到期的**（2026-11-11 定）
- 运营活动（FR-193）发的次数也进这里，规则相同
- **不新建「我的权益」页，和线上 PawCoin 页合并**（2026-11-13 定）：线上 PawCoin 余额页（`PawCoinPage`，路由 `/me/pawcoin`）改为「Koin & Jatah Saya」（我的金币和免费次数），**路由不变**，现有跳转（订单列表 PawCoin 页签提示条、退款成功页、商城顶栏、各处「去充值」）都不用改
  - **名称不用「Dompet」（钱包）**：印尼用户会联想到能提现、能转账的电子钱包（GoPay / OVO 等）。余额卡下加一行说明：PawCoin 只能在 TailTopia 使用，不能提现、不能转到别的账号
  - **页面从上到下**：余额卡 +「Isi Saldo」（照线上）→ 不能提现的说明 →「JATAH GRATIS」区（每类一张卡：剩余次数、KTP 按模板分的次数、最早到期日、「去使用」，7 天内有到期的标红）→「Riwayat Hadiah」送礼记录入口（照线上）→ 记录区两个 Tab：「PawCoin 记录」（即线上流水，原「Riwayat transaksi」标题去掉）/「免费次数记录」（获得 / 使用，来源：礼包 / 活动名 / 后台补发）
  - PawCoin 和免费次数分两块、记录分开，**不能互相兑换**，页面上也不做任何换算
  - 没有任何未过期次数时，「JATAH GRATIS」区显示空态「还没有免费次数」+「看看超值礼包」按钮进礼包页（礼包停售时不显示按钮）；PawCoin 部分照常
  - 余额和次数任一接口加载失败，整页报错 + 重试（照线上），不只显示一半
  - 商城优惠券这版不并入，留在订单列表「Belanja」下（2026-11-13 定）
- **入口**（2026-11-13 定）
  - 「我的」页「活动」中间格「Koin & Jatah」**常驻**，副信息「{余额简写} · {n} jatah」（余额简写同商城顶栏，如 50rb）；后台礼包总开关关掉也照常显示。游客点了先走登录
  - **商城顶栏胶囊**：线上只显示 PawCoin 余额，改为「余额 | 免费次数合计」（超过 99 写 99+），点击照旧进本页；没有次数时只显示余额（同线上）；游客仍显示「登录」
  - 购买成功页「查看我的金币和免费次数」
  - 活动发到次数的站内通知（FR-193），点开直接进本页
- **到期前 7 天**发一条站内通知（2026-11-11 定）「你有 {n} 次权益将在 {日期} 到期」，点开进本页；不发推送

| 权益 | 怎么用 |
|---|---|
| KTP 高清解锁（每款 1 次） | 打开该款模板的未解锁卡 → 高清解锁抽屉里**付款按钮换成「用免费次数解锁」**（显示「剩余 N 次」），**点了直接解锁，不再二次确认**（2026-11-13 定：抽屉已开着，不叠确认抽屉），成功后 toast 提示用了 1 次；不走支付；这款用完后抽屉恢复原价 |
| 性格测试解锁 1 次 | 测试结果的解锁抽屉同上；用在哪份结果由用户选 |
| 宠物名额 1 个 · 30 天 | **买完立即生效**（2026-11-11 拍板）：名额 +1、从购买时刻算 30 天，到期提醒和到期处理同线上月租；到期后可按原价续租 |
| 免费 Rp1.000 礼物 5 次 | 选礼物目录里 Rp1.000 档的礼物，在送礼优化的包装页（FR-188）支付区多一个选项「免费次数（剩 N 次）」，**有次数时默认选中**；1 次 = 1 个 Rp1.000 礼物，数量不能超过剩余次数；选非 Rp1.000 的礼物不出现此选项 |

- 已经解锁过的卡 / 结果，不会重复扣次数
- **免费礼物的 EXP**（2026-11-11 定）：收礼方照常得 `GIFT_RECEIVED`（每个 +4，主人那边体验和付费礼物一样）；送礼方**不再得** `GIFT_SENT`（买礼包时已按金额返过）
- 免费礼物照常走送礼仪式、主人拆礼物、举报等全部流程，和付费礼物没有区别；礼物详情不显示「免费」

### 3.6 名额已满时（FR-194，2026-11-11 定）

名额总数最多 5 个。已经有 5 个名额的用户：档 2、档 3 照常可买，礼包里的名额改为**给最早到期的租用名额延长 30 天**；全是等级送的名额（没有可延长的）时，档 2、档 3 置灰并提示「名额已满」。

### 3.7 【后台】礼包（AB-41）

- **配置：** 「配置与安全 → 运营配置」页加「超值礼包」卡：三档价格、**总开关**（关掉 = 停售：App 的礼包卡、付费抽屉推荐行、开屏弹窗的礼包页跳转都消失；已买的权益照常可用，「Koin & Jatah」入口不受影响）。停售期间，跳转目标为礼包页的开屏弹窗照常展示，点按钮只关弹窗、不跳转（2026-11-13 定）
- **跳转目标：** 开屏弹窗和「系统通知发送」共用的 App 页面列表（`OpsAppPage`）都加「超值礼包页」（2026-11-13 定）；停售时点开跳礼包页的系统通知：停在原处不跳转，弹 toast「Paket Hemat sedang tidak dijual.」（超值礼包暂时停售，`showAppToast`）（2026-11-13 定）
- **订单：** 礼包的 QRIS 订单出现在现有「支付记录」列表（新用途「超值礼包」）；PawCoin 支付出现在 PawCoin 流水
- **用户抽屉「已购解锁」页签：** 礼包购买记录（每次的档位、时间、支付方式）、各类权益剩余次数与到期日、获得 / 使用记录
- 支持运营**手动补发**单项次数（客诉用，必填原因、写审计），不做手动扣减（2026-11-11 定）；**一次最多补 3 次**（2026-11-13 定）。新权限「补发免费次数」（`user.entitlement_grant`），默认给超级管理员和运营主管（同「补发宠物名额」「赠送 PawCoin」，写进 `AdminRole.OPS_MANAGER`；运营主管在代码里写死、「角色配置」页不显示），其他角色在「角色配置」里按需勾选（2026-11-13 定）
- 后台文案按中 / EN / ID 三语准备

### 3.8 通用付费抽屉改版（2026-11-12 定，11-13 并入本 PRD）

**起因：** KTP 高清下载、性格测试解锁等共用的底部付费抽屉里，PawCoin / QRIS 上下两行排列别扭；余额为 0 时 PawCoin 行整行置灰却又挂着紫色「先充值」；KTP 抽屉头卡是紫色占位，看不到自己的卡。礼包的付款（§3.4）、推荐行（§3.3）、用免费次数（§3.5）都画在改版后的抽屉上，所以一起做。

**范围：** 改的是共用组件（`PayChannelPicker`），下面这些地方会一起变，都要回归：

| 调用处 | 抽屉里的特殊部分（保持原样） |
|---|---|
| KTP 高清解锁 | 头卡（改为卡片缩略图，见下） |
| 性格测试结果解锁 | 结果卡缩略 + 代号 + 角色名 |
| 性格测试配型解锁 | 单买配型 / 买完整解读两用 |
| 宠物名额租用 | 数量步进器、单价 × 数量总价行 |
| 宠物名额续租 | 名额勾选列表 |
| 护照快照 | 护照缩略 + 护照号 |
| 登机牌解锁 | 章面缩略 + 场所名 |
| keepsake 付款流程 | — |
| 超值礼包付款（新，§3.4） | 礼包摘要头卡 + 「不可退款」说明 |

送礼包装页的支付区不走这个组件，由送礼优化 PRD 按同一套卡片和文案改（`V1.5.0/ui-gift-optimization/1-5-0送礼优化prd.md`）。

**规则：**

- **两种付款方式从上下两行改为左右两张等宽卡**：左「PawCoin」、右「直接付款」（Bayar langsung）
  - PawCoin 卡：所需币数 + 「余额 {n}」
  - 直接付款卡：金额 + 渠道小标签（目前只有 QRIS）；1.5.2 接入新渠道后也放在这张卡里，点卡再选渠道
  - 选中的卡：紫色描边 + 浅紫底 + 右下角勾
- **默认选中**：PawCoin 余额够 → 默认选 PawCoin；不够 → 默认选直接付款；从充值页回来余额够了 → 自动改选 PawCoin
- **余额不足时 PawCoin 卡**：不置灰；写所需币数、红字「余额 {n} · 还差 {m}」、卡内「先充值 →」；点这张卡进充值页，不能被选中
- **头卡**：KTP 高清解锁抽屉的头卡由紫色占位改为该宠物这款 KTP 卡的缩略图（带「预览 · 低清 + 水印」说明）；其他调用处头卡不变
