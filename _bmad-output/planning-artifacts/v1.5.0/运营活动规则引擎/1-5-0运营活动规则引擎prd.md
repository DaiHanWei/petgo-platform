## 1. 版本目标

运营现在办一次「带 #话题 发帖得奖励」的活动，要在活动结束后自己拉名单、用批量发放（AB-33）手工发 EXP，其他奖励（PawCoin、优惠券）要一个个手动补，参与的用户当时看不到任何回报。本项让运营在后台**自助配置活动**，系统自动判定、自动发奖：

- 「参加就有奖」的活动，用户做完当场到账
- 「比热度」的活动，结束后系统按热度排出名单，运营核对后一键发放（2026-11-11 拍板：两种发放方式都要，由运营按活动选）
- 奖励不只 EXP，还可以发 PawCoin、优惠券、KTP 高清解锁、性格测试解锁、免费礼物（2026-11-11 拍板）

**不做：** 实物奖励；App 内活动中心 / 活动页（活动说明靠话题页顶置的推广卡和运营推送）。

**观察指标：** 活动期间带活动话题的发帖数、参与人数、参与者活动后 7 天留存（对比同期未参与的活跃用户）、各活动发出的 PawCoin / 优惠券成本。

## 3. 功能与需求

### 3.1 活动由什么组成（AB-40 配置，FR-193 执行）

一个活动 = **名称 + 时间 + 一种行为 + 范围 + 发放方式 + 奖励**。

| 项 | 说明 |
|---|---|
| 名称 | App 里显示（EXP 明细「Event · {名称}」、到账 / 获奖通知）。**印尼语、英语两个名称都必填**，各 ≤ 40 字，App 按用户的界面语言显示（2026-11-12 定）；另有一个只给后台看的备注 |
| 时间 | 开始、结束时间，按 WIB 填写；只判定这段时间内发生的行为，按**行为发生的时间**判，不按系统处理的时间（2026-11-13 定） |
| 行为 | 三选一：**发帖 / 点赞 / 评论**（2026-11-11 拍板四种；2026-11-12 去掉场所打卡——打卡功能目前在用户侧隐藏，先不考虑） |
| 范围 | 见 §3.2，按行为不同 |
| 发放方式 | **参与即奖** 或 **排名奖励**（只有「发帖」能选排名），见 §3.4 / §3.5 |
| 奖励 | 一份「奖励组合」，见 §3.3 |

一个活动只配一种行为（2026-11-11 定）。想做「发帖 + 评论都有奖」就建两个活动、用同一个名称；这样每个活动的判定、上限、数据都单一，后台好核对。

### 3.2 行为与范围

所有行为都沿用线上成长值的判定口径，只是多了「活动范围」这一层过滤：

| 行为 | 什么时候算一次 | 可选范围 | 不算的情况（同线上） |
|---|---|---|---|
| 发帖 | 帖子发出；需人工审核的帖子在**审核通过**时发奖，但按**发帖时间**判是否在活动时间内，活动结束后才审核通过的也补发（2026-11-13 定） | 指定话题（1–3 个）· 内容类型（Diary / Moment / Tips，可多选，默认全部） | 私密帖（2026-11-11 定：不限话题的活动也不算） |
| 点赞 | 给别人的帖子点赞 | 被赞的帖子带指定话题（可不限） | 给自己点赞；同一个人对同一条帖子只算一次（取消后再点不重复算） |
| 评论 | 在别人帖子下的评论**变为可见**时 | 被评论的帖子带指定话题（可不限） | 自己帖子下的评论；同一个人在同一条帖子下只算一次（多条评论、删了再评都不重复算，2026-11-13 定） |

- **话题只能选官方话题**（2026-11-11 定）：用户话题谁都能建、名字随意，挂活动容易被抢注蹭；选择框只列状态为「正常」的官方话题
- 活动进行中话题被**隐藏**：活动照常判定（隐藏只是不推荐）；话题被**禁用**：之后的帖子不再关联该话题，自然不算，后台活动页提示「话题已禁用」

### 3.3 奖励组合（2026-11-11 拍板扩展奖励种类）

每「一份奖励」可以包含下面任意几项（至少一项）：

| 奖励 | 填什么 | 到账后在哪看 / 怎么用 |
|---|---|---|
| EXP | 数值（1–1,000） | EXP 明细「Event · {名称}」，同线上 |
| PawCoin | 数值（1–100,000） | 钱包流水，记为赠送（`BONUS`），可正常消费，**不可提现**（同线上 PawCoin） |
| 优惠券 | 从商城优惠券里选 1 张（只列「生效中、未过期」的券） | 「我的优惠券」，有效期、使用门槛按这张券的配置；**发券遵守这张券自己的总库存和每人限领**（见下） |
| KTP 高清解锁 | 次数 + 模板（8 款之一，或「任意款」） | 「Koin & Jatah Saya」页，用法同超值礼包（FR-195）；「任意款」次数可用在任何一款 |
| 性格测试解锁 | 次数 | 同上 |
| 免费 Rp1.000 礼物 | 次数 | 同上，在送礼支付区用 |

- **点赞活动只能发 EXP**（2026-11-13 定）：取消点赞只扣得回 EXP，PawCoin、优惠券、权益次数扣不回（§3.4），如果点赞活动发这些，「批量点赞领奖再全部取消」就能白拿；后台行为选「点赞」时奖励只列 EXP
- **权益次数的有效期：** 同超值礼包，**到账起 3 个月**（2026-11-11 定礼包为 3 个月；活动发的次数沿用同一规则，2026-11-11 定）
- **成本控制**（2026-11-11 定）：**参与即奖**活动的奖励里含 PawCoin 或优惠券时，必须填**活动总份数上限**（全站最多发出多少份），发满自动停止发放、后台活动页标「已发完」；只发 EXP / 权益次数的可以不填。排名活动的份数由档位决定，不填（2026-11-13 定）
- **优惠券的库存与每人限领**（2026-11-12 定）：活动发券和其他渠道一样，受这张券的总库存、每人限领数约束。库存发完或这个用户已领满时，**只跳过这张券，同一份里的其他奖励照发**，发放记录里写明「券未发出：库存不足 / 已达每人限领」。后台选券时旁边显示这张券的**剩余库存**和**每人限领数**，由运营自己判断够不够（不拦）
- **到账通知**（2026-11-11 定）：奖励里含 EXP 以外的东西时，发一条站内通知「你参加 {活动名} 获得了：{奖励列表}」（印尼语稿定稿时写），点开进「Koin & Jatah Saya」页（PawCoin 和免费次数都在这页；只含优惠券时进「我的优惠券」）；**不发推送**；同一活动每人每天最多 1 条（当天后续到账合并不再发）。只有 EXP 的不发（同线上）

### 3.4 发放方式一：参与即奖

- 每次符合条件发**一份奖励**，**当场到账**
- 上限按**次数**算：**每人每天最多几次**（按 WIB 切天，可不填）和**每人活动内最多几次**（必填，防止无限刷）；含 PawCoin / 优惠券时另有活动总份数上限（§3.3）
- 活动奖励**不占**日常 EXP 规则（发帖 3 次 / 天等）的额度，也**不受**日常规则启停影响；只受 `OPS_CAMPAIGN` 总开关控制（关掉 = 所有活动暂停发放）
- **扣回：**
  - EXP 沿用线上：帖子被**运营下架** → 扣回这条帖子从参与即奖活动得到的 EXP（排名奖不扣，见 §3.5）；**取消点赞** → 扣回这次点赞得到的 EXP；作者自删帖、评论被删不扣回；只扣实际入账的部分，不扣成负数
  - **PawCoin、优惠券、权益次数不扣回**（2026-11-11 定）：用户可能已经花掉 / 用掉，扣回会出现负余额和客诉；防刷靠次数上限和总份数上限，以及运营在后台对异常用户停发（§3.8）
- 同一个行为同时符合多个进行中的活动：**每个活动各算各的**（2026-11-11 定）；后台新建活动时，如果和进行中的活动「行为 + 话题」重叠，提示一次但不拦

### 3.5 发放方式二：排名奖励（只限发帖）

用于「谁的帖子最火谁得奖」的活动（2026-11-11 拍板）。

- **参赛帖子：** 发帖时间在活动时间内、带指定话题、符合内容类型的公开帖子；需人工审核的帖子按发帖时间算，生成名单时还没审核通过的不参赛（2026-11-13 定）
- **热度：** 截至活动结束时刻，帖子的 **点赞人数 × 1 + 评论人数 × 3 + 收藏人数 × 2**（与「被点赞 / 被评论 / 被收藏」的 EXP 权重一致）；评论按不同评论人算，同一个人在这条帖子下评论多条只算 1 次（2026-11-13 定，防小号刷评论）；只算真实用户的互动，不算作者自己、不算虚拟号；同分时先发的排前面（2026-11-11 定）
- **奖励档位：** 运营配置若干档，每档一份奖励组合（§3.3），如「第 1 名：300 EXP + 20.000 PawCoin；第 2–3 名：150 EXP + 优惠券；第 4–10 名：50 EXP + 免费礼物 3 次」；最多 5 档，名次连续不重叠
- **每人只取最好的一条帖子**，一个人不会占多个名次
- **结算流程：**
  1. 活动结束后系统自动生成「待发放名单」（结束后 1 小时内）：名次、用户、帖子、热度、应发奖励
  2. 运营在后台核对，可以**剔除**某个用户（必填原因，如刷赞）：剔的是人不是帖子，这个人的其他帖子也不再上榜（2026-11-13 定）；剔除后后面的人自动递补名次；发放前可以「撤销剔除」（2026-11-13 定）
  3. 点「确认发放」→ 服务端确认弹窗（人数、EXP 合计、PawCoin 合计、优惠券张数、各类次数合计）→ 发放；同一活动只能发一次，重复点不会重复发。个别用户发放失败的标「发放失败」并写原因，可在名单里重新发放（见 §3.8）
  4. 名单生成后 **7 天内**没确认，进后台侧栏「📥 待办中心」：照「商城待办」的写法在末尾加小标题「运营待办」+「排名待发放 ↗」，角标 = 超过 7 天未确认的排名活动数，点进运营活动页签并筛「待发放」；只对有「改 EXP 配置」权限的人显示（2026-11-13 定：后台没有首页待办区）；不自动发放
- 发放时帖子已被下架、作者已注销 / 停用：该行自动标为「不发放」并写明原因，不递补
- **排名奖发出后一律不扣回**（2026-11-12 定），包括 EXP：名单是运营人工核过的，有问题应在发放前剔除；之后帖子被下架也不扣
- **获奖通知**（2026-11-11 定）：发站内通知 + 推送各一次「恭喜！你的帖子在 {活动名} 里拿了第 {名次} 名」，正文列出奖励（印尼语稿：「Selamat! Postinganmu juara #{名次} di {活动名}」，定稿时与 EN 一起进文案表），点开进这条帖子；推送分类归「Promo & aktivitas」（`PROMO`）。点推送**直达帖子**，不先进通知中心（2026-11-13 定）；从通知中心点、帖子已删时留在通知中心弹 toast「Konten ini sudah tidak ada」（这条内容已经不在了），同追更宠物。获奖通知已经列了奖励，不再另发 §3.3 的到账通知
- 排名活动**也可以同时设参与奖**：建两个活动（一个参与即奖、一个排名），同名即可

### 3.6 活动状态

| 状态 | 什么时候 | 能改什么 |
|---|---|---|
| 草稿 | 新建未发布 | 全部 |
| 未开始 | 已发布、未到开始时间 | 全部 |
| 进行中 | 开始 ≤ 现在 < 结束 | **只能延长结束时间、提前结束**（2026-11-11 定），避免同一活动前后口径不一 |
| 已发完 | 参与即奖活动发满总份数上限 | 只能延长结束时间（不能加份数）、提前结束 |
| 已结束 | 到结束时间或被提前结束 | 不能改；排名活动在这里做结算 |

- 提前结束：二次确认；已发的奖励不收回
- 删除：只有草稿能删
- 选作奖励的优惠券在活动期间被停用 / 过期：之后这一项不再发，其余奖励照发；后台活动页提示「优惠券已失效」

### 3.7 App 侧

- 活动 EXP 进现有 EXP 明细，显示「Event · {活动名}」（线上已有）；升级照常弹庆祝
- PawCoin 进 PawCoin 流水（赠送），活动发的这一行显示「Event · {活动名}」（同 EXP 明细写法，2026-11-13 定；其他 `BONUS` 照旧显示「Bonus」）；优惠券进「我的优惠券」（券卡不显示来源，无改动）；权益次数进「Koin & Jatah Saya」页的免费次数区（超值礼包 FR-195 由线上 PawCoin 页改造，本文复用）
- 新增：§3.3 到账通知、§3.5 获奖通知两种通知类型。两类都走通知中心的「后端文案条目」（后端按收件人界面语言写好标题、正文，App 读存的），正文最多 2 行、超出用现有「Lihat semua」展开；图标都用「Promo & aktivitas」推送分类的 `campaign_rounded`（1.4.2 定：通知图标与推送分类一一对应），2026-11-13 定
- 活动说明由运营放在**话题页顶置推广卡**（AB-10A，线上已有）或运营推送，本文不新增 App 入口
- 不加「+N EXP」即时提示（2026-11-11 定）：线上所有日常规则都没有，只给活动加会不一致

### 3.8 【后台】运营活动（AB-40）

**位置：** 「配置与安全 → 成长体系」页新增页签「运营活动」（与现有 规则 / 消费 / 等级 并列）。

- **列表：** 名称、行为、范围（话题）、发放方式、奖励摘要、时间、状态、参与人数、已发出（EXP / PawCoin / 优惠券 / 次数）合计；按状态筛选、按名称搜索
- **新建按钮：** 放在「运营活动」页签内工具栏右侧，页头「批量发放」不动
- **发布确认**（2026-11-13 定）：点「发布」弹服务端确认弹层，逐项复述名称、时间、行为与范围、发放方式、每份奖励、上限，并提醒「发布后进行中只能延长结束时间或提前结束」；和进行中的活动「行为 + 话题」重叠时，在这个弹层顶部加黄色提示、按钮改「仍然发布」，不另弹（§3.4 的重叠提示即此处）
- **新建 / 编辑：** 右侧 480 抽屉表单（同后台惯例），字段见 §3.1–§3.5；名称分印尼语 / 英语两栏；选优惠券时显示剩余库存与每人限领；按所选行为显示对应的范围字段，行为选「点赞」时奖励只能加 EXP；奖励组合用「＋ 添加奖励」逐项加；发放方式选「排名奖励」时出现档位编辑，每档一个奖励组合

  - 新表「运营活动」：名称（印尼语 / 英语）、备注、行为、范围（话题 ID 列表 / 内容类型）、发放方式、奖励组合、每人每天次数、每人总次数、活动总份数、已发份数、排名档位、起止时间、状态、操作人

  - 新表「排名结算名单」：活动、名次、用户、帖子、热度、应发奖励、状态（待发 / 剔除 / 不发放 / 已发）、剔除原因
  - `growth_ledger` 加可空的「活动 ID」列；活动 EXP 仍用规则码 `OPS_CAMPAIGN`，`note` 写印尼语名称（旧版 App 照旧显示）；新版 EXP 明细接口有活动 ID 时按用户界面语言返回对应名称。通知同理按语言出

  - 优惠券：`user_coupons` 发券来源加 `ACTIVITY`（带活动 ID）；发券走现有 `ShopCouponRepository.incrementIssuedIfAvailable` 原子扣库存并校验 `per_user_limit`，失败只跳过券这一项
  - 幂等键：参与即奖——发帖 `ACT:{活动ID}:POST:{帖子ID}`；点赞 `ACT:{活动ID}:LIKE:{用户ID}:{帖子ID}`；评论 `ACT:{活动ID}:COMMENT:{用户ID}:{帖子ID}`（点赞 / 评论必须带用户 ID，否则同一条帖子只有第一个互动的人能拿奖；用帖子 ID 而不是点赞 / 评论记录 ID，保证取消重点、多条评论不重复算）；排名发放 `ACTRANK:{活动ID}:{用户ID}`；同一份奖励里各项按同一个键发，任何一项出错整份重试（券因库存 / 限领发不出不算出错，记原因后跳过）
- **判定：** 在现有监听里（发帖、点赞、评论）入账日常规则之后，再查一次「**行为发生时刻**进行中、行为匹配」的活动并逐个发放（发帖用发帖时间，点赞 / 评论用点赞 / 评论的创建时间；不用监听处理的时刻，否则活动最后几秒的行为、活动结束后才审核通过的帖子会漏发）；活动 EXP 不走 `adjust()`（那条路径跳过上限、是手动发放用的），走 `accrue()` 同样的锁和幂等
  - 点赞 / 评论要按「被互动的帖子」的话题判定：`ContentLikedEvent` / `ContentCommentedEvent` 现在不带话题，监听里按帖子 ID 查 `content_topics`
  - 总份数上限要在并发下准确（发放时原子扣减已发份数）
  - 不能静默丢发放：现有监听失败不重试，活动发放要先写一条「待发」记录再发奖，成功改「已发」，出错改「发放失败」并记原因；后台重新发放用同一幂等键（§3.8）
