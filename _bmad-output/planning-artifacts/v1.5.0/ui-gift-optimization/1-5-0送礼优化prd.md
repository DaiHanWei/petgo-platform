## 1. 版本目标

送礼从「点一下扣钱、弹个 toast」变成一次有仪式感的送礼：送礼人能写祝福语、看到快递把礼物送到；主人收到的是一份要拆开的礼物，而不是一个累计数字。

- 去掉粉丝榜和礼物总价值：不鼓励比拼金额（11-02）
- 礼物按运营在后台配置的**分类**分组，不再按价格写死五档（11-11）
- 不改价格、EXP 规则、支付渠道和退回规则
- **不做：** 选礼盒 / 付费礼盒（设计稿有，11-13 再次确认不进 1.5.0）

## 2. 现状（2026-11-13 核 `origin/main 355a37dee`）

| 项 | 现状 |
|---|---|
| 送礼接口 | `POST /api/v1/pets/{petId}/gifts`（`GiftSendRequest`：giftToken / quantity 1~99 / channel PAWCOIN·QRIS / requestId / source / postId），**没有祝福语字段** |
| 订单 | `gift_orders`（`GiftOrder`），没有「主人是否已拆」 |
| 礼物展示 | `GET /api/v1/pets/{petId}/gifts` 按**礼物种类汇总**（礼物墙 + 总价值 totalValue + 礼物个数 giftCount + 送礼人数）；`/gifts/supporters` 是粉丝榜分页 |
| 礼物分类 | **没有分类字段。** App 按价格分组，五个档名（Camilan / Makan enak / Mainan / Gaya / Hadiah besar）写死在 `gift_style.dart` 的 `giftTierName`；后台价格自由填，不在五档上的礼物没有档名 |
| EXP | 送达时由 `GiftSentEvent` 入账：送礼人 `GIFT_SENT` 每 Rp1,000 = 5，主人 `GIFT_RECEIVED` 每 Rp1,000 = 4 |
| 收礼通知 | `PET_GIFT_RECEIVED`，点开进礼物页 |
| 送出反馈 | 1–2 秒小动效 + toast（`gift_send_animation.dart`） |
| Rive | App 已依赖 `rive: ^0.14.11`（支持数据绑定、换图、事件）；`features/place/presentation/widgets/stamp_ceremony.dart` 已在用 |

## 3. 功能与需求

### 3.1 选礼物目录（FR-187，泳道 B）

- 普通礼物**按后台分类分组**（FR-225），分组标题只写分类名，礼物格显示价格「{n} PawCoin」和送礼人自己能得的「+{n} EXP」
- 专属礼物不归分类，照线上按解锁等级单独分组，放在最后
- 没有在线礼物的分类不显示
- 「收到过的礼物」区（B3）显示是谁送的：「dari {名字}」；超过 3 人显示最近 3 人 +「+N」
- 照线上保留：等级锁区块、按物种排序（在每个分类内）、数量 ×99 上限、加载失败（B5）

### 3.2 包装页与祝福语（FR-188，泳道 C）

- 选完礼物进包装页（C1），标题「给{宠物名}包一份礼物」
- **礼盒：** 不可选，所有礼物用同一个默认礼盒（红盒紫丝带）；总价 = 礼物单价 × 数量
- **EXP 提示：** 只写送礼人自己的（如 5,000 档 +25），不写「双方都得」
- **祝福语：** 选填，上限 500 字符，计数常驻，到上限不能再输入
  - 点「Kirim」时先做**敏感词拦截**：命中则不扣款、输入框变红、下方提示（C3）。复用内容审核的敏感词库
  - **不做人工复审**；发出后的问题靠举报（FR-191）
- **支付区：**
  - 收起时：标题行「Bayar dengan PawCoin」（用 PawCoin 支付）+ 余额、数量、主按钮、不可退说明、开关行「Pilih metode bayar」（选择付款方式）
  - 展开（点开关行或上拉）：**与 1.5.0 超值礼包付款抽屉 C7 同一套写法**（11-13）——数量 → 粗体「Pilih metode bayar」（右侧箭头收起）→ 左右两张卡「PawCoin」/「Bayar langsung」（直接付款）→ 不可退说明 → 主按钮在最底。展开时不显示收起状态的标题行
  - PawCoin 卡：所需币数 + 灰字「Saldo {n}」；余额不足时卡不置灰、不可选，红字「Saldo {n} · kurang {m}」（余额 · 还差）+「Isi saldo dulu →」（先去充值），点卡去充值，充完回到本页、礼物 / 数量 / 祝福语保留，余额够则自动选中 PawCoin
  - 直接付款卡：总价 + 渠道小标「QRIS」；总价低于后台配置的 QRIS 门槛（现 Rp10,000）时置灰、写「Minimal Rp{n}」（C5）。1.5.2 接入新渠道后也放在这张卡里
  - 默认 PawCoin；余额不足时自动展开：总价够门槛默认选中直接付款、主按钮「Kirim · Rp{n}」（C9），不够则主按钮置灰（C6）
  - 主按钮跟随所选方式；扣款中（C7）开关行置灰；扣款中、扣款失败（C7 / C8）照线上
  - 「选付款方式」卡片组件以通用付费抽屉 / 超值礼包那份 PRD 为准，两份各在一个分支

### 3.3 送出动画（FR-189，泳道 E）

- 付款成功后全屏白底，播放 Rive 动画 `Send gift/send_gift.riv`（约 5 秒）：所选礼物在画面中间浮现（E1）→ 快递员骑摩托载着礼盒开走（E2）→ 送达页（E3）。替代线上的小动效 + toast `giftSentToast`
- 动画中任意时刻点「Lewati」（跳过）直接到 E3
- **E3 送达页：** 白底；宠物头像右下压礼盒；「Hadiahmu sudah sampai ke」+ 宠物名；送礼人自己得到的 EXP；紫色主按钮「Lanjut」回到进入送礼前的页面
- QRIS 付款照线上流程（二维码、过期、失败不改），付款成功后同样进 E1；付款时已离开 App 的不播动画（线上）

### 3.4 主人拆礼物（FR-190，泳道 F / G）

- **礼物页改为按订单逐笔列出**（不再按礼物种类汇总）。主人视角有「未拆」状态，按**笔**记，不按个数；可筛选「Belum dibuka」（未拆，F4）；筛选胶囊里的分类是后台分类（FR-225）
- 未拆礼物显示礼盒 +「Masih terbungkus」（还包着）+「Baru」角标；Diary 礼物行显示未拆数 + 最近几笔（F1）
- **拆礼物：** 浅色客厅插画背景，Rive 动画 `Open gift/receive_gift.riv`：礼盒在地毯上轻晃（G1「Ketuk untuk membuka」点一下打开）→ 点礼盒开盒、礼物升起 → 动画结束后淡入送礼人、标题、祝福语、主人得到的 EXP、「Lanjut」、「Lihat profil {送礼人}」（G2）
- 无祝福语时（G3）不留空白、不显示「⋯」
- 多笔时「Buka Semua」（全部拆开）：同一个礼盒开盒后先看汇总（G4，每页 9 格，超过 9 份分页 G5），有祝福语时「Berikutnya」逐条看（G6），最后一条按钮变「Lanjut」
- **拆礼物不触发任何成长值入账。** EXP 仍在送达时由 `GiftSentEvent` 入账，拆礼物页只读这笔订单的 EXP 来显示
- **收礼通知点开直接拆这一份礼物**（G1），已拆过则进礼物详情（H1）

### 3.5 礼物详情、访客与举报（FR-191，泳道 A / H）

- 礼物详情抽屉（H1 主人 / H2 访客）：礼物浮在礼盒上方、数量、收到日期、送礼人和他的宠物、祝福语
- **访客能直接看主人还没拆的礼物，含祝福语；访客侧没有「未拆」状态**（11-02）
- **举报祝福语：** 礼物详情和拆开页（G2 / G6）的「⋯」菜单 →「Laporkan ucapan」（H5 → H6）。设计稿去掉了拆开页的「⋯」，按需求保留（11-13）。复用现有举报抽屉和举报后台，新增一个举报目标类型，**后台不另出稿**
- 举报处理后祝福语隐藏，显示「这条祝福语违反社区规范，已隐藏」（H3）；礼物本身照常显示
- 送礼人已注销（H4）：照线上的注销用户展示规则
- **入口：** 他人宠物 Diary Tab 的「Kirim Hadiah」从标题行挪进宠物卡，与「Ikuti」（关注）各占一半；已关注时「Mengikuti」描边、「Kirim Hadiah」实心（A1 / A7，11-12）

### 3.6 去掉粉丝榜与总价值（FR-192）

- Diary 统计卡、礼物页去掉粉丝榜和礼物总价值
- **H5 宠物名片的「Hadiah」列由礼物总价值改为礼物个数**，布局不变，不出稿
- 后台送礼记录（AB-36）不受影响，照常能看金额

### 3.7 礼物分类（FR-225 App / AB-43 后台）

**为什么：** 线上分组是按价格写死的五档，后台价格又能自由填，不在五档上的礼物归不进任何组，1.5.0 的筛选也没法做。11-11 定：新增独立的分类，与价格脱钩。

**App（FR-225）：** 选礼物目录（B）、礼物页筛选（A4 / F2）按分类分组和筛选，分类名按 App 语言显示印尼语或英语；排序按后台排序值；没有在线礼物的分类不显示；专属礼物不归分类。

**后台（AB-43，后台整合稿 K / L 泳道）：**

- **入口：** 礼物目录页标题下加页签「礼物 / 分类」（照成长体系页），不新增导航；权限复用礼物目录的查看 / 编辑
- **分类管理（K）：** 列表列 名称（EN / ID）、礼物数（在线 / 全部）、排序、状态、更新时间；在线但没有在线礼物的分类标灰色「App 不显示」。新建 / 编辑用 480 抽屉：名称 EN、名称 ID（必填，各 ≤ 40，与已有分类含已下线的都不能重名）、排序
- **只下线、不删除；分类下还有在线礼物时不能下线**：「下线」按钮置灰，旁边写原因「还有 N 个在线礼物，先把它们改到别的分类或下线」+「查看礼物 ›」（跳到礼物页签并带上该分类筛选）。下线前原生确认框；已下线的分类可重新上线、可改名改排序
- **礼物（L）：** 表格在名称后加「分类」列、筛选栏最前加「全部分类」；礼物抽屉在「类型」下加「分类」下拉——选普通时必选、只列在线分类，选专属时隐藏（与「最低等级」互斥，用同一段显隐逻辑）
- 所在分类已下线的礼物：编辑时下拉标「（已下线）」+ 红字，必须改选在线分类才能保存或重新上线（L5）
- **线上文案改三条：** `admin.v140.gift.form.speciesHint`「送礼面板每个价格档内…」→「每个分类内…」；礼物图标说明 `admin.gifticon.spec.create` / `.edit`「推荐 112×112」→「推荐 1000×1000（送礼动画按原尺寸显示，小图会变小），建议 WebP」。上传校验（PNG / WebP、≤ 512 KB、最短边 ≥ 42）不变
- **新增后台文案**（页签、分类表、分类抽屉、下线确认、两条禁用原因、「App 不显示」）的中 / EN / ID 三语对照，以及给研发的执行说明（数据库、服务校验、模板、测试、验收），都在后台整合稿页头

**上线迁移：** 建 5 个分类，名称取 App 现有档名——Snacks / Camilan（Rp1,000）、Treats / Makan enak（Rp5,000）、Toys / Mainan（Rp10,000）、Style / Gaya（Rp25,000）、Big gifts / Hadiah besar（Rp50,000），排序 10 / 20 / 30 / 40 / 50；存量普通礼物按价格归入对应分类；**不在五档价格上的礼物迁移前列出来，由运营指定分类**。专属礼物不迁移。

### 3.8 动效交接（FR-189 / FR-190）

**动效以 Rive 文件为准**，整合稿 E / G 泳道的画面是用 Rive 文件实际渲染出来的帧。

| 文件 | 画板 / 状态机 | 对外接口 | 状态 |
|---|---|---|---|
| `Send gift/send_gift.riv` | `GiftSend` / `SendSM` | 礼物图：图片资源 `plushy-image`（或数据绑定 `Gift.giftImage`），App 加载时换成所送礼物 | 换图已验证可用；**缺结束事件 `sendDone`**（已请设计师加） |
| `Open gift/receive_gift.riv` | `GiftReveal`（1080×2340）/ `GiftSM` | 触发器 `GiftVM.open`（点礼盒时 App 触发）；礼物图 `GiftVM.giftImage` | **礼物现在写死成小熊（矢量），App 换不掉**，已请设计师改成可替换图片；缺结束事件 `revealDone`；文件里另有 `TapBox`，待设计师确认是否会自己触发 `open` |

- **礼物图必须 1000×1000（或同比例）**：Rive 按图片像素尺寸画，原图 `plushy-image` 就是 1000×1000，小图会画小。11-13 定：后台礼物图标推荐尺寸由 112×112 改为 1000×1000（见 §3.7），存量礼物由运营用设计师的 SVG 原稿重新导出上传（见 §6）
- 全屏铺满用 `Fit.cover`；收到结束事件后再进 E3 / 淡入 G2 的文字按钮。设计师补事件前，App 可先按状态机状态变化判断
- 接法照 `stamp_ceremony.dart`：`assetLoader` 换图、`dataBind(DataBind.auto())`、`stateMachine.addEventListener` 收事件
- 系统开了「减弱动态效果」、低端机或动画加载失败：直接显示终态页（E3 / G2），不卡流程
- 设计师 11-13 另需交：礼盒透明 PNG（合盖 / 开盖）。App 里动画之外的礼盒（F 未拆格、E3、H 详情）统一用这一款，现在稿里是从设计稿截图抠的

**待补素材不阻塞开发（11-13）：** 两份 Rive 的修改和礼盒 PNG 由设计师交回后产品直接转研发替换文件。文件路径（`assets/rive/send_gift.riv`、`assets/rive/receive_gift.riv`、`assets/gift/gift_box_closed.webp`）、属性和事件名、兜底时间（送出 5.5 秒、开盒 2.5 秒）、临时礼盒图见 App 整合稿页头「待补素材」。

**QA 场景：** 动画中点「Lewati」；连续快速点礼盒；批量拆 1 份 / 9 份 / 超过 9 份；Rive 文件或礼物图加载慢 / 失败；减弱动态效果打开；播放中切到后台再回来；换不同尺寸礼物图看大小是否一致。

## 6. 开发注意与接口约定

- **建议分支：** `feat/1.5.0-gift`，与首日与新手任务、推送与召回、健康记录提醒互不依赖；支付卡组件以超值礼包分支为准
- **数据：**
  - `gift_orders` 加祝福语（≤ 500 字符，可空）和「主人拆开时间」（可空 = 未拆）；**上线前的存量订单一律视为已拆**（11-10），老用户打开新版不会突然多出一堆未拆礼物
  - 新增礼物分类表：EN 名、ID 名、排序、状态（在线 / 下线）、更新时间；礼物表加分类 ID（普通礼物必填、专属礼物为空）
  - 本版不加礼盒样式字段
- **接口：**
  - 送礼请求加可选的祝福语字段；服务端再做一次敏感词校验，App 的拦截只是提前提示
  - 礼物目录接口改为按分类分组下发（分类名两种语言、排序），专属礼物单独一组
  - 新增按订单逐笔的礼物分页接口（主人 / 访客两种视角，访客不返回未拆状态，支持按分类、未拆筛选）；Diary 礼物行要「未拆数 + 最近 N 笔」
  - 新增拆礼物接口（单笔 / 批量），幂等，**不入账**
  - 收礼通知的跳转目标改为这一笔订单
