# V1.5.0 会话 ② 送礼与礼包 · Epics

## Overview

一条分支 `feat/1.5.0-gift-pack` 串行实现两份 PRD：先送礼优化（Epic 1 ~ 3），后超值礼包（Epic 4 ~ 7）。每个 PRD 都按「后端 → App → 联调」推进。

**执行顺序例外（唯一一处）**：Story **4-1 权益次数表与发放扣减接口**排在全线**第一个**做——它是会话 ⑥ 运营活动规则引擎的前置契约。4-1 完成并 push 后，由本地操作者决定是否把分支此刻的状态提 PR 合进 `dev_1.5.0`（此时分支上只有 4-1 一个提交），⑥ 即可开工；之后继续 Epic 1。

### NonFunctional Requirements

- 资金正确性：扣次数与解锁 / 送礼同事务、按目标幂等；礼包到账发放可重试、绝不丢；PawCoin 失败整笔回滚。
- 旧版 App 不受影响（架构 §6）。
- 护栏：对外标识用 token（分类 id 为参考数据例外，D-4）；Flyway 时间戳号段 `V20261115_0200 ~ 0259`；共享 CHECK DROP + ADD 重列全集；不引新中间件；日志不记祝福语正文 / 昵称 / 金额以外的 PII。
- App 文案逐字取 PRD / UI 稿表格（ID、EN 两份 arb）。

### Additional Requirements（架构）

D-1 ~ D-31，见 `architecture-v1.5.0-gift-pack-delta.md`。重点：D-9（通知不改、App 打开最新未拆）、D-13（两张付款卡共享组件）、D-16 / D-17（免费礼物事件与订单形状）、D-18（`PayChannel.PACK_CREDIT` 护栏）、D-19（性格测试用次数不写 keepsake）、D-22（购买限制）、D-24（礼包到账状态机）、§5（⑥ 契约）。
